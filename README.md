# 线簿 · ClueLedger

**写到第八章，还记得第三章的那只怀表。**

一款面向长篇悬疑小说的 AI 写作工作台。

写悬疑，凶手可以说谎，时间线得对得上。第三章留下的湿脚印、第六章已经死亡的人、计划在第七章回收的怀表，都会影响下一章怎么写。

线簿把章节、人物小传、线索与原文依据接入同一轮创作：**写前核对材料，写时限定范围，写后按需检查。** 作者在对话里提出要求，模型直接操作本地作品文件，过程和改动都可以回看。

## 三个悬疑写作现场

### 第六章已经死亡的人，第八章还要赴约

> 「继续写第八章，让林远与旅馆老板娘碰面。」

假如正文核对记录显示，老板娘已在第六章死亡，线簿会把这条有效状态优先放进人物状态上下文，并标明最后核对的章号，供模型判断这场见面应当是回忆、转述，还是需要调整情节。

人物的位置、生死、立场随章节变化。线簿保留「截至第几章核对过」的依据，后续缺了几章记录也会说明。回到早期章节时，状态按任务截止章筛选。

身份另有一层区分：作者的小传声明、正文核对出的披露、计划披露分别保留。写作的状态分区按截止章提供已披露内容；写作 Agent 仍能读取真相设定，方便规划伏笔，因此这项筛选本身不保证正文绝不提前泄密。

### 第三章的怀表，该轮到它出场了

> 「写第八章，继续追查怀表停在十点十七分的原因。」

如果这条线索已登记为「第三章埋设、第七章计划回收、尚未回收」，写到第八章时，它会被标为超期，在未回收线索中优先进入写作上下文。

每条线索都带埋设处的原文依据；登记为已回收，还要给出回收处的依据。改过来源，旧登记就失效，读取时会提示重新核对。同一线索由多章分别整理时，按章保留贡献，重建一章不会删掉另一章的依据。

### 只想改一场雨，不想顺便改掉半本书

> 「参考第二章，把第三章结尾的雨夜改成雪夜。只改第三章，改完检查时间线。」

这一轮有三个明确步骤：

1. **先读材料。** 选中的参考默认必读；预读被截断，就得继续读完再写。界面分别记录作者带了哪些文件、模型实际读到了哪些区间。
2. **再定范围。** 模型先登记本轮允许修改的文件和操作。参考第二章不产生修改第二章的授权；固定范围外的写入由工具拒绝。
3. **最后检查。** 作者明确要求后，进入只读检查，给出问题、建议与原文证据。检查工具不能修改作品；没有读完目标全文和必需参考，就不能发布「未发现问题」的完整结论。

作者明确允许「同步相关章节」时，模型才可在已登记的可追加范围内补充具体文件，并提供本轮读过的原文依据。检查发现问题，也不会自行扩大修改范围。

## 一本小说，一个本地目录；一套设定，多个作品共用

正文一章一文件，人物一人一份小传，线索和真相各自保存。作品用 Markdown 存在电脑里，也可以用自己的编辑器打开。

```text
雪山旅馆/
├─ 正文/
│  ├─ 0001 雪夜来客.md
│  ├─ 0002 书房里的脚印.md
│  └─ 0003 怀表停在十点十七分.md
├─ 设定集/
│  ├─ 角色小传/
│  │  ├─ 林远.md
│  │  └─ 艾琳·沃克.md
│  ├─ 线索.md
│  └─ 真相.md
└─ .clueledger/assembly.json      # 这个作品用了库里哪些精确版本
```

写作台围绕阅读和对话展开：左侧找章节与设定，中间读正文，右侧提要求、看回复。应用内稿纸只读，修改经对话执行；外部编辑后可以重新读取。思考与工具过程默认折叠，需要时再展开。

### 全局模块库

同一份人物或世界设定，常要在多部作品里复用。线簿把它存成应用级的**模块库**，按七种类型管理：人物、世界设定、线索与伏笔、真相与事件经过、时间线、剧情安排、自由资料。同一类型可以建多份实例，两份同名人物不会自动合并。

- **版本不可变。** 修改生成新版本，旧版本仍可读；库的当前版本不会悄悄覆盖作品里已固定的版本。
- **作品只绑定精确版本。** 两个作品可以固定同一个模块的不同版本，各自升级、互不影响。
- **装卸只改装配清单。** 装、卸、升级操作只改 `.clueledger/assembly.json`，不复制模块原文；卸下后，后续默认检索与详情展开都不再包含它。
- **保存与使用分开。** 「保存到模块库」与「保存并用于本作品」是两个动作，界面分别显示结果；发布成功但绑定失败时，只重试绑定。
- **以当前组合派生新作品。** 新作品继承装配，正文与观察从空白开始；源作品不受影响。

### 故事资料：一份索引，两种读法

资料页分「章节与事件」「人物」「线索与伏笔」「名词表」。一次整理只产出一份统一投影，从它读两个视图：

- **章节视图**按章序看「这一章发生了什么」，带摘要、事件与原文区间。
- **故事视图**只对能证明的先后排序。回忆、证词、推测和梦分别标注；未知时间与不连通事件单独列出，不按章号伪造故事顺序。

每条资料都显示「读到并提交了什么」和「依据还对得上当前文件没有」。空结果也带来源指纹；正文一改，旧记录就标为失效。重建一章只替换这一章的贡献，其他章节不受影响。

### 有界检索与任务卡

材料多起来以后，把所有条目塞进上下文并不可靠。线簿把检索分成三层：先看一眼装了哪些模块版本，再按人物、章区间或关键词查询候选，最后才按完整引用读取原文区间。候选命中不等于读过全文；游标与查询条件绑定，换条件就要求重新查询。

对话里的任务卡把本轮事实集中显示：作者授权的原话、允许与禁止的操作、装配与发布授权、必读材料与未读剩余、实际改动与检查状态。它只是事件流的投影，不另建一份事实来源。

## 也用它研究 Agent 怎么做事

这个项目首先用于学习 **Agent 编排思路与开发流程**，悬疑写作提供了一组具体而严格的问题：材料很多、事实会变、修改有范围，检查还得拿出依据。

当前采用一个写作 Agent，按任务切换上下文与可用工具。围绕它，应用负责执行读取、范围、版本和证据校验。

| 设计选择 | 解决的问题 | 保留的取舍 |
|---|---|---|
| 按任务装配上下文，并记录装入与跳过的内容 | 写作、建索引、检查需要不同材料，上下文也有容量限制 | 重要性排序与预算会影响模型实际看到什么 |
| 写操作先登记范围，再由工具逐次核对 | 限制操作路径与类别，避免超出已记录范围 | 作者原话怎样解释为范围，仍依赖模型 |
| 模块按精确版本绑定，不跟随库的最新版本 | 共享设定的修改不应影响其他作品 | 升级需要作者显式操作 |
| 检查使用只读工具，问题附原文证据 | 让检查结果可以复查，也避免检查过程继续改稿 | 证据存在不等于判断正确，检查仍可能误报或漏报 |
| 来源变化后使相关记录失效 | 避免旧索引、旧状态和旧报告继续被当作当前依据 | 更新需要作者发起相应任务 |

遇到重名、身份冲突或证据疑点，系统列出冲突，采信由作者决定。任务停止或失败时，已经写入的文件会保留，并单独记录完成情况与版本状态；检查失败也不会撤销已落盘的修改。

## 本地启动

准备好 **uv、Python ≥ 3.12、Node.js ≥ 18 和 Git**，在仓库根目录执行：

```powershell
uv sync
Set-Location frontend
npm install
npm run build
Set-Location ..
uv run python -m hastings.server
```

打开 [本地写作台](http://127.0.0.1:8000)，新建或打开作品。在顶栏「模型设置」添加自己的模型连接，保存并设为当前，就可以开始对话。

也可以在启动时打开已有作品，或指定模块库与状态目录：

```powershell
uv run python -m hastings.server --workspace "D:\写作\雪山旅馆"
uv run python -m hastings.server --library-dir "D:\写作\模块库" --state-dir "D:\写作\应用状态"
```

模块库默认位于 `~/Documents/ClueLedger/ModuleLibrary`。模型连接可由界面配置，也可参照 [配置模板](config.example.yaml) 编写本机 `config.yaml`。密钥优先保存在系统凭据存储中；运行时的模型配置从文件读取。前端开发启动与连接细节见 [前端说明](frontend/README.md)。

## 当前能力与边界

当前运行版本为 **0.8**，包版本为 `0.8.0`。上文介绍的是当前实现；后续方案见 [0.8 产品方案](product-design/v0.8/README.md)。

- **能核对来源，也需要模型判断语义。** 文件版本、章号、读取区间、模块版本和引文可以确定性校验；人物状态是否概括准确、伏笔是否真的回收，仍依赖模型。
- **灵感还没有界面和工具。** 灵感条目的修订、冲突、删除恢复与历史查询已有后端与接口，顶栏入口、参考 chips 和 agent 灵感工具尚未接入；写作轮次不会自动读取灵感。
- **资料页只读。** 正文与设定仍由对话修改；状态面板未提供作者手动编辑表单。系统不会自行启动检查、自动修稿或自动重试模型任务。
- **只有一份故事索引。** 同一事件的多条计划线尚未叠加显示；资料导入没有实施，作品包导出导入已取消。
- **长篇创作效果仍待验证。** 本次只跑确定性与浏览器用例，未用在线模型复核长文材料使用、证词辨别与泄露边界；已有在线流程证据来自更早版本，不能直接当作本版结论。覆盖范围见[运行与验证](dev-notes/v0.8/release.md)。
