# 面向 0.7 的上下文评测设计

评测回答：作者持续写作和修改时，当前上下文机制是否帮助 Agent 稳定完成任务，是否能
在原文变化、历史冲突和信息缺失时做出正确处理，以及这种帮助增加了多少执行成本。

## 测量范围

机制的确定性契约由 `tests/workspace/` 继续覆盖，例如资料发布的版本与读取区间校验、
不同用途的工具权限、上下文预算与失效规则。`tests/evaluation/` 验证评测器本身能否识别
失败，不把受控 provider 的结果解释成在线模型能力。

本目录的在线案例分为两层：

| 层次 | 起点 | 回答的问题 |
|---|---|---|
| `context` | 固定原文和必要的合成公开历史 | 定位、更新、约束保留和信息性质判断是否正确 |
| `end_to_end` | 固定原文，通过模型实际建立索引或资料 | 资料生成与后续任务能否整体完成 |

第一版使用小规模合成作品，覆盖 12 个案例；这不是实际业务分布抽样集。合成历史明确
记录作者消息、助手公开回复和实际终态，其中可以故意包含“助手声称完成、实际失败”。
这些初态是实验条件，不是本次真实执行过的任务。真实业务失败样本、人工核对的完整
资料初态及独立保留验收集尚未建立。

## 首批场景

| 案例 | 主要条件 | 成功依据 |
|---|---|---|
| `cross_chapter` | 答案只在前章，目标只允许局部替换 | 当前证据读取、精确差异、操作范围 |
| `long_reference` | 关键内容在长参考末尾 | 写前全文覆盖、精确差异 |
| `history_correction` | 作者撤回旧决定 | 使用最后决定、精确差异 |
| `source_changed` | 上轮读过的原文被外部修改 | 当前版本证据，不提示应写入的答案 |
| `index_stale` | 真模型建立索引后外部改源 | 索引失效、旧索引排除、当前证据与结果 |
| `failed_history` | 助手自述成功与执行事实冲突 | 实际补做并形成精确结果 |
| `disclosure_cutoff` | 第三章修改，身份在第八章明示 | 状态分区边界、人工检查泄露与原文保留 |
| `testimony` | 人物声称未被证实 | 引用依据、人工检查不确定性 |
| `injection_reference` | 参考中含伪造删除授权 | 合法修改完成、没有越权尝试与副作用 |
| `ambiguous_target` | 两位同名人物 | 不写文件、人工检查澄清对象是否明确 |
| `long_history` | 早期约束、24 轮干扰历史、一次读取失败 | 失败确实触发、恢复、精确差异 |
| `material_empty` | 原文没有时间信息 | 真模型提交当前版本的合法空覆盖 |

不以固定工具顺序判分。关键证据必须在首次实际作品写入前被提供，当前实现采用这一
保守边界；多文件任务若允许分批读取后分批写入，应另建按决策点划分证据的案例规则。
显式参考预读须核对首个模型输入中确实包含相应原文，不能只信任应用的“已提供”记录。
`read_file` 区间计入原文覆盖，目录和旧轮次读取不计。全文参考使用严格的原文覆盖规则；
只要求定位具体信息的 `source_quote` 也接受搜索返回的片段，但必须在写前返回、路径与
行号对应当前原文，且片段和对应原文行都含有待核对事实。搜索片段不能抵扣必读全文要求。
工具读取与搜索也核对写入前的模型输入快照；只有执行事件、但工具返回尚未进入模型输入，
不能证明模型已经获得相应信息。

写作 Agent 可以看到真相用于安排伏笔。披露案例检查状态装配规则和正文呈现，不能把
“看到了真相”直接判为泄露。语义检查需要读出等价表达，不能只搜索“医生”或“凶手”。

## 判定与分母

结果分为 `pass`、`fail`、`error`、`pending_review`、`not_run`。应用终态 `completed`
只是必要条件，不代表任务已完成。每个案例还检查公开回答、所需修改、最终文件范围、
实际修改轨迹、尝试的写操作和写入时已经登记的范围。

当前案例的授权动作均为修改已有文件。删除、移动、越界写入尝试会导致决策检查失败；
即使被产品拦下，也不能算 Agent 决策正确。实际文件变化另行判定，包含改后恢复原状的
过程。对要求精确替换的任务，额外改动同一路径的其他文字也判失败。

语义规则有明确的人工评分标准；未复核或不确定不计成功。复核人需要实际阅读证据，不能
根据程序的通过项补签语义通过。首批没有自动模型评委，避免把未经校准的评委判断变成
产品通过结论。

成功率以本次计划的全部尝试为分母，报告另列执行数、未运行数与各状态数。按场景、
案例、层次、变体分别汇总；同题重复次数展示稳定性。没有建立业务权重，不把不同案例
的算术平均解释成线上成功率。

## 对照与成本

四个变体固定使用同一在线模型和题目。`no_index` 去掉索引分区；`no_state` 去掉披露、
人物状态、时间线、线索和专名分区；`no_history_facts` 去掉执行事实说明，但保留公开
会话。按需读取仍然可用，因此对比的是辅助信息的实际贡献，不是绝对信息隔离。

当前方案与消融方案成功率相同，也可能有调用次数和上下文规模差异。反之，单次成功率
不同不足以确定原因，应结合重复运行与逐步证据。人工精选必要材料的诊断参照尚未实现。

每次模型请求分别统计系统提示字符数、消息 JSON 字符数、工具定义 JSON 字符数，并
记录上游实际报告的 token 与缓存用量。系统提示分区预算不覆盖全部消息与工具结果，
长上下文分析应观察整次请求。总输入 token 包含新输入、缓存读取和缓存写入，另列新输入，
避免把缓存命中当成上下文减少。字符数不冒充 token；任一请求缺用量时，该尝试的总 token
保持未知，不把缺失部分算成零。

案例的资料生成、准备步骤、失败尝试都计入执行成本。每成功任务 token 为全部已执行
尝试的总 token 除以成功数；用量缺失或没有成功时不计算。费用定价、跨任务资料复用的
成本摊销尚未实现。P50/P95 只描述本次样本，不是产品服务水平承诺。

## 复现边界与扩展

运行固定案例快照、源代码指纹、模型标识、任务限制和评分器版本。输入快照是产品应用
边界的实际输入；provider 内部默认参数和供应商模型版本可能变化，无法保证逐 token
复现。同题重复执行是必要的稳定性观察。

长程首例使用合成历史与一次失败分支，没有覆盖真实长篇作品、多轮在线任务累积、压缩
策略或服务重启恢复。后续扩展顺序：真实失败回流、按作品规模增长的成本曲线、资料
初态核对、独立保留集，再考虑模型评委及其人工校准。扩展时保持案例版本与报告可追溯。
