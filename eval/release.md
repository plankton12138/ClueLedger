# 上下文评测运行与验证

日期：2026-10-24。适用产品运行实现：0.8；下列核心基线与对照在此之前采集，用于评测器
自身验证，不随 0.8 能力变化重判。

## 可用能力

- 20 个固定案例，包含跨章定位、长参考、多轮纠正、改源、索引失效、失败续做、披露、
  声称与事实、参考注入、同名澄清、长历史及临时读取失败、资料空结果，以及 0.8 的灵感
  讨论／落实／未引用外溢与未装模块单轮引用；I6 增加只读展开的三例、明确禁止搜索与
  保存灵感的一例。
- 案例可预置灵感条目与已装模块，步骤可指定本轮灵感参考。
- 真实任务服务与工具链路；每题、每方案、每次重复使用独立作品及状态。
- 当前方案与三个分区消融方案，重复与交错运行、同题对比。
- 保存模型输入、工具详情、前后文件、差异、资料终态；离线重新判分与带证据的人工复核。
- 分场景覆盖与成本统计；缺失用量、待复核和未运行均明确保留。
- 默认从 `.env` 读取在线模型，支持单行引号与注释、显式模型覆盖；不改进程环境。
  显式 `--config` 可复用产品连接；两种模型来源在运行清单中分别记录。

当前入口见[运行说明](README.md)。原有在线功能验收脚本继续使用原判定口径。

## 在线基线

模型均为在线 **`deepseek-flash`**，使用产品 worker provider。核心基线与执行事实对照
是在默认模型入口调整前，读取产品配置运行；新增冒烟按当前约定读取 `.env`。每个核心
案例执行一次，评分器版本 `2`；基线最终结果采用保存证据的离线重新评分，没有填写人工
通过结论。

对照中，同次移除执行事实相对当前方案的输入 token 差异为 -38、+121；模型路径不同，
不据此得出稳定的成本优势。完整请求规模和逐项用量见对应 JSON 报告。

核心基线的两个失败均来自 `preread_delivered`：长参考与带注入内容的参考案例中，
应用记录声称前 2000 字或参考全文已提供，但首个实际模型输入没有对应原文。两题最终
要求的精确替换和范围检查均通过；注入案例没有发生被诱导删除，不将其失败解释为攻击
成功。缺口位于材料交付与读取记录的一致性，不能只看最终文本就将整题判通过。

披露、声称与事实、同名澄清三题的程序检查已执行，语义部分仍待人工复核。本次没有
人工校准集，不能把这些题记为通过。基线成功比例只描述这批小规模合成题，不代表真实
作者任务分布，也不用于承诺产品成功率或时延。

模型端默认值和实际可观察参数、代码及案例指纹、任务限制见各运行清单。原始模型输入与
正文证据保存在本机被忽略的 `evidence/`，报告可入库；迁移或共享报告时需另行携带证据
目录，不能仅凭报告 JSON 在其他机器重新核对全文。
