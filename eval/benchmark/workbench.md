# 运行评测工作台

工作台仅供本机评测，不挂到作者界面或生产服务。它读取仓库中的 Task，不修改 Task，也不会因为打开页面、查看证据或重判而调用模型。

## 启动

从仓库根目录执行：

```sh
uv sync
npm --prefix frontend ci
npm --prefix frontend run build:workbench
uv run --no-sync python -m eval.benchmark.workbench_api
```

打开 `http://127.0.0.1:8765/`。默认读取 `writing` 库和机器上已有的 T01 历史索引；新检出只有任务，没有假档案。可用 `--library 库ID=目录`（可重复）替换库配置，用 `--history` 指定 [P0 档案清单](workbench-index.md)，用 `--state` 切换本机运行档案目录。默认运行目录 `eval/data/workbench/` 与历史原件分离，均不入 Git；不要托管到公网或透过反向代理开放。

### 在线运行

不带 `--config` 时不能开跑，但可查询与复核已有档案。需要运行时，将 `--config` 指向选中 API Key 连接的线簿服务配置；推荐使用系统凭据存储，不在页面输入或随档案保存。订阅连接不开放给隔离 Runner，因为其刷新可能改变共享凭据。切换连接要用另一份配置重启工作台。

在「任务库」选正式 `writing / T01 r1`，进入「运行评测」。预检在临时副本核对配置、模型选择和空初态，不发送作者消息，也不探测供应商；点击开始后，Runner 再核对本轮独立作品、会话和模块库，成功后才向真实产品对话入口发送 Task 的作者原话。一次只运行一题；每次都使用新目录，不继承旧结果或人评。服务在档案落盘后清理临时副本；如界面提示清理失败，不要导出该副本。其他任务仍可浏览，但不能在线运行。

### 复核、重判和补证

- **人评**：核对该轮证据和判据后逐项提交，标注绑定当前证据摘要。旧证据的标注不能替代新证据；缺项保留待复核。
- **重判**：选择已有证据版本，只运行评测器，保留旧报告；不会开新轮。历史原始材料仍只读。
- **补证**：先停止正在使用同一个 `--state` 的工作台，准备符合 [证据契约](evaluator.md#本地证据包) 的纠正 JSON，再用下面的本地命令导入。Task 和 Turn 必须属于原运行；会追加版本并重判，不改开始时间或原证据。不要把含凭据的配置、原始服务日志或模型请求复制到纠正文件。

```sh
uv run --no-sync python -m eval.benchmark.workbench_api --repair RUN_ID --evidence corrected-evidence.json
```

- **复跑与比较**：复跑创建新的 Trial；比较显示模型、任务修订、初态和版本等差异。历史无法核对的字段标为未知，不把缺记录解读为相同；独立正文回归不算 T01 的通过。
