# hastings — 悬疑小说写作 Agent 应用层

tau 内核之上的**薄应用层**：装配（工具注册、system prompt、事件订阅）与落盘（Bible / 正文 / 审计）全部在此完成，`tau_agent` / `tau_ai` 零改动。设计说明见 [dev-notes/v0.1/DESIGN.md](../../dev-notes/v0.1/DESIGN.md)，AI 检索入口见 [dev-notes/README.md](../../dev-notes/README.md)。

## 子包职责

| 路径 | 职责 | 关键文件 |
|---|---|---|
| `bible/` | 账本域：数据模型与状态机、工作区六阶段生命周期、派生统计与审计、时间线检测 | models / store / state_machine / story_state / stats / audit / timeline_check |
| `tools/` | 小说写作工具集（**硬约束所在层**）：账本读写、正文、手法锁、时间线、阶段机；V2 项目下旧写工具（bible_upsert/write_chapter/method_lock/unlock/story_stage）经 `architecture_gate` 换为拒绝桩（Phase 17 T17.6） | bible_tools / chapter_tools / method_tools / timeline_tools / story_tools / architecture_gate / errors |

模型接入与选择入口：`provider_catalog.py` 提供公开目录，`server/model_access.py` 保存连接与当前模型，`server/provider_config.py` 管理配置与实例。`server/v2_agents.py` 与 API 共享同一 ProviderBook；前端入口为顶栏模型按钮与 `ModelSettings.tsx`。设计取舍见 [Phase 18](../../dev-notes/v0.2/phase-18-model-access.md)。

## 五焦点导航（读源码对号入座）

V2 七页作者工作台入口见 [frontend/README.md](../../frontend/README.md) 与 [前端构建笔记](../../dev-notes/v0.2/phase-17-frontend-workbench.md)。项目身份/正文缓冲在 `frontend/src/state/v2.ts`，业务事件在 `state/v2socket.ts`。作者模型按 0.3 范围**不交付入口**（计划 §9.1：移除 0.3 入口、注入与默认调度）：v2 已下线路由与前端页面，旧数据保留可备份回看；`interfaces/api/author_decisions.py` 作为 0.2 遗留模块保留但不再挂载。

Phase 15 的 V2 变更闭环见 [change-impact.md](../../dev-notes/v0.2/modules/change-impact.md)：`domain/changes/` 与 `application/workflows/{change_analysis,plan_revision,revision,review,rewrite,audit}.py`；HTTP 在 `interfaces/api/changes.py`，前端在 `frontend/src/components/ChangeCenter.tsx`。服务器通过 `uv run python -m hastings.server` 默认启用独立仓库，`--v2-db <路径>` 可指定作品库；默认路径与恢复规则见 [启动修复记录](../../dev-notes/v0.2/phase-19-default-startup.md)。项目直接在 V2 中新建，旧工作区迁移已退役。

Phase 16 的无状态工作者与持久任务见 [orchestration-context.md](../../dev-notes/v0.2/modules/orchestration-context.md)：`agents/{schemas,roles,coordinator}.py`、`application/contexts/`、`application/workflows/{agent_workflows,worker_job}.py` 与 `infrastructure/agents/tau_runner.py`。Job/事件在 `infrastructure/jobs.py`，API 在 `interfaces/api/agents.py`；界面入口为“变更中心→规划与生成任务”（`AgentWorkbench.tsx`），服务生命周期负责恢复与派发。真模型评测入口为根目录 [eval/v2](../../eval/v2/README.md)，不使用旧 Hastings 工具。

Phase 19 的常驻对话侧栏与显式创作周期见 [phase-19-chat-workbench.md](../../dev-notes/v0.2/phase-19-chat-workbench.md)：对话契约在 `frontend/src/api/chat.ts`（模拟与真实 API 同接口），后端事实源在 `domain/conversation/`、`application/services/{conversation_service,task_prep_service,task_projection}.py`、`infrastructure/conversations/` 与 `interfaces/api/conversations.py`（REST/SSE）。普通聊天没有写端口（tools 恒空），创作只能经 TaskDraft 显式启动映射到既有工作流，候选接受复用审阅规则；模型绑定快照随任务定格（`server/v2_agents.py`）。真模型走查入口 `eval/v2/chat_driver.py`。

0.3 的正文中心工作区见 [v0.3 开发文档](../../dev-notes/v0.3/README.md)（实施进度与偏差以该文档为准）：正文写入统一走 `application/services/publish_manuscript_change.py`（导入/保存/恢复/候选采用同一管线，证据核对与摘要失效在同一次提交内），操作回执与讨论投影在 `application/services/operation_service.py`、`application/workflows/operation_projection.py`；入口预约与无模型想法在 `application/services/entry_service.py`（`POST /api/v2/entries`），正文导入在 `interfaces/importers/manuscript_text.py` 与 `application/services/import_service.py`，手工修改副本在 `domain/manuscript/edit_session.py` 与 `application/services/edit_session_service.py`（保存序号 CAS 经 `CommitService.aux_mutate`；本轮章节清单：`POST /edit-sessions` 可带 `chapter_ids` 声明，首次保存自动入列，完成前清单内未保存的章报 `EDIT_SESSION_UNFLUSHED`；完成操作按确定性 op_id 先回放已提交结果再补关闭，关闭/归档失败重启后不再发版（V03-5.5）；修改稿快照 `EditSnapshot` 经 `POST/GET /edit-sessions/{id}/snapshots` 冻结 save_seq/选区/文本与逐段来源，确定性 ID 可在副本前进后回放；候选用进副本经 `POST /drafts/{id}/apply-to-edit-session`，只写副本并把写入段落标为 `agent`，候选转 `applied`，完成时把逐段来源压成区间写进操作记录 refs，`GET /operations/{id}` 可回读）；正式稿前进时按 `domain/manuscript/merge.py` 三方合并（干净叠加自动发布、重叠报 `EDIT_SESSION_MERGE_CONFLICT` 并由 `merge_choices` 逐处选择，选择进操作记录 refs），章版本历史在 `application/queries/chapter_history.py`，证据查询与人工重锚在 `application/services/evidence_service.py`，操作后的摘要/建议状态在 `application/queries/followups.py`，试写候选在 `domain/manuscript/drafting.py` 与 `application/services/drafting_service.py`（`/drafts`，采用按预览哈希走同一发布管线），可引用账本投影在 `application/queries/ledger.py`（`GET /api/v2/projects/{id}/ledger`）；统一图谱只读投影在 `domain/story/graph.py` 与 `application/queries/graphs.py`（节点/边带四语义层 truth/knowledge/disclosure/plan 与 M05 证据状态，固定到读取的 Commit，`GET /api/v2/projects/{id}/graphs`，无第二份可写事实）；人物图 `character_projection` 在同一投影上筛选——真关系（truth 层）与角色认知（knowledge 层）分开，作者全知或角色视角（角色视角隐藏关系 `true_state`），「截至某章」先经 `narrative/order.last_beat_of_node` 解析为章内末节拍再与 `at_beat_id` 走同一折叠路径、角色知情按获知事件过滤，未记录不合成「不知道」；端点 `GET /api/v2/projects/{id}/graphs/characters`（`perspective`/`at_beat_id`/`at_chapter_id`/`focus`）；线索图 `clue_projection` 在同一投影上只保留与线索相连的边——计划出现（`Clue.disclosure_plan` 落在结构内）与已在正文出现（`points_to` 所指事实的读者披露位置，复用 `views.reader_reveals`）分开报出，后文线索以 `within_position` 标出、无记录报 `missing`（合法缺口），端点 `GET /api/v2/projects/{id}/graphs/clues`（`at_beat_id`/`at_chapter_id`/`focus`，复用同一份 `position_map`）；账本直接保存在 `application/services/ledger_service.py`（`domain/story/canon/entries.py` 十种条目的类型化校验与 revision CAS），设定候选成组与部分确认在 `application/services/ledger_candidate_service.py`（暂存、假设拦截、依赖闭合），表单描述在 `application/queries/ledger_forms.py`（`GET /ledger/schema`），本书约定在 `domain/story/agreements.py` 与 `application/services/agreement_service.py`（`story.agreement` 版本化、同主题唯一生效、按 Commit 的 `AgreementSnapshot`；`GET/POST /agreements`、`PATCH /agreements/{id}`），背景装配在 `application/contexts/background.py`（六层材料，披露边界排在约定之后、核心之前；优先级裁剪、`omissions`/`coverage`/`versions`）与 `application/contexts/collector.py`（按 Commit 取材料、临时原文按需读、`render()` 共用；`GET /context/background`），试写经 `DraftingService` 按 `base_head` 取背景、讨论经 `ConversationService.background_provider` 追加系统消息，章摘要在 `domain/manuscript/summary.py` 与 `application/services/summary_service.py`（来源清单冻结、落地前核对、`POST/GET /chapters/{id}/summary`；失效改写保留正文），摘要任务化在 `application/workflows/summary_jobs.py`（`summary.chapter` 任务：排队/停止/重试，停止在提交前拦截），账本更新建议在 `domain/story/suggestions.py` 与 `application/services/suggestion_service.py`（提示词与严格 JSON 解析、`POST /chapters/{id}/suggestions`；候选组带 `origin`/`source`，采用前核对章基础版本，变化报 `SOURCE_NEEDS_RECHECK`），关联撤销在 `application/services/undo_service.py`（按 `operation_id` 对比 before/after/head 做段落级三方逆向；非重叠的后续修改保留、重叠逐处 `restore/keep`、`preview_token` 绑定预览；`GET/POST /operations/{id}/undo`），正文与关联账本对象经 `publish_manuscript_change.publish_commands(extra_changes=…)` 一次提交（同一 Commit 内逐对象 CAS，失败不留半套），提交层的并发条件在 `application/services/operation_service.py`（保留调用方 `old_revision_id`，不一致即 `MANUSCRIPT_BASE_CONFLICT`；求值基础由 `publish_manuscript_change.publish_commands(base_commit_id=…)` 按准备时快照给定），对话来源与工作台共享状态在 `application/services/operation_service.py`（`origin_conversation_id` 提交时固定归属）、`application/workflows/operation_projection.py`（按记录里的会话投影并校验归属）与 `application/queries/desk_state.py`（`GET /desk-state`：计数 + `recent_operations` + 权威 ID；前端 `frontend/src/api/desk.ts`），披露边界在 `domain/story/disclosure.py` 与 `application/services/disclosure_service.py`（章/节拍位置解析、读者与角色两通道、证据待核对优先、名称级扩大披露检测；`GET /disclosure-boundary` 与 `POST /disclosure-boundary/check`；采用改写稿时未授权扩大披露即 409），本地模型任务在 `local_model_service.py`，执行日志在 `interfaces/api/execution_log.py`（`GET /api/v2/execution-events` 与 `/stream`）。图谱交互与布局在 `frontend/src/state/{graphLayout,graphDirectory,graphLabels}.ts` 与 `components/desk/{GraphCanvas,GraphDirectory,GraphPanel,GraphDetail}.tsx`（拖动只写本地区、落定帧统一落盘、文字目录是无画布的等价路径，来源定位走 `GET /evidence-links?target_id=`）。对话意图三分在 `domain/conversation/intent.py` 与 `application/services/intent_service.py`（`POST /api/v2/conversations/{id}/intents`：只读分类、只认作者消息、讨论无写权限、同范围不重复审批）；全局上下文与原文覆盖台账在 `domain/revision/coverage.py` 与 `application/services/revision_work_service.py`（`revision_work`/`current` aux 记录原子读改写，`POST/GET /api/v2/projects/{id}/revision-work`、`/reads`、`/coverage/{chapter_id}`，五状态覆盖与读取区间，摘要不得记 `checked_unchanged`；预算与两轮修正上限随 V03-7.3）。前端写作台壳层在 `frontend/src/components/desk/`，状态不变量在 `state/desk.ts`；默认入口尚未切换（V03-8.6）。

Phase 17 的旧工作区迁移已按[未上线项目的退役决策](../../dev-notes/v0.2/phase-17-workspace-retirement.md)删除：不再提供迁移面板、slug 迁移接口、导入器或 CLI 工作区映射。旧写路径退役证明在 `tests/v2/server/test_legacy_write_unreachable.py`；V2 业务事件在 `server/v2_ws.py`，备份导出与恢复在 `interfaces/exporters/v2_package_exporter.py`，均保留。
