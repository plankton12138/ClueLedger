# v1.1 产品方案：全对话创作

日期：2026-11-03。状态：**方案已与作者确认，待实施**。运行版本仍为 1.0.8；v1.0.9 已实施 P0—P6，其 P7 验收并入本版，不再单独交付 1.0.9 版本号。本方案在 [v1.0.9 产品方案](../v1.0.9/README.md) 的拆门槛成果上继续推进。

## 1. 为什么要再改一版

v1.0.9 拆掉章节门槛后，作者仍面对三个思维压力点：

1. **全书构思仍是一段要作者亲自组织的文字。** 要写出「可继续发展的意图」，作者先要理解「核心处境」「从哪里开始」这些结构概念。
2. **模型按钮分散在作品链路的各输入旁。** 作者要理解「哪个按钮管哪类对象」才能求助。
3. **结构决定仍由作者做。** 建章、起标题、看方向建议、处理对齐，每一步都要求作者理解内部对象。

作者对本版的目标裁决（2026-11-03）：

- 减轻思维压力，减少人工维持对象。
- 对话栏作为修改内容的唯一入口。
- 作者不考虑任何行文结构问题，由模型分解；模型可以引导提问，作者也可以选择自由发挥。
- 正文也不允许任何手写，稿纸退位为阅读面。
- 不保留无模型时的手写兜底入口。

这实际上是 0.3 时期「2026-10-20 写作台再收拢裁决」已确立方向的正式兑现：对话是唯一操作面，稿纸彻底只读，模型的写操作一律先提议、作者的确认是唯一落盘通道。当年只撤了前端入口，后端语义没有跟上；本版在当前链路上把两端一起做实。

## 2. 本版固定的产品规则

1. **对话是作品链路唯一的输入面。** 设定、章节、正文、信息线相关的所有内容，都由模型在对话中产出，作者不手写任何作品内容。
2. **作者只有两种动作。** 在对话里说话；对模型产出的结果确认，或再说一句。
3. **稿纸只读。** 正文阅读面与页边索引沿用 v1.0.9 形态；修改正文回对话说一句。
4. **模型执行、作者确认。** 确认前不产生正式变更；确认后联合提交，可整体撤销。作者真相与已确认内容不被静默改写。
5. **结构由模型分解。** 建章、章节标题、方向建议由模型提出，作者确认或用一句话调整。
6. **无可用模型时作品链路不可用。** 界面如实说明需要先完成模型设置，不提供绕过对话的手写路径。可用模型是产品的前置条件。
7. **范围边界。** 本版只收敛作品链路；灵感速记与模块库是独立素材工具，保留现状手写输入。
8. **索引机制维持 v1.0.9。** 信息线从正文生长、候选确认入账、空章温和提示，全部不动。

## 3. 起步：设定是聊出来的

新作品直接进入对话，不出现意图输入框。两种起步模式：

- **引导提问**：模型一次只问一个问题，每个问题可跳过，随时可以说「就这样开始」。问题数量有上限，不追问时间线、人物关系这类内部属性；未知保持未知，不为生成完整大纲而补造答案。
- **自由发挥**：作者给一句话（甚至只给题材和氛围），模型直接产出一版设定。

两种模式都汇聚到**设定卡**：模型把对话内容整理成一段可继续发展的作品意图候选，在对话中呈现。作者只有两个动作：确认开写，或继续聊。确认后服务端写入作品意图，门槛通过。

门槛本身不变：作品意图非空即可写任何章节，校验位置与对象都不动，只换意图的来源——从「作者填写」改为「对话确认」。

## 4. 正文：只由模型写

- 空正文章节在对话中提供两个起步入口：**由模型起草**、**看看方向建议**。方向建议只是参考文字，不进入正式数据。
- 已有正文的正文面是阅读与核对面：阅读渲染、页边索引（已写入、正文新增候选、需要对齐）、双向定位全部沿用；「让模型续写」并入对话任务。
- 想改正文，回对话说一句，模型执行后回显差异，确认后落盘。
- 空章反馈保留：「本章还没有可核对的信息变化」温和提示，「让模型看看本章」改为对话任务发起。

## 5. 修改闭环：对话是唯一入口

一次修改的完整闭环：

1. 作者在对话里说一句改动（「把雪夜改成台风天」）。
2. 模型分解影响：涉及哪些章、哪些信息线。
3. 模型执行修改，结果先进暂存，不产生正式变更。
4. 对话回显差异三要素：改了什么、影响哪里、基于哪个修订。
5. 作者一次确认 → 联合提交，可整体撤销；或驳回 → 暂存丢弃，可以再说一句。

配套规则：

- **全书设定页变为只读投影**：显示当前意图、章节顺序与信息线概览，附「在对话里继续调整」入口，不再提供意图编辑框。
- **候选确认与对齐处理保留一键操作**：那是做判断，不是组织文字；同样支持在对话里用一句话处理（「蓝蜡留到第十二章再决定」）。
- **对话历史不是正式设定**：正式数据仍由确认写入，不从聊天记录猜最终决定。
- **暂存正文不触发语义索引**；确认落盘后才进入索引分析，防止未确认内容被当作已入账信息。

## 6. 结构：模型分解，作者点头

- **建章**：稿纸读完后说「下一章」，或模型在章末建议收束；确认即建章（建章事务沿用）。
- **章节标题**：模型起草，作者可留空或回对话改。
- **方向与收束**：每章起步、推进与章末的参考意见都由模型在对话中给出。

## 7. 无模型的前置条件

不保留任何手写兜底。无可用模型时：

- 作品链路入口如实说明「需要先完成模型设置」，提供设置入口。
- 已有作品内容照常只读展示，索引照常可见。
- 不出现散布的禁用按钮，也不提供隐藏的手写路径。

## 8. 范围与取舍

### 8.1 纳入

- 对话式起步与设定卡确认。
- 正文面只读化与起草、续写的对话任务化。
- 修改闭环：暂存、差异回显、一次确认、联合提交与撤销。
- 建章、标题、方向建议的结构提议。
- 作品链路入口收敛与无消费者接口清理。
- 无模型前置说明。

### 8.2 不纳入

- 灵感速记与模块库的改造。
- 旧数据迁移；沿用 v1.0.9 原则，测试使用隔离新作品。
- 作者模型、修订学习（已顺延至 v1.2 预留）。
- 自动确认、自动连续生成多章。

### 8.3 已知取舍

1. **每次修改都经过一轮对话加确认**：换来的是作者零结构负担、零手工维持对象。这是本版的核心交换。
2. **产品完全依赖模型**：无模型即不可用。作者已明确接受，文档如实呈现。
3. **v1.0.9 刚建成的手写正文编辑器退位**：改动集中在前端入口与工具执行模式，服务端保存、锚点、联合提交机制全部保留复用。
4. **对话轮次成本上升**：所有验收用例都需要在线模型；按既有纪律执行单例复测。

## 9. 判断标准

第一轮从空作品连续走完：引导提问（或自由发挥）→ 设定卡确认 → 对话起草第一章 → 阅读面看正文与页边索引 → 说一句修改 → 回显差异 → 确认 → 撤销恢复。

成功的直接表现：全程作者不打开作品链路内的任何输入框（对话输入除外），不需要理解「章节构思、信息线、对齐」任何内部概念，仍能随时知道「这章写了什么、哪些信息已入账、哪句正文承载哪条信息」。若仍需理解内部对象或出现新表单，本版目标未达到。
