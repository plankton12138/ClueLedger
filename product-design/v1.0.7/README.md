# v1.0.7 产品方案：构思与线索简化

日期：2026-11-01。状态：已实施（v1.0.7）。开发入口见 [v1.0.7 开发计划](../../dev-notes/v1.0.7/README.md)。

## 1. 要解决的问题

目前作者需要同时理解构思节点、线索计划、正文观察、同步状态、知识层和多处线索入口。作者实际进行的判断更集中：这一段想写什么，正文写到了哪里，这条信息会让读者接近真相还是产生误解。

本版按这些判断组织界面。详细的来源、版本和核对依据继续由应用维护，避免作者为了管理写作过程而反复维护重复信息。减少入口和默认字段，同时保留处理复杂情节所需的正文关联、时间维度和线索关系。

## 2. 讨论依据与设计取舍

对话中已经明确的方向：

1. 写作时和线索查看时都区分真相与误导。
2. 正文与构思节点的绑定是必须保留的能力。
3. 构思与正文有差异时警告，并指引使用对话处理。
4. 保留类似甘特图的时间轴，禁止拖动修改顺序。
5. 保留线索之间的关系图。
6. 仅在作者主动点击开启讨论时建立对应讨论。

后续交互预览采用了「正文 / 构思 / 线索」三个入口、三种构思状态和按选择变化的详情区。本计划采用这一组织方式，并补齐预览没有覆盖的持久化、多人次操作冲突、真实对话、空作品、多次出现和大数据量情形。

本计划新增的具体落地选择：模块库移到全局工具区；作者的线索主用途保存在当前构思方案；默认右侧为所选内容详情，进入讨论后同一区域显示对话。它们是本版的实施方案，不将其描述为之前对话已经逐项确认的要求。

## 3. 三个主入口

| 入口 | 主区域 | 选中后显示 | 主要动作 |
|---|---|---|---|
| 正文 | 章节阅读与线索标记 | 当前段落的构思、线索与提醒 | 选段标记、查看构思、查看线索、讨论调整 |
| 构思 | 按披露章节分组的故事时间轴 | 构思内容、正文出处、相关线索 | 编辑构思、关联正文、定位出处、讨论调整 |
| 线索 | 关系图；无关系时显示线索列表 | 作者事实、读者可能理解、出现位置、关系 | 新建线索、改类型、登记关系、定位正文 |

模块库使用现有独立页面和返回位置能力，从全局工具区进入。目录按需展开，避免同时出现目录、主内容、详情、对话四个常驻栏。灵感的现有入口继续可达。

详情与对话共用辅助区域，但各自保留状态。切换章节或线索不会丢弃未发送的对话，也不会在后台改变本轮已经冻结的引用。窄屏将详情置于主内容下方；对话打开后提供返回当前内容的明确动作。

## 4. 线索：两个主用途，一个详情

「真相线索」表示作者希望它支持对事实的正确理解；「误导线索」表示作者希望它引导出不正确的理解。误导可以来自真实信息的错误解释，不等于原句是谎言。

接口和存储统一使用 `truth / mislead`，界面显示「真相线索 / 误导线索」。

- 每条线索有稳定身份；同名线索可以分别存在。
- 当前方案中只选择一个主用途，所有正文标记与线索视图同步显示。
- 事实和读者理解可以暂时留空，不能让模型为填写表单而补造真相。
- 尚未决定用途的模型观察可以保持空值，显示普通线索样式；它不是第三种可选分类。作者手动新建时直接选择两种用途之一。
- 同一条线索在多章出现时沿用身份，保留每一次真实出处。
- 同一句话承担多个线索时显示一个可展开标记，列出相关线索；不同节点可以关联同一段正文。

「埋设、提及、回收」描述出现过程，与真相/误导的主用途不同。默认界面撤除这些角色选择器；已有正文观察所需的历史信息在内部保留，不能把“回收”直接换算成“真相”。逐次出现的类型覆盖不纳入本版。

## 5. 时间轴：发生时间与披露位置分开

横轴回答故事里何时发生，纵向分组回答在哪一章告诉读者。第四章可以披露第一章之前发生的事。时间轴只支持选中和定位，任何编辑都在详情里进行。

一章可以有多个构思节点，一个节点可以关联多个章节。没有实际正文的节点按计划章节排列；已经绑定正文的节点使用实际出处，并在详情中列出全部位置。不能把预览中的“一章一个节点”写成数据限制。

精确时间、时间区间、瞬时事件和时间未定分别呈现。仅有“在某事之前”的关系时保留相对顺序，不能制造一个精确时刻或持续时长。未定时间的节点仍然可以选中、编辑和关联正文。

v1.0.7 采用统一的相对时间基准。例如将“案发当天 00:00”设为零点，“前一天 23:50”是 -10 分钟，“当天 00:10”是 10 分钟。界面显示作者能读懂的日期/时刻说明，内部使用相对分钟；“晚餐后”这样的描述只作为文字，不默认换算成某个钟点。基准标签可写明绝对日期，本版不增加绝对日期输入与自动换算流程。

## 6. 三种状态与提醒

| 状态 | 作者需要知道的事实 | 可进行的操作 |
|---|---|---|
| 就绪 | 当前关联可定位，且与最近一次确认的构思及正文基准一致 | 继续写作或修改 |
| 草稿 | 当前节点尚无正文关联，且没有适用的未解决核对问题 | 完善构思、关联正文或开始写作 |
| 需核对 | 关联内容变化、位置失效，或有尚未解决的核对结果 | 查看原因、讨论调整、稍后处理 |

“就绪”不等于应用证明了文学或推理上的完全一致。“稍后处理”只暂缓同一份提醒，状态仍为需核对；构思或相关正文再次变化后重新提醒。

“同一份提醒”由相关内容的稳定摘要判断。刷新页面、修改标题、改动其他段落或保存暂缓决定，都不产生新提醒；原片段、构思意图、关联目标或核对依据变化时，才重新提醒。时间戳只用于记录操作时间。

普通构思修改可以保存，并在影响到正文时留下提醒。只有版本已变化、目标位置不可信、修改范围不符等技术问题继续阻止写入。应用不能为了放行一次创作差异而覆盖作者新写的内容。

提醒只陈述已知事实。例如机械检查应提示“构思内容在上次核对后发生变化”。只有作者或核对结果提供了具体原文依据，才能展示“构思为22:10，正文为23:00”这样的具体差异。

## 7. 主动讨论与调整

作者点击「讨论调整」后，应用携带所选节点、正文片段、相关线索、具体提醒和当前版本开启讨论。首次请求只分析和提出建议。

作者可以选择修改正文、修改构思，或解释为什么保留差异。应用随后按明确范围提交实际修改，再重新读取状态；不能只改状态标签、只更新摘要，或直接用浏览器字符串替换模拟完成。

对话可以关闭、重开和恢复。同一提醒重复点击进入已有讨论；新的内容版本对应新的核对依据。用户明确要求全书核对时才扩大范围，默认不把全书材料塞进一次讨论。

## 8. 关系图的定义与交互

### 8.1 三类关系

关系表达作者指定的陈述或读者理解。说明中要写出比较的解释与必要前提，不能直接把证词当成已确认事实。

| 关系 | 含义 | 例子 |
|---|---|---|
| 支撑，A → B | A 增加 B 所表达陈述或解释的可信度；不等于证明 B | “存根签名与林舟笔迹一致”支撑“存根记录林舟 21:10 登船”的可信度 |
| 矛盾，A ↔ B | 在相同人物身份、时间和前提下，两个陈述不能同时成立；不直接判断哪一个真 | 在确认登船后无法及时返港的前提下，“21:10 离港”与“22:00 仍在旅馆”矛盾 |
| 共同误导，A ↔ B | 两条信息共同强化同一个错误理解 | 走廊证词与伞上的血迹共同使读者怀疑“林舟在旅馆伤人” |

两条线索共同指向某个结论，不自动构成有方向的支撑关系；需要说明 A 如何增加 B 的可信度。共同误导不要求两句原文都虚假，也不要求两条线索都被分类为误导；说明必须指出共同的错误理解。分别指向不同错误方向的两条误导线索，不因类型相同而自动建立关系。

预览中的停钟与船票支撑连线只提供了共同质疑时间记录的说明。正式样本需补足支撑方向的依据，或不登记这条边，不能把预览连线直接当作已验证关系。

### 8.2 最小交互

关系图展示已登记的「支撑 / 矛盾 / 共同误导」关系。每条关系都有说明，可附带正文依据；由作者明确登记，或由对话提出后采用。打开页面本身不调用模型推断。

1. 选择节点时更新同一个线索详情区，并突出其直接关系；其他线索仍可从列表选择。
2. 选择连线或列表中的关系项时，同一辅助区显示端点、类型、说明和出处。支撑显示箭头；另两类显示关系名称并采用无方向连线，颜色不承担唯一识别作用。
3. 从当前线索的「添加关系」选择另一条线索、类型、说明与可选出处；支撑明确展示“当前线索 → 目标线索”。所有必填项集中在这一处，不再增加独立关系管理页。
4. 修改、删除或撤销以真实回执更新；请求失败保留表单。图和列表都能打开同一份关系详情，键盘操作不依赖细小连线。

尚无关系时显示可用的线索列表和登记关系动作，不编造连线。线索较多时默认展示选中线索的一跳关系及完整线索列表，避免将所有节点缩成不可阅读的全图。图与列表使用同一份数据。

### 8.3 矛盾建议与试读

作者主动在讨论中要求核对关系时，可以得到带原文与前提的“可能矛盾”建议。作者明确采用后才登记关系；未采用的建议留在对话，不增加待办列表或第四种关系状态。同一人物在不同时间地点出现、证词含糊或身份未定时，应用不能直接判定矛盾。

作者查看“读者可能的理解”时可以看到主用途和作者事实；实际 `reader_preview` 仍只获得截止位置已经披露的内容，不获得作者分类、隐藏真相或未来关系。

## 9. 视觉与范围

采用预览的分区、主次和按需详情，正式实现沿用[现行视觉语言](../visual-language.md)中的阅读字号、基础控件与对话气泡。预览的绿灰配色不自动取代全应用视觉规范；本版不安排全局主题重做。

本版不新增复杂阶段筛选、知识泳道、线索档案独立页面、常驻状态统计条、全书后台自动审计或时间轴拖动。既有结构与写作能力的内部表达按真实调用保留，移除没有消费者的界面与专用接口。

对本轮补充建议的范围决定：

| 建议 | v1.0.7 范围 | 取舍 |
|---|---|---|
| 自动检测矛盾 | 在作者主动讨论中提出建议，采用后写入 | 复用已有核对链路，避免后台推断与持续误报 |
| 批量标记 | 保留单个连续选段的一次标记；多选片段批量分类暂缓 | 先明确同一身份还是多条线索，以及类型改动影响的全部出处 |
| 按类型将所有线索移动到节点 | 暂缓；后续如需批量关联，应保留既有正文出处与节点关系 | 节点与线索并非互斥归属，整体移动可能丢失关联 |
| 读者视角开关 | 暂缓新开关，完成既有试读上下文隔离的回归 | 完整读者视图还需按截止章过滤线索、出处、关系与详情；仅隐藏类型文字不能完成隔离 |
