# 1.0.3 全书构思总览与线索联动

日期：2026-10-30。状态：**1.0.3 已交付**。正式开发入口见 [1.0.3 开发文档](../../dev-notes/v1.0.3/README.md)。

## 为什么做这一版

作者实际测试后发现，构思按章节逐一生成节点，最终呈现为很长的单链。纵向画布改善了阅读和操作，但总览仍不能清楚表达多条叙事线如何推进、相互影响和共同收束。

本版把构思定义为全书的叙事结构总览，线索详情负责具体呈现和正文依据。目标是作者能够在总览中理解整体发展，再进入相关线索或正文处理细节。

## 作者看到什么

构思按故事阶段自上而下推进，多条叙事线横向并列。节点只显示关键行动带来的局面或理解变化，章节仍在正文目录中，通过关联查看。一章可以推进多个节点，一个节点也可以由多章实现。

每条线具有自己的目标、主要阻力和转折。跨线连接说明某条线取得的结果怎样改变另一条线的判断或行动；汇合节点只显示一次。各线不必同时开始、贯穿所有阶段或同时结束。

较长作品可以折叠阶段，保留该阶段的摘要与前后关系。展开当前阶段时，其余阶段保持简短。现有滚动条、完整全貌缩放和恢复 100% 继续使用，文字保持可读大小。

## 构思与线索怎样联动

| 作者操作 | 预期结果 |
|---|---|
| 点选构思节点 | 高亮直接相关关系，在下方查看关键安排 |
| 点击“查看相关线索” | 右侧切到此处涉及的线索，保留原构思位置 |
| 点选一条线索 | 高亮它在全书中的使用过程，展开具体呈现、创作意图与正文依据 |
| 点击线索中的一个构思位置 | 展开目标阶段并定位节点，保持可读缩放 |
| 点击正文依据 | 定位原文，返回时恢复构思选中对象和视口 |
| 将节点或线索带入对话 | 本轮修改围绕明确对象执行；浏览其他位置不改变运行任务 |

构思中，右侧未选择节点时可看全书线索，选中后看相关线索；正文中继续按本章和截止位置查看。沿用对话／线索栏位，不增加第四个常驻栏或独立故事资料页。

## 线索的计划与实际内容

同一条线索使用同一个稳定身份。作者真相、计划如何呈现、希望引发的理解和后续回应属于计划；正文引文、实际提及、埋设与回收属于观察，分开展示。

没有正文也能设计完整的线索使用过程，此时显示暂无正文依据。计划修改后列出相关位置需要重新核对；正文是否矛盾，需要结合原文判断。作者要求一起修改时执行相应范围，不能仅修改计划就显示正文已同步。

## 如何改善生成

生成先形成各条线的目标、关键变化、相互影响和收束，再细化线索使用。阶段和线的数量随作品决定，不强制所有故事使用同一模板。

已有正文按实际内容归纳；准备新增的冲突明确标为计划。真相、目的或结局尚未决定时保留未定。核对给出对应位置和具体问题，关注支线中断、缺少前提、无影响的并行安排，以及结尾新增决定性条件。

结构校验能验证引用和顺序，文学感染力仍需要作者阅读评价。线条数量与连线数量不作为“精彩程度”的替代指标。

## 范围

本版保留一份构思，继续通过对话修改、写作、定位和撤销。备选、比较采用、试读与独立候选正文均不恢复。

上下文容量与预算由 [1.0.2](../v1.0.2/README.md)负责，本版承接其限制和实际输入检查。修订学习、多人协作、任意层级编辑器、双时间轴和桌面端交付不进入本版。不做旧数据迁移。

## 交付判断

必须实际完成“生成多线总览 → 查看相关线索 → 定位另一处构思或正文 → 对话修改 → 保存重载与撤销”。界面样例与真实生成分别验证；在线模型只使用 `.env` 配置，保留失败和实际请求证据。完整标准见[验收计划](../../dev-notes/v1.0.3/acceptance.md)。
