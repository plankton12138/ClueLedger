# 构思与正文的页面设计

日期：2026-10-28。状态：**页面交互讨论稿，尚未实施**。作者已认可上一轮[线索结构与 Agent 全流程](structure-and-agent-lifecycle.md)的整体方向；本文继续细化页面呈现，具体控件与实现规格尚未冻结。

## 1. 一个创作工作区

写作页内部切换**构思／正文**，右侧保留同一个对话区。选中位置、当前方案、引用与输入草稿随切换保留，作者可以从一个安排直接进入文章，再回到原处讨论。

整体仍采用已确认的 [Aqua 视觉与布局](../visual-language.md)：银灰工具栏、清晰分栏、较大字号、平整正文底色，作者与助手分别使用绿色和银灰气泡。浏览器宽窗口是本轮对象，独立桌面应用继续排除。

| 区域 | 呈现方式 |
|---|---|
| 应用顶栏 | 作品选择、原有写作与模块库入口、设置；故事资料完全移除 |
| 写作工具栏 | 目录开关、构思／正文切换、当前查看的方案 |
| 中央主区 | 构思时显示分支结构，写作时显示关联正文 |
| 节点详情 | 选中后在结构下方展开，保持图和对话可见；不增加第四个常驻侧栏 |
| 对话区 | 当前讨论对象、生成内容、具体取舍问题与固定输入位置 |

构思时默认收起目录，把主要宽度交给结构；需要跳转片段或章节时再打开。正文模式在宽度允许时保留章节目录。对话沿用可调分栏，空间不足时切换视图，不通过缩小文字维持多栏。

## 2. 构思如何呈现

### 默认按揭示顺序展开

结构自上而下推进，多条故事内分支并列，汇合后继续向结局发展。用户先看到具体发生的事情和它们的连接，不先看到线索分类表、字段列表或推理参数。

每个节点默认只显示一句安排，如“林岚在遗书翻面前遮住一行字”。已有正文时附一个简短章节入口；需要处理时显示“待调整”。不为每张卡添加真假、置信度、来源类型等成组标签，也不通过红绿颜色把线索强分真假。

选中节点后突出它及直接相关连接；其余结构继续可读。节点可以承载人物行动、冲突和情绪，不要求每个节点都对应一条线索。

实际事件时间在节点详情中查看与调整，和揭示顺序分开。倒叙不会改写事件实际发生的时间。长篇的全书时间对照可后续细化，默认页面不同时铺开两套完整时间轴。

### 选中之后看什么

详情先显示当前安排和正文入口，再按需展开“真实作用与后续回应”，包含作者真相、此处希望引发的理解和后面如何解释。尚未决定的内容直接保留未定状态，不阻止讨论。

默认动作围绕当前任务选择：

- **调整这处**：将当前节点作为对话对象，作者说想怎样改。
- **写成场景／重写这段**：根据是否已有正文改变动作名称，使用当前方案和信息边界。
- **分出一条线**：从当前处讨论另一条故事内发展，保留共同结局或询问确实缺失的目标。

延伸、连接到某处、删除和试另一版放在次级操作中，不全部常驻工具栏。作者可以说“让这条线在照片这里汇合”，由 Agent 处理关系和相关安排；直接连线、拖动等作为可选辅助，不能成为完成创作的前提。

点击连线时说明两个节点为何相关，修改也沿用原对话。连线只是呈现所记录的关系，不能因为画出了连接就显示推理已经成立。

## 3. 两种分支在页面上分开

图中的多条线属于同一个故事，能够共同推进和汇合。

创作备选放在工具栏的方案切换中，例如“主方案 · 周衡作案”“备选 · 两人合谋”。切换后读取对应方案的结构和关联正文；查看备选不会自动将其设为主方案，也不会改变主方案数据。

作者说“试试两人合谋”，可以在独立备选里探索。需要采用时，显示实际将改变的关键安排与已有正文影响，在原对话中完成决定。局部采用先处理相关铺垫与依赖，不能只替换结局标题。

对比时仅展开本次有变化的部分，按需并列查看。日常页面始终突出一个正在查看的方案，不把多种互斥结局混画在同一条正式时间线上。

## 4. 正文与构思如何往返

从节点点击正文入口，中央切换为文章并定位相关段落；对话仍围绕原对象。正文上方提供“回到这处构思”，返回时恢复位置和选中状态。

选中正文中的一段，可以在对话中要求调整；已关联的节点随选择带入。多处正文共同实现一个节点时，按章节列出简短入口，不迫使用户合并成一段。

尚无正文时显示该安排与“写成场景”，不显示空白的证据表。生成时正文逐步出现，未完成部分保留为草稿；核对和提交完成后再建立实际正文关联。正式文章保持现有阅读和选段引用习惯，修改以对话为主要入口。

修改构思影响已写文章时，在当前节点与相关段落显示“待调整”。作者可以说“正文也一起改”或“先保留文章”，不需要自行找出每处依赖。点击“待调整”看到具体差异及其对应内容，不跳转独立影响管理页面。

## 5. 对话承担修改和任务操作

对话顶部只保留一句具体对象，例如“围绕：林岚提前遮住一行字”。模型执行期间显示本次已绑定的对象与方案。浏览其他节点不会暗中改变正在执行的任务；插话默认继续作用于该任务，要改处理目标时明确说明。

作者明确要求执行时，Agent 在范围内修改、核对并保存，完成后显示简短结果与**查看改动、继续修改、撤销**。只讨论方案时，候选提供“用这个”与继续修改，不把所有任务强制变成待确认表单。

需要取舍时，在原对话里给出一个具体问题和少量选项，也接受自由输入。例如“保留林岚无辜，还是将两人合谋作为独立备选？”不会把整套数据字段逐一交给作者填写。

任务状态只在发生时展示：

| 状态 | 可见反馈与操作 |
|---|---|
| 生成 | 实际内容流式出现，输入框可用，提供暂停；发送新要求即插话 |
| 核对或整理上下文 | 在同一任务中标明当前目的，展示模型的实际输出；暂停与插话保持一致 |
| 已暂停 | 保留已显示内容，明确已有提交与未完成部分，提供继续 |
| 完成 | 显示实际完成内容及查看改动、继续修改、撤销 |
| 尚有冲突 | 保留草稿与具体位置，给出可继续处理的选择；不显示全部完成 |

插话立即中断旧生成，后续按新要求继续。结果与改动记录以实际提交为准。材料来源、版本、模型使用情况与详细核对记录通过按需入口查看，不占据主要阅读区域。

## 6. 从空白开始与长篇使用

空白作品只需在对话中描述一个谜题、结局或片段。主区随着构思逐步出现节点，无须先建资料、填写类型、挂载模块或编好所有章节。

长篇默认按作者的故事片段折叠展示；展开某段时保留前后连接和通往结局的位置。目录用于跳转片段与章节，图内用于理解当前段如何推进，不要求用户在数百张卡片中持续缩放寻找。

结构先于篇章存在。章节目录随着写作形成，构思片段与章节可以是多对多关系。全书概览、当前段和具体节点是浏览深度，不增加新的创作概念或必填配置。

普通“预览到这里”展示已安排的呈现内容，不调用模型。“让助手试读”是明确的模型任务，使用独立的信息范围并在对话中流式反馈；两种动作不能混为一个不知是否调用模型的按钮。

## 7. 窄窗口

构思、正文和对话按视图切换，保持同一个任务与选中对象。点“调整这处”进入对话；点正文入口进入文章；返回恢复位置。文字保持可读大小，结构中较多的并行分支分组展开，不压缩卡片文字来强行塞下所有列。

对话暂时不可见时，正在执行的任务仍有简短状态和暂停／继续入口。作者不应为立即中断生成而先找回另一个页面。切换视图不触发新的模型调用，也不丢失输入草稿。

## 8. 本轮示意的边界

已制作的页面交互示意用于讨论构思、正文和对话的空间关系，以及选中、分支、方案切换、定位、暂停、插话与撤销的连贯性。内容和生成过程均为固定示例，没有接入真实模型或作品数据。

长篇折叠、精确连线、多节点选择、方案局部采用及完整输入记录等，以产品文字明确原则，不据此宣称原型或正式应用已经实现。具体首版范围与实施顺序见[开发计划](../../dev-notes/v1.0.1/development-plan.md)。

故事资料的导航、页面、专用任务和接口清理继续以[全流程讨论稿](structure-and-agent-lifecycle.md)为准；此次构思视图不会恢复旧资料管理页面。
