# 线簿 0.9：上下文用量与会话压缩

日期：2026-10-26。状态：**产品方案已确定，待实施**。目标发布版本为 `0.9.0`。
当前运行实现仍为 0.8；本方案不代表功能已经交付。
开发入口见[0.9 开发文档](../../dev-notes/v0.9/README.md)。

## 1. 为什么先展示用量，再接入压缩

作者需要知道当前会话还能携带多少内容，以及这段对话已经消耗多少模型用量。
前者影响接下来能否继续处理任务，后者帮助理解实际调用成本。两个数字分别计算，不能混用。

在此基础上，同版分阶段交付上下文压缩：旧讨论整理成可追溯的摘要，近期原始对话继续保留，
作品资料依照本轮用途和版本重新装配。压缩应当维持作者最新要求、任务状态与原文读取边界。

范围已于 2026-10-26 确认：**v0.9 先交付统计基础，再完成跨轮与轮内压缩**。
统计阶段通过不代表整个 0.9 已完成。

## 2. 输入框下方的两个入口

沿用当前对话布局，在输入框下方左侧增加两个低强调入口，发送与停止保持原位置。
参考作者提供的 DeepSeek Harness 截图，保留按需展开的方式，不复制其完整性能面板。

| 入口 | 常驻内容 | 点击后的内容 |
|---|---|---|
| 上下文 | 小圆环、预计占比；容量未知时显示预计 tokens | 预计输入 / 模型窗口、单色进度条、三项构成、回复预留 |
| 累计用量 | 本次对话已知的累计 tokens | 输入、输出、其中缓存读取；模型请求次数与模型用时 |

上下文构成只展示三项：约定与作品资料、工具定义、对话与工具结果。
摘要属于对话部分。回复预留单列说明，不算作已经使用的输入。

浮层向上展开，同一时刻只开一个；支持点击、键盘打开、Escape 与外部点击关闭。
内容随应用缩放，窄栏不得遮住发送、停止或编辑草稿的必要操作。信息不能只靠悬停才能访问。
正常状态保持中性色，接近输入预算时使用提醒色，并带文字说明。

本版不展示价格、首 token 延迟、输出速度、缓存命中率，也不新增独立统计页面。

## 3. 两种数字的含义

### 当前上下文

显示按实际装配规则生成的有效输入估算。运行中包含当前轮次的工具交互；本轮结束后，
按照下一轮能够恢复的公开历史重新估算，旧工具原文不跨轮累加。未发送草稿与未受理的临时参考不计入。

首次请求前显示“待计算”，不把空对话解释成系统约定与工具定义也不占空间。
每次真实模型请求前更新，完成后记录供应商实际输入用量；两者的时间与用途分别保留。
分项仍为估算时，不能因总量取得实测值而宣称每个分项都已实测。

估算量统一带 `≈`。模型容量未知时不显示百分比，详情提供模型设置入口。
切换模型、作品资料版本或任务用途后重新估算；旧请求的数字只能作为历史详情查看。

### 本次对话累计用量

累计本会话真实发生的模型请求，包括写作、检查以及本版新增的摘要调用。
重试、失败和停止请求只要返回可靠用量，同样计入；重复推送同一请求不重复计数。
模型列表发现、连接测试与其他会话的任务不混入。

输入包含缓存读取与缓存写入，输出包含协议已经计入的推理用量；子项不重复相加。
缓存命中不会减少上下文占用。模型用时是请求耗时之和，不是从打开会话到现在的时长。

切换模型和压缩后累计值继续保留，新对话重新统计。供应商没有返回用量时标注
“部分请求未统计”；不能按零处理，也不能将估算 token 作为实际消耗加入累计值。

## 4. 压缩应保留什么

| 信息 | 处理原则 |
|---|---|
| 作者要求与修正 | 保留最新有效要求、适用范围及原消息引用；记录被替代的决定 |
| 创作讨论 | 区分作者确认、助手建议、尚未确定与已经否定 |
| 操作进度 | 以应用实际保存、挂载、失败、停止和撤销事件为准 |
| 待回答问题 | 从问题记录恢复，保留问题与回答关联 |
| 正文与模块 | 保存定位、版本及重读要求，继续读取当前合法原文 |
| 修改授权 | 继续由作者原话和现有范围校验决定，摘要不产生授权 |

摘要用于继续任务，不自动成为故事模块、人物状态或正文。未来剧情与作者计划不能经由
摘要进入限定章节、限定用途的事实提取任务。原聊天记录继续完整展示。

## 5. 自动与手动整理

自动压缩属于作者已经启动的任务：在受理后的执行边界、工具结果收齐后的下一次推理前，
按预算判断是否需要整理。不会因打开会话、展开详情、刷新页面或服务重启而产生摘要调用。
这项自动行为是本版新增范围，不沿用旧版“完全没有自动压缩”的交付描述。

上下文浮层提供一个“整理上下文”入口。空闲时提交独立后台操作；任务运行中则登记到下一个
安全边界，同一请求键只受理一次。界面说明正在整理或等待整理，可停止，不逐项弹出确认。
无需压缩时返回“当前没有需要整理的较早内容”，不发起模型调用。

整理时在既有任务状态中显示“正在整理上下文”；完成后更新占用，详情可查看整理前后规模、
摘要和来源。摘要的生成用量计入累计用量，不新增常驻指标。

若整理失败，保留上一份有效上下文。仍能容纳请求时继续原任务；必要内容本身超限时明确报告，
保留已完成改动与未完成状态。溢出恢复只重试尚未执行的推理请求一次，不重做已落盘的工具操作。

错误格式沿用 `[错误码] 位置：现象。建议：…`，例如：

> [CONTEXT_REQUIRED_INPUT_TOO_LARGE] 对话上下文：当前请求与必要原文超过模型输入预算。建议：缩小本次处理范围，或选择容量更大的模型。

## 6. 版本边界

本版交付统计基础、跨轮摘要、轮内压缩、手动整理、溢出恢复、恢复与验收。
会话分支、任意位置回退、跨会话长期记忆、向量检索和自动整理作品资料不在本版范围内。

发布前须完成[验收矩阵](../../dev-notes/v0.9/acceptance.md)，包括在线模型的摘要语义保留验证。
实现阶段与已验证状态分别记录，不以交互示意、接口存在或单次模型通过推断完整交付。
