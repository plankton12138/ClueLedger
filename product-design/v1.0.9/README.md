# v1.0.9 产品方案：正文为主写作与从正文生长的信息索引

日期：2026-11-02。状态：**修订版方案，待实施**。本方案在同日由“每章最小构思门槛”修订为“正文为主”设计：全书构思是唯一写作前置，章节没有构思输入，信息线索引从正文观察。按先前设计实施的 P0—P5 记录保留在[开发文档](../../dev-notes/v1.0.9/README.md)及其 `notes/` 中；本方案落地前需要先执行门槛拆除改造。当前运行版本仍为 1.0.8。本方案承接[统一工作区研究](../research/plan-first-writing-design.md)与[真实可用性用例](../research/ideas-clues-usability-cases.md)。

## 1. 为什么要再次修订

v1.0.8 已经减少属性编辑，但正文、构思与线索仍由不同入口组织。作者必须先判断自己在操作哪一类对象，再人工维持计划、线索和正文的对应关系。v1.0.9 的目标是减轻写作时的思维压力，减少需要人工维持的对象。

最初方案把它落实为“每章先确认一句构思才能写正文”。这个设计有一个错误前提：它假设作者在写正文之前就能准确说出“本章要改变什么、包含哪些线索”。实际创作常常相反——作者先写出正文，再从正文看出这一章做了什么。章节构思门槛把系统应该替作者完成的观察工作，变成了作者要先交出的输入，与目标相反。

修订后的设计只保留一个前置：全书构思。它是作者唯一需要先写的计划性文字。章节不再有构思输入，创建章节即可写正文。线索、伏笔和回收由系统从正文观察：确定性锚点记录已确认信息线的准确原句，增量语义分析提出候选，作者确认后信息才正式入账。账本从正文生长，而不是先有账本再写正文。

这一版用可见性代替强制：不再要求“每章都有构思”来防止无目标写作，改为保存后提示“本章还没有任何信息变化”，作者可以继续写，也可以忽略。

## 2. 本版固定的产品规则

1. 撤除主导航中的“构思”和“线索”，作品内只保留一个“写作”入口。
2. “全书构思”与所有章节位于同一目录；不再建立独立的构思页或线索页。
3. 全书构思是唯一写作门禁：作品意图非空即可创建和编辑任何章节正文；章节自身没有构思输入，也没有确认环节。
4. 章节信息索引是正文的投影：已确认信息线的锚点随保存确定性更新，语义分析只产生候选；作者确认候选后信息才入账。
5. 线索、伏笔和回收伏笔统一为跨章的“故事信息线”；作者不预先规划本章线索，只确认从正文观察出的候选。
6. 采用已选定的“连续稿纸”方向：正文是主要内容，信息索引按段落出现在页边，不常驻第三张管理表。
7. 全应用所有会写入作品或其他创作内容的文本输入，都同时提供模型起草入口。
8. 模型输出默认是候选；作者已输入的文字不会被生成结果静默覆盖。
9. 保存后本章没有任何信息变化时，给出温和提示与“让模型看看本章”入口；提示不拦截写作。

搜索、筛选、文件路径和模型连接地址属于控制信息，不要求模型代填。作品名、章节名、灵感、模块内容、作品意图、正文、差异处理说明和对话指令都属于创作性文本，必须有模型入口。对话输入旁提供“给我下一步建议”，模型可以在作者尚未输入指令时提出可选操作，因此不会形成必须先写提示词才能求助的循环。

## 3. 唯一门禁：全书构思

### 3.1 全书构思

新作品只要求一段可以继续发展的意图：核心处境或冲突，以及准备从哪里开始。结局、真相、动机和章节总数都可以未知。作者可手写，也可选择“交给模型构思”；模型只能提出候选，不能把未知内容当作作者决定。

意图非空由服务端校验，不只是按钮禁用。直接编辑、模型起草、模型续写和外部请求都必须经过同一门槛；门槛的对象是作品，不是章节。

### 3.2 章节没有构思输入

章节只保存顺序、可选标题和正文文件。创建章节即分配正文文件并可以开始写作，不需要先说明“这一章要改变什么”。

空正文提供三个起步入口：

- 自己写第一段：默认状态，直接进入稿纸。
- “由模型起草”：依据全书构思与已完成章节生成正文候选。
- “看看方向建议”：依据全书构思与已完成章节提出这一章可以往哪走的参考文字；建议不进入任何正式数据，作者看完直接写正文。

### 3.3 空章反馈

保存后，若本章没有任何信息变化——没有新的已确认信息线、没有待确认候选、已确认信息线也没有新出处——页面给出温和提示，并提供“让模型看看本章”入口。这是反馈，不是门禁：作者可以继续写，也可以忽略。空章是合法状态，不要求补足。

## 4. 一套写作工作区

### 4.1 顶层与目录

顶部只显示“写作”和仍然独立的全局能力，例如模块库。左侧目录第一个项目固定为“全书构思”，下面按顺序显示章节。旧的 `mode=story`、`mode=clues` 和 `mode=chapter` 链接回落到同一写作工作区，不保留隐藏的旧页面。

### 4.2 选择全书构思

主区域显示：

- 一段当前作品意图。
- 章节顺序，每章显示已入账的信息变化。
- 故事信息线在各章的变化与已有正文出处。

没有属性表、关系图或完整度面板。选择一条信息线时，在同一主区域展开跨章过程；需要建议时打开对话，由对话替换辅助区域。

### 4.3 选择空正文的章节

主区域直接是可编辑的空白稿纸，不做构思确认：

- 顶部一行显示来自全书构思的当前起点。
- 自己开始写是默认状态。
- “由模型起草”与“看看方向建议”作为起步入口提供。
- 模型候选出现后可以采用、局部修改或重新生成；采用候选与保存正文是两个明确动作，生成完成本身不写文件。

### 4.4 选择已有正文的章节

默认使用连续稿纸：

- 中间是可直接编辑的正文，不在阅读器和编辑器之间来回切换。
- 与段落相关的信息在页边对齐显示；点击索引定位原句，点击正文标记回到信息项。
- 页边索引只显示从正文观察出的信息：已写入、正文新增（候选）、需要对齐；不显示长期空分组和统计条。
- 对话打开时占用同一辅助区域，不增加第四栏；关闭后回到原信息项。

宽屏时页边索引贴着对应段落；中等宽度时索引成为可开合的右侧辅助区；窄屏时信息项紧随相关段落或从稿纸逐层进入。任何尺寸都只保留一个主要写作面。

### 4.5 章末反馈

“完成本章”不是状态表单。执行时只列需要作者判断的项目：待确认的正文新增候选、需要对齐的信息线差异；本章没有信息变化时，提示与空章反馈一致。每个需要文字回答的处理动作同样提供“请模型给出处理建议”。

## 5. 模型辅助是每个创作输入的并行路径

| 输入位置 | 人工路径 | 模型路径 | 采用规则 |
|---|---|---|---|
| 作品名与作品意图 | 直接输入 | “交给模型构思” | 候选进入输入区旁，不自动建作品事实 |
| 章节标题 | 直接输入 | “请模型拟标题” | 候选填入标题输入，仍由作者保存 |
| 空白正文 | 直接写第一段 | “由模型起草”“看看方向建议” | 起草返回正文候选与绑定建议，不自动写文件；方向建议只是参考文字 |
| 已有正文 | 继续手写 | “让模型续写” | 以当前光标与全书构思为边界，候选可局部采用 |
| 改稿说明 | 直接说明目标 | “请模型建议改法” | 建议与实际写入分开 |
| 章末差异 | 直接决定 | “请模型给出处理建议” | 不能替作者确认真相或删除内容 |
| 对话指令 | 直接输入 | “给我下一步建议” | 先列可选指令，选择后仍由作者发送 |

模型入口始终可见。没有可用模型时，入口保持可见但禁用，并说明需要先完成模型设置；人工路径不受影响。生成进行中仍允许作者继续输入。若作者在生成期间修改了内容，结果作为旁置候选返回，不能覆盖新文字。

每次生成绑定目标、全书构思修订、正文摘要和请求键。同一目标只保留一个活动生成；新生成取消旧请求。旧修订生成的结果标记为过期，可以比较，但不能直接覆盖当前稿件。

## 6. 正文与信息线

### 6.1 全书构思进入写作上下文

- 起草、续写、改稿和方向建议的模型上下文包含全书构思、已完成章节的摘要和直接相关信息线。
- 修改全书构思不自动改写正文；正文依据旧意图写成的内容，由对齐候选提示。

### 6.2 正文生长出信息线

- 已确认信息线的原句移动、删除或恢复时，绑定随正文保存立即更新。
- 手写正文出现可能重要的新信息时，索引给出候选；作者确认后，同一联合提交创建信息线（若候选未指向已有信息线）与绑定，可以整体撤销。
- 确认入账不修改正文原句；入账只是建立“这句正文承载这条信息”的正式记录。
- 正文和已确认信息线冲突时，呈现具体差异，不默认选择任何一方覆盖另一方。

### 6.3 对齐与有意信息差

- 正文与已确认信息线矛盾时，索引给出“需要对齐”候选，指出具体原句与具体信息线。
- 有意谎言、角色证词与作者真相的信息差不判为普通冲突；作者判断后可以豁免，豁免本身不修改正文。

### 6.4 实时的范围

实时表示保存后无需刷新，并且页面只展示最新修订：

- 已知锚点的移动、删除和恢复使用确定性计算，与正文保存同步完成。
- 模型生成的正文在同一次候选中携带绑定建议；采用时服务端重新核对原句和当前修订。
- 手写新内容在停止输入或保存后进行增量语义分析；连续输入合并，过期请求取消，不按每个按键调用模型。
- 语义分析失败不阻止正文保存。索引明确显示未更新，不能沿用旧结果冒充最新状态。
- 自动分析只能提出索引候选，不能修改正式信息线或正文。

## 7. 故事信息线与信息索引

故事信息线是跨章稳定身份，例如“湿手套为何仍在滴水”。它由确认候选入账创建，也可以由作者直接建立。每条信息变化记录它发生在哪一章、原句是哪句。内部可以推断引入、加强、转义、否定和回收等作用，但这些不是作者必须选择的字段。

章节信息索引只显示当前有内容的部分：

- 已写入正文：已确认信息线在本章有一个或多个准确原句。
- 正文新增：达到信息意义阈值、尚未确认的候选。
- 需要对齐：某句正文使某条已确认信息线不再成立，排除有意谎言和披露差异。

同一信息多次出现要保留多个出处。关键词相似不能建立绑定。作者真相、角色说法、读者已知内容和模型推测继续分开，即使界面把它们放在同一条信息线附近。空列表是合法结果，由空章反馈温和提示，不强制补足。

## 8. Aqua 视觉方向

本版在现有银灰与蓝色基础上加强经典 Mac OS X Aqua 的结构特征。参考资料强调 Aqua 的直观操作、明亮色彩、顶部受光的半透明与光泽控件，以及银灰材质中的层次感；v1.0.9 采用这些原则，但不仿造系统窗口或牺牲正文可读性。参考：[少数派《Mac 视觉史（三）：浴“水”重生的 Mac 视觉美学》](https://sspai.com/post/60888)。

- 顶部与工具区使用有层次的银灰材质，正文保持低干扰的浅色稿纸。
- 主操作使用蓝色高光按钮；普通操作保持银灰，按下时有清楚的内陷反馈。
- 选中项使用浅蓝到深蓝的层次，不靠额外状态说明重复解释。
- 输入框、分段按钮、滚动条和进度反馈使用一致的顶部高光、内边线和圆角。
- 光泽集中在操作控件，不给每个内容块添加高光卡片；长篇正文优先于装饰。
- 不绘制假的红黄绿窗口按钮；若宿主窗口已有原生标题栏，就不再复制。
- 所有状态都保留键盘焦点、足够对比度、200% 缩放与减少动态效果支持。

完整组件规则见[视觉实施规范](../../dev-notes/v1.0.9/style-document.md)。

## 9. 本版范围与取舍

### 9.1 纳入

- 单一写作导航、全书构思与章节目录。
- 全书构思门槛及服务端正文写入策略。
- 同页正文编辑、自动保存和连续稿纸布局。
- 故事信息线、章节信息索引、候选确认入账与增量同步。
- 空章反馈。
- 所有创作性文本输入的模型辅助候选。
- Aqua 视觉系统收敛与响应式行为。
- 旧构思、线索页面及无消费者接口的撤除。

### 9.2 不纳入

- 旧数据迁移；v1.0.9 使用新建的当前格式数据。
- 章节构思输入、章节确认环节和门槛页。
- 关系图、时间轴、评分、完整度仪表和独立线索管理页。
- 自动生成整本章节、自动确认作者真相或自动修改已有正文。
- 把所有正文按键实时发送给模型。
- 修订学习与长期写作偏好，继续留在后续版本。

### 9.3 已知取舍

- 正文起草的模型上下文变薄：没有章节构思作边界，起草与续写更依赖全书构思、已完成章节摘要和相关信息线；“看看方向建议”部分弥补。
- “每章都有信息变化”从硬保证变为提示：空章反馈不能阻止无目标写作，只让它可见。
- 已按章节门槛实施的后端与前端机制需要拆除重建；确定性锚点、联合提交、撤销、候选、增量分析和 Aqua 视觉全部保留。

## 10. 第一轮判断标准

第一轮先连续完成真实用例 UC-P01—UC-P06：从空作品建立意图、直接写第一章正文、容纳计划外信息、确认候选入账、处理锚点移动并走完章末反馈。若作者仍需理解内部对象或频繁切换页面，本版目标未达到；不能用增加字段和新页面解决。

成功的直接表现是：作者只写全书构思和正文，仍能随时回答“这章写了什么、哪些信息已经入账、哪句正文承载哪条信息、还有什么待判断”，而不需要维护另一套线索账本。
