# 0.5 人物文件、上下文与对话阅读

作品继续采用本地 Markdown 目录；人物小传改为一人一文件，让作者能独立查看人物，也让模型按当前写作对象读取材料，减少每轮自动携带的人物全文。

角色文件位于 `设定集/角色小传/姓名.md`，别名和化名保存在同一份小传。左侧在设定集中提供可展开的人物列表；点击只读查看，增删改经对话完成。线索和真相仍各一份固定文件，正文仍一章一文件。

不保留旧版汇总小传格式，不做迁移或兼容层。角色改名不隐含修改全文人名，删除小传不隐含删除正文人物；需要联动时由作者明确提出，模型读取受影响材料后修改。人物变化参与搜索、Git 差异、记录和撤销。

当前实现见[模块说明](../../dev-notes/v0.5/modules/README.md)。对话阅读的流式、Markdown、默认折叠过程与基础阅读操作已接入，契约见[模型对话框计划](../../dev-notes/v0.5/chat-experience-plan.md)，验证范围见[运行说明](../../dev-notes/v0.5/release.md)；预选项、专用可视化和上下文压缩暂不做。

## 材料定位与作者可见信息

长篇写作先解决「该读取哪些材料」和「哪些信息仍然有效」。章节索引辅助定位，关键细节返回原文核对；索引记录来源版本，源文件变化后明确标为过期，不能继续当作当前依据。作者主动生成或更新索引，打开、刷新和过期检测不自动启动模型。

正文入口与稿纸统一显示「第几章 + 章名」，书名保留在作品层；缺章不导致后续章序变化，序章、尾声和番外保留名称。人物列表与小传顶部显示侦探、助手、凶手、嫌疑人、受害者标签，可多选或无标签，来源保存在人物文件中。凶手表示作者确认的真实身份，不代表正文已披露；聊天假设不能直接成为身份标签。

本轮材料是待实施目标：对话输入区区分当前打开的文件和作者指定参考，发送后固定本轮材料。添加文件可选，作者也可以直接在对话中指出参考；参考不代表允许修改。界面区分候选材料、部分读取和完整读取，不因选中了文件就宣称模型已读。旧聊天、摘要与作品文件发生冲突时，结合当前明确要求和原文处理，无法确定时由作者裁决。

章序与人物标签的实现以当前模块说明为准。尚未实施的材料引用、章节索引与来源核对由 [0.6 上下文与文件操作开发计划](../../dev-notes/v0.6/context-and-file-operations-plan.md)承接，并增加本轮修改范围和明确请求的写后检查；模块示例、阶段顺序与验收统一在该计划维护。该计划不交付会话压缩、全书自动总结或跨会话聊天共享，也不代表当前能力。
