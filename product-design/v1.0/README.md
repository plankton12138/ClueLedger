# 1.0 产品记录：悬疑线索设计与写作联动

日期：2026-10-28。状态：**原实现已完成自动验证，产品体验问题仍待处理，独立人工签收未执行**。

当前主包与前端为 `1.0.0`。本页记录原版方向与现状；新讨论的分支时间线已独立放入[1.0.1 想法占位](../v1.0.1/README.md)，具体开发计划后续编写。

## 原版目标与实现

原版围绕正文中的线索，连接原文依据、作者计划、推理核对和对话改写，帮助作者查看线索出现在哪里、当前依据支持什么，以及修改后哪些内容需要复查。

| 能力 | 原实现内容 |
|---|---|
| 线索记录 | 稳定身份、按章贡献、有效性与整理覆盖 |
| 本章与详情 | 本章提及、正文依据、作者计划与推理目标 |
| 原文定位 | 对应版本的引文定位、失效说明与返回位置 |
| 构思关联 | 作者计划来源关联、保存目标与多线索关系 |
| 核对与讨论 | 依据指定目标核对，引用线索进入对话，按要求修改和复查 |
| 恢复 | 浏览器阅读位置、当前格式作品状态与备份恢复 |

实现和验证证据见[开发入口](../../dev-notes/v1.0/README.md)与[S8 记录](../../dev-notes/v1.0/notes/S8-web-delivery.md)。这些记录说明原实现，不代表后续产品想法已经交付。

## 已发现的体验问题

- 作者此前要求取消故事资料板块，当前入口和页面仍待撤除；视觉方案或历史记录不能作为重新保留该板块的依据。
- 计划关联、推理目标、意图、前提与其他解释的配置过于复杂，现有流程未能体现先构思故事结构、再展开正文的创作顺序。
- 所有模型节点的过程可见性与控制需要统一；已有停止能力不等于已经支持立即暂停后继续、运行中插话。

反馈与后续归属见[原讨论入口](interaction-redesign.md)。本次登记新版本不自动关闭这些问题或把 1.0 标为完成。

## 继续保留的原则

正文观察、人物表述、作者计划和模型判断分别处理。引文存在不证明某个解释成立，人物证词不能直接当作客观事实；有意误导和保留多种解释本身不是错误。

原文定位核对真实版本与范围。浏览不扩大写作权限，模型检查不隐含改稿；讨论构思后由作者明确要求保存或修改。

对外名称为线簿 / ClueLedger。桌面端暂不纳入当前范围，旧数据不迁移；真实模型评测使用 `.env` 在线模型。
