# 1.0 产品方案：悬疑线索设计与写作联动

日期：2026-10-27。状态：**已确定优先级，开发计划已制定，尚未实施**。目标发布版本：**1.0.0**。

作者决定优先完成悬疑创作能力；原「修订学习与写作偏好」顺延为 [1.1 预留计划](../v1.1/README.md)。
当前代码包为 `0.9.0`，处于发布候选；制定本计划不修改运行版本。
开发安排见 [1.0 开发入口](../../dev-notes/v1.0/README.md)。

## 1. 本版要解决的问题

线索、身份披露、事件的信息性质与检查记录已经存在，但作者需要分别翻资料和历史对话，
难以持续判断一条线索写到了哪里、希望推出什么、当前依据是否足够，以及接下来该怎样修改。

本版以同一条线索连接「正文依据 → 读者已见 → 作者计划 → 推理核对 → 讨论与改写」。
创作讨论能够设计线索的不同解释及后续验证，检查能够指出推断缺少的前提，界面能够定位实际原文。

核心验收样本：林岚说出遗书背面的内容，作者希望借此揭示她提前接触过原件。
系统需要区分人物的表述、作者设想与已给读者的依据，并识别照片、转述等其他来源。
新增「警方此前公开过背面照片」后，能够找到相关推断并提示重新核对；是否保留误导由作者决定。

## 2. 作者使用流程

1. 阅读或写作时，在现有右侧区域切换「对话／本章线索」，原对话和输入草稿保持可继续。
2. 选中线索，阅读正文依据、读者已见和折叠的作者计划；点击依据定位正文。
3. 尚无记录时，区分尚未整理、已整理无发现、材料不足和来源已变化，按需整理本章。
4. 在详情中关联已有作者计划，或带入对话构思目标、表面解释、其他解释与验证安排。
5. 明确发起「核对推理」，查看目标结论、已使用依据、必要前提、其他解释及未覆盖范围。
6. 点击「讨论设计／讨论修改」，将精确线索、原文、计划与问题加入消息草稿，作者继续输入后发送。
7. 作者要求修改时，沿用现有对话写作与范围登记；完成后显示相关依据需重新整理或核对。

纯讨论和浏览不保存创作设定、不调用整理或检查模型。作者明确要求保存构思时，沿用作品内模块保存，
不增加每条线索必须逐项确认的表单。

## 3. 页面与呈现

| 位置 | 呈现与行为 |
|---|---|
| 写作页 | 目录、正文与辅助区；辅助区共用「对话／本章线索」，按需打开 |
| 本章线索 | 列本章有效提及、推进或回收的线索；不仅列本章首次埋设的线索；旧失效记录可查看 |
| 线索详情 | 标题下显示埋设、回收计划和状态；正文依据在前，读者已见随后，作者计划折叠 |
| 正文依据 | 章、引文与来源性质；人物表述、推测、回忆保留性质，不能直接升级为真实经过 |
| 推理核对 | 目标、缺少的前提、其他解释、反证和覆盖；每条判断能定位所用来源 |
| 故事资料 | 保留「线索与伏笔」，集中查看全书；与写作页共用详情，不另建故事总览 |
| 对话 | 引用明确的线索和问题，正文与设定的实际写入仍通过现有写作流程 |
| 窄屏 | 正文与详情按需切换，提供返回原文与焦点恢复；不靠缩小字或横向挤压容纳三列 |

默认不铺开全部线索、不常驻全部原文高亮；选中有效依据后才定位和突出相应段落。
信息通过分区和顺序说明，颜色仅辅助；不增加悬疑评分、通用仪表盘或固定大图谱。

原型仅用于讨论交互。示例小说、检查结果、数字及模拟整理不能成为生产初始数据或已交付证据。
界面按钮以真实服务接通为开放条件；不存在能力时不显示可操作占位。

## 4. 必须区分的内容

| 内容 | 含义与使用边界 |
|---|---|
| 正文观察 | 在某版原文里存在的描述或表述；引文存在不证明其解释成立 |
| 读者已见 | 截至所选章已呈现的信息及其性质；不宣称读者一定相信或已经推理出来 |
| 作者计划 | 当前作品模块中的目标、真实作用、误导与回收安排；单独显示与读取 |
| 推理判断 | 模型依据指定目标、材料与范围形成的判断；有来源、可纠正，不是客观真相认证 |
| 线索状态 | 未回收、已回收、已废弃；与整理覆盖、来源有效性和检查运行状态分开 |

一条线索可以只引起怀疑，多条线索共同完成一个推断。系统不要求每条线索单独证明凶手，
也不要求每条线索同时支持所有嫌疑人。保留多种解释可以是作者的目标；只有目标要求收敛时才提示未排除的解释。
目标尚未确定时允许先构思，不把缺少目标归为作品错误。

## 5. 时间、浏览与写作边界

- 当前阅读文件、资料「查看截至第 N 章」、本轮任务的披露截止章分别保存。
- 跳转原文只改变阅读位置，保留所选线索和资料浏览时点；浏览不更改写作任务范围。
- 正文观察逐条按依据章过滤，回收在后章发生时，前章视图不能出现后章回收引文或状态。
- 作者计划可包含未来安排，必须单独标明；其正文不计为读者已见，也不用于证明推理前提已交代。
- 写前按目标章节重新装配正文观察和披露状态；引用未来资料不能扩大正文写入权限。
- 故事发生时间与叙述章序分开；倒叙和证词里的时间不凭章号推成客观先后。

程序核对版本、引用和章界；表达中的等价泄露还需在线案例核验，不宣称确定性保证无剧透。

## 6. 构思与核对的最小深度

每个关键推理步骤可以关联多条线索，记录：目标结论、正文支持、必要前提、其他解释、验证或排除安排。
这些关系由对话整理，作者仍可用自由正文保存模块；不要求普通模块改为类型化表格。

构思输出应说明方案需要补什么、何时给读者、如何改变人物表现；作者明确保存后才成为计划。
核对仅检查作者指定的结论和已选范围，不自动设计凶手、修改谜底或将推测当作设定保存。
检查结果允许：发现有依据的冲突、发现待核对疑问、在本次范围未发现问题、部分完成、失败、停止。
有意误导、人物误信及开放解释本身不是错误。

## 7. 交付范围与后续

1.0 必须交付：稳定线索身份、按章贡献与有效性、共享详情、本章入口、原文定位、作者计划关联、
一个推理步骤的构思与核对、引用草稿与真实请求、变更后复核、在线语义及桌面升级验证。

本版不包含完整角色认知系统、全书唯一解证明、自动全书改稿、密室空间求解器、关系图谱恢复、
作者习惯学习或模型参数训练。人物身份披露继续沿用，线索中的人物表述按具体来源展示。
完整全文一致性审计仍见[后续设计](../future/consistency-audit-design.md)；本版只纳入与线索目标有关的核对。

1.1 保留直接改稿、差异、人工修订证据与写作偏好学习。其面板接入本版已有辅助区，
不替换线索详情或改变本版的阅读、浏览与任务章界。

发布依据见[验收与在线评测](../../dev-notes/v1.0/acceptance.md)。
