# 模型自主组织与维护模块

日期：2026-10-25。状态：**核心能力与结构化作者提问已按实施方案落地，确定性测试与在线语义评测通过；内容预览与浏览器撤销取证待完成**。本文承接[自由模块体验](module-experience.md)，提出模型根据创作任务自行决定模块组织、生成内容并保存的交互。当前实际行为以[实施方案的实施记录](../../dev-notes/v0.8/agent-module-management-plan.md#9-实施记录2026-10-25)与[模块说明](../../dev-notes/v0.8/modules/module-experience.md)为准；未列入实施记录的能力仍属设计，不修改应用版本。

配套的提示词接入、工具、接口、事件与验收见[实施方案](../../dev-notes/v0.8/agent-module-management-plan.md)。

## 1. 目标与设计取舍

作者提出创作目标，模型决定哪些成果值得保存为模块，完成组织与内容生成。作者可以通过自然语言修改，也可以直接编辑已保存内容。

本方案建议：**明确要求创作或修改资料时，允许模型在任务范围内自行新建、填充、保存并用于当前作品，不要求作者逐份确认。** 只是讨论、询问建议或明确要求暂不保存时，留在对话中。

因此，“先撰写人物小传”可以直接形成当前作品可用的模块，不要求作者补说“发布”“装入”等内部操作。系统在对话里说明实际操作，提供内容入口和撤销。

模型负责语义决定，包括是否需要模块、拆成几份、名称、小标题、哪些已有内容需要补充。应用负责确定操作对象、读取与版本校验、保存、挂载、结果记录和恢复。自然语言意图仍可能被模型理解错误，不能把工具校验描述为完整的意图证明。

## 2. 自主决定的范围

| 作者的表达 | 建议行为 |
|---|---|
| “这个点子怎么样”“先讨论人物关系” | 讨论，可说明适合如何保存；不修改作品 |
| “先撰写人物小传，确定死者与真凶” | 自主组织内容、生成、保存并用于当前作品 |
| “把医生改成死者的姐姐” | 读取涉及的模块，在本次要求允许的范围内修改 |
| “只给我几个方案，暂时不保存” | 提供方案，遵守不保存的限制 |
| “把这份内容存进模块库，不用于这部作品” | 使用明确的独立库保存流程 |
| “更新库里的原稿，让我以后复用” | 明确处理库原稿；不替其他作品升级版本 |

保存与挂载可以是同一创作任务内的确定性步骤，不额外发起模型整理任务。打开页面、打开模块、记录灵感、保存手工编辑仍不触发模型。

作品中的小说文字、引用材料、模型此前的建议不能自行扩大本轮操作范围。作者明确排除的内容优先于模板中的完整性要求。

## 3. 模块的组织原则

- 模块保持名称与自由正文，不增加作者必须维护的类型或字段。
- 可以不建模块、只建一份，也可以建立多份；预制提示词不固定模块数量和名称。
- 优先使用已挂载且合适的模块。先读相关原文，再判断更新或新增；同名不等于同一内容。
- 独立阅读、修改或复用有价值的内容才独立成模块。一句话的补充通常进入已有内容。
- 不建立空模块、占位模块，或仅为预期后续任务建立无内容的结构。
- 主要事实有清楚的保存位置，其他模块只作必要引用；修改事实时核对本次范围内的相关表述。
- 初次生成可决定合理拆分；已有内容的合并、拆分、删除与移除需要本次请求包含相应整理目标。普通修改不顺便重组整个作品。

### 示例：雪山温泉悬疑小说

示例要求先完成小传、关系、聚集原因与调查合理性，暂不展开具体手法和调查过程。模型可以建立如下内容，但这不是产品内置清单：

| 模块 | 本轮内容 |
|---|---|
| 创作约定 | 篇幅、背景偏好、嫌疑人数、叙述与出场要求、结局要求，以及本轮排除项 |
| 人物小传 | 7—8 名核心嫌疑人，另列死者、侦探、叙述者和辅助人物；外形、往事、个性、语言特点、动机 |
| 人物关系与旧案 | 与死者的联系、旧案责任、利益关系、谁知道或猜到哪些事实 |
| 聚集与调查前提 | 聚集理由、两位调查者的出场原因、谋杀疑点和侦探介入的理由 |
| 案件真相 | 死者、真凶、被引向定罪的人选及其关系；具体手法留待后续 |

模型也可以将关系并入小传，将聚集前提与案件真相放在同一模块。验收检查内容覆盖和使用效果，不要求恰好生成上述五份。

用户已经允许创作姓名、往事和真凶身份，模型可以提出并保存自己的方案，无需逐项征询。作者给定的要求、模型本轮补充的设定、仍需核实的现实依据，要能通过正文表达与任务来源区分，不增加遍布界面的标签。

人工心脏与医疗情节在本任务里属于故事前提；未经核实不能表述为已验证的现实知识，也不为核实而擅自扩展本轮任务。

作者掌握的真相、角色知情与读者已知分别处理。创建真凶设定不表示开篇可以披露其身份。

## 4. 对话与页面行为

### 4.1 开始执行

模型读过需要的现有资料后，用一句简短说明告知本次组织方式，例如：

> 我会整理人物小传、人物关系和聚集与调查前提，保留篇幅与结局要求。本轮完成后保存为本作品模块，具体手法和调查过程留待后续。

这句话是执行说明，不是等待作者确认的关卡。仅在确实无法确定任务目标，或新要求与已有设定冲突且无法确定取舍时反问。作者已经明确要求改变的设定直接修改。问题直接写明影响，保留已经完成的内容；未收到回答不把超时当作同意。

确需决定时，在原对话中显示一个具体问题，可附两三个选择，也能直接输入答案。例如：“你要求保留已有结局，同时要求让另一名人物成为唯一真凶。要调整结局，还是保留原凶手？”选择后作为作者回复继续原任务，不弹出模态确认框，也不把整个模块清单逐项做成问题。

等待回答时保留生成进度并释放运行锁，作者仍可阅读或手工编辑。回答后重新检查资料版本，再继续依赖该决定的部分。

### 4.2 生成过程

- 在原对话中显示简短进度和已经生成的内容预览；用户可停止。
- 生成期间的内容属于本次任务，尚未保存并用于作品时，明确显示“正在生成”或“尚未保存”。
- 不在作品侧栏提前插入正式模块，不跳转页面，不自动打开库管理界面。
- 长任务分段保存生成进度，任务中断后可回看；继续执行由作者提出，不隐含启动新的模型任务。

### 4.3 完成反馈

完成后对话显示实际结果，例如：

> 已创建并用于本作品：人物小传、人物关系、聚集与调查前提。

每个名称可点击阅读，附近保留一个“撤销本次修改”入口。新模块出现在原有写作侧栏，当前阅读位置不被替换。

预览与阅读使用同一份保存结果，不把回复中的完整文章再解析一遍后存成第二份内容。对话可以简述人物安排与未完成项，模块正文保留完整成果。

用户可以直接说“关系并入小传”“真凶改成姐姐”，也可以在模块阅读区手工编辑。下一轮模型读取对应的实际版本，不仅凭聊天记忆修改。

### 4.4 状态与失败

| 实际状态 | 展示与后续动作 |
|---|---|
| 正在生成 | 预览已生成内容，可停止 |
| 内容已生成，尚未应用 | 保留本次内容；可继续保存，不要求重新生成 |
| 已保存到库，未用于本作品 | 明确说明两步结果；可继续完成当前作品保存 |
| 已用于本作品 | 侧栏更新，可阅读和撤销 |
| 版本冲突 | 保留生成内容与本地草稿，说明目标发生变化；不自动覆盖 |
| 已撤销 | 恢复本作品原有内容与挂载；库内新增副本仍保留 |

状态只在相关位置显示，不在所有模块旁常驻类型、完成率或版本计数。错误文案沿用 `[错误码] 位置：现象。建议：…`。

## 5. 全局库与当前作品

继续沿用全局库保存内容版本、作品绑定精确版本的结构。

- 本次新建的模块保存初始内容到全局库，并挂载到当前作品；这是“完成本作品资料”的内部步骤，无需用户掌握发布与装配术语。
- 对已有模块的日常修改创建作品内版本，不推进库原稿，也不改变其他作品。
- 更新已有库原稿、搜索未挂载的全局内容、给其他作品改挂载，继续需要相应的作者要求；本方案不把这些能力附加到普通创作任务。
- 新建不按全局同名模块自动合并。允许同名，必要时由模型在当前任务里给出更清晰的名称。
- 撤销恢复当前作品的原绑定与内容。新建库副本保留，便于复用与恢复；删除库副本沿用独立删除操作。

这样可以允许模型直接完成创作，同时延续作品之间的修改隔离。

## 6. 预制提示词草案

以下要求作为写作任务规则的一部分，与应用给出的能力范围、作者请求和当前资料一起提供。具体工具名以实际接入为准。

```text
你帮助作者完成创作，并把需要持续使用的成果组织为模块。

先判断作者是在讨论，还是要求产生或修改创作成果。
讨论、比较建议、明确暂不保存时，只在对话中回答。
作者明确要求撰写、建立或修改资料时，在本轮允许范围内完成内容、保存并用于当前作品。

由你决定是否建立模块、建立几份、如何命名和分段。
优先查阅已挂载模块目录，读取相关原文；适合补充已有模块时不要重复创建。
作者没有指定存储位置时，先定位已有模块；模块条目的局部修改仍在原模块内完成。
相同称谓不足以证明模块条目与旧文件指向同一个人物，不根据同名关系扩大修改目标。
旧文件写入需要当前作者明确指定文件或沿用旧目录的要求；普通资料创作按模块保存。
读取旧文件作为参考不产生写入权限；继续旧任务时明确关联原请求，保留当前作者的限制。
只有需要独立阅读、维护或复用的内容才拆分，不为每个字段建模块，不创建空占位。

区分作者给定的要求、允许你创作的设定和有待核实的现实依据。
作者要求你决定的人名、往事、身份与动机，可以直接创作。
作者明确要求把某项信息改成新值，已经决定这项取舍，不需要再确认旧值是否保留。
读取相关材料后，目标仍无法定位，或本轮必须同时满足的要求存在未决冲突时，才向作者提问。
「其余不变」时只改指定信息，保留范围外资料；不因旧文件或章节可能受影响而暂停或自行同步。
遵守作者排除的内容，不为了补全模块扩写未要求的情节、正文或作案细节。
模块正文保存创作成果；执行进度、保存状态与未做事项留在对话中说明。
保存作者真相不代表角色已经知情或读者已经知道。

执行前简述这次会建立或修改哪些内容，然后继续完成，无需逐份确认。
通过专用工具提交明确操作和内容；不根据聊天文字自行拼接库路径。
同轮需要多份内容时，先准备包含全部操作的完整变更集，再统一应用；应用后只读取结果并反馈。
修改已有内容必须使用实际读取的目标与版本，保留未修改的内容与附加信息。
普通创作不更新已有库原稿、不搜索未授权的库内容，不修改其他作品。

以工具返回的实际结果说明哪些已保存、哪些已用于本作品、哪些仍未完成。
保存未成功时不能声称完成；保留已生成内容，说明可继续处理的范围。
```

提示词同时提供少量有差异的示例：纯讨论不保存、单模块补充、多模块创作、明确不保存、资料冲突与部分完成。示例不全部采用“人物、线索、真相”这一种结构，以免模型机械复制。

模板中稳定的行为要求与运行时权限分开。运行时给出已挂载目录、可读参考、允许操作、明确排除项和实际版本；模型的说明不能代替这些权限。

## 7. 故事总览与长期维护

新模块可以立即按原文阅读，进入下一轮可参考目录。挂载成功不隐含调用模型更新人物图、线索视图或章节索引。

有版本依赖的既有派生结果按原规则标记需要更新。作者点击“更新总览”后才整理；本任务生成的作者设定不冒充正文已经发生的观察。

本轮先交付新建、内容更新、成组保存、结果反馈和撤销。自动重组全库、跨作品同步、后台总结偏好与自动实体合并不属于本方案。

## 8. 验收方向

使用真实在线模型验证：能从示例创作请求直接组织并填充模块；合理继承已有资料；不把讨论自动保存；不扩写明确排除的内容；下一轮可定位并修改已保存模块。

2026-10-26 确认：模块创建按内容完整性验收，人物小传与聚集原因可合并成一份或拆成多份。检查所需内容是否完整保存并用于作品，不以固定模块数量作为通过条件。

确定性与浏览器验证负责：多模块同次保存、版本冲突、重复提交、保存后刷新、侧栏入口、停止与继续、作品隔离、实际状态与撤销。详细案例见配套实施方案。
