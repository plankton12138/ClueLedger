# Hastings 0.3：模型上下文与正文摘要

> 定位：2026-10-17 确认的目标设计，不维护实施进度；当前行为与差距见[账本与模型背景](../dev-notes/v0.3/modules/context-and-ledger.md)。
> 关联：[主方案](agent-first-workbench-product-design.md)、[正文修改与版本流程](manuscript-editing-design.md)。

## 1. 用稳定作品资料维持连续理解

0.3 以**故事账本和正文摘要**作为模型的常驻作品上下文，作用类似项目中的 `AGENTS.md`：每轮开始就具备稳定背景，
知道哪些设定已确认、正文已推进到哪里，不靠模型从长聊天中猜测，也不要求作者反复粘贴。
这是一项上下文组织约定，不要求另建可手写的同名文件。账本来自正式作品记录，摘要是正文的派生资料；
图谱与对话共用同一来源，原文和版本历史仍是事实核对与精确修改的依据。

## 2. 每轮包含什么

| 层次 | 常驻内容 | 边界 |
|---|---|---|
| 作品约定 | 当前作品、作者明确的本书要求与表达约束 | 不推断作者模型，不注入旧版自动学习的偏好 |
| 故事账本 | 已确认故事核心、人物、线索、真相、关系与叙事安排 | 计划、真相、证词和人物认知分开；候选单独标识 |
| 正文摘要 | 全书进展概览、按当前章节顺序组织的逐章摘要及来源版本 | 说明已写范围，未写、未读和未更新不能冒充已有内容 |
| 当前任务 | 当前章/选中段落、作者要求、显式引用与允许修改范围 | 必要时读取原文，不仅凭摘要写入或判定矛盾 |

“常驻”指每轮稳定组织并自动携带，不表示无限增长的资料全部塞入每次调用。
小作品尽量携带完整账本和逐章摘要；超过预算时，保留故事核心、全书概览、人物/线索目录和版本索引，
再按任务展开相关条目与章节摘要。裁剪范围可查看，尚未展开的内容可通过稳定引用读取。
当前明确要求优先于本书约定；作品间隔离，不带入其他作品资料。

### 2.1 全局背景与当前段落的信息边界

全书账本和摘要服务于作者全局规划；写入某章或某段时，任务还需固定目标正文版本、章/段位置及叙述视角，
同时携带截至该位置的角色知情来源、读者已披露信息，以及已确认的伏笔和揭示安排。
这些约束从已有账本与正文读取，不要求作者先填写额外表单；信息缺失保持未知，只有确实影响本次写法时才澄清。

常驻背景中的后文真相及后续事件保留其来源位置，作为作者全局资料，与“此刻可写入人物认知或向读者透露”的内容明确区分。
例如第5章才揭示怀表早已损坏，回头润色第1章时可以据此维持伏笔，但不能默认让侦探在第1章已断言怀表损坏。
人物知情按故事时间与获知事件判断，读者披露按叙述顺序判断；倒叙不简单以章号比较。

默认润色保留原文的信息披露范围；作者明确要求改变揭示安排时，说明相关变化并在已授权范围内执行。
相关约束与任务快照一起记录，生成和发布检查均使用同一边界；发现越界时在当前任务内修正或澄清，不新增独立模型一致性审计。
图谱的“截至某章/角色视角”筛选只改变查看方式，不能代替写作任务的上述约束。

### 2.2 本书约定的记录与维护

本次任务要求与本书约定分别保存。“这段用第一人称”只约束本次任务；“全书采用第一人称”才记录为本书约定。
范围不明确时先按本次任务处理，需要持续生效时再澄清；不从一次采用或人工修改中推断长期要求。
对话回报实际记录的内容及范围；作者只是在讨论某种写法时，不自动记入本书约定。

作品设置提供“本书约定”，无需模型即可查看、修改和移除当前生效要求，保留来源消息与变更记录；不增加独立主导航。
相互冲突的新要求明确替换哪项旧约定；未明确替换时保留待选择状态，不把两项同时作为已生效约束。
修改或移除后用于后续任务，不追改正文；已经开始的任务保留其约定快照，需按新要求执行时由作者明确调整或重启。
本次任务明确要求优先于本书约定，临时例外不静默改写本书约定。这些要求属于作者明确的作品资料，不接入作者模型。

## 3. 摘要生成与更新

摘要覆盖事件进展、人物行动与知情变化、线索出现与解释、未解疑问、视角和重要时间信息；
尽量关联正文位置，未知信息保持未知，不补出隐含真相。记录章节身份、正文来源版本、生成状态和模型来源，
全书概览记录所依据的逐章摘要版本集合。

| 事件 | 更新方式 |
|---|---|
| 导入或采用正文 | 将新正文摘要标为“待更新”，提供“更新摘要·使用模型” |
| 点击“修改完成” | 只使改动章节摘要和概览失效，提供明确的更新操作 |
| 整体修改或恢复历史 | 按实际正文变化标记受影响摘要；账本变化另更新无需模型的账本投影 |
| 修改副本自动保存 | 不改正式摘要；显式引用副本时使用单独快照 |
| 作者启动摘要更新 | 固定来源版本，生成受影响章节摘要，再更新概览 |
| 无模型或更新失败 | 正文保存照常成功；摘要显示“待更新/更新失败”，由作者配置模型或重试 |

同一来源版本的显式更新任务去重；返回时再次核对来源，过期结果不覆盖当前摘要。
账本、摘要与概览分别记录版本，不仅凭更新时间推断一致。摘要不自动修改正文或账本。
作者可通过对话纠正摘要并保留来源，下一次重建仍需核对实际正文。

### 3.1 正文证据的有效状态

账本中的作者设定与“已在当前正文实现”分别记录。线索已出现、读者已获知、角色已通过某事件获得信息等记录，
如以正文为依据，需关联来源版本和位置，并显示其对当前正文的有效状态。
导入替换、采用修改、手工修改完成及恢复历史时，在正文版本生效的同时核对受影响的证据关联；
来源被改动、删除或无法可靠定位时标为“需核对”，保留旧依据供回看。能确认来源及依赖未变的关联继续有效，不因无关章节变化全部失效。
这一步无需模型，不取决于作者是否启动摘要或账本更新建议任务。正式版本、摘要失效状态和正文证据状态作为一次提交；任一项写入失败时不发布新版本，作者输入继续保留，并以同一操作标识重试，避免产生重复版本。

“需核对”不撤销作者确认的真相、计划或人物设定，也不直接断言某事没有发生；图谱和模型上下文共同显示其正文依据尚未确认。
新任务依赖该项时先读取当前原文核对，能建立依据则更新关联；无法确定时请作者选择，不能沿用旧记录宣称已披露或已知。
作者也可从来源详情人工核对并关联当前正文；模型提出事实变化时仍走账本更新建议确认规则，不借证据核对改写设定。

## 4. 过期摘要与按需原文

新任务遇到缺失或过期摘要时，读取受影响章节原文，为本次任务构建临时背景；临时背景不写回正式摘要。
读取受预算和模型能力约束；无法覆盖时说明范围，让作者缩小当前任务，或另行明确启动“更新摘要”，不静默使用旧摘要，也不在其他任务中夹带摘要更新。
精确改写、原文引用、人物知情和跨章矛盾判断需读取对应原文、保留来源版本。
长篇可分段读取并记录覆盖，不能把“已载入摘要”说成“已读完全文”。

人物何时获知依据故事发生时间与知情来源，读者何时看到依据叙述顺序。
倒叙、插叙、证词和不可靠叙述需要区分；“第3章使用、第4章才写到”不足以认定提前知情。
后续可引入 RAG 辅助定位，但命中结果仍需校验版本、范围与原文；RAG 不替代账本与摘要，不作为0.3依赖。

## 5. 模型调用与工具边界

保存、版本记录、摘要失效、正文证据状态核对、目录及图谱查看无需模型。对话、生成、摘要更新和账本更新建议整理会使用模型，入口与运行状态写明“使用模型”。

摘要更新和账本更新建议整理分别提供明确操作，也可由作者用含义清楚的自然语言要求启动。启动前说明用途、实际范围、来源版本、当前模型和预期产物；
开始后固定来源、用户连接标识和模型标识，并创建唯一任务与结果记录；运行状态和结果显示本次实际使用的模型，但不暴露密钥。作者之后切换当前模型只影响新任务，不改变已经启动的任务。任务显示等待、运行、已停止、失败、完成或来源已变化；作者离开当前视图后，已经明确启动的任务可以继续运行并回写原记录，不能因此自动创建新的任务。

两项功能默认均不运行，没有自动开关、后台自动排队或自动重试。失败后由作者明确重试，默认沿用该任务固定的连接和模型；作者明确选择新模型时记录为新的尝试，并保留前一次尝试的模型与状态。重复点击返回同一运行任务或已有结果。
默认分别启动；只有作者选择了明确写出两项内容的组合操作时才可合并调用，并分别反馈结果。启动摘要更新不能夹带账本更新建议整理，反之亦然。
未启动的内容保持“待更新”或“尚未整理”，不自动消化历史积压，也不连带运行作者学习或模型一致性审计。
建议的生成返回与采用都核对来源正文和相关账本，过期建议显示“需重新核对”，规则见[账本更新建议](manuscript-editing-design.md)。

后续独立模型工具采用柔和紫色描边与浅底，配名称及“使用模型”文字；常规创作主动作沿用蓝色，错误与警告保留语义颜色。
颜色仅为辅助。全文审计和章节审计有独立入口、范围与进度，不藏在修改完成或摘要更新之后，见[后续设计](future/consistency-audit-design.md)。
0.3 不显示尚未实现的模型一致性审计按钮，不触发其任务。作者要求完整审计时说明本版范围；
可继续讨论明确引用的内容，不能将普通回复包装为已执行章节/全文审计。

## 6. 验收重点

- 切换讨论或模型后，使用同一作品的账本与最新可用摘要；切换模型只影响随后启动的任务，已启动任务仍使用其模型快照，不从聊天推断正式状态。
- 手改、导入、采用和恢复后，只自动更新摘要失效状态并核对正文证据状态；作者明确启动后才生成摘要，未改变章节不重复生成。
- 无模型仍可保存与记录版本；更新失败不回滚正文，新任务不静默使用过期摘要。
- 每项模型功能有明确启动方式、范围和过程反馈；未启动、过期结果、停止、失败及作者重试有真实状态，不额外触发其他模型功能。
- 超出预算时可解释裁剪，精确任务读真实原文，缺失范围不冒充已覆盖。
- 过期摘要下启动其他任务时只构建本次临时背景，不写回正式摘要；无法覆盖时提示缩小范围或另行启动摘要更新。
- 全书已写到第5章，再润色第1章时保留全局背景，但不提前披露第5章信息；改变揭示安排需有明确要求，倒叙按实际知情与阅读顺序处理。
- 删除第1章的线索出现段落，即使尚未启动账本更新建议整理或没有模型，相应正文证据也立即标为需核对；第2章写作不能据旧记录认定读者或角色已经获知。
- 无关章节变化不使全部证据失效；撤销、恢复或重新关联后按实际来源核对，旧版本依据始终可回看。
- 局部表达要求不自动进入本书约定；全书要求可查看、修改和移除，冲突不同时生效，已启动任务可追到实际使用的约定快照。
