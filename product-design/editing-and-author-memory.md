# Hastings 0.3：正文修改与作者长期记忆

> 性质：产品设计提案，待实现；与[主工作区产品方案](agent-first-workbench-product-design.md)共同定义目标体验。
> 日期：2026-10-16。
> 目标版本：0.3（开发中），版本约定见[产品设计入口](README.md#版本约定)。
> 核心决定：创作台与对话框始终承载主要操作；版本、全局修改和作者记忆融入其中。

## 1. 作者眼中的两条路径

| 作者想做什么 | 交互过程 | 系统承担的工作 |
|---|---|---|
| 改掉不满意的表达 | 直接修改正文 → 完成本次修改 → 继续写作 | 保留草稿，记录完整版本与差异，空闲时归纳作者习惯 |
| 调整整个故事中的重要内容 | 在对话中说明 → 回答必要问题或选择方案 → 整体修改 → 阅读结果 | 理解关联，统一修改账本与相关正文，检查并记录版本，支持恢复与撤销 |

独立的协作主编模块、变更发起页、修改审计/修订审阅模块和作者模型页从目标产品中移除。
版本历史、详细改动和记忆来源可以按需查看，主要过程不依赖这些详情视图。
正文始终在创作台中可阅读和编辑，对话区保持可用；结果与选择按钮回到同一对话。
版本历史只负责回看与恢复，不要求先发起修改审计。有正文后可按需使用[悬疑审计](mystery-audit-interaction-design.md)，
它检查故事内容并给出依据，不承担保存正文或整体修改的人工审批职责。

## 2. 直接修改正文：从一次编辑到一个版本

### 2.1 一次完整交互

1. 作者在已生成的正文中删去套话、调整用词或重写一段对话。
2. 系统持续保留编辑草稿，显示“草稿已保存”或真实的保存失败状态。
3. 作者点击“完成本次修改”，系统立即记录这一轮修改，并提示“已记录本次修改”。
4. 作者继续阅读、写作或聊天；模型空闲时再整理这轮改动带来的观察。

“完成本次修改”是版本边界。自动保存保障输入不丢失，短暂停顿和切换视图不等于作者已经修改完毕。
跨章编辑可纳入同一轮，按钮摘要显示本次包含哪些章节；暂时离开后仍能接着编辑或完成这一轮。
模型未配置、离线或繁忙时，版本记录照常完成，记忆整理留待可用时继续。

### 2.2 类似 Git 的记录能力，使用写作语言呈现

每次完成修改保留基础版本、最终内容、前后差异、受影响章节、时间和修改来源。
版本摘要先由实际改动生成，例如“修改第2章的3处文字”；模型之后可补充描述，但不阻塞保存。
作者不必填写提交信息，也不需要操作分支或合并命令。

正文旁的“历史”显示可读的版本条目，支持查看前后对照、回到相关段落和撤销指定修改。
人工编辑、Agent 执行、作者采用候选及历史恢复分别记录来源，不能混为作者亲手写作的证据。
一次完成操作对应一个版本；重复点击或网络重试不能重复记账。

没有实际差异时不创建空版本。未完成草稿切换视图或作品后继续保留，保存失败需要明确提示和重试。
恢复较早版本时保留现有历史；如果随后已有新修改，需要只撤销目标修改或在对话中解决冲突，不能静默丢掉后续内容。

### 2.3 正文事实与账本的关系

人工保存即时生效，不以模型检查或记忆整理完成为前置条件。
仅有表达变化时无需改动故事账本；若修改可能涉及人物身份、时间或线索事实，系统在对话中给出具体提示，
例如“你把到达时间改成了九点，要同步相关记录吗？”
作者可以选择同步或继续调整。等待处理期间明确显示相关差异，不能假装正文和账本已经一致。
这种故事事实核对与文风观察分别处理，人物名字或凶手变化不能被记成作者的表达偏好。

## 3. 作者长期记忆：从真实改动中逐步理解作者

### 3.1 记什么，怎样使用

记忆来自已完成版本中的真实人工差异，以及作者在对话中明确表达的写作偏好。
每条观察保留来源版本、修改前后片段、适用作品或场景、归纳理由和可靠程度。
只保存有后续用途的观察；不能为了完成一次后台任务强行得出偏好。

例如作者反复将概括情绪的句子改为动作和对话，系统可以逐步记住：

> 在人物对话场景中，作者倾向用动作和台词传达情绪，减少直接解释心理的总结句。

这一记忆可以帮助下一次写作选择表达方式。它是可以修正的参考，当前明确要求优先。
一次局部调整先保留为有限范围的观察；多次一致修改或作者明确说“以后都这样写”，才支持更广泛的使用。
某个角色的说话方式默认只适用于相关角色或作品，不能自动推广到作者所有作品。
直接接受 Agent 生成的一段文字不等于主动修改所提供的偏好证据；撤销和放弃也不能一概解释为文风厌恶。

### 3.2 模型空闲时整理

完成版本后，系统把待整理记录加入后台队列。同一版本只处理一次，支持失败重试与重新进入后继续。
有前台对话、生成或整体修改任务时优先服务作者；后台整理不抢占相同模型的前台工作。
整理期间开始新的交互时，后台任务可让出资源，已记录版本不受影响。

后台任务只分析本次可用的差异与必要上下文，写入有来源的记忆，不改写正文或故事事实。
没有模型可用时保留待处理状态；错误不会使正文保存失败，也不连续弹出打断创作的提示。
具体调度、额度和停用设置在实现方案中定义，产品需提供轻量的“自动学习写作习惯”开关。
作者关闭后仍可编辑和记录版本，停止新的自动归纳；已有记忆可以通过对话继续查看或删除。

### 3.3 通过对话理解、纠正和忘记

不设独立的作者模型导航，也不要求作者逐条审批学习结果。
作者可以说：

- “你现在记住了我的哪些写作习惯？”——回答相关记忆，并提供可展开的修改依据。
- “这只是这个角色的说话方式。”——收窄适用范围，后续生成按新范围使用。
- “以后少用总结人物心理的句子。”——记录明确要求，并在必要时询问只用于本书还是作为通用偏好。
- “忘记关于短句的那个偏好。”——停止使用指定记忆，并避免再次从同一旧证据自动恢复它。

只有确实影响当前选择时，Agent 才简短说明采用了哪条记忆，不在每次回复中重复汇报学习进度。
作者撤销作为证据的修改后，相应记忆需要重新评估，避免继续把已撤回的选择当成当前偏好。
记忆处理失败、证据不足或互相矛盾时保留不确定性，不能生成一套看似确定的作者人格描述。

## 4. 通过对话进行整体故事调整

### 4.1 从一个要求开始

例如作者说：

> 把凶手改成姐姐，保留妹妹的视角和旅馆背景，前面的线索与伏笔一起改好。

Agent 读取实际账本与已有正文，梳理身份、动机、作案过程、线索解释、人物认知和章节呈现的关联，
说明自己的整体理解。必要选择用短问题和按钮完成，例如“保留原手法 / 一起调整手法”。
问题应来自实际缺口；作者已说明的要求不再重复索取。

当范围仍需作者选择时，对话可显示：

> 我会调整姐姐的动机、相关线索与真相揭示，保留妹妹视角和旅馆背景，并检查已写章节中的对应内容。
> [按这个整体修改] [调整要求] [先看看方案]

上面的范围是示意，实际摘要必须来自读取和分析。未读完的范围应明确说明，不能声称已经检查全书。
作者已经明确同意相同范围时直接执行，不增加重复确认；“先看看方案”只生成方案，不授权改写。

### 4.2 确认后连续执行

1. 保存当前稳定作品版本，固定本次基础、目标和作者要求。
2. 在内部工作版本中修改相关账本、人物与线索关系，以及所有受影响的已写正文。
3. 检查新设定、人物认知、伏笔与解释的衔接；必要时在授权范围内修正遗漏。
4. 检查写入基础是否变化；遇到人工新编辑时保留它们，处理冲突后才能完成。
5. 相关账本与正文统一形成新的作品版本，对话反馈实际完成的内容和未决问题。

作者不需要逐一发起分析、批准章节、打开修订页或逐段接受。范围已经确认的中间动作由系统持续推进。
“整体”意味着全局检查与联动修改；不受影响的章节不必重写。
如果关键选择改变了授权范围，例如原本要求保留手法但模型认为必须更换，应回到对话说明并让作者选择。

### 4.3 执行中与完成后的体验

执行中显示半折叠的过程，展开可看实际读取、修改和检查记录，并可停止任务。
创作台保持可读、可编辑；新人工编辑不能被后台任务覆盖。当前章节有未完成草稿时，
在对话中选择先完成本轮编辑或暂缓会冲突的整体修改，不能自动丢弃草稿。

完成后中间仍是正文，对话显示简短摘要，例如实际修改了哪些人物、线索和章节，提供：

> [查看改动] [撤销这次修改] [继续调整]

查看改动可从摘要定位到正文，详细差异为按需能力，不作为完成任务的必经步骤。
正常情况下不需要在执行结束后再做一次同范围的总批准；选择的是“先看看方案”时则仍需作者决定是否执行。

### 4.4 停止、失败与撤销

停止或失败时保留原稳定作品版本，内部完成的工作记录为未完成进度，不能让正式账本与正文处于半套新设定中。
对话说明实际停在哪里，并提供继续、调整要求或放弃本次执行；重试承接已完成的可复用工作。
无法完成全局检查时不能显示“整体修改完成”，而应说明尚未覆盖的章节或未解决的问题。

撤销产生可追溯的恢复记录，覆盖本次关联账本与正文。若随后没有修改，可以整体撤销；
若已有后续人工编辑，保留新内容并处理与本次修改的关系，必要时在对话中让作者选择冲突部分。
Agent 执行产生的文字与作者之后的人工调整分开记录，只有后者可作为相应的人工修改观察来源。

## 5. 实现衔接与验收重点

这些流程是目标设计。已有版本、作者观察、任务与修订能力需要逐项核对，不能以现有接口可调用代替完整产品交付。
前后端至少要对齐以下边界：

| 边界 | 必须一致的行为 |
|---|---|
| 草稿与完成修改 | 保存的是当前实际文本；完成生成唯一版本和真实差异，刷新不丢未完成内容 |
| 版本与记忆 | 人工来源、基础版本和作用范围可查；失败重试不重复归纳，纠正与忘记会影响后续使用 |
| 对话与执行 | 讨论、候选和执行意图清楚；已确认范围一次贯穿内部任务，无须旧表单中转 |
| 整体结果与恢复 | 正文和账本一致成为当前版本；部分失败保持原稳定状态，撤销保护后续编辑 |

关键验收用例包括：无模型时完成润色并记录版本；前台任务优先于记忆整理；单次局部改写不变成通用偏好；
通过对话纠正和忘记记忆；更换凶手、手法或背景贯穿相关内容；中断重进后继续；执行期间人工编辑发生冲突；
整体完成后继续编辑再撤销，仍保留新写的内容。
