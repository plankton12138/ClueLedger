# 线簿 / ClueLedger 产品设计

线簿是面向悬疑长篇作者的 AI 写作工作台。作者决定故事方向、修改范围和真相的揭晓时机。线簿让作者在同一个工作区里读章节、讨论、写作、修订和维护作品资料，并能核对每次改动。本文以当前工作区的网页和 Agent 行为为准。账号与订阅适用于启用相关服务的托管模式。

往期方案见[产品设计归档](archive/README.md)。

## 一、产品角度

### 1. 进入工作区与管理作品

- **本地使用**直接进入工作区。作者可以选取已有作品文件夹，或命名并新建作品。
- **托管使用**从账号页进入。提供邮箱注册与验证、登录、忘记密码、重置密码和退出。新作品归当前账号管理，作品、会话、私有模块库和模型连接按账号隔离。
- **作品菜单**提供打开或新建、切换最近作品、重命名、重新读取内容和清理失效记录。删除前展示目标和影响范围，作者确认后删除该作品的内容与记录。可复用的模块库独立管理。

### 2. 写作台与章节阅读

- **目录**用来切换全书结构、章节和已装入本作品的资料。作者可在章节列表改名。全书结构用于查看故事方向、章节安排、长期约束与揭晓计划，创作性变更通过对话提出。
- **稿纸**默认用于阅读。选中文字可引用到本轮对话，引用附来源，作者可以移除或补充要求后再发送。章节已有可核对的信息时，「本章信息」提供原文定位、待确认的新增信息和需对齐的条目。
- **布局**在较宽窗口并列显示目录、稿纸和对话，支持调整栏宽。窗口较窄时可以按需打开侧栏或对话，全局字号可在设置里调整。界面沿用经典 OS X Aqua 风格，稿纸采用暖白底，作者与 Agent 的对话分别使用绿色与银灰色。长回复可以展开阅读或复制。

### 3. 对话创作

1. **开始作品。** 作者可以用一句想法开始。可以直接写第一章，也可以先整理全书结构；是否建立结构由作者决定。空白页示例只填入对话草稿，由作者决定何时发送。
2. **交代本轮目标。** 可以讨论方案、检查正文、起草新章、续写、局部改稿或整理作品资料。当前章节帮助定位目标，选段、文件参考和灵感帮助补足材料。对话中明确排除的内容保留原状。
3. **在创作中控制任务。** 支持新建、切换和重命名会话，各会话保留各自草稿。写作过程逐步显示，工具步骤可展开。任务可暂停，在任务允许时继续，也可插话调整要求。离开页面后可以返回正在运行的原会话。
4. **核对结果。** 本轮结果说明完成情况、实际保存的对象和未完成项。作者可以按列出的对象核对内容，发起「检查本次改动」，或在适用时撤销和补记历史。如果提供备选方案，作者可以在对话中指定采用哪一版。
5. **补充资料后接续。** 当任务需要可复用的资料时，Agent 可建议装入已有模块或新建模块。作者选择后接续原请求，选择暂不调整时沿用现有资料继续。

### 4. 手工修订、差异与写作约定

- **手动改稿。** 在某一章点击「修改正文」，编辑稿纸后先看差异，再确认入稿。取消修订时保留已保存原文。遇到正文已在别处更新的情况，保留当前编辑内容并提示作者核对。
- **本章修订。** 回看已记录的手工改稿和 Agent 改稿，按段落核对新增、删除和改写。可按需让 Agent 分析修订，判断哪些变化涉及写作约定、全书结构、已装资料或仅当前场景。
- **写作约定。** 作者可以直接编辑并保存这部作品的长期表达要求，例如叙述视角、对白风格。修订分析给出的约定、结构或模块建议由作者选用。仅用于当前场景的选择继续留在这次创作中。

### 5. 灵感与资料复用

- **灵感本。** 从可移动的浮动入口随手记录，也可以用快捷键打开，或把已完成的对话选段记成灵感。有搜索、编辑、历史版本、最近删除与恢复入口。已有灵感可以连同来源加入当前对话草稿，作者在发送前仍可调整。
- **模块库。** 用独立模块保存人物小传、旧案、背景等可复用资料。支持搜索、预览、新建、编辑、版本浏览、另存变体、单个或批量删除与恢复。作品有可导入的旧资料时，可以在模块库中整理成模块。
- **作品中的模块。** 作者可选定具体版本装入作品，从目录读资料，在作品模块管理中调整或卸下。作品内的内容变更只影响这部作品，库原稿及其他作品的使用独立。可用一组模块新建作品，新作沿用选定的模块组合，从空白正文开始。

### 6. 记录、上下文与设置

| 功能 | 作者可以做什么 |
| --- | --- |
| 活动记录 | 按作品或会话看事件流，查看任务进度、模型请求、工具动作、失败及恢复。可筛选、查看已保存的详情、导出记录，并管理详情保留和清理。 |
| 运行追踪 | 从会话进入具体一轮，查看各执行阶段、工具往返和写入拦截。结果有争议时，可以沿时间顺序核对实际发生了什么。 |
| 文件版本 | 启用版本记录，查看作品变更的历史和文件差异。在满足撤销条件时，可以撤销最近一次符合条件的修改。 |
| 上下文与用量 | 分别查看当前上下文占用和本会话累计模型用量。历史太长时可手动压缩，也可以停止正在进行的压缩。供应商缺少用量时显示为未知。 |
| 模型设置 | 管理模型连接及默认选择，分别测试模型响应与工具调用。在对话中切换后续使用的模型。支持的模型可调整思考深度，已开始的任务沿用受理时的选择。 |
| 无模型时 | 可阅读、记灵感、手工改稿和整理模块库，保留对话草稿。生成、对话和分析等操作需要可用的模型连接。 |

### 7. 托管订阅与额度

启用订阅服务的托管模式提供套餐和权益查看、购买、额度进度、订单状态查询及退款申请。支付结果以已确认的订单状态为准。额度接近用完时提醒作者，耗尽后仍可阅读和编辑，可等待额度恢复或切换自带模型连接继续生成。套餐权益与作品内容分开管理。

## 二、Agent 角度

### 1. 任务受理与 System Prompt（系统提示）

**先明确作者希望得到什么，再决定可执行的动作。** 「帮我想两个结尾」交付两个方案，「把第三章结尾改成雪夜，其他不动」交付限定范围的修改，「检查这次改动」交付有原文依据的报告。作者选中的章节和选段用于定位，写入依据来自本轮请求或作者明确承接的已有授权。目标仍不明确、约束冲突且必须取舍时，向作者提出一个具体问题，等答案后接续。

系统提示规定 Agent 的角色、当前任务规则、作品约束和交付要求。写作时关注叙事连贯、作者约定和允许揭晓的信息。检查时以已保存原文为依据，说明覆盖到哪里。提示为判断提供指引，实际写入还须通过应用对授权、材料和版本的检查。

### 2. 上下文装配与压缩

每轮先准备当前要求、相关对话和作品依据。全书结构提供长期方向与关键约束，章节记录与原文说明实际写过什么，写作约定用于正文生成，作者明确引用的资料随本轮任务使用。详细模块和长篇原文按需读取，先定位目标，再补齐足以做判断的原文。这样能把更多空间留给当前任务，也可能增加读取次数。

对话接近可用容量时，可以自动整理较早的历史，作者也可手动发起。摘要保留目标、限制、已确认决定、尚未采纳的建议、待答问题和必要引用，带有可追查的来源。最近的完整对话、当前要求和仍待解决的问题优先保留，原始会话仍可回看。只有新摘要确实缩短上下文且满足来源和预算要求时才采用。整理失败时继续使用原有对话历史，必要时减少本轮携带的非必需材料。必需信息仍放不下时，提示作者缩小任务或减少参考资料。

### 3. Memory（跨轮次和跨会话记忆）

| 信息 | 在后续任务中的用途 |
| --- | --- |
| 会话与任务状态 | 保留这一轮目标、草稿、作者答复和已执行的事实。切换会话时各自恢复，继续任务时按实际进度接续。 |
| 全书结构与写作约定 | 全书结构保留作者已确定的故事方向、人物关系和揭晓要求。写作约定保留长期表达规则。后续写作使用当前已保存内容。 |
| 正文与章节记录 | 反映已经写进作品的事实。涉及事件顺序、原句或读者能否知道某件事时，回到相关章节核对。 |
| 作品模块与灵感 | 读取当前作品使用的模块版本，遇到同名人物或设定时查来源再判断。未采用的灵感和聊天建议仍是备选，经作者选择并保存后才成为长期依据。 |

悬疑写作要分别处理**作者掌握的真相、角色在当前位置知道的事、读者已从正文看到的信息**。同一条设定可能只对其中一方可见。Agent 可以用作者真相规划写作，落笔时按叙述视角和揭晓时机决定可以呈现什么。旧摘要与新保存的资料冲突时，先核对当前版本和原文。

### 4. Function Call Agent 框架（模型调用工具的工作方式）

1. **按任务开放能力。** 讨论和检查使用读取、查询与核对能力。需要写入时，再开放该任务允许的正文、结构或模块操作。查阅资料、引用资料和修改资料分别判断。
2. **在工具往返中逐步完成任务。** 模型提出要执行的动作，应用校验后执行并把实际结果交回。Agent 根据结果继续读取、修正操作、提出问题或结束本轮。查询摘要和界面焦点用于定位，精确改稿与校对需要已读取的原文。
3. **保护正式内容。** 明确授权的直接修改要核对目标、原文和当前版本。先起草的正文候选还须核对关键叙事要求，满足提交条件后才入稿。由作者挑选的备选方案，在作者明确采用后执行。同步结构、跨章修改、删除或改名分别核实授权。
4. **依据结果交付。** 应用分别显示任务完成情况、作品是否写入、历史是否记录。只有实际保存结果能确认入稿。完成后指出改动位置、保留范围和仍需作者决定的问题。

### 5. 错误处理与 Tool 兜底

| 出现的情况 | Agent 和产品如何处理 |
| --- | --- |
| 查询无结果、原文只读到一部分 | 先核对查找范围，必要时换明确的名称、读已知来源或补读剩余内容。查无结果仍可如实反馈，只有缺少关键材料时才向作者询问。 |
| 工具参数错误、目标不唯一、超出授权 | 把失败原因和可修正的下一步交回模型。能在原授权内定位时修正，仍有歧义时请作者确认。超出范围的写入由应用拒绝。 |
| 资料或章节在执行中改变 | 保留作者最新版本。重新读取并定位，再决定是否继续。同一改动遇到冲突时保留草稿或可复用结果，并说明哪些内容尚未应用。 |
| 模型连接或读取暂时失败 | 对可安全重试的临时故障做有限恢复。无法继续时保留输入并提示检查连接、权限或额度。写入结果不明确时，先核对作品状态和保存记录，避免重复提交。 |
| 候选核对未通过或任务耗尽预算 | 可以局部修正后再核对，仍无法确认时保留候选或已完成部分。反馈具体失败项、影响范围和可继续的位置。 |
| 作者暂停、插话，或页面断开 | 区分页面连接状态与任务实际状态。重新连接后先看原任务；支持续办时依据保留进度与最新要求继续，已保存的变更单独展示。 |

作者看到的失败信息说明发生位置、结果和下一步。需要进一步排查时，可根据会话和任务在活动记录中定位对应的运行追踪，核对授权、读取依据、工具实际结果和作品变化。
