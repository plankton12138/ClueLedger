# 产品设计

本目录保存产品方案、用户旅程和交互原则。产品决定与交付状态分开记录；开发计划和构建记录见 [dev-notes](../dev-notes/README.md)。

0.3 的模块拆分、接口、三批实施任务与验收见 [完整开发计划](../dev-notes/v0.3/development-plan.md)（计划，待实施）。

2026-10-17 已确认：[prototypes 目录](../prototypes/README.md)中的原型图和网页仅提供设计语言参考，不代表成品功能、最终布局或交付状态。
功能范围与交互以本目录当前方案中的明确决定为准，不从原型中的页面、按钮或示例数据反推需求，也不因原型未展示而取消功能。

## 版本约定

项目尚在开发中，产品版本统一使用 `0.x`：原 V1 称为 **0.1**，原 V2 称为 **0.2**，下一版本为 **0.3**。
0.3 范围已完成本轮产品评审，仍待实现与验收；开发包版本统一为 `0.3.0`，不表示 0.3 已交付或发布。
后续产品迭代按 `0.4`、`0.5` 递增，修复版本使用第三位编号。

产品版本与接口、数据格式版本分别管理；现有目录、`/api/v2` 与架构标识保持兼容，历史记录中的 V1/V2 分别对应 0.1/0.2。

## 0.3 范围决定

2026-10-17 产品评审后的范围决定已确认，方案仍待实现：

| 范围 | 0.3 决定 |
|---|---|
| 主工作区 | 无正文时承接对话，有正文后以文章为中心；保留账本、图谱与执行日志 |
| 首版正文 | 由模型生成候选后采用，或导入已有正文；0.3 不提供空白首章的“直接写作”入口 |
| 人工修改 | 随时点击“手工修改”，在独立工作副本中跨章修改，点击“修改完成”后统一记录版本，再进入后续处理 |
| 模型常驻上下文 | 已确认账本与正文摘要，附来源、版本及更新状态；任务按需读取原文 |
| 模型功能启动 | 不运行默认或隐含的后台模型任务；每项模型功能均由作者通过明确操作或自然语言要求启动，并反馈范围、过程与结果 |
| 账本更新建议 | 根据正文变化建议补充或同步账本，在原对话中成组确认；不增加独立模块，不依赖 RAG |
| 结果与撤销 | 手工修改、导入和任务均有固定归属的结果记录；撤销覆盖原始正文及关联账本更新，并保护后续独立编辑 |
| 正文证据状态 | 正文保存同步核对“已出现、已披露、已知”的依据；失效关联标为需核对，无模型或尚未启动账本更新建议整理时仍生效 |
| 正文导入 | 默认新增章节；替换需明确目标，保护未完成副本，预览、去重与统一保存遵循同一版本规则 |
| 本书约定 | 与本次任务要求分开，可直接查看、修改和移除；保留来源及任务实际使用的快照 |
| 无模型记录 | 可保存多条作者消息并创建作品；草稿单独保留，连接后由作者选择继续讨论 |
| 作者模型 | **后续保留项，0.3 不实现**；不交付自动学习、偏好推断或记忆管理流程 |
| 模型一致性审计 | **后续保留项，0.3 不实现**；保留全文/章节审计及独立模型工具的设计 |
| 参考材料导入与材料库 | **后续保留项，0.3 不实现**；写作风格语料与检索用途留待后续。导入已有小说正文仍属本版 |
| RAG | 后续探索，不作为本版上下文或创作闭环的前提 |

“后续保留”指保留设计与既有资料，不进入本版开发、验收或默认后台任务，也不展示可用的占位按钮。
0.2 已有实现与数据按现状保存，具体去向在实施计划中说明；本次决定不代表已经删除或改造代码。

确定性的保存、版本记录、摘要失效和正文证据状态核对可以随作者操作自动完成；对话、生成、摘要更新、
账本更新建议整理等需要模型思考的功能，必须由作者明确启动。已启动任务可以在作者离开当前视图后继续运行，
但系统不能自行创建任务、夹带另一项模型功能或自动重试。

## 0.3 当前方案

- [Agent 主工作区与故事账本](agent-first-workbench-product-design.md)：产品定位、主要旅程、账本与图谱、交付顺序和验收范围。
- [作家的桌面](writers-desk-design.md)：老 iOS 控件风格、稿纸中心、模块化布局与按需展开。
- [正文修改与版本流程](manuscript-editing-design.md)：随时触发的手工修改支线、跨章工作副本、完成后的处理及对话整体调整。
- [模型上下文与正文摘要](context-and-summary-design.md)：账本与摘要常驻、更新、按需原文及显式模型工具的边界。

方案包含构思期对话与正文编辑布局、个人 API 接入与本地模型试用引导、可展开的思考与执行过程，
以及人物关系、线索关联、作案手法和时间线的可视化。相关依据与阅读体验建议融入同一账本和正文工作流。

主要过程围绕创作台、对话框和选择按钮完成；历史与差异按需查看。手工修改无需模型，版本记录后将摘要和账本更新建议标为待处理，由作者按需启动相应模型功能。
全书背景与当前章节的角色知情、读者披露边界一并进入写作任务，避免回写前章时提前透露后文信息。
执行日志保留明确的按需入口，持续记录 Agent 事件流，支持实时查看和跨会话回看；过程详情默认收起不影响日志记录。
前端说明直接写明用途、条件、操作和结果；作者模型与模型一致性审计均不是完成修改的前置条件。
