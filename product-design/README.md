# 产品设计

本目录集中保存产品方案、用户旅程、交互设计和可视化设计。文档需明确提案与已交付状态；开发阶段计划和构建记录仍见 [dev-notes](../dev-notes/README.md)。

## 版本约定

项目尚在开发中，产品版本统一使用 `0.x`：原 V1 称为 **0.1**，原 V2 称为 **0.2**，下一版本为 **0.3**。
下列方案归入 0.3，仍需完成评审与实现；开发包版本统一为 `0.3.0`，不表示 0.3 已交付或发布。
后续产品迭代按 `0.4`、`0.5` 递增，修复版本使用第三位编号。

产品版本与接口、数据格式版本分别管理；现有目录、`/api/v2` 与架构标识保持兼容，历史记录中的 V1/V2 分别对应 0.1/0.2。

## 0.3 产品方案

- [作家的桌面：视觉与交互原则](writers-desk-design.md)（2026-10-17，整体方案待评审）：已确认前端延续老 iOS 风格；稿纸居中、工具在手边，以留白、排版和按需展开保持简洁优雅，同时确保操作与反馈清楚。
- [Agent 主工作区与故事账本](agent-first-workbench-product-design.md)（2026-10-17，整体方案待评审）：以人物、线索及账本关联组织创作，将伏笔、悬念与信息揭示融入写作指导；覆盖从想法到正文的完整旅程，已确认保留记录 Agent 事件流的执行日志。
- [正文修改与作者长期记忆](editing-and-author-memory.md)（2026-10-16，待评审）：直接编辑形成版本，模型空闲时归纳作者记忆；通过对话确认并执行整体故事调整。
- [悬疑审计交互设计](mystery-audit-interaction-design.md)（2026-10-16，待评审）：有正文后才能检查，明确功能介绍、使用步骤、进度反馈、问题定位与复查；取消独立修改审计模块。

方案包含构思期对话与正文编辑布局、个人 API 接入与本地模型试用引导、可展开的思考与执行过程，
以及人物关系、线索关联、作案手法和时间线的可视化。故事依据检查与阅读体验建议融入同一账本和正文工作流。

主要过程始终围绕创作台、对话框和选择按钮完成；历史与差异按需查看，作者记忆在后台积累并可通过对话纠正。
执行日志保留明确的按需入口，持续记录 Agent 事件流，支持实时查看和跨会话回看；过程详情默认收起不影响日志记录。
前端说明直接写明用途、条件、操作和结果，悬疑审计的反馈与处理也在同一工作区完成。

2026-10-16 已确认取消“节拍”（Beat）概念：创作直接依据人物、线索、作者要求与正文范围，后续移除独立节拍对象及其任务依赖。
决定、信息归属与验收要求已记入当前方案；代码与存量数据尚未调整。
