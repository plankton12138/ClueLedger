# Hastings 0.3：Agent 主工作区与故事账本产品方案

> 性质：产品评审后的目标方案，范围决定已确认；不维护实施进度，不分配新的阶段编号。当前行为与差距见[模块说明](../dev-notes/v0.3/modules/README.md)。
> 日期：2026-10-17。
> 目标版本：0.3（开发中）；接续 0.2（原 V2），版本约定见[产品设计入口](README.md#版本约定)。
> 依据：作者确认“主体类似 Work Agent，右侧边栏为小说专用账本；进入软件就知道先做什么、想法放哪里”。
> 本提案调整 Phase 19 的界面主次：尚无正文时以主区对话接住想法；已有正文后，创作台中间默认展示文章，右侧常驻故事账本。
> 创作台与对话框始终是主入口；手工修改为随时触发的跨章支线，整体故事调整在对话中完成。
> 作者决定权、版本记录、影响分析和正文保护作为系统能力融入上述流程。
> 2026-10-17 评审决定：账本与正文摘要作为模型常驻上下文；作者模型与模型一致性审计保留设计，0.3 不实现。

## 1. 产品定位与体验目标

**Hastings 以故事账本为创作基础，围绕人物、线索及其关联，帮助作者发展和书写故事。**

账本既记录故事中发生了什么，也承载这些内容将如何被读者逐步发现。
Agent 在创作过程中协助维护人物动机与事件因果的一致性，并结合伏笔、悬念、信息揭示和情绪变化提出写作建议，
最终由作者决定故事的表达。

对外始终是一个熟悉当前作品的写作伙伴；策划、写作和修订是内部协作方式，模型一致性审计留待后续。
作者可以从一个人物、一条线索、一段关系或一个疑问开始，逐步建立关联并写成正文。
章节和场景承载故事内容，不构成必须先创建、审批才能开始写作的规划层级。
作者不必在第一次输入前选择后台角色，也不必先掌握变更集或提交等内部术语。

**主要互动发生在创作台与对话框中，通过手工修改、自然语言和少量选择按钮完成。**
独立的协作主编表单、修改审计与修订审阅入口由同一工作区内的流程承接；移除入口前须完成能力替代。
作者随时点击“手工修改”，可修改多章的不同部分，点击“修改完成”后统一记录版本；摘要更新与账本更新建议整理分别由作者明确启动。
更换凶手、手法或背景时，作者在对话中说明要求，Agent 理解关联、确认必要选择后统一修改。

### 0.3 范围边界

账本与正文摘要提供每轮稳定的作品背景，精确任务按需读取原文；详见[模型上下文与正文摘要](context-and-summary-design.md)。
作者模型、自动学习写作习惯、全文/章节模型一致性审计和 RAG 均为后续保留项，0.3 不开发、验收或隐含触发。
参考材料导入、材料库和写作风格语料同样留待后续；导入已有小说正文仍保留，见[材料范围](future/reference-material-design.md)。
保留设计不表示提供可用占位按钮；0.2 的实现与历史数据按现状保存，不在本轮删除或扩展。
本次修改所需的版本、范围和引用校验继续保留，不能包装为已经完成模型一致性审计。

### 产品决定：取消节拍概念

2026-10-16 确认：项目取消“节拍”（Beat）这一独立概念。作者围绕人物、线索、章节和正文表达创作意图，
无需把故事拆成节拍，也无需创建、批准或维护节拍后才能写作。这样可以减少从想法到正文之间的组织负担。

此决定覆盖产品界面、领域对象与任务依赖：后续实现移除节拍目录、编辑与审批入口，以及以节拍为单位的生成、检查和关联契约，
不将节拍换名后继续保留，也不在后台自动创建隐藏节拍来满足旧流程。

原先由节拍承载的有效信息按用途归入已有内容：人物目标与变化关联人物及具体故事事件；
伏笔、未解疑问和揭示安排关联人物、线索及正文位置；视角、表达目的和写作范围直接进入本次任务要求。
章节、场景与选中段落用于组织和定位正文，不增加一个替代节拍的强制最小规划单元。
取消节拍不取消对叙事节奏、因果、悬念或信息披露的判断，这些判断结合账本与具体正文给出建议。

本次先记入产品设计，代码与存量数据尚未调整。[V2 总设计](../dev-notes/v0.2/DESIGN.md) 中的节拍层级及相关模块契约
属于待修订设计；涉及节拍的后续实现以本决定为准。实施时需同步清理前后端接口、任务输入、上下文与关联引用，
妥善处理已有记录中的有效信息，不以只隐藏界面入口作为完成标准。

### 创作判断如何融入产品

产品内部从两个角度理解同一组故事内容，两者共同服务于账本与正文：

| 观察角度 | 关注的问题 | Agent 的协助方式 |
|---|---|---|
| 故事内部是否成立 | 人物行动是否有动机，线索如何产生，时间与因果是否一致，角色从何处获得信息 | 指出相关记录、具体矛盾或缺少的依据，并提出可检查的调整方式 |
| 读者如何经历故事 | 此刻知道什么、怀疑谁，哪些疑问应保留，伏笔何时出现与回应，情绪怎样变化 | 结合正文与作者意图，提出有理由的表达方案，说明可能带来的阅读感受 |

日常创作中的这两个角度不成为独立模式、导航页或评分体系。用户始终围绕人物、线索、真相和章节操作，
看到的是具体提示，例如“妹妹还没有获得这条信息”或“这里说明姐姐的动机会提前解开疑问”。
事实冲突需要依据；信息缺失需要说明未知；表达建议保留作者取舍。
刻意留白、延迟解释和不可靠叙述不能直接判为错误，阅读体验建议也不能作为阻止写作或采用正文的硬门槛。

### 用户需要获得的清晰感

三个需要直接被界面回答的问题：

1. 我的想法放哪里？——工作区唯一的协作输入框，想法和粘贴文字从这里进入并保存为讨论；已有正文时，输入框服务于正在阅读和编辑的文章。
2. 现在可以做什么？——Agent 根据实际进展给出一个主要建议和至多两个备选动作。
3. 哪些已经确定？——右侧账本的“已确认”内容；讨论、候选和正式正文有各自明确状态。

产品成功首先取决于这三个答案是否清楚。视觉与交互以“作家的桌面”为基准：一张稿纸、几本书、
一支代表 Agent 的笔，以及少量明确操作。正文居中，工具安静可达，留白和排版形成简洁优雅的阅读环境。
完整原则见[作家的桌面](writers-desk-design.md)。

### 各区域的职责

2026-10-17 补充：采用[模块化布局与空间利用原则](writers-desk-design.md#模块化布局与空间利用)，参考 dark 原型的大字号、清楚分区与充分使用页面的方式。
各模块按当前任务分配宽高，保留适当间距与内部边距；下列侧栏宽度为起点，可随内容和屏幕调整，优先保障文字可读。
布局与控件结合已确认的老 iOS 风格，原型中的功能和页面不作为成品要求。

| 区域 | 固定职责 | 规则 |
|---|---|---|
| 顶栏 | 作品身份、模型、作品设置 | 配置完成后收纳全局入口；未配置时主动显示接入引导，不能只留下一个空模型菜单 |
| 左侧导航，展开时约 180–220px | 找回讨论与正式稿件 | 默认紧凑目录，可收起；保留正文导入，不提供参考材料库入口 |
| 主区，使用剩余宽度 | 构思时展示对话；已有正文时默认阅读和编辑文章 | 创作台与对话框持续可用，文章占据主要空间；历史、方案和图谱作为临时视图按需打开 |
| 右侧账本，展开时约 300–340px | 已确认事实、结构与待确认候选入口 | 桌面保留轻量摘要，可收起；优先本章相关，完整目录与详情按需展开 |

主区按内容状态确定默认工作焦点：没有正文时展示完整对话；已有正式正文或导入稿件时，
进入创作台直接打开当前章节，没有阅读记录则打开第一章。仅有未采用试写时仍明确标为候选，不能冒充正式稿。

正文下方保留同一个对话区和输入框，引用条标明当前章节和版本；选中文字后可将该段作为明确引用。
进入手工修改支线后显示“手工修改中”与“修改完成”，正文切换为本轮工作副本；可跨章修改并暂存返回。
默认模型背景仍是正式账本和摘要，明确引用修改稿时附其快照，避免混用正式版本与未完成内容。
回复先在下方的紧凑结果区呈现，长讨论按需展开并限制高度，文章保持主要阅读空间。
作者可以主动打开完整讨论、候选、方案、差异或图谱；提供清楚的“返回正文”入口。
来回切换保留文章的未保存编辑、光标、选区和滚动位置，也保留讨论的滚动位置。
关闭临时成果后恢复正文及其目标引用；切换当前对象时更新自动引用，作者手动添加的引用继续保留。

发送消息、收到回复、任务完成和收到设定候选，都不能自动把正在阅读的正文替换成完整聊天记录或新候选。
明确点击“查看候选”“查看改动”才进入对应视图。作者采用首章后，主区显示刚采用的正文，进入写作状态。
已明确授权的整体修改完成后，同一正文视图更新至新版本并保留章节定位；有正在编辑的内容时先处理版本冲突。

主区最多打开一个完整成果或完整讨论，协作输入与摘要位于其下方，避免重现四列布局。
用户需要完整空间时，可以收起左侧导航和账本。
正文上方只保留章节名、简短状态和必要动作；历史和图谱按需打开，本版不展示模型一致性审计按钮。
功能入口使用明确文字，纸张、书籍、印章等意象用于指导视觉轻重，不替代可理解的功能名称。

### 屏幕适配

- 宽屏：左导航、主工作区、账本三部分；主区保留可读的文字宽度。
- 中等屏幕：左导航折叠，主区与账本并列；空间不足时账本改抽屉。
- 手机：先呈现主区；已有正文同样默认显示文章，协作输入可收起再展开；顶栏“账本”打开抽屉。

## 3. 首次进入：先准备模型，再接住想法

首次进入先读取模型配置和实际可用状态。未配置时优先展示 §3.2 的接入引导；
已配置且可用时直接进入构思或正文。已有配置但连接失败时保留原配置，提供重试与切换入口。
接入模型不要求先创建作品，也不收集作品名、大纲等业务字段。

### 3.1 没有作品

模型已就绪、尚无作品时，主区文案：

> 你想写一个怎样的故事？
> 一个画面、一个人物，或一句还没想清楚的念头，都可以从这里开始。

下方直接显示输入框，示例占位：“一场暴雪把几名住客困在雪山旅馆，第二天有人死了……”
辅助入口为“导入已有稿件”，进入同一个工作区。

不要求预填作品名、字数、类型、文风或完整大纲。第一次发送或点击“保存想法”创建一个“未命名作品”，
保存这条作者消息，之后再建议合适的作品名。操作前的小字分别说明“发送后开始一部新作品”或“保存后开始一部新作品”。

0.3 不提供空白首章的“直接写作”入口。首版正文来自模型生成候选后的采用，或导入已有正文；“手工修改”只针对已经形成正式版本的正文。

没有发起消息时，保存结果按需进入本作品复用的“创作记录”默认讨论；作者无需先创建会话。
导入时展示实际章节、正文及写入目标预览，确认后形成版本，规则见下节。
导出和备份入口保留在作品设置，不因移除概览页而丢失；导入与导出的文件格式、大小限制在实施契约中明确，写入行为以本方案为准。

还没准备展开的念头持续保存在讨论中，作者可从对应消息继续，不必先收藏才能留住输入。
本版不提供依赖材料库的“存为灵感”入口；讨论内容不会因此进入正式设定。

右侧账本空态：

> 这里会保存你确认过的故事设定。
> 先说说想法，稍后再整理也可以。

不显示空表格、虚构的完成百分比或要求作者填满的设定清单。

#### 正文导入的写入规则

首次导入可在确认时创建未命名作品；导入已有作品时默认在目录末尾新增章节，不按同名标题自动匹配或覆盖。
预览逐项显示实际正文、章节顺序及“新增”或“替换”的目标；作者可调整新增章节的名称，取消预览不改正式内容。
需要替换时由作者明确选择现有目标章节，展示前后差异；0.3 不隐含执行段落合并或向已有章末追加文本。
同一次导入中的目标不得重复，全部选中内容一次保存为一个版本，并生成固定归属的结果记录；部分解析或保存失败不发布半份导入。

确认前核对预览基础。涉及未完成人工副本的目标章节时，先完成该轮修改，或取消本次导入；不覆盖或自动放弃副本。
正式目标已变时更新预览并由作者重新确认；无关章节变化经核对后可继续，不误报目标冲突。
网络重试及重复点击返回同一次导入结果，不重复创建作品或章节。再次主动导入相同内容时提示已有导入记录，
由作者选择取消、明确新增副本或选择替换目标，不把相同文件当成新的自动写入授权。
导入后沿用摘要、正文证据核对、账本更新建议及关联撤销规则，不额外建立一套正文事实源。

### 3.2 没有配置模型

**检测到未配置模型后，立即引导，不等作者点击发送才告知无法对话。**

没有正文时，主区首先展示：

> 先为你的写作伙伴连接一个模型
> 可以连接你自己的模型服务账号，也可以下载本地模型试用。
> [连接已有模型]　[下载本地模型试用]
> 也可以先记录想法或导入稿件，稍后再配置。

两条路径并列可见，不要求用户先理解“提供商”“端点”等技术概念：

| 路径 | 引导步骤 | 完成后 |
|---|---|---|
| 连接已有模型 | 选择服务 → 填写用户自己的 API Key → 获取并选择模型 → 测试连接 | 保存用户的连接与当前模型，显示测试结果并进入创作 |
| 下载本地模型试用 | 检测本地运行环境与已有模型 → 使用已有模型，或选择适合设备的试用模型 → 安装引导/下载 → 加载并测试 | 设为当前模型，返回原工作区 |

已有本地模型时优先提供“直接使用”，不要求重复下载。对熟悉本地服务的作者，保留连接已有本地服务的入口。
服务预设隐藏不必要的地址字段；仅自定义连接展开高级配置。

#### 用户自带 API Key

当前产品按“用户使用自己的模型服务账号与 API Key”设计。连接页直接提供服务选择、
“填写你的 API Key”、获取密钥帮助、测试连接和模型选择；用户可以更换或删除自己的连接。
已保存密钥只展示掩码与配置状态，修改时重新输入，不在普通查询、日志、对话或导出中暴露完整密钥。
本地桌面形态由应用管理用户自己的凭据，不能要求普通用户编辑环境变量或项目配置文件。

现有界面的“使用服务端环境变量 DEEPSEEK_API_KEY”表示从运行后端进程的环境读取密钥，
属于开发或自行部署的配置能力；新产品的普通接入流程移除此选项，避免用户误解为使用平台提供的额度。
界面未配置个人密钥时明确引导填写，不静默借用部署环境中的其他凭据。
配置保存、连接测试、模型选择和实际任务调用必须使用同一个用户连接，前后端保持一致。

当前范围是个人 API 接入和本地模型使用。Hastings 的收费、订阅、充值、平台代付及统一模型额度
留待后续独立讨论，不在本轮引入收费计划，也不把用户自己的 API 使用称为平台免费试用。
模型服务费用由用户与所选服务方的关系决定；本地模型入口明确写“下载到本机运行”。

#### 本地试用的具体体验

1. 先检测运行环境、可获得的设备信息和已安装模型。环境缺失时显示安装引导及重新检测，不能声称模型已经可用。
2. 默认突出一个适合当前设备的试用选项，并提供“其他模型”。展示模型名称、下载大小、资源需求和预期用途；
   无法可靠检测设备时说明依据不足，由作者选择，不能保证流畅运行或高级创作任务一定成功。
3. 作者点击下载后显示真实阶段：等待下载、下载中、加载中、连接测试、可使用；下载进度、大小和错误来自实际服务。
   进度不可得时展示阶段，不编造百分比；提供取消和失败重试，返回引导时回读真实状态。
4. 下载成功只表示文件已获取。模型加载及实际调用测试通过后才能标为“可使用”，再提供“开始创作”。
5. 环境安装失败、资源不足或模型调用失败时，说明具体原因并提供重新选择或连接已有模型；
   不把安装、下载或调用故障包装成故事任务失败。

不在产品方案中固定某个模型及硬件门槛；交付时依据实际可用目录和设备适配给出选项。
复用现有本地模型检测、下载与配置能力，新增的是首次引导与状态衔接；现有设置入口继续可用。

#### 保留想法与已有作品

模型引导为优先入口，仍允许“先记录想法”或“导入稿件”。未就绪时明确标示暂不能使用 Agent。
选择“先记录想法”后沿用唯一输入框，主动作显示“保存想法”；保存为作者消息，标明“尚未请求 Agent”，不创建模型任务或伪造回复。
尚无作品时首次保存创建未命名作品及讨论，并固定消息归属；此后可连续保存多条想法，切换作品或讨论不混用记录，重试不重复创建。

点击保存前，文字仍是自动暂存的输入草稿；尚未创建作品时属于新作品入口，创建后绑定实际作品和讨论。
配置过程中、失败、刷新及重启后均保留草稿与已保存消息，恢复时区分两者。连接成功回到原位置，不自动发送草稿或批量重放已保存消息。
作者可继续编辑草稿并发送，或从已保存消息选择“让 Agent 接着讨论”；后者引用选定消息并标明实际读取范围，不重复创建原作者消息。

已有正文时，模型未配置也保持文章在中间可阅读、编辑和保存，在正文下方协作区展示接入卡片，
不以整页配置遮住文章；右侧已有账本仍可查看和人工维护。作者点击 Agent 功能时展开同一接入流程。
连接失败保留输入和原配置，并区分未配置、下载中、加载中、可用与连接失败，不能只显示一个笼统的“未连接”。

### 3.3 已有作品，重新进入

进入创作台时，有正文就恢复上次阅读的章节及位置，无阅读记录则打开第一章；没有正文才恢复上次讨论。
作者主动进入左侧“讨论”时可以查看完整对话，并随时返回正文。继续提示放在正文下方的协作区或构思对话中，例如：

> 上次讨论到姐妹关系；开场试写还没有采用。
> [继续修改开场] [接着讨论] [查看待确认设定]

提示依据真实的讨论、候选和任务状态生成。打开作品只回读状态，不因进入页面创建新的创作任务。
如已有任务正在执行，显示当前阶段及取消入口；如失败，显示恢复动作，而不是假装已经完成。

## 4. 单一输入框与引导方式

输入框始终接收作者自然语言，不出现“planner/writer/auditor”等角色选择。
输入框附近只放引用和必要的发送/停止操作，创作动作出现在具体讨论附近；本版不提供参考材料附件上传。

| 用户行为 | 产品如何响应 | 作者看到的下一步 |
|---|---|---|
| 讲想法、提出假设 | 讨论、对比方案；不自动修改故事 | 一段回应，必要时一个关键问题 |
| 粘贴文字 | 保存为消息并说明实际读取范围，不创建材料库条目 | 继续讨论，必要时整理设定建议 |
| 导入已有正文 | 预览章节和实际文本，作者确认后形成正式正文版本 | 阅读、手工修改及摘要待更新入口 |
| 选择一种故事方向 | 显示该方向的清晰摘要 | “记入账本”或“继续调整” |
| 请求试写或起草 | 汇集相关人物、线索、已确认事实及作者的表达要求，整理本次范围 | 一次明确的生成动作 |
| 想埋伏笔、保留悬念或改变读者判断 | 基于相关人物、线索及已有正文提出表达候选，说明可能的效果 | 选择一种写法、继续讨论或保持原稿 |
| 点击“手工修改”后编辑正文 | 建立跨章工作副本并自动保存；完成时统一记录实际差异和版本 | “修改完成”；随后可选择“更新摘要·使用模型”“整理账本更新建议·使用模型”或继续写 |
| 请求修改建议或备选写法 | 绑定当前正文与选中范围，给出可比较的候选 | “使用这版”或继续提出要求 |
| 明确要求修改现有正文 | 确认必要的意图与范围，在授权内修改并记录版本 | 结果摘要、“查看改动”“撤销这次修改” |
| 要求更换凶手、手法或故事背景 | 在对话中理解全局关联，澄清必要选择后统一修改账本与相关正文 | 一次整体执行选择；完成后继续阅读和修改 |
| 说明本书的表达要求 | 作为作者明确的作品约定进入本书上下文，不推断跨作品偏好 | 回报实际记录范围；可继续调整 |
| 请求全文或章节一致性审计 | 说明该独立模型工具留待后续，0.3 不启动审计 | 可讨论明确引用内容，不冒充完整检查报告 |

本次任务要求不自动升级为本书约定；作品设置中的“本书约定”可直接查看、修改和移除，来源、冲突及任务快照规则见[本书约定的记录与维护](context-and-summary-design.md#22-本书约定的记录与维护)。

### 引导原则

- 每次只问一至两个真正影响下一步的问题，避免连续填写式的访谈。
- 已给出的信息不再重复索取；未确定的内容允许保持开放。
- 推荐动作至多三个；给出“为什么现在适合做这件事”，例如“姐妹关系已确定，可以试写她们抵达旅馆时的第一次交锋”。
- 用户随时可以忽略推荐并继续说话，不用完成整个设定清单才能尝试一幕。
- 对已经完成的工作不反复推荐同一个动作；切换讨论也不清空作品进展。
- 对读不完的粘贴文字或正文明确显示范围与省略，不能把标题、摘要或局部摘录说成全文已读。

### 前端说明与反馈

设计理念由交互体现：作者明确决定创作后 Agent 才开始相应任务，试写候选经作者采用后才进入正式稿。
不以“作者拥有最终解释权，Agent 提出候选，接收才进入正文”等常驻黄色提示框代替实际行为；
操作顺序、触发条件和结果反馈应让作者自然感知自己的决定权，具体示例与验收见[桌面交互原则](writers-desk-design.md#通过交互让作者感知设计理念)。
作者已经明确要求创作且范围清楚时直接执行，不为体现决定权增加重复确认；已授权修改仍遵循下节执行边界。

功能入口使用明确名称；打开时用简短说明解释“检查或修改什么”“操作哪些内容”“完成后得到什么”，详细规则按需展开。
使用前提供必要的范围与条件，使用中显示实际状态，使用后在原位置更新为可查看的结果，避免不断新增状态卡。
避免用“洞察故事脉络”“让故事更精彩”等修辞替代功能介绍、空态或结果说明。
按钮写具体动作，例如“检查当前章”“定位原文”“重新检查”，不只写“探索”“优化”“处理”。
错误提示说明失败对象、原因及下一步；没有结果、尚未完成和执行失败分别呈现。
这些规则适用于整个前端；后续模型工具见[模型一致性审计](future/consistency-audit-design.md)，不计入本版交付。

### 执行边界

系统区分讨论、试写建议和明确执行要求。“假如姐姐是凶手会怎样”进入讨论；
“给我一个替代写法”产生候选；明确的“按这个改”授权在已说明的范围内执行并记录版本。
意图、对象与范围已经清楚时可以直接开始，不再要求填写角色表单或重复点击确认。

若作者要更换凶手、手法或背景，Agent 先阅读相关账本与正文，整体确认理解：将改变什么、保留什么、
哪些已写内容需要联动，以及哪些关键选择尚不明确。必要的澄清和选择全部在对话中完成。
未确定范围时提供“按这个整体修改”“调整要求”“先看看方案”等按钮；作者已明确认可同一范围时不再重复确认。
内部的分析、起草、校验和版本记录由系统连续执行，不要求逐页发起或逐章批准。

首章试写和明确要求比较的方案仍先以候选呈现；已授权的整体修改通过版本、范围、引用及本次要求的检查后统一形成新版本，
不追加逐段采用的必经环节。超出授权的事实变化、关键歧义或与新编辑的冲突才返回对话询问。

### 思考与执行过程：默认折叠，随时展开

每轮回复或创作任务提供一个可展开的过程区域，放在对应回复或任务卡上方。
默认只占一至两行，显示当前状态、简短过程预览和展开入口；用户能看见过程正在输出，也能按需查看详情。
已有正文时，该区域位于正文下方的协作区，限制展开高度并独立滚动，保持文章的阅读和编辑空间。

```text
▸ 思考过程 · 正在输出                   [展开] [停止]
  （预览模型公开返回的最新一段过程内容）

展开后：
▾ 思考过程                              [收起]
  模型公开返回的思考内容或推理摘要，随接收逐步显示……
▾ 执行记录
  实际读取的章节与账本条目、检查结果、已完成或失败的操作……

正式回复 / 修改建议
  ……
```

展示内容按来源区分：

| 内容 | 展示规则 |
|---|---|
| 模型公开返回的思考内容或推理摘要 | 有对应输出时逐步展示；若服务只提供摘要，明确标为“思考摘要” |
| 应用的执行记录 | 根据实际事件显示读取、检查、生成等阶段，以及相关对象和结果；可从引用定位依据 |
| 正式回复与创作结果 | 独立展示，可直接阅读；不与过程内容混为同一段正文 |

模型没有提供可展示的思考内容时，显示“该模型未提供思考内容”，仍展示真实执行状态。
只有收到对应过程输出或执行事件时才描述具体活动；等待响应时显示“等待模型响应”，不能编造正在分析哪些人物或线索。
过程预览是临时推演，不能自动成为账本事实、正式正文或已执行操作的证明。

交互细则：

- 生成中可以随时展开或收起，展开后继续流式显示；用户向上阅读时停止自动滚动，提供“回到最新”。
- 完成后保留可回看的过程；折叠标题更新为“已完成”，作者主动展开的区域保持展开，不强行收起。
- 停止或失败时保留已经收到的内容并标明“已停止”或“失败”，同时提供具体恢复动作。
- 重试作为独立尝试记录，前一次的过程与结果不会混入新一轮；刷新后可恢复已保存的过程和真实任务状态。
- 详情只呈现可公开展示的模型输出与应用事件，不把凭据、内部配置等敏感内容带入界面。

实现时需要前后端分别传递和保存过程内容、执行事件及最终回复，不能只在最终文本里寻找特定标签来猜测。
是否支持思考内容以实际服务能力及返回结果为准；不能设计一个可展开入口却没有相应的数据与恢复接口。

### 执行日志：保留 Agent 事件流

2026-10-17 已确认：**产品仍需保留执行日志，用于记录和回看 Agent 事件流。**
日志帮助作者理解 Agent 实际做了什么、任务停在哪里，也为学习和检查 Agent 编排过程提供依据。
默认收起过程详情只改变展示方式，事件仍持续记录并保存；对话摘要和最终回复不能替代执行日志。

- **入口与展示**：创作台保留明确的“执行日志”轻量入口，按需打开独立滚动的日志视图；
  对话中的执行记录展示同一事件流的任务片段，并可定位到对应日志。作者已明确启动、离开当前视图后继续运行的任务也纳入记录，不要求先有一条对话回复。
- **记录范围**：包括任务开始与结束、Agent 调度与交接、模型调用、工具调用及结果、作品内容变更，
  以及等待作者输入、失败、停止和重试等实际发生的事件。思考内容是否可用不影响事件记录。
- **事件信息**：每条事件保留唯一标识、发生时间、执行顺序、所属作品、任务与本次尝试、执行 Agent、事件类型和结果摘要；
  涉及子任务、工具或内容变更时关联相应调用、对象与版本，展开可看必要详情和失败原因。
- **实时与回看**：执行中持续追加，支持按任务和事件类型筛选；向上阅读时暂停自动滚动，可回到最新。
  刷新、重进作品后可恢复历史；停止和失败保留已有事件，重试单独记录尝试并关联原任务。
- **前后端一致**：后端持久保存真实事件，提供历史查询与实时订阅；重连能补齐断开期间的事件，
  前端按事件标识去重并保持执行顺序，不从回复文字推测事件。没有事件时明确空态，连接中断不能显示为任务完成。

执行日志记录应用可观察到的行为；模型公开返回的思考内容或摘要仍在对应过程区域展示。
日志中的调用详情需过滤密钥等敏感信息；作品变更事件关联版本历史，日志本身不替代正文版本与恢复能力。

### 常驻上下文：账本与正文摘要

每轮自动携带作品约定、已确认账本、正文摘要及其版本，作用类似项目的 `AGENTS.md`。
摘要包含全书概览与逐章进展；长作品按预算分层，保留核心及索引，当前相关细节按需展开。
精确修改和矛盾判断需读取实际原文，不能把摘要当作全文阅读证明。
人工修改期间，正式上下文与显式引用的修改稿快照分别标识。采用、导入、修改完成或历史恢复后，
只将受影响摘要标为“待更新”；作者明确启动后才生成摘要，未更新或失败状态可见，后续任务不能静默使用过期背景。
摘要更新与账本更新建议整理均需作者明确启动，运行后可停止、去重并让出前台资源；启动其中一项不夹带另一项，也不连带运行作者学习或模型一致性审计。详见[上下文设计](context-and-summary-design.md)。

## 5. 右侧故事账本

账本是创作的组织基础，围绕人物、线索及其关联保存可检查、可引用、可修改的作品依据。
同一条目同时关联其故事事实和叙事作用；讨论中的可能性、作者的安排与正文中已发生的表达必须区分。

### 5.1 内容组织

1. **本次相关**：当前打开的章节或任务用到的条目；显示相关原因，点开能看完整内容。
2. **待确认入口**：例如“待确认 2 条”，展开为独立候选区，不混入已确认条目列表。
3. **已确认目录**：故事核心、人物与关系、真相与线索、时间与地点、章节与场景。
4. **最近确认记录**：谁确认了什么、何时更新；版本细节按需展开。

上述分组是内容组织方式，不要求同时展开。右侧默认只展示本章相关的简短摘要、完整目录入口和非空待确认提示。
点人物打开详细设定；点章节打开主区稿件；点修改记录打开差异，历史记录按需展开。
大篇幅编辑可以在主区打开账本条目详情，右侧仍保留目录定位。

账本同时提供人物关系、线索关联、手法结构和时间线的可视化入口，详见 §5.4–5.8。
这些视图承担作者理解与推演故事的核心工作，不作为交付完成后的装饰性增强。

### 5.2 什么能进入账本

| 内容 | 保存在哪里 | 是否成为生成依据 |
|---|---|---|
| 作者随口提出的可能性 | 讨论记录 | 作为假设讨论，不能当成既定事实 |
| Agent 整理的设定候选 | 待确认候选及其来源 | 可以比较，不自动当成正式事实 |
| 作者确认的设定或直接编辑保存 | 正式账本及版本 | 可以；任务记录实际使用的版本 |
| 作者确认的伏笔、悬念或揭示安排 | 相关人物/线索条目的叙事安排及版本 | 作为写作指导；计划中的安排不代表正文已经实现 |
| 采用、导入或修改完成的章节 | 正式稿件及版本、派生摘要 | 正文可引用；事实经有来源的候选核对后更新账本 |

“作者确认了某条设定”与“角色知道这件事”是两个维度。
悬疑账本继续区分真实发生的事、角色认知、读者已知；不能把角色猜测登记成客观真相。
正文形成版本后共用账本更新建议整理路径，集中核对新增、冲突和认知陈述；未处理项保留可见状态。
建议在本次结果对应的对话中成组呈现，右侧只提供数量和定位入口；无需独立页面或逐句审批。
每次导入、采用或修改完成创建唯一的持久结果记录：绑定发起会话或本作品当前会话，无会话时复用“创作记录”默认讨论。
归属固定后，作者明确启动的任务始终更新该记录；切换讨论或作品不改变归属，不自动跳转视图，历史与账本入口均可定位回看。
任务依赖某项冲突时才询问作者，不因未入账本而忽略已写内容，也不静默选定冲突一方。

### 5.3 设定确认与修改

候选卡展示具体条目、原文来源以及“哪些仍未确定”。提供“采用选中条目”“调整”“暂不采用”。
允许同一小组候选一次确认，也允许只采纳其中几条；不会要求每句话都点击确认。
正文产生的账本更新建议沿用相同确认规则，在原对话展示依据与调整，作者可以“更新选中条目”“调整建议”或“暂不更新”。
生成返回和采用前核对来源正文与对应账本；相关内容已变化时标为“需重新核对”，不能原样采用旧建议。
已明确授权的同范围联动更新不重复确认，单独采用建议只更新选中账本条目，详见[修改与建议流程](manuscript-editing-design.md)。
建议及采用后的账本变化关联原始正文操作；撤销该次正文修改时一并核对关联变化，保护后续独立编辑。

作者从账本直接编辑并点击保存即构成明确操作，保存后回读实际版本。
既定设定的变化附带影响说明，例如“涉及第1章和第3章”；这个数字必须来自实际分析。
仅保存账本条目时，提示相关正文可能需要同步，并在对话中提供“同步修改相关正文”。
作者已通过对话授权整体调整时，账本和相关正文由同一次任务统一更新，不再要求分别批准。
正文与账本暂时不一致时保留可见提示，不能把单个条目保存成功说成整个故事已同步完成。

### 5.4 视觉账本：右侧概览、主区展开

作者补充要求：线索、作案手法、角色等需要更直观的可视化展示。

右侧账本提供“目录 / 人物关系 / 线索关联 / 手法结构 / 时间线”的视图选择。
默认呈现与当前工作相关的摘要、小图及选中条目，不把整个作品的几十个节点塞进窄栏。
点击“展开查看”在主区打开同一视图，底部保留唯一输入框；返回正文或讨论时保留图谱的定位，再次打开可继续查看。
账本目录和图形共用同一组对象与版本，不重新维护一份“图上的真相”。

各视图只展示能帮助作者作决定的信息：谁与谁有关、这条线索说明什么、手法怎样在故事中成立、
某个时间点发生了什么。节点数量、网络密度或视觉中心位置都不表示故事质量或嫌疑程度。

### 5.5 人物关系图

**主要回答：这些人怎样关联，各自想要什么、隐瞒什么、知道什么？**

- 节点是角色，卡片摘要包含身份、当前目标；秘密和动机点开查看，避免所有信息挤在图面上。
- 连线带关系名称和必要方向，例如“姐妹”“雇佣”“怀疑”“隐瞒”，不让作者猜线条含义。
- 真实关系和人物理解分开显示；可选择“作者全知”或某个角色视角。
- 选择章节/场景后，显示该位置已记录的关系与认知；信息缺失显示“未记录”，不能默认成“不知道”。
- 选中姐姐时，突出与她相关的人物、线索和场景；其他节点淡化，便于从局部理解故事。
- 人物详情可查看与其有关的未解疑问、读者目前对其身份与动机的认识，以及作者希望逐步展示的变化；未确定的内容可留空。

示例：姐姐与女侦探之间可以同时存在“姐妹”的真实关系，以及“妹妹怀疑姐姐隐瞒行程”的角色认知。
后者不能自动变成“姐姐作案”的作者事实。

### 5.6 线索关联图

**主要回答：这条线索在哪里出现、指向什么、曾被怎样误解、最终怎样解释？**

以线索为中心连接人物、事件、真相、误导解释和出现/回收的章节，边明确标注
“支持”“反驳”“曾被解释为”“首次出现”“最终解释”等关系。

示例叙事链：

```text
第2章发现的停走怀表
  ├─ 角色的初步解释 → 姐姐当晚离开过房间
  ├─ 已确认的客观事实 → 怀表在更早以前已经损坏
  └─ 第5章重新解释 → 原先用于判断时间的依据不成立
```

这些连接只有在账本存在对应记录时才展示为正式关系。Agent 提出的连接显示为待确认候选，
没有来源时显示缺口；不能仅凭回复措辞画出看似已被证实的推理链。

点击线索展开“客观内容、来源原文、作者解释、角色解释、读者何时看到、留下什么疑问、后续如何回应”。
计划出现、已在正文出现、计划解释、已在正文解释分别记录；已实现的状态必须关联具体正文及版本。
来源正文变化后，相关实现依据同步核对；需核对时仍可回看历史，但不能显示为当前正文已经实现，详见[正文证据状态](context-and-summary-design.md#31-正文证据的有效状态)。
可选择“截至第几章”查看已披露的线索，防止作者把后文才出现的证据误用到前面的推理中。
“还没有关联解释”可以是作者刻意保留的悬念，不直接判定为错误。

### 5.7 作案手法结构图

**主要回答：作者设定的真实过程、表面现象和破解依据如何对应，哪些成立条件尚未交代？**

以叙事机制组织，而不是只显示一段长文字：

```text
核心假象：看起来不可能发生的事情
  ↓ 依赖哪些人物、地点、时间与既定规则
真实过程：准备条件 → 关键事件 → 事后表象
  ↓ 产生哪些可以被观察到的证据
破解依据：哪条线索推翻哪种表面解释
```

- 0.3 只投影正式账本中已经存在的作案手法文字，以及与人物、地点、时间、真相、线索和正文位置之间已有的正式关系。
- 已有类型能区分“实际发生”与“证词/表面解释”时分轨展示；没有对应正式记录时显示“尚未记录”，不从描述中推断补齐。
- 同时只聚焦一个正式机制；存在已记录的备选时允许比较，采用前不替换正式真相。
- 已有规则检查明确发现问题时展示依据和定位；图中缺少关系只表示当前没有正式记录，不自动判为冲突。

0.3 不为了图谱新增步骤、条件或证据关系的结构化领域对象，也不启动模型从文字补图。
手法图的验收以忠实投影当前正式数据、清楚显示来源和缺口为准，图画得完整不代表手法逻辑已经成立。

### 5.8 时间线、视角与图谱交互

时间线按角色或地点分轨展示故事中的事件。实际事件与证词中的事件明确区分，
时间不确定时显示范围或“时间未定”，不能用猜测补齐精确时间。
选择一个时段可突出相关人物、线索、已有作案手法记录及其正式关系；故事发生时间与章节叙述顺序分别表达。
人物知情另关联实际获知事件；倒叙或插叙不能仅因章节先后就被判断为提前知情，证词时间与真实事件时间分别记录。

所有图谱遵循共同的操作规则：

1. 点节点看条目；点连线看关系含义及来源；从来源可定位正文、讨论或确认记录。
2. “加入讨论”把选中对象作为可见引用附到主输入框，例如“检查这条线索是否足以支持妹妹的判断”。
3. 已确认与待确认用文字标识配合线型区分；人物的误信、猜测是认知类型，不能混同于未确认数据。
4. 切换作者全知/角色视角/截至某章时，显式显示当前视角与范围；未知资料显示未知，避免提前泄露后续信息。
5. 拖动节点只调整布局；关系或作案手法文字的正式变更必须通过账本已有的编辑与确认路径，不能靠拖线直接写入正式账本。
6. 条目修改后按实际版本刷新，影响到的节点与连线可高亮；高亮只说明影响，不代表已完成修订。
7. 无障碍目录与文字详情同步可用，不能要求作者必须操作画布才能读写设定。

图谱引导也跟着创作进展出现：人物较多时建议查看关系图，线索出现后建议查看关联，
开始设计案件时建议打开手法结构；空作品不先给一个等待填满的大画布。

### 5.9 账本条目的叙事作用

伏笔、悬念、误导与揭示依附于具体人物、线索、关系或事件，并关联承载它们的正文位置。
作者可以从任意条目继续写作，例如“写出她第一次隐瞒行程的对话”“让这条线索先引起一个错误怀疑”。
这些要求直接进入本次写作任务，不要求建立额外的中间规划对象。

以“停走的怀表”为例，同一条目可以包含：

| 条目内容 | 示例 |
|---|---|
| 已确认事实 | 怀表更早已经损坏，与人物推断的时间不同 |
| 人物认知 | 妹妹暂时把它当作判断姐姐行程的依据 |
| 作者希望留下的疑问 | 姐姐是否隐瞒了当晚的去向？ |
| 计划中的呈现 | 首次出现时让人物自然注意到时间，暂缓解释损坏原因 |
| 正文中的实现 | 关联已出现的段落；尚未写到的内容保持“计划中” |
| 后续回应 | 在获得新信息后重新解释怀表；具体位置允许未定 |

以上信息按需补充，不作为创建条目或写正文的必填清单。伏笔可以是动作、对话或人物关系中的细节，
不要求所有伏笔都成为案件证据，也不要求每条线索都有误导或反转作用。
悬念可以来自人物命运、关系变化或事件结果；表达方式由作者选择。

Agent 的提示同时引用相关账本与正文：有证据的冲突指出具体矛盾；尚未落实的安排提示“还未写到”；
阅读体验建议说明意图和取舍，例如“暂缓这句解释可保留对姐姐的疑问，但会降低当前段落的清晰度”。
作者可以接受、调整或忽略建议，不设“精彩程度达标”之类的强制门槛。

## 6. 创作台中的正文与修改支线

完整规则见[正文修改与版本流程](manuscript-editing-design.md)；上下文来源与摘要更新见[上下文设计](context-and-summary-design.md)。

### 6.1 成果身份与正文中心

对话卡、稿件目录和账本入口打开同一稳定对象。卡片写明“候选”“正式稿”“修改稿”或“修改结果”，
不靠位置或颜色暗示是否已经采用。已有正文默认阅读，选中后可引用；点击“手工修改”才开启本轮人工修改副本。
首章候选的主要动作是“采用为第1章”；采用成功后回读实际正式版本，并显示文章。
候选若支持人工编辑，采用时必须提交作者实际预览的文本；首版也可明确只读，通过“继续修改”生成新候选。
不能沿用接受原始任务输出的方式而忽略作者在候选上的改动。

### 6.2 随时开启、跨章完成手工修改

这是一条随时可进入的创作支线，不是写满章节后才出现的阶段。作者点击“手工修改”，系统固定正式基础版本，
创建或恢复工作副本。此时显示“手工修改中”“修改完成”和“暂存返回”，自动保存负责防丢失，不推进正式版本。
作者可以修改第1章和第2章的部分文字，来回切章；第3章保持原样。切视图、切作品或重启后仍能找回本轮内容。

点击“修改完成”后，系统校验保存与基础，将本轮涉及章节的差异、正式版本、摘要失效状态和正文证据状态作为一次提交；任一状态写入失败时不发布该正式版本，保留工作副本并使用同一操作标识重试。提交成功后再进入后续处理：
将受影响正文摘要标为“待更新”、账本更新建议标为“尚未整理”，并提供各自的明确启动操作，作者也可直接继续创作。模型不可用时仍能记录版本，后续步骤保持待处理。
不运行作者学习或独立模型一致性审计，不要求填写修改说明或逐章确认。无实际差异不产生空版本，重复完成不重复记账。

默认对话背景是正式账本与正文摘要；手工修改时，明确引用的段落带修改稿快照及正式基础。
本轮 Agent 建议先形成候选，作者采用后保留生成来源，不能混为亲手写作。
正式内容已变化时先比较并处理冲突，不能覆盖新内容或自动丢弃工作副本。

### 6.3 从人物、线索与正文进入写作

作者可从对话、人物/线索条目和选中段落发起写作。任务直接记录：

- 相关账本内容及版本；相关线索不存在时允许为空。
- 作者希望写什么、采用谁的视角、输出到新章还是指定范围，以及大致长度。
- 目标正文位置及版本、截至此处角色实际知情与读者已披露信息，以及需要保留的揭示安排；从已有记录读取，缺失只在影响本次任务时澄清。
- 希望保留的疑问、伏笔、暂缓的解释或情绪变化；这些可以未定。
- 本次输出性质、正文基础与写入范围：试写候选、备选建议或已明确授权的修改。

不要求完整大纲、节拍或替代的隐藏规划对象。例如以姐妹关系与旅馆设定试写妹妹视角的抵达片段，
可以保留姐姐隐瞒事情的感觉而暂不确定凶手。模型新增事实保留候选身份；正文采用后可引用，并进入事实核对路径。
全书摘要中的后文信息保留来源位置；默认润色保持目标段落的信息披露范围。全局背景与当前可写入的信息分开约束，详见[上下文边界](context-and-summary-design.md)。
### 6.4 正文采用后的事实与摘要

导入、采用和人工修改完成共用同一后续路径：先保存正文版本，使对应摘要失效并核对正文证据，再提供摘要更新和账本更新建议整理的明确启动操作。
区分新增事实、与账本冲突、人物认知/证词及证据不足项；作者可集中采用、调整或暂不处理，不逐句确认。
尚未通过账本更新建议确认的信息不自动进入正式账本，但已写正文仍是后续任务可读取的内容。
任务确实依赖某项分歧时才澄清，不把“未入账本”当成“未发生”，也不把人物猜测当客观真相。

正文保存同时核对受影响的既有证据关联；“已出现、已披露、已知”的来源变化时标为需核对，不等待模型建议。
这项状态保护无需模型，无论作者是否启动后续模型处理都必须执行；它保留作者设定和历史来源，图谱与任务上下文共同遵守其有效状态。

摘要失败不回滚正文；下一次任务读取原文构建本次临时背景，不能静默拿旧摘要作最新背景，也不能夹带正式摘要更新。
账本、正文和摘要的实际版本可分别追溯。草稿自动保存不更新正式摘要，正式任务不能混读未完成修改。
账本更新建议在原对话处理；正文或相关账本变化后旧建议需重新核对。摘要更新与账本更新建议整理默认均不运行，分别明确启动；启动一项不能夹带另一项。
手工修改和导入也产生固定会话归属的结果记录，摘要与账本更新建议任务只回写该记录，无需先有一条作者消息。

### 6.5 对话发起整体故事调整

作者可以要求“把凶手改成姐姐，保留妹妹视角和旅馆背景，把前面的伏笔一起调整”。
Agent 先用账本和摘要建立全局背景，再读取必要原文，确认理解与真正需要作者选择的内容。
分析范围与允许修改范围分别明确；同一范围已经获得认可时不重复确认，不要求逐章批准。

内部工作版本连续修改账本与相关正文，记录各章节的实际覆盖；未读内容不能标为无需修改。
版本冲突、范围越界、引用失效必须处理；本次已发现的有依据的故事冲突需修正或请作者选择。
表达与阅读体验建议不阻塞发布；未覆盖要求范围时保留内部进度，不标为整体完成。
自动修正最多两轮，任务的调用/轮次上限可见；到达上限由作者选择继续，不无限重写。
本次内部校验不等于独立的章节/全文审计，不以模型一致性审计作为本版依赖。

完成后账本与正文统一成为新版本，受影响摘要标为“待更新”，主区保留文章与定位；对话显示实际修改摘要、后续模型操作及“查看改动”“撤销这次修改”。
有未完成手工修改副本时，可先分析或生成内部候选；发布前需完成人工修改并重新核对基础，或暂缓整体任务。
停止、失败、刷新都保留稳定版本与可恢复进度，不发布部分新设定。
撤销产生新恢复记录，范围包括原始正文变化及通过其建议采用的关联账本更新，执行前说明涉及章节和条目。
无后续冲突时一起恢复；存在后续独立编辑或引用时保留它们并处理冲突，不能只撤回正文而无提示地留下已入账的旧更新。
作者明确选择只撤销正文时，说明保留的账本更新和差异。摘要与账本更新建议状态按实际恢复结果更新，细则见[关联撤销](manuscript-editing-design.md)。

### 6.6 后续保留的作者模型与模型一致性审计

作者模型/长期记忆、章节审计、全文审计的设计分别见[作者模型](future/author-model-design.md)和[模型一致性审计](future/consistency-audit-design.md)。
0.3 不实现这些流程，不接入旧版自动推断偏好，不把审计嵌入修改完成或摘要任务；也不展示可用占位入口。
未来模型工具以柔和紫色按钮和“使用模型”文字区分，常规创作主动作保持蓝色，颜色不作为唯一提示。
RAG 是后续可选的原文定位能力，不替代账本与摘要，不作为本版前提。

## 7. 从首次创作到持续修改的完整例子

| 时刻 | 作者动作 | 主区反馈 | 账本与上下文 |
|---|---|---|---|
| 模型准备 | 连接个人 API 或下载本地模型，也可先记录想法或导入正文 | 展示实际接入与测试阶段，返回原位置 | 无模型也可记录想法、导入正文及修改已有正文 |
| 第一次输入 | “雪山旅馆谋杀案，凶手还没想好” | 保存想法，创建未命名作品，问真正影响下一步的问题 | 不把假设变为正式真相 |
| 整理 | 补充姐妹与侦探关系 | 展示带来源的故事核心与人物候选 | 待确认与正式条目分开 |
| 确认 | 采用选中设定 | 回读正式账本与版本 | 每轮自动带入正式账本 |
| 开始写作 | “写她们抵达旅馆，姐姐像在隐瞒什么” | 明确依据、视角、范围，生成完整试写候选 | 无需完整案件或节拍 |
| 采用 | 采用为第1章，继续写到第3章 | 显示正式正文，保留唯一协作入口 | 标记摘要待更新，并提供摘要与账本更新建议的启动操作 |
| 开启修改 | 点击“手工修改” | 显示本轮工作副本和“修改完成” | 固定正式基础，摘要仍标明正式来源 |
| 跨章编辑 | 改第1章部分对话、第2章部分描写 | 自动保存，同一轮可跨章继续，第3章不变 | 引用修改稿时显示独立快照 |
| 完成修改 | 点击“修改完成” | 统一记录一个版本，核对正文证据并显示后续启动操作 | 不自动运行模型任务，无模型时后续保持待处理 |
| 整体调整 | 在对话中要求更换凶手并调整相关伏笔 | 选择必要方案后连续执行，完成可查看或撤销 | 账本与正文统一发布，摘要标为待更新 |
| 继续 | 下次进入或换一段讨论 | 恢复章节、修改副本或任务进度 | 从真实账本与摘要继续，按需读原文 |

## 8. 现有能力的去向与切换条件

| 现有入口/能力 | 0.3 去向 | 退出旧入口的条件 |
|---|---|---|
| 项目概览 | 欢迎、作品选择、恢复提示；导出/备份进入作品设置 | 作品创建、找回和导出均可达 |
| 创作台 | 正文中心、手工修改支线、目录和版本历史 | 阅读、跨章修改、冲突与恢复闭环通过 |
| 故事账本 | 右侧摘要与主区详情/图谱 | 真实对象、确认与来源回读完整 |
| 变更影响/协作主编表单 | 对话中的理解、范围、必要选择和连续执行 | 对话能承接分析、授权、执行与失败恢复 |
| 修改审计/修订审阅入口 | 取消独立模块；正文历史与查看改动按需打开 | 替代流程可操作历史对象，不丢进行中任务 |
| 作者模型、模型一致性审计 | 后续保留设计，本版无新流程与可用按钮 | 既有资料保留；实施计划列明现状与未来范围，不伪装为本版交付 |
| 执行日志 | 明确的按需入口，对话片段关联同一事件流 | 历史、实时订阅与断线补齐一致 |

不先删除旧入口再等待替代能力。分批期间可以保留旧工作台供过渡；新流程验收完成后再同步切换。
过渡只服务实施，最终日常创作不需要进入旧业务页。历史记录保留不等于要求本版扩展作者模型或审计。

## 9. 实现顺序与退出条件

### 第一批：作品上下文与最小创作闭环

先落实正式稿/修改稿/候选/任务快照的身份，以及账本、摘要、引用的版本契约。
交付主工作区、模型接入、无模型记录/导入、设定候选确认、从账本生成与采用首章、正文摘要更新。
同时交付已有正文的单章手工修改工作副本、自动保存、暂存返回、修改完成形成版本，以及保存失败/基础冲突时的副本保护，确保单章修改不依赖第二批。
交付固定归属的结果记录、基础账本更新建议确认及原始操作关联；无后续冲突时可撤销该次正文及关联账本更新，遇到冲突保留现状并说明。
同步移除节拍起草前置条件，提供真实过程与执行日志，不仅改布局或入口名称。
退出条件：模糊构想到首章采用走通；无模型能保存想法、导入正文并修改已有正文；结果可回看，账本和摘要可追溯，模型背景与界面一致。

### 第二批：手工修改支线与账本图谱

在第一批单章路径上扩展跨章工作副本、一次修改完成的多章统一版本，以及对应摘要状态与账本更新建议；完善历史回看、后续编辑冲突选择和关联撤销。
交付人物关系图与线索关联图，目录/图形共用对象、版本及来源，计划与正文实现分开。
退出条件：三章中只改第1、2章后统一完成；切换、重启、无模型和冲突均不丢内容，未完成副本不污染正式上下文。

### 第三批：整体调整与长期继续

交付对话中的全局理解、范围选择、有限连续执行、覆盖状态、账本正文统一版本、失败恢复及保护后续编辑的撤销。
完善手法既有数据投影、时间线、角色认知/读者披露视角以及影响高亮；四类图谱均为0.3范围，不作为装饰性后补，且不为手法图新增结构化领域对象。
退出条件：换凶手、手法或背景无需逐章审批；内部未完成进度不污染稳定版本；图谱来源和两种时间顺序可解释。

### 每批共同门槛

旧入口按第8节的能力条件退出，不以批次号决定提前移除。前后端同步交付真实数据、状态、命令回读与恢复接口。
上文为分批实施边界，0.3 完整交付仍包含跨章修改；每批只开放已形成闭环的动作，不能以只定义修改稿身份代替可用的保存与完成流程。
界面延续老 iOS 风格、dark 原型模块化空间组织与较大字号，默认突出文章和协作入口。
测试使用默认启动、生产构建和真实应用契约；模拟结果与真模型证据分开。
作者模型、模型一致性审计、参考材料导入/材料库及 RAG 不进入任一批次的开发或验收；已有正文导入继续保留。

## 10. 0.3 验收清单

1. 首次表达想法前无需业务必填字段；个人 API 与本地模型引导真实可用，无模型可记录想法或导入正文。
2. 用户 Key 的配置、测试和实际任务使用同一连接，不回显密钥，不静默借用部署环境凭据。
3. 本地下载、加载、实际测试分别显示；取消、失败与重新进入恢复真实状态，不编造进度。
4. 已有正文时默认显示文章；发送消息、任务完成和收到候选不自动挤走正文。
5. 临时讨论、候选、差异、图谱与日志可返回正文，恢复阅读位置与未完成修改。
6. 讨论、候选、正式设定及正式正文可辨；假设不写账本，来源与实际版本可查。
7. 从人物、线索或正文直接起草，无节拍、隐藏规划对象或完整大纲前置依赖。
8. 试写先生成候选；采用回读实际预览文本，首版只读候选则明确限制。
9. 点击“手工修改”随时开启支线，可跨多章修改并暂存，导航和重启不自动结束本轮。
10. 点击“修改完成”统一记录一个版本，去重且不创建空版本；无模型也可完成。
11. 副本、正式版本、任务快照和生成候选分别标识；模型任务快照固定实际使用的连接与模型，混合编辑保留来源，冲突保护作者新内容。
12. 修改完成后只自动使受影响摘要失效并核对正文证据；摘要更新和账本更新建议整理各有明确启动方式与过程反馈，未启动时不运行模型任务。
13. 采用、导入和手改共用事实核对路径；未入账本的正文仍可引用，分歧在确有依赖时澄清。
    账本更新建议在原对话成组确认，来源已变不能原样采用；重复操作不重复入账，单独采用不擅自重写正文。
14. 每轮有账本和正文摘要背景；长篇按预算分层，版本、裁剪和未读范围可查看。
15. 摘要过期或失败不回滚正文，不静默用于新任务；其他任务只构建临时背景，不夹带正式摘要更新，重复、停止、失败及过期返回可控。
16. 精确改写与矛盾判断读取实际原文，摘要不能替代全文阅读与证据。
    写作任务固定目标叙述位置、角色知情和读者披露边界；润色前章不默认泄露后文，作者明确改变揭示安排时按范围处理。
17. 单独保存账本不擅自重写正文；对话明确授权的整体调整统一更新账本与相关正文。
18. 整体任务明确分析/修改范围和实际覆盖，自动修正有上限，表达建议不成为强制门槛。
19. 停止、失败与冲突保留稳定版本与可恢复进度，发布前处理人工副本，不要求逐章审批。
20. 撤销产生新记录并核对已采用的关联账本更新，默认一起恢复；保护后续独立编辑与引用，相关摘要及建议状态同步更新。
21. 人物、线索、手法、时间线四类图谱可查看与展开；节点、连线和高亮均有真实来源，手法图只投影当前正式数据并显示缺口，不推断或生成缺失结构。
22. 图谱目录与文字详情同样可操作；拖动只改变布局，事实变更经过同一版本与确认规则。
23. 真相、角色认知、读者披露及计划/实际分开；故事时间与叙述顺序不混用。
24. 模型公开提供的过程、应用执行记录和正式回复分别传递与保存；不支持时如实说明。
25. 执行日志记录任务、尝试、Agent、调用与异常，支持实时、历史、去重与断线补齐，不泄露密钥。
26. 作者模型、模型一致性审计和参考材料库标为后续保留，本版无伪入口、自动任务或隐藏依赖；RAG 不作为前提，正文导入仍可用。
27. 正文、对话和账本有舒适字号与空间，辅助区域可折叠；重要入口有文字，不靠低对比度或隐藏操作实现简洁。
28. 默认启动与生产构建可走通上述闭环，前后端契约一致；旧入口仅在替代能力验收后退出。
29. 导入无需先发消息也有持久结果记录；切换讨论、作品或刷新不改变已启动任务的结果归属，入口可找回且重试不重复创建。
30. 删除线索或获知事件后，即使无模型或尚未启动账本更新建议整理，相关正文证据也立即标为需核对；无关来源与作者设定保留，图谱和写作任务不沿用失效依据。
31. 导入默认新增章节，替换需明确目标及差异；预览基础变化、未完成副本、重复内容及网络重试均按规则处理，失败不发布半份正文。
32. 本次任务要求与本书约定分开；本书约定无需模型即可查看、修改和移除，冲突与已经启动任务所用快照明确。
33. 无模型且无作品时可连续保存多条想法，归属、草稿恢复与去重正确；连接后由作者选择继续，不自动重放消息或发送草稿。

## 11. 本方案的取舍

- 构思期对话承接想法，有正文后文章居中；协作输入持续可用，长内容按需展开。
- 人物、线索和关联组织创作，账本与正文摘要维持背景；精确任务读取原文，长期聊天不承担事实源职责。
- 手工修改是可随时往返、跨章完成的支线，正式版本与自动保存分开；模型后续处理不阻塞保存。
- 作者控制落实为来源、清楚范围、一次授权、可回看与撤销，避免后台模块转化为逐页审批。
- 本版先完成写作、修改与继续创作闭环，保留四类可视化与执行日志；作者模型和模型一致性审计留待后续，RAG 未排期。
- 原型提供设计语言参考，功能以当前范围为准；任意自动整书写作与多人协作不在本轮。

具体接口、数据兼容与开发阶段在实施方案中安排；产品决定不表示已经交付代码。
