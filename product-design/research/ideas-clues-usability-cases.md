# 先构思再写作：真实可用性用例

日期：2026-11-02。状态：**用例已进入 v1.0.9 验收计划，尚未执行**。结构与页面方向见[统一写作工作区设计](plan-first-writing-design.md)，正式门槛见 [v1.0.9 验收计划](../../dev-notes/v1.0.9/acceptance.md)。

## 1. 测试目标

本轮不再测试「先写正文，再补构思」能否成立，而是测试更明确的前提：**每一章必须先形成最小构思，才能开始正文；写作过程中，正文与构思通过章节信息索引持续互相校准。**

这里的最小构思不是完整大纲，也不是属性表单。作者只需要说明：

1. 这一章要让故事发生什么变化。
2. 这一章要让读者获得、误解、重新理解或确认什么信息。

每章至少要有一项「信息变化」，但不要求每章都出现新的物证。人物证词、危险升级、旧信息改变解释、伏笔推进和伏笔回收都属于信息变化。

用例重点观察四件事：

- 作者是否能用自然语言完成前期构思，不必维护线索、伏笔和回收三套对象。
- 没有构思时禁止进入空白正文，是否确实降低了无目标写作，而不是增加阻碍。
- 正文写入后，章节信息索引能否自动显示构思已经落实到哪些原句。
- 正文偏离构思时，系统是否只呈现差异并帮助处理，不静默改写作者意图。

## 2. 共用故事材料

所有用例使用悬疑小说《雪夜旅馆》。测试者只获得当前步骤所需信息，不一次展示完整数据结构。

### 2.1 作者最初的一句话

> 暴雪封山的旅馆里发生命案，侦探林砚从一双仍在滴水的手套开始怀疑管家，但手套后来会得到另一种解释。

### 2.2 后续逐渐确定的作者事实

- 21:50，雪停。
- 22:05，管家搬过尸体。
- 22:45，管家在室内洗过手套。
- 22:50，林砚抵达，只看到手套还在滴水。
- 管家声称自己从 21:30 起一直待在房间；这是证词，不是作者真相。
- 第五章取得雪停记录，第八章取得洗手套证词，第二十四章完成回收。

## 3. 前期用例

### UC-P01 从一句想法建立可继续生长的全书构思

**初始状态**

新作品中没有章节、正文或线索对象。页面只提供构思入口，不显示空白编辑器。

**作者操作**

输入共用材料中的一句话，然后说：

> 结局还没想好，先从抵达旅馆开始。

**应当发生**

- 系统建立一份很短的全书构思：暴雪旅馆命案、湿手套会先造成误解、第一章从抵达开始。
- 未确定的凶手、动机和结局保持未知，不为了生成完整大纲而补造答案。
- 页面提出第一章构思，而不是立即生成正文。
- 作者能从全书视图看到「湿手套」是一条会跨章发展的信息，但不需要先选择“线索”“伏笔”或“误导”。

**不能发生**

- 自动创建二十多个空章节。
- 追问时间、用途、关系和节点类型。
- 仅因作者提到湿手套，就把管家定为凶手。

**验证问题**

作者是否觉得自己已经获得了一个可写的起点，而不是又得到一份需要维护的系统大纲？

### UC-P02 第一章没有最小构思时，正文保持关闭

**初始状态**

作品已有一句全书构思，但第一章尚未确定。

**作者操作**

点击「第一章」并尝试开始写作。

**应当发生**

- 主区域显示「这一章要改变什么」，而不是空白稿纸。
- 系统根据全书构思提出一个可修改的简短方案：林砚抵达；看见湿手套；听到管家的不在场证词；暂时不揭示手套为何湿。
- 章节信息索引预先列出两项信息变化：引入湿手套的错误解释、引入管家的证词。
- 作者只需说「可以，开始写」或用一句话调整；提交后正文编辑器才打开。

**不能发生**

- 用标题、章节目标、人物、地点、冲突、线索类型等多个输入框代替构思。
- 作者还未确认就创建正文文件或生成正文内容。
- 因为结局未知而阻止第一章构思成立。

**验证问题**

这一次确认是否让作者更清楚本章任务，还是只增加了一次形式操作？若测试者普遍直接跳过阅读，构思摘要仍然太长或太抽象。

### UC-P03 只给一句章节意图，也能满足开始写作的条件

**初始状态**

作者不接受系统提出的第一章方案，希望自己简短决定。

**作者操作**

> 第一章只做三件事：封山、林砚入住、管家说谎。湿手套放到结尾再出现。

**应当发生**

- 系统把这句话保存为第一章构思，不继续追问内部属性。
- 信息索引显示：建立封闭环境；出现不在场证词；章末引入湿手套。
- 「开始写作」可用。湿手套的具体真相仍未知。
- 后续生成或对话读取这一顺序，不能在开头提前写湿手套。

**不能发生**

- 因为缺少人物情绪、精确时间或线索用途而判定构思不完整。
- 把「管家说谎」直接写成正文中人人已知的事实。

**验证问题**

作者能否在十秒内完成这一章的最小构思？

### UC-P04 开始写作后，构思自动绑定到具体原句

**初始状态**

第一章构思已经确认，正文编辑器解锁。

**作者操作**

手写以下内容并保存：

> 山路在傍晚彻底封死。林砚登记入住时，管家说自己九点半后一直待在房间。临上楼前，林砚看见柜台下有一双湿手套，水珠正沿着指尖落下。

**应当发生**

- 章节信息索引在当前页面实时显示三项构思已经落到正文，并列出各自准确原句。
- 点击信息索引中的「湿手套」能够定位到对应正文；点击正文标记能够回到同一条信息。
- 构思仍保存“本章为什么需要这些内容”，正文保存“实际怎样写出来”，二者不合并成一段无来源总结。
- 后续对话自动携带第一章构思和实际原句，不需要作者重新引用。

**不能发生**

- 作者手动选择每段属于哪个线索。
- 只按关键词命中，把所有“水”或“手套”都绑定到同一位置。
- 保存正文后还要刷新或打开另一页面才能看到完成情况。

**验证问题**

作者是否能只看当前页面就回答「本章原来想写什么、已经写到了哪里」？

### UC-P05 写作中临时出现原构思没有的细节

**初始状态**

第一章已经写到一半，构思中没有蓝蜡。

**作者操作**

在正文增加：

> 壁炉旁的火钳沾着一小片蓝蜡。

随后继续写作，不立即处理它。

**应当发生**

- 信息索引出现「正文新增：火钳上的蓝蜡」，带准确原句，但它不会自动成为正式构思。
- 这条新增信息不阻断继续打字，也不弹出分类窗口。
- 作者稍后说「保留蓝蜡，第十二章再决定是否回收」后，它才进入正式构思。
- 系统不强迫作者判断它是物证、伏笔还是误导；后续作用可以保持未定。

**不能发生**

- 每个具体名词都进入候选列表。
- 未经作者确认，把模型猜测的蓝蜡含义装入其他章节上下文。
- 因为出现计划外内容而自动删除或改写正文。

**验证问题**

信息索引能否接住即兴创作，而不把即兴创作变成即时整理工作？

### UC-P06 完成本章前，处理构思与正文的少量差异

**初始状态**

第一章正文已写完。构思中的「林砚暂时相信管家」没有在正文体现；正文新增的蓝蜡仍未决定是否保留。

**作者操作**

点击「完成本章」。

**应当发生**

- 页面只列出这两处需要决定的差异，不重复展示已经落实的内容。
- 作者可以说「删掉暂时相信这一安排；蓝蜡保留到第十二章再决定」。
- 构思、信息索引和后续上下文一起更新，正文不需要为了满足旧构思被强行补写。
- 差异处理完成后，系统才能把本章作为下一章的稳定前情。

**不能发生**

- 要求作者逐项填写完成状态。
- 将“构思未落实”一律判断为正文错误。
- 未解决差异仍向后续章节声称第一章已经完整落实旧构思。

**验证问题**

章末核对能否控制在少数真正需要作者判断的事项，而不是生成一份检查报告？

## 4. 连续创作用例

### UC-C01 从尚未处理的信息建立下一章构思

**初始状态**

第一章已完成，湿手套、不在场证词和蓝蜡仍待后续发展。

**作者操作**

创建第二章，输入：

> 第二章先调查停电，不回收湿手套；让林砚更相信管家的证词。

**应当发生**

- 第二章构思立即成立，因为它明确改变了读者与角色的理解，即使没有新物证。
- 信息索引显示：推进不在场证词；湿手套保持未回收；停电调查成为本章新信息。
- 系统不会为了“每章一条线索”硬塞入新的物件。
- 第一章的准确原句可作为上下文读取，但不会被复制成第二章对象。

**不能发生**

- 要求第二章必须新增一种线索类型。
- 把“更相信证词”写成作者确认管家没有离开房间。

### UC-C02 在写正文前改变本章的信息顺序

**初始状态**

第五章已有构思：先查气象记录，再询问女仆；尚未开始正文。

**作者操作**

> 第五章只取得雪停记录。女仆证词推迟到第八章。

**应当发生**

- 第五章和第八章构思同时更新，当前没有正文，因此不产生正文冲突。
- 湿手套这条跨章信息的路径立即变为：第一章引入、第五章改变时间判断、第八章改变湿水原因、第二十四章回收。
- 打开第五章正文时，生成上下文中不再包含女仆证词。

**不能发生**

- 作者分别进入构思页和线索页重复调整。
- 把推迟证词理解为删除证词。

## 5. 改稿用例

### UC-R01 正文变化使原有推理失效

**初始状态**

第一章和第二十四章已经写完。作者把第一章改为「雪刚停，林砚便抵达」，仍保留湿手套。

**作者操作**

直接修改第一章并保存。

**应当发生**

- 第一章信息索引立即更新当前原句。
- 第二十四章的回收立即显示证据不足：湿手套不能单独证明雪停后外出或搬尸。
- 作者真相「管家搬过尸体」保持不变；变化的是正文证据能够支持的结论。
- 系统可以提出需要独立外出或搬运证据，但不能自动补造证据。

**不能发生**

- 为维持“已完成”而自动改回第一章。
- 继续用已经失效的推理指导第二十四章。

### UC-R02 调整构思后，已有正文只显示影响，不静默改稿

**初始状态**

第五章正文已经包含女仆证词。

**作者操作**

先说：

> 女仆证词推迟到第八章。

随后说：

> 同步删掉第五章提前出现的证词，第八章先只保留构思。

**应当发生**

- 第一句提交后，第五章正文立刻显示一处与新构思不符，但原文保持不变。
- 第二句明确授权后，第五章正文、出处和两章构思一次提交。
- 第八章显示「已安排、尚未写入」，不能伪装成已有正文。
- 任一写入失败时，不留下正文与构思各自成功一半的状态。

### UC-R03 删除铺垫后，跨章回收与撤销一起更新

**初始状态**

第一章的湿手套已经在第二十四章回收。

**作者操作**

删除第一章「手套还在滴水」并保存，随后撤销。

**应当发生**

- 删除后，旧高亮消失，湿手套仍保留为作者构思，但显示当前无正文出处。
- 第二十四章立即显示缺少第一章铺垫。
- 系统不能通过相似词在别处猜一个新出处。
- 撤销后，正文、锚点、信息索引、跨章回收状态和后续上下文一起恢复。

## 6. 悬疑写作边界用例

### UC-B01 角色谎言不能覆盖作者真相

**作者操作**

第一章写入：

> “九点半以后我一直在房间，”管家说，“一步也没出去。”

随后请求一次截止第一章的读者视角分析。

**应当发生**

- 原句绑定为管家证词；作者真相仍是管家 22:05 搬过尸体。
- 因构思已安排早期误信，这一矛盾显示为已落实的有意信息差，不显示成普通错误。
- 读者视角只能读取截止第一章的正文和已披露内容，不能读取搬尸与洗手套真相。

## 7. 统一测试记录

| 指标 | 通过标准 |
|---|---|
| 前期负担 | 从一句作品想法到第一章可写，不出现属性表单，作者最多确认一次章节构思 |
| 开始条件 | 无章节构思时没有空白正文；有一句有效章节意图后可以开始写作 |
| 信息有效性 | 每章至少有一项读者、角色或调查状态的变化，不机械要求新增物证 |
| 自动绑定 | 已计划内容写入正文后，无需手动登记即可定位准确原句 |
| 即兴容纳 | 计划外内容可以继续写，候选不阻断创作，也不自动成为正式设定 |
| 页面切换 | 前期构思、正文写作、信息核对不需要进入独立构思页或线索页 |
| 实时更新 | 已提交变化无需刷新；当前章与受影响后续章节显示同一修订结果 |
| 写入边界 | 自动更新索引和影响，但不静默重写正文或改变作者真相 |
| 上下文正确 | 下一轮读取最新构思与当前正文，不读取已撤销内容，不泄露隐藏事实 |
| 恢复能力 | 撤销同时恢复正文、绑定、索引和跨章影响，或明确说明依赖冲突 |

## 8. 第一轮测试顺序

第一轮先连续完成 UC-P01 至 UC-P06。它们构成从空作品到第一章完成的完整过程，能够直接判断「必须先构思」是在帮助作者聚焦，还是把原来的属性编辑换成新的确认流程。

只有前期流程成立后，再测试 UC-C01、UC-C02 和改稿用例。若作者在 UC-P02、UC-P03 中难以用一句话形成章节意图，应先改进构思辅助，不应放宽为无构思直接写正文。
