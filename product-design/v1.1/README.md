# v1.1 产品方案：对话创作与结构装配

日期：2026-11-03（合并定稿）。状态：**方案已与作者确认，待实施**。基线 v1.0.9（运行版本 1.0.9）；v1.0.9 的 P7 验收并入本版，版本直接提升为 1.1.0。

> 2026-11-03 合并裁决：原「全对话创作」与「结构文档与装配」两版合并。**取消暂存确认闭环**：
> 结构/模块直接事务落盘、事后可回退；正文候选采用保留确认门。稿纸退位与入口收敛（UI 收敛）
> 顺延后续版本，本版保留 v1.0.9 前端现状。

## 1. 问题与目标

v1.0.9 拆掉章节门槛后，作者仍面对两个思维压力点：

1. **全书构思仍是一段要作者亲自组织的文字**，且模型逐章推进缺乏一份自己维护的全书工作记忆，跨章一致性靠上下文硬扛。
2. **结构决定仍由作者做**：建章、起标题、看方向建议，每一步都要求作者理解内部对象。

作者裁决（2026-11-03）：

- 对话是内容变更的主入口：设定聊出来、正文由模型起草、结构由模型分解。
- 采用 coding agent 的 `AGENTS.md` 思路：**文件是模型自己的工作记忆，表征由模型自选**。写作三线的书它自己画线位表，写单视角的书只用三行——格式跟着书走，不为「模型执不执行某个格式」设计 schema。
- 作品根目录使用真实 `STRUCTURE.md`，自由格式 Markdown，模型写、模型改，作者只读。
- 结构/模块**直接落盘、事后可回退**（Git 逐次入档）；正文候选采用保留确认门。不做暂存确认闭环——对作者无法亲手编辑的文件，确认门是假控制。
- 不做任何确定性字段校验器；不变量写成文件开头的「铁律」，由模型写后自查。
- 无可用模型时作品链路如实说明，不提供手写兜底。
- 分层判据一条：**全局文档讲「怎么写」，模块讲「是什么」**。一切随写作增长的数据（伏笔账、人物、旧案事实）下沉为挂载模块，复用 v0.8 机制，零改动。

实验与试验依据（2026-11-03）：滑杆、预设面板、字段级机检被否决；存活的遗产为必发生清单护栏、行为锚点写法、「读者主判断站错边」聚合规则（铁律化）。最小试验确立**事实层与模型层分离**：正文台账由事务层维护，模型只读不可写；被动注入事实模型不对账（0/3），对账必须确定性执行。

## 2. 本版固定的产品规则

1. **对话是内容变更的主入口。** 设定、章节、正文相关的所有内容变更都可由对话发起；模型产出，作者说话或确认。
2. **结构直接落盘、可回退。** 模型对 `STRUCTURE.md` 与模块的更新随事务直接入档，每次入档有 Git 记录；计划性变化必须在对话中单独说明，作者可一句话改回或整体撤销。
3. **正文候选采用是唯一的正文入稿通道。** 起草产出候选与三层自查，作者采用后入稿；确认前不产生正式正文变更。
4. **正文台账是事实源。** 每章实际入档记录由事务层自动维护，模型只读不可写；与结构文件中任何「已写」标记冲突时以台账为准。
5. **结构由模型分解。** 建章、章节标题、方向建议由模型提出，作者确认或用一句话调整。
6. **无可用模型时作品链路不可用。** 界面如实说明需要先完成模型设置，不提供隐藏绕过路径。
7. **范围边界。** 灵感速记与模块库是独立素材工具，保留现状手写输入；稿纸编辑面与入口收敛顺延后续版本，本版维持 v1.0.9 前端现状。
8. **索引机制维持 v1.0.9。** 信息线从正文生长、候选确认入账、空章温和提示，全部不动。

## 3. 作者旅程

```mermaid
flowchart LR
    A[空作品起步对话<br>引导提问或自由发挥] --> B[设定卡确认过门槛]
    B --> C[模型起草第一版结构<br>并创建首批模块<br>直接入档可回退]
    C --> D[逐章写作<br>装配注入结构与模块]
    D --> E[写后自查进对话]
    E --> F[采用入档<br>正文+结构+模块原子提交]
    F --> G[侧栏只读页<br>随时看结构现状]
    G -->|想调整| D
```

作者可见的只有四样：对话、正文阅读面、结构只读页、入档回执。没有新表单、没有画布、没有仪表盘。

## 4. 起步：设定是聊出来的

新作品直接进入对话。两种起步模式：

- **引导提问**：模型一次只问一个问题，每个问题可跳过，随时可以说「就这样开始」。问题数量有上限，不追问时间线、人物关系这类内部属性；未知保持未知，不为生成完整大纲而补造答案。
- **自由发挥**：作者给一句话（甚至只给题材和氛围），模型直接产出一版设定。

两种模式都汇聚到**设定卡**：模型把对话内容整理成一段可继续发展的作品意图候选，在对话中呈现。作者确认开写或继续聊；确认后写入作品意图，门槛通过，并**紧接着起草第一版结构（铁律、路线、骨架、模块索引）与首批模块（伏笔账、人物等，按书自选），直接入档**。作者在只读页核阅，不满意一句话改——反正 v0 本来就是要被改的。

门槛本身不变：作品意图非空即可写任何章节，只换意图的来源。

## 5. 写作与修改：直接落盘，两级控制

- **正文起草**：空正文在对话中由模型起草（`prose_draft` 候选），同回合产出三层自查；作者采用后入稿。想改正文，回对话说一句。
- **修改**：作者说一句改动 → 模型执行并入档（三元原子提交：正文 + 结构 + 模块）→ 对话回显差异三要素（改了什么、影响哪里、基于哪个修订）。不满意就整体撤销，或说「不同意，改回来」让模型改回。
- **感知区分**：记账类更新（标记某伏笔已埋、某章已写）静默，仅入档回执可见；计划性变化（改回收点位、新增叙事线、改铁律）单独一行说明。不被蒙在鼓里，也不被要求逐次确认。
- **对话历史不是正式设定**：正式数据仍由事务写入，不从聊天记录猜最终决定。
- **索引时点维持**：候选采用前页边索引不更新，采用落盘后才进入索引分析。

## 6. 结构文档与装配

- `STRUCTURE.md` 开头是**铁律段**（固定标记，常驻注入），其后是路线、章节骨架、模块索引；格式由模型自选。
- 每次起草、修改请求的装配顺序（冻结契约）：铁律 → 结构全文 → `STYLE.md` 空占位 → 当次涉及的挂载模块（按需，未涉及不注入）→ 正文台账（只读事实）→ 必发生清单（模型起草同回合自列，回执展示给作者一眼可否决）。
- **确定性对账**：目标章号与台账比对，之前有缺章即拦截改派；这是第一道防线，纯函数。起草前强制对账流程是第二道保险。
- 结构文件增长超出冻结字数预算时，入档前由模型先压缩（随同一事务入档）。
- 作者对结构文件只读（侧栏只读页）；外部编辑器直接改文件的场景不设对照界面，按磁盘现状如实注入，模型下次入档时自行整理。

## 7. 写后自查

起草任务同回合产出三层自查，进入对话：

0. **强制对账（先行）**：核对目标章与台账，发现更早章节缺正文不得写目标章、改为补缺。
1. **必发生核对**：清单逐条对正文定位，缺失即报。
2. **铁律自查**：逐条检查本章是否违反。
3. **读者认知提示**：当前误读是否立住、有无提前起疑，给可执行的修改建议。

自查是概率性的，界面如实标注「自查」，不承诺无漏报。作者采纳建议则模型修改随事务直接入档，复检仅对改动项。

## 8. 范围与取舍

### 8.1 纳入

- 对话式起步与设定卡确认；起步即生成第一版结构与首批模块。
- `STRUCTURE.md` 生命周期、注入装配、正文台账与确定性对账、必发生清单护栏。
- 三元原子直接落盘与整体撤销；感知区分。
- 建章、标题、方向建议的结构提议。
- 写后自查三层与结构只读页。
- 无模型前置说明。

### 8.2 不纳入（砍掉或顺延）

- **暂存确认闭环**：废弃。结构/模块直接落盘 + Git 回退替代（裁决见上）。
- **稿纸退位、入口收敛、散布按钮撤除**：UI 收敛，顺延后续版本；本版保留 v1.0.9 前端现状。
- **手动修订结构 / 修订学习**：作者对结构文件只读；修订学习前提（人工编辑差异）作废，方案归档。
- `STYLE.md` 规则组织与冲突处理：后续版本，本版仅留装配空位。
- 模块机制改动：类型、字段、挂载规则一律沿用 v0.8。
- 确定性校验器、结构可视化（画布、时间轴、起伏曲线、预设面板、滑杆）：全部不要。
- 旧数据迁移；自动确认、自动连续生成多章。

### 8.3 已知取舍

1. **结构直接落盘意味着模型可能写坏结构而作者未细看**：换来的是零确认摩擦与真正的 agent 工作流。Git 历史、台账、对账与感知区分让风险可恢复；不可恢复的静默变更才是真问题，而那已被排除。
2. **产品完全依赖模型**：无模型即不可用。作者已明确接受。
3. **对话轮次成本上升**：所有验收用例都需要在线模型；按既有纪律执行单例复测。
4. **确定性校验降级为概率性自查**：换自由格式；护栏用对抗用例回归兜底。

## 9. 判断标准

从空作品连续走完：引导提问（或自由发挥）→ 设定卡确认 → 结构与首批模块入档 → 只读页核阅 → 对话起草第一章（带三层自查）→ 采用入稿 → 说一句修改 → 差异回显 → 撤销恢复。

成功的直接表现：全程作者只说话和做判断（确认候选、看回执），不需要理解内部概念；结构与正文始终一致（台账可证）；对抗用例（风格指令、伪造「已写」标记）下护栏实测有效。若出现新表单或结构脱节，本版目标未达到。
