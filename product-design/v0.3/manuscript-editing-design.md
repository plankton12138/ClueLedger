# Hastings 0.3：正文修改与版本流程

> 定位：2026-10-17 确认的目标设计，不维护实施进度；当前行为与差距见[修改与撤销](../../dev-notes/v0.3/modules/editing-and-undo.md)。
> 关联：[主方案](agent-first-workbench-product-design.md)、[模型上下文与正文摘要](context-and-summary-design.md)。
> 作者模型与独立模型一致性审计为后续保留项，不属于本版流程。

## 1. 修改是随时触发的支线

主线是围绕人物、线索和正文持续创作。作者在任何已有正文的阶段，都可以点击“手工修改”开启一次修改，
无需先完成整本书，也无需进入独立审阅页面。修改可以跨章，不被当前阅读的章节限制。

例如已完成三章，作者点击“手工修改”，改第一章的部分对话，再改第二章的某段描写，第三章保持原样；
点击“修改完成”后，这次人工修改统一记录为一个版本，并标记摘要与账本更新建议的待处理状态；需要模型的后续处理由作者另行启动。
这里的分支是可往返的创作支线，内部用工作副本隔离未完成修改；作者无需命名分支或操作合并命令。

| 作者动作 | 系统行为 | 可见状态 |
|---|---|---|
| 点击“手工修改” | 固定正式基础版本，创建或恢复本作品的人工修改工作副本 | “手工修改中”，显示“修改完成”“暂存返回” |
| 修改任意章节 | 自动保存该副本的实际文本，记录涉及章节 | “修改稿已保存”或真实保存失败提示 |
| 切章、切视图或离开作品 | 保留副本、选区与位置，不自动结束修改 | 返回时可继续本轮修改 |
| 点击“修改完成” | 检查基础、冲突及实际差异，原子记录本轮全部改动 | “已记录本次修改：第1章、第2章” |
| 完成后的处理 | 使受影响摘要失效、核对正文证据，并提供摘要更新与账本更新建议的启动操作 | 分别显示“待更新/尚未整理”，不影响已保存正文 |

## 2. 正式稿、修改稿与任务快照

| 内容 | 身份与用途 |
|---|---|
| 正式稿 | 已采用/导入/完成修改的正文，具有正式作品版本，作为日常创作依据 |
| 人工修改稿 | 绑定基础版本与独立修改标识的工作副本；自动保存不推进正式版本 |
| 任务快照 | 一次模型任务实际读取的不可变内容，绑定正式版本或修改稿的保存序号、内容标识，以及启动时所用的用户连接标识和模型标识 |
| 生成候选 | 尚未采用的模型输出，有独立基础、来源和状态；不覆盖正式稿或人工修改稿 |

默认对话使用正式账本与正式正文摘要。手工修改期间，引用条明确标出“第1章·修改稿”，
作者可以将已保存的选中段落作为本轮对话的额外引用；任务冻结该修改稿快照，并同时说明常驻摘要仍对应正式稿。
不能用正式稿内容冒充正在屏幕上显示的修改稿，也不能把修改稿静默注入其他会话的正式上下文。

本轮只允许一个活动的人工修改副本，重复点击恢复同一轮；历史版本可回看，但不默认暴露多个可切换分支管理界面。
修改中请求 Agent 改写时，先返回候选与差异，不自动写入人工副本；作者采用后单独记录生成来源。
后续从副本汇总版本时保留各段来源，不能把生成文字算成人工编辑证据。

## 3. 修改完成与后续步骤

1. 确认所有涉及章节的修改稿已经保存；失败时保留副本并提供重试。
2. 核对基础版本。正式稿已发生变化时，先比较差异；不重叠的改动可在展示合并摘要后继续，重叠部分由作者选择。
3. 准备本轮正式版本，包含基础、前后差异、章节范围、时间与来源，但尚不单独发布。
4. 计算受影响章节的摘要失效状态，并核对依赖本次正文的账本证据关联；来源已变或无法确认时标为“需核对”。正式版本和两类状态作为一次提交，任一项写入失败时都不发布新版本，保留工作副本并使用同一操作标识重试。未修改章节的正文和摘要不重复处理。
5. 将摘要显示为“待更新”、账本更新建议显示为“尚未整理”，分别提供“更新摘要·使用模型”和“整理账本更新建议·使用模型”；不自动启动任一任务。
6. 回到刚完成的正文，提供上述模型操作，以及“查看改动”“撤销这次修改”“继续创作”。

版本记录、摘要失效及正文证据状态核对不依赖模型。离线或无模型时仍能完成步骤1—4中的保存和状态记录；未启动的模型处理保持待处理，不将它们伪装为已完成。
这些状态和启动操作可在正文下方原位查看，作者无需先处理它们即可继续阅读或修改已有正文。
其他模型任务遇到过期摘要时，按[上下文规则](context-and-summary-design.md)读取实际正文构建本次临时背景，不能顺便更新正式摘要，也不能继续使用过期内容而不说明。

“修改完成”无需填写说明；修改摘要直接由实际差异产生，如“修改第1、2章的5处文字”。这里的修改摘要只是本次保存结果说明，不是需要模型生成的正文摘要。
没有差异不创建空版本；重复点击和网络重试返回同一结果。完成成功前工作副本持续保留，成功后保留可追溯的修改记录。
作者可明确放弃本轮；放弃操作只处理该副本，不删除正式历史。

## 4. 对话中的账本更新建议

“账本更新建议”指从已保存正文中整理出来、等待作者决定是否补充或同步到账本的信息，文档和界面统一使用此名称。
例如正文新增“姐姐九点到达旅馆”，可建议补充到达时间；若只是证词，则应建议记录“某人声称九点到达”，而非直接认定真实时间。
它用于衔接正文与账本，直接对照本次正文变化和相关账本即可，不依赖 RAG；与正文候选、写作风格学习及独立审计分别处理。

正文采用、导入和人工修改完成共用同一条核对路径。正文成功保存后即成为已写内容，后续任务可以引用，
但正文中的陈述不自动变为客观真相：对话、猜测、证词和不可靠叙述需要保留原有身份。

保存时对既有正文证据的核对先于模型建议，规则见[正文证据的有效状态](context-and-summary-design.md#31-正文证据的有效状态)。
即使作者尚未启动账本更新建议整理，也需标明受影响的“已出现、已披露、已知”记录是否仍有当前正文依据；作者设定与计划不因此被自动撤销。

模型只整理本次值得入账或更新的变化，分为新增记录、已有记录调整、人物认知或证词，以及证据不足的待确认项。
每项保留来源正文版本、位置、原文和对应账本条目的基础版本；作者可成组采用、部分采用、调整或暂不处理。
部分采用时，引用的人物或线索必须已存在，或与必要依赖一起确认；不能产生断开的正式关系。
只集中询问影响后续创作的选择，不要求逐句确认。

### 4.1 在原对话中成组处理

作者从本次导入、采用或修改完成对应的持久结果记录启动整理；返回的建议继续写入同一记录，先给简短说明和数量，详细内容按需展开；该记录在对话区呈现，归属规则见下节。
例如：“这次正文将姐姐到达时间由九点改为八点，账本仍为九点。建议同步到达时间。”
展开时列出相关账本内容、正文依据和建议调整；提供“更新选中条目”“调整建议”“暂不更新”，允许一次处理一组相关建议。
证词保留“某人声称”等认知类型，不能因采用建议而变成客观真相。

这不是独立功能页或必须走完的审阅流程，也不要求逐句审批。没有值得更新的信息时不创建空卡片。
正文已经保存成功，作者可以继续创作；未启动时显示“尚未整理”，启动后的等待、生成、停止、失败和结果在同一记录原位更新。
右侧账本只提供待处理数量和定位到该对话的入口，共用同一组建议身份与处理状态，不另建一份列表事实源。
作者已明确授权同一账本范围随正文一起修改时，沿用该授权执行并回报结果，不再重复要求采用；超范围或关键歧义仍需作者选择。
单独采用建议只更新选中的账本记录并回读版本，不因此重写正文或宣称整部作品已经同步。

### 4.2 没有发起对话时，结果放在哪里

每次导入、采用或修改完成都保留唯一的操作标识和结果记录，关联作品、来源版本及发起位置。
从对话发起时绑定该会话；纯界面操作绑定该作品当前会话，没有当前会话则按需创建并复用作品的“创作记录”默认讨论。
导入或手工修改不要求作者先发送消息或手动创建讨论；首次产生保存结果时即可按上述规则记录。

正文版本记录与结果记录的关联一并持久保存，同时记录正文摘要和账本更新建议的待处理状态；保存本身不创建模型任务，刷新与网络重试不重复创建记录。
结果记录先显示实际导入或保存结论；作者明确启动后，相应任务的生成、停止、失败和建议处理状态持续更新同一记录；没有建议时不额外创建建议卡片。
任务启动后归属固定，切换章节、讨论、作品或重启均不将结果写入后来打开的会话，也不自动跳转作者的当前视图。
正文旁的最近修改结果、历史条目和右侧待处理入口均可定位到该记录；不要求先找到一条作者消息才能查看结果。

### 4.3 来源变化与重复处理

建议生成返回时、采用前都核对来源正文与对应账本。正文证据或拟修改条目已变化、删除或撤回时，
旧建议标为“需重新核对”，保留历史依据但不能原样作为当前建议采用。只发生无关变化时核对依赖后可继续，不因作品任意更新全部作废。
重新核对后在原记录显示新版建议，并保留与旧版的关系；无法确认时留待作者判断，不静默恢复旧事实。
同一来源变化和目标建议去重，重复点击、刷新及重试不重复更新账本；一组选择一次保存，未选部分继续保持原状态。
部分采用后，涉及已变更条目的剩余建议按新基础核对，已采用的条目不重复提交。
建议及每次采用产生的账本变化均关联原始正文操作，记录实际更新对象和前后版本，用于查看和关联撤销。

未处理建议有轻量入口；正文照常可引用，建议保持未确认，任务上下文说明存在分歧。
下一次任务确实依赖某项冲突时才请作者选择，不能静默选账本或正文的一边，也不把“未入账本”理解为“从未发生”。
账本单独保存不自动重写正文；需要联动时在对话中说明范围后执行。

## 5. 对话中的整体故事调整

作者仍可说“把凶手改成姐姐，保留妹妹视角和旅馆背景，把前面的伏笔一起调整”。
系统读取账本、摘要和必要原文，说明将改变、保留及联动的范围，补问真正影响执行的选择。
已明确同意相同范围时直接执行；“先看看方案”仅授权生成方案。

1. 固定基础、目标、只读分析范围和允许修改范围，保留稳定版本。
2. 依据摘要定位关联，再读取相关原文；需要全局覆盖时逐章记录“已检查、无需修改、待处理、未覆盖”，未读取不能记为无需修改。
3. 在内部工作版本连续修改账本与受影响正文，不逐章要求作者批准。
4. 检查版本、写入范围、引用完整性及本次要求是否落实；相关问题分级处理，见下表。
5. 确认基础仍有效后统一发布账本与正文版本，将受影响的派生摘要标为“待更新”并提供明确启动操作。摘要未更新时显示真实状态，不能作为发布成功的替代证据。

| 检查结果 | 发布规则 |
|---|---|
| 版本冲突、越出授权、引用失效或内容缺失 | 必须解决，不能发布 |
| 本次修改中已发现且有依据的故事冲突、关键选择未定 | 在授权内修正，或回到对话由作者决定；未解决不标为整体完成 |
| 表达、悬念和阅读感受建议 | 可保留建议，不作为发布门槛 |
| 未完成要求中的覆盖范围 | 保留内部进度，说明未覆盖部分，提供继续或调整范围 |

本版的内部检查用于验证这次修改与写入边界，不新建章节/全文审计任务，不宣称已经执行模型一致性审计或穷尽全部逻辑问题。
单次任务设置可见的调用/轮次上限；自动修正最多两轮，到达上限保留进度并由作者选择继续，不能无限重写或静默扩大调用。
前端显示实际已用次数，无法估算服务价格时不编造费用。

有未完成的人工修改副本时，整体修改可先分析或生成内部候选；发布前需要完成该轮人工修改并重新核对基础，
或暂缓整体任务。不得自动放弃副本。作者在执行期间新开启手工修改时，同样执行这一规则。
正式版本仅发生不相关变化时可重新核对后继续；发生重叠时由作者处理冲突。

## 6. 停止、恢复与撤销

停止或失败保留原稳定版本及内部已完成工作，不能让正式账本与正文处于半套新设定。
刷新和重进恢复本轮标识、进度及任务状态，继续时校验基础与授权；不可复用的工作说明原因，不自动重复调用。
完成后显示实际范围、未决事项和“查看改动”“撤销这次修改”“继续调整”。

### 6.1 撤销正文及其关联账本更新

撤销产生新的恢复记录，按原始正文操作汇总本轮正文变化，以及后来通过其建议采用的账本变化。
正文版本与每次建议采用仍分别保留真实时间和来源；关联仅用于说明因果与撤销范围，不将历史合并或改写。

例如原来正文和账本均为九点，手工修改正文为八点，再采用建议将账本更新为八点；
撤销这次修改时应同时考虑正文与该项关联账本更新，不能只把旧建议标为撤回而保留八点账本。

- 撤销入口或展开后的范围摘要列出涉及章节、已采用的关联账本条目，以及执行后将恢复的内容；没有关联更新时按普通正文撤销处理。
- 没有后续独立修改或引用冲突时，默认将原始正文变化与其关联账本更新一起恢复，一次形成新的正式作品版本。
- 存在后续独立编辑、其他任务更新或新增引用时，只撤回目标变化，保留后续内容；重叠或依赖冲突在原对话提供具体选择，解决前不发布半套恢复结果。
- 作者也可明确选择仅撤销正文、保留某些账本更新；范围摘要须说明将保留哪些记录及尚存差异，不宣称故事已同步。
- 撤销成功后，同一结果记录回报实际恢复范围；受影响摘要标为“待更新”并提供明确启动操作，未采用的旧建议标为来源已撤回，已采用项保留记录并关联新的恢复版本。

恢复后的正文证据关联也按当前来源重新核对；保留某项账本更新不等于其旧正文依据继续有效，不能仅靠撤销操作清除“需核对”状态。

尚在运行的旧任务返回时仍校验来源，不恢复已撤销的建议，也不重复写回旧事实。重复点击撤销返回同一恢复结果。

## 7. 本版验收

- 已有三章，点击“手工修改”，跨第1、2章修改并完成：只产生一个正式版本，第3章不变。
- 自动保存、切章、离开作品或重启均不隐式结束修改；副本可找回，失败不丢字。
- 无模型仍能完成已有正文的修改；摘要更新/账本更新建议整理单独显示待处理，未明确启动时不产生模型任务，也不触发作者模型与模型一致性审计。
- 正式版本、摘要失效状态和正文证据状态原子提交；任一状态写入失败时不发布版本，重试不产生重复版本。
- 修改稿引用可追到实际快照；正式摘要与修改稿的差异明确，生成内容与人工来源分开。
- 正文采用、导入和手改后均提供明确的账本更新建议整理操作；作者启动后产生有来源的建议，未确认和冲突不会被当作既定真相。
- 建议在原对话成组处理，暂不更新不阻止继续创作；右侧入口与对话共享同一处理状态。
- 建议返回后再次改正文或账本，原建议标为需重新核对；重新生成、部分采用及重复点击不把旧事实写回或重复入账。
- 整体调整有明确范围、覆盖记录、有限自动修正和统一发布；中断不污染正式版本。
- 发布遇到未完成副本或新版本时保护作者内容；完成后再编辑再撤销，仍保留新写部分。
- 正文从九点改八点并采用账本更新后撤销，默认同步恢复两者；账本随后另改为八点半时，保留该独立修改并明确处理冲突。
