# 作家的桌面：视觉与交互原则

> 产品版本：0.3，目标设计。本文描述要求，不维护实施进度；当前行为与差距见[模块说明](../../dev-notes/v0.3/modules/README.md)。
> 日期：2026-10-17。
> 设计基准：一张稿纸，几本书，一支笔，几个印章，一枚镇纸。
> 关联：[主工作区方案](agent-first-workbench-product-design.md)、[正文修改](manuscript-editing-design.md)、[模型上下文](context-and-summary-design.md)。
> 2026-10-17 范围决定：作者模型与模型一致性审计留待后续，本文不将其入口作为0.3交付。
> 参考材料导入与材料库同样留待后续；本版保留已有正文导入，不展示材料附件入口。

## 1. 第一眼看到正在写的文章

界面围绕一张安静的稿纸展开。正文拥有主要面积和最清晰的文字层级，其他内容在手边，需要时拿出来。
尚无正文时，这张稿纸承接想法与对话，也可导入已有正文；有正文后，默认阅读，点击“手工修改”进入编辑支线。Agent 对话入口始终容易找到。

桌面意象用于决定信息和操作的轻重，不要求把界面画成一张写实木桌。
不添加影响阅读的木纹、纸张噪点、钢笔插画、翻书效果或盖章动画；温度主要来自排版、留白与克制的色彩。

## 2. 五件物品对应五种职责

| 桌面意象 | 产品中的职责 | 呈现方式 |
|---|---|---|
| 稿纸 | 当前章节与正在表达的想法 | 连续的正文阅读区，舒适行宽和页边距，低干扰编辑 |
| 几本书 | 章节目录、讨论与故事账本 | 两侧轻量目录与摘要；点开阅读，长内容按需展开 |
| 一支笔 | Agent 与作者的持续协作 | 正文下方一个清晰的对话入口，最近回复和必要选择就近出现 |
| 几个印章 | 保存、确认、检查等少量明确操作或结果 | 小型文字按钮与状态标记；只在相关时出现，不铺满彩色标签 |
| 镇纸 | 稳定的当前工作位置 | 保持章节、光标、选区和滚动位置；已启动任务不挤走正文或跳转视图 |

界面使用“账本”“讨论”“手工修改”等明确名称，不要求用户猜物件图标代表什么。

## 3. 默认桌面只展开当前需要的内容

正文上方保留章节名、简短状态与“手工修改”“历史”入口。开启修改后显示“手工修改中”“修改完成”“暂存返回”，
并列出本轮涉及章节，避免将完成按钮误读为只保存当前章。自动保存不结束本轮；0.3 不展示模型一致性审计占位按钮。
作品选择、模型和设置集中在紧凑顶栏；模型就绪后不持续展示配置表单或醒目的连接状态。
首次未配置模型时仍优先显示清楚的接入引导，完成后收起。
“先记录想法”使用同一输入框和“保存想法”动作，已保存消息标明“尚未请求 Agent”；连接模型后不自动发送。
作品设置中的“本书约定”支持直接查看、修改和移除，无需模型或新增导航；当前任务的临时要求不自动记入。

左侧默认使用紧凑目录，可展开章节或讨论。右侧账本保留轻量摘要，优先显示本章相关人物与线索，
完整目录、确认记录和图谱按需查看；待确认事项有内容才显示数量，空列表不占一张卡片。
不同时展开所有人物详情、任务历史、恢复表单与结果详情；作者记忆留待后续。

正文下方保留一个对话输入框和最近一次相关回复。长讨论与思考过程按需展开，使用独立滚动范围，
不能让一段流式输出不断推移正文。收起详情后仍可看见正在执行的动作或结果摘要。
作者主动回看历史对话时可以展开全文，返回正文恢复原位置。

保留“执行日志”轻量文字入口，用于实时查看和回看 Agent 事件流；打开后使用独立滚动区域，不推移正文。
日志默认收起时仍持续记录，对话中的执行记录可定位到同一日志；具体记录与恢复规则见[主工作区方案](agent-first-workbench-product-design.md#执行日志保留-agent-事件流)。

“专注写作”可收起两侧目录，保留稿纸与对话入口。小屏幕优先保留正文，目录和账本改为抽屉。

### 模块化布局与空间利用

2026-10-17 已确认：参考 [dark 原型](../../prototypes/dark/README.md)的模块化组织、大字号和充分利用页面的方式。
模块有清楚的职责与边界，文字容易阅读，区域之间有呼吸空间，整体仍保持充实、有序的工作台观感。

- **充分利用视口**：工作区随窗口宽高展开，主要模块使用可用空间；减少外围大块空白和内容只缩在页面中央一小块的情况。
  正文仍保持舒适行宽，宽屏增加的空间用于模块分配与内部留白，不将正文无限拉长。
- **按职责分区**：正文、协作、相关账本和按需打开的日志各有明确区域，以模块标题、对齐、细边界和间距区分。
  同类信息在模块内成组呈现，不将所有说明、操作和结果堆进一块，也不把每条信息拆成独立卡片。
- **字号优先可读**：正文、对话、账本条目和主要操作采用较大且清楚的字号，标题形成明显层级；
  不靠缩小文字塞入更多列。内容过多时通过模块内滚动、摘要和展开处理。
- **充实而不拥挤**：模块之间保留稳定间距，模块内部有足够边距、行距和表格行高；
  主要内容获得足够宽高，次要内容按需出现。无关统计、空卡片和装饰不用于填满页面。
- **按内容分配空间**：正文为主时优先保障阅读与编辑，打开完整账本、图谱或执行日志时让该内容使用主区；
  侧栏宽度随内容与屏幕调整，空间不足时折叠辅助区域，不能把多个模块压成难以阅读的窄栏。

借鉴的是模块化排布、文字尺度与空间节奏，具体模块和功能仍由当前产品方案决定。

## 4. 视觉语言

2026-10-17 已确认：**前端继续沿用老 iOS 风格**，作为 0.3 的视觉基调。“作家的桌面”用于组织工作区与信息层级，
在这一风格下落实稿纸中心、轻量侧栏和按需展开。控件延续老 iOS 的圆角、轻微渐变、细腻高光与阴影层次，
保留克制的拟物质感；装饰仍需服从正文阅读与操作清晰度，不增加前述木纹、纸张噪点或装饰动画。

[原型目录](../../prototypes/README.md)仅提供设计语言参考，不代表成品功能、最终布局或交付状态。
老 iOS 原型用于参考控件质感和视觉层次；其中的七页导航、旧审批流程、示例数据与功能按钮不作为实现要求。
dark 原型用于参考模块化布局、大字号与页面空间利用；这些布局原则与老 iOS 控件风格共同用于成品设计。
成品布局遵循本文，功能与交互遵循当前产品方案；原型未展示的执行日志等已确认能力仍需保留。

- **颜色**：采用柔和纸白或浅暖灰底色、清晰的深墨色正文；常规创作主动作沿用低饱和蓝色，错误与提醒使用语义颜色。
  后续独立模型工具使用柔和紫色描边与浅底，附“使用模型”文字，颜色不作为唯一标识；本版不提前展示未实现工具。
- **字体**：正文优先考虑中文长文阅读，字形清楚、行距舒适；对话、账本和工具文字同样保持较大、易读的字号，使用少量清晰层级。
- **版面**：模块充分使用页面宽高，以适量留白、对齐和细分隔线组织信息；正文保持适合阅读的行宽，模块间距与内部边距避免内容拥挤。
- **层次**：稿纸与功能模块可有轻边界或阴影，让分区清楚可辨；同一模块内用排版和分隔组织内容，避免每段说明都套卡片和厚边框。
- **按钮**：当前步骤突出一个主要动作，其他操作退为轻量文字按钮；重要入口保留文字，不只依赖悬停或图标。
- **动效**：仅用于说明展开、状态切换和定位，不循环装饰；任务成功不自动弹窗或播放盖章效果。

正文无需按固定纸张尺寸分页，窗口缩小时仍能自然阅读。纸面感不能降低文字对比度，
也不能依靠浅灰小字、极小点击区域或隐藏焦点来制造简洁。键盘操作、缩放和清楚的选中状态需要保留。

## 5. 说明清楚，但在需要的时候出现

### 通过交互让作者感知设计理念

2026-10-17 已确认：**设计理念通过操作顺序、触发条件、内容归属和结果反馈体现，让作者在使用中自然感知。**
页面上的说明用于帮助作者完成当前操作，不用常驻提示框宣告“作者拥有决定权”等产品理念。

例如，当前黄色背景框中的“作者拥有最终解释权，Agent 提出候选，接收才进入正文”，应转化为实际交互：

1. 讨论中给出方向或建议时，提供继续讨论、调整要求或开始试写的相关动作；提出建议本身不触发创作。
2. 作者选择方向并要求创作后，Agent 才开始相应任务，原位显示正在执行的动作，让作者感受到自己的决定推动了创作。
3. 试写结果先以候选呈现，作者查看并选择“采用为正文”后才进入正式稿；未采用时保留候选，原稿保持原状。

作者已通过自然语言或按钮明确要求创作、且范围清楚时，这一要求就是决定，不额外增加确认步骤。
已授权整体修改的发布规则仍遵循[主方案的执行边界](agent-first-workbench-product-design.md#执行边界)，不要求所有结果再次逐项采用。
界面改进应落实上述行为并移除宣告理念的黄色提示框，不能只改写提示文字。

评审时检验：去掉解释设计理念的文案后，作者是否仍能从操作与反馈中理解“由我决定何时开始、哪些内容进入正文”。
必要的操作说明、真实状态、错误原因与恢复入口仍应清楚可见。

### 按需提供操作说明

简洁与清晰同时成立：入口使用明确名称；打开工具后给一句用途和当前步骤；详细规则通过“检查说明”等入口展开。
初次使用、条件不满足或失败时直接解释下一步，不把关键原因藏进悬停提示。
产品文档中的完整字段表和状态表用于实现，不要求原样铺在前端。

以手工修改为例：

1. 平时提供“手工修改”，点击后标明正在编辑工作副本，可继续切章修改。
2. 修改中显示“修改稿已保存”和本轮章节范围，“修改完成”是清楚的结束动作。
3. 完成时原位反馈“已记录本次修改：第1章、第2章”，详细差异按需打开。
4. 完成后分别显示“摘要待更新”和“账本更新建议尚未整理”，提供带“使用模型”标识的明确启动操作；不因模型可用而自动运行。
5. 作者启动后原位显示等待、执行、停止、失败或完成；无模型时仍完成版本记录，不弹出强制配置页或启动审计。

无实际改动时直接说明未创建新版本；失败时直接写明失败对象、原因和下一步。
结果必须明显可见并可回看，但可以通过原位更新、准确文字和适当强调来表达，无需大色块或模态弹窗。

## 6. 桌面的收纳规则

任务完成后，详细过程收进对应记录；Agent 事件流持续保存在执行日志中，作者明确启动的摘要等模型任务也可回看；版本记录进入历史。
未完成人工修改保留副本及继续入口，未启动的摘要更新和账本更新建议保留简短状态；本版无后台作者学习。
当前未处理的问题保留简短入口，作者可以稍后继续，不让每个历史事项永久占据桌面。
导入和对话任务的结果都可从正文历史或相关入口找回；已明确启动的任务即使在作者离开当前视图后完成，也只更新固定归属的记录，不把作者带到其他讨论。
新增功能优先寻找已有的正文操作、对话动作或账本条目，不默认增加导航、独立页面或常驻卡片。

详细图谱和前后对照可以临时展开到主区，提供明确返回入口；退出后恢复原稿件位置和未完成编辑。
工具说明中使用准确的功能语言，桌面氛围由视觉承载，不用比喻性按钮名称替代操作含义。

## 7. 视觉与交互验收

1. 有正文时第一眼看到文章和清楚的对话入口；正常状态下没有整排业务页面与仪表盘卡片。
2. 默认不展开历史、任务详情、长篇工具说明和所有账本分组，使用相关功能时可以明确找到它们。
3. 右侧仍可查看本章相关账本；收起侧栏后正文与对话都能独立完成主要工作。
4. 功能使用前能理解用途与操作，结束后能看见真实结果，不依赖装饰动画或瞬间消失的通知。
5. 流式输出、作者已启动的摘要更新和其他任务完成不导致正文跳动、失焦或失去阅读位置。
6. 不以过小字号、低对比度、图标猜谜或仅悬停可见的操作换取视觉简洁。
7. 前端整体与控件保持老 iOS 风格，稿纸与侧栏的布局调整延续这一视觉基调。
8. 执行日志入口清楚可达，收起或离开日志视图不影响事件记录；展开、回看及实时追加不干扰正文阅读和编辑。
9. 工作区充分使用窗口宽高，主要模块清晰分区，正文、对话与账本文字足够大且易读；页面没有无目的的大块外围空白，也不靠缩字、挤窄栏或增加无关卡片填充空间。
10. “手工修改”可随时发现，开启后明确显示修改稿、本轮章节与“修改完成”；常规阅读与未完成副本不混淆。
11. 撤销入口说明正文及关联账本的实际恢复范围；存在后续独立修改时，在原对话展示具体冲突选择，不静默丢失新内容。
12. 正文证据需核对时，账本详情与图谱明确显示状态及旧来源；不只用颜色提示，也不将整条作者设定显示为已被撤销。
13. 导入预览能看清新增或替换的目标及实际正文；无模型保存想法与请求 Agent 的动作、状态清楚区分。
14. 无需黄色理念提示框，作者也能通过“讨论或选择方向 → 明确要求创作 → Agent 执行 → 查看候选并采用为正文”感知决定权；提出建议不自动开工，已明确的创作要求不被重复确认阻断，未采用的试写不改变正式稿。
