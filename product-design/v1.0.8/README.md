# v1.0.8 产品方案：只读总览、随章查看与对话调整

日期：2026-11-02。状态：P0—P4 已实施，版本已升至 1.0.8；确定性、前端与浏览器验收已完成，在线模型 O01—O06 待执行。[开发入口](../../dev-notes/v1.0.8/README.md)、[P5 发布记录](../../dev-notes/v1.0.8/notes/P5-release.md)。

## 1. 为什么改造

v1.0.6 建立构思与正文的关联，v1.0.7 收敛入口和状态，但详情仍要求维护标题、内容、时间、章节、用途、事实、读者理解和关系。作者表达一个想法，需要处理多项结构化信息。

本版减少作者需要维护的信息：页面呈现当前结果，调整统一通过对话。系统继续保留来源、版本和披露边界，但不要求作者或模型为了表单完整而补齐未知信息。

## 2. 已确认要求与本版落地选择

作者已确认：

- 取消构思和线索的大量属性编辑。
- 全部通过对话调整，页面只负责查看。
- 「构思与线索」全书总览和「随章查看」两种布局同时存在。
- 改造版本为 v1.0.8。

本方案确定的落地方式：保留正文 / 构思 / 线索三个主入口；全书总览位于构思和线索页，随章查看直接出现在正文页。它们共享对象、来源和修改结果，不新增第四个主入口，不设置一套需要作者维护的布局配置。

## 3. 两种布局如何共存

| 所在位置 | 默认内容 | 选择之后 | 调整方式 |
|---|---|---|---|
| 构思页 | 按讲述顺序组织的情节列表 | 只读情节安排、已登记出处、必要提醒 | 在详情所在区域进入对话 |
| 线索页 | 全书线索列表 | 原文按出现顺序展示，附已确定的作者意图 | 在详情所在区域进入对话 |
| 正文页 | 正文与已有标记；「本章相关」按需展开 | 本章关联的构思、线索及对应原句 | 同一辅助区进入对话 |

全书总览用于跨章安排，随章查看用于就近讨论。两处选中同一对象时，显示相同的当前内容；随章查看只限制列表范围，不建立章节专属副本。

宽屏默认最多两块主要内容区域：总览列表与详情，或正文与辅助区。目录按需展开；打开对话替换辅助区内容，提供返回当前详情的动作。窄屏采用主内容和详情逐层进入，保留返回位置。不得将目录、列表、图、详情和对话全部常驻。

切换全书与正文保留对象和返回位置。发送后，本轮引用不随页面切换改变；未发送的文字不因换对象丢失，改变引用必须在输入区明确可见。

## 4. 构思：当前确定的情节安排

默认显示标题和一段安排；章节、时间说明只有明确时才显示。讲述顺序与故事发生顺序分别保存，不能互相替代。

作者说「把目击放到第一次命案之前」时，若语境不能确定指发生时间还是披露次序，只问这一处歧义；不要追问开始分钟、结束分钟和其他内部字段。确认是发生先后时保存先后关系；没有具体时刻就不生成数值时间。

时间轴保留为构思页的只读辅助视图，通过「查看时间轴」进入并返回原选择。没有数值时间时显示已知文字或先后关系，不画没有信息量的时间条。未知内容不产生待填清单。

## 5. 线索：正文出处与创作意图

默认展示线索名称、按正文顺序排列的出现位置，以及已确认的创作意图。无出处时写「暂无已登记正文出处」，不能推断作者尚未写作。

已确定的真相、用途和关系可以只读查看，但不再常驻空字段，不要求新建时选择真相 / 误导。作者隐藏解释与正文原句分开呈现，不混合成无来源的一段总结。读者理解是作者意图或模型判断，不能自动当作真实读者反馈。

关系图保留为线索页的只读辅助视图。只展示已登记关系，无关系时直接显示空结果；打开页面不调用模型补边。作者通过对话建立或删除关系，模型必须解释关系的前提和依据。

## 6. 随章查看的范围

- 纳入与当前正文有有效关联的构思节点，以及在本章有可验证出处的线索。
- 本章计划项尚无正文依据时，可以单独呈现为「本章安排」，不得显示为已经出现。
- 原引用失效的项仍可查看历史引用和原因，但停止正文高亮。
- 一个片段可以关联多个构思或线索；同一线索的多次出现不能合并掉。
- 不通过同名、关键词相似或整章全文匹配猜测关联。
- 无关联时提供「讨论本章」；选段后提供「讨论此段」。作者可直接说「把这段记作线索」，不弹属性表单。

全书入口始终可达，未安排章节的构思不会因为随章查看而消失。

## 7. 所有调整进入对话

点击「讨论调整」只打开输入区并准备引用，不立即发送固定核对请求，也不调用模型。没有会话时，在首次发送后建立；有当前会话时复用，正在运行的回合不被中途替换材料。

| 作者表达 | 结果 |
|---|---|
| 「有没有更好的安排？」 | 给出带依据的建议，不改当前方案 |
| 「把身份揭示推迟到第五章」 | 明确范围后直接调整计划，返回实际结果 |
| 「就按你刚才第二个方案改」 | 对应具体建议与其版本，采用后提交 |
| 「同步修改第三章正文」 | 取得该正文范围后执行正文修改 |
| 「撤销刚才对这条线索的调整」 | 撤销对应变更，检查后续依赖 |

创建、改名、调整内容、删除、关联正文、用途与关系调整均须能通过对话完成。讨论只涉及构思时不能顺便改正文。删除仍被其他对象引用的内容时，说明影响并只处理已授权范围，不静默级联。

成功回执给出简短结果，可展开变化和出处；撤销位于对话回执中。失败显示事实和建议，格式为 `[错误码] 位置：现象。建议：…`。不能仅凭模型说「已完成」刷新成成功状态。

## 8. 上下文原则

当前正式方案、正文证据和未采用建议保持分离。聊天探索不自动成为长期设定；确定的安排进入现有正式存储，下一次按当前版本读取。

每轮从明确对象或本章出发，读取相关原文与适用约定，必要时再扩展范围。保留预算和材料缺失记录，不能把未读取当作不存在。关系存在也不意味着无限扩展整个关系图。

随章查看仍是作者视图，不等于读者试读。实际试读在服务端按截止位置过滤，禁止隐藏真相、未来关系以及带有未来信息的总结进入试读上下文。

## 9. 本版撤除与保留

撤除属性输入框、类型切换按钮、添加关系表单、各处保存按钮，以及正文选段后的名称 / 用途填写弹窗。提醒暂缓、确认差异和撤销也统一由对话承担。

保留直接正文编辑、原文定位、三状态内部计算、时间轴和关系图的阅读能力、模块库与灵感入口。正文编辑器的正常写作不受「构思与线索只读」约束。

本版不增加新知识分类、自动全书审计、后台生成关系、读者视角新页面或旧数据迁移。正式界面沿用现行视觉语言，预览只用于说明信息组织。
