# V04-8 位置改由系统文件夹对话框选择

目标：去掉「手抄目录路径」的输入方式——作者不该知道绝对路径、不该记分隔符、也不该先去资源管理器里建好目录。

## 实际改动

- **系统对话框（服务端弹出）**：新增 `workspace/directory_dialog.py`。用 Tk 的
  `askdirectory` 打开系统文件夹窗口（Windows 上是系统的「浏览文件夹」对话框），
  取消返回 `None`；窗口置顶，避免被浏览器窗口盖住。对话框跑在请求线程里，
  其他接口（含事件流）不受影响。
- **新接口**：`POST /api/file-workspaces/pick-directory`，请求体 `{"initial": "<起始目录>"}`，
  返回 `{"path": "<绝对路径>" | null}`。同一时刻只允许一个窗口——第二个请求以
  `DIRECTORY_PICKER_BUSY_CONFLICT`（409）拒绝；没有桌面会话或没有 Tk 组件时以
  `DIRECTORY_PICKER_FAILED`（500）失败，并给出 `--workspace` 的替代路径。
- **界面改版**：目录对话框换成两个页签。「打开已有」只认「作品文件夹」；
  「新建作品」分「存放位置」与「作品名」，最终目录是「位置 / 作品名」。
  两者都只显示对话框选出来的路径，**没有可手输的路径输入框**；作品名仍是文本框
  （名字不是路径）。首次没有作品时默认落在「新建作品」页签。
- **默认位置沿用 V04-7**：`GET /api/file-workspaces/default-location` 给出系统文档目录，
  作为新建时的初始位置与对话框的起始目录。

## 接口与数据影响

- 新增 `POST /api/file-workspaces/pick-directory`；`GET /default-location` 语义从
  「预填路径」变成「起始位置」，结构不变。
- 前端不再往 `POST /api/file-workspaces` 里传手输路径，改传对话框结果（新建时由
  「位置 + 作品名」拼出）。
- 轮次、Git、文件接口均不变。

## 实现取舍

- **为什么由服务端弹窗**：浏览器拿不到本机绝对路径（`showDirectoryPicker` 只给句柄），
  所以「真正的资源管理器式选择」只能由跑在同一台机器上的进程提供。这是本地单用户工具
  才成立的前提，因此无桌面会话时必须明确失败，而不是退回一个假的输入框。
- **为什么不做「输入框 + 浏览按钮」并存**：两种入口意味着两套校验和两种错误消息，
  作者也会分不清「填错了」和「选错了」。只留一条路径，失败原因就只有一种。
- **为什么作品名还是输入框**：名字是创作决定，路径是机器细节；把名字也做成选择器
  反而更别扭。
- **为什么限制同时只开一个窗口**：系统对话框是单例资源，同时开两个会让作者分不清
  哪个属于哪个请求；冲突比排队更好解释。

## 验证

- 后端 `uv run pytest tests/workspace -q`：145 项通过（新增 3 项：返回选中目录并透传
  起始目录、取消返回 `null`、忙时 409）。
- `uv run mypy src/hastings`、`uv run ruff check src/hastings tests/workspace`：无问题。
- 前端：`npx tsc --noEmit` 通过；`vitest` 20 项通过（新增 2 项：`pickDirectory` 的
  POST 形状与取消结果）。
- 浏览器 E2E：6 项通过。新建流程改为用 `page.route` 截获 `pick-directory` 返回临时目录，
  断言最终目录、Git 基线，并断言界面上不存在「目录路径」输入框。
- 真实对话框：启动真实服务后请求该接口，系统窗口以标题「选择作品位置」出现，
  请求一直挂起到作者操作（相当于取消时进程结束、窗口消失）。

## 偏差与未完成

- 打包后的 sidecar 未验证：PyInstaller 需要把 Tcl/Tk 数据一起带上，否则发行版里
  对话框打不开（会走到 `DIRECTORY_PICKER_FAILED` 而不是静默失败）。
- 对话框是系统的经典「浏览文件夹」样式，不是资源管理器同款的现代选择器；外观取决于
  系统，若需要现代样式要换成 COM 的 `IFileDialog`。
- 浏览器标签页在对话框开着时被关闭，窗口会留在桌面上直到作者取消；不做自动关闭。
