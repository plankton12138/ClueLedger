# Git 历史

核对日期：2026-10-20。本文描述 V04-2 已实现的版本行为。写作 Agent 与对话尚未接入，因此「一轮请求」目前只由记录层单独验证，见[阶段记录](../notes/v04-2-git-history.md)。

## 1. 职责

作品目录是一个独立 Git 仓库。这一层只做三件事：调用真实 `git`、把结果整理成可判断的结构、守住几条不允许越过的边界。它不维护自己的版本对象，也不解释一份平行历史——作者在应用之外用自己的 Git 工具，看到的是同一份记录。

## 2. 仓库边界

| 情况 | 行为 |
|---|---|
| 作品目录没有 `.git` | 可阅读、可写文件，但自动记录前必须先「启用版本记录」 |
| 作品目录套在上级仓库里 | 不使用上级仓库；初始化时在作品目录内建立独立仓库 |
| `.git` 存在但仓库根不等于作品根 | 拒绝写入，返回 `GIT_ROOT_MISMATCH` |
| 处于分离头指针 | 拒绝自动写入与提交（`GIT_NO_BRANCH`） |
| 有未解决的合并冲突 | 拒绝自动写入与提交（`GIT_MERGE_CONFLICT`） |
| 暂存区已有内容 | 拒绝自动写入与提交（`GIT_STAGED_CHANGES_CONFLICT`），不消费作者的暂存区 |

命令一律以列表传入、`shell=False`、30 秒超时；不提供 `git add .`、`reset --hard`、`clean`、强推或改写历史的入口。提交身份只用 `-c` 对本次命令生效（`Hastings <hastings@local>`），不读也不写作者的全局配置。

## 3. 初始化

初始化做三件事：建立仓库、写入 `.gitignore`、把当前内容记成第一个提交「初始化作品目录」。已有内容的目录因此有可比对的起点，撤销与差异从第一次打开就能用。

`.gitignore` 固定忽略 `.obsidian/`、`.DS_Store`、`Thumbs.db` 与应用写入用的 `.hastings-*.tmp`：外部工具文件和临时文件不属于作品内容。

新建作品时由创建操作一并初始化；打开已有目录只检查，不擅自初始化。重复初始化不会产生额外提交。

## 4. 受管范围

只有 `正文/` 与 `设定集/` 下的受管文件参与状态、差异与提交。`.gitignore`、`.obsidian/`、`正文/` 里的非 `.md` 文件都不计入改动，也不会被提交带进去。

状态区分四类：暂存区路径（全部路径，用于识别预暂存）、受管改动（相对 HEAD）、未合并路径、以及受管改动中的重命名原路径。

## 5. 差异与历史

| 读取 | 内容 |
|---|---|
| 工作区差异 | `git diff HEAD` 的受管文件差异；未跟踪的新章节不在其中，只在状态里标为「未跟踪」 |
| 提交差异 | `git show` 的完整差异，包含新增文件与删除文件 |
| 历史 | 作品仓库的全部提交，最新在前；每条含提交 ID、时间与标题 |

未跟踪文件不进工作区差异是 Git 本身的行为，这里不伪造 diff：新章节的完整内容在提交差异里看，工作区只报告「这是一个新文件」。

## 6. 一轮写入的记录

一次修改请求的记录分两步，只在真正要写文件时才启动：

1. **准备基线**：校验仓库可写；受管文件已有未记录改动时，先单独记一笔「外部修改：应用之外保存的内容」，再以它作为本轮基线。作者的改动与模型的改动因此分属两个提交。
2. **结束记录**：按磁盘上的实际变化提交一次；没有变化不提交。停止或失败时，已写入的内容仍然记录，标题标明「部分完成」「失败」「已停止」或「中断」。Git 失败时保留文件，结果记为 `unrecorded`，可以单独补记，不重跑模型。

执行状态与记录状态是两条独立的轴：

| 字段 | 取值 |
|---|---|
| `status` | `completed`、`partial`、`failed`、`stopped`、`interrupted` |
| `recording` | `committed`、`no_change`、`unrecorded` |
| `changed_paths` | 本轮实际变化的受管路径 |
| `commit` | 记录成功时的提交 ID，否则为空 |

「文件写进去了但历史没记上」由 `status=failed` + `recording=unrecorded` 表达，不会显示成全部成功。运行期间 HEAD 被外部推进时同样不自动提交，结果标为 `unrecorded` 并说明原因。

## 7. 撤销

最新一次修改的撤销使用 `git revert` 生成反向提交，历史只增不减。前提是：目标提交仍是 HEAD、受管文件没有未记录改动、暂存区干净。任一条件不满足就拒绝并说明原因（`GIT_HEAD_MOVED_CONFLICT`、`GIT_DIRTY_CONFLICT`）；撤销过程中产生冲突时清掉 revert 的中间状态，工作文件保持原样。

不实现历史任意位置的三方撤销，也不通过移动分支指针回退。

## 8. 当前缺口

- `git/status`、`git/diff`、`git/log`、`git/commits/{sha}/diff`、`git/init`、`git/record`、`git/revert` 已有 HTTP 端点（V04-4）。
- 一轮写入还没有串行锁与对话生命周期：同一作品并发写入的限制随写作 Agent 一起实现。
- 没有文件系统监听：外部改动要等下一次读取才被发现。
- 不提供分支管理、远程同步与多人协作；撤销只覆盖最新一次。
