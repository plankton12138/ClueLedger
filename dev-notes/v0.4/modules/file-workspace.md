# 文件工作区

核对日期：2026-10-20。本文只描述 V04-1 已实现的行为；Git 历史、写作 Agent、对话与前端接线分别属于后续阶段，尚未实现。

## 1. 职责

把「一部作品 = 一个本地目录」落实为可校验的读写。阅读器、后续的文件工具和应用之外的编辑器操作同一份文件；目录是当前内容的唯一依据，应用不保存第二份正文。

这一层只回答三件事：哪些路径属于作品、当前内容是什么、这次写入是否基于刚才读到的那一份。它不解析段落、不维护章节清单、不写数据库，也不判断内容质量。

## 2. 内容结构

```text
作品目录/
├─ 正文/
│  ├─ 0001 雨夜.md
│  └─ 0002 来信.md
└─ 设定集/
   ├─ 角色小传.md
   ├─ 线索.md
   └─ 真相.md
```

| 规则 | 行为 |
|---|---|
| 正文 | `正文/` 的直接子级 `.md` 文件，按文件名排序；不递归子目录 |
| 设定集 | 只有三个固定路径，不能新增第四种、不能改名或删除，只能创建与改写 |
| 章节序号 | 应用新建时取当前最大四位序号加一，文件名形如 `0001 雨夜.md` |
| 章节标题 | 首个一级标题；缺失时回退文件名（去掉序号前缀） |
| 技术文件 | `.git/`、`.obsidian/` 等不属于作品内容，不列出、不搜索、不提交 |
| 编码 | 读取接受 UTF-8 与带 BOM 的 UTF-8；应用写入固定 UTF-8、LF |

新建目录时建立 `正文/`、`设定集/` 与三份空设定文件，不创建数据库。打开已有目录只检查和读取，不创建、不改写任何文件；缺少受管文件时由后续正常写入补齐。

## 3. 读写与指纹

读取返回路径、LF 文本与实际字节指纹（SHA-256）。指纹按原始字节计算，因此 BOM、换行方式、行尾空格都算内容差异——外部编辑器保存过一次，指纹就会变。

写入必须带上次读取得到的指纹：

| 传入的指纹 | 条件 | 结果 |
|---|---|---|
| `None` | 文件不存在 | 创建 |
| `None` | 文件已存在 | `FILE_EXISTS_CONFLICT`，不做覆盖 |
| 具体指纹 | 文件不存在 | `FILE_NOT_FOUND` |
| 具体指纹 | 当前指纹不同 | `FILE_STALE_CONFLICT`，磁盘内容保持不变 |

写入先在同目录写临时文件、`fsync` 后替换目标，进程中断不会留下半个文件。删除与移动同样要求指纹；两者只作用于正文章节，设定文件移动或删除返回 `SETTING_PATH_FIXED`。

## 4. 路径边界

词法校验只接受 `正文/<名字>.md` 与三个设定路径；随后再按解析后的真实目录复核，拒绝符号链接、目录联接和任何越出作品根的结果。仅靠字符串检查无法覆盖 Windows 的目录联接，因此两层都保留。

被拒绝的输入包括：绝对路径、`..` 跳转、`./` 与非规范分隔符、Windows 盘符、反斜杠、子目录、`.git`、非 `.md` 后缀、非三类的设定文件、Windows 保留名（`CON`、`NUL` 等）、首尾空格或点结尾的文件名。

## 5. 搜索与导入

搜索逐行匹配受管文本，大小写不敏感，返回路径、行号与单行摘录；命中超过 `limit` 时截断并标记 `truncated`（刚好等于上限不算截断）。无法解码的文件不静默跳过，单独列入 `unreadable`。

导入直接写章文件，不产生候选或预览：`.md` 一个文件一章，`.txt` 沿用 0.3 的分章纯函数；默认新增，重名不覆盖（序号递增）。不支持的格式返回 `IMPORT_FORMAT_INVALID`，空内容返回 `IMPORT_EMPTY`。

## 6. 应用状态与绑定

作品正文之外，应用只记录「最近打开过哪些目录」。登记文件是应用状态目录下的 `workspaces.json`，默认 `~/.hastings`，可用 `HASTINGS_STATE_DIR` 覆盖。

绑定 ID 由规范化后的绝对路径散列得到：同一目录重复打开只有一条记录，界面、后续会话与事件因此不需要另一套映射。目录被移动或删除后 ID 变化，按「换了一个目录」处理。登记文件损坏时按空列表处理，让作者重新选择目录，而不是让启动失败。

## 7. 接口

前缀 `/api/file-workspaces`，与旧 `/api/workspaces`、`/api/v2` 区分。本阶段只提供读取与导入，**没有写正文的端点**：正文修改只来自对话中的 Agent（V04-3）或应用之外的编辑器。

| 方法与路径 | 行为 |
|---|---|
| `GET /api/file-workspaces` | 最近目录列表，含目录当前是否可用 |
| `POST /api/file-workspaces` | 按服务器本地路径打开；`create=true` 时补齐两块内容与三份设定 |
| `GET /{id}/files` | 两块内容目录；设定集固定三条，缺失时 `exists=false` |
| `GET /{id}/file?path=…` | 单文件原文、指纹、类别与标题 |
| `GET /{id}/search?q=…&limit=…` | 逐行搜索与无法解码的文件 |
| `POST /{id}/imports` | 上传 `.md` / `.txt` 并直接新增章文件，返回新的目录 |

错误统一为 `{"error": {code, where, why, fix, details}}`，状态码按错误码尾缀映射：`*_NOT_FOUND` → 404，`*_CONFLICT` → 409，`*_FAILED` → 500，其余 400。前端按 `code` 分支，不解析文本。

## 8. 启动方式

```bash
uv run python -m hastings.server --workspace <作品目录>
```

文件工作区模式只装配文件接口、健康检查与静态前端：不读 `config.yaml`、不打开旧工作台数据库、不挂 `/api/v2` 与旧模型路由。与 `--v2-db` 同时出现按参数错误退出（退出码 2）；目录不存在或不是目录按启动故障退出（退出码 1）。默认入口仍是旧工作台，V04-5 再切换。

## 9. 当前缺口

- 没有 Git：初始化、差异、提交与撤销属于 V04-2，本阶段不声称已有版本记录。
- 没有模型与对话：`--workspace` 模式没有可用的写作 Agent，也没有会话与事件流。
- 前端仍是 0.3 写作台，未接新接口；界面上的目录选择与 Markdown 稿纸属于 V04-4。
- 没有文件系统监听：外部改动通过重新请求目录或文件回读发现，切换窗口不自动刷新。
- 跨文件写入不是事务：一次导入多章时，失败前已创建的章保留，需要按实际结果核对。
- `desktop/` 的版本号仍为 `0.3.0`；本次按计划只同步后端包与 `frontend/` 的版本。
