# 会话、草稿与任务归属

核对日期：2026-10-21。本文描述 V04-10 已实现的行为：正式会话的边界、同一会话的上下文范围、草稿与切换、任务归属与恢复、接口与失败行为。轮次执行与 Git 记录的职责见[写作 Agent 与对话](agent-and-chat.md)，不在这里重复。

## 1. 会话边界

一部作品可以有多个会话。正式会话从**第一条非空提示被后端受理**那一刻开始存在：

- 点「新对话」只切到临时输入状态：不生成会话 ID、不登记、不写日志、不请求模型。
- 输入空白或输入后又全部删除，切走时什么都不留下。
- 输入了非空内容但没发送，切走后保存为该作品的「新对话草稿」，不进入正式会话列表。
- 首次发送是一次请求同时建会话与受理首轮，标题取首条提示的简化文本。
- 受理前失败（空提示、作品忙碌、状态目录不可写）不留下任何会话，输入与错误都还在。

已经存在的旧记录不会被删除或改写；旧日志没有新的元信息行，也能按首条提示读出标题。

## 2. 上下文范围

模型只收到当前会话已保存的讨论，以及当前作品的文件：

- **回放**：本会话此前每一轮的作者提示与公开回复；工具调用参数、工具结果正文、思考内容不回放。
- **执行事实**：每一轮实际是完成、部分完成、失败、停止还是中断，动了哪些文件，历史有没有记录。这段说明写进系统提示，不冒充作者的要求；`run_finished` 与模型自述冲突时以执行事实为准。
- **当前提示只出现一次**：受理时记下历史游标，恢复范围止于该游标。
- **文件是共享的**：A 会话写过的章节，B 会话下一轮读取时看到的是当前内容。旧的工具输出不会被当成当前原文，需要时模型自己重新读。

换模型不影响历史：原连接与模型记在各轮事件里，不篡改归属。

## 3. 草稿

- 草稿按「作品 + 会话」保存，键是正式会话 ID；未发送的新对话用固定槽位 `new`。
- 草稿不是已发送的提示，不进消息列表、不进模型上下文。
- 输入立即进入内存，短暂合并后写入应用状态目录；切换会话、离开页面前会先保存当前草稿。
- 只有收到受理确认后才清除「仍然等于提交文本」的草稿：受理期间作者新输入的字不会被旧响应擦掉。
- 保存带版本核对：同一窗口的草稿写入串行执行，后一条使用前一条返回的版本号；版本过期时先按当前版本自动重发一次，仍冲突才保留本地文字并提示，不用旧内容覆盖另一端的新草稿。
- 刷新只恢复已保存的内容，不自动发送、不自动重跑中断的轮次。

## 4. 任务归属与恢复

同一作品同时只受理一轮，**包括已受理但还没开始执行的轮次**：受理锁覆盖查重、忙碌判断、写初始记录与占用。作品忙碌时，新会话请求同样被拒绝，且不会留下空会话。

- 切走只解除事件订阅，不停止服务器任务；任务始终属于原会话。
- 切回时先取快照（事件 + 该会话活动轮次），再从 `last_seq` 订阅，补上读取与订阅之间的事件。
- 停止在受理阶段就有效：还没调用模型的轮次直接收尾为「已停止」，不假装轮次不存在。
- 事件订阅按会话隔离，每个订阅捕获自己的会话键与代次；旧订阅的收尾不改动其他会话。
- 网络断开只显示连接中断，不宣布任务结束。

进程重启后按轮次配对修复：任何有 `turn_started` 却没有 `run_finished` 的轮次都补一条中断终态，崩在工具开始、工具结束或助理回复之后同样识别；重复启动不会补第二条。中断只说明执行未正常结束，文件与 Git 以磁盘为准，不自动继续。

## 5. 存储布局

```text
~/.hastings/workspaces/<作品绑定 ID>/
├─ conversations.json     # 会话列表索引（可从日志重建）
├─ c_<ID>.jsonl           # 本会话事件；首行是 seq 0 的元信息
└─ conversation-ui.json    # 最近正式会话、各会话草稿、界面版本
```

- 日志是「受理成立」的依据，索引只是加速列表；首轮日志整份原子发布，索引写失败由下次读取的重建补齐。
- 元信息行不进入界面事件流（`seq` 为 0），只用于会话重建。
- 状态目录不能读时给状态存储错误，不会像没有聊天一样返回空历史继续执行。

## 6. 接口

| 方法与相对路径 | 行为 |
|---|---|
| `GET /{wid}/conversations` | `items`、`recent_id`、作品 `active_turn`、`revision`；按最近活动倒序 |
| `POST /{wid}/conversations` | 必须带非空 `text` 与 `request_key`；建会话并受理首轮，返回 202 |
| `PATCH /{wid}/conversations/{cid}` | 改标题；空标题按输入错误拒绝 |
| `GET /{wid}/conversations/{cid}/messages?after=` | 事件、`last_seq`、该会话 `active_turn`、`revision` |
| `POST /{wid}/conversations/{cid}/turns` | 已有会话发送一轮，要求 `request_key` |
| `POST /{wid}/turns/{tid}/stop` | 停止指定轮次，覆盖已受理未开始的情况 |
| `GET /{wid}/events?conversation_id=&after=&follow=` | 只推送指定会话；每轮以 `run_finished` 结束 |
| `GET /{wid}/conversation-ui` | 最近正式会话、非空草稿、界面版本 |
| `PATCH /{wid}/conversation-ui` | 按目标合并；`If-Match` 带界面版本，空草稿文本表示删除 |

旧的 `POST conversations {}` 不再创建空记录（缺字段返回 422，空提示返回 400 `PROMPT_EMPTY`）。

## 7. 失败行为

| 情况 | 结果 |
|---|---|
| 空提示 | 400 `PROMPT_EMPTY`，不留会话 |
| 同一请求键、相同文字 | 返回原来那一轮，不重复调用模型 |
| 同一请求键、不同文字或不同会话 | 409 `REQUEST_KEY_CONFLICT` |
| 作品已有一轮在跑（含已受理未开始） | 409 `WORKSPACE_BUSY_CONFLICT`，`details` 带所属会话与轮次 |
| 初始日志写不下去 | 500 `STATE_WRITE_FAILED`，列表里没有这条会话 |
| 界面状态版本过期 | 409 `CONVERSATION_UI_CONFLICT` |
| 停止一个已结束的轮次 | 404 `TURN_NOT_FOUND` |

## 8. 当前边界

- **没有压缩与摘要**：长会话不自动截断，也不展示 token 百分比；厂商返回超限时原样说明。
- **不共享其他会话的讨论**：没有跨会话检索、长期记忆与会话分支。
- **草稿不合并多窗口**：两个窗口同时编辑同一草稿时以版本先到者为准；后到者自动用当前版本重发一次，仍冲突则保留本地文字并提示。
- **没有 token 级流式**：回复整条写入事件。
- **浏览器内的真实创作未逐屏走查**：真实链路在应用接口层取证（见[验证材料](../artifacts/v04-10-verification.md)），界面由构建、状态与组件测试覆盖。
