## 1. 目标与范围

让作者能够围绕不同话题持续讨论：新建时不会留下空记录，回来时能接着聊，切换时不会丢草稿或混入其他会话的结果，任务离开当前视图后仍有明确归属。

本次补齐会话生命周期、连续对话、草稿、切换、运行恢复，以及最小的列表整理。沿用作品目录、单写作 Agent、文件工具和 Git 历史，不增加新的作品内容类别。

### 1.1 交付范围

- 空白新会话只存在于界面；首次发送非空提示词时才建立正式会话。
- 同一会话可以连续讨论，并在切换、刷新和服务重启后恢复已保存的讨论。
- 不同会话的聊天上下文默认独立；同一作品下的会话共享当前作品文件。
- 草稿按作品与会话分别保存；输入但未发送的新会话内容作为草稿保留。
- 任务归属原会话；切换不停止任务，返回后能够恢复状态、查看结果和停止任务。
- 记住每个作品上次查看的正式会话，支持改名、最近活动排序和运行状态标识。
- 受理请求能够去重；中断能够识别；已修改文件、Git 记录与执行结果继续如实呈现。

### 1.2 不进入本阶段

自动共享其他会话的讨论、跨会话检索或长期记忆；上下文压缩与自动摘要；token 级流式、思考展示和复杂结构化卡片；会话分支、编辑历史消息后重跑；会话搜索、归档与批量删除；同一作品的并行执行、任务排队与自动续跑。

已有会话与历史空记录不批量删除，旧记录仍可回看。本阶段的空会话规则从新入口生效。

## 2. 会话边界与用户行为

### 2.1 会话独立，作品共享

一部作品可以有「讨论人物动机」「修改第三章」等多个会话。模型只接收当前会话已保存的讨论与执行结果，不自动读取其他会话的聊天、草稿或隐藏状态。

所有会话读取的是同一份当前正文和设定。A 会话修改了第三章，B 会话再次读取第三章时应看到新内容；新建会话不复制作品，也不恢复到旧版本。若讨论中的要求被作者明确写入正文或设定，其他会话可以通过作品文件读到它，这属于共享作品内容。

当前打开的章节只帮助定位，不自动把其他会话的讨论带入，也不把旧的文件读取内容视为当前原文。每轮继续执行时重新装配当前文件目录与设定，改文件前仍须重新读取并校验指纹。

### 2.2 新建与首次发送

「新对话」先切到临时输入状态，不立即调用创建会话接口，不生成会话 ID、登记、消息文件或模型请求。每个作品最多保留一个尚未正式发送的新会话草稿，重复点击新建复用它。

| 作者操作或结果 | 会话与草稿行为 |
|---|---|
| 新建，没有输入或仅输入空白，随后切会话/切作品 | 丢弃临时空状态，不出现在会话列表，不生成会话记录 |
| 新建，输入过内容又全部删除，随后切走 | 按当前空白处理，不保留空记录 |
| 新建，输入非空内容但未发送，随后切走 | 保存为该作品的「新对话草稿」，不进入正式会话列表；再次新建时恢复 |
| 在已有会话输入但未发送 | 只保存到该会话自己的草稿，不成为模型上下文 |
| 首次点击发送，后端成功受理 | 同一次操作建立正式会话并登记首轮，标题取首条提示的简短文本；列表出现该会话 |
| 首次发送被空白校验、作品忙碌或保存失败拒绝 | 不留下新正式会话，保留输入与错误，供作者修正或重试 |
| 已成功受理，随后模型未配置、调用失败或作者停止 | 保留会话、提示与实际结果；它已经承载一次明确请求 |
| 请求已发出但前端未收到响应 | 保留待确认请求标识与提交文本，用相同标识查询或重试，不能直接当成未发送空状态丢弃 |

因此，正式保存的边界是「首条非空提示被后端受理」。用户要求的空白新会话不会保存；非空未发送输入通过草稿保护，不需要为它提前建立会话。

### 2.3 切换、草稿与恢复

- 切换前保存当前非空草稿，空白新状态直接丢弃。切换回来恢复该会话的输入内容，不能沿用其他会话的输入。
- 仅在收到后端受理确认后清除已提交的那一版草稿。发送失败保留原文；受理期间作者新输入的文字不能被旧响应清掉。
- 已发送提示始终属于发送时的作品和会话；请求返回时如果作者已经切走，更新原会话，不强行把界面切回去。
- 刷新或重启后恢复每个作品上次查看的正式会话；恢复时不自动发送草稿、不自动重跑中断任务。
- 打开空白新状态不覆盖「上次正式会话」。非空新草稿在「新对话」入口显示草稿标识，作者可主动返回。
- 仅切换会话不更改模型选择，不撤销文件、不新建 Git 提交；每轮继续沿用供应商连接功能的模型快照规则。

### 2.4 运行中的任务

同一作品同时只受理一轮，包括已受理但尚未开始执行的轮次。作者可以查看其他会话和编辑草稿；发送按钮说明哪个会话仍在运行，后端也必须拒绝第二次受理，不能只依赖前端禁用。

切走可以关闭当前视图的事件订阅，但不能清掉服务器任务。会话列表与作品状态标识运行所属会话；返回后先恢复完整状态，再从最新事件位置接收后续事件。作者只能通过明确的「停止」操作停止任务。

每一轮的结果卡跟随其原会话和轮次。执行状态、文件变化、Git 记录状态分别呈现，不由「当前正在看的会话」决定结果归属。

### 2.5 最小列表整理

保留对话栏内的紧凑入口，展开后显示标题、最近活动时间与进行中/中断等状态，提供改名。列表按最近实际活动排序，但排序变化不改变当前选择。只阅读历史不更新活动时间；新请求、执行结束与改名可以更新。

自动标题仅在首次受理时生成一次，不额外调用模型，不覆盖作者改过的标题。新建空白状态不占列表行，未发送新草稿通过新对话入口标识。

## 4. 模块设计与关键示例

以下示例用于明确设计，不是已实现代码。职责保持在 Hastings 内，复用 Tau 的公开消息与 Agent 能力，不修改其通用循环。

### 4.1 会话存储：首次提示与正式创建合一

扩展 `ConversationStore`，对外提供 `create_with_first_turn()`，取代新界面中的「先创建空会话，再发送」两次调用。

首次请求先验证非空提示、作品存在、请求标识与忙碌状态；在作品受理锁内持久化首轮记录，之后才安排执行。正式会话只有在包含至少一条已受理提示时才能成为可见记录。目录、首条提示、任务 ID 和首次请求标识必须可以一起恢复。

继续使用应用状态目录，不建立作品内容数据库：

```text
~/.hastings/workspaces/<作品绑定 ID>/
├─ conversations.json          # 可恢复的会话列表索引
├─ c_<ID>.jsonl               # 本会话的正式事件记录
└─ conversation-ui.json        # 最近正式会话、各会话草稿、新对话草稿
```

首次创建采用先原子发布包含会话元信息和 `turn_started` 的初始日志，再更新列表索引的方式。正式日志是是否已受理的依据；列表索引可从日志重建。初始日志发布前失败不留下可见空会话；发布后索引写失败不得把已受理提示当成不存在。启动与回读需要发现并修复索引缺项，不能只信列表文件。

新日志的开头保存可校验的会话元信息与格式版本。旧日志继续使用已有登记读取，不要求旧记录拥有新元信息，也不批量重写旧记录。

`request_key` 写入正式受理记录，按作品、会话或首次请求范围查重；同键同内容返回原会话/原轮次，同键不同内容返回冲突。超时重试和重启后的重复提交不能生成第二个会话或重复修改文件。只有作者明确再次执行时才生成新键。

```python
@dataclass(frozen=True)
class AcceptedTurn:
    conversation_id: str
    turn_id: str
    request_key: str
    last_seq: int

# create_with_first_turn() 内部验证和持久化；不是公开空会话工厂。
accepted = store.create_with_first_turn(
    text=text,
    request_key=request_key,
    turn_id=turn_id,
)
```

多文件之间的中断恢复是本模块的显式责任，不能以进程内锁代替落盘一致性。正式日志不可读时给出状态存储错误，不能像没有聊天一样返回空历史并继续执行。

### 4.2 上下文恢复：先实现可预测的连续讨论

新增 `workspace/conversation_context.py`，只接收指定作品、会话和上一条已确认事件位置。模型输入由以下内容组成：当前系统要求与当前作品材料、本会话过去的用户提示和公开助理回复、必要的实际执行结果，以及本轮提示。

首版跨轮不回放原始思考、工具调用参数或工具结果正文：工具完整往返只保留在当前轮 Agent 中。旧轮次通过实际状态、改动路径与 Git 记录供模型了解结果，涉及原文时重新读取。这一取舍保留当前日志不重复存整章内容的边界，也避免带入残缺工具消息或跨供应商的思考签名。

```python
def replay_public_messages(events: Sequence[dict[str, Any]]) -> list[AgentMessage]:
    messages: list[AgentMessage] = []
    for event in events:
        if event["type"] == "turn_started":
            messages.append(UserMessage(content=event["text"]))
        elif event["type"] == "assistant_message":
            messages.append(AssistantMessage(content=event["text"]))
    return messages

history = replay_public_messages(previous_events)
harness = build_harness(..., messages=history)
async for event in harness.prompt(current_text):
    ...  # 本轮提示在这里追加，不能已包含在 previous_events 中。
```

实际实现先校验事件、按轮次分组，并为每个历史轮次附应用生成的执行事实：完成/失败/停止/中断、真实改动路径与记录状态。通过单独的应用说明进入模型上下文，不冒充作者要求，不把错误堆栈、Key 或未经确认的成功文字带入。`run_finished` 与助理自述冲突时，以实际执行事实为准。

受理当前轮次时保存其历史游标，恢复范围止于该游标，确保当前提示不重复、其他会话不混入。公开助理消息在每个 `MessageEndEvent` 时即保存，后续工具或模型失败也能保留此前已完成的公开回复；本阶段不增加 token 级消息事件。

同一会话更换模型后仍使用这些公开历史，原模型/供应商继续记在各轮事件中，不篡改历史归属。旧日志可恢复已有的用户提示与最终公开回复，但不能声称恢复了过去未保存的中间文本。

本阶段不压缩、不自动摘要、不静默截断聊天。已知模型窗口时按完整请求估算并预留输出空间，超限提示保留当前输入，建议新建会话；窗口未知时不展示虚假百分比，厂商返回超限错误时明确说明。长会话压缩另行设计。

### 4.3 轮次执行：导航状态不决定任务生命周期

扩展 `TurnService` 的受理状态管理，保留同一作品只执行一轮。受理锁覆盖重复请求检查、忙碌占位和初始记录提交，不能等后台 `_run()` 获得执行锁之后才算忙碌。

```python
async with self.admission_lock:
    previous = self.find_accepted(request_key, conversation_id)
    if previous is not None:
        return self.require_same_request(previous, text)
    self.require_workspace_idle()
    accepted = self.persist_acceptance(conversation_id, text, request_key)
    self.reserve_active_turn(accepted)  # 安排后台任务之前就占用
    self.schedule(accepted)
    return accepted
```

内存活动记录至少保存作品 ID、会话 ID、轮次 ID、模型快照与 accepted/running/stop_requested 状态；终态沿用现有 completed/failed/stopped/interrupted 及 Git 记录状态。受理前失败释放占位；受理后执行失败写回原会话；收尾只释放自己的轮次，不能清除后来任务的状态。

停止操作在 accepted 阶段也有效：记录停止请求，尚未开始模型调用的轮次不再调用；正在执行则传递取消。停止完成后保留实际文件变化，结束事件与 Git 记录沿用现有规则。不因为没有建好 harness 就把有效停止说成轮次不存在。

服务重启时按每个 `turn_started` 匹配终态，修复所有未正常结束的轮次，不能只检查日志最后一条是否恰好是 `turn_started`。最后一条为工具开始、工具结束或助理回复时也需要识别中断；重复恢复不追加多个中断终态。

中断只说明执行未正常结束，文件与 Git 以磁盘实际状态为准。不自动继续工具、不重复模型请求、不从未知写入状态重新执行整轮。

### 4.4 界面状态与草稿：与正式消息分开

`conversation-ui.json` 保存每个作品的最近正式会话和非空草稿，草稿键使用正式会话 ID；未发送新草稿使用固定的 `new` 槽位与独立草稿标识。空白新状态不写会话登记；清空草稿时删除对应草稿条目。

草稿不是已发送提示，不纳入消息列表和模型上下文。前端输入立即进入按会话索引的内存状态，短时间合并写入应用状态目录，正常切换前完成待保存草稿。刷新只自动恢复已保存内容，不自动提交。

为保护请求失败或页面意外关闭前尚未确认保存的文字，可以在浏览器保留有版本的恢复缓存；只缓存草稿文本、目标与请求标识，不缓存 Key 或模型配置。服务端保存确认后清理对应缓存；出现更新冲突时保留恢复副本供作者选择，不能用旧缓存自动覆盖服务器新草稿。本阶段不承诺多窗口同时编辑同一草稿的实时合并。

```typescript
type ConversationTarget =
  | { kind: "new"; workspaceId: string; draftId: string }
  | { kind: "saved"; workspaceId: string; conversationId: string };

type Draft = {
  text: string;
  revision: number;
  savedRevision: number;
};

type PendingSend = {
  target: ConversationTarget;
  requestKey: string;
  text: string;
  draftRevision: number;
};
```

提交时固定目标、文本、草稿版本与请求标识。确认受理后只清除文本和版本仍与提交相符的草稿；若作者已继续输入，保留新版本。首次受理将对应新草稿绑定为正式会话的草稿，不覆盖作者已经打开的其他新草稿，也不强行改变当前查看位置。

保存失败时保留内存和恢复缓存，明确提示尚未保存到应用状态目录。浏览器恢复缓存也不可用时提示当前保存限制，不能显示「已保存」。

### 4.5 前端事件接收：所有更新有明确目标

将 `workspace.ts` 中共用的 `events/running/activeTurn/lastResult` 变为按作品与会话索引的状态，当前选中项只负责决定显示哪一份。可拆出 `state/conversations.ts`，避免继续把会话生命周期堆进文件阅读状态。

每个事件订阅捕获固定的作品/会话键与订阅代次。事件只能更新该键；关闭旧订阅的 finally 也只能结束自己的接收状态。去重按会话和 seq，不能跨会话按同一个 seq 合并。

```typescript
const key = conversationKey(workspaceId, conversationId);
const generation = beginSubscription(key);
try {
  for await (const event of streamEvents(workspaceId, conversationId, after, signal)) {
    if (!isCurrentSubscription(key, generation)) break;
    updateConversation(key, state => applyEvent(state, event));
  }
} finally {
  finishSubscription(key, generation); // 不修改其他会话，也不宣布服务器任务已结束。
}
```

选择会话时先获取事件与运行快照，再从快照的 `last_seq` 订阅，补上读取到订阅之间的事件。返回运行中会话要恢复活动轮次和停止按钮；网络断开只显示连接中断，不能直接变成任务已完成。

关闭视图、切换作品或切换会话可以解除订阅。重新聚焦或返回时通过快照重建；旧的请求结果、事件、加载状态和 refreshAll 回调均须校验目标与代次，不能覆盖后来选中的作品。运行列表状态可以通过本机状态查询更新，不调用模型。

每轮结果按 `turn_id` 显示在该轮消息之后，替代只显示一个全局 `lastResult` 的归属方式。已有未记录改动、补记和撤销入口继续由 Git 层验证，不能因为打开旧会话就把旧提交当作当前可撤销提交。

### 4.6 API：新建与发送一体，读取带运行快照

接口仍位于 `/api/file-workspaces` 下；会话始终由作品定位，不新增全局共享会话空间。

| 方法与相对路径 | 目标行为及调用者 |
|---|---|
| `GET /{wid}/conversations` | 返回 items、最近正式会话 ID、作品活动轮次；列表与初始化使用 |
| `POST /{wid}/conversations` | 必须带非空 text 与 request_key；创建并受理首轮，返回 202 与会话/轮次信息 |
| `PATCH /{wid}/conversations/{cid}` | 修改标题；列表中的改名操作使用 |
| `GET /{wid}/conversations/{cid}/messages?after=` | 返回 events、last_seq、该会话活动轮次与状态版本；回读及切回使用 |
| `POST /{wid}/conversations/{cid}/turns` | 在已有会话发送一轮，要求 request_key；返回原请求或新受理结果 |
| `POST /{wid}/turns/{tid}/stop` | 停止指定轮次，覆盖已受理但尚未开始的情况 |
| `GET /{wid}/events?conversation_id=&after=&follow=` | 保留游标事件流；只推送指定会话，终态按轮次识别 |
| `GET /{wid}/conversation-ui` | 获取最近正式会话、非空草稿和界面状态版本 |
| `PATCH /{wid}/conversation-ui` | 按目标更新草稿或最近正式会话，空值删除草稿；要求对应版本 |

快照中的 `last_seq` 与事件批次须在一致的存储视图下生成。活动轮次包含所属会话、轮次 ID、执行状态与已固定模型的公开信息，不包含 provider 实例或凭据。

```json
{
  "events": [],
  "last_seq": 18,
  "active_turn": {
    "turn_id": "t_example",
    "conversation_id": "c_example",
    "state": "running"
  },
  "revision": "<状态版本>"
}
```

旧的 `POST conversations {}` 不再创建空记录，按字段校验失败处理。会话列表从数组改为带状态的响应对象；前端类型、测试准备器、浏览器脚本与其他实际调用者必须同批更新，不同时保留两种创建路径。旧磁盘记录保持兼容，此处的接口调整不代表自动迁移或删除旧会话。

错误沿用 `code / where / why / fix / details`。草稿版本冲突、同请求键内容冲突、作品忙碌和状态文件不可读各有可识别错误码；前端按码处理，不解析错误文案。界面状态更新只合并指定条目，不能整份覆盖其他会话草稿。

## 5. 实施顺序与依赖

本次作为 V04-10，保留在 0.4 范围内，不仅为新增计划升级包版本。供应商连接 V04-9 与本计划都会修改 service/api 与界面入口，实际实施时顺序整合并重新核对；本计划只复用模型快照与生命周期，不重写供应商配置。

| 子阶段 | 实际工作 | 结束条件 |
|---|---|---|
| V04-10A：会话生命周期 | 临时新状态、首次创建与发送、持久去重、日志与索引恢复、接口调用者调整 | 空白新建往返不产生会话；首次请求超时重试不重复创建；旧记录可读 |
| V04-10B：连续讨论 | 本会话公开历史恢复、当前提示去重、执行事实、当前文件重读、重启后续聊 | 能承接前文；跨会话不读取聊天；模型切换和失败后的讨论结果可解释 |
| V04-10C：任务归属与恢复 | 受理即占用、活动快照、停止与中断修复、事件按会话隔离 | 切走后任务仍属于原会话；切回可查看/停止；重启中断不自动执行 |
| V04-10D：草稿与列表 | 草稿持久化和恢复缓存、最近正式会话、改名和排序、逐轮结果、完整浏览器走查 | 草稿不串会话；旧响应不清新输入；刷新恢复；所有入口有真实后端行为 |

各阶段先通过自己的关键失败场景，再进入下一步；最终一起运行相关回归。阶段记录建立 `notes/v04-10-conversation-management.md`，只记本阶段改动、取舍、接口影响与验证；证据放入 `artifacts/`。

## 6. 验收矩阵

| 类别 | 必须验证的行为 |
|---|---|
| 空白临时会话 | 新建不调用创建接口；无输入/仅空白/删光后切走，登记与日志数量不增加；重复新建不堆积条目 |
| 新草稿与首次发送 | 未发送非空文本可恢复且不在正式列表；首次发送只生成一个会话和一轮；受理前拒绝不留空记录；受理后失败保留记录 |
| 去重与磁盘失败 | 首次创建响应丢失、重复点击、同键不同内容、服务重启后重试、初始日志或索引写失败；不得重复执行模型或文件工具 |
| 连续与独立 | A 会话先声明约束再追问，第二轮实际请求包含前文；B 不收到 A 的聊天/草稿；切回 A、刷新和后端重启后仍能续聊 |
| 文件共享与历史 | A 修改作品后 B 能读取新文件；A 继续时读取当前内容；旧工具结果不当作当前原文；当前提示只出现一次 |
| 上下文与失败 | 过去已完成公开回复在后续失败后仍可读；停止/中断/无回复轮次有执行事实；日志损坏不静默清空；超限不暗中裁剪历史 |
| 忙碌与停止 | 同作品两个几乎同时的发送只受理一个；新会话发送遇忙不留空会话；accepted 阶段可停止；其他作品不被全局锁阻塞 |
| 切换与事件 | 运行中切到新会话、其他已有会话或其他作品；旧事件/旧 finally/旧加载响应不污染当前视图；切回恢复任务与停止按钮 |
| 网络与中断 | SSE 断开不宣布任务结束；回读与订阅之间不漏事件；不同工具阶段崩溃均补中断；重复恢复不重复补记或执行 |
| 草稿与恢复 | 各会话草稿独立；保存失败可恢复；旧提交确认不清新输入；pending 首次发送切走后确认不抢焦点；刷新不自动发送 |
| 列表与结果 | 记住最近正式会话；空白新状态不覆盖它；改名不被自动标题覆盖；排序不改变选择；结果属于对应轮次；旧提交撤销仍受 Git 校验 |
| 兼容与接线 | 旧会话可回看和继续；所有新接口有前端调用者；所有旧调用者完成调整；应用状态与凭据不进入作品 Git |
