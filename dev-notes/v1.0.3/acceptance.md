# 1.0.3 验收计划

日期：2026-10-30。状态：**计划**。P0—P7 实施后按本计划执行；未执行与未通过分别记录，历史通过项不自动继承。计划、示例代码和界面样例都不算实现或测试通过。

## 1. 基线与隔离

P0 先记录实际基线，再开始验收：

- 当前分支、代码指纹、主包与前端版本、后端全量测试命令与数量、前端单元／类型／构建命令与结果。
- 当前工作树中与 1.0.3 无关的既有改动，单独记录，不混入本版成果。
- 1.0.2 的输入预算、压缩和真实请求检查实际执行到哪一步；未验收项保留原身份。凡影响本版输入、暂停或生成的，在本版重新检查，不能因为开设新版本改成已通过。
- 空白、未定、多线、纯计划、已有正文、冲突和临时身份的固定 JSON 样例；这些样例是后续接口、工具与页面测试的共同输入。

验证使用隔离作品目录，例如 `data/test-tmp/v103-<场景>-<日期>`。不写入作者作品、`mynotes/` 或项目根 README；不执行旧数据迁移。旧格式或损坏状态必须明确报错，不能当成合法空数据。

成功的一次不能覆盖之前的失败尝试；确定性、浏览器、在线语义和作者体验分别给结论。

## 2. 确定性验收

优先扩展现有测试：`test_story_contracts.py`、`test_story_store.py`、`test_story_joint_commit.py`、`test_story_api.py`、`test_story_tools.py`、`test_story_context.py`、`test_story_review.py`、`test_story_projection.py`、`test_story_index.py`、`test_clue_ledger.py`、`test_clue_views.py`、`test_clues.py`、`test_clue_context.py` 和 `test_story_routing.py`。测试放在真实执行边界，不能只复制校验公式。

| 编号 | 场景 | 必须证明 |
|---|---|---|
| A01 | 阶段契约 | 阶段顺序唯一且非负；摘要 `null` 与空白字符串区分；节点可暂不归阶段，但不能引用不存在的阶段；删除阶段不丢节点，仍被引用时要求同一变更先调整或解除归属 |
| A02 | 推进与阶段 | `next` 无环；已归属不同阶段的两端不能逆阶段推进；同阶段顺序由推进边决定，不按数组顺序；`reframe / answer` 可回指，不改变事件时间，也不被自动当成因果 |
| A03 | 故事线与共同节点 | 一个节点可属于多条线，只保存一份；成员由节点导出；删除线只清成员，不删节点；空线、未分阶段和无线索片段是合法状态 |
| A04 | 线索身份唯一 | 标题与身份只从账本读取；同名不自动合并；只有计划的线索和只有正文贡献的线索都能读取；不在构思里保存第二份标题 |
| A05 | 临时身份解析 | 同一请求可创建身份、写计划并使用；服务端分配稳定 ID 并返回 `id_map`；同键同负载返回原映射，同键异负载冲突；保存结果不残留临时 ID |
| A06 | 计划与实际观察 | `roles` 只描述计划，不能改写正文生命周期；story 范围可见未来计划，chapter 范围按截止位置隐藏；没有正文时计划可见、观察为空，实际状态为未知 |
| A07 | 回收意图一致 | `explain` 至少有一个 `resolve` 使用节点；`leave_open / undecided` 不得带回收作用；删除计划不删除身份与正文贡献；回收位置由使用导出，不另存节点清单 |
| A08 | 引用与删除 | 身份仍被计划、节点使用、正文贡献或撤销目标引用时，删除创建与删除身份都被阻止，并报出具体冲突对象；只删计划或使用关系时不影响身份 |
| A09 | 联合提交 | 结构、账本与必要正文补丁在同一请求中提交；同请求重试只应用一次；在写入各阶段注入失败，重启后按提交决定补完；没有决定时回到原状态，不出现半更新关系 |
| A10 | 锁与独立写入口 | 所有交叉写入口固定「构思 → 账本」锁顺序；只改线索贡献的入口也经过同一协调器；并发结构写入与线索写入不丢失更新、不反向加锁、不以超时掩盖冲突 |
| A11 | 修订与依赖 | `expected_revision`、`expected_ledger_revision` 与读取依赖逐项核对；任一过期冲突都不写入；变体、正文、约定、模块和会话依赖分别验证；停止或暂停后旧代次不能写入 |
| A12 | 撤销 | 反向操作覆盖结构、账本与正文补丁；无关的后继编辑保留；相关对象后来被改或新增引用时冲突；同一变更不能撤销两次；撤销创建身份仍执行删除检查 |
| A13 | 读取范围 | story 范围返回全书身份、计划、使用与观察；`node_id` 只接受当前作品与当前构思中的节点；chapter 范围不扩大截止位置；`as_of_chapter` 只限制观察，不隐藏作者计划 |
| A14 | 组合视图与分页 | 图、列表、详情使用同一结构／账本快照；`view_revision` 覆盖身份标题、计划、使用和观察来源状态；游标绑定筛选与视图修订；内容变化后不能拼出跨修订页 |
| A15 | 缓存、引用与定位 | 任务受理后冻结方案、对象与修订；后续浏览不改受理快照；引用在内容变化后失效并给出冲突；定位不调用模型；快速切作品、重复点击和迟到响应不串数据 |
| A16 | 旧接口与旧参数退出 | 公开读参数不再使用 `group_id`；旧分组请求不改变返回范围；备选、比较、采用、试读、候选正文与独立正文预览接口保持退出；模型不开放对应工具；页面无相关入口 |
| A17 | 错误格式 | 新错误码与 HTTP 状态统一映射；文案符合 `[错误码] 位置：现象。建议：…`；冲突返回具体目标，不把内部异常或堆栈直接交给作者 |
| A18 | 数据格式与损坏 | 当前格式头、字段和索引严格校验；缺字段、未知格式版本或损坏文件明确失败；不把损坏数据读成空作品；不做旧数据迁移，也不自动删除作者文件 |
| A19 | 全量回归与构建 | 后端全量、前端单元、类型检查和生产构建通过；受影响的构思、线索、对话、上下文预算和正文写入测试同步更新；记录精确命令、结果和未执行项 |

新增字段必须从模型、变更应用、存储、工具、接口和测试同时接通。只改接口响应模型、只改前端类型或只写样例都不算完成。

## 3. 页面与浏览器

浏览器测试沿用隔离端口与隔离作品目录，保留上一次构建产物；启动前重新构建。按实际重命名扩展 `story-structure.spec.ts`、`story-overview-removal.spec.ts`、`chapter-clues.spec.ts`、`clue-source-navigation.spec.ts` 和 `clue-reference.spec.ts`。

- **B01 阶段与多线布局**：固定 3 阶段、3 故事线、1 个共同节点的样例，验证阶段纵向推进、线与线横向并列、共同节点只出现一张卡；折叠某阶段后摘要与前后关系仍可理解，展开恢复原节点与边；折叠不补造新关系。
- **B02 节点 → 线索 → 另一节点 → 正文 → 返回**：选中节点查看相关线索，点线索中的使用位置展开目标阶段并定位节点，再打开正文依据；返回时恢复阶段展开、选中对象和视口。全程不调用模型，不把浏览位置写进结构。
- **B03 对话与任务隔离**：节点或线索可带入对话；运行中的任务在作者浏览其他位置时不被改到新位置；切换会话或重载后，结构引用按当前修订恢复或明确提示冲突。
- **B04 画布体验**：双向滚动条、滚轮平移、键盘导航、缩放、查看全貌、恢复 100%、超过 15 个节点的概览；15 个以上节点时仍可读；字体放大后卡片不塌陷；320／390／640／1440 宽度无页面横向溢出，窄屏视图切换保留对象。
- **B05 空白与异常状态**：空白作品显示创建入口；未分阶段节点有明确区域；已删除或被替换的节点在定位时显示事实与处理建议；不显示假结构、假摘要或空工具栏。
- **B06 快速切换与迟到响应**：连续切换作品、重复选择节点、折叠阶段和返回，旧请求不能覆盖新作品；缓存键包含作品、方案、修订与读取范围。
- **B07 作者体验**：在 1440 与 1024 宽度下能读懂三线总览、阶段摘要、节点关键变化和线索计划；选择节点不强制关闭对话；折叠后仍知道当前选中对象；记录截图与作者确认。
- **B08 无副作用读取**：打开、折叠、选择、查看线索和定位正文都不调用模型、不写入状态；只有明确保存动作产生结构或正文提交。

页面与真实后端联调用受控接口测试分别留证，不相互替代。样式通过不等于接口字段正确。

## 4. 在线语义

只使用 `.env` 配置的在线模型，不使用本地模型。每个必测场景先固定样例、断言和证据目录，再发起最少必要的真实请求；基础设施失败可在同一请求键下重试，不用改提示词反复试到通过。所有尝试、失败和模型身份都保留，成功的一次不能覆盖之前的失败。实际命令以实施时的评测脚本为准，以下场景不是可直接执行的现有命令。

- **O01 空白多线生成**：要求建立 2—3 个阶段、3 条故事线、1 个汇合节点和至少 1 条线索计划。核对保存结果确有阶段、各线目标／阻力／计划收束、关键变化、汇合只一张卡、关系理由存在；不是只保存资料模块或一段文字。
- **O02 已有正文归纳**：根据实际章节要求归纳结构。检查正文观察与计划分开，未出现作者真相被写成角色已知，未补造不相连的章节；未分阶段片段允许保留，保存后重读一致。
- **O03 局部修改**：选中一个节点和一条线索要求调整。检查只改相关对象，其他节点、线和线索计划保持；受理时的对象与修订被冻结，浏览其他位置不改变本轮目标。
- **O04 真实写作**：依据当前结构写一段场景。检查必需前提、角色知情、证词性质与正文观察边界；正文实际保存，作者真相没有因为规划存在而进入角色台词；计划修改没有被当成正文已同步。
- **O05 暂停、继续与恢复**：在真实任务中暂停、继续、插话，换会话或重载后读取结构。检查结构持久、没有重复执行、代次隔离生效、任务对象没有被浏览位置重定向；失败或暂停的中间状态可恢复。
- **O06 大结构与输入预算**：使用较大阶段／故事线样例，核对实际请求分区、覆盖和省略对象；容量不足时按阶段或线拆分，明确本轮范围，不静默裁掉后半部结构；沿用 1.0.2 的预算，不新增放宽公式。
- **O07 无效输出与修正**：让模型提交悬空引用、未解析临时身份或与回收意图矛盾的计划。服务端拒绝且不落半份结构；允许一次有边界的修正，仍有缺口时保留问题和未完成状态，不显示成功收据。

在线记录至少包括：模型身份、受理与完成时间、代码指纹、预算配置、实际请求分区、结构／账本修订、请求键、回执、失败原因、耗时和可用量。价格没有可靠来源时不估算金额；不输出密钥、请求头中的凭据或作者隐私内容。

## 5. 证据

真实证据写入 `dev-notes/v1.0.3/artifacts/<场景>/<批次>/`。批次用日期或序号区分，失败尝试单独保留，不覆盖。

```text
artifacts/<场景>/<批次>/
  .last-run.json        测试运行的原始结果
  run.json              日期、代码指纹、版本、命令、模型、预算与结论
  requests/             脱敏后的实际请求分区
  responses/            脱敏后的关键响应
  receipts/             提交回执、修订与撤销记录
  screenshots/          布局、折叠、定位与返回截图
  trace.zip             浏览器或在线流程的跟踪
```

`run.json` 不写 API 密钥，不写作者作品全文；路径使用隔离目录，不暴露用户主目录。测试数量、耗时和用量按当次实际结果填写，不预填、不复制历史批次。每次失败的注入点、外部修改或模型缺口一并记录，注明是否重试以及重试是否使用同一请求键。

## 6. 发布门槛

全部满足才进入 P7 的版本更新：

1. A01—A19 通过；受影响的完整后端回归、前端单元、类型检查和生产构建通过。
2. B01—B08 通过，关键流程有截图或跟踪；作者确认能读懂多线总览、阶段折叠和双向定位，且没有被强制中断对话。
3. O01—O07 的关键链路有真实证据；严重的一致性、信息边界或静默丢结构问题为零。未执行和未通过分别列出，不能互相抵消。
4. 1.0.2 承接的输入预算与暂停恢复事项已检查；影响本版的部分不能以「上一版本已通过」代替。
5. 页面、接口、工具和字段样例一致；旧参数与旧接口无残留调用；文档链接有效。

通过后统一更新 `pyproject.toml`、`uv.lock`、`frontend/package.json`、`frontend/package-lock.json` 的本项目版本，核对实际构建与界面版本，再同步开发入口、产品方案和验收状态。未通过时保持当前版本显示，记录未完成项和阻塞原因，不创建发布标签。

不修改项目根 README，不修改 `mynotes/`，不自动删除作者作品，不做旧数据迁移。作者体验与模型语义判断分别记录；结构校验通过不能替代叙事判断，界面样例也不能替代真实生成。

## 7. 记录方式

每个场景至少留下以下字段，便于之后区分「没执行」和「执行过但有缺口」：

| 字段 | 内容 |
|---|---|
| 场景／批次 | 例如 `story-multiline-20261030/attempt-1` |
| 代码与版本 | 分支、代码指纹、主包与前端版本 |
| 环境 | 隔离作品路径、命令、模型身份、预算配置 |
| 结果 | 通过、失败或未执行；失败注入点与重试情况 |
| 证据 | 请求、响应、回执、截图、跟踪的实际文件 |
| 结论 | 结构、叙事判断和作者体验分别说明 |

实施记录写在 `dev-notes/v1.0.3/notes/Px-主题.md`；没有实际执行时不创建空通过记录。
