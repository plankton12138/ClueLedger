# 构思入口、画布密度与回合上限：调查及改进方案

日期：2026-10-31。调查时状态：**调查完成，改进待实施**。后续代码与验证见[实施记录](2026-10-31-story-followup-implementation.md)；以下保留调查时的事实与方案。运行版本仍为 1.0.3。本次没有修改应用代码、真实作品、模块或任务草稿，没有执行新在线调用或后端全量测试。

## 1. 结论与目标

本次有三个相互关联的问题：普通对话的成果类型取决于构思面是否打开；分批草稿缺少受应用控制的阶段和修复规则；画布虽然避免了遮挡，却没有实现预览中的紧凑行列版式。不能仅靠改提示词、增加回合数或缩小间距解决。

作者说“根据现有模块生成构思”，无论在哪个面板发送，都应建立可进入构思图、可定位和修改的故事结构。资料模块是输入来源，只有作者明确要求保存模块时才成为写入目标。复杂任务应能保留有效草稿并继续，不能在读取、准备和纠错耗尽预算后丢失处理入口。

**可以实现附件中的版式与密度。** 应采用“左侧阶段标记、顶部故事线、紧凑对齐的卡片行、跨列汇合卡片”。实际故事有五条线时保留五条线，通过滚动或筛选查看；不为模仿三列示例删除或合并真实故事线。

证据见 [evidence.json](../artifacts/story-entry-layout-turn-budget-20261031/evidence.json)；[附件预览](../artifacts/story-entry-layout-turn-budget-20261031/reference-preview.png)是设计目标，不是本轮运行截图。原始工具参数只保留本机索引，没有复制整份作品或模型思考内容。

### 2.1 普通对话没有进入成果判定

代码链路明确：

- `frontend/src/state/conversations.ts:665–689` 仅在构思面打开或带有结构引用时注入构思上下文；正文面上的相同要求可以不带此上下文。
- `service.py:2128–2156` 的 `_task_intent` 在 `story is None` 时直接返回 None，未对这句明确的构思创建要求判定成果类型。
- `agent.py:3118` 只有存在 `run.story` 才提供结构工具；`:3150` 只有存在任务目标且不允许模块写入时，才移除模块内容工具。
- 本次普通对话既没有结构工具，也没有模块成果限制。模型随后登记模块写入范围，准备和应用了三份新模块；应用没有以作者要求的结构成果拒绝这条路径。

上次修复了“已有构思上下文内，来源模块被误判为模块目标”的分类问题，但没有覆盖上下文本身缺失的普通对话入口。同一句话不应由面板开关决定成果类型。此次没有证据表明是作者表达不清，也无需让作者每次额外补“不要生成模块”。

### 2.3 草稿流程仍存在四处缺口

**第一，准备阶段过早返回最终一致性错误。** `story_tools.py:619–649` 每次先保存草稿，再对整份候选执行 `check_candidate`。仅有线索计划、还在补节点时，就返回 `STORY_GRAPH_INVALID`，并在后续几乎每批重复。第 9 回合返回 19 条缺少回收的线索问题和一条重复的整体异常；没有“本阶段允许待补”和“必须立即修正”的分级。

**第二，模型实际收不到字段问题列表。** 应用把 `issues` 放在 `WorkspaceError.details`，但 `tau_agent/loop.py:360–367` 把异常转为 `str(exc)`，返回 `details={}`。原始两次失败详情也只有“草稿字段校验未通过。建议：按问题列表局部修正”，没有列表。使用真实工具执行边界做内存复现，结果一致。仅测试直接捕获异常里的 `details`，不能证明模型已收到结构化诊断。

另有定位缺口：追加批次的错误路径使用合并后全局索引，错误对象提取却在当前批次中查找；例如全局 47 项对应本批 0 项，容易丢掉目标 ID。应同时记录批内位置和稳定对象 ID，不让模型自行换算。

**第三，局部修正依赖可猜错的数组索引。** `story_drafts.py:181–227` 不验证替换项与原项的对象种类和 ID 相同。把线索创建替换成节点创建在字段层合法，随后可保存；整图重复节点要到后续 `candidate_data` 才发现。代码顺序是先写草稿，再报告候选问题。内存复现也确认：两个同 ID 的 `add_node` 能通过操作 schema，候选应用时才拒绝。

**第四，预算耗尽后没有草稿继续入口。** 操作落为 failed；`operations.py:54–57,192` 的继续能力不包含 failed，`StoryDraft.tsx:22` 也不读取 failed 任务的草稿。实际操作虽然 `resumable=true`，但该状态下继续能力仍为假。`pending_units` 为空，没有可恢复阶段和待办对象清单。现有草稿文件并未丢失，界面没有将其作为可处理结果展示。

## 3. 为什么画布达不到预览效果

当前实现解决了节点重叠，但它的排版规则与附件不同：

| 预览中的结构 | 当前实现与影响 |
|---|---|
| 阶段放在左侧，不占用一整行摘要 | 摘要在卡片前独占高度，文字越长，后续空白越大 |
| 列间紧凑、宽度随可用区域分配 | 普通卡固定 280，列间距 64，起点固定 x=200，未按画布可用宽度计算 |
| 同一推进层次的卡片横向对齐 | 有故事线时按每列已有高度分别摆放；卡片高度不同会产生参差与空洞 |
| 汇合卡片跨越参与列 | 当前只把普通宽度卡片放在参与列中间，宽度仍为 280 |
| 一段内容只计算一次底部间距 | 节点尾部 64、阶段尾部 48、下一阶段摘要高度及其后 32 连续叠加 |

依据 `storyLayout.ts:20–36,59–71`，相邻阶段卡片净距为 `64 + 48 + 下一阶段摘要高度 + 32`。用三条线、三行转折加一行汇合的合成样例重放，假定卡片 280×112、摘要高 120，结果如下：

- 三列左边界为 200、544、888，列间净距 64。
- 四行卡片顶部为 276、652、1028、1404，相邻卡片净距均为 **264**。
- 三列整体跨度 968，汇合卡片仍为 280，右边界达到 1168。

这是纯布局函数重放，不是浏览器实测，也不是最新失败草稿的截图。最新作品没有正式构思可供量测。附件是设计示例，能够确定目标版式；本次不能据此声称已实测作者当前画布的每处距离。

上次几何测试检查了不相交、节点数量和页面不溢出，没有限制最大间距、默认可读缩放、行对齐或跨列卡片宽度。再大的空白也能通过原测试。

## 4. 改进方案

### A. 在受理请求时统一确定成果类型

将成果判定移到普通聊天、构思页、创建按钮共用的受理层，先读取作者原话，再冻结对应目标。明确的“根据现有模块生成构思”应自动解析为当前作品的结构创建，即使尚无构思、正文面打开，也能得到 empty 主构思身份。

```python
goal = resolve_goal(author_text, explicit_action, current_workspace)
# 成果与资料来源独立；资料内容不参与授予写权限。
target = freeze_target(goal, current_workspace)
tools = tools_for(goal, target)
require_write_family(goal, requested_mutation)
```

结构任务保留资料读取，关闭模块新建、发布和应用能力；工具注册和实际提交两处都检查成果类型。完成判断必须看到结构收据或有依据的无需改动记录。未知目标先讨论或提问，不能默认允许模型自行选模块作为交付物。

结构引用继续只提供对象范围与来源版本，不再用面板是否打开或引用的 `purpose=write` 代替成果判定。明确保存模块、混合成果和只讨论仍按作者原话分别处理。

### B. 把分批草稿变成应用控制的阶段流程

应用维护“来源覆盖 → 多线骨架 → 线索及知情细化 → 完整检查 → 提交”的阶段、待办和修订。骨架应先有节点与真实依赖，避免先录完整线索表，再靠缺回收错误逐个补事件。节点以关键变化组织，章纲作为参考或细节，不直接把每章机械变成一张总览卡片。

批次按阶段或故事线组织，并按预计输出长度控制大小；不统一要求每批 12 项。简单身份可成批准备，长节点需要较小批次。作者不必确认每一步，核心故事决定或来源授权缺失时再集中询问。

准备时分类返回：

- `blocking_issues`：字段错误、重复 ID、修正目标不符、循环等必须立即修复。
- `pending_dependencies`：本阶段尚未准备的合法引用，绑定具体待办对象。
- `deferred_checks`：解释计划等待回收节点等最终检查，进入完整检查阶段再阻止提交。

正式提交仍执行全部引用、线索生命周期和授权规则，不放宽真相、结局与必需约定。模型反馈以本批新增／消除问题为主，完整问题清单按目标查询，不每批重发整图异常。

### C. 稳定对象修正与真实错误反馈

局部修正改为按对象种类和 ID 定位，数组索引仅留作内部日志。短期兼容索引时也必须携带原对象身份并核对，例如：

```json
{
  "target": {"kind": "node", "id": "node-after-accident"},
  "expected_revision": "对象修订",
  "patch": {"stage_id": "stage-clear"}
}
```

禁止把线索创建改成节点创建。先在内存应用修改并检查本阶段硬约束，再原子保存新草稿；错误修正保留前一份有效草稿及新诊断，不覆盖有效版本。最终仍通过现有联合提交生成正式结构和线索收据。

错误内容必须实际进入模型可见的工具返回，不能只留在异常 `details`：

```json
{
  "ok": false,
  "code": "STORY_CHANGE_INVALID",
  "issues": [{
    "batch_index": 0,
    "operation_index": 47,
    "target": {"kind": "node", "id": "node-example"},
    "field": "node",
    "message": "缺少节点对象，节点字段出现在操作外层",
    "suggestion": "将 id、title、action 等节点字段放入 node 对象"
  }]
}
```

应用层可利用现有 `after_tool_call` 扩展点，把应用侧保存的诊断写入返回 `content`，同时保留失败标记和机器字段；不必修改通用 Agent 循环。HTTP、模型内容和活动详情复用同一诊断，作者默认只看简短现象与建议。验收要穿过实际工具执行边界，而非只检查 Python 异常对象。

### D. 预算管理和可恢复停止

回合上限保留为保护，增加任务规模估算、阶段预算和提交／收尾预留。每批返回剩余阶段和预算，让模型知道该继续准备还是进入核对。临近上限时，应用保存阶段检查点并停止新增工作，避免最后几轮只剩翻页找索引。

有可恢复草稿的预算终止应落为 `needs_attention`，说明“来源已读取、骨架完成多少、待补哪些关系、正式提交是否发生”，提供“查看草稿／继续任务”。真正的不可恢复失败继续保留 failed。失败状态中已有草稿也应可只读查看，不能隐藏。

继续必须绑定任务、草稿、基础修订和冻结资料版本，保留原权限与联合提交边界。既有总预算、时间／容量约束仍有效，不通过无限新代次规避限制。扩大单轮预算可作为修复后的容量配置，不能替代阶段管理、局部修正和诊断修复。

建议文案：`[TURN_LIMIT_REACHED] 构思生成：本次执行预算已用完，草稿已保留，尚未正式提交。建议：查看待补安排后继续此任务。` 其中是否已提交必须取实际收据，不能固定写“若已保存”。

### E. 按附件实现紧凑行列布局

保留现有画布、滚动、选择和定位能力，替换排布规则：

1. 左侧设置约 88—112 逻辑像素的阶段区域；摘要默认收进阶段详情或折叠摘要，不在每个阶段上方插入整块长文。
2. 普通卡片宽度按可用画布计算，建议起始范围 240—380；列间距 16—24、行间距 28—40。以上是拟议初值，须用真实文字和字号复验。
3. 同阶段先按真实推进依赖形成显示行，各列同一显示行对齐，以该行最大卡片高度推进。显示行用于排版，不新增事件先后或因果关系。
4. 每段只登记一次尾部间距；只在有真实内容时占位。测量实际卡片高度，长文字进入详情，字号放大仍不遮挡。
5. 汇合节点只有一份，宽度覆盖参与列范围，必要时覆盖全列；中间列的卡片也必须纳入占位。跨列节点尺寸不参与普通列宽的最大值计算。
6. 列头、阶段标记、正文节点和走线分别保留自己的区域。初次视口按实际画布宽度定位；重排保留选中节点和相邻上下文。

例如画布宽 1014、阶段区域 96、外边距合计 32、列间距 20 时，三列各宽 `(1014-96-32-2×20)/3 = 282`，无需缩小正文就能显示三列。更多故事线保留横向滚动；窄屏和大字号按可读尺寸展示，不强行把全部卡片缩到很小。

附件是这次版式验收的基准：检查阶段在左、卡片行对齐、间距紧凑、汇合跨列和下方详情；颜色沿用产品主题。不同内容的文本高度可以变化，不能以“完全复用演示内容”代替真实作品验证。

## 5. 实施顺序与验收

| 顺序 | 交付内容 | 通过条件 |
|---|---|---|
| S1 | 普通对话成果路由与写入边界 | 原句从正文面、构思面、结构引用和创建表单发送，都产生结构成果；非模块目标时模块库与装配无新增 |
| S2 | 错误桥接、对象定位、草稿事务 | 两次真实字段失败实际返回可读问题；错对象替换立即拒绝，草稿摘要不变；模型不必翻页猜索引 |
| S3 | 应用阶段调度与预算恢复 | 本次规模能完成骨架、关系、核对与一次正式提交；临近预算上限有检查点，可恢复而不重复写入 |
| S4 | 紧凑版式 | 按附件同类结构检查默认缩放下的行距、列距、左阶段与跨列汇合，保留长文／大字号的不遮挡 |
