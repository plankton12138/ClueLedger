## 2. 当前写入口

P2 的联合提交必须覆盖以下入口，不能让独立入口绕过同一锁顺序和恢复边界：

| 入口 | 位置 | 现状 |
|---|---|---|
| 界面确定性变更 | `POST /api/file-workspaces/{id}/story/changes` | 只写构思与正文补丁，未覆盖线索账本 |
| 模型结构变更 | `update_story` → `StoryStore.commit_change` | 带代次与对象授权；仍只写构思 |
| 撤销 | `POST /story/changes/{change_id}/undo` | 反向操作只覆盖构思与正文 |
| 新建线索身份 | `POST /api/file-workspaces/{id}/clues` | 直接写账本，尚未与构思计划联合 |
| 章节线索整理 | `ClueLedgerStore.publish` | 直接写账本贡献与覆盖 |
| 创建／继续／插话 | 现有会话与统一操作接口 | 受理时冻结 `StoryContextSnapshot`，提交走 `StoryStore` |

当前 `group_id` 仍出现在节点、图读取参数和前端分组状态中；线索标题、作者真相与回收意图仍保存在构思 `StoryVariant.clues`，账本另有身份与贡献。两项都是 P1—P3 要收敛的重复来源。

## 3. 当前读入口

| 入口 | 现状 | 本版要求 |
|---|---|---|
| `GET /story/variants`、`GET /story/variants/{id}` | 只返回主方案；可按 `group_id` 折叠片段 | 返回阶段、完整故事线目标、宏观节点与关系；移除分组读参数 |
| `GET /story/nodes/{node_id}` | 节点安排、当前线索内容、知情与正文关联 | 补阶段、关键变化、统一线索摘要与正文入口 |
| `GET /clues`、`GET /clues/{id}` | 只按章界读取身份、贡献与观察 | 增加 `scope=story`，读取全书计划与使用，同时保留章界 |
| `read_story` | 无选中节点时主要列前 40 个标题 | 读取阶段、线目标、节点、计划、关系理由与覆盖 |
| 上下文装配 | 按节点装配计划、真相、前提、约束、知情、正文观察与证词 | 增加宏观阶段与线目标；容量不足时拆分并报告覆盖 |
| 正文定位 | 现有文件读取、原文定位与返回 | 继续复用，不新增资料系统 |

所有读取都不调用模型。跨构思与账本的组合读取需要同一快照；当前 `ClueReader` 每次自行读取账本，P3 需要支持传入已读快照。

## 5. 固定样例

P1 在 `tests/fixtures/story/v103/` 建立本版样例，并在模型、变更应用、存储、接口、工具和前端类型之间共用。至少包括：

| 样例 | 用途 |
|---|---|
| `blank-multiline.json` | 空白作品建立 2—3 个阶段、3 条线、1 个汇合节点和 1 条线索计划 |
| `existing-prose.json` | 已有正文归纳出的观察与计划分开保存；含未分阶段片段 |
| `undecided.json` | 目标、真相、计划收束为空；只有片段也能保存 |
| `temp-identity.json` | 同一请求创建身份、计划、节点使用；回执含 `id_map` |
| `conflict.json` | 结构／账本修订过期、外部正文修改、撤销目标已变化 |
| `group-migration-absent.json` | 旧 `group_id` 不再作为读参数或节点字段生效 |

现有 `blank-mystery.json`、`flashback.json`、`testimony.json`、`long-distance.json` 在 P1 更新为当前格式，继续承担时间、证词、长距离线索和循环校验；不在旧格式上做兼容迁移。
