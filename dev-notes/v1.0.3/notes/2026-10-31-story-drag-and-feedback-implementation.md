## 设计与当前行为

构思图的位置表示故事线、阶段与推进关系，不作为独立可编辑坐标。关闭所有单卡鼠标拖动和键盘移动，保留画布平移、滚动、缩放、节点选择、详情和反向定位。主要故事线、阶段和顺序仍通过结构修改后自动重排，没有新增手动调整归属或坐标保存接口。

禁用拖动后，底层组件也会关闭不可选择节点的指针响应。首次浏览器回归发现详情点击被阻断，随后为卡片和可展开的列头明确保留鼠标响应；卡片禁止触发整图拖动，空白区域继续平移。最终浏览器整组复验通过，初次失败证据保留。

模型执行反馈与作者摘要由同一应用层处理，但各自保留所需内容：

- 结构任务工具反馈为单份 JSON，保留原结果和 `execution_budget`，不再将多个 JSON 或纯文本直接拼接。失败仍保持 `is_error`；非文本内容保留。
- 结构工具异常提供 `ok`、`code`、`summary` 及问题列表。通用工具边界仍拒绝未知调用，应用补充有效工具清单和恢复指引，不自动别名映射或猜测写入参数。
- 工具事件 `summary` 使用独立作者摘要；预算、字段问题列表保留在完整结果详情和模型输入中，默认红色摘要不显示它们。前端沿用同一事件字段，无需新建接口或在页面解析 JSON。
- `draft_revision` 明确是参数。提示补充最小追加与整体提交样例，说明节点字段必须在 `node` 内。
- 来源授权暂停改为依据结构化错误码判断，预算暂停和现有回合上限继续保留。

未知工具的作者摘要示例：

```text
[TOOL_NOT_FOUND] 构思生成：调用的工具 draft_revision 不存在。建议：使用 read_story 读取草稿版本，将 draft_revision 作为 update_story 的参数提交。
```

这使无效调用能够得到准确指引，不承诺模型永远不会再产生无效调用。

## 追加批次诊断

校验合并后的完整操作列表时，直接用完整列表提取对象身份，再根据追加起点计算 `batch_index`。错误同时包含 `operation_index`（全局）、`batch_index`（本批）与 `object_id`；也支持缺失操作包装时从裸对象提取 ID。替换操作仍保留原全局位置，原子保存之前拒绝无效变更。

专项用例验证：已有 1 项有效草稿，追加的第 0 项无效，返回全局索引 1、批内索引 0、对象 ID n2；有效草稿摘要保持不变。字段错误和未知工具均穿过实际执行、工具事件与下一次模型输入验证。
