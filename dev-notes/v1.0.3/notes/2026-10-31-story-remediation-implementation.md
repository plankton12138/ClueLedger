# 构思多线、布局与提交改造记录

日期：2026-10-31。运行版本保持 1.0.3。状态：**代码已接入，针对性验收通过**；未据此宣布新版发布。

## 设计与实际改动

构思应说明各条线怎样各自推进、相互影响并共同收束。节点涉及多条线，并不意味着它就是汇合；事件发生在后面，也不意味着它由前一件事推动。此次把这两组区别落实到数据、画布和生成流程中。

| 范围 | 当前实现 |
|---|---|
| 节点职责 | 新增 `primary_thread_id`、`is_convergence`、`reveal_order`；主要归属必须属于 `thread_ids`，汇合至少涉及两线 |
| 画布 | 按故事线固定列、按阶段纵向排列；测量阶段摘要、列头和卡片后预留空间；共同节点只有一个，公共行预留所有列 |
| 卡片与导航 | 总览优先显示关键变化，行动留在详情；详情中的相邻节点可直接定位；目标阶段展开后再定位 |
| 阶段折叠 | 隐藏内部节点，既有跨阶段关系映射到阶段摘要；保留关系 ID 和理由，不添加故事关系 |
| 读写契约 | HTTP 节点统一使用 `thread_ids / clue_ids`；模型读取完整节点、知情变化、线索使用和边理由；概览说明覆盖范围，支持精确节点读取 |
| 任务草稿 | `prepare` 分批增量准备，按原始操作索引局部替换，正式构思与线索账本在完整 `commit` 时联合保存 |
| 报错 | 非法 JSON 单独报告语法位置；字段校验返回最多 20 项问题；线索计划冲突指出具体线索与回收节点 |
| 知情 | 区分现场观察与推断；同场观察允许自身来源，推断依赖明确的实际事件先后；上下文与写作核对按生效事件消费，不按承载节点或揭示先后消费 |
| 模块约定 | 来源精确绑定库、模块、版本、条目和摘要；作者在界面核对原文与作用范围后集中确认，已确认来源可以保留原强度继承 |
| 任务完成 | 未提交草稿或多线结构缺项返回待处理；保存收据与语义完成分开；来源模块不再被误判为额外的模块保存任务 |

未分线的单线与真实分叉继续合法。布局没有补造关系；结构诊断报告缺项和单链事实，不把线数当成文学质量。未明确归属的多线片段保留在未归属区域。

## 模型工具的实际用法

```json
{
  "mode": "prepare",
  "operations": [
    {"op": "add_thread", "thread": {"id": "detective", "title": "侦探", "order": 0}},
    {"op": "add_node", "node": {
      "id": "record", "title": "查到记录被改", "action": "核对值班表",
      "change": "调查转向调度权限", "thread_ids": ["detective"],
      "primary_thread_id": "detective", "reveal_order": 0
    }}
  ]
}
```

后续批次携带返回的 `draft_revision`。修正现有项时发送 `replace_operations: [{"index": 1, "operation": {...}}]`，不必重发整份构思。准备阶段允许暂缺引用和回收位置；字段类型仍必须合法。`read_story(source="draft", operation_start=0)` 分页返回操作及原始索引，指定 `node_ids` 可读完整候选节点；覆盖标记区分全部结构与局部读取。

```json
{"mode": "commit", "draft_revision": "准备阶段返回的精确摘要"}
```

最终提交必须满足全部引用、线索生命周期和授权规则，复用既有联合事务与撤销。草稿冻结基础修订、任务身份与模块版本；暂停后不能写入，新代次可恢复同一任务草稿，正式结构变化则返回冲突。相同草稿重复提交返回原收据；正式写入后、草稿标记完成前发生中断时，依据已保存变更恢复回执，服务端按变更 ID 去重统计。

## 约定确认的边界

普通模块尚无可直接信任的“作者已确认约定”字段。此次没有将“模块含必须字样”或模型自报来源当作授权，改为作品级确认记录。

1. 模型准备必需约定，逐字引用来源内容，填写 `source_ref`。
2. 未确认时保持 `required`，正式提交拒绝并保留草稿。构思页显示原文、强度、作用范围及来源引用。
3. 作者点击“确认这些必需约定并继续”，应用核验草稿摘要、基础修订、任务状态和冻结模块版本，记录准确来源并继续任务。
4. 后续工具读取可取得 `confirmed_module_constraints`；相同来源、内容、范围和强度才允许继承，来源记为 `author_module`。

接口为 `GET /story/drafts/{operation_id}` 与 `POST /story/drafts/{operation_id}/confirm-constraints`，后者只记录作者确认，不直接提交故事。普通模型文件工具没有确认记录的写入入口。已有必需约定的修改保护保持有效，草稿局部修正也禁止降级或移除必需约定，禁止移动同一知情内容的生效事件或翻转已确定的解释／开放计划。改变这些创作决定应由作者另行提出，不能作为格式修正混入。
