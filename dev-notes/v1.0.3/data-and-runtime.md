# 1.0.3 数据与提交契约

更新：2026-10-31。阶段、故事线及联合提交已有实现；本轮补入节点职责、任务草稿、实际事件知情与模块约定确认。实际改动和验收边界见[改造记录](notes/2026-10-31-story-remediation-implementation.md)。下文保留完整目标契约，未覆盖项不据文档视为已通过。

## 1. 结构对象

| 对象 | 字段与职责 |
|---|---|
| `StoryStage` | `id`、`title`、`order`、可空 `summary`；阶段按揭示顺序组织，摘要用于折叠 |
| `StoryThread` | 现有 `id`、`title`，新增 `order`、可空 `goal`、`obstacle`、`intended_resolution` |
| `StoryNode` | 保留 `id`、`title`、`action`、`thread_ids`、`clue_uses`、时间与知情；新增可空 `change`，`stage_id` 替代 `group_id` |
| `StoryEdge` | 保留 `next / reframe / answer` 和 `reason`；顺序不自动等于因果成立 |
| `ProseBinding` | 保留节点／可选线索与正文区间关联；一个节点和多章、多节点和一章均合法 |

阶段、故事线顺序分别唯一且非负，ID 与索引一致。节点可以暂时 `stage_id=null`，显示于“未分阶段”区域，避免只有片段时被迫补全故事；未定目标和变化保存 null，不用空字符串代表否定事实。

`thread_ids` 表达涉及的故事线，`primary_thread_id` 表达主要推进的线且必须属于前者；只有 `is_convergence=true` 才表示多线成果在此共同作用，至少涉及两线。`reveal_order` 可空，表示阶段内展示顺序，不产生因果边。成员只由节点持有，不在线对象中重复存节点清单。无故事线归属的片段允许暂存，在公共区域显示；完成明确的多线任务时由叙事核对报告尚未归属的安排。

`next` 仍须无环；已归属不同阶段的两端不能逆阶段推进。同阶段顺序由推进边决定，不按数组顺序猜测。`reframe / answer` 可按现有约定回指，不能改变实际事件时间。重新排序阶段时在一个变更内处理受影响关系，最终整体校验。

新增 `add_stage / update_stage / remove_stage`。删除阶段时，在同次变更中重新分配或解除节点归属；不能丢弃节点。移除 `group_id` 的页面与公开读参数，执行任务的分批继续维持原职责。

## 2. 线索的唯一身份与内容归属

| 所在位置 | 保存内容 | 不承担的内容 |
|---|---|---|
| 账本 `ClueIdentity` | `clue_id`、标题、身份修订与创建记录 | 不记录凭空产生的正文埋设与回收 |
| 构思 `clue_plans: dict[clue_id, StoryCluePlan]` | `clue_id`、`author_truth`、`intention`、`resolution_intent` | 不复制线索标题，不保存第二套正文引文 |
| 节点 `clue_uses` | `clue_id`、`roles`、`presentation`、`mode`、`speaker_id`、`expected_interpretation` | 角色说法不自动成为真相或实际正文事实 |
| 账本 `ClueContribution` | 现有实际引文、来源、性质、提及／埋设／回收 | 不因为安排写好就形成正文贡献 |
| 组合详情 | 只读身份、计划、使用过程和实际依据 | 不另存一份可编辑内容 |

`StoryCluePlan` 替代现有构思 `Clue` 的内容所有权；所有消费者要从组合读取层取得标题，不能继续从旧字典读取。正文中新发现的线索可以只有身份和贡献，尚无计划；纯构思线索可以只有身份和计划，尚无贡献。

`roles` 可取 `plant / develop / misdirect / reinterpret / resolve`，一次使用允许多个作用，禁止重复；尚未决定作用时可为空。该分类只描述计划。实际引文的 `plant / mention / resolve` 仍使用账本记录，不由 `roles` 推算。

`resolution_intent` 沿用 `explain / leave_open / undecided`。计划回收节点从同一线索中具有 `resolve` 作用的节点导出，不另存 `node_ids` 清单。明确 explain 时应有对应安排；其余状态与回收作用不能互相矛盾，提交时整体检查。

作者真相可为 null；非空时必须是非空白文本。所有保存的线索引用必须存在于同一作品账本，不按标题或相似度自动合并。

## 3. 新身份与变更操作

公共变更列表扩展 `create_clue_identity`、`rename_clue_identity`、`remove_clue_identity` 与 `upsert_clue_plan / remove_clue_plan`。创建使用请求内 `temp_id` 和标题，服务端分配稳定 ID，再解析本次节点和计划中的临时引用。

请求内映射在准备阶段完成并进入待提交记录；发布后的回执返回 `id_map`。先查请求回执再检查当前修订，同请求同负载返回原结果，同请求不同负载返回冲突。未决定的准备被放弃后，不把临时 ID 当作已发布身份。

已有 `add_clue / update_clue / remove_clue` 在本版当前格式中由上述明确操作替换，不保留两套内容写入逻辑。所有模型工具示例、鉴权、对象摘要与反向操作同时更新。

只删除计划或使用关系，不删除身份及正文贡献。删除身份要求最终状态中不存在计划、节点使用、正文贡献或其他有效引用；撤销创建身份也执行同样的检查。引用仍存在时报具体冲突。

## 4. 修订与缓存

- `story_revision` 继续覆盖阶段、线目标、节点、计划和关系。
- `ledger_revision` 覆盖身份和正文贡献；纯计划修改不虚构正文变化。
- `plan_revision` 从当前线索计划和使用关系的规范化内容导出。
- `view_revision` 包含身份、相关计划、观察及来源状态，不能只依赖账本版本。
- 模型上下文和引用冻结相关结构／账本修订。新增账本读取依赖，检查实际用到的内容是否仍有效。

跨文件组合读取要在恢复之后获得一致快照；可采用同一协调锁，或读取后复核所有参与修订并在变化时重读。不能以两个独立 GET 各自成功作为联合一致性的证明。

## 5. 联合提交与恢复

现有机制能协调构思和正文，本版扩展为受限的结构、账本与必要正文补丁；不能把它扩大成任意路径写入器。建议新增 `workspace/story_clue_commit.py` 管理相关准备和恢复职责，复用现有原子文件和提交决定机制。

一次写入执行：

1. 查询同请求回执，取得所需锁并恢复未完成的已决定提交。
2. 校验受理对象、任务代次和相关修订，读取工作副本。
3. 分配新身份、解析临时引用，应用全部变更，验证最终状态。
4. 准备每个目标的前摘要、后摘要、前后内容与反向操作，记录待提交内容。
5. 在现有任务提交资格保护下复核依赖，持久化覆盖全部目标的提交决定。
6. 发布所有已决定目标，写修订与回执，然后清理待提交记录。

记录失败或发布失败必须保留可恢复信息。无决定的准备可以舍弃；有决定则按预期摘要补完；外部文件既不等于预期前状态也不等于目标状态时报告冲突，不覆盖外部修改。

结构、账本及独立线索贡献写入遵守统一的锁顺序和恢复入口。具体锁集合在 P0/P2 根据现有任务保护和文件锁确定并写入实施记录；必须覆盖所有交叉写入口，不允许两种相反的加锁顺序。

## 6. 撤销与影响

撤销记录包含所有相关对象与必要正文补丁的反向操作。执行前检查这些对象及其引用是否仍处于原提交之后的预期状态。无关修改保留；后来修改了相关计划、正文或新增了对身份的引用则报告冲突。

影响范围由实际改动的对象、线索使用和正文关联导出。结构变化意味着相关核对需要更新，是否已经造成正文矛盾应由原文核对说明。删除或移动使用位置时同步更新导出的使用过程，不用异步复制去维持两份清单。

## 7. 模型任务与格式

延用现有统一操作、流式、暂停、继续、插话与代次控制。浏览状态独立；受理时固定本轮节点、线索、目的、结构和账本依赖。继续时按现有规则恢复任务并校验，不静默改到作者刚浏览的位置。

作者计划可以包含未来安排，`reader_seen` 只能包含截止位置内有效正文。过期引文、证词性质和作者真相继续分别表达。

数据格式版本与产品版本分别管理。P1 明确当前格式头与完整字段，不做迁移；遇到损坏当前格式仍报错，不能当作合法空数据。验证和开发使用隔离状态目录，不自动删除作者作品。

### 2026-10-31 草稿保存与恢复规则

任务草稿以任务 ID 与方案 ID 定位，冻结基础修订、来源模块版本、任务代次与操作摘要。准备先在内存应用候选，再原子保存；字段错误、重复对象或替换目标不匹配时保留上一份草稿。替换必须保持对象种类和 ID，节点局部补丁按稳定 ID 查找后仍走同一保护，不能绕过约定强度、知情时点或解释计划保护。

分批准备的最终依赖检查不等于正式提交；未补齐安排可以存为草稿。提交仍整体检查结构、线索、授权与冻结来源，并生成一次联合回执。来源约定确认取最终候选的有效约定，不直接遍历历史 add 操作。

预算按本代实际模型请求计数，结构准备进入最后 3 回合时保留草稿并可恢复停止，作者继续后使用同一任务与现有草稿。应用不自动无限继续，不扩大原回合上限。当前已有下一步建议及恢复检查点，完整规模估算与持久化多阶段调度仍属规划，见[后续实施记录](notes/2026-10-31-story-followup-implementation.md)。
