# V06-F 活动记录

## 目标与实际交付

将「改动与历史」扩展为活动记录，保留文件版本操作，并使用户与开发者能查询模型任务的实际
执行过程。原型参考 `prototypes/dark/p5-agent-events.png`，沿用现有产品配色。

- 事件流大面板：会话和任务分组、作品级查询、类型/结果/时间/关键词过滤、详情、跳转、导出。
- 会话日志继续作为原始事实，作品操作有独立 JSONL，查询索引按偏移生成且可重建。
- 持续订阅跨轮次运行，游标去重、有限重连、历史分页与有界显示；停止、失败与中断保留记录。
- 模型实际请求、工具详情、文件变化、状态发布与 Git 结果相互关联。
- 可选输入快照、详情保留和清理、凭据字段处理、包含附件的导出。

当前接口、存储和边界见[活动记录模块](../modules/activity-log.md)，不以本记录代替现状说明。

## 实现位置

`workspace/activity.py` 提供索引、筛选、导出、操作日志、附件与设置；`model_activity.py` 包装
应用层 provider 记录实际请求；`service.py` 关联模型、工具与版本，`agent.py` 在实际写入与状态
发布成功后记录结果。`api.py` 增加活动接口并接入导入和版本操作。

前端 `api/activity.ts` 提供分页与持续订阅，`ActivityPanel.tsx` 提供活动面板；原版本组件支持
嵌入，原聊天事件归并仍沿用。客户端事件类型同步补齐，旧会话没有的新字段保持可读。

## 验证与修正

原有相关定向回归首次 100 项通过。新增后端回归覆盖跨会话顺序、游标分页与去重、半行和损坏
记录、重建、作品隔离、设置与附件、实际请求快照、模型失败无重试、文件副作用与授权依据。
前端新增客户端用例覆盖筛选编码、取消、分片解析、去重、导出和错误响应。

首次全量执行为 **555 通过、1 失败**，日志保存于 `data/test-tmp/activity-full.log`。失败用例
`test_deltas_are_readable_before_the_response_ends` 原先断言完整固定事件列表，新增诊断事件后
列表不再相同。修正为独立核对请求配对，再对回复事件保留原有严格顺序、内容和增量断言。

首次浏览器执行保存在 `data/test-tmp/activity-browser/`：输入快照开关在异步保存前被受控值
恢复，浏览器确认点击未改变状态。修正为设置加载完成后才允许操作、乐观更新、保存失败恢复，
并隔离切换作品后的迟到响应。修正后同一在线场景通过，证据在
`data/test-tmp/activity-browser-fixed/`，模型为 **deepseek-flash**。

该在线场景通过真实页面发送一次文件修改，断言请求、工具、文件变化和提交事件，查看输入快照，
过滤并下载日志，再在同一订阅下接收第二轮只回复任务。没有增加模型自动重试或 Playwright 重试。

最终验证结果见[运行说明](../release.md)，原始失败与修正后的输出分别保存，不以重跑覆盖首错。

最终交付验证：Python 全量 **561 通过**，前端 **113 通过**，浏览器单批 **17 通过**（含
`deepseek-flash` 在线活动流）；构建、Ruff 与 Mypy 通过。最后补充的请求关联回归说明了队列
边界：请求标识和观察时间随事件入队固定，不能在消费旧事件时读取已经更新的当前请求标识。

可保留的交付证据集中在[产物目录](../artifacts/activity-log/README.md)，包含首次失败、最终
输出与[页面截图](../artifacts/activity-log/activity.png)。未把配置、凭据或输入快照加入产物。

## 未覆盖与限制

没有对任意长篇作品进行容量与长期运行验收，没有模拟磁盘断电原子性、多进程共同写入或任意
第三方扩展行为。输入快照是应用传给 provider 的材料，不是供应商内部推理或完整 HTTP 请求。
原始日志不自动清理，附件的过期与手动清理不回写原始事件。索引损坏可重建，不能恢复已删除
的事实源或附件。现有修改范围、文件网关与检查权限保持原契约。
