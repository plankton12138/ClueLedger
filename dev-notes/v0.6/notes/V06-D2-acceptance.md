# V06-D2 在线模型验收

> 日期：2026-10-22。状态：已执行；用例与驱动器在仓库内，可重复运行。

## 目标

计划 §11.2 与 §11.3 要求用真实模型核对「作者的话是否被正确理解」，用真实后端的浏览器流程核对
前后端接线。本阶段补上这两块的运行方式与首轮结果，不再把「需要人工启动」当作长期阻塞：
可判定的事实由脚本核对，文学判断留给作者看样例。

## 实际改动

**浏览器流程（`frontend/e2e/model-flows.spec.ts`）**

- playwright 拆成两个项目：`workspace` 保持不调模型的确定性回归，`online` 真的调用在线模型。
  `npm run test:e2e` 两个都跑；`test:e2e:local` / `test:e2e:online` 分别单跑。
- 两个用例：①「只改第三章、真相不要动」——核对禁止文件指纹不变、范围外章节不变、目标章节
  确实改了、事件里有范围登记；②「改完检查」——核对出现检查报告、报告落到 `/reviews`、
  回看时 `freshness` 为有效、报告 id 与事件一致。
- 失败按三类留证：端点或网络、产品接线或规则、模型理解。证据（提示、事件、前后指纹、
  分类）写到 `data/test-tmp/e2e-model/`，不重试。

**七类任务驱动器（`scripts/model_acceptance.py`）**

- 每类任务一份独立作品与独立状态目录，跑完比对改动集合、禁止文件指纹、读过哪些文件、
  范围登记与追加、检查报告的证据路径、索引记录。
- 结果写 `--out/<时间>/report.json` 与 `report.md`；作品本体留在数据目录，不进验收材料。

## 接口与数据影响

- 浏览器流程没有新增接口；检查报告的回看只用到既有的 `GET /reviews`。
- `extend_task_scope` 的入参增加 `evidence_path`（必填），事件增加 `evidence_path` 与
  `evidence` 两个字段；`set_task_scope` 事件不受影响。

## 实现取舍

- **在线用例只断言事实**：改没改、改在哪、指纹变没变、报告是否存在且有效。文笔与
  「伏笔是否自然」不在自动判断范围内。
- **每个浏览器用例一份新作品**：会话与草稿按作品保存，共用一份会让后一个用例继承前一个的
  对话历史；首轮就踩到了这一点——第二个用例沿用了第一个的要求。
- **失败不重试**：首轮失败先分类再改；本轮两次失败都不是产品问题，一次是夹具把「第三章」
  写成了走廊（模型如实反问），一次是检查项把 `references` 当成字符串列表。

## 验证证据

模型：`deepseek-flash`（`config.yaml` 里的在线连接，非本地模型）。

| 检查 | 结果 |
|---|---|
| `npx playwright test --project=online`（端口 8931，真实后端） | 2 项通过：只改指定章节 13.9 秒、改完检查 29.7 秒 |
| `uv run python scripts/model_acceptance.py` | 7 类任务全部通过（明细见下表） |

| 任务 | 结果 | 关键事实 |
|---|---|---|
| 不选文件，参考第一章修改第三章 | 通过 | 读了第一章与第三章，只改第三章 |
| 只选小传，「修改这一章」 | 通过 | 小传作为参考登记、未被改动，改动只落在当前章节 |
| 只改第三章，不动人物设定 | 通过 | 小传与真相指纹不变，写入全在已登记范围 |
| 修改动机并同步相关章节 | 通过 | 改第三章与第四章，全部在已登记范围；本次一次登记完整，没有走追加 |
| 假设凶手 / 只检查 / 继续 | 通过 | 讨论轮没有产生任何文件改动 |
| 索引之后回到原文呼应 | 通过 | 第一章索引生成，后续写作仍在已登记范围内 |
| 改完检查 | 通过 | 形成 `findings` 报告，证据全部来自本轮读过的文件 |

报告原文：`artifacts/model-acceptance/20261022-222827/report.json`（7 项全过）。同目录下另有两批
更早的运行产物，是驱动器自身缺陷的证据，不是模型问题：

- `20261022-222004`：「小传作为参考登记」把 `references` 当成字符串列表，实际是
  `{path, digest}` 对象。
- `20261022-222345`：「同步相关章节」要求必须出现范围追加事件，而这一次模型一次登记了三章，
  没走追加——检查项写死了路径，改为「追加时核对依据、并把是否追加记进报告」。
- `20261022-222742`：修正后单独补跑 `sync_chapters` 的产物。

## 偏差与未完成项

- **追加路径未在在线样例中出现**：两次同步任务里，模型都选择一次登记完整范围。
  `extend_task_scope` 的证据要求由工具层用例（`test_extend_requires_evidence_from_a_read_range`
  等）覆盖，在线样例尚未观察到真实追加。
- **浏览器流程只覆盖两条**：范围登记与写后检查已有在线用例；参考选择、索引面板、
  草稿切换与外部改源仍只有不调模型的断言或接口层用例。
- **索引只在自动核对层面通过**：索引内容是否准确、后文呼应是否自然，需要作者看
  `report.json` 里的事件与作品原文。
- **只覆盖一个在线模型**：结论只对 `deepseek-flash` 成立，不外推到其他模型。
- **检查质量只看了样例**：报告里的疑点是否该报、有没有漏报，仍需作者判断。
