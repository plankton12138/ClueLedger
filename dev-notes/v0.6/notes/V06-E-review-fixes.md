# V06-E 状态层审查修复

日期：2026-10-23。范围：修复 E1–E5 审查发现的七处状态边界与接线问题。

## 最终行为

| 问题 | 修复后的行为 |
|---|---|
| 设定与未读内容可登记为正文状态 | 五个发布工具统一校验对应章号的正文来源、版本、精确区间和本轮读取记录；角色类发布还要求本轮读完目标小传。整批核对完成后才保存 |
| 全书末章状态进入早期改稿 | 状态截止章独立于全书进度，五个域均按该章筛选；无法定位时不自动采用末章状态 |
| 省略生死字段默认在世 | `alive` 为必填布尔值，缺失或空值拒绝，不覆盖原死亡记录 |
| 改完检查没有状态层 | 第二阶段重新装配人物状态、时间线与线索，使用相同作品的存储，并记录检查用途的注入事件 |
| 单条披露过期影响整个角色 | 按记录分别判断有效性，保留同一角色的其他有效披露，汇总状态仅用于诊断 |
| 裁剪后超预算导致整个分区消失 | 人物与线索分区把末尾说明、隐藏条数提示一并计入预算，保留可容纳的优先条目 |
| 写作查询返回计划披露 | 写作模式不返回计划、未来条目及失效证据；核对模式和作者侧接口仍可查看计划 |

回看早期章节时，截止章之后才回收的线索按当时仍未回收显示，保存的最终记录不变。

## 接口与数据

- 对话 `context` 增加可选 `state_chapter`，非负整数，前端类型同步。该字段进入受理快照与
  同键核对；省略时兼容旧请求。没有新增作者必须操作的界面入口。
- 未明确截止章时，检查按目标章中最早一章、写作按当前阅读章定位；都无法定位则按第 0 章
  装配。只在对话中指出目标时，模型可用 `read_state.as_of_chapter` 明确查询时点。
  查询可收窄已固定的时点，不能扩大；没有固定时点的查询可显式选择章号。
- 五个派生状态文件的 `recipe_version` 从 1 升为 2，旧文件保留但不再采用，需重新核对。
  声明、小传、正文、索引和报告不迁移。此升级用于排除旧规则下可能登记的不合格状态。
- `save_character_state.states[].alive` 变为必填。缓存解析也不再用缺失值推断在世。
- 写后检查追加第二个 `state_injected` 事件，写作与检查各自记录实际装配结果。

## 剩余边界

- 原文来源、版本、章号与读取区间可以确定性核对，事实是否被正确概括仍依赖模型。
- 显式章号和当前阅读位置不代表修改授权，文件写入继续受任务范围约束；模型仍可能理解错
  对话中的目标章节，需要依据实际任务评判。
- 全量回归出现过一次文件替换拒绝访问，单独诊断未复现，首次失败保留；没有增加自动重试。
- 作者侧状态编辑、长篇真实作品验收、在线范围追加与检查误报漏报质量不在本次通过范围。
