# 活动记录

活动记录用于查询一次任务实际执行过什么，以及文件变化和版本提交的关系。顶栏「活动记录」
打开大面板，分为事件流和文件版本；版本页继续提供工作区差异、提交差异、补记与最新提交撤销。
此功能属于 0.6 文件工作区，接口前缀与会话日志格式保持兼容。

## 查看与查询

默认选择当前会话，没有正式会话时选择当前作品。筛选器可切换作品全部活动或指定会话，并按
任务标识、类型、结果、时间和关键词组合查询。关键词搜索原始事件中已记录的字段，包含路径、
摘要和错误信息，不搜索独立附件全文。

事件按实际时间显示，以会话和任务分组；同一毫秒内用索引序号辅助排序。新导入的历史记录可能
发生在已有记录之前，订阅游标使用索引位置，不能把游标当作发生时间。记录时间表示应用观察到
事件的时间，不代表模型内部开始思考或外部编辑器保存文件的时间。

- 默认隐藏文字块与增量分片，回复和工具过程仍可单独查看；勾选后显示原始分片事件。
- 列表先载入最近 100 条，每次可加载更早 100 条，页面最多保留 1000 条。查看更早记录时暂停
  插入新行，仍接收统计和新事件提示；点「回到最新」重新取得最近记录。
- 自动跟随可关闭；向上滚动会暂停跟随。折叠状态只显示摘要、结果和耗时，详情按需请求。
- 开始事件显示「已开始」，仅陈述当时动作；侧栏最近任务的状态以轮次终态为准。
- 实时断线按 1、2、5 秒有限重连，沿同一游标续传；仍失败时保留已加载记录并显示重新连接。
- Esc 关闭面板，键盘焦点限制在面板内，关闭后回到打开前的控件。
- 面板顶部可调字号，与工作台共用设置；事件、详情和版本页同步变化，刷新后保留。见[显示偏好](appearance.md)。

展开事件可查看原始字段、工具输入与结果、已保存的模型输入，并跳转所属对话、当前文件或关联
提交差异。文件已删除时打开当前文件会按文件接口报错，不把当前文件冒充事件发生时的版本。

## 事件内容

| 范围 | 记录内容与来源 |
|---|---|
| 任务 | 受理时的作者原话、上下文快照、所选模型；停止请求；轮次实际终态 |
| 材料和权限 | 实际读取区间与版本、参考登记、修改范围及授权引文、上下文分区规模与跳过原因 |
| 模型请求 | 实际调用边界、用途、模型、请求标识、工具集合、输入规模、结束原因、首个输出与总耗时 |
| 工具 | 调用标识、定位参数、完整参数与结果附件、结果摘要、字符数、成功与失败、观察耗时 |
| 文件变化 | 写入成功后的路径、动作、前后指纹、是否变化；局部替换位置；移动目标与删除结果 |
| 状态和索引 | 五个状态域的发布数量、发布字段与证据；章节索引更新；检查请求与报告 |
| 版本 | 首次写入的基线和外部改动提交；本轮版本记录结果、提交与实际变化路径 |
| 用户操作 | 正文导入、启用版本记录、补记、撤销、日志设置、清理详情、重建索引的开始和结果 |

文件变化发生后才发布变化事件；工具调用成功不等于一定产生文件变化。Git 记录状态与任务执行
状态分别保留：模型任务失败后仍可能成功记录已写入的文件。文件差异以关联 Git 提交为准；一轮
中的具体编辑参数也可从工具详情查询，不维护第二套文件版本仓库。

模型请求通过应用内的 provider 包装器观察，发送的系统提示、消息和工具定义仍直接传给原
provider，不重组实际输入，也不增加模型重试。工具、文件与状态事件用调用标识、父请求标识和
轮次标识关联。思考只来自供应商原本返回的可展示内容，不获取或推测内部推理。

用量只有上游实际填写时才记录，默认用量对象不显示成实测零消耗；没有成本计算。首个输出耗时
以应用收到文字、思考或工具输出为准，响应壳不算输出。恢复后的中断请求不补造耗时与用量。

## 存储与恢复

作品状态目录保存原始事实，作品 Git 不包含这些应用日志：

| 位置 | 用途 |
|---|---|
| 原有 `<conversation_id>.jsonl` | 会话事件，继续用于对话回放和聊天实时流 |
| `activity/operations.jsonl` | 不属于某次对话的作品操作事件 |
| `activity/index.sqlite3` | 从两类日志生成的查询索引，可删除后重建 |
| `activity/details/<id>.json` | 工具输入、结果与可选模型输入的独立详情 |
| `activity/settings.json` | 本作品的输入快照和详情保留设置 |

业务记录只追加到对应的原始日志；索引按文件偏移消费完整行，不要求业务同时成功写索引。
日志末尾半行等待下一次完整写入；语法损坏或字段不合法的完整行会显示诊断事件。索引检测到
日志被替换、截断或删除时改变游标代次，客户端重新取得快照，清除旧页面，避免混用位置。
重建索引也改变代次，保留原始事件标识。旧会话没有的新字段按未记录处理。

服务重启按原有规则结束未封口轮次，同时给未结束模型请求补中断事件。未结束的作品操作只标注
中断与「实际结果未确认」，不推断文件回滚。原始日志与文件写入、Git 提交之间没有跨文件事务，
进程恰在副作用与结果记录之间退出时，仍须结合文件和 Git 核对。

## 详情设置与导出

默认不保存模型输入快照。作者启用后，新建执行阶段会固定该设置，并为后续请求保存应用实际
传入的系统提示、消息与工具定义；同一阶段中途切换设置不追溯改变已启动的记录策略。历史未
保存的输入不能从当前文件还原。输入快照排除思考块、图片数据和供应商签名，不是原始 HTTP 抓包，
不记录认证头、密钥或 provider 内部默认参数。

工具输入和结果默认保存详情。结构化密钥字段、签名与常见认证串隐藏；任务范围的授权原话与
事件序号保留。这不是任意正文的秘密识别器，作品正文可能出现在本机详情里。

详情默认保留 30 天，可改为 7 天或直到手动清理；读取已过期详情或写入新详情时清理过期文件。
手动清理有二次确认，保留事件、摘要和版本关联，已清理的详情明确显示不可用。

导出按当前筛选生成 JSONL，覆盖全部匹配事件，独立于页面已加载数量。默认包含原始事件字段和
附件引用，勾选「导出包含已保存详情」后附带仍可用的附件；未保存、过期或已清理的内容不会补造。
导出固定开始时的上界，之后新增的事件留给下一次导出。

## 接口

以下路径均位于 `/api/file-workspaces/{workspace_id}` 下。

| 接口 | 行为 |
|---|---|
| `GET /activity` | 分页查询，返回摘要、统计、最近任务、续传游标与历史分页位置 |
| `GET /activity/stream` | 同格式快照与增量，跨轮次持续订阅，不在 `run_finished` 关闭 |
| `GET /activity/{event_id}` | 原始事件详情 |
| `GET /activity/attachments/{key}` | 仍保留的详情附件或明确的不可用原因 |
| `GET /activity/export` | 筛选导出；`include_details=true` 包含可用附件 |
| `GET /activity/settings`、`PUT /activity/settings` | 查询和设置快照开关、保留天数 |
| `DELETE /activity/details` | 清理详情，不删除原始事件 |
| `POST /activity/rebuild` | 重建派生索引，订阅方重新取得快照 |

列表、订阅与导出共用 `conversation_id`、`turn_id`、`category`、`status`、`q`、`since`、`until`、
`verbose` 筛选。时间包含时区，列表另支持 `after`、`before` 与最多 500 条的 `limit`。

当前没有外部文件编辑器监听，没有自动轮转或清理原始会话日志，也不支持多个服务器进程同时
写同一状态目录。索引可重建，原始日志和被清理的附件不可由索引恢复。
