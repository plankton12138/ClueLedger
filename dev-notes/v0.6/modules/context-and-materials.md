# 本轮材料、参考、范围、索引与检查

这一份说明覆盖 0.6 新增的四块能力。它们共用同一道「写前检查」入口和同一份会话事件，
不引入新的角色或第二个创作流程：普通讨论不写文件、不建索引、不跑检查；作者明确要求时
模型先登记，应用核对后才执行。

## 1. 材料与参考

**作者这一轮带了什么**与**模型实际看到了什么**分开记录：

- **受理快照**：首次发送与续聊接收 `context`（当前阅读、参考列表、客户端看到的版本）。
  受理时冻结路径与服务端指纹写入 `turn_started`；执行开始复核，版本变了整轮失败，不偷换。
  同键重试必须带同一份材料。
- **预读**：显式参考按选择顺序登记为必需参考，每份最多 2000 字符、总量 8000。被截断的
  参考在写作品前必须读完，剩余区间随错误返回。
- **读取记录**：只有真正返回给模型的原文计入；目录、搜索摘录、界面打开、`edit_file`
  内部读文件都不算。区间用服务端字符下标（左闭右开），`read_file` 返回 `next_cursor`
  继续读，单次最多 16000 字符，超长单行可继续。
- **自然语言登记**：`register_references` 只接受作者文本来源（带原话引文与事件定位）与
  发现的材料（先读过并引用文件原文）。作者选的文件由应用登记。发现的材料还要引文落在
  本轮实际提供过的区间里——读过文件开头、引用后面一段会被拒绝。
- **必读不会被降级**：同一路径的重复登记只做合并，`required` 只会保持或加严，
  `author_selected` 类别保持；模型再用 `required=false` 登记同一份文件，不能取消
  写作品前的读完检查。
- **界面**：输入区「添加文件」多选参考，目录每行右侧的「＋」把该文件加入当前草稿的参考；
  两处写同一份草稿状态，顺序即选择顺序。每轮显示材料、必读标记与已提供范围。
- **失效**：参考文件被外部改动时写入按 `CONTEXT_SOURCE_STALE_CONFLICT` 失败并给出
  剩余区间，重读后恢复；本轮自己的删除不阻断后续操作。

## 2. 本轮修改范围

- 没有登记范围时四个写工具一律拒绝（`TASK_SCOPE_REQUIRED_CONFLICT`），拒绝不产生文件、
  目录或 Git 副作用。
- 范围只接受确切路径与操作类别（新建 / 修改 / 删除 / 移动两端）；「修改」不隐含删除；
  禁止项写进 `denied_paths`。
- 授权只认 `turn_started` 的作者原话（短引文 + 事件序号）；「继续」必须用
  `carried_from_seq` 指认被承接的作者消息，且不能与授权语句同一条。
- 固定范围不能自行扩大；登记为可发现范围（「同步相关章节」）时 `extend_task_scope`
  只能追加具体文件与已允许的操作类别，旧版本号不能覆盖新版本。追加要给出依据文件与原文
  引文（`evidence_path` + `evidence`），引文必须落在本轮实际读过的区间里，凭印象写的
  理由会被拒绝并按 `REFERENCE_EVIDENCE_INVALID` 返回。
- **重复登记只能收窄**：再次调用 `set_task_scope` 可以去掉已登记的路径与操作、补充禁止项、
  改成只读；不能新增允许操作、不能撤掉已登记的禁止项、不能把固定范围改成可追加范围，
  也不能放宽可追加的操作类别。扩大范围只有 `extend_task_scope` 一条路。
- 每轮范围、授权原话与允许项写入 `task_scope_set` / `task_scope_extended` 事件并在界面展示。
- **确定性边界**：应用能证明操作没有超出已记录范围，不能证明范围解释符合作者意图。

## 3. 章节索引

- 索引保存在作品状态目录 `chapter-index.json`，不参与作品 Git；规则版本变化时旧记录过期。
- 一轮最多更新 10 章；索引任务只用只读工具与 `save_chapter_index`，不暴露作品写工具。
- 发布四道核对：目标在允许范围、读完当前版本全文、引文与字符区间一致、发布前复核源指纹。
- 状态 `valid` / `stale` / `source_missing` / `unavailable` 按当前磁盘算出；只有有效记录
  注入普通写作的系统提示（总预算 8000 字符），索引任务本身不注入旧摘要。
- 顶栏「索引」面板展示每章状态、摘要与证据，勾选章节发起更新。

## 4. 写后检查

- 入口只有两个：作者显式要求（`purpose=review`，1–20 个文件），或修改任务里模型登记的
  `request_review`（作者原话引文）——修改完成后同一轮进入只读检查阶段。普通修改、打开
  文件、刷新、保存都不启动检查。
- 检查工具集只有目录、搜索、读取与 `save_review_report`；检查失败不撤销已落盘的修改，
  整轮按部分完成，报告状态单独说明。
- 每条问题至少一处原文证据（路径、版本、区间、引文），跨文件冲突列双方出处，推测标为
  疑点；`no_findings` 只有读完目标全文与必需参考才允许，否则 `incomplete` 并列出未覆盖项。
- **证据要看区间**：只核对「这个版本读过」不够，证据区间必须落在实际提供过的原文里；
  读过文件开头、引用后面一段会被拒绝。
- **回合预算跨阶段共享**：写后检查是同一轮的第二阶段，写作阶段用掉的模型回合要从检查
  阶段扣除；剩余为 0 时不进入检查，报告记为未完成并说明原因。
- 报告保存在 `reviews.json`（最多 50 份），回看时按当前指纹标记 `freshness`，过期不重跑。
- `GET /reviews` 返回保存时的目标版本 `target_digests`（路径与指纹列表）；来源改变后，
  旧版本快照保持不变，当前有效性由 `freshness` 表示。
- 界面：结果卡「检查本次改动」只对仍然存在的改动文件发起；报告显示问题、建议与证据，
  回看时按当前磁盘核对版本，过期或来源缺失时标注「已过期」并说明旧结论不再对应当前内容。

## 5. 上下文装配与注入记录

系统提示不再是一段拼好的字符串，而是按分区装配的结果（V06-E1）：

- **按用途装不同分区**：写正文装任务要求、目录、本轮材料、章节索引、设定集、此前轮次；
  建索引只装任务要求与目录（读原文即可，不需要线索与真相，也不注入自己的旧摘要）；
  只读检查装任务要求、目录、材料与设定集，不装索引摘要（避免用摘要替代原文证据）。
- **分区顺序固定**：任务要求 → 目录 → 材料 → 索引 → 设定 → 此前轮次。
- **必装分区不截断**：任务要求与目录超出预算时整轮失败（`CONTEXT_ASSEMBLY_FAILED`），
  不会截一半后宣称完整；可裁分区超预算时整块跳过，并记下原因与字符数。
- **记录与实际同源**：每轮先写 `state_injected` 事件，列出用途、各分区字符数、跳过项与
  预算使用量，再把这**同一份**装配结果交给模型。事件只记规模，不复制注入正文。
- **界面**：回复上方显示「本轮上下文」，展开可见每个分区与「未注入：超出预算」。

两处边界：

- 用途由受理时的 `purpose` 决定，不看作者意图。同一轮既能讨论也能改稿，所以「讨论」
  不单列类型。
- 写作上下文仍装真相（单 agent 需要它规划伏笔与自查），隔离放在状态层：真身份与计划
  揭底章不进入写作上下文。

## 6. 人物身份状态

身份按章节生效，写作上下文只拿「读者已知」那一栏（V06-E2a）。

- **声明写在小传元信息里**：`surface`（社会身份）、`aliases`（别名）、`revealed`（第几章
  起读者已知）、`planned`（计划第几章披露）。条目写法是「章节号:事实」，例如
  `revealed: [3:主治医师]`；格式不对的条目单独作废并给诊断，同字段其他条目照常生效。
- **核对记录可重建**：正文核对的结果存在作品状态目录的 `disclosure.json`，不进作品 Git。
  每条记录带小传与原文的路径、版本、字符区间与引文；小传或原文被改过即失效，失效记录不
  采用、退回「只按声明显示」并给一条诊断。核对过的事实优先于声明，同一事实不重复注入。
- **核对任务只读原文**：用途 `update_disclosure`，工具模式 `state`，只开放目录、搜索、读取
  与 `save_disclosure`；发布要过三关（小传可读、原文可读、区间与引文一致），任一条不过
  整批不写。一次最多核对 10 份小传。
- **三档分开**：已披露进写作上下文；声明了起始章但正文还没写到那一章的标记「未到章」，
  不注入、面板显示「正文写到该章后生效」；计划披露只在面板出现，从不进入写作上下文。
- **冲突单列**：别名指向两个角色（双方各报一条）、多个角色标 `culprit`、同一事实既已披露
  又计划披露。冲突只显示，不阻断保存，也不替作者裁决。
- **接口**：`GET /api/file-workspaces/{workspace_id}/state?domain=disclosure` 返回当前章节、
  每个角色的三档条目与冲突；界面顶栏「身份」打开面板，只读。
- **边界**：核对只证明原文里存在引用到的那段话，不证明读者理解了它；没有核对记录的声明
  仍按作者声明处理。「该披露了」只说明计划章已到，不能说明正文已经披露。

## 7. 专有名词词典

同一事物多种写法是长篇最常见的漂移。词典把作品用过的名字汇总成一份白名单（V06-E3）。

- **两类来源**：人物姓名与别名来自小传声明；地名、组织、物件由核对任务用
  `save_glossary_term` 从原文登记，必须带路径、版本、区间与引文。记录存作品状态目录的
  `glossary.json`，不进作品 Git，源文件改过即失效。
- **只列已经出现的词**：核对来的词要满足起始章不超过当前章节，写到第 1 章时不会看到第 5 章
  才出现的地名。按人物、地点、组织、物件分行，每类最多 24 个。
- **注入独立分区**：写作上下文里的「专有名词」，预算 800 字符，超了整块跳过并记原因。
- **三类冲突**：正名被别人的别名占用、别名互相撞车、同名不同类型。只报告，不自动合并——
  合并等于替作者判定两个名字指同一个东西。
- **边界**：模型只登记它读到的名字，哪些算同一事物的不同写法仍是它的判断，没有确定性校验。
  词典可用 `GET /state?domain=glossary` 或 `read_state` 查看，但状态抽屉还没有对应的标签。

## 8. 人物状态与故事时间

位置、生死、立场与「这一章发生在什么时候」都是随章节变的事实，不是设定。两项都只来自
原文核对，没有声明字段（V06-E4）。

- **记录**：`character-states.json`（一角色一章一条，位置、生死、立场）与 `timeline.json`
  （一章一条，时间说法、跨度、主要地点），存作品状态目录，不进作品 Git。都带
  `record_version` 与 `recipe_version`，源文件改过即失效。
- **当前状态**：取当前章及以前最新的有效快照；最新那条失效时退回上一章并给诊断
  「最后一次核对在第 N 章，此后 M 章没有核对记录」。
- **注入**：写作与检查两种用途各加 `roster`（700 字符）、`timeline`（400 字符）两个分区。
  人物排序「已死亡优先，再按最后核对章倒序」，超预算按行裁掉并说明还有几人未列入，不整块
  丢弃；时间线超预算先丢较早的锚点，保留最近一章与「下一章从第几章之后接着写」。
- **发布**：`save_character_state`、`save_timeline`，与披露、词典共用同一套证据校验
  （路径、版本、区间、引文），任一条不过整批不写。
- **查询**：`read_state` 的 `domain` 取 `disclosure` / `roster` / `timeline` / `glossary`。
- **检查**：已死角色在新场景里行动（回忆、转述、尸体、梦境除外）、时间锚点与本章时间词
  冲突，按 `continuity` 类报出并引用双方出处，允许写成「疑点」。
- **界面**：「作品状态」抽屉三个标签（身份、人物状态、时间线），人物状态可勾选后发起
  `update_state` 核对；时间线只读，缺锚点的章单列。
- **不做**：不把 `when` 解析成日期，因此不自动判定先后；不做「改了某章就标记依赖它的状态
  过期」，失效在读取时按指纹算。

## 9. 线索与伏笔台账

「第 3 章埋下、第 7 章该回收」这类信息最容易丢：写第 8 章时没人提醒，它就永远留在第 3 章。
台账把未回收的线索按「该回收了没有」排好，放进写作与检查上下文（V06-E5）。

- **一条线索**：内容（读者能观察到的事实）、埋设章、计划回收章（可空）、状态
  （`open` / `resolved` / `dropped`）、埋设处原文依据；标为已回收时还要回收章与回收处依据。
  同一句线索只留一条，后来覆盖旧的。
- **只有未回收的进上下文**：已回收与已废弃只给作者看。排序是确定的——超期（计划章 ≤ 当前
  章）→ 下一章该回收 → 有计划未到期 → 没定回收章；超期清单在接口里单列。
- **失效即不采用**：埋设处或回收处任一被改过、文件被删，整条登记失效并给一条诊断。
- **预算**：`clues` 分区 500 字符、最多 8 条；超了按行裁并写明还有几条未列入，不整块丢弃。
  超期项不是必装分区——做成必装会让一条误判顶掉其余全部状态。
- **界面**：状态抽屉第四个标签「线索」，未回收与已回收/已废弃分列，超期条目标黄。
- **不做作者确认**：计划里写的「作者在界面确认后才入账」本版没做，因为作者手动修改状态
  不在范围内。核对任务登记即入账，面板显示原文依据，误判由作者要求模型改或标 `dropped`。

## 错误码

新材料相关的错误码集中在 §9.4 的计划文档中定义；状态码由尾缀决定（`*_NOT_FOUND` 404、
`*_CONFLICT` 409、`*_FAILED` 500，其余 400）。工具错误按模型可修正的方式返回：先报
「为什么不允许」，再由模型读取或澄清后继续，不终止整轮。

## 明确不做

任意本机附件、外部资料导入、向量检索、会话压缩、长期记忆、角色知情状态机、章节锁定、
跨文件事务、每章独立提交、自动修稿、自动重试与检查后自动扩大范围。
在线模型样例的验证范围与仍未覆盖的行为见[运行说明](../release.md)。
