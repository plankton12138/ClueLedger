# 上下文用量与压缩模块

日期：2026-10-27。对应版本 `0.9.0`。本文件说明各模块的职责与边界，
运行方式与验证结果见[运行与验证](../release.md)。

## 职责划分

| 模块 | 回答的问题 | 不负责 |
|---|---|---|
| `server/model_limits.py` | 这个模型能装多少 | 分词、估算、是否该整理 |
| `workspace/context_usage.py` | 这次请求大概占多少 | 读取事件、调用模型 |
| `workspace/conversation_usage.py` | 这个会话累计用掉多少、现在占多少 | 写事件、算容量 |
| `workspace/compaction.py` | 切哪里、摘要是否成立、怎么投影 | 发起模型调用、维护操作状态 |
| `workspace/compaction_ops.py` | 一次整理操作的受理、状态与取消 | 摘要内容与记录校验 |
| `workspace/context_boundary.py` | 请求边界自动整理、手动队列与冻结投影 | 改写原始会话 |
| `workspace/context_summary.py` | 摘要分段、最多四次调用与取消 | 操作受理与写工具 |
| `workspace/model_activity.py` | 实际请求的边界：估算、裁剪、用量记录 | 决定是否整理 |
| `api/contextUsage.ts` + `ConversationUsageBar` | 把服务端的数字变成文案与入口 | 自己累计、自己估算 |

一条原则贯穿全部模块：**只有一处权威来源**。数字由服务端聚合，前端不重算；
容量由连接配置解析，估算不猜；切点由事件决定，界面不推断。

## 数据流

```text
连接配置 ─→ model_limits ─┐
                           ├─→ RecordedProvider（真实请求边界）
装配结果 ─→ context_usage ─┘         │
                                     ├─→ model_request_started（估算、裁剪、容量）
                                     └─→ model_request_finished（供应商用量）

会话事件 ─→ conversation_usage ─→ usage 接口 ─→ 两个入口
         └→ compaction ─→ context_compacted ─→ 下一轮投影
```

## 各模块的边界

### 容量

按 `(连接, 协议, 精确模型)` 解析。未配置即未知，不按名称前缀推断，也不填默认窗口。
回复预留取运行时实际请求上限（4096），显示与调用共用同一份数据。

### 估算

宽字符一字一 token，其余四字符一 token，另加消息与工具的固定结构开销。方法标识
`cjk-aware-v1` 会进指纹；换模型、换资料、换方法都会让旧估算失效。估算只读传入的文本，
不读文件、不调用模型。

### 统计

以请求为单位去重。四类协议的用量在适配层已归一化，这里只做两件换算：把缓存读写并回输入、
不重复叠加推理。缺失与零分开表达。

### 压缩记录

记录是追加的事件，不改写原对话。读取时重新校验四件事（摘要非空、范围有效、保留点存在
且在范围之后、来源指纹一致），任何一条不成立就按未压缩处理。摘要条目带原事件引用与原话。

### 整理操作

操作有自己的标识与状态，不占创作轮次、不产生作品提交。同一请求键只受理一次。
操作和请求键以事件持久保存；用量接口附带最新操作，刷新与切回可恢复并停止。
重启关闭未完成操作，不重新付费调用；压缩记录和投影仍从事件重建。

### 请求边界

`RecordedProvider` 是唯一能看到「真正发出去的请求」的地方。估算、裁剪、溢出重试与用量记录
都在这里，因此界面上的数字与实际请求不会各算一套。裁剪只作用于发出去的副本。

供应商明确拒绝上下文且尚未接受输出时，保留更少的近期消息重发一次，并写入
`model_request_retried`。窗口未知也可以重试：拒绝本身说明装不下，不需要先知道容量。
普通网络失败、超时与输出截断不按溢出处理；第二次仍失败就保留实际状态结束。

## 前端

`ConversationUsageBar` 只负责刷新时机与文案。零、统计中、未知、部分、完整五种状态各有
独立文案；窗口未知时只给 token 数，不给百分比。整理按钮按操作状态轮询，终态后重新读取用量。

## 已知空缺

- 溢出识别是启发式：只认供应商文案里明确指向长度或容量的措辞，其余按普通失败处理。
- 自动整理与有界分段摘要已接入；单个必要单元无法容纳时明确报错，未生成轮内工具摘要。
- 在线两方案 16 次任务与代理复核、浏览器三项回归通过；剩余专项与独立人工签收见[逐项证据](../notes/R1-acceptance-matrix.md)。
