# 0.9 上下文用量与会话压缩开发计划

日期：2026-10-26。状态：**待实施**。目标版本：`0.9.0`。
产品范围见[产品方案](../../product-design/v0.9/README.md)，模块代码见[实现示例](implementation-examples.md)，
逐项验证见[验收矩阵](acceptance.md)。本文中的拟新增文件、字段与接口均为计划。

## 1. 目标与取舍

先让作者看到当前上下文容量和本会话累计消耗，再通过压缩支持持续工作。
统计与压缩共用实际请求边界和同一份上下文投影，防止界面展示与模型真正收到的内容不一致。

本版采用两个轻量入口、应用层投影与追加式压缩记录。继续复用当前单 Agent、文件读取凭据、
任务范围、问题记录和会话事件；不引入会话树、跨会话记忆，也不复制一套作品事实库。
不直接导入 `tau_coding` 的完整会话运行环境，不修改 `tau_agent`、`tau_ai` 的便携核心。

自动压缩只发生在作者已启动任务内的安全边界。手动整理是显式受理的操作。
浏览、统计读取、模型选择和重启只做确定性估算，不调用摘要模型。

## 2. 2026-10-26 代码基线

| 现有位置 | 已有事实 | 本版处理 |
|---|---|---|
| `workspace/state.py` | 事件按 `seq`、`event_id` 追加，有残尾处理与索引恢复 | 继续作为公开对话和执行事件来源，追加压缩记录 |
| `workspace/conversation_context.py` | 跨轮只恢复作者提示与公开回复；执行事实另算 | 提取共用投影入口，再接摘要与保留边界 |
| `workspace/service.py` | 受理冻结 `history_seq`、模型和装配；作品内单任务 | 在冻结输入上估算、整理，保护当前提示只追加一次 |

| `workspace/materials.py`、`task_scope.py` | 读取区间、指纹、作者原话与修改范围 | 保留程序凭据，摘要不能增加权限或原文覆盖 |

| `server/model_api.py`、`model_connections.py` | 连接配置使用 `If-Match` 并发检查 | 扩展精确模型的容量配置与对外视图 |
| `frontend/api/workspace.ts`、`state/conversations.ts` | 会话事件、断线回读与按会话归属 | 接统一统计接口与新增事件，不在组件里独立累计 |

现有工具事件只保留定位参数和摘录；详情附件也受脱敏、捕获与保留策略约束。
**现有事件不是所有协议消息的无损副本**。跨轮恢复以公开对话为源；轮内投影以本轮内存中的
真实协议消息为源，崩溃后沿用现有中断处理，不承诺从日志自动续跑任意工具步骤。

## 3. 统一统计口径

### 3.1 模型容量

以 `(connection_id, api, exact_model_id)` 识别容量配置。来源顺序：用户显式覆盖 → 有来源和版本的
可信模型元数据 → 未知。模型发现列表只有名字时不能据此猜容量，名称前缀匹配不能作为权威来源。

保存 `context_window_tokens`、`max_input_tokens`、`max_output_tokens`、实际 `output_reserve_tokens`、
容量来源与元数据版本。缺值使用 `null`。回复预留必须与实际 provider 请求上限一致；调整它时同步
修改运行配置并冻结，不能只改显示。用户设置通过现有模型配置保存路径完成，沿用 `If-Match`。

任务运行中继续使用受理时的模型与容量。此时更改全局选择只影响下一轮，不能用新模型的窗口
解释旧模型正在发生的请求；统计视图携带实际模型身份，必要时在详情中说明正在使用的模型。

```text
可用输入上限 = min(已知最大输入量, 上下文窗口 - 实际回复预留 - 安全余量)
上下文显示占比 = 当前预计输入 / 上下文窗口
```

未知项不代入零；能从已知最大输入量判断边界时仍可使用该上限。
只有窗口未知时不展示窗口百分比；所有输入上限均未知时停用阈值自动整理，手动整理仍可用，
但不能声称已具备确定的防溢出预算。收到明确溢出时仍只允许一次恢复尝试。

### 3.2 当前上下文

计算范围为：系统约定与当前合法资料、工具定义、有效历史与摘要、当前已受理提示、轮内保留消息、
协议结构开销。输入框草稿和未受理的临时参考不计入。

对外区分 `estimated_active`（当前有效输入估算）与 `last_request_input`（最近真实请求的实测或估算）。
运行中每次推理前更新；响应完成后按真实后续可见内容更新，不能简单加上全部输出 tokens，
因为推理内容与协议签名不一定会被下一次请求回传。本轮结束后按跨轮公开历史重新投影。

系统与工具定义或模型、用途、材料版本变化后，重建投影并使旧校准失效。
估算优先使用已具备且可验证的对应分词方式，否则采用中文感知的启发式并记录方法版本。
不使用英文字符数除以四作为所有中文与协议的通用估算。

供应商用量只校准其对应的模型、协议与请求指纹；不能将旧请求用量直接加到重写后的新前缀。
分项估算与供应商实测总量并存，不按比例伪造精确分项。状态至少包含 `pending`、`ready`、`stale`、
`unavailable`，并携带模型身份、来源游标、资料指纹和更新时间。

### 3.3 累计用量

- 作用域为作品内的指定会话。写作、检查、索引、资料任务与摘要，只要实际归属该会话就计入；
  其他会话、连接发现与探针不计入。
- 按真实请求 `operation_id` 去重。运行中请求计次数，实际已返回且可靠的用量才累计；统计完成、
  失败、停止和溢出尝试，不因任务最终失败删除已发生消耗。
- 规范化输入等于未缓存输入、缓存读取与缓存写入之和；协议已计入输出的推理 tokens 不再加一次。
  优先保留供应商可靠总量；总量与分项口径不一致时留诊断，不静默改写供应商数据。
- 缺少整个 Usage 与缺少分项分别标记。`Usage` 默认零不能证明供应商确实返回了零；U0 必须核对
  各协议的字段可用性。无法确认的分项不展示，可靠总量仍可保留。
- 返回已知累计值及未上报/部分上报/尚未结束的请求数。全部缺失时累计 tokens 为 `null`；
  只有尚无请求时显示零。混合数据展示已知累计值，并注明“部分请求未统计”。
- 模型用时为实际请求耗时之和；并发时不等同于自然经过时间。缓存读写属于输入子项，不改变窗口占用。
- 从持久会话事件重建；缓存只能加速。关闭输入捕获不影响数值统计，切换模型或压缩不重置累计。

## 4. 应用层职责与调用顺序

| 拟新增职责 | 建议位置 | 输入与输出 |
|---|---|---|
| 模型容量解析 | `server/model_limits.py` | 配置和元数据 → 冻结容量，不含凭据 |
| 请求估算与预算 | `workspace/context_usage.py` | 实际请求 → token 估算、分项、预算状态 |
| 有效上下文投影 | `workspace/context_projection.py` | 冻结历史/本轮协议消息 → 有来源的有效消息 |
| 会话累计统计 | `workspace/conversation_usage.py` | 会话事件 → 去重累计与完整度 |
| 压缩计划与校验 | `workspace/compaction.py` | 有效投影 → 安全切点、摘要候选与校验结果 |
| 压缩记录与操作 | `workspace/compaction_store.py` | 来源范围、记录与操作幂等；索引可重建 |
| 请求边界编排 | `workspace/context_provider.py` | 实际请求 → 预算检查、压缩、真实 provider 调用 |
| 统计与压缩接口 | 现有 `workspace/api.py` | 读视图、手动操作、状态与取消 |
| 前端契约与显示 | `api/workspace.ts`、`state/conversationUsage.ts`、`components/chat/ConversationUsageBar.tsx` | 服务端视图 → 两个浮层与运行状态 |

文件可在实施时按复杂度合并，职责与权威来源不合并。

```text
作者请求 → TurnService 固定历史、模型、资料 → 有效上下文投影
       → ContextManagedProvider：检查/必要时整理
       → RecordedProvider：记录真正发出的请求 → 供应商

摘要调用 → 独立 RecordedProvider(stage="compaction") → 同一受理模型
       → 候选摘要校验 → 持久追加 → 启用新投影 → 继续原推理
```

编排器转换请求副本，不在运行中的 harness 上异步替换共享消息列表。
摘要请求没有工具，绕开压缩编排器，避免递归整理。每一次真实调用都经过记录器。
只读估算接口使用同一装配函数，但不能创建写会话、产生提交、登记读取凭据、隐式读取未授权灵感
或启动模型。统计 GET 不写会话活动；资料变化通过指纹使只读估算缓存失效。

目前 `_record_activity` 会将最新模型请求设为本轮工具事件的父请求。新增摘要调用必须使用
明确的 `request_kind`、`parent_operation_id` 与操作栈，不能让摘要请求覆盖正在执行的写作请求关联。

## 5. 压缩契约

### 5.1 跨轮压缩

在受理冻结的 `history_seq` 内，优先按完整终态轮次选取较早范围，近期轮次原样保留。
当前作者提示、最新有效约束、待回答问题与理解保留区所需的原话不受普通淘汰策略影响。
保留量根据整请求剩余预算计算，不能固定搬用 Tau 的 20K。必要内容无法容纳时明确失败。

触发上限与整理后的目标规模分别设置，整理后留出继续读取和回复的空间，避免下一次请求立即再次整理。
同一来源指纹下已经失败或没有有效缩减时不反复自动调用摘要；新的来源变化或作者再次手动请求可重新判断。

摘要结构包含目标、有效约束、作者决定、助手建议、进展、未完成事项和资料定位。
语义条目包含原事件引用、性质、适用范围与被替代关系；应用再补入真实执行结果和待回答问题。
合法引用不代表语义理解已被证明，语义保留由在线验收验证。

摘要以明确标识的应用历史消息放在近期对话之前，系统约定只保留说明摘要用途的固定规则，
不将摘要提升为系统指令。范围校验继续从原事件读取作者原话，不从摘要重建授权。

来源具有用途、章节与版本边界。事实提取任务不直接接收整个自由摘要；按确定性来源范围选择可用
条目，不能确定范围的故事结论不注入受限事实任务。摘要不可充当正文证据或作者授权。

允许增量整理，但关键约束与状态从原话/实际事件重建。摘要超预算、来源冲突或重复整理明显失真时，
按原始事件分段重建。章节索引继续只从章节原文生成，不改为从会话摘要生成。

### 5.2 持久记录与启用

`context_compacted` 至少携带：`schema_version`、`compaction_id`、`kind`（session/run）、
`source_head_seq`、`covered_through_seq`、`first_kept_turn_id`、`source_digest`、上一记录标识、
摘要及其来源、模型与提示词版本、压缩前后估算、生成请求关联、触发原因。
轮内记录另带 `turn_id` 和本轮稳定消息 ID，不能用会话事件 `seq` 替代协议消息边界。

压缩记录写入位置可以晚于它覆盖的历史。投影按来源范围与 `history_seq` 验证，不把压缩提交时的
`seq` 当成覆盖边界，也不扩大受理快照。首次启用可使用刚持久提交的候选，但不能重复装入本轮提示。

摘要是功能恢复数据，不使用活动日志的短期详情附件保存唯一副本。原事件不删除、不改写。
候选必须通过结构、引用、保护项、来源指纹、实际缩减和预算检查后，才持久追加完成事件并切换。
发生冲突则不发布；持久化失败继续使用旧投影；重启只恢复已完整提交的记录。
正文或模块变化使相关故事内容须重读，不使无关作者约束一并消失。

### 5.3 轮内压缩与溢出

安全边界是工具调用全部得到结果、下一次推理尚未发出时。将 assistant 的一组工具调用与全部
对应结果视为完整单元；任一结果缺失时保护整个单元，不能切断调用关系。
本轮原始请求、当前修改所需原文、最新错误与执行回执、范围、指纹和必读要求保持可用。

旧工具正文可以用有来源的运行摘要替换；运行时读取账本和范围控制不被重置。压缩后若需要
精确措辞或旧原文已不在有效上下文中，重新提供对应原文；摘要不新增读取覆盖。
程序校验已有读取记录仍保留，但不能据此宣称模型当前仍看得到原文。

只有供应商明确拒绝上下文且尚未接受本次推理输出时，允许整理后重发同一个推理一次。
网络超时、输出截断与普通失败不解释为上下文溢出；有部分输出或执行状态不明确时不自动重发。
已执行工具不重做，本轮原始作者消息不重加。第二次仍失败则保留实际状态并结束。

### 5.4 成本、停止与降级

预留摘要生成空间；待压范围过长时按完整轮次/闭合工具单元分段。摘要使用同次受理的模型、
空工具列表和明确输出上限；设置摘要总调用数、总输出与修复次数预算，防止反复整理。
初始预算在 U1/C1 记录并用 R1 数据调整，不作为用户必须理解的配置。

摘要为空、格式非法、引用错误或没有缩减时不启用；可在已声明预算内修复一次，仍失败保留旧投影。
预算仍能容纳时继续原任务，不能容纳时报告错误。停止信号传播到写作与摘要调用；停止后不提交
未完成摘要，已经发生的用量仍记录。不同会话与作品的摘要、锁和统计相互隔离。

## 6. 前后端接口与事件

接口沿用 `/api/file-workspaces`，应用版本升级不改接口前缀。

| 契约 | 主要内容 | 对应前端 |
|---|---|---|
| `GET /{workspace_id}/conversations/{conversation_id}/usage` | 当前有效估算、最近请求输入、累计已知用量、完整度、来源游标、活动压缩操作 | 用量栏首次加载、切回与断线恢复 |
| `POST /{workspace_id}/conversations/{conversation_id}/compact` | `request_key`；返回 202、`operation_id`、queued/running/noop，重复键返回原操作 | 上下文浮层“整理上下文” |
| `GET /{workspace_id}/conversations/{conversation_id}/compactions/{operation_id}` | 状态、摘要、来源范围、前后估算与错误；无模型调用 | 进度恢复与整理详情 |
| `POST /{workspace_id}/conversations/{conversation_id}/compactions/{operation_id}/stop` | 幂等取消排队/运行中的手动整理 | 整理中的停止入口 |
| 现有 `/api/model-connections/{name}` PATCH 与配置视图 | 增加按精确模型保存的 `model_limits`，保留 `If-Match` | 模型设置中可选容量字段 |
| 现有 SSE 与 messages 回读 | 扩展实际请求身份与 context/compaction 事件 | 同一数据流更新用量、任务状态与详情 |

全部路径均校验作品与会话/操作归属。`compact` 是操作而非创作轮次，不注入一条假的作者消息，
不创建作品提交。运行中手动请求排队并与阈值整理合并；作品空闲时进入现有执行锁，避免与受理、
写作或其他整理互相改投影。排队手动请求重启后标记中断，不自行继续付费调用。

空闲手动操作在受理时冻结当前模型；忙时排队操作绑定当前任务的受理模型，到安全边界执行。
客户端切换下轮模型不能改变已受理摘要的模型、容量或停止归属。
若原轮次正常结束前没有新的推理边界，排队请求转为空闲手动操作；作者停止原任务时一并取消绑定的整理。

新增事件：`context_usage_updated`、`context_compaction_queued`、`context_compaction_started`、
`context_compacted`、`context_compaction_failed`、`context_compaction_stopped`、`context_compaction_noop`。
字段含 `operation_id`、`turn_id`（空闲手动操作为 null）、触发原因与必要状态，不伪装 assistant 回复。
无论成功、失败、停止或 noop 都发终态；现有 SSE 按 `run_finished` 收口，需扩展为识别手动操作终态。

统计与运行状态字段同步添加到服务端视图、客户端联合类型、事件 reducer、活动分类和回读逻辑。
前端以服务端聚合为准，可本地更新视图，不再独立累计一套账。响应携带 `through_seq` 与投影指纹，
避免旧 GET 覆盖更新的 SSE；同游标的模型切换也要按模型配置版本和请求代次隔离。

HTTP 与 SSE 字段沿用现有 snake_case。前端如采用 camelCase 展示模型，由 API 层显式转换，
配套接口契约测试；不能依赖类型断言将两种字段形状直接互换。

## 7. 分阶段任务与交付条件
