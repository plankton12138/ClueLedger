## 1. 统计与配置

| 编号 | 场景 | 通过条件 |
|---|---|---|
| U01 | 四类协议的完整、部分和缺失 Usage | 未缓存、缓存读写、输出与推理不重复累计；缺值不伪装零 |
| U02 | 同一 operation 多次推送、GET 与 SSE 重放 | 请求次数、耗时和用量不重复；冲突终态留诊断 |
| U03 | 失败、停止、进行中和无数据请求 | 已发生消耗保留；未知与进行中数量可见，不用成功状态过滤用量 |
| U04 | 刷新、切会话、切作品、后台完成与断线 | 聚合一致，异步结果不串会话，旧响应不覆盖新模型/新游标 |
| U05 | 输入捕获关闭、附件过期、旧日志 | 数值仍可统计，缺数据如实标记，不要求开启原始输入捕获 |
| U06 | 模型容量未知、覆盖、配置冲突与模型切换 | 未知无百分比；精确身份匹配；If-Match 冲突保留表单；新轮次冻结新容量 |
| U07 | 输入、输出与合并窗口不同上限 | 使用正确可用输入边界，回复预留和实际运行上限一致 |
| U08 | 中文、英文、混排、长工具定义与协议开销 | 计入完整请求；方法可复算，分项估算不冒充实测 |
| U09 | 本轮多次工具调用及本轮结束 | 轮内更新；结束后按公开历史重建，不无限累加历史工具正文 |
| U10 | 草稿、临时参考、打开详情、刷新或重启 | 未受理内容不计入；统计读取不产生模型调用、写入凭据或作品修改 |

## 2. 跨轮压缩与恢复

| 编号 | 场景 | 通过条件 |
|---|---|---|
| C01 | 压缩较早完整轮次 | 新增摘要与保留边界，旧事件字节保留，近期轮次原样可读 |
| C02 | 压缩提交 seq 晚于受理 history_seq | 按来源范围应用，当前作者提示只出现一次，无越过冻结历史 |
| C03 | 最新修正、禁止事项、否定与被替代决定 | 必要原话保留；语义项有来源；新要求不被旧摘要覆盖 |
| C04 | 模型声称完成但保存失败、部分挂载、撤销 | 按实际事件呈现，不能写成已经全部完成 |
| C05 | 未回答问题与跨轮回答 | 问题 ID、回答与待办持续存在，不因较早轮次被归档而消失 |
| C06 | 用途、章节、模块版本与正文变化 | 不将未来剧情或过期观察当当前事实；涉及原文时重新读取 |
| C07 | 连续至少三次整理与原始事件重建 | 来源仍可定位，关键约束有效，状态可修正，不靠截断摘要长度完成 |
| C08 | 空摘要、格式/引文错误、无缩减、模型失败 | 候选不启用，保留旧投影；必要时给出预算错误，修复次数受限 |
| C09 | 记录写入失败、崩溃残尾、提交后重启 | 只恢复完整提交记录；不自动重新付费整理、不自动续跑写工具 |
| C10 | 旧会话无摘要、摘要格式版本不支持 | 合法兼容或明确降级；不删除公开历史，不伪造旧用量 |
| C11 | 手动整理、重复键、忙时排队、noop 与停止 | 操作幂等；与自动整理合并；原轮正常结束或停止均正确处理队列；无假作者提示；全部状态有持久终态 |
| C12 | 来源与模型配置在摘要期间变化 | 不发布错误快照，不扩大原范围；旧资料项失效与作者约束分别处理 |

现有回归包括 `test_compaction.py`、`test_compaction_service.py`、`test_context_boundaries.py`、
`test_chat.py`、`test_conversations.py`、`test_author_questions.py`。
程序校验通过只证明结构和执行边界，C03 等语义保留还需第 5 节在线评测。

## 3. 轮内与错误恢复

| 编号 | 场景 | 通过条件 |
|---|---|---|
| R01 | 多个并行工具调用、结果交错 | 调用组与全部结果作为单元；不能保留孤立结果或缺失回执 |
| R02 | 单个作者轮次很长，无较早可归档轮次 | 在合法协议边界压缩已完成前段，或明确报告必要输入超限 |
| R03 | 必改原文、读取凭据、指纹与任务范围 | 不增加授权或已读区间；仍需精确措辞时重新提供原文 |
| R04 | 明确上下文溢出后恢复 | 只重试当前尚未接受输出的推理一次，已执行写入次数不增加 |
| R05 | 普通网络失败、超时、length 与部分输出 | 不按上下文溢出自动重做，不丢弃已公开内容 |
| R06 | 摘要自身超限、连续失败或被停止 | 分段和调用预算生效；同来源失败不反复自动整理；取消传播，未完成候选不提交，已知用量保留 |
| R07 | 摘要请求与工具事件父操作 | 原写作请求和摘要请求分开关联，工具不挂到错误模型请求下 |
| R08 | 隔离与多操作竞争 | 不跨作品/会话复用摘要，手动/自动整理与新轮次按执行锁串行 |
| R09 | 必要内容本身大于可用输入 | 明确错误、可保留已完成改动，不静默移除当前请求或必要证据 |

使用脚本化 provider 驱动生产服务、真实工具和临时作品验证副作用；不能只 mock 压缩规划函数。
错误注入覆盖推理前、工具落盘后、摘要生成中、提交前后与事件重放。

## 5. 在线模型语义评测

只使用仓库 `.env` 中配置的在线模型，复用 `eval/` 的隔离作品、生产任务链路、报告与人工复核。
不使用本地模型，不把答案、期望断言或评分标准注入模型上下文。

| 用例 | 作者任务 | 重点判定 |
|---|---|---|
| E01 最新人物修正 | 多轮改变人物身份，压缩后继续写作 | 最终修正与禁止扩写项持续有效 |
| E02 讨论与确认 | 提出并否定一种作案方案，压缩后继续规划 | 助手建议、否定方案与作者决定不混同 |
| E03 实际进展 | 制造部分保存或挂载失败，再要求继续 | 不宣称全部完成，只处理实际未完成项 |
| E04 待回答问题 | 必要提问被较早历史覆盖，再回答 | 恢复对应原问题并继续原任务 |
| E05 章节与版本 | 已讨论后期真相，转做前章事实提取；另修改原文 | 未来计划与过期内容不作为当前证据 |
| E06 多次整理 | 在连续创作中至少触发三次压缩 | 约束与任务续接正确，来源能够回查 |
| E07 长单轮工具过程 | 一次请求读取多份材料并修改指定模块 | 轮内可继续，不漏必要原文，不重复产生修改 |
| E08 溢出与停止 | 在在线内容任务上注入可确定的拒绝/取消边界 | 恢复边界符合程序验证；在线部分验证整理后语义可继续 |

已新增 `eval/cases/v09.yaml`、`eval/suites/v09-context.json`，并在 schema/runtime 中登记
压缩触发阈值覆盖和 `no_compaction` 对照。此次在线窗口未知，使用显式整理，不伪造自动触发。
阈值覆盖只降低整理触发点，不伪造模型真实容量，两个方案使用同一在线模型和任务。
确定性错误注入用于精确验证副作用，不能冒称真实供应商在线溢出的覆盖证据。

报告保存任务完成结果、关键约束遗漏、不实完成结论、原文引用、压缩次数、前后有效输入规模、
全部模型用量（含摘要）、摘要耗时和任务总耗时。没有供应商用量时标记不可比较，不能补估算成本。
比较同一续接任务的有压缩/无压缩结果；语义有歧义的项目保持 `pending_review`，人工复核后才判通过。

E01–E08 全部通过，E06 多次整理有证据，且没有新增授权越界或重复写入，才允许完成 R1。
压缩率较高不能代替任务正确。有限在线案例通过不表述为“不会遗忘”或完整自然语言正确性证明。
