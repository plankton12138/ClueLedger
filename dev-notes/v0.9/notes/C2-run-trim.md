# C2 第一片：轮内裁剪

日期：2026-10-27。阶段：C2（轮内压缩、安全边界与单次溢出恢复）。状态：**已完成**。

本片交付的是「一次请求装不下时，先丢掉最不需要的部分」：按完整工具单元裁剪，
只改请求副本，不调用模型。供应商明确拒绝上下文时的一次重发见第 6 节。

## 1. 为什么轮内不生成摘要

跨轮压缩会把旧讨论概括成一段话，因为那些轮次之后还要被反复引用。轮内不一样：
工具往返里的旧正文大多已经过期——文件改过、章节重写过，模型真需要时会重新读取。

为此再调用一次摘要模型有三个代价：慢（每次超限都多一次往返）、贵（同一轮可能多次触发）、
可能递归（摘要请求自己也可能超限）。所以轮内只做确定性的丢弃，不做概括。

这带来一个必须说清楚的边界：**读取凭据与任务范围不会因为消息被裁而失效**——它们保存在
应用自己的账本里，不在这份消息列表里。但模型确实看不到被裁掉的那些原文了，
需要时只能重读。记录里不把这一点写成「仍可访问」。

## 2. 切点只在完整单元上

一个单元是「一条助手消息 + 它要求的全部工具结果」。三种情况整段不裁：

| 情况 | 后果 |
|---|---|
| 助手要求了 3 个工具，只收到 2 个结果 | 切在这中间会让供应商收到残缺请求 |
| 工具结果找不到对应的调用 | 同上，而且说明这段历史本身已经不一致 |
| 只有一个单元，或保留量覆盖全部 | 没有可裁的内容 |

残缺时宁可让请求超限、由供应商拒绝，也不发一份结构错误的请求——后者的报错信息
通常无法指向真正原因。

## 3. 只在请求副本上裁

裁剪发生在请求记录器里，处理的是即将发出去的副本。harness 手里的消息列表不动：
它下一轮还会带着完整历史，届时重新判断要不要裁。

这样做的原因是 harness 是便携核心，不该为了压缩改造它的内部状态；而每次请求前都重新
估算，裁剪结果本来就只对那一次请求成立。

窗口未知时不裁：没有可比的边界，裁多裁少都是猜。

## 4. 事件里留下痕迹

`model_request_started` 增加 `request_trim`（仅在实际裁剪时出现）：

```text
dropped_messages / tokens_before / tokens_after
```

有了它，「这一轮为什么少了几条工具结果」不用靠猜。记录的是裁剪前后的估算值，
不是供应商的实测值。

## 5. 验证

```text

uv run pytest tests/workspace/test_activity.py      → 27 passed
uv run pytest tests/workspace/test_chat.py          → 41 passed
ruff、mypy                                           → 干净
```

覆盖：裁剪保留最新单元与当前提示、调用与结果数量始终配对、残缺单元不裁、孤立结果不裁、
预算充足不裁、单单元不裁、非正预算不动；接入层覆盖超限裁剪与窗口未知不裁两条路径，
以及「调用方手里的列表不变」。

## 6. 溢出后的单次重试

供应商明确拒绝上下文时，`RecordedProvider` 在**尚未接受任何输出**的前提下收紧一次：
把保留量减半后重新切分消息，重发同一个推理，并写入 `model_request_retried`：

```text
reason / tokens_before / tokens_after / dropped_messages / message
```

三条边界：

| 情况 | 行为 |
|---|---|
| 已经输出过文字或工具调用 | 不重发，避免两段互相矛盾的半成品 |
| 连最新一轮都放不进更小的窗口 | 不重发，错误照常上抛，不无限重试 |
| 网络超时、限流、输出截断 | 不识别为溢出，按普通失败结束 |

窗口未知时也允许重试：拒绝本身就是「装不下」的证据，不需要先猜到确切容量。识别只认
错误文案里明确指向长度或容量的措辞；未覆盖的措辞仍按普通失败处理，这是已知局限。

在线证据见 E08（`eval/runs/context-20261027-144609-398337/`）：注入一次拒绝后，请求估算
从 19610 降到 11573、丢弃 23 条消息，重发成功；同一条用例还验证了停止一轮后下一轮能
识别「上一轮没有留下文字」并补写。

## 7. 未完成

- **长单轮分段**：一个单元本身超过预算时，轮内没有可用切点。本片的选择是让它照发、
  由供应商拒绝，而不是切断工具对。分段读取属于材料侧的能力，未在本版实现。
- **自动触发**：本片只在超预算时裁剪，还没有「接近上限就整理较早轮次」的自动压缩；
  那是 C2 的另一半，依赖跨轮压缩在运行中的调用时机。
- **浏览器与在线验收未做**（在线报告仍待复核）。
