# 0.9 完成情况检查后的修复

日期：2026-10-27。版本 `0.9.0`，状态仍为发布候选。

这次修复让用量显示、实际模型输入和整理操作使用一致的会话边界。作者切换会话后应看到该会话的数字；整理完成后应看到后续写作的有效上下文；停止整理只取消摘要工作。

## 已修复

| 问题 | 当前行为 | 主要位置 |
|---|---|---|
| 跨会话比较事件游标，低序号会话不更新 | 按作品与会话重建组件状态；旧异步响应无法覆盖新会话 | `ConversationUsageBar.tsx` |
| 摘要请求覆盖写作上下文数字 | 摘要独立计入累计；空闲上下文按有效公开历史、摘要和写作约定重新估算 | `conversation_usage.py` |
| 停止接口没有界面入口，刷新后操作丢失 | 提供停止按钮；用量接口携带最新操作；事件持久保存操作和幂等键，重启关闭未完成操作，不重复调用模型 | `compaction_ops.py`、`api.py` |
| 自动整理缺失 | 已知容量达到可用输入的 90% 时，在已受理任务的请求边界整理；同一受理历史最多自动尝试一次 | `context_boundary.py` |
| 摘要自身过长或连续调用无上限 | 按完整轮次分段，最多四次摘要调用，全部成功且候选通过校验后只提交一次 | `context_summary.py` |
| 裁剪可能移除当前原始要求 | 始终保留当前作者提示、有效摘要及最新完整工具单元；必要输入仍超限时返回明确错误 | `compaction.py`、`model_activity.py` |
| 手动整理与写作竞争模型和锁 | 绑定受理轮次的冻结模型，在工具结果完成后的请求边界或正常收尾执行；停止写作传播取消 | `service.py`、`compaction_ops.py` |
| 浮层遮挡输入，窄屏缺证据 | 按输入区上边界定位、限制高度和宽度；Escape 恢复触发按钮焦点 | `ConversationUsageBar.tsx`、`index.css` |
| 评测漏算空闲摘要请求 | 按事件游标捕获全部新请求；加入不整理对照、摘要用量与耗时分项 | `eval/harness/` |

单个不可拆分的必要输入超过容量时，返回 `[CONTEXT_REQUIRED_INPUT_TOO_LARGE]`；不会靠丢弃当前作者要求或截断必要原文继续。长单轮当前采用完整工具单元裁剪与明确超限处理，没有另行生成轮内工具摘要。

摘要携带来源、原话与类型；投影包含这些条目。原始公开事件不删除。模型配置在受理时冻结；容量未知时不猜窗口，也不自动触发整理。供应商明确拒绝后的单次恢复仍可执行。
