# 运行追踪开发计划

更新于 2026-11-08。首版已实施，发布版本待定。

## 1. 产品目标

活动记录需要回答三个问题。用户发起的这一轮最终怎样结束，时间花在哪些步骤，中途的失败是否恢复。查看时先选会话，再选作者发起的 Turn，最后查看该轮的执行事件。

Turn 是一次作者请求及其执行结果。Loop 是 Turn 内一次模型回合，通常包括模型请求和随后的工具调用。同一个 Turn 可以包含多个 Loop。Loop 折叠时保留耗时、调用数和结果，展开后可查看具体步骤。一次工具调用超时后重试成功，应保留两次调用和各自的结果，整轮结果仍由 Turn 的结束记录决定。

首版覆盖有明确会话和 Turn 归属的执行。文件版本和无会话的作品操作继续从「活动记录」查看。

## 2. 查看流程

1. 顶栏「活动记录」内新增「运行追踪」视图，优先打开当前会话的最新一轮。当前会话没有 Turn 时，提示选择其他会话。
2. 左侧选择会话及其 Turn。Turn 列表显示请求摘要、开始时间和耗时。窄屏将两级选择移到时间线上方。
3. 主区显示作者请求、整轮结果、总耗时、Loop 数、工具调用次数和已记录的 Token 用量。下方每行对应一条事件，整轮共用从零开始的甘特时间轴。
4. Loop 默认折叠，支持逐组切换与展开或折叠全部。展开后的子事件沿用整轮刻度。开始位置表示事件何时发生，条长表示实际耗时，重叠的条表示观测到的时间重叠。Gate 的决策用时间点表示。
5. 选中事件后显示开始、结束、输入摘要、结果和可用详情。工具调用显示参数与结果，模型请求显示模型、用途、结束原因和实测用量。Gate 显示检查项、判定及可公开的原因。

交互验收沿用预览里的两种情形。核对章节时间线时，Loop 2 有一次工具调用超时，随后重试成功。折叠后显示「已恢复」，展开后分别看到失败和重试。另一轮的正文写入请求在权限检查处被拦截，时间线保留 Gate 和判定原因。

## 3. 事件记录契约

沿用会话日志作为事实来源，活动索引负责查询和重建。新增事件统一记录归属、身份、时间和结果，服务端将原始开始与结束事件合成为一条展示记录。

| 类型 | 记录来源 | 展示规则 |
| --- | --- | --- |
| Loop | Agent 每次模型回合的开始与结束 | 记录回合序号和整体结果。通过明确的父事件标识关联子事件。 |
| Model | 现有模型请求开始与结束 | 以请求标识配对。记录模型、用途、结束原因、实测用量和可用的输入详情。 |
| Tool call | 现有工具调用开始与结束 | 以调用标识配对。每次重试有独立标识，能够确认重试关系时引用原调用。 |
| Gate | 实际权限、写入范围或预算规则作出决策的位置 | 点事件，判定为通过、拦截或跳过。判定需要作者确认时，Turn 按执行事实显示等待或结束。 |
| Retrieval、Write、Reply | 已记录的上下文装配、写入回执、回复边界 | 有真实边界时绘制时段。仅有单次观测时显示时间点，并标明记录类型。 |

同一 Turn 内以 `span_id` 作为展示事件的稳定标识，`parent_span_id` 关联父事件。开始和结束原始记录各有独立事件标识，并以会话序号去重和排序。重试通过 `retry_of_span_id` 关联首次失败或前一次尝试。只有 Loop 完成且已确认相关失败恢复时，才显示「已恢复」。

以下为单轮快照 `events` 中一条失败调用的示例。契约版本放在快照的 `schema_version`。

```json
{
  "span_id": "verify-timeline-1",
  "parent_span_id": "loop-2",
  "kind": "tool_call",
  "name": "核对时间线",
  "start_offset_ms": 16900,
  "duration_ms": 6100,
  "status": "failed",
  "error_code": "TOOL_TIMEOUT",
  "start_event_id": "evt-41",
  "finish_event_id": "evt-42"
}
```

- **时间。** 原始事件记录实际观测时间。同一执行阶段内用单调时钟计算耗时，查询结果统一返回相对 Turn 起点的毫秒偏移。整轮总耗时按 Turn 边界计算，包含观测到的等待。跨重启或缺少结束记录时，只展示能确定的时间和状态。
- **结果。** Turn 以轮次或任务状态为准，区分等待作者确认、主动停止和异常中断。Gate 的判定与执行错误分别表达。写入以已有写入回执为依据。
- **统计。** 工具次数按独立调用标识计数，包含重试。Token 用量只汇总实际返回的模型请求用量。有缺项时标为部分记录，全部缺失时显示「未记录」。金额和扣点由现有计费记录表达。
- **详情。** 延续现有脱敏、模型输入快照开关和附件保留规则。列表及时间线返回摘要和详情引用，选择事件后读取详情。详情过期后仍可查看事件摘要。
- **历史。** 新执行写入新契约。历史 Turn 缺少追踪字段时显示「未记录运行追踪」，可回到原始活动记录查看已有事实。

## 4. 实施模块

### P0 盘点执行边界并冻结契约

- 从 [运行循环](../../src/tau_agent/loop.py) 和 [写作服务](../../src/hastings/workspace/service.py) 核对普通对话、确认续接、主动停止和异常退出。运行循环已经发出回合开始与结束信号，写作服务目前用开始信号统计回合数。确定哪些入口经过该循环，哪些仅产生独立的模型或工具事件。
- 对照 [模型请求记录](../../src/hastings/workspace/model_activity.py) 和 [现有活动记录](../v0.6/modules/activity-log.md)，确定可复用的请求、调用和详情标识。列出首批 Gate 及其真实决策位置，统一判定和原因的字段。
- 固定开始、结束、拦截和重试四类样例，作为前后端共用的验收输入。

### P1 采集并生成每轮追踪

- 在真实回合开始、结束处记录 Loop。模型请求及工具调用在发起时绑定当时的 Turn 和 Loop，完成时携带原身份。事件归属在调用边界确定，避免异步队列消费时读到下一回合的上下文。
- Gate 在规则得到实际结果时记录。一次规则判断只生成一条事件。工具或模型重试沿用现有执行策略，记录本次身份和可确认的来源。
- 在 [活动索引](../../src/hastings/workspace/activity.py) 生成 Turn 摘要及事件投影。用同一批原始事件重建索引时，投影的事件身份和归属保持一致。停止或重启时扩展现有恢复逻辑，标记仍在执行的事件；未确认的文件副作用由写入回执或版本记录核对。

### P2 对齐查询接口与页面

拟议接口均位于 `/api/file-workspaces/{workspace_id}` 下，并沿用 [现有作品接口](../../src/hastings/workspace/api.py) 的作品与会话归属校验。

| 接口 | 页面用途 |
| --- | --- |
| `GET /conversations` | 复用会话列表及当前会话信息。 |
| `GET /conversations/{conversation_id}/turns` | 新增按会话分页的 Turn 摘要列表，返回请求摘要、时间、状态和追踪可用性。 |
| `GET /conversations/{conversation_id}/turns/{turn_id}/trace` | 新增单轮快照，返回 Turn 摘要、事件、时间轴范围和与快照一致的续传游标。 |
| `GET /activity/stream` | 按会话和 Turn 订阅运行中的活动。收到相关增量后刷新快照，断线或索引代次变化时重新同步。 |
| `GET /activity/{event_id}` 和 `GET /activity/attachments/{key}` | 复用事件与附件的按需读取。 |

从 [活动记录面板](../../frontend/src/components/workspace/ActivityPanel.tsx) 进入新视图。页面按稳定标识维护选中事件和 Loop 展开状态，切换会话或 Turn 后丢弃旧请求的迟到结果。时间条的位置和宽度分别由起始偏移、耗时除以当前 Turn 的时间轴范围得到。展开、折叠和选中事件都使用同一比例。

### P3 专项验收

| 情形 | 验收结果 |
| --- | --- |
| 切换会话和 Turn | 标题、时间轴和详情归属一致。当前会话没有 Turn 时显示空状态。 |
| 展开和折叠 Loop | 子事件缩进清楚，共用时间刻度。折叠后父行仍显示耗时与结果。 |
| 调用失败后重试成功 | 两次调用独立可查，失败原因保留，Loop 可显示「已恢复」，Turn 显示实际终态。 |
| Gate 拦截 | 显示决策时间、检查项和原因。仅展示实际发生的后续事件。 |
| 运行中断、重连和索引重建 | 已记录事件无重复，详情归属稳定，缺失数据明确标注。 |
| 作品隔离和详情过期 | 其他账号无法通过列表、快照、订阅或附件读取记录。过期附件的事件摘要仍可查。 |
| 窄屏与键盘操作 | 可完成会话选择、Loop 展开和详情查看，时间轴与状态可读。 |

先用确定性事件样例覆盖排序、配对、重试、恢复和浏览器交互，再使用 `.env` 中配置的在线模型做单例验收，确认真实模型请求、工具事件和可用的实测用量能关联到正确的 Turn。模型链路失败时先修复，再复跑同一单例。

## 5. 首版实施记录

- 「活动记录 → 运行追踪」已接通单轮快照、会话内的分页轮次列表和运行中的事件订阅。事件流与文件版本仍可从同一面板访问。
- Gate 已接入写入资格和模型输入预算。供应商拒绝上下文后，现有的收紧重试记录为两次模型尝试。工具调用在来源显式提供关联时显示为重试；普通重复调用分别展示。
- 浏览器用真实接口读取确定性日志，覆盖会话切换、Loop 键盘展开、失败参数详情、重试恢复、Gate 拦截和窄屏。两账号测试覆盖追踪列表、快照、订阅和附件的作品归属校验。
- 在线只读单例完成两个 Loop、两次模型请求和一次 `read_file`，输入 4,497 Tokens、输出 87 Tokens。模型请求和工具调用归属均与各自 Loop 一致。
