# 线簿 / ClueLedger 功能地图（Feature Map）

从作者描述的界面或操作出发，找到入口、可重复执行的测试，以及判定通过需要的证据。首批覆盖写作台的三条路径，不是全量产品清单，也不评估模型写作质量。

| 作者怎么说 | 功能 |
| --- | --- |
| 「想直接改稿纸」「看差异」「我取消了，正文不该变」 | [手工修订](#手工修订) |
| 「点灯泡，把这条灵感带进聊天」「加引用时别把草稿发出去」 | [灵感加入对话](#灵感加入对话) |
| 「换个对话」「切回来草稿还在吗」「引用跑到另一个对话了」 | [切换会话](#切换会话) |

## 怎么验证

按[源码运行文档](../SETUP.md#安装依赖)安装依赖，确认 `git` 可执行，再在 `frontend/` 目录运行 `npx playwright install chromium`（首次运行时）。下文命令也都在 `frontend/` 执行；浏览器用例会启动真实本地服务并准备测试作品，不调用在线模型。运行前可追加 `--list` 确认选中了预期用例，再去掉它执行。

- 隔离运行时，设置 `HASTINGS_E2E_PORT` 为未占用端口、`HASTINGS_E2E_DATA_DIR` 为临时目录，避免复用默认服务和测试状态。设置 `HASTINGS_E2E_SCREENSHOT_DIR` 可将用例主动保存的截图写到临时目录，避免改动仓库内的截图。
- 浏览器用例失败时保留 Playwright trace；需要保留成功过程时追加 `--trace on`。核对保存、隔离和未发送等行为时，以断言为准，不用单张截图代替。

## 手工修订

- **入口**：写作台 → 左侧目录选一章已有正文的章节 → 对话区「修改正文」→ 编辑稿纸 →「看差异」。
- **通过证据**：差异中有新增和删去的内容；点「确认修改」后稿纸显示新正文，修订接口可读回作者修订。再次编辑后点「取消」并确认「丢弃修改」，稿纸仍显示上一次确认的版本。若编辑期间正文被别处更新，界面提示冲突并保留当前编辑内容。
- **测试**：[稿纸修订用例](../frontend/e2e/writing-workbench.spec.ts#L250)还会保存编辑、差异和确认入稿三张截图。

```sh
npm run test:e2e:local -- writing-workbench.spec.ts -g "稿纸修订模式"
```

## 灵感加入对话

- **入口**：打开作品，在写作台对话框留一段未发送的文字 → 点浮动「灵感」（也可用 `Alt+I` 打开）→ 在一条已有灵感旁点「加入对话」，或输入新灵感后点「记下并加入对话」。
- **通过证据**：对话区出现引用，原草稿文字不变；点「查看引用的灵感」能看到长灵感全文。整个过程没有新建会话或启动一轮对话的请求。
- **测试**：[连续加入灵感用例](../frontend/e2e/ideas-companion.spec.ts#L60)通过浮动按钮进入，覆盖已有灵感和新记灵感两个入口；不验证快捷键。

```sh
npm run test:e2e:local -- ideas-companion.spec.ts -g "列表直接连续加入"
```

## 切换会话

- **入口**：同一作品至少有两条已有对话。进入写作台，在对话区顶部的「选择对话」下拉框中从 A 切到 B，再切回 A。
- **通过证据**：切换前保存 A 的未发送草稿，切到 B 不显示 A 的事件。在 A 点「加入对话」，若灵感还在读取时切到 B，完成后提示当前对话已切换，A、B 都不新增这条引用。
- **测试**：[会话状态测试](../frontend/src/state/conversations.test.ts#L348)验证草稿保存和事件归属；[迟到引用浏览器用例](../frontend/e2e/ideas-companion.spec.ts#L178)用受控会话列表和延迟响应验证不会串入草稿，不证明真实模型任务的切换行为。

```sh
npm test -- src/state/conversations.test.ts -t "切换会话"
npm run test:e2e:local -- ideas-companion.spec.ts -g "读取期间切换对话"
```

## 维护

UI 入口、用例名或通过条件改变时，同一改动里更新对应条目。新增条目至少交代作者用语、操作入口、验证命令和证据；暂时没有自动化覆盖的行为标为手验，不借相邻用例宣称已覆盖。
