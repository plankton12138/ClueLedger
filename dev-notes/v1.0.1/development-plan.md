# 1.0.1 开发计划

日期：2026-10-30。状态：**六项缺口已修复，后端全量与浏览器复验通过；在线受影响场景与作者体验待执行**。主包、前端及锁文件统一为 `1.0.1`；修复记录见[授权与采用修复](notes/2026-10-30-authorization-adoption-fixes.md)，修复前缺口见[阶段质量检查](notes/2026-10-30-quality-audit.md)，前一收尾批次的[验收证据](artifacts/acceptance-matrix.md)保留原结果。以下保留原阶段划分与完成标准。

## 1. 产品目标与范围

作者从空白作品就能提出谜题、片段或结局，由 Agent 形成可分支、汇合与收束的创作结构。结构持续参与写作，正文提供实际呈现依据。作者用自然语言修改，应用处理关联、版本与恢复。

写作区提供构思／正文切换和同一个对话区。取消独立故事资料，减少表单和参数，以当前安排、正文位置和可继续操作的结果为主体。产品依据见[全流程](../../product-design/v1.0.1/structure-and-agent-lifecycle.md)和[页面设计](../../product-design/v1.0.1/page-design.md)。

本版必须完成：

1. 稳定的线索、节点、关系与约定；空白构思无需正文依据，真相允许未定。
2. 故事内分支与独立创作备选；方案差异查看、整案或选定片段采用。
3. 实际事件时间与揭示顺序分开，角色知情与作者真相分开。
4. 每次重建有效模型输入，压缩、换会话、重开应用后仍沿用当前结构与约定。
5. 对话创建／修改结构、写场景、核对、有限局部修正、正文关联与可撤销结果。
6. 全部模型入口真实流式、立即暂停、继续与插话；断线和刷新不重复执行。
7. 故事资料的页面、导航、专用接口与任务退出，必要内部能力重新归属。

首版采用自动排布、选择、片段折叠和对话指令。任意自由拖线、同时展示全书两套时间轴、多人协作和复杂版本合并界面不作为首版门槛。局部采用仍需支持，通过对话分析依赖完成。

独立桌面应用、安装包、旧数据兼容与迁移、自动学习跨作品写作偏好排除。本书明确约定的持续使用属于本版，1.1 修订学习继续独立。

## 2. 当前代码基线

以下为 2026-10-28 阅读源码所得，不是本版完成记录。

| 位置 | 当前能力或缺口 | 本版处理 |
|---|---|---|
| `workspace/clue_models.py`、`clue_store.py` | 稳定身份、正文贡献、版本与单账本原子写入 | 借鉴保护机制，新增构思格式，不沿用依赖章号的起步流程 |
| `clue_context.py`、`materials.py` | 精确引用、实际读取覆盖和来源冻结 | 扩展方案、节点、约定与依赖装配 |
| `service.py` 的 `WriteSession` | 先改文件后记历史，无正文与结构跨文件事务 | 引入工作副本及提交协调器，历史仍在提交后处理 |
| `service.py` 的 `stop` | 有取消，尚无统一继续、插话和代次隔离 | 持久任务控制，阻断迟到输出与写入 |
| `context_summary.py`、`compaction*.py` | 已有压缩与用量管理 | 有效结构独立重装；模型整理过程进入可见任务 |
| `state.py`、`activity.py`、`model_activity.py` | 会话事件、游标与实际调用记录 | 复用来源，不另建矛盾的任务事实 |
| `api.py`、`server/model_api.py`、`model_probe.py` | 会话事件与停止；连接测试返回汇总 | 扩展统一操作；真正调用模型的连接测试也接入 |
| `AppHeader`、`WorkspaceShell`、`navigation` | 故事资料仍可进入和挂载 | 删除入口、路由、页面与位置记忆 |
| `ChapterClues`、`materialTasks` | 本章线索依赖旧资料任务 | 同批替换为构思与统一操作 |
| `WritingLayout`、`Paper`、`ConversationPanel` | 阅读、选段、对话、字号与分栏 | 接入构思、定位和任务控件，保留草稿与灵感体验 |
| `frontend/playwright.config.ts` | 用例显式白名单，在线与无模型项目分开 | 新用例登记，沿用零自动重试 |

实施前重新记录工作树，保护已有灵感与视觉改动，不将其他工作计入本版成果。

## 3. 模块划分

文件名可按体量调整，但职责和契约不能省略。业务改动留在 `hastings`，不重写通用模型内核。

| 模块 | 拟议位置 | 输出 |
|---|---|---|
| 结构与存储 | `workspace/story_models.py`、`story_store.py` | 方案修订、线索、节点、关系、约定与隔离 |
| 提交与依赖 | `workspace/story_changes.py`、`story_projection.py` | 工作副本、日志、来源、失效、影响与撤销 |
| 模型输入 | `workspace/story_context.py`，接入 `materials.py` | 必需依赖、实际输入、容量处理与试读隔离 |
| 统一任务 | `operations/models.py`、`store.py`、`runtime.py`，接入 service | 持久操作、代次、流式事件、暂停／继续／插话 |
| Agent 与核对 | `workspace/story_tools.py`、`story_review.py`，接入 agent | 有范围的变更、候选正文、证据与有限修正 |
| 服务接口 | `workspace/story_api.py`、`server/operation_api.py` | 结构操作、任务控制、依据与结果 |
| 页面 | `api/story.ts`、`api/operations.ts`、`state/story.ts`、`state/operations.ts`、`components/story/` | 构思图、详情、方案、任务控件和正文往返 |
| 旧功能清理 | 原 materials 页面、状态、API 与工具注册处 | 无旧入口、无双重维护，写作正常 |

唯一字段说明见[数据契约](data-and-runtime.md)，前后端见[接口契约](api-and-frontend.md)，关键实现见[代码示例](implementation-examples.md)。

## 4. 阶段依赖和完成条件

顺序：**P0 → P1 → P2 → P3 → P4 → P5 → P6 → P7**。每阶段留下代码、相关验证与实际记录；不用耗时估计代替完成条件。

### P0：固定基线、格式与调用清单

- 记录版本和工作树，登记 1.0 剩余体验问题。
- 固定字段、API、事件与错误格式，建立共享请求／响应样例。
- 从所有模型调用反查 UI，覆盖写作、构思、模块、灵感、核对、摘要、压缩、试读与模型连接测试。
- 建立无正文、长距离依赖、备选、倒叙、证词、emoji 定位样例。
- 列出旧资料域的全部调用方与替代归属。

完成条件：每个按钮有服务能力，每个服务入口有调用方；普通操作与模型调用可区分，没有未归属的旧资料依赖。

### P1：结构与一致性基础

- 新格式初始化、稳定作品身份、方案修订和备选隔离。
- 节点、线索、关系、知情、约定和正文关联；允许合法未定。
- 引用与范围校验，推进／实际时间无环校验，重新解释可指回前文。
- 工作副本、提交日志、请求去重、故障恢复、失效与撤销。
- 分离应用提交与 Git 补记，历史失败不重复执行模型。

完成条件：并发修改、每步崩溃、外部改文件、同键重试均不会被误报为完整成功；备选不改变主方案。暂停竞态在 P2 接入后补齐。

### P2：统一模型操作与恢复

- 现有轮次接入统一操作视图，复用事件来源；各模型阶段属于同一可见操作。
- 区分真实文本增量、工具进度、完整候选与提交结果。
- 暂停撤销代次资格、继续新代次、插话原子受理、等待作者回答、失败保留草稿。
- 压缩、写后核对、模块、灵感与连接模型测试使用同一控制契约。
- 统一前端控件，窄屏对话收起也能暂停。

完成条件：每个模型入口可见、可暂停、可继续与插话；迟到结果无效；刷新不再次调用模型。能力测试的插话只调整测试目标，不改凭据或伪造测试结果。

### P3：长期连续性与实际输入

- 按任务、方案、位置、约定与依赖装配必需内容。
- 分开作者真相、计划、正文观察、证词与模型判断；实际请求与读取范围对齐。
- 记录实际发送内容、版本、覆盖与省略理由，按需可查。
- 压缩、换会话与恢复后重装当前结构；过期摘要回读原文或报告缺口。
- 试读独立历史和工具范围，过滤标题、摘要、缓存及问题中的剧透。
- 超容量拆分任务；最小单元仍放不下则停止依赖部分。

完成条件：必需长距离线索进入实际请求；旧版、其他备选和未来信息不错误注入；新会话无需作者重复粘贴全部设定。

### P4：Agent 创作与修改闭环

- 实现结构读取、原文查询、变更提议、候选正文与核对工具；授权由应用持有。
- 空白构思、延伸、分支、汇合、备选、局部采用通过同一对话执行。
- 明确修改直接执行范围内改动；讨论保留候选；只有取舍冲突才提问。
- 候选正文核对必需呈现、保留信息、角色知情、作者真相和必要前提。
- 默认一次局部修正加一次复核；仍有关键问题保留草稿并询问。
- 正文与有效关联成组提交，合法空结果与核对失败分开。

完成条件：真实完成“构思 → 写场景 → 插话 → 联动修改 → 定位 → 撤销”；模型不能改写约束来通过检查。

### P5：页面接通并移除故事资料

- 构思／正文切换、稳定对话、就近详情、自动布局、片段折叠和节点／片段引用。
- 方案切换与差异查看，正文定位与返回，多段来源按实际内容呈现。
- 切换保留草稿，浏览不重定向正在执行的任务。
- 同批执行下方移除清单，内部来源与知情能力接到新任务。

完成条件：真实后端驱动页面，无演示数据冒充成果；旧页、旧 API 和旧工具退出；阅读、模块、灵感与写作仍正常。

### P6：真实使用与在线评测

- 按[验收清单](acceptance.md)执行故障、事件、来源、浏览器与在线验证。
- `.env` 在线模型评测，不使用本地模型，保留所有尝试及失败。
- 覆盖长篇、方案隔离、试读、回写前章、重复继续、断线与服务重启。
- 修正后重跑受影响项，改版后的语义结果单独统计。

完成条件：确定性要求全部通过，语义达到门槛，严重越界和隐形模型调用为零；作者体验验收独立记录，不由模型评分替代。

### P7：文档、版本与交付判断

- 更新实际模块、操作、格式和错误说明，清理当前文档中过期入口。
- 实现与验证完成后主包和前端统一为 `1.0.1`，桌面包排除。
- 汇总证据、限制、失败与人工体验结果，区分开发完成、待验收和可发布。
- 根 README 需作者另行要求才改；`mynotes/` 不改；历史措辞不回改。

完成条件：实现、接口、页面、测试和当前文档一致，无未关闭的必需事项才标记完成。

## 5. 故事资料移除清单

| 当前内容 | 处理与替代 |
|---|---|
| AppHeader／WorkspaceShell 的资料入口与挂载 | 删除，构思进入写作内视图 |
| navigation／pagePositions／来源返回中的 materials 类型 | 删除；未知旧 URL 回普通写作，不设兼容页 |
| StoryMaterialsPage、分域浏览／整理、MaterialTaskBar | 删除；仍需的共用定位组件先转到使用方 |
| state/storyMaterials、api/storyMaterials、state/materialTasks | 调用方替换后删除，不留空客户端 |
| ChapterClues 的全部线索与整理本章 | 转为当前构思及明确启动的核对任务 |
| `/story-materials/*`、`/story-events`、`/material-tasks*` | 删除专用 API，结果由结构与统一任务读取 |
| material_tasks.py、materials 工具模式 | 删除旧入口，提取能力归新任务阶段 |
| story_materials.py 的 CoverageStore、标签等共享逻辑 | 沿调用关系拆至来源／投影职责后删旧装配，不能整文件盲删 |
| 原 clues API、计划关联、推理表单及专用工具 | 定位与核对能力接入新结构，撤掉复杂配置与重复维护接口 |
| state、章节索引、角色／披露／词汇内部能力 | 按真实写作调用保留必要读取，统一来源与失效，不重复注入旧推测 |
| 当前帮助、文案、浏览器用例 | 改到新流程；历史记录保留版本身份 |

旧数据不迁移，新格式不读取旧账本或旧会话事实来恢复废弃方案。现有正文仍可阅读，作者明确要求分析已有正文时按新任务重建；不后台调用模型重抽取。
