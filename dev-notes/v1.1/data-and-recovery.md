初稿：2026-10-26；更新：2026-10-27。状态：**待实施**。本文是新增记录结构的单一出处。
接口见[接口与前端](api-and-frontend.md)，阶段见[开发计划](development-plan.md)。
写作约定的文件内容与生效规则以[写作约定文档契约](style-document.md)为准。

## 1. 权威来源

| 内容 | 权威来源 |
|---|---|
| 当前正文 | 作品目录中的 Markdown 文件 |
| 当前写作约定文本、条件、例外与声明范围 | 作品根目录的 STYLE.md；规则详情编辑同一文件 |
| 正文版本 | 作品自己的真实 Git 仓库 |
| 会话与公开执行事实 | 现有会话事件 |
| 编辑操作、草稿、学习、偏好决策、停用与排除 | 本文规定的作品内新增记录；已启用文本索引由 STYLE.md 派生 |
| 模型实际使用偏好 | 与真实请求绑定的使用回执 |
| 活动列表 | 上述记录的可重建索引，不作为唯一恢复数据 |

新增记录不成为第二份正文主库。前后快照用于说明一次修改和恢复操作，不能直接覆盖当前正文。
索引、历史或使用快照也不能替代缺失或非法的 STYLE.md 继续提供旧约定。

## 2. 存储、身份与生命周期

1.0交付的workspace_lineage复用为本文workspace_uid，不再为同一作品生成另一份身份；
线索记录和人工修订记录分别管理并引用同一作品。新增document_uid、数据库和保存流程仍须在G0按1.0实际能力重新核对。

拟放在 `workspace_state_root(state_root, workspace_id)/revisions.sqlite3`。
使用 Python 标准库 SQLite，短连接、显式短事务、参数绑定、外键、格式版本 1；
初始用 DELETE journal、FULL 同步和有界 busy timeout，暂不引入 WAL 与独立数据库服务。
原因是草稿、并发决策、去重、证据失效及操作完成需要一致提交，而不是引入新的作品内容体系。

首次显式编辑、设置写入或实际写作请求记录约定使用时初始化；纯 GET 不悄悄创建数据库或调用模型，
无记录时返回空候选/历史，已有 STYLE.md 仍可返回只读解析视图。
已有文件格式高于可识别版本、损坏或权限不足时明确错误，不将坏库解释为空库。
正常阅读和导出正文仍可用；编辑事务无法安全记载时不开始正文写入。

内部关系使用稳定 `workspace_uid` 和 `document_uid`。路由 `workspace_id` 仍用于当前路径登记，
改名后变化，但不重写所有证据外键。文档 UID 随受管移动维护，不能仅按相同文件名重绑。
复制一个作品目录不复制应用状态，因此默认新身份；状态备份恢复须核对作品身份与版本。

本版直接建立新格式，不开发旧偏好和学习记录迁移；不兼容记录明确报错，不静默解释为空库。
重新初始化只处理应用学习记录，保留作品正文与 STYLE.md；发布前验证冻结后的 sidecar 包含 SQLite 支持。
改名/删除前停止调度、取消分析、等待状态发布完成并关闭连接，再迁移/删除整部作品状态。

会话草稿、文档历史、偏好状态和来源引用。轮次使用快照仅保存该轮允许的规则版本，
与运行时可撤销过滤分开；忘记时清理其可控正文副本。

## 4. 状态分开管理

| 维度 | 取值 |
|---|---|
| 编辑会话 | open / closed / discarded |
| 文件保存 | saved / no_change / not_saved |
| 版本记录 | committed / no_change / unrecorded |
| 学习资格 | eligible / awaiting_record / excluded / needs_review |
| 操作阶段 | prepared / file_written / version_checked / completed / recovery_needed |
| 学习任务 | pending / running / completed / failed / cancelled / interrupted |
| 学习等待原因 | coalescing / foreground / disabled / model_unavailable / budget / none |
| 偏好 | pending / active / paused / dismissed / superseded / forgotten |
| 证据 | valid / no_net_change / superseded / reverted / needs_review / excluded |
| 约定文件 | missing / ready / invalid / needs_review |
| 文件与索引同步 | synchronized / index_pending / recovery_needed |

前端不得将 `saved + unrecorded` 画成全部完成；分析失败不使文件状态退回 not_saved。
pending 加等待原因代替一串含义重叠的任务状态；completed 可合法返回零候选。

## 5. 编辑与草稿

进入编辑创建会话，服务端读取并冻结完整原文、原始字节指纹和基线。
读接口文本虽然规范化为 LF，但原文件可能含 BOM/CRLF；保存仍按实际字节 digest 做 CAS。
正文编辑只针对已有 chapter，不顺带开放新章、人物文件和模块编辑。
如编辑器隐藏元信息，保存必须由服务端按基线重组；不得用 display_text 覆盖原文件。

草稿是完整文件文本，按会话存储。默认输入停顿 300ms 后写，连续输入至多每 2s 持久化一次；
这些是初始可测参数，不是跨机器性能保证。退出前对未持久化序号提醒。
界面显示最后持久化的序号/时间；突然断电不能宣称最近按键已保存。
正文保存直接携带完整提交文本，不依赖某次草稿自动保存恰好完成。

草稿写入带 expected_draft_revision 和 client_sequence；同键同载荷幂等。
重复与迟到请求不能覆盖较新草稿，多窗口同会话发生冲突则保留双方输入。
正文保存返回新的 base_id 和 digest，客户端仅推进已提交基线，不覆盖保存期间的新输入。
恢复草稿发现磁盘不同，只恢复原草稿与原基线供对照，不将新磁盘指纹偷换成可覆盖基线。

## 6. 保存步骤和失败边界

同一作品共用原子写入 claim。只读编辑基线/草稿不占正文长锁；
模型写作运行中可保留草稿，实际正文保存需等待或先停止原任务，不强停模型。
前台轮次在受理入口领取一次，轮内文件/模块工具只核对已有 owner，不再次 claim。
独立 HTTP 写操作自己领取并释放，不能传入客户端 owner 冒用前台占用。

1. 查请求键；相同载荷返回原操作，不再执行写入。
2. claim 后复查会话、完整路径、字节指纹、仓库状态及操作未完成阶段。
3. 无变化则返回 no_change，不生成空版本或学习任务。
4. 处理既有未知改动，独立记录其来源；再核对 HEAD 与目标原文。
5. 在记录库事务中写入前后快照、预期结果 hash、唯一操作标识和 prepared 意图。
6. 原子替换正文，核对落盘内容；记录 file_written。
7. Git 可用且状态安全时仅提交本次确定路径，附操作关联；核对 parent、路径和目标 blob。
8. 在事务中完成版本状态、推进编辑基线、建立学习资格与 outbox，最后返回结果。

文件、Git 和 SQLite 没有跨系统原子事务。意图解决的是可判断和可恢复，不提供外部工具不能写入的保证。
同键请求对应的原操作仍由活跃 owner 执行时返回 202，不在它尚在写入时并行 reconcile；
仅已完成或确认失去执行者的操作进入核对恢复。
外部编辑器可绕过应用锁；关键步骤前后都核对，发现竞争保留真实结果并报告，不通过回写旧文件消除竞争。
提交身份和标题不证明来源，操作关联只用于找到候选提交，还须验证实际内容与服务端记录。

| 发生点 | 恢复行为 |
|---|---|
| 意图之前失败 | 未写正文；保留草稿，返回正常错误信封 |
| prepared 后、替换前崩溃 | 磁盘仍是 before 则记未保存；不自动替换 |
| 文件已替换、阶段未记 | 磁盘等于 after 且其他条件匹配则补 file_written；不重复写 |
| 文件成功，Git 失败/未启用 | saved + unrecorded + awaiting_record；提供补记 |
| Git 提交后、记录库未完成 | 按操作标识/parent/路径/blob 核对，匹配才补完成 |
| HEAD 已推进或磁盘为第三种内容 | recovery_needed；保留现场，不自动提交或覆盖 |
| 版本完成，学习登记通知失败 | outbox 重放/后台扫未登记操作，按 source_digest 去重 |
| 响应丢失 | 同请求键返回原结果，客户端可按请求键查询 |

补记只核对/记录历史，不能重新提交正文文本。若未启用 Git，启用后核对 after 是否已有锚定版本；
before 仍以保存前持久快照为依据，明确标注其不是 Git parent，不伪造旧提交。
当前磁盘已变化且找不到精确锚定版本时保持待核对，不把当前内容当旧操作的结果。
重启恢复默认只补状态和通知，不重跑模型或自动创建 Git 提交。

## 7. 中文差异与坐标

证据坐标统一为规范化 LF 文本的 Unicode code point 半开区间 [start,end)，
同时保存所属 blob hash、行区间和算法版本。显示序号只用于阅读，不是身份。
原始字节与规范化文本 hash 分开；BOM、CRLF 或纯格式变化不能被误认为风格。

先段落对齐，再对对应段计算字符差异；中文不依赖空格分词。
重复段落必须通过位置与上下文消歧，不能仅按句子 hash 定位。
移动不伪装删除再新增；拆并段记录多对一/一对多引用，无法确定则显式 uncertain。
前端尽量直接渲染服务端片段文本，不把 code point 偏移当 JS UTF-16 下标；必要时显式转换。
保留原始 Git patch 作为回看入口，结构化差异不是另一套提交历史。

初始预算：单个对应段最多 4,000 code points 做精细差异，超过展示整段范围；
大章先分段对齐，耗时超预算返回 coarse 状态及完整段落，不阻塞正文保存。
上述上限在 G0/E2 测量后调整，算法版本进入证据摘要。

## 8. 独立证据与来源

来源枚举 manual_edit / agent_write / adopted_suggestion / external_unknown / import / revert。
只有人工保存服务可生成 manual_edit；客户端的来源字段和模型自述不具有权威性。
应用内手动操作不证明所有粘贴文字由作者原创；整章覆盖和大段来源不明替换先 needs_review。

同片段沿革的连续修改归入一组：A→B→C 分析 A→C 的净变化，不能计两次独立支持。
批次与 12s 等待用于合并调用，不单靠时间窗判断独立证据。
跨批次同处修改仍追溯沿革；不确定是否独立时按相关证据处理。
净变化回到起点则该组不再支持风格推断。

新增无关段落不使旧证据失效；相关段被替换或撤销时更新对应 group 状态。
未知外部改动覆盖定位范围则 needs_review，不能猜是作者反悔。
历史被外部改写或引用提交缺失时暂停相关自动分析，已明确声明的规则不直接删除。

## 9. 后台操作、预算与重启

初始运行参数：全应用后台并发 1；同作品 pending 合并等待 12s、连续改稿最长 60s 形成分析切点；
每次最多 8 组片段、必要上下文总计不超过 12,000 字符、最多提出 3 条候选。
这些是上限，不是必须填满的数量；节奏上下文不能安全切分时返回 insufficient_context。

默认每作品每天最多 20 次分析请求、全应用每天最多 60 次；设置可关闭或降低/调整作品额度。
请求发出前事务预占次数，实际发送后即计入，失败/取消也保留。
没有可靠 token 用量时不以零结算；字符上限不能替代 0.9 的完整 token 预算。
分析只调用当前所选模型的固定快照，不自动换模型或切到本地。

任务领取使用租约和 fence，发布须同 fence、未取消、作品 generation 相同、来源仍有效。
不在网络调用期间持数据库事务或正文锁。前台请求到来时停止启动后台请求，并请求取消在途后台分析；
不等待其模型超时才受理前台。实际供应商是否立即停止和已发生消耗分别如实记录。

每次实际请求独立 request_id；业务任务可多 attempt，但重试必须显式发起并检查预算。
网络失败/无效输出不自动再次调用；只允许确定性的格式清理后重校验。
重启后 pending 可继续调度；running 已发送则 interrupted，不能靠租约过期再次付费请求。
已明确尚未发送的领取可退回 pending。迟到结果不能覆盖取消、忘记或删除后的状态。

## 10. 候选与决策

候选模型输出只含 evidence 引用、分类、规则、条件、例外和建议范围，不含可生效状态。
引用由程序核对版本、区间与引文；合法引用不证明语义正确，需在线和作者复核。
相似候选可以归并来源，但新的规则正文或更大范围生成新待确认版本。

确认使用 expected_revision、expected_style_digest、作者看到的规则和 request_key。
确认或修改生效块会写 STYLE.md，先记录阶段意图、写文件与核对版本，再在短事务中记录决策、更新索引、
状态、epoch 和 outbox；不能用单一数据库事务声称文件也已原子完成。
仅候选拒绝等不改文件动作可直接短事务完成。同键相同载荷返回原结果，不同载荷冲突。
显式编辑并确认保存 author_declaration 性质；仅确认推断保留 confirmed_inference 性质。
直接文档维护的新增或实质改写也保存 author_declaration；纯格式变化不改变性质。
证据全部失效时 confirmed_inference 暂停待核对；author_declaration 保留为作者要求，显示来源已变化。
支持与冲突证据分别保留，不自动从晚一次修改推翻早规则。

scope 只允许当前 workspace_uid，可附人物稳定引用或场景锚点、章界、条件与例外。
绑定人物须稳定模块/条目或作者明确关联；卸下、删除或身份变化不能按名字重绑。
后文来源默认不用于更早章节；作者可明确调整规则章界，不能由模型自证 fact_free 绕过。
后文故事原文示例即使规则范围被扩大，也不自动进入前章。

## 11. 停用、忘记与撤销

停用/忘记先在事务内改变状态与 epoch，使之后的请求过滤生效。
运行中已发送的请求不能撤回；提供停止入口，之后未发出的请求排除相应版本。
恢复建立新版本，不能把旧轮次快照中的已撤销版本重新启用。

忘记建立证据组和候选指纹排除，清理规则正文、旧版本正文、派生示例、受控运行快照、
带对应引用的输入捕获附件和压缩投影；最小决策元数据与无正文回执可保留。
清理失败仍保持排除，显示 cleanup_pending 并重试本地清理，不再次调用模型。
同旧证据再分析不得学回；从新独立修改提出相似理解仍须作者确认。
原始正文 Git 和作者公开会话不因忘记被改写；模型有效投影不能把其中已失效的来源化偏好段当作有效要求。
已入文档的规则还须按指纹从 STYLE.md 移除；失败保持排除与 cleanup_pending，不能写旧文件覆盖外部更新。
作品 Git 中的 STYLE.md 历史不自动重写；外部删除规则停止使用并排除已知旧证据，但不冒充历史清理完成。
混合摘要无法安全移除该段时不注入或从原始来源重建，不靠附加一句停用说明继续注入旧规则。

撤销正文仍只覆盖当前已有的最新提交 revert 规则，不新增任意历史三方撤销。
Git 成功而证据失效记录未完成时，保持 invalidation_pending，下一请求先过滤相关 group，再补状态。
撤销和恢复不是新的人工风格证据。多个修改位于同一组时按剩余净变化重算。
应用之外的 Git revert 需以图谱、内容和已有操作核对，不能只看提交标题。

## 12. 使用快照和实际请求

受理冻结已确认版本 allowlist、任务历史和资料版本。每次请求前选择只能取该 allowlist，
再与当前未撤销版本相交；作者随后确认的新规则等下一轮。
同时冻结 style_digest；每次请求前读取并核对当前文件，只保留仍存在且未变化的允许块。
变化无法可靠对应、文件缺失/非法或索引未完成时按[文档契约](style-document.md)排除，不用旧缓存回退。
目标后续由工具确定时，允许在原 allowlist 内重选。目标、人物或章界未知则跳过相关局部偏好。

使用回执绑定 request_id，保存规则 ID/版本、示例 blob 引用、选择/排除原因及完整预算。
同时保存 style_digest、块引用与声明性质；实际发送的规则必须可追到本轮允许文件版本。
与实际请求由同一编译结果生成；界面不能仅列「可能适用的偏好」。
当前指令优先，事实/知情/披露与修改授权独立校验。
extract/materials/review/compaction 默认不装文风，writer 的讨论回复也不被要求模仿小说文风。
0.9 压缩保留失效来源标识，不能从旧摘要恢复已停用或忘记的规则。

## 13. 文档保存与外部同步

STYLE.md 固定在作品根目录，不由客户端提供任意路径；不得通过通用模型写文件工具绕过作者确认。
应用内整份编辑、详情编辑和候选确认统一进入 style_document 服务及作品 claim，
复用第 6 节的意图、前后字节、Git 核对和恢复原则，但不创建正文人工证据或学习任务。
文件保存与版本记录及索引同步分别返回；文件和索引一致后即可使用明确约定，Git 未记录可后补。
文档草稿与正文草稿按不同归属隔离，支持跨刷新/重启和端口变化恢复。

纯 GET 不创建文件或数据库、不调用模型；已初始化作品可确定性同步外部文件的派生索引和排除，
未初始化时仅返回解析视图，首次显式维护或正式写作请求登记时才落库。每次请求前仍须核对实际磁盘内容。
外部同步只更新记录，不自动写文件、提交 Git 或把外部修改当 manual_edit。
索引重建不抹掉证据来源、停用和忘记；这些生命周期记录不能仅靠文件文本重建。
复制作品只带入文件声明，新作品不继承旧证据；无效人物或场景引用先待核对。
文档变更、暂停或删除仍受作品 generation 约束，迟到发布不得恢复旧文件或已删除作品。
