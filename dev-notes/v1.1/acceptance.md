|---|---|---|---|
| UC-D01 | 引导提问起步 | 一次只问一个问题；每问可跳过；随时可说「就这样开始」；问题数不超过上限；未知保持未知 | 追问时间线、人物关系等内部属性；为完整而补造结局 |

| UC-D03 | 首章起草 | 空正文经对话起草；采用候选后正文入稿纸；页边索引正常；候选带三层自查 | 候选自动写文件；自查缺失被静默跳过 |
| UC-D04 | 一句话修改与回退 | 说一句改动 → 直接入档并回显差异三要素（改了什么、影响哪里、基于哪个修订）；「不同意，改回来」或整体撤销后正文、结构、模块一起恢复 | 撤销只恢复一半；无 Git 记录的静默改写 |
| UC-D06 | 无模型状态 | 作品链路如实说明需要模型设置并给入口；已有内容只读可见 | 出现绕过对话的隐藏路径；散布禁用按钮 |
| UC-D07 | 结构提议 | 建章提案确认即建章（含可选标题）；标题想改回对话说一句 | 作者填写任何章节字段；建章失败留半登记 |
| UC-D08 | 索引时点 | 起草候选采用前页边索引不更新；采用落盘后才出现候选与出处 | 未采用正文被当作已入账信息；索引沿用旧结果冒充最新 |

## 2. 结构装配用例（UC-S01—S05）

对应 2026-11-03 最小试验的回归与扩展：

| # | 用例 | 应当发生 | 不能发生 |
|---|---|---|---|
| UC-S01 | 空作品起步 | 设定卡确认 → 第一版结构 + 首批模块入档，全程对话 | 依赖任何手写表单完成起步 |
| UC-S02 | 两章写作 | 结构随入档同步；记账静默；计划性变化有单独说明 | 「只入正文不入结构」路径存在 |
| UC-S03 | 对抗：风格指令 | 风格指令（如「对白多一点」）下必发生清单护栏保证规定事件不丢 | 规定事件被风格指令挤出章节（对应实验失败场景） |
| UC-S04 | 计划修改 | 「把回收提前一章」直接入档并可整体撤销；差异三要素完整 | 改动无声发生且不可回退 |
| UC-S05 | 台账对账 | 结构文件含伪造/过期「已写」标记时，确定性对账拦截、强制对账流程改写缺章 | 模型顺假前提继续写作；自查对幻觉正文逐条「核对通过」 |

## 3. 统一记录指标

| 指标 | 通过标准 |
|---|---|
| 对话闭环 | 起步到修改全程可经对话完成；不需要理解章节构思、信息线、对齐等内部概念 |
| 结构真实性 | `STRUCTURE.md`、台账与实际入档正文一致；台账为准的优先级生效 |
| 装配可核对 | 每次请求的装配回执列明注入层、模块与清单条目 |
| 原子与回退 | 三元提交无半状态；整体撤销回退正文、结构、模块、台账四者 |
| 回显完整 | 计划性变化必有单独说明；记账静默仅入档回执可见 |
| 恢复能力 | 撤销、过期、刷新、重启后无半状态；直接落盘均有 Git 记录 |
| 降级处理 | 环境故障明确归因（含 `MODEL_UNAVAILABLE`）；不调模型猜；自查缺失按任务失败归因 |
