# Q0 契约冻结（实施记录）

日期：2026-11-03。阶段：Q0 收尾。本文件冻结 v1.1 实施期间不变更的契约值与规则；
后续阶段如需变更，必须先修订本文件并登记理由，不得在实现中悄悄偏离。

## 1. 结构文件契约（值冻结）

| 项 | 冻结值 | 来源 |
|---|---|---|
| 文件名 / 位置 | `STRUCTURE.md`，作品根目录 | `structure_document.py: STRUCTURE_FILENAME` |
| 铁律段标记 | `## 铁律`，必须为文件首个非空行 | `structure_document.py: IRON_RULES_MARKER` |
| 铁律段范围 | 标记行之后到下一个二级标题（`## `）或文件尾，非空行各为一条 | `split_iron_rules` |
| 标记丢失处理 | 降级全文注入 + 装配回执如实标注；不猜、不静默修复、不自动补标记 | `IronRules.ok=False` 路径 |
| 字数预算上限 | **1600 字符**（全文，含铁律段） | `structure_document.py: BUDGET_LIMIT` |
| 超限处理 | 不是错误；入档事务要求同事务先提交压缩版结构，不静默截断 | `BudgetReport` 信号 |
| 内容指纹 | 与 `files.py: digest_bytes` 同一算法（UTF-8 编码后摘要） | `structure_digest` |
| 写入路径 | `files.py` / `git.py` 同一路径，随作品 Git 逐次入档，可回退 | M2 契约 |

## 2. 正文台账契约（事实层）

| 项 | 冻结值 | 来源 |
|---|---|---|
| 落盘文件 | `prose-ledger.json`，与 `STRUCTURE.md` 同级 | `prose_ledger.py: LEDGER_FILENAME` |
| 数据结构版本 | `schema: 1`（章号 → 最近入档修订号）；版本不符按空台账重建 | `LEDGER_SCHEMA` |
| 事实源 | **仅事务层可写**：三元提交成功时追加、整体撤销时回退；模型只读不可写、不进 `STRUCTURE.md` | M4 契约 |
| 损坏处理 | 文件缺失或损坏按空台账处理，不带病运行 | `load_ledger` |
| 并发 | 专用 `.lock` 文件 + 原子写（Windows 惯例，不锁数据文件本身） | `save_ledger` |
| 重复入档 | 覆盖处理，修订号取最新 | `record_chapter` |

## 3. 确定性对账规则（第一道防线）

- 目标章号来源：**任务元数据**（系统发起写作任务时已知），不从自由格式解析。
- 规则（`reconcile` 纯函数，离线可测）：
  1. `1..目标章` 均有登记 → 放行写目标章；
  2. 存在缺章 → 默认**改派最早缺章**（`action="redirect"`）；
  3. 作者明确跳过 → 放行并记录被跳章号进装配回执（`allow_skip=True`）；
  4. 目标章本身已入档不拦——修改既有章是合法路径。
- 优先级：台账与结构文件任何「已写」标记冲突时**以台账为准**（写入装配契约与提示词）。
- 主防线为装配层确定性执行；起草提示词强制对账流程为第二道保险（试验 0/3 vs 3/3）。

## 4. 装配顺序契约（冻结）

注入顺序固定为六层，装配回执按此列明：

```
1. 铁律（常驻，标记丢失时降级全文注入并标注）
2. 结构全文（常驻，预算 1600 字符，超限走压缩路径）
3. STYLE.md（本版空占位）
4. 当次涉及挂载模块（按写作目标按需选择；目标未知时注入模块索引）
5. 正文台账（只读事实）
6. 必发生清单（模型起草同回合自列，不落盘，回执展示）
```

- 装配快照进请求回执：实际注入了哪些层、哪些模块、清单条目。
- 模块按需选择是必需项而非优化项（全量重注入实测第 4 章 16.4k prompt tokens，随章节数平方增长）。
- 必发生清单自列为空时如实说明并建议补骨架或模块，不猜；写后宽松关键词机检只报相对偏差、不判失败。

## 5. 事务与感知契约

- 三元原子提交：正文 + `STRUCTURE.md` + 涉及模块，一次联合提交，直接落盘（无暂存确认门），可整体撤销；**无「只入正文」路径**。
- 原子性兜底：写作回合预期正文未产出 → 整个任务按失败归因，任何部分不入档。
- 感知分类（模型入档时标注，装配层校验完整性）：
  - **记账**：伏笔标记已埋、章节状态更新——静默，仅入档回执可见；
  - **计划性变化**：改回收点位、新增叙事线、改铁律、删模块——单独一行说明，附「不同意，改回来」。
- 差异回显三要素：改了什么、影响哪里、基于哪个修订。

## 6. 起步 / 设定卡 / 建章契约

- 起步双模式：引导（一次一问、数量有上限、每问可跳过、随时「就这样开始」、未知保持未知）与自由发挥。
- 设定卡：`book_intent` 候选，对话呈现；确认端点核对候选依据后联合提交写入作品意图；**重复确认拒绝**；可整体撤销。
- 起步结构：确认后同链路起草第一版结构 + 首批模块，随事务直接入档（Git 可回退）；起步前 `STRUCTURE.md` 缺失视为空、台账为空。
- 建章提案：模型在对话中提议（含可选标题），确认后走既有建章事务，重复请求键幂等；失败回滚不留半登记。

## 7. 错误码（对外稳定契约）

沿用仓库既有命名惯例（`*_CONFLICT` 为冲突拒绝，归因码用于任务失败归因）。v1.1 新增：

| 码 | 场景 | 行为 |
|---|---|---|
| `MODEL_UNAVAILABLE` | 新作品起步无可用模型 | 如实返回，前端设置引导，不产生半提交 |
| `BOOK_INTENT_CONFIRMED_CONFLICT` | 设定卡重复确认 | 拒绝，幂等 |
| `STRUCTURE_BUDGET_CONFLICT` | 结构超预算且事务未携带压缩版 | 拒绝入档，要求先压缩 |
| `STRUCTURE_REVISION_CONFLICT` | 结构文件基础修订过期 | 过期事务不可覆盖，比较后重新发起（沿用既有过期规则） |
| `LEDGER_RECONCILE_CONFLICT` | 对账发现缺章且作者未确认跳过 | 拦截装配/起草，改派最早缺章（`redirect` 决策） |
| `EXPECTED_PROSE_MISSING` | 写作回合预期正文未产出 | 任务失败归因，任何部分不入档 |
| `SELF_CHECK_MISSING_CONFLICT` | 自查段缺失 | 任务失败归因，不静默跳过 |

既有码（`REVISION_CONFLICT` 族、`STORY_AUTHORIZATION_CONFLICT`、`REQUEST_KEY_CONFLICT` 等）含义不变，复用。

## 9. 实验结论（设计依据登记）

以下 2026-11-03 最小试验结论作为设计依据冻结，后续阶段不再重新论证：

1. 被动注入台账事实，模型不对账（0/3 顺假前提跑）；提示词强制对账流程 3/3 → 对账以装配层确定性执行为主防线。
2. 对白驱动提示下核心物件 0 出现 → 风格指令会挤出剧情，必发生清单护栏为必需项。
3. 混合意图回合偶发「只交文件更新不交正文」且自查对幻觉正文自洽 → 原子性兜底 + 「预期正文缺失」确定性失败归因。
4. 全量重注入成本随章节数平方增长（第 4 章 16.4k prompt tokens）→ 模块按需选择为必需项。
5. 滑杆/预设面板实验已证伪并废弃（行为锚点优于均匀刻度；自由格式 + 模块挂载替代参数化预设）。
