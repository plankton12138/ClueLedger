# 1.1 写作约定文档契约

更新：2026-10-27。状态：**已确认方向，待实施**。
产品范围见[产品方案](../../product-design/v1.1/README.md)，执行顺序见[开发计划](development-plan.md)。
本文统一规定 `STYLE.md` 的维护、生效和外部编辑行为；记录结构、接口和验收分别引用本文。

## 1. 目标与取舍

作者已经知道的写作要求应当能够直接表达，不必先修改正文再等待系统推断。
每部作品根目录使用真实的 `STYLE.md`，界面称「写作约定」，应用内和外部编辑器均可维护。
文件随作品复制、导出并由作品自己的 Git 记录，关闭修订学习后仍可独立用于写作。
本版仅有作品级文件，不增加目录逐层继承或个人全局规则。

`STYLE.md` 是当前约定文本、条件、例外和声明范围的权威来源。
记录库保存候选、证据、决策、停用状态、排除标识、历史和可重建索引；不得独立保存另一套生效正文。
有效集合必须同时满足：规则仍在当前合法文件中、范围可验证、生命周期允许使用。
记录库只能进一步排除规则，不能使已从文件移除的规则重新生效。

## 2. 作者维护的内容

建议按叙述、情绪表达、对白和避免事项组织，具体标题由作者决定。例如：

```markdown
# 写作约定

## 叙述
- 使用第三人称限知视角。
- 当前视角人物不知道的事情，不直接写成确定事实。

## 情绪表达
- 人物回避追问时，优先用动作和对白表现紧张。
- 重要情绪转折允许直接描写心理。
```

直接新增或改写规则是明确声明，不要求改稿证据，不调用模型解释后才允许保存。
文件变化不是人工正文改稿，不生成修订学习证据；外部文件来源只记为外部约定维护，
不据此声称文字由作者原创。模型只能提出候选或文档修改建议，不能自行写入生效文件。

人物事实、线索状态、知情和谜底披露仍以作品账本为准；约定可以要求遵守这些约束，
不能以文件中的文字覆盖账本事实、读取权限或正文修改授权。

## 3. 文本与范围表示

使用 UTF-8 Markdown，允许 BOM/CRLF；并发判断基于原始字节，展示可规范化换行。
初始文件大小上限为 256 KiB 原始字节，G0 测量后冻结；请求输入预算另行计算，不能因单次装不下就判文件非法。
首版按二级标题划分规则块，首个二级标题前的非空正文作为独立块；块内列表和段落整体保留，
不把一句例外拆成与主规则无关的偏好。无标题文本也是合法的作品级约定。
未声明结构化范围的新块默认为当前作品；正文中的条件和例外随块保存，不推断人物稳定身份。

应用生成或维护的块使用可见于源码的 Markdown 注释保存稳定 ID 和范围，元信息不进入模型输入。
拟议格式如下，G0 冻结解析和往返保留规则：

```markdown
## 林岚的对白
<!-- clueledger:style {"id":"pref_001","scope":{"kind":"character","character_ref":{"binding_id":"binding_001","entry_id":"character_001"},"chapter_from":7,"chapter_to":null}} -->
- 回避追问时，优先使用短回答和转移话题。
- 正式陈述证词时允许完整解释。
```

稳定 ID 在当前作品中唯一；身份与章界按既有材料和文档核验，不按标题中的人名绑定。
未标注 ID 的块可直接读取，以文件指纹和块位置生成该版本内引用；应用首次修改该块时补稳定 ID。
只读同步不擅自改文件、整理标题或补注释。注释仅为数据，不允许包含任意工具指令。
重复 ID、无效元信息、无法确认的范围不静默降为作品全局规则。
原有人物/场景/章界标记被移除或无法可靠对应时，将相关变化标为待核对，作者明确范围后才能使用；
不能把丢失范围理解为允许全作品使用。普通约定内容保存仍不要求再次逐条确认。

## 4. 两个维护入口与统一保存

| 入口 | 保存行为 |
|---|---|
| 应用内整份文档编辑 | 保留作者看到的完整文件和字节指纹，保存直接声明；不重排未改内容 |
| 偏好详情编辑 | 定位同一文件中的稳定规则块，修改正文或范围，不写另一套生效规则 |
| 修订候选确认 | 预览将加入或替换的完整规则块，确认精确版本后写入文件；候选不提前进入文件 |
| 外部编辑器 | 在打开面板、任务受理和每次实际模型请求前核对文件；监听仅用于及时提示 |
| 停用与恢复 | 记录库保留停用原因和内容引用，文件保留约定；恢复只引用仍存在且核对后的当前内容 |
| 移除规则或忘记 | 应用内从文件移除对应块，更新排除和投影；外部删除也立即停止后续使用 |

确认推断保留 `confirmed_inference` 性质，全部证据失效时可以暂停；
直接新增、实质改写为明确要求保存 `author_declaration`，不依赖学习证据存续。
只调整排版不提升声明性质，不扩大范围。外部修改无法可靠对应旧规则时先排除相关规则并提示核对。
外部移除已知规则时，记录其旧证据排除标识，防止同批证据立即学回；
外部删除不宣称完成应用内「忘记」的历史副本清理。

文件写入、Git 和记录库没有跨系统原子事务。应用内文档保存、候选确认及会改文件的决策
共用作品写入 claim、请求键和阶段记录，校验文件指纹及候选精确版本：

1. 解析并验证拟议文本和范围，冻结前后字节及 HEAD，持久化操作意图。
2. 原子替换 `STYLE.md`，核对实际结果，按路径记录版本。
3. 提交与文件指纹绑定的索引、声明性质、决策、epoch 和通知，完成后才报告已生效。

文件已保存而 Git 失败，单独显示版本未记录；只要文件、索引与范围核对一致即可用于后续写作，
明确声明不依赖 Git 成功才生效，也不进入正文的 `awaiting_record` 学习流程。
索引未完成时暂不使用该文件规则，重启仅核对并补状态，不回写旧文件、不自动再次提交。
停用、忘记的排除先持久化；文件冲突或清理失败也不恢复被排除规则。
无条件覆盖、自动合并以及后台覆盖作者文档均不在本版范围。

## 5. 缺失、异常与历史

| 情况 | 行为 |
|---|---|
| 尚无文件 | 读取返回 missing 和空约定；只在作者首次保存或确认候选时创建，不复制应用仓库 AGENTS.md |
| 文件清空或被删除 | 当前有效集合为空，旧索引、会话和摘要不能补回；待处理候选不因此变为已确认 |
| 文件不可读、编码/结构非法、超出文件大小上限 | 不覆盖文件、不回退到旧约定；标明不可用，允许正文保存及不使用该文件的写作 |
| 外部更新与应用内草稿冲突 | 保留基础、草稿和磁盘三份文本，作者合并后基于新指纹保存 |
| 文件回退到旧 Git 版本 | 重新解析，既有停用/忘记排除仍生效；恢复排除项由作者主动决定 |
| 文件随作品复制或导入 | 新作品身份，普通声明可读取；旧人物/场景引用须重新核对，不带入旧作品证据与权限 |

忘记清理受控规则副本、示例和投影，保留最小排除标识。
作品 Git 历史中的 `STYLE.md` 与正文历史一样不自动改写，界面如实说明这个边界。
本版直接使用新格式，不建设旧偏好数据迁移或历史批量导入。

## 6. 请求中的使用

任务受理冻结 `style_digest`、规则块 ID/版本和允许集合；每次发送前再次核对文件与撤销状态。
期间出现新文件版本，不把新规则加入当前任务；只保留原允许集合中仍未变化且有效的规则。
无法可靠证明某块未变化时排除该块；文件缺失或非法时排除整个文件，下一任务再使用合法新版本。
变化检测必须先于旧索引读取，不能把文件监听或已打开的界面当作一致性保证。

适用顺序为：本次明确要求、适用的具体明确约定、作品一般明确约定、已确认推断。
同层冲突保留提示，条件无法区分且影响任务时由作者决定，不按文件靠后或修改时间自动覆盖。
规则与示例各自检查章界，后文示例不随规则范围扩大而自动进入前章。
仅用于正文写作和改稿；事实提取、资料整理、默认检查、压缩和普通讨论不应用小说文风。
规则按完整块选择并计入真实输入预算；超预算记录排除原因，不截去条件或例外。
回执保存 `style_digest`、块 ID/版本、声明性质、选用和排除原因，与实际输入同源。

## 7. 界面与接口入口

「写作偏好」辅助区内提供「写作约定」和「待确认」入口，共用现有对话、线索所在区域，
不新增第四列或主导航。整份 Markdown 编辑和规则详情都显示同一文件版本。
保留草稿、外部变化提示、来源、停用/恢复/忘记以及实际使用详情；说明按需展开。
文档草稿使用专用归属，不扩大既有正文编辑接口的 chapter 限制。
接口定义见[接口与前端](api-and-frontend.md)，故障和验收见[验收计划](acceptance.md)。
