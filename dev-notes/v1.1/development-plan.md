# v1.1 详细开发计划：全对话创作

日期：2026-11-03。状态：**P0—P5 待实施**。[产品方案](../../product-design/v1.1/README.md)与[验收计划](acceptance.md)共同约束实现。基线为 v1.0.9 P0—P6 已实施状态（运行版本仍为 1.0.8），基线事实见 [v1.0.9 开发入口](../v1.0.9/README.md)与 [P6 拆门槛记录](../v1.0.9/notes/p6-gate-removal.md)。v1.0.9 的 P7 在线验收并入本版 P5，版本不再统一为 1.0.9，直接提升为 **1.1.0**。

## 1. 交付目标

1. 新作品直接进入对话，引导提问或自由发挥产出设定卡，确认后门槛通过；意图来源从「作者填写」改为「对话确认」。
2. 作品链路内不存在任何手写输入面：正文只由模型产出，正文页是阅读与核对面。
3. 一切修改经对话发起：模型分解影响、暂存执行、对话回显差异三要素，作者一次确认后联合提交、可整体撤销。
4. 建章、标题、方向建议由模型提出，作者确认或一句话调整。
5. 页边索引、候选确认入账、空章反馈、Aqua 视觉维持 v1.0.9 形态不动。
6. 无可用模型时作品链路如实说明，不提供手写绕过。

完成标准不是「入口减少」，而是验收用例 UC-D01—UC-D08 可从空作品连续走完，作者全程不打开作品链路内任何输入框（对话输入除外）。

## 2. 基线核对（v1.0.9 P6 后的当前事实）

| 当前代码 | 当前行为 | v1.1 改动 |

## 3. 模块计划

### M1 对话起步与设定卡

**为什么**

意图手写输入是最后一个「作者先理解结构概念才能动笔」的负担。门槛本身（作品意图非空）已被验证有价值，保留；只换来源。

**设计**

- 新作品打开即进入会话，新增起步任务意图（模式：引导 / 自由发挥），复用现有会话受理、材料装配与流式链路。
- 引导提问的约束放在任务意图与提示装配层，不硬编码在业务代码：一次只问一个问题、问题数量有上限、每问可跳过、作者随时可以说「就这样开始」、未知保持未知。`ask_author` 工具沿用。
- 起步以设定卡候选结束：模型把对话内容整理为一段作品意图，经目标化辅助候选链路（`book_intent`）产出，在对话中呈现，不进入正式数据。
- 新增设定卡确认端点：服务端核对候选依据与当前状态后，联合提交写入作品意图；重复确认拒绝；可整体撤销。
- 无可用模型时新作品会话如实返回 `MODEL_UNAVAILABLE`，前端展示设置引导。

**主要落点**

- 修改：`task_intent.py`、`materials.py`、`service.py`、`api.py`、`story_candidate.py`。
- 前端：新作品起步视图（对话承载）、设定卡确认卡。

**退出条件**

从新作品到确认过门槛全程无输入框；引导上限、跳过、「就这样开始」、未知保持未知有测试；确认幂等与撤销通过；无模型状态可见且不产生半提交。

### M2 正文对话化：稿纸退位

**为什么**

正文是最后一个手写内容面。撤掉手写不撤掉机制：保存、锚点、索引、候选采用全部保留，只换发起方。

**设计**

- `ChapterEditor` 编辑面退役：正文页改为阅读渲染（沿用阅读组件与页边索引），中文阅读、选段讨论焦点保留；「让模型续写」并入对话任务，稿纸旁续写入口撤除。
- 空正文两个起步入口均由对话任务发起：由模型起草（`prose_draft` 候选）、看看方向建议（`chapter_direction`，仅参考文字）。
- 服务端正文保存接口保留，供候选采用与 Agent 写入使用；前端手写保存、自动保存与摘要冲突交互撤除。
- 空章反馈的「让模型看看本章」改为对话任务发起；`index-review` 端点复用。
- 正文修改一律进入 M3 的暂存闭环，不走独立保存路径。

**主要落点**

- 前端：`ChapterEditor.tsx` 拆分为只读阅读面、`ConversationPanel.tsx`、写作工作台状态。
- 后端：`chapter_writing.py` 保留候选采用路径；清理仅服务手写保存的交互分支。

**退出条件**

作品链路内不存在 `textarea` / `contenteditable`；起草候选采用后正文入稿、索引正常；阅读面选段可发起对话焦点；刷新与重启后正文恢复不受影响。

### M3 修改闭环：提议—确认语义

**为什么**

对话成为唯一入口后，「模型执行、作者确认」需要落盘语义支撑。0.3 裁决「提议→采用是唯一落盘通道」在本链路兑现：未经确认不产生正式变更。

**设计**

- 新增暂存变更（待确认变更）记录：目标、基础修订、变更内容（正文前后文本或意图前后值）、影响清单（涉及哪些章、哪些信息线）。存储复用候选存储与摘要前提。
- 修改任务中，Agent 工具切换为暂存执行模式：`write_file`、`edit_file`、`propose_story_structure`、`propose_story_scene` 只产出暂存变更，不直接落盘。这是工具层硬约束，按任务意图切换，不依赖提示词自觉遵守。
- 暂存后模型必须在对话中回显差异三要素：改了什么、影响哪里、基于哪个修订；未回显的暂存视为未完成动作。
- 确认：核对暂存依据的基础修订与当前状态一致后，走联合提交（复用 `StoryChangeService` 与既有事务），返回可整体撤销的回执。驳回：暂存丢弃，无残留。
- 并发与过期沿用候选规则：基础修订过期时暂存不可确认覆盖，只能比较后重新发起。
- 暂存正文不触发语义索引分析；确认落盘后才排队增量分析。
- `BookPlanView` 改只读投影，附「在对话里继续调整」。

**主要落点**

- 修改：`agent.py` 工具执行模式、`story_candidate.py`（暂存载体）、`story_changes.py`、`materials.py`、对话回显事件（`tool_feedback.py` / `chat_stream.py`）、`api.py`（确认与驳回端点）。
- 前端：差异回显卡（确认 / 驳回 / 再说一句）、`BookPlanView.tsx`。

**退出条件**

未经确认无正式变更（全写入路径测试）；确认可整体撤销；驳回无残留；过期暂存不可覆盖新修订；暂存期间索引不更新、确认后更新；回显三要素完整。降级处理：暂存构造失败按环境故障归因，不调模型猜。

### M4 结构由模型分解

**为什么**

建章、标题、方向是结构性决定，要求作者理解章节与信息线概念。改为模型提议、作者确认。

**设计**

- 建章提案：模型在对话中提议建章（含可选标题），确认后走既有建章事务（同事务登记章节、分配正文路径、写入标题）；重复请求键幂等沿用。
- 标题起草作为设定类候选：确认写入或留空，想改回对话。
- 章末收束与下一章方向在对话中给出，不设独立按钮。

**主要落点**

- 后端：建章提案确认端点（复用建章事务）、标题候选。
- 前端：目录中的确认交互。

**退出条件**

作者建章全程无字段填写；建章失败回滚不留半登记；提案确认幂等。

### M5 入口收敛、无模型前置与清理

**为什么**

散布的模型按钮要求作者理解「哪个按钮管哪类对象」。收敛后作品链路只有一个求助位置：对话本身。

**设计**

- 撤除清单（作品链路内）：意图输入与「交给模型构思」、标题输入与拟标题按钮、稿纸旁续写按钮、方向建议按钮、对齐处理建议按钮、「完成本章」表单化路径中残留的独立模型入口。
- 保留：对话内「给我下一步建议」、候选一键确认与豁免（判断类操作）。
- 灵感速记与模块库不动，其手写输入与模型按钮维持现状。
- 无模型状态：作品链路顶部如实说明并给设置入口，不出现散布禁用按钮。
- 消费者矩阵清理：撤除后无消费者的端点、组件、样式与测试一并删除；更新 [v1.0.9 创作输入清单](../v1.0.9/notes/creative-input-inventory.md) 的登记口径（作品链路条目标记为「对话」）。

**主要落点**

- 前端：按钮与输入组件删减、状态与路由清理。
- 后端：无消费者接口撤除；错误码对齐（`MODEL_UNAVAILABLE` 口径统一）。

**退出条件**

作品链路无孤儿入口、无无消费者接口；灵感与模块库行为不变；无模型状态各页面一致。

### M6 验收与发布

**设计**

- 确定性矩阵：起步双模式、设定卡确认、起草采用、暂存→确认→撤销、驳回丢弃、过期修订、建章提案、索引时点、无模型状态。
- 浏览器走查：从空作品到第一章完成的全对话旅程、阅读面与页边索引、无模型状态页。
- 在线模型评测：承接 v1.0.9 O01—O10 按全对话改写，新增对话修改与引导提问用例；沿用单例复测纪律，使用 `.env` 在线模型。
- 所有门槛通过后统一版本为 **1.1.0**（`pyproject.toml`、`src/hastings/__init__.py`、前端包与锁文件、健康检查、版本断言），v1.0.9 不再单独出版本号。

**退出条件**

验收有证据；文档状态同步；未完成项如实保留。

## 5. 关键实现顺序

1. 起步任务意图与设定卡候选（复用候选链路）。
2. 设定卡确认端点与门槛衔接。
3. Agent 工具暂存执行模式（任务意图切换）。
4. 暂存确认 / 驳回端点与联合提交接线。
5. 对话回显差异三要素的事件契约。
6. 正文面只读化与手写入口撤除。
7. 建章提案与标题候选。
8. 入口收敛、清理与无模型状态。
9. 验收与版本统一。

前端不得用本地假数据长期顶替真实交互；每阶段结束切回真实接口。

## 6. 风险与处理

| 风险 | 处理 |
|---|---|
| Agent 直写路径与暂存语义冲突 | 执行模式按任务意图在工具层切换，属硬约束；提示只解释不兜底；全写入路径补测试防绕过 |
| 对话回合预算耗尽（1.0.3 曾 24 回合耗尽） | 修改任务设回合上限；回显走结构化事件不占模型轮次；超限给明确归因 |
| 暂存与索引时点错位 | 暂存不触发语义分析；确认落盘才排队；索引测试覆盖该时点 |
| 全链路依赖在线模型，评测成本上升 | 确定性测试优先；在线用例失败修复后单例复测，不短时间重复 |
| 撤掉手写后作者控感下降 | 确认前零落盘、回显三要素、整体撤销三层保障；不接受任何静默改写 |
| 阅读面退役编辑器后丢能力 | P0 冻结阅读渲染与选段焦点的复用接口；编辑内核代码保留不删，仅撤入口 |
| 无模型不可起步被当作缺陷 | 产品方案已裁决接受；界面文案如实说明，不造绕过路径 |
| 撤按钮误伤灵感 / 模块库 | 收敛清单逐项登记位置；灵感与模块库在 P4 回归确认行为不变 |

## 7. 文档与验证纪律

- 每阶段完成后写简短实施记录到 `notes/`，说明真实改动、验证命令、结果与未覆盖项。
- 决定变化时同步更新本目录文档，不保留相互矛盾的计划。
- 仅文档或版本号调整不跑后端全量；写入路径、联合提交或上下文链路实际改变后，按风险执行定向测试与一次必要广泛回归。
- 根目录 README 仅在作者要求时修改；`mynotes/` 只读。
