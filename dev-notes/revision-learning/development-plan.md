# 修订学习与作品同步开发计划

日期：2026-11-04。状态：本轮确认的修订记录、对话入口与日志、写作约定、结构与模块建议应用已实施。验证见 [实施记录](notes.md)。基线为 v1.2 的写作工作台。

## 1. 产品目标与范围

作者希望已经纠正过的写法少在后续正文中重复出现，也希望已入稿的设定变化能同步到作品资料。系统保留真实改稿的前后版本。作者从对话发起分析，模型逐项判断差异影响写作约定、全书结构、已装入的模块，还是仅影响当前场景，并说明依据。作者在同一条对话中审阅并应用建议。

这项计划保留 [v1.2 产品方案](../../product-design/v1.2/README.md) 的对话入口，调整稿纸只读和全局提示范围。作者从对话进入章节编辑，稿纸承载直接修订。`STRUCTURE.md` 负责全书方向、情节与章节计划，已装入的模块负责人物、世界、线索等具体资料，`STYLE.md` 负责行文表达。写作约定默认限当前作品，每次正文生成全文注入。首版按单次修订手动分析，模块更新只涉及当前作品已装入的版本。

| 正文变更 | 记录与分析资格 |
| --- | --- |
| 作者亲手修改已入稿正文并确认 | 保存成功后记录「作者修订」，有效差异可分析。 |
| 作者在对话中要求模型修改已入稿正文 | 实际入稿后记录「按作者要求改稿」，关联作者原话和提交结果。沿用该路径已有的入稿机制。 |
| 作者采用模型的修改后又亲手改写 | 保存来源为「按作者要求改稿并由作者编辑」。保留模型候选引用，分析时可区分作者请求、模型改法和最终正文。 |
| 首次起草、单纯续写新增、导入、模型自行修改、未入稿候选、撤销 | 各自沿用既有历史或活动记录。若一次请求既续写又修改已有段落，只纳入修改已有正文的片段。 |

正文入稿、发起分析、应用建议是三个独立决定。模型执行的措辞选择只能作为观察线索。比如作者说「把这段压短」，应保留「这段」的局部范围。若作者说「以后质问场景都少写解释」，才有更直接的长期偏好依据。分析允许返回零条建议，并告知作者原因。

## 3. P1 修订记录、差异与恢复

| 数据 | 内容与归属 |
| --- | --- |
| `Revision` | `id`、`chapter_id`、`change_id`、`source`、`before_ref/digest`、`after_ref/digest`、`confirmed_at`。模型改稿补 `author_message_ref`、`operation_id` 和可用的 `candidate_ref`。一笔提交涉及多章时按章生成记录，用 `(change_id, chapter_id)` 去重。 |
| `DiffHunk` | `id`、算法版本、两侧段落范围、行内差异和定位所需的内容指纹。由不可变前后版本派生，可缓存。差异 ID 绑定修订和算法版本，行号仅用于显示。 |
| `RevisionAnalysis` | `id`、`conversation_id`、`operation_id`、修订和片段引用、状态、实际读取的结构和约定指纹、装配指纹及模块条目版本、各项判断和建议引用。 |
| `ImpactDecision` | 关联的差异片段、去向、简短理由、证据引用和结论。结论可为建议更新、仅本段、已有内容覆盖、依据不足。一个片段可有多个去向。 |
| `ImpactProposal` | `id`、目标类型、目标定位、基线版本、精确补丁、依据、依赖组和应用状态。模块目标包含装配绑定、模块、版本和条目 ID，文件目标包含文件指纹和块定位。 |
| `ImpactApplyReceipt` | 分析 ID、作者确认的建议及依赖组、请求键、目标前后版本、各步骤状态和撤销引用。生效内容仍由 `STYLE.md`、`STRUCTURE.md` 和当前装入的模块版本各自保存。 |

**记录时机。** 保存动作或已授权的对话执行将来源写入正文事务的持久化记录。事务准备时固定前后内容引用，完成后才向界面暴露修订。提交收尾重试或进程恢复时从同一事务补齐投影。Git 提交成功与否单独反映在回执中，已经确认落盘的正文可凭事务快照供分析。未入稿、无正文变化和仅换行编码变化均不生成分析记录。示意：

```python
revision_key = (receipt.change_id, chapter_id)
if receipt.finalized and eligible_origin and prose_delta.has_content_change:
    revisions.ensure(revision_key, origin, prose_delta.before, prose_delta.after)
```

**可分析范围。** 按段对齐，再对有对应关系的段落做字符级高亮。章节当前指纹等于修订后的指纹时可直接使用。后续改稿后，凭保留的段落及相邻锚点唯一确认当前仍保有的改动。纯删除需要确认两侧锚点仍相邻，并保留撤销关联。被覆盖、已撤销或有歧义的片段留在历史中。部分失效时，详情标记实际送审片段。提交 Git 或切换章节不影响资格。超长段落可以整段显示，超过分析输入上限时让作者明确选择送审片段。

## 4. P2 对话入口、稿纸修订与运行日志

- 在对话输入区提供「修订本章」「改动」「写作约定」。「修订本章」把 [写作布局](../../frontend/src/components/workspace/WritingLayout.tsx) 的稿纸切换为当前章编辑器。稿纸内提供差异预览和确认保存。冲突时保留本地草稿并展示当前稿。
- 人工改稿确认和模型改稿入稿后，都在对话里显示修订回执。回执提供「查看差异」「让模型分析」。「改动」可在对话里打开历史修订并选择要分析的版本。
- 正文 diff 按段纵向显示增删，行内高亮具体变化。折叠未变内容，改动片段可展开上下文。回执显示来源，模型改稿可展开作者原请求。分析回复按「写作约定」「全书结构」和模块名称展示实际有结论的目标，支持逐项展开依据和建议 diff。
- 每次在对话中调用模型，都在当前回复内显示简短进度并提供「查看运行日志」，包括普通讨论、起草、续写、改稿和修订分析。日志展示已读取的正文片段或资料、实际发生的工具动作、开始与完成时间、失败或重试状态。判断摘要说明模型依据哪些改动和现有资料做出判断。前端根据实际任务事件展示，按序号补收，切换章节或刷新后可以从原回执继续查看。

```text
对话输入框                            [修订本章 ▾]
对话回执 · 第七章修订                 [查看差异] [让模型分析]
  按作者要求改稿                       [展开原请求]
分析回复 · 建议更新「林岚」人物条目   [查看依据] [查看日志]
  作者明确要求林岚在后续被追问时转移话题。
  [查看模块差异] [应用建议]
```

## 5. P3 分析影响范围并解释判断

- 从对话开始分析时固定修订、有效片段、作者原话引用、`STYLE.md`、`STRUCTURE.md` 和当前模块装配快照。先依据差异和相邻段落定位人、物和事件，再按需读取已装模块的精确条目版本。原消息不可用时在结果里标明，判断限于现有证据。相同请求键返回原结果，运行中的相同输入共用任务，失败后从对话重试。
- 按语义判断影响。台词、环境描写和叙述是改动所在位置，同类文本可能有不同去向。优先比对已有资料和作者明确要求。一个片段可以影响多处，也可以只改当前段落。

| 判断 | 写到哪里 | 例子 |
| --- | --- | --- |
| 全书可复用的表达偏好 | `STYLE.md` | 作者要求以后写环境都先呈现人物能感知的细节。建议写清适用场景；一次换景或单处改句通常不足以推出全书规则。 |
| 人物、世界或线索的持续变化 | 对应的已装入模块条目 | 作者明确要求林岚从这一章起遇到追问就岔开话题。若只是此处临时掩饰，保留在该场景。环境描写改变了地点的固定布局时，也可能归入世界模块。 |
| 跨章事件、路线或披露计划变动 | `STRUCTURE.md` 对应段落 | 台词将关键证据的揭露从第七章提前到第六章，可以分别提示全书结构和已装线索模块受影响。 |
| 仅当前场景、已有内容覆盖或依据不足 | 在对话说明，必要时追问 | 一句更短的台词可能是在加快这场对话，也可能是人物长期说话习惯。先给作者看差异并询问适用范围。没有匹配的已装模块时，说明缺少目标，由现有对话流程决定是否装入或创建。 |

- 对每个送审片段给出可核对的结论。每项建议包含目标、依据和将发生的具体变化。可直接读取并比对同一目标的既有内容，已有覆盖时说明对应规则或条目。正文台账和事实索引继续沿用既有提交与校验流程。
- 模型提出补丁，服务端校验目标属于已读取的文件或已装入模块，引用指向本次有效差异，旧内容与分析基线一致。首版支持对文件规则块、结构段落和模块条目做小范围增改。对话内展开每个目标的前后差异。

```json
{
  "hunk_ids": ["hunk_1"],
  "target": {"kind": "module_entry", "ref": "person_lin_lan"},
  "decision": "propose_update",
  "reason": "作者明确要求林岚从这一章起用转移话题应对追问。",
  "replacement": "从第七章起，林岚受到追问时习惯把话题引回对方身上。"
}
```

分析结果返回后和应用前都重新检查证据是否仍有效。作者补充意图或当前稿、目标资料发生变化时，从原对话按最新版本重新分析受影响的建议，旧结果保留供回看。

## 6. P4 建议应用、作品同步与固定注入

**对话确认。** 作者在对话里按目标确认建议。应用时校验目标文件指纹、模块条目版本和装配版本。发生冲突时说明哪个目标变了，引导作者重新比较。

**结构与模块。** 结构补丁沿用结构文件写入。模块更新复用 `ModuleChangeService` 与 `save_workspace_revision`，从作品当前装入的精确版本生成新版本，切换当前作品的绑定。公共库头版本和其他作品的绑定不随该操作更新。

- 「打开写作约定」显示可读可写的完整 Markdown。手动保存可创建、修改或清空 `STYLE.md`。对话中的写作约定建议也可先修改再确认，与手动编辑共用文件保存服务。原子替换、并发检查和版本记录复用现有工作区机制，为根目录文件补齐历史和撤销路径。`STYLE.md` 的写入以作者保存或确认建议为授权。
- 写入时校验原始字节指纹。文件在编辑或分析期间被修改时，显示「当前文档」和「待保存内容」，保留本地编辑稿，作者基于当前文件合并后再确认。文件保存和 Git 记录分别报告，避免重试重复追加或覆盖。
- 在模型发送前按 `STRUCTURE.md` → `STYLE.md` → 相关模块与正文事实的顺序装配。每次正文生成入口读取已保存的文件，全文预留输入空间，并记录实际发出的 `style_digest`。同一执行使用已装配的版本，新请求和恢复后重新生成的尝试读取最新版本。普通讨论和上下文摘要不用这个写作区块。写作规则按适用条件执行，作品事实和结构约束由现有机制负责。
- 文件不存在或为空时使用空约定。作者保存时校验编码及长度。外部编辑造成不可读、超限或写作请求放不下完整约定时，在发送前给出明确处理提示。写作约定保留完整，先为可选上下文调整预算。

```python
style = read_style_snapshot(workspace)
if request.generates_prose:
    context.add_required_section("写作约定", style.text, digest=style.digest)
```

```text
[STYLE_CONTEXT_TOO_LARGE] 写作约定：本轮无法装入完整文档。建议：缩短写作约定或减少本轮引用材料。
```

## 7. 前后端接口对齐

以下路径以作品路由为前缀，具体命名在 P0 按现有路由核定。版本回执和按钮显示以服务端返回为准。

| 界面操作 | 接口与最小返回 |
| --- | --- |
| 读章、确认人工修改、采用正文候选 | 复用读章及 `PUT /story/chapters/{chapter_id}/prose`。保存带 `expected_digest`、`request_key`，必要时带候选引用。返回 `change_id`、正文指纹和可空的 `revision_id`。对话改稿在现有回执补章节与修订引用。 |
| 看某章修订列表、展开某次差异 | `GET /story/chapters/{chapter_id}/revisions`、`GET /revisions/{id}`。返回来源、历史差异、当前可分析片段、已有分析引用。 |
| 对话发起分析或重试、查看分析 | `POST /revisions/{id}/analyses` 带对话 ID、片段 ID 和请求键，返回分析记录。`GET /revision-analyses/{id}` 返回状态、判断、日志和建议。 |
| 在对话查看进度和日志 | 正文对话沿用已有消息和工具活动。修订分析读取分析记录的状态与日志，重新打开修订时按会话恢复最近一次分析。 |
| 在对话应用建议 | 按目标调用 `POST /revision-analyses/{id}/applications`、`/structure-applications` 或 `/module-applications`，校验目标版本后写入并记录结果。 |
| 直接读写写作约定 | `GET /style` 返回全文和指纹。`PUT /style` 接收全文、基线指纹和请求键，按作者声明保存。 |

本地预览差异和已保存差异共享展示格式。编辑预览的行号或文本不得用来确认已保存修订的分析资格。写入请求同键同内容返回原回执，同键异内容返回冲突。

## 8. P5 验收与交付

| 验收 | 通过条件 |
| --- | --- |
| 人工与对话两条路径 | 同一章分别完成亲手修改和要求模型改稿。两次都有独立 diff；模型改稿能查看作者原话。单纯续写和未采用候选没有可分析修订。 |
| 历史与可分析状态 | Git 干净后仍可发起，刷新后结果可恢复。无关段落更新保留原资格。相关段落撤销、覆盖或产生歧义时只保留历史；部分失效时只发送仍有效的片段。覆盖插入、纯删除和重复段落。 |
| 影响判断与依据 | 分别验证人物长期习惯、人物临时反应、作者表达习惯、地点固定布局和跨章揭露变化。覆盖同片段建议同步结构及模块、已有内容覆盖和需要作者确认范围。回复能定位到相应 diff 和资料。 |
| 写入、重试与并发 | 分析后目标变化时提示冲突；模块建议应用后当前作品使用新模块版本，公共库头版本和其他作品仍使用各自版本。 |
| 建议与生效 | 对话可分别应用三类目标的建议。手工改约定、保存建议或清空后，下一轮使用最新保存的约定。 |
| 实际模型请求 | 对所有正文生成入口截取实际请求，校验完整约定和记录指纹一致。覆盖无文件、空文件、不可读、过长、暂停后重试。 |
| 浏览器和在线模型 | 浏览器从对话走通两条改稿路径、原始 diff、分类说明、各目标 diff 与应用回执。模型运行时日志可展开，切换章节、刷新、失败重试后可继续查看。用 `.env` 的在线模型做少量语义用例，覆盖人物与文风区分、结构与模块联动、局部改动不推广。失败后先修复再单例复测。 |

实施顺序为 P0 → P1 → P2 → P3 → P4 → P5。P1 与 P2 先用确定性输入验证正文保存和 diff。P3 与 P4 接通分析及写作请求后再做在线验收。交付时补实际测试结果和版本记录。
