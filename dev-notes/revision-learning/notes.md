# 修订学习实施记录

日期：2026-11-04。对应 [开发计划](development-plan.md)，记录修订、影响分析、写作约定和对话交互的实施情况。

## P0 入口与事务映射

| 写入路径 | 事务位置 | 能否生成修订 | 来源标记 |
| --- | --- | --- | --- |
| 作者在章节编辑器整章保存 | `chapter_writing.save_chapter_prose` → `StoryStore.commit_change(kind=prose_save)` | 能；只比正文，结构改动不参与 | 收据 `result.revision_source = author` |
| 作者采用创作辅助候选 | `service.py` 候选采用 → `commit_change` | 能；候选与作者确认一起入档 | `candidate`，附候选 ID、操作号与作者原话 |
| 作者要求模型改稿 | `agent.write_file` / `agent.edit_file` 写入正文后 | 能；无结构变更记录，按前后指纹直接落一条 | `model`，附操作号、会话与作者原话 |
| 建章、章节改名 | `writing_actions` | 不能；骨架与标题变化不构成写作习惯证据 | — |
| 撤销、结构变更、未入稿候选 | `StoryStore.undo` / `story.update` / 候选存储 | 不能 | — |

`STYLE.md` 由 `style_io` 直接读写，作者保存即生效；模型只能提出建议，写入仍由作者确认。
写作轮次在 `service.py` 装配上下文时读取最新文件，并在 `state_injected` 事件里记录
`style_digest`。

## 已实现

- **修订记录**：从变更记录的整文件反向补丁派生，`(change_id, chapter_id)` 幂等；首次起草、
  纯追加续写不生成。状态目录 `story/prose-revisions/`，不写作品目录、不进 Git。
- **差异**：段落对齐 + 段内字符高亮；片段 ID 由内容与算法版本决定。可分析性按当前正文
  重新判定：改写段落唯一命中即有效，删除要求两侧锚点仍相邻，歧义片段只留在历史。
- **接口**：章修订列表、修订详情、发起分析、读取分析、确认写入写作约定、读写
  `STYLE.md`。见 [数据与接口](../v1.2/data-and-api.md)。
- **分析**：一次分析固定修订、有效片段、作者原话、`STYLE.md`、`STRUCTURE.md` 与已装模块
  条目摘要；模型逐条给出「写作约定 / 全书结构 / 模块条目 / 仅当前场景」和依据。
- **写作约定生效**：对话起草、续写、改写及创作辅助的起草、续写都读取最新保存的 `STYLE.md`。
  写作约定紧跟全书结构全文注入，共用预算检查，超预算报 `STYLE_CONTEXT_TOO_LARGE`。
- **对话回执**：章节选中时，对话输入框上方显示最近一次修订（来源、时间、改动处数），
  提供「查看差异」「让模型分析」。发起后在对话内容内显示进度、判断与建议。刷新后从同一会话的
  修订详情恢复分析结果或继续查看进行中的任务。
- **运行日志**：分析记录实际读取的资料（修订片段、写作约定、全书结构、已装模块条目）
  与执行步骤（准备材料、模型请求开始/完成、解析判断、失败原因），开始请求时就保存并展示。
  对话中的「查看运行日志」可展开这些记录，进程中断后可从同一处重试。
- **界面**：对话输入区提供「修订本章」「改动」「写作约定」。修订面板在对话内容内展示差异和
  建议，写作约定可整份编辑、保存。
- **稿纸修订模式**：从对话点击「修订本章」后在稿纸编辑。编辑与「看差异」共用纸面，差异按段落对齐、
  段内高亮增删；输入时不自动入稿，只有「确认修改」产生一次修订。取消需要二次确认，
  切换章节或刷新后草稿仍在。正文期间被别处更新时保留草稿并让作者选择用哪一份；确认后
  对话回执可打开同一条修订记录。
- **结构建议应用**：分析若判断改动影响跨章事件或披露计划，要求模型给出 `patch_find` /
  `patch_replace`，定位文本必须从当前结构逐字复制且唯一。面板可勾选并写入 `STRUCTURE.md`；
  应用前核对分析时的结构指纹，定位失效或结构已被改过时拒绝覆盖，保留建议供重新分析。
- **模块建议应用**：分析材料只给与本次改动同名的已装条目附上正文与指纹（总预算 24000 字符，
  单条 1200 字符）。模型返回模块、版本、条目、条目指纹与定位补丁；分析时校验条目归属与唯一性。
  面板勾选后按模块合并成一次 `ModuleChangeService` 更新，生成作品专用版本并切换本作品绑定，
  模块库头版本和其他作品的绑定不动。条目指纹变化或定位失效时拒绝覆盖。
- **分析基线**：分析记录同时保存 `assembly_digest`。应用模块建议前核对装配没有被别处改过。

本轮更新目标为 `STYLE.md`、`STRUCTURE.md` 和已装入模块条目。线索页的计划与台账同步、跨目标联合提交与联合撤销另属其他范围。
