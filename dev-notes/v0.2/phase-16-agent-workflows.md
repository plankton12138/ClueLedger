# Phase 16：无状态工作者、任务上下文与持久工作流

> 状态：已完成，2026-10-15。前置：[Phase 15](phase-15-change-impact.md)；下一阶段：[Phase 17](plans/phase-17-migration-cleanup-plan.md)。

## 1. 为什么做这一阶段

前几阶段已经能可靠保存故事、批准影响范围并在分支修订。本阶段解决的是：把模型接进这条管线以后，不能让“模型说完成了”重新成为项目事实。

因此把三个结果分开：Job 记录执行进展，Proposal 记录候选，Commit 证明作者接受后的项目变化。模型每次从固定版本重新取得任务资料，不依靠一份长期 Harness 记忆维持项目状态。

## 2. 交付内容

| 用例 | 实际行为与边界 |
|---|---|
| 主编 | 确定性意图分类支持查询、人工命令、发起/继续变更、审计、草稿、解释和规划；也可用独立 Worker 返回用例候选。歧义返回少量问题，不签发审批 |
| 规划 | `StoryProposal` 的内容按纯领域命令预演，顺序校验父级与引用；作者接受后同一 Commit 写入故事对象与关系 |
| 草稿 | 只从已接受 Beat 出发，Writer 返回整章候选；接受时检查基础版本和相关人工改动，同事务建立 Beat→TextUnit 的 `renders` 血缘 |
| 修复 | 按 Phase 15 已批准步骤构建 Repair Context；越权或过期补丁先回报模型，最多纠正一次，再交原有执行器写 revision branch |
| 审计 | 确定性审计先行；Critic 只有只读工具。Finding 必须有范围内对象、精确原文引用和理由；无定位意见属于 editorial note |
| 风格观察 | Outbox 自动派发真实人工保存前后的 diff；规则优先识别事实/格式，模型补充观察只归纳为 candidate，不能激活或复活撤销的偏好 |

六类 Worker 共用严格输出联合，但发送给 Provider 的 Schema 只包含当前角色允许的分支。所有模型返回，包括替换实现的 AgentRunner，都再次经过应用层范围、版本、正文身份及引用证据检查。

`SqliteJobStore` 与项目共用数据库文件，任务表独立于故事 Commit。状态为 queued/running/waiting/retryable_failed/terminal_failed/completed/cancelled，保存输入 Context、检查点、尝试次数、退避时间、租约代际和单调事件游标。已取消或被接管的执行不能发布迟到输出。

服务启动会自行发现待发布项目 Outbox、恢复到期任务，并补交“Worker 已完成但分析元数据尚未提交”的结果。正常停机保留可恢复状态；故障重试不会改写输入意图。预算不足属于需要缩小任务的违规，Provider 断线属于环境故障，空结果独立完成。

界面入口为“变更中心→规划与生成任务”：可新建 V2 故事、接受规划、选择节拍、审阅正文、人工保存、查看任务事件和取消/重试；已批准变更另有“由 Agent 执行已批准修订”。完成状态与正式提交编号分别展示。V1 项目仍使用原链路。

## 3. 关键决策与取舍

1. **先选资料，再给模型。** 四类 Builder 共用确定性选择内核，按角色绑定依赖深度：Draft/Audit 两跳，Repair/Style 一跳；补充结构父级、相邻段落与前一节拍正文窗口。Draft 携带目标 Beat 的进入/离开状态、角色认知与读者披露；Repair 保留种子变化、步骤、影响路径及审批证据。偏好按章节优先级解析，仅使用 active 偏好与有效正反例引用。
2. **预算采用保守上界。** 用 UTF-8 序列化字节估计 token 上界，保证固定版本、授权、错误和指令不被截断；可选输入按固定顺序裁剪并给 omissions 与可读回引用。必需输入装不下则要求拆小任务。尚未进行 Provider 专用分词校准。
3. **工具只有查询和提案。** 注册集合为角色白名单与 Capability 的交集。没有旧 `bible_upsert/write_chapter/story_stage`、任意写文件或审批工具。Writer 的设定缺口可以成为建议，不能借此接受 Canon 修改。
4. **候选接受需要可重放证明。** 接受结果随 Commit 保存 `agents.acceptance`，崩溃窗口重试读取原 Commit；分析提交也使用稳定幂等键。正文生成本身不发送人工保存事件，显式观察入口也拒绝把候选接受 Commit 当成人工编辑来学习。
5. **接口保持最小。** 当前事件出口为带 `after` 游标的持久任务事件查询，界面轮询；未新增 WebSocket 会话记忆或独立分布式任务系统。服务为单节点装配，跨进程仍依靠持久 claim 和仓库 Lease 防止重复生效。

## 4. Agent 设计经验

### ① 错误消息是喂给模型的 API

输出不合法时提供 `where/why/expected`，让模型知道错在范围、基础版本、内容身份还是原文引用。真实修复回放先故意提交范围外文本，模型读到错误后缩回本步骤；第二次仍失败则保留原输出和错误，不让“再试一次”变成无限循环。

领域命令预演同样重要：JSON 格式正确不等于故事结构可提交。Planner 的角色枚举、父级存在性及必填字段在候选阶段便受到检查，而不是留到作者点击接受时才发现。

### ② 硬约束放工具层，prompt 只负责解释世界

审计员看不到写工具；Reviser 的补丁必须同时通过 Capability、固定 Revision、内容结构守卫与 Phase 15 审批/Lease。主编 prompt 解释“选择用例不需要正文写权限”，但即使模型误解，也不能生成 Approval Receipt 或绕过作者接受。

真 Provider 还暴露了工具 Schema 的协议边界：嵌套输出的 `$ref` 必须在工具参数根部解析。新增六角色引用契约测试，防止“Fake 能解析、实际接口拒收”。

### ③ 泄压阀：区分违规、空结果与环境故障

没有问题用 NoResult 正常完成；越权、错版本与两次 Schema 失败终止并供作者处理；断线使用有上限的退避。即使重试次数耗尽，错误类别仍保留 environment，不把基础设施故障归责于模型。

自动编辑分析遇到超预算时保存可见失败，不中断后台派发循环，也不把过长正文悄悄裁掉当作完整证据。风格任务始终以真实 diff 为依据，规则确认的数字变化不会被模型的“短句偏好”判断覆盖。

### ④ 可观测性是事件契约的一部分

任务事件保存独立 sequence，`commit_id/project_sequence` 保持空值；分析元数据或作者接受另给真实 Commit 证明。取消会推进代际并停止续租，迟到事件和候选都被拒绝。重启不需要复原一份隐藏的模型会话。

Tau 当前 loop 不把工具结果中的 `terminate` 当作停止条件。适配器在完整回合结束时停止并关闭本次流，避免候选已收到后仍多调用一次模型；上游 `tau_agent/tau_ai` 没有改动。

## 6. 下一阶段边界

本阶段提供独立 V2 创作入口，不迁移 V1 工作区，也不删除旧 Agent、旧工具和旧存储。旧数据导入、界面全面迁移、导入导出及旧写入口不可达证明归 Phase 17。复杂自由文本修改仍须通过明确对象和变更审批；主编不代替作者批准。
