# ADR-005：人工保存先提交，风格观察与影响分析后置

- 状态：已接受（2026-10-14）
- 关联：[DESIGN.md §7.2](../DESIGN.md#72-人工修改正文)、[manuscript-author-model.md](../modules/manuscript-author-model.md)

## 上下文

V1 中人工编辑与 Agent 写入走不同路径，人工保存可能被后台对账（reconcile）判定为"漂移"而覆盖。任何"保存时顺带分析"的设计都会把模型延迟和故障传染给最不能失败的操作——作者保存自己的正文。

## 决定

人工修改（ManualEdit）与 Agent 修改共用统一提交入口：版本与文本边界检查通过后原子提交新正文版本，立即向作者返回成功。事实分类、影响分析、风格观察全部作为提交后事件驱动的工作流异步执行；后台分析失败不影响已提交的正文，任务保留可重试状态。风格证据采集在提交后进行，且事实修订、错别字修复、格式化不作为文风证据。

## 后果

- "用户保存的正文立即成为当前有效版本"成为可测试的不变量（P5）；
- 人工与 Agent 写入共享版本历史，消除分叉；
- 事件驱动的后台分析引入最终一致：作者看到影响报告有延迟，需要 UI 明示"分析进行中/失败可重试"，不得静默吞掉失败。

## 替代方案

- 保存时同步完成分析：保存延迟绑定模型延迟，模型故障会导致保存失败，违反 P5；
- 人工编辑独立通道不复用提交管线：回到两条写路径分叉的老问题。

## 触发重新评审的条件

- 后台分析延迟长期不可接受（如 > 分钟级）且作者明确要求即时反馈——应做增量/乐观分析展示，而非阻塞提交；
- 事件丢失率不可忽略时优先修复 Outbox（ADR-007），不回退到同步分析。
