# Phase 18：模型接入与切换

> 日期：2026-10-15。前置：[七页作者工作台](phase-17-frontend-workbench.md)。
> 方向：参考 Tau Coding 的连接目录与模型选择流程，优先国内厂商 API / Coding Plan，保留本地模型。

## 1. 为什么这样设计

作者需要决定的是“连接哪家服务、用哪个模型”，服务地址和协议应由应用填好。
旧设置只提供通用表单，而且 V2 工作者自行读取默认路径、选择第一个可用档案：
即使作者保存了另一家配置，也不能确定任务实际用了谁。新的接入流程必须同时解决
界面选择与运行时选择，不能只给旧表单加几个默认值。

## 2. 交付内容

- 顶栏显示当前模型，点击“切换模型”打开独立模型设置；普通设置也保留模型入口。
- 来源按厂商 API、订阅 / Coding Plan、本地模型与自定义分组。内置来源不要求填写服务地址。
- 连接与选择分开：先保存密钥或显式环境变量引用，再选择模型并点击“使用此模型”。
- 国内 API 包括 DeepSeek、智谱、Kimi、百炼、MiniMax、硅基流动；保留已有 OpenAI、OpenRouter。
- 套餐目录包含 GLM Coding Plan、百炼 Coding Plan、Kimi Code、MiniMax M Plan / Token Plan。
  它们分别保存凭证，不把普通 API Key、网页会员订阅和套餐 Key 混为一谈。
- Ollama 和 LM Studio 预填本机地址、免密接入、读取模型列表；Ollama 保留安装引导、
  检测、下载进度、取消、删除与设为当前模型的流程。自建兼容服务继续通过自定义入口接入。
- `/api/model-selection` 查询/保存当前来源与模型；`/api/providers/connect` 按目录连接，
  `/api/providers/{name}/model-choices` 提供实时模型列表或明确标注的内置候选。
- 显式选择持久保存为服务级配置中的 `active_provider` / `active_model`，跨项目、刷新和重启生效。
  正在运行的任务保留已解析的适配器，后续开始的模型调用使用新选择。

## 3. 关键决策与取舍

### 与 Tau 的对应关系

参考 `tau_coding/provider_catalog.py` 与 `data/catalog.toml` 的公开目录、
`credentials.py` 的服务端凭证边界，以及 `tui/app.py` 中连接和选择分开的处理。
Hastings 只维护应用需要的来源子集，不直接引入 TUI 和整份模型元数据依赖。
`tau_agent`、`tau_ai`、`tau_coding` 均无改动。

### 同一份选择驱动界面和任务

应用装配把同一 `ProviderBook` 注入连接 API 和 `ConfiguredV2Runner`，修复 V2 忽略
`--config` / `--config-dir`、自行重读默认文件的问题。显式选择失效时任务报错，
不会静默换厂商。既有默认配置在没有显式选择时继续提供启动默认值。
密钥、端点或协议更新会失效旧实例缓存；配置通过临时文件原子替换，写盘失败不更新内存选择。

### 本地模型不能只在表单里“免密”

本机模型发现和实际推理都绕过系统代理，空密钥不发送 Authorization。
接入协议显式声明，不根据 `gpt-*` 等模型名字猜协议：例如本机 `gpt-oss:20b`
仍使用配置的兼容接口。本地下载卡片通过 V2 选择出口切换，不创建旧工作区。

### 模型候选不等于已验证的连接

模型列表接口返回 404/405 时才回退内置候选，并明确说明尚未验证实际模型调用。
401/403、网络故障和无效响应继续显示各自错误，不能用目录兜底把坏密钥伪装成成功。
模型列表为空是合法结果；可手动指定模型编号。密钥只提交到服务端配置，不写入浏览器存储。

### 订阅的接入边界

本阶段使用厂商提供的套餐 Key，没有实现浏览器 OAuth 登录，也不读取或复用 Tau 的账号凭证。
预设的存在不代表 Hastings 获得厂商的套餐工具资格，不伪装成其他工具或自动改走按量 API。
界面提供对应的官方说明及使用范围提示：

- [智谱官方接入工具](https://docs.bigmodel.cn/cn/coding-plan/tool/others)：指定支持的工具与套餐专用端点。
- [百炼 Coding Plan](https://help.aliyun.com/zh/model-studio/coding-plan)：套餐 Key / 地址与普通 API 不互通，
  官方明确不允许自定义应用后端调用；Hastings 应选择百炼普通 API。
- [Kimi 第三方工具](https://www.kimi.com/help/kimi-code/third-party-agents)：工具接入范围由厂商决定。
- [MiniMax M Plan](https://platform.minimax.cn/docs/m-plan/intro)：第三方 AI 工具使用订阅 Key，
  新旧套餐的模型权益以账户实际返回的列表为准。
- [DeepSeek 快速开始](https://api-docs.deepseek.com/) 与 [Kimi API 快速开始](https://platform.kimi.com/docs/get-api-key)
  用于核对普通 API 的地址与候选模型。

来源核对日期为 2026-10-15。没有用户真实厂商凭证，本阶段不声称已验证账户权益、配额扣减或真实推理成功。

## 4. Agent 设计经验

### ① 错误消息是喂给模型的 API

“模型来源缺少凭证”明确定位到当前来源，并指向设置中的连接与选择动作。
不再让模型猜测启动脚本读了哪个文件。候选列表兜底同时说明原因与尚未验证的边界。

### ② 硬约束放工具层，prompt 只负责解释世界

厂商预设的地址由服务端决定，前端只提交目录身份；套餐凭证与普通 API 凭证分开。
选择来源不可用就拒绝执行，不能在 prompt 里承诺“使用 A”而实际调用 B。

### ③ 泄压阀：违规、空结果与环境故障

未知来源/空模型是参数问题，空模型列表是正常结果，鉴权/网络/配置写入失败有独立提示。
只有确定不支持模型列表接口时才使用静态候选；凭证失效不能触发跨厂商自动回退。

### ④ 可观测性是事件契约的一部分

`agent.started` 增加实际使用的 `provider` 与 `model`，属于任务过程，不冒充项目 Commit。
界面显示的是服务端确认的模型选择，异步旧读取不能覆盖新选择；任务事件可核对实际执行来源。

## 5. 验证与评审记录

核心行为先写失败测试，再实现。覆盖预设连接、凭证隔离、选择持久化、真实 V2 适配器装配、
无凭证不跨厂商回退、实例缓存更新、写入失败保留配置、模型列表回退和本机免密协议。

浏览器旅程使用隔离配置与确定性模型目录，验证厂商连接→选模型→刷新保留→套餐预设→
本地接入，以及鉴权失败保留当前模型；原有创作与修订旅程继续通过。
所有模型发现和任务模型响应均为测试替身，不向真实厂商发送请求。

后端全量 1,238 项、前端单元 277 项、浏览器旅程 9 项通过；生产构建、全项目静态检查、
215 个源文件的类型检查及差异空白检查通过。截图位于 `frontend/test-results/v2-models-*/`。

## 6. 交付后本机联调修复（2026-10-15）

用户遇到模型选择 GET 404 / PUT 405，且厂商下拉框为空。实机检查发现 8000 端口仍运行
19:01 启动的旧进程：旧目录没有 `category` 字段，新前端按分组过滤后没有任何匹配项；
模型选择新路由也尚未加载。确认没有持久任务后，保留原数据库路径重启该项目服务，
模型选择接口恢复 200，目录返回 14 个带分组的来源。

客户端现对旧目录缺少分组字段、模型选择接口 404/405 给出明确的“前后端版本不匹配，
重启后端后刷新”提示，不再把旧响应当成合法空列表。合法空目录与业务拒绝保留原语义。
先观察 3 项失败的契约测试，再补实现；4 项客户端兼容测试和旧后端模拟浏览器旅程通过。

本机原配置的 `qwen3:4b` 未安装，实际已有 `qwen3.5:4b` 等 4 个模型；将当前选择切到
已安装的 `qwen3.5:4b`。真实适配器短请求返回 `OK`。首次冷启动触发旧 45 秒等待上限，
因此回环地址的工作者 HTTP 等待调为 180 秒、任务总预算调为 600 秒；云端仍为 45/120 秒，
分别有回归测试。模型内部的加载时间与长上下文性能仍由本机运行环境决定。

补充验证：前端单元 281 项、模型接入浏览器旅程 4 项通过，生产构建和类型检查通过。
本节的实机短调用只访问本地 Ollama，没有使用任何云端厂商凭证。
