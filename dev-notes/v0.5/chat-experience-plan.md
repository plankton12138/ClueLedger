## 1. 为什么做与完成目标

作者发送要求后，应能及时读到生成内容、知道任务正在做什么，并在需要时展开过程。任务结束后，公开回复易读、容易复制；切走、刷新或断线后仍能恢复同一条消息，停止后也能看清已生成内容与实际文件变化。

对话仍是写作台的一部分，回复文字保持主体地位。思考和工具详情按需展开，不长期挤占阅读空间；宽表、代码和长回复可临时展开阅读。已经确认的独立会话、空白新建不保存、草稿保护和任务归属继续生效。

本次交付不是仅把整段回复做成逐字动画，而是将模型实际返回的增量接到会话记录与界面上。对不提供增量的端点，收到完整回复后正常展示，不伪造模型生成过程。

### 1.1 本次交付

- 实时更新同一条公开回复，按实际顺序穿插思考文本与工具执行过程。
- 思考与工具详情默认折叠；运行时显示真实阶段与可测量的耗时，点击展开已有内容。
- 公开回复以 Markdown 展示，支持自然段、标题、列表、引用、表格与代码块。
- 复制公开回复的 Markdown 原文、展开回复阅读、自动跟随与回到最新位置。
- 停止、失败、输出达到上限时保留已有内容并标记完整性；重连和刷新只补齐记录。
- 旧日志可读，新消息的增量、最终公开文本与后续会话上下文保持一致且不重复。

### 1.2 不进入本阶段

预选项、模型提问选项、快捷提示词与后续建议按钮；方案卡、关系图、流程图、任意可视化组件；上下文压缩与自动摘要；思考深度/预算设置；自动切换模型；重新生成或编辑历史消息后重跑；新增写入审批流程、正文编辑器或自动任务。

Markdown 表格属于普通排版，保留在本次范围内。流式写作不等于逐字写入正文文件，作品文件仍由现有工具按原规则修改，Git 仍按轮次记录。

材料定位、人物标签、章节名称和作者主动生成的章节索引见独立的[上下文与作品信息开发计划](context-management-plan.md)。上面的摘要排除项适用于本对话框阶段，不取消该独立计划；两项计划都不实现会话压缩。实施时共用现有轮次与事件，不建立平行的任务系统。

## 2. 使用行为与默认值

### 2.1 一轮对话的阅读顺序

按事件发生顺序展示作者要求、模型内容、工具操作、后续回复和本轮结果。同一轮可能有多次模型响应；每次响应也可能同时包含思考与公开文本，不能把所有文字都推迟到整轮结束再统一放到底部。

```text
作者要求
  → 等待模型响应
  → 思考内容（默认折叠，有内容时可展开）
  → 模型公开说明或回复（逐段更新）
  → 工具执行（紧凑摘要，可展开详情）
  → 后续思考/公开回复
  → 本轮执行与历史记录结果
```

状态必须有依据：尚未收到内容时显示「等待模型响应」，收到思考事件后才显示对应阶段，实际工具开始后显示「正在读取/修改……」。没有可靠信息时不显示进度百分比或预计完成时间。

### 2.2 思考与工具过程

- 每段思考默认折叠，运行中也不自动展开；作者展开后继续更新，结束时保持其本次展开选择。
- 仅展示供应商实际返回的可展示思考文本或摘要。没有返回文本时不显示空的可展开面板；不额外调用模型生成一段解释充当思考过程。
- 隐藏或展开只改变阅读方式，不改变模型请求参数。本阶段不自动开启更高推理预算，也不为获得思考文本更换模型。
- 只保存思考文本和展示所需状态，不输出或存入展示事件的原生思考签名、加密字段、redacted 内容与完整原始响应。
- 工具摘要显示动作、文件或查询对象及成功/失败；详情沿用安全的定位参数和结果摘录，不复制整章正文或完整写入参数。
- 同名工具的不同调用独立配对。失败在折叠状态也可见，详情提供已保存的具体原因。
- 各块持续时间从应用实际观察到的开始、结束计算。只观察到一段思考输出时，标成「思考输出持续时间」，不宣称测到了模型内部全部思考时间；只有完整结束后才冻结耗时。

当前阶段的一行状态常显；详细过程默认收起。实际已修改文件与 Git 结果来自应用执行记录，模型的准备说明不替代成功状态。

### 2.3 流式 Markdown

公开回复默认按 Markdown 阅读。小说片段保持自然段，不强制所有回复使用小标题或表格。作者消息继续按原输入文字展示。

流式期间优先呈现已经收到的文字，允许未闭合的列表、代码围栏和表格暂时以容错布局显示；结束时以保存的最终文本重新核对排版。渲染不改写原文、不往消息里补永久 Markdown 字符。

段落、标题与已完成内容块使用稳定标识，降低新文本到来时的重排。代码和表格在对话栏内允许横向滚动；普通长词换行。沿用现有 Markdown 渲染组件，关闭内嵌 HTML，任务列表只读，链接按允许的协议处理。外部图片不在本轮自动加载，保留链接或替代文字。

### 2.4 阅读操作

- **复制回复**：复制该条公开回复的 Markdown 原文，不夹带思考、工具日志、耗时或按钮文字。生成中复制的是当前已收到文本；无公开文本时不提供空复制。
- **展开阅读**：在宽阅读对话框中查看同一条回复，继续跟随它的内容更新；关闭后回到原消息与原滚动位置，不创建第二份消息或新会话。
- **自动跟随**：作者位于底部附近时跟随新增内容；主动向上滚动、选择文字或展开旧内容时暂停跟随，显示「回到最新」。
- **回到最新**：点击后滚到最新内容并恢复跟随；结束或收起过程不能强行把向上阅读的作者拉回底部。
- 折叠选择、展开阅读和滚动锚点是界面状态，不发送给模型。首次打开或刷新后的默认过程状态仍为折叠。
- 保留现有停止入口和草稿编辑。复制、阅读或关闭展开视图均不执行模型，也不重新执行文件工具。

### 2.5 停止、失败与断线

作者停止后，已保存文字继续显示并标明「已停止，回复未完整生成」，实际文件与历史仍按现有规则处理。模型失败、达到输出上限、服务中断也要显示内容完整性，不能因为存在一段文字就显示完整成功。

网络断开表示接收中断，不代表服务器任务结束。重新接收时从最后确认的会话事件继续；正常完成的块不重复追加，增量也不在最终完整文本到来后显示两遍。服务重启后只恢复已保存内容并标记中断，不自动再次调用模型或工具。

## 4. 消息与事件契约

### 4.1 标识和层级

一条记录明确归属「作品 → 会话 → 轮次 → 模型响应 → 内容块」。每次模型响应由应用生成稳定 `message_id`，不能用模型名称或供应商返回的响应 ID 代替。思考与文字块分别有 `block_id`，基于响应内实际内容位置保持顺序；工具用独立 `tool_call_id` 配对。

所有新事件继续有本会话单调递增的 `seq`、时间和 `turn_id`。前端先按会话/seq 去重，再按消息/块归并。局部字符批次使用连续 `part` 编号，避免不同语言对 Unicode 字符偏移计数不一致。

每个块的 `part` 从 0 开始，无增量时不生成 delta，结束事件的 `last_part` 为 -1。空块不展示；块顺序来自开始事件和原始内容位置，不能按块类型重新排序。

### 4.2 新增事件与保留事件

| 事件 | 内容与用途 |
|---|---|
| `assistant_started` | message_id，标记一次模型响应 |
| `assistant_block_started` | message_id、block_id、kind（text/thinking）、顺序；创建展示块 |
| `assistant_block_delta` | block_id、part、text；追加一批真实增量 |
| `assistant_block_finished` | block_id、最终完整 text、last_part、completion、duration_ms；校对与关闭该块 |
| `assistant_message`（保留） | message_id、公开文本、completion；一次响应唯一的正式公开文本记录 |
| `assistant_finished` | message_id、completion、供应商结束原因；结束一次响应，不等于整轮已完成 |
| `tool_started / tool_finished`（扩展） | 保留定位与摘要，增加 tool_call_id 和观察到的耗时 |
| `run_phase` | 应用确认的等待模型/工具执行/记录历史等阶段，用于状态行 |
| `error / run_finished`（保留） | 本轮失败原因、实际结果与 Git 记录状态 |

`completion` 取 completed/stopped/failed/interrupted/truncated；块结束和响应结束只说明相应对象的状态。公开回复被截断时，整轮不能仅凭 harness 返回而显示全部成功；轮次执行状态按已有 partial 等规则处理，文件记录轴保持独立。

示例增量：

```json
{
  "seq": 12,
  "at": "<事件时间>",
  "type": "assistant_block_delta",
  "turn_id": "t_example",
  "message_id": "m_example",
  "block_id": "m_example:text:1",
  "kind": "text",
  "part": 2,
  "text": "旅馆的灯熄灭了。"
}
```

`assistant_block_finished.text` 是该块的最终完整值，用于一致性核对与重建，不作为另一条回复追加。`assistant_message.text` 是按固定规则从该响应公开文本块得到的权威公开文本，供复制与后续上下文使用；它与流式块关联到同一 `message_id`，不能再生成第二个气泡。

没有新事件标识的旧 `assistant_message` 按旧记录单独展示，以会话/seq 生成本地稳定标识。旧记录没有保存的思考、时间和增量不补造。新客户端同时识别旧日志与新日志；前后端类型和所有解析分支同批更新。

## 5. 模块设计与关键示例

以下示例用于明确接口与关键取舍，不是已实现代码。实际代码以接入后的会话模块为基础，保持上游 `tau_agent` 与 `tau_ai` 契约不变。

### 5.1 事件转换：模型增量到会话记录

新增 `workspace/chat_stream.py`，集中处理响应/内容块状态、批量增量、最终文本与耗时；`TurnService._consume()` 负责把 Agent 事件交给它，并保留工具与整轮结果的执行责任。

```python
if isinstance(event, MessageStartEvent):
    bridge.start_response(event.message)
elif isinstance(event, MessageUpdateEvent):
    delta = event.assistant_message_event
    if isinstance(delta, TextDeltaEvent):
        await bridge.append_text(delta.content_index, delta.delta)
    elif isinstance(delta, ThinkingDeltaEvent):
        await bridge.append_thinking(delta.content_index, delta.delta)
elif isinstance(event, MessageEndEvent):
    await bridge.finish_response(event.message)
```

实际实现同时处理文字/思考的开始和结束事件，过滤非助理消息，支持缺少开始事件但收到完整结束消息的端点。桥接层只提取展示字段，不序列化整个模型响应对象。

增量按「最多等待约 100 毫秒或累计约 1,024 字符」合批，先到者触发；空闲定时刷新不依赖下一个 token 到来。工具开始、内容块切换、响应结束、错误、停止与轮次结束前强制按顺序提交缓冲。实现可采用单个受控读任务与有界队列，不能通过不断取消模型迭代器来实现刷新定时。

结束时对照 `AssistantMessage.content` 中的完整文字与思考文本；完整结束消息是校对依据，已发增量不能被再次拼进去。每个响应最多保存一条正式公开文本。无公开文本的响应保留其过程状态，不生成空回复。

工具定位参数仍经现有 `_short_args()`，结果仍为摘录。将当前按工具名称暂存参数改为按 `tool_call_id` 保存，避免同名工具多次调用相互覆盖。

### 5.2 存储与传输：先保存，再发布

扩展 `ConversationStore` 的批量追加能力：一次分配连续 seq，追加并确认一批事件，再让 SSE 读取。写入确认失败时停止继续执行本轮，保留已有文件变化并尝试记录失败；无法收尾的记录由重启恢复标记中断。不能只推送一段尚未保存、刷新后必然消失的文字。

```python
records = store.append_batch(
    conversation_id,
    bridge.take_ready_events(),
    update_activity=False,
)
# SSE 读取已确认写入的 records；不另建一份仅内存存在的消息来源。
```

高频增量不逐条改写 `conversations.json`。最近活动时间在受理、必要的低频检查点与轮次结束更新；一批内容在同一写锁内获得顺序，不能被工具事件插入后又倒序补发。

批量写入与回读共享已确认可见的 seq 范围；追尾不能绕过存储确认边界，读到还在写的一部分批次。进程退出后的完整日志前缀由恢复流程校验，再决定哪些内容可以展示和封口。

现有 SSE 每次轮询都会从头读取日志，流式事件变多后需要按游标定位、随后增量追尾。文件替换或截断时重新定位并验证 seq；只读完整日志行。消息回读与活动快照仍提供一致的 `last_seq`，客户端从该位置订阅，不遗失读取与订阅之间的事件。

沿用两个入口：

- `GET /api/file-workspaces/{wid}/conversations/{cid}/messages?after=`：回读含新事件的快照。
- `GET /api/file-workspaces/{wid}/events?conversation_id=&after=&follow=`：推送相同格式的已保存事件。

不新增另一个模型流式调用接口。停止、活动任务查询、草稿和首次发送继续使用会话管理接口；SSE 断开不取消模型。SSE 连接到轮次 `run_finished` 后结束，客户端按真实活动状态决定是否再次订阅。

停止或异常前提交已接收缓冲，再封口块与响应，最后生成整轮结果。服务突然退出时，尚未提交的一小批可能无法恢复；界面仅恢复日志实际保存的部分，不宣称回复完整。

### 5.3 重启恢复与上下文：公开文本只回放一次

扩展会话管理的中断修复：遍历未结束轮次，重放已保存增量重建尚未封口的内容块，补一次 interrupted 块/响应终态；如有尚未正式保存的公开文字，生成一条对应 `message_id` 的部分公开文本，再补本轮中断结果。修复必须幂等。

`conversation_context.py` 继续只使用 `turn_started` 和正式 `assistant_message`，不把 block_delta 或思考加入下一轮。修复后的部分公开文本可作为曾生成的内容保留，并通过执行事实说明未完成；不把它描述为完整成功回答。

```python
for event in events:
    if event["type"] == "turn_started":
        add_user_prompt(event)
    elif event["type"] == "assistant_message":
        add_public_reply_once(event.get("message_id"), event["seq"], event["text"])
    # 流式展示块与思考事件不再次回放。
```

正常完成、停止、模型错误、token 上限、服务中断分别验证公开文本的唯一性。旧日志无 message_id 时按 seq 识别；正式文本缺失或日志损坏不能被解释为模型从未说过话而静默继续。

### 5.4 前端归并：同一条消息持续更新

新增 `state/chatMessages.ts` 作为纯归并模块，供 `state/conversations.ts` 的实时事件与历史回读共同调用。归并按作品/会话分区，复用订阅代次，保持现有草稿和任务独立性。

```typescript
type ChatBlock = {
  id: string;
  kind: "text" | "thinking";
  text: string;
  nextPart: number;
  completion: "streaming" | "completed" | "stopped" | "failed" | "interrupted" | "truncated";
  durationMs?: number;
};

function appendDelta(block: ChatBlock, part: number, text: string): ChatBlock {
  if (part < block.nextPart) return block;
  if (part > block.nextPart) throw new NeedsConversationReload();
  return { ...block, text: block.text + text, nextPart: part + 1 };
}
```

实时状态先按 seq 去重，内容批次缺口触发回读本机会话日志，不重发用户请求。块终态用完整文本替换该块并校验批次，正式公开文本更新同一响应。实时接收与从零回放最终必须得到相同展示结果。

网络异常后先取活动快照，再以最后确认 seq 重连；可按 1、2、5 秒作有限退避尝试，仍失败则保留运行状态与「重新连接」入口，窗口重新聚焦时也可回读。离开原目标后取消其视图重连。回读日志仍存在批次缺口且无法由完整块校正时，显示记录不完整，不无限重连或猜测缺失文字。

保存完整原始文本，Markdown 展示可按约 50～100 毫秒合并渲染；只重绘正在变化的块，完成块保留稳定 key。不能为每个 token 重建整个会话组件、改写全部事件或重置展开状态。

`WorkspaceEvent` 从松散可选字段逐步收敛为按 type 区分的联合类型，新事件列明必要字段。后端展示 DTO、前端客户端、归并器与历史解析共用一份明确契约；未知事件保留游标并显示兼容性提示，不能悄悄丢失正文。

### 5.5 Markdown、折叠过程与阅读操作

组件放在 `components/chat/`：`AssistantMessageView`、`ChatMarkdown`、`ThinkingBlock`、`ToolActivity`、`MessageActions`、`ExpandedReplyDialog`。`ConversationPanel` 继续装配会话选择、模型、草稿与轮次结果，不承担全部消息解析。

```tsx
function ChatMarkdown({ text }: { text: string }) {
  return (
    <div className="prose-chat">
      <ReactMarkdown remarkPlugins={[remarkGfm]} skipHtml>
        {text}
      </ReactMarkdown>
    </div>
  );
}

function ThinkingBlock({ block }: { block: ChatBlock }) {
  return (
    <details>
      <summary>{thinkingLabel(block)}</summary>
      <ChatMarkdown text={block.text} />
    </details>
  );
}
```

示例展示核心结构；实际补齐链接和图片组件、只读任务列表、横向滚动容器与可访问标签。思考块用稳定 ID 维护展开状态，正文完成或流式刷新不重置作者选择。

生成中复制按固定规则从当前已收到的 text 块取得公开原文；完成后以正式 `assistant_message.text` 为准。Clipboard 不可用或被拒绝时提供可选择的原文并提示手动复制，不能显示虚假成功。展开阅读绑定当前会话/message_id 的同一状态，关闭后归还焦点与阅读位置；切到其他会话时关闭或明确保留原目标，不显示错会话内容。

工具详情仅展示服务端允许的参数和摘录。过程展开不执行工具；结果卡继续由真实 `run_finished` 生成，原有撤销与补记仍由 Git 接口验证。

### 5.6 滚动、计时与可访问性

将跟随逻辑独立为 `useChatScroll`。根据作者是否在底部附近以及是否正在选择文字决定跟随，阈值用小范围余量并经过窄对话栏走查。主动阅读时以消息锚点保持位置，展开、收起过程与图片替代文字变化不抢走阅读位置。

```typescript
if (followLatest && !hasTextSelection()) {
  scrollToLatest({ behavior: "auto" });
} else if (hasNewContent) {
  showReturnToLatest();
}
```

运行时阶段时间由已保存的开始时间与本地时钟展示，最终持续时间由服务端单调时钟记录；恢复后不把断开连接的时间算成新一次思考。时间不可靠或未保存时省略对应数值，不补造历史耗时。

状态变化以适当频率通知辅助阅读工具，不逐 token 宣读。折叠、复制、展开、关闭与回到底部可用键盘操作；保持焦点样式，尊重减少动画设置。宽表和代码块可横向滚动，普通文字在窄栏与展开视图中均可读。

## 7. 验收与验证范围

| 类别 | 必须验证的场景 |
|---|---|
| 真实增量 | 受控 provider 分段输出，首段在最终响应前出现；停顿时定时提交缓冲；无增量端点一次展示，不伪造打字过程 |
| 消息顺序 | 文字/思考交错、多个响应、工具前后回复、同名工具多次调用；开始事件缺失、合法无公开回复 |
| 思考边界 | 有/无思考文本、仅签名或 redacted 字段；不泄露原生响应；折叠状态与展开后持续更新正确 |
| 保存与归并 | 重复 seq、重复批次、缺批、最终完整值校正、正式文本不重复；实时与从零回放结果相同 |
| 失败恢复 | stop、模型错误、token 上限、存储错误、SSE 断开、响应结束前服务退出、工具后服务退出；部分内容保留且状态正确 |
| 会话隔离 | 运行中切会话、切作品、刷新再回来；旧订阅和旧渲染回调不覆盖新视图；原任务状态和草稿保留 |
| 上下文 | 已完成及部分公开文本各只回放一次，思考与展示增量不进入后续输入；旧日志继续可读 |
| Markdown | 未闭合围栏、逐段成形的表格/列表、中文长段、长链接、代码、引用；最终复制值等于保存原文；HTML 与不允许的链接不执行 |
| 阅读操作 | 生成中复制、Clipboard 失败、展开后继续更新、关闭还原焦点与位置、向上阅读不被拉回、回到最新恢复跟随 |
| 时间与状态 | 等待阶段不冒充思考；多段思考各自计时；终态冻结；刷新使用保存值；不伪造进度和旧耗时 |
| 日志与性能 | 合批后不逐 token 重写会话索引；SSE 不重复全量扫描长日志；大量增量仍可停止、切换和选择文字 |

在固定的本机测试条件下记录首次可见内容延迟、保存批次与浏览器渲染次数。验收核心是模型尚未结束时内容已经可见及界面可操作，不把某个毫秒阈值宣称为所有供应商的响应保证。
