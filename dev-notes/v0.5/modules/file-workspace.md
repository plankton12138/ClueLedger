# 文件工作区与角色小传

核对日期：2026-10-21。本文描述 `0.5.0` 当前文件结构及其与模型、Git、界面的连接。将角色拆成文件，是为了单独查看、修改和按需读取人物材料；目录本身就是清单，不额外维护人物数据库或索引。

## 内容与路径

```text
作品目录/
├─ 正文/
│  └─ 0001 雨夜.md
└─ 设定集/
   ├─ 角色小传/
   │  ├─ 林远.md
   │  └─ 陈默.md
   ├─ 线索.md
   └─ 真相.md
```

| 类型 | 范围与行为 |
|---|---|
| 正文 | `正文/` 的直接子级 `.md` 文件，按文件名排序；应用新增章名使用四位序号 |
| 角色小传 | `设定集/角色小传/` 的直接子级 `.md` 文件，按文件名排序；不递归子目录 |
| 固定设定 | 只有 `设定集/线索.md`、`设定集/真相.md`；允许创建和改写，禁止改名、移动或删除 |
| 标题 | 从文件前 20 行中取首个一级标题；没有时角色取完整文件名，章节去掉四位序号前缀 |
| 别名 | 同一人物的别名、化名写在同一小传；目前由写作要求约束，没有自动合并或重名判定 |
| 编码 | 读取 UTF-8 或带 BOM 的 UTF-8；应用写入使用 UTF-8、LF |

新建作品建立正文、设定集和角色小传目录，以及两份空的固定设定，随后建立 Git 基线。打开已有目录只检查和读取，不补建文件、不初始化 Git。需要创建文件时会安全补齐其父目录。旧版汇总小传路径不属于受管内容，不列目录、不搜索、不提交，直接读取返回路径错误；没有转换、双读或回退逻辑。打开作品不会自动删除磁盘文件。

路径分类集中在 `workspace/files.py`，文件读写、目录、搜索和 Git 共用同一范围。拒绝绝对路径、跳转、反斜杠、非规范分隔符、更深的子目录、非 `.md` 后缀和 Windows 非法或保留文件名。访问前再校验真实目录，拒绝符号链接、目录联接及越出作品根的访问。

作品位置通过本机系统文件夹对话框选择，新建默认父目录为系统文档目录。位置、最近作品与工作区绑定逻辑没有因角色拆分而改变。

## 读取与修改

文件读取返回原文、路径、大小与实际字节指纹。指纹反映磁盘字节，外部编辑、换行或 BOM 改动都会使旧指纹失效。

| 操作 | 前提与结果 |
|---|---|
| 新建 | `write_file` 的 `expected_digest=null` 只允许创建不存在的文件；已存在则冲突 |
| 改写或局部替换 | 必须使用刚读取的指纹；过期返回 `FILE_STALE_CONFLICT`，不覆盖外部改动 |
| 小传改名 | `move_file` 携带源文件指纹，目标必须不存在，且仍在角色小传目录；不能移动成章节或固定设定 |
| 小传删除 | `delete_file` 携带刚读取的指纹；删除后从目录和搜索中消失 |
| 章节移动与删除 | 沿用相同指纹约束，只能在正文目录内移动 |

改名只改变文件路径，不自动修改一级标题、正文中的人名或其他人物关系；删除小传不删除正文中的人物。应用不提供独立的角色编辑表单，文件修改经对话中的文件工具或外部编辑器完成。

写入先写同目录临时文件再替换。跨文件修改不是事务，失败或停止前已成功写入的文件会保留。Git 初始化、改动状态、记录、差异和撤销均包含角色文件；撤销后应重新读取文件取得当前指纹，不能复用撤销前的旧指纹。

## 接口与界面

文件接口前缀保持 `/api/file-workspaces`，没有新增角色专用增删改接口。

| 接口或入口 | 当前行为 |
|---|---|
| `GET /{id}/files` | 返回 `chapters`、`characters`、`settings` 三组；无角色时 `characters=[]`，固定设定保留两项及其 `exists` 状态 |
| `GET /{id}/file?path=…` | 返回原文、指纹、标题和类别；角色类别为 `character`，另两类为 `chapter`、`setting` |
| `GET /{id}/search?q=…` | 同时逐行搜索章节、角色和固定设定，返回路径、行号、摘录、无法解码文件与截断标记 |
| `POST /{id}/imports` | 继续只导入正文，返回目录也包含 `characters`；不解析或导入人物小传 |
| 模型 `list_files` | 与 HTTP 目录一致，单列角色路径、标题和大小 |
| 左侧设定集 | 可折叠的角色小传分组，下面列出角色；线索和真相是独立入口，无角色时显示创建提示 |
| 阅读与刷新 | 点击角色在只读 Markdown 稿纸显示；刷新保留仍存在的选中文件，外部改名或删除后清除旧路径的选择 |

搜索结果可直接定位人物文件。没有文件监听；外部改动通过刷新或窗口重新获得焦点时回读。改名后界面不猜测新旧路径属于同一人物。

错误仍按 `{code, where, why, fix, details}` 返回，前端按 `code` 分支。异常消息写成「位置与现象，再给一句建议」（`[错误码] 位置：现象。建议：…`），对话里的错误行与命令行直接展示这句，不另加标签。

## 模型如何使用人物

每轮系统材料列出角色名称与路径，不自动装入小传全文。系统要求写到某人物前读取其小传，涉及多人时分别读取；这是模型指令，没有确定性的工具调用强制检查。`read_file`、`write_file`、`edit_file`、`move_file` 和 `delete_file` 都支持角色路径。

线索与真相按总计 6000 字符的默认预算分配，超出时明确标记截断并提示继续读取。角色目录完整列出，没有另设清单压缩；角色很多时清单本身也会占用上下文。此前会话读过的小传可能仍在该会话历史里，本次拆分不新增历史压缩或清理机制。

## 当前边界

角色名与路径分别取自标题和文件名，不保证一致。没有人物关系可视化、独立人物搜索索引、批量导入、自动拆分或跨文件原子改名。思考过程、流式输出和对话 Markdown 的新体验仍见[待实施计划](../chat-experience-plan.md)。验证范围与未验证项见[运行说明](../release.md)。
