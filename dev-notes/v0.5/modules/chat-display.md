# 对话展示与流式回复

作者发送要求后，回复应当边生成边可读；思考与工具过程按需展开，不长期挤占阅读区。
本说明描述当前实现：事件怎么记、界面怎么收、阅读操作怎么做，以及哪些情况会显示
「未完整生成」。

一轮对话的受理、归属与停止仍按[会话与草稿](../../v0.4/modules/conversations.md)；
整轮执行与 Git 记录仍按[写作 Agent 与对话](../../v0.4/modules/agent-and-chat.md)。
本说明只补上「回复内容如何逐段到达界面」这一段。

## 一轮对话的阅读顺序

```text
作者要求
  → 等待模型响应（状态行）
  → 思考内容（默认折叠）
  → 模型公开说明或回复（逐段更新）
  → 工具执行（一行摘要，可展开详情）
  → 后续思考与公开回复
  → 本轮结果卡（执行状态 + 记录状态）
```

同一轮可能有多次模型响应（例如先说明再动手）：每次都占一个独立位置，各自有
`message_id`。没有公开文字的响应只留下过程（思考、工具），不生成空气泡。

状态行只描述应用确认的事实：还没收到内容时是「等待模型响应」，工具开始时是
「正在执行工具」，收尾阶段是「正在记录历史」。不显示百分比、预计完成时间或
模型内部的思考时长。

## 事件

会话日志仍是按 `seq` 追加的 JSONL。整轮新增以下事件，旧日志继续可读。

| 事件 | 主要字段 | 用途 |
|---|---|---|
| `run_phase` | `phase`：`model`/`tool`/`record` | 状态行 |
| `assistant_started` | `message_id` | 一次模型响应开始 |
| `assistant_block_started` | `block_id`、`kind`（`text`/`thinking`）、`order` | 建立内容块 |
| `assistant_block_delta` | `block_id`、`part`、`text` | 一段真实增量 |
| `assistant_block_finished` | `block_id`、`text`、`last_part`、`completion`、`duration_ms` | 用完整文本校对并封口 |
| `assistant_message` | `message_id`、`text`、`completion` | 本次响应的正式公开文本 |
| `assistant_finished` | `message_id`、`completion`、`stop_reason`、`duration_ms` | 本次响应结束 |
| `tool_started` / `tool_finished` | `tool_call_id`、`tool`、`args`、`ok`、`summary`、`duration_ms` | 工具过程 |
| `error` / `run_finished` | 沿用 | 本轮失败原因与实际结果 |

`completion` 取 `completed`/`stopped`/`failed`/`interrupted`/`truncated`。块与响应
只说明自己的状态：一次响应可能因为停止而 `stopped`，但它已经收到的文字块仍可以是
`completed`。整轮是否成功由 `run_finished` 说明。

标识与顺序：

- `message_id` 由应用生成（`m_` 前缀），不用供应商的响应 ID；
- `block_id` 形如 `m_xxx:text:1`，末段是响应内的内容位置 `order`；
- 每个块的 `part` 从 0 开始，连续递增，用于去重与识别缺口；只有完整消息、没有增量的
  响应，块的 `last_part` 为 -1；
- 工具按 `tool_call_id` 配对，同名工具多次调用互不覆盖。

## 保存与传输

增量按「约 100 毫秒或累计约 1,024 字符」合批，先到者触发；事件之间的空闲由读循环的
定时提交覆盖，不等下一个 token。工具开始、内容块切换、响应结束、错误、停止与轮次结束
前强制按顺序提交。

- 一批事件在同一把写锁内分配连续 `seq` 并一次写入，写完才让事件流读到。界面上出现的
  字，刷新后一定还在。
- 高频增量不改写会话索引：最近活动时间在受理与轮次结束时更新。
- 事件流按字节偏移追尾读取，只消费完整行；文件被替换或截断时重新定位。每个订阅者各持
  一份偏移，谁的游标也不会把别人的位置推走。
- 两个入口不变：`GET /conversations/{cid}/messages?after=` 回读快照，
  `GET /events?conversation_id=&after=&follow=` 推送同一格式的已保存事件。

## 界面收法

前端把事件折成「轮次 → 条目」的展示结构，实时接收与从头回放走同一个函数，两条路径得到
相同结果（`frontend/src/state/chatMessages.ts`）。

- 同一条回复只有一个位置：`assistant_message` 更新那条消息，不再追加第二个气泡。
- 未受影响的轮次保持对象引用，只重绘正在变化的那一条。
- 局部增量缺号时回读本会话日志；回读后仍有缺口的轮次标为「记录不完整」，不无限重连、
  不猜缺失文字。
- 网络中断后按 1、2、5 秒有限退避重连；仍失败时保留运行状态并给「重新连接」入口。

**长输出的渲染开销。** 一段思考可能有两三万字符、近两万个增量事件；按事件逐条更新会让
同一段文本被反复解析与排版，这是界面卡顿的主要来源。前端在四处收敛：

- 增量先按 50 毫秒合批（`frontend/src/state/streamBatcher.ts`），一批只通知界面一次；
  内容块结束、响应结束、错误与轮次结束时立即提交，终态不会越过已有文字。切换作品后，
  未到点的旧批次按订阅代次丢弃，不会把旧会话的分片填回页面。
- 思考块折叠时不挂载正文；展开后实时阶段只按原文换行显示，块结束后才解析一次 Markdown。
- 轮次、回复、内容块与 Markdown 渲染按引用记忆化：已完成的轮次在别的轮次流式更新时保持
  原样，只有正在变化的那一块重绘。
- 滚动跟随放在 `requestAnimationFrame` 里，一帧最多读一次高度、调一次位置；作者离开底部
  或正在选字时只提示「回到最新」，不抢位置。

## 阅读操作

| 操作 | 行为 | 边界 |
|---|---|---|
| 思考折叠 | 每段思考默认折叠，运行中也不自动展开；作者展开后继续更新保持其选择 | 只展示供应商实际返回的思考文本；签名、redacted 内容不落地 |
| 工具详情 | 折叠为一行摘要（动作、对象、结果、耗时），失败在折叠状态也可见 | 参数只含服务端保留的定位字段，结果只存摘录 |
| 复制 | 复制该条公开回复的 Markdown 原文 | 不含思考、工具日志、耗时与按钮文字；生成中复制当前已收到文本；无公开文本时不提供 |
| 展开阅读 | 在大面板里看同一条回复，生成中继续更新 | 绑定当前会话与 `message_id`；关闭后回到原消息与原位置；切到别的会话即关闭 |
| 自动跟随 | 在底部附近时跟随新增内容 | 主动向上滚动、选中文字时暂停 |
| 回到最新 | 离开底部即出现，点击回到底部并恢复跟随 | 收尾或收起过程不会把作者拉回底部 |

复制失败（没有剪贴板接口、被拒绝）时打开同一条回复的原文供手动选择，不显示虚假成功。

Markdown 沿用稿纸的渲染器与 `remark-gfm`：内嵌 HTML 不执行，链接只放行 http/https/mailto，
外部图片不自动加载（保留替代文字），任务列表只读。宽表与代码块在对话栏内横向滚动，
需要舒适阅读时用展开视图。

## 停止、失败与中断

| 情况 | 已保存文字 | 标记 |
|---|---|---|
| 作者停止 | 保留 | 响应 `stopped`，正文下方「已停止，回复未完整生成」 |
| 厂商报错 | 保留已收到的部分 | 响应 `failed`，另有 `error` 事件说明原因 |
| 达到输出上限 | 保留 | 响应与块 `truncated`，整轮 `partial` |
| 服务重启 | 按已保存增量重建块与部分公开文本 | 块与响应 `interrupted`，整轮 `interrupted` |

重启修复只做一次：补齐块终态、部分公开文本与响应终态后，下一次扫描认为这次响应已经
结束。没有保存下来的增量无法恢复，也不猜。

## 上下文边界

下一轮模型输入仍只有「作者提示」与「正式公开文本」：同一轮的多次响应的公开文本合并成
一条 assistant 消息，各回放一次。思考、展示增量、工具过程都不进入模型上下文。中断修复
产生的部分公开文本按曾生成的内容回放，并由执行事实说明未完成。

## 已知限制

- 思考文本取决于供应商：只返回加密字段或完全不含思考的模型不会出现可展开面板。
- 耗时是应用观察到的开始与结束；思考块的数字表示输出持续时间，不是模型内部思考的全部
  时间。恢复后不把断开连接的时间算成新的一次思考。
- 浏览器里的流式渲染由 `frontend/e2e/chat-rendering.spec.ts` 用受控 SSE 夹具覆盖：真实
  客户端、归并与组件，只替换事件来源，断言折叠时不解析 Markdown、突发分片合批后只有变化
  的那一轮重绘、历史轮次计数不变、展开后原文逐字一致。断线重连仍由后端用例与状态层用例
  覆盖，没有在浏览器里模拟真实网络中断。
- 长思考的「部分空白」没有精确复现：夹具里展开后的文本与事件原文逐字一致，探针也没有
  记录到超过 50 毫秒的长任务。因此按「显示层重复解析与排版」修复，不声称覆盖所有绘制环境。
- 合批是固定的 50 毫秒窗口，不按帧率或设备性能自适应；特别长的公开回复仍会每批解析一次
  Markdown，没有做分段渲染或虚拟滚动。
