# Hastings 0.5 上下文与作品信息开发计划

> 编写日期：2026-10-21。状态：待实施。本文描述目标与建议实现，不代表已有能力。
> 已确认方向：定位相关材料、回到原文核对、识别过期信息与冲突；章节显示章序和章名，人物显示身份标签，传递当前文件与本轮指定参考。
> 当前实现见[模块导航](modules/README.md)；流式与对话阅读单独见[模型对话框计划](chat-experience-plan.md)。

## 1. 为什么做与完成目标

作品变长后，模型每轮只能读取其中一部分。只保留聊天历史会持续增长，只依赖摘要又可能遗漏细节。先解决「怎样找到相关材料」和「哪份信息仍然有效」，让后续会话压缩有可返回的原文依据。

作者界面与模型应共用章节名称、人物身份和文件来源。作者说「第三章」时，目录、稿纸、章节索引与模型必须指向同一章；人物标签不能只在界面成立，也不能由模型根据一次猜测直接写成事实。

本阶段交付完成后，作者能够：

1. 按「第几章 + 章名」浏览正文，按身份标签识别人物。
2. 看清当前文件与自己指定的参考材料；发送后切换界面不改变已受理任务。
3. 主动生成或更新章节内容索引，查看缺失、有效、过期或无法读取的状态。
4. 让模型经索引和搜索定位章节，再读取原文；区分仅列出、部分读取与完整读取。
5. 在源文件变化或材料矛盾时得到具体提示，不把旧摘要、聊天提议或工具摘录作为当前事实。

“先读再写”可以增加确定性的检查；模型是否找齐所有相关材料、概括是否准确，仍需要写作验收，不能宣称因此消除幻觉。

## 2. 范围与边界

### 2.1 本次进入

- 章节章序、章名、显示名称和命名异常提示。
- 侦探、助手、凶手、嫌疑人、受害者五种人物标签；允许多标签和无标签。
- 当前文件定位、本轮指定参考、受理时固定材料范围、请求去重与恢复。
- 章节内容索引及原文来源、文件指纹、读取范围与过期判断。
- 原文读取记录、相关材料检索工具、冲突说明和紧凑的材料状态展示。
- 前后端共同契约、受控模型测试、真实后端浏览器验证和少量真实写作取证。

### 2.2 本次不进入

会话压缩、全书自动总结、向量检索、跨会话聊天检索、长期偏好记忆、人物关系图、角色知情状态机、历史章节重编号、正文编辑器和独立人物编辑表单。

不承诺本阶段解决整条请求的 token 容量问题。材料预读和工具输出需要明确上限与截断提示，但它们不能被称为总上下文预算。不同模型的容量适配与会话压缩另立方案。

不自动拆分旧版汇总小传，不为旧版本引入兼容层。没有人物标签的普通小传是合法文件，不代表需要迁移。编写本计划不修改运行代码或包版本。

## 4. 作者可见的行为

### 4.1 章节：书名只在作品层显示

```text
作品：雪山旅馆
正文
  第一章  暴雪来客
  第三章  书房里的脚印
  尾声
```

章序来自现有章文件的四位编号，不按列表位置重新编号；缺第二章时仍显示第三章。序章、尾声、番外使用明确名称，不额外显示普通章序。列表、稿纸顶部、搜索定位标题、材料选择器与模型目录使用同一个服务端显示结果。

新建普通章节规范为 `正文/0003 书房里的脚印.md`，正文一级标题使用章名。模型写作要求、创建章节与导入生成结果一并核对，不能只修改前端文字。

名称读取规则按以下顺序实现：

1. 在开头约定范围内识别明确的章节标题，如 `## 第三章 书房里的脚印`；去掉其中的章序后取得章名。
2. 使用有意义的一级标题；与作品名相同，或在多章中重复的同一书名式一级标题，不能无提示地当作章名，优先回退文件名中的章名并给命名诊断。
3. 使用去掉文件编号与章节前缀的文件名；仍无有效章名则显示 `第三章（未命名）`。

文件编号和标题中的显式章序冲突时，显示遵循文件编号并标注冲突，不静默重写文件。无编号的外部文件不凭位置编造编号，显示可识别章名并提示缺少编号；重复编号需要提示。标题诊断不阻止正常阅读。

编号的中文格式集中实现，测试十、十一、二十、一百等边界。章序、原始章名和最终显示名分开保存于响应中，前端不得再自行拼一套规则。

### 4.2 人物：标签与小传共用同一来源

```text
角色小传
  林远    [侦探]
  陈默    [助手]
  许衡    [嫌疑人] [凶手]
```

标签使用文字和颜色共同表达，列表与小传顶部一致，键盘和辅助阅读能读到完整身份。普通人物不强制出现“其他”标签。

标签保存在人物 Markdown 文件开头的结构化元信息中，人物名继续来自正文一级标题或文件名，避免再维护一个重名字段：

```markdown
---
roles: [suspect, culprit]
---
# 许衡

身份、往事、关系与别名……
```

| 保存值 | 界面文字 | 含义 |
|---|---|---|
| `detective` | 侦探 | 主要调查身份 |
| `assistant` | 助手 | 协助调查的身份 |
| `culprit` | 凶手 | 作者已确认的真实身份 |
| `suspect` | 嫌疑人 | 故事中的嫌疑身份，不等于已确认有罪 |
| `victim` | 受害者 | 故事中受害的身份 |

可同时是侦探与嫌疑人，或嫌疑人与凶手。缺字段视为空标签；未知值或格式损坏给诊断，不能猜测标签。别名仍写在同一小传，不在本阶段新增别名识别系统。

标签通过对话修改人物文件，模型必须依据作者明确要求或已确认设定；讨论“如果他是凶手”不能直接增加 `culprit`。修改标签与改正文共用指纹和 Git，不增加只写浏览器状态的标签表。

这里是作者视角。标签不表示读者或角色已知；章节索引也不能因为小传有凶手标签就把“本章已揭露凶手”写成事件。小传、真相、正文之间的语义矛盾由模型指出具体出处，程序只负责字段与版本验证。

### 4.3 当前文件与指定参考分开显示

输入区上方紧凑显示：

```text
当前文件：第三章《书房里的脚印》
指定参考：[林远 ×] [陈默 ×]  添加参考
```

- 当前文件默认跟随稿纸，只帮助解释“这一章”“这个人物”，不限制可写文件，也不自动宣称已读全文。
- “添加参考”从本作品的章节、人物与固定设定中选择；不接任意本机路径。
- 指定参考表示本轮必须考虑的材料，不代表仅允许使用这些文件。未列出时模型仍可继续搜索和读取。
- 点击发送即固定本轮路径与版本；发送后切换稿纸、会话或作品，不更改旧任务。
- 材料选择随各会话草稿隔离；只有非空文字草稿才持久化其参考选择。没有提示词的新对话不建正式会话，也不因选了材料留下空会话。
- 只有受理确认后，清除仍等于本次提交的文字与参考；受理期间的新编辑不被清除。

已发送轮次可展开“参考材料”，分别显示作者指定、系统定位到的候选和实际读取范围。仅列出、读了部分、完整读过必须区分；这些状态不能使用一个笼统的“已参考”。

### 4.4 章节索引由作者主动更新

正文目录提供“章节索引”紧凑入口，列表显示缺失、有效、过期、来源缺失、无法核对；可查看摘要和来源、选择章节后点“生成/更新所选索引”。不默认占据新的常驻面板。

点击更新后，通过当前会话受理一个明确的索引任务，文字提示、模型使用、停止、失败与结果仍显示在对话中；没有会话时这次非空操作创建会话。一次任务初始最多选 10 章，超过时要求分批；停止后保留已完成章节，未完成章节保持原状态。

普通打开、刷新、切换会话、外部改动与过期检测只做确定性的读取和比较，不启动模型、不自动更新索引。自然语言讨论索引也不启动后台任务；明确的更新入口会把本轮用途标记为 `update_chapter_index`。

## 5. 数据来源、版本与可信范围

### 5.1 内容与派生数据分开存放

作品内容仍只有正文、人物小传、线索和真相。新增章节索引是可重建的派生数据，保存在应用状态目录：

```text
~/.hastings/workspaces/<作品绑定 ID>/
├─ c_<会话 ID>.jsonl          # 本轮材料快照、读取与警告事件
├─ conversation-ui.json       # 文字草稿及其参考选择
└─ chapter-index.json         # 可重建的章节索引
```

不新增人物数据库，不把索引纳入受管作品路径或 Git 提交。复制或移动作品后索引可能缺失，仍可正常写作和阅读，只提示按需重建。缓存丢失不等于作品丢失，更新索引不产生作品提交。

每章索引至少保存：`source_path`、`source_digest`、`recipe_version`、摘要、带证据的事件/人物/时间地点/线索、生成时间。索引只依据该章原文生成，人物字符串按章内原文记录；关联到当前人物路径在使用时完成，重名不强行匹配，不引入章外真相。

若以后允许多源生成，每个实际依赖的文件必须记录指纹，不能只记主章文件。本阶段只实现单章来源，避免隐含依赖。

### 5.2 有效性由程序判断

| 状态 | 条件 | 进入模型上下文的方式 |
|---|---|---|
| `missing` | 没有索引 | 目录可见，提示可直接搜索、读取原文 |
| `valid` | 来源存在且当前字节指纹、生成规则版本均匹配 | 可作为定位材料，明确标注派生信息 |
| `stale` | 指纹或生成规则版本不一致 | 不带入旧摘要、旧实体与旧摘录，只列过期路径 |
| `source_missing` | 文件已删除或改名 | 不自动猜测新路径，不沿用旧摘要 |
| `unavailable` | 无法读取来源、编码错误或缓存损坏 | 不标为有效；显示具体原因，允许其他文件继续使用 |

外部编辑、模型修改、Git 撤销、导入后都按实际字节重新核对。恢复到原来相同字节时可再次有效；只恢复相同文字但换行不同也属于不同指纹。检测过期不删除旧缓存，旧缓存不能默默重新进入上下文。

索引生成时先固定来源指纹；发布前再核对一次。生成过程中来源变化就拒绝发布，不能把旧摘要盖上新指纹。写缓存按章更新并原子替换整个状态文件，进程中断不发布半份记录。

### 5.3 引用能定位到原文

索引中的重要事件、人物和线索至少关联一个原文范围：`source_path`、`source_digest`、起止行号、短引文。保存时核对行号合法、引文确实包含在该范围，并确认本任务已读过该版本的相应范围。

证据范围证明来源存在，不能证明模型对它的解释一定正确。模型仍需区分“文中明确写了”“人物声称”“可以推测”；界面不把摘要标成作者确认的设定。

### 5.4 冲突处理规则

| 冲突 | 处理 |
|---|---|
| 有效性已失效的摘要与原文不同 | 排除旧摘要，重新读原文；不自动启动摘要更新 |
| 旧聊天与当前文件不同 | 旧聊天作为历史讨论；核对当前要求是否明确要改变现有设定 |
| 假设、提议与正式设定混杂 | 假设不自动升为事实；未落盘决定只属于当前会话，不跨会话自动传播 |
| 正文、小传、真相互相矛盾 | 给出文件和原文出处；不能确定作者意图时在对话里请求决定 |
| 作者明确要求改变设定 | 按请求修改，并检查相关材料；不把“当前文件优先”理解成禁止修改 |

语义冲突检查属于已启动写作任务的一部分，不因文件保存自动启动全书审计。不能承诺程序自动判断小说中的事实真假。

## 6. 材料进入模型的顺序

```text
受理提示与本轮材料范围
  → 校验路径、存在性与版本，固定请求快照
  → 构造当前目录、标签、有效索引和来源说明
  → 定位候选章节，按需搜索原文
  → 读取相关原文，记录版本与实际读取区间
  → 核对矛盾与缺口，再写作或请求作者决定
  → 写前复核本轮依赖材料，记录实际结果
```

1. 当前文件默认只带路径和显示名称。作者指定参考按每份最多 2000 字符、总计最多 8000 字符预读开头，按参考顺序分配；首批最多 20 个路径。这些是实施初始值，不是用户已配置项。
2. 预读保留完整行边界，标记实际行范围、剩余范围与截断原因。长单行超限不截出“半行已读”，只返回定位说明，交由分段工具读取；不得将未预读文件标为已读。
3. 每轮最多注入 8000 字符的有效索引，优先当前章、指定章及其邻章；其余通过 `search_chapter_index` 查询。没有有效索引时继续使用目录与 `search_text`，不伪造摘要。
4. 索引检索先用章序、名称、原文实体和关键词做确定性匹配，返回路径、匹配原因、证据及截断状态；没有命中明确返回空，不保证召回所有相关材料。
5. 搜索命中只代表找到线索；摘要也不代表读过原文。只有文件读取工具和应用实际预读可写入读取记录。
6. 文件工具增加单次字符上限和分页位置，防止一行或自定义 `limit` 使输出无界；默认上限 16000 字符，超限可继续读。不要让“200 行”冒充字符限制。
7. 进行故事文件修改前，核对指定参考是否已完成读取，并检查本轮已读原文的指纹是否变化。长参考未读全时返回 `REFERENCE_NOT_FULLY_READ_CONFLICT`；这项确定性检查不要求程序猜出所有相关文件。
8. 依赖变化时先返回 `CONTEXT_SOURCE_STALE_CONFLICT` 让模型重新读取，不能无声继续写；外部程序仍可能在复核与写入之间改文件，本阶段不声称提供跨文件原子快照。

所有实际装入请求的索引、固定设定和预读原文都登记来源依赖；索引的来源指纹参与写前核对，但注入索引不算读过其原文。读取覆盖和来源依赖使用两份状态，不能为了通过版本检查把摘要误记成全文已读。

读取记录必须包含本轮写入产生的新版本。已有文件成功写入或局部修改后，用实际落盘结果更新该路径的版本并清除旧版本区间；完整写入的全文可记为已知，不能把其前一个版本永久列为过期，造成下一次工具操作无法继续。

本轮写入改变了索引来源时，相关索引立即失效。已经发给模型的旧版本内容无法撤回，写工具结果必须明确说明新版本以及先前摘要已失效；后续索引查询不再返回旧摘要，涉及细节时重新读取。不能声称更新指纹就让模型遗忘了旧内容。

“本轮参考材料”及工具来源是应用事实，提示词中独立标注；作品正文和索引内的文字都是内容，不转成系统指令。具体原文只存在于本轮模型材料，界面事件只留定位、指纹和范围，不复制整章原文。

## 7. 模块实现与代码示例

以下为目标接口示例，辅助实现与命名在阶段开发中补齐；当前源码尚无这些类型。模块内共用一个解析与序列化入口，不让 HTTP、模型工具和前端各自解释字段。

### 7.1 元信息：新增 `workspace/metadata.py`

职责是解析人物标签、章名与显示名称，返回值和诊断分开。安全解析文件开头的元信息，限定长度、字段类型与枚举；禁止重复键、非安全标签及无界别名展开。格式损坏时保留原文可读，不产生猜测标签；模型写入格式错误在落盘前拒绝，外部错误通过诊断修复。

```python
from dataclasses import dataclass
from typing import Literal

CharacterRole = Literal["detective", "assistant", "culprit", "suspect", "victim"]

@dataclass(frozen=True)
class FileMetadata:
    title: str
    display_title: str
    chapter_number: int | None
    chapter_type: Literal["regular", "prologue", "epilogue", "extra"] | None
    roles: tuple[CharacterRole, ...]
    display_text: str  # 人物元信息从阅读正文中分离，原始 text 仍完整保留
    warnings: tuple[str, ...]

def regular_chapter_display(title: str, chinese_number: str) -> str:
    # chinese_number 来自唯一的编号格式化函数，不由模型或前端生成。
    clean = title.strip()
    return f"第{chinese_number}章 {clean}" if clean else f"第{chinese_number}章（未命名）"
```

`files.py` 统一生成元信息；`FileEntry`、单文件视图与模型 `list_files` 使用同一结果。保留 `title` 为纯名称，增加 `display_title`、`chapter_number`、`chapter_type`、`roles`、`metadata_warnings`；单文件另给 `display_text`。`text` 保留包含元信息的完整 LF 文本，`digest` 仍按磁盘实际字节计算；搜索行号按完整文本，不因隐藏元信息偏移。

### 7.2 本轮材料：新增 `workspace/materials.py`

职责是校验并固定材料、记录读取区间和校验版本，不负责生成摘要。所有路径调用现有 `Workspace` 校验，不能直接拼接任意本机路径。

```python
from dataclasses import dataclass

@dataclass(frozen=True)
class SourceRef:
    path: str
    digest: str

@dataclass(frozen=True)
class TurnContext:
    selected: SourceRef | None
    references: tuple[SourceRef, ...]

    def canonical(self) -> dict[str, object]:
        # 去重后保留作者选择顺序：顺序决定预读预算分配，不能排序后丢掉差异。
        return {
            "selected": None if self.selected is None else vars(self.selected),
            "references": [vars(item) for item in self.references],
        }

def verify_sources(workspace, sources: tuple[SourceRef, ...]) -> tuple[str, ...]:
    changed = []
    for source in sources:
        if workspace.read(source.path).digest != source.digest:
            changed.append(source.path)
    return tuple(changed)
```

实际核对需将来源缺失、编码错误与版本变化分别转为业务错误。读取记录按 `(path, digest)` 记录区间并合并，分页重叠不重复计数；只对当前版本累计覆盖。不能把客户端或模型声称的“已读”直接写进记录。

### 7.3 索引：新增 `workspace/chapter_index.py`

存储、状态核对、证据验证与模型生成分开。状态目录沿用现有作品绑定位置，不写死用户目录、不从环境变量另取配置。

```python
from dataclasses import dataclass
from typing import Literal

IndexState = Literal["valid", "stale", "source_missing", "unavailable"]

@dataclass(frozen=True)
class ChapterIndex:
    source_path: str
    source_digest: str
    recipe_version: int
    summary: str

def freshness(workspace, entry: ChapterIndex, recipe_version: int) -> IndexState:
    from hastings.workspace.errors import WorkspaceError
    try:
        current = workspace.read(entry.source_path)
    except WorkspaceError as exc:
        return "source_missing" if exc.code == "FILE_NOT_FOUND" else "unavailable"
    if current.digest != entry.source_digest or entry.recipe_version != recipe_version:
        return "stale"
    return "valid"

def quote_matches(text: str, start_line: int, end_line: int, quote: str) -> bool:
    lines = text.split("\n")
    if not quote.strip() or not 1 <= start_line <= end_line <= len(lines):
        return False
    return quote in "\n".join(lines[start_line - 1:end_line])
```

完整结构另包含带证据的事件、人物、时间地点和线索。默认每章摘要最多 500 字符、最多 12 个事件条目、每段引文最多 160 字符；人物等分类复用证据编号而非复制引文，结构上限通过共同模型约束，模型超限返回可修正错误。

缓存中的 `source_path` 再次按受管章节路径验证；缓存损坏不直接丢作“从未生成”，要展示无法读取。没有条目时才是 `missing`。

### 7.4 模型工具：调整 `workspace/agent.py`

普通写作轮次增加 `search_chapter_index`，返回有效记录和来源；失效记录仅返回状态，不返回旧摘要。现有 `read_file` 接入读取记录和字符分页，现有写工具执行前统一调用依赖检查，不在各工具复制规则。

索引任务只开放目录、搜索、读取和 `save_chapter_index`，关闭正文/小传写工具，不得为生成索引创建 Git 提交。普通轮次不开放 `save_chapter_index`，避免普通阅读或创作隐含启动索引维护。

```python
async def save_chapter_index(arguments, *, workspace, ledger, store, allowed_paths):
    draft = ChapterIndexDraft.model_validate(arguments)  # 与工具 schema 共用约束
    if draft.source_path not in allowed_paths:
        raise index_scope_error(draft.source_path)
    current = workspace.read(draft.source_path)
    if current.digest != draft.source_digest:
        raise source_stale_error(draft.source_path)
    ledger.require_complete(draft.source_path, current.digest)
    for evidence in draft.evidence:
        if not quote_matches(current.text, evidence.start_line,
                             evidence.end_line, evidence.quote):
            raise invalid_evidence_error(evidence.id)
    # publish 内在真正替换前复核来源；未完成记录不能覆盖有效旧记录。
    store.publish(draft, expected_source=SourceRef(current.path, current.digest))
```

覆盖完整章原文是索引发布的必要条件，不能用只读前 200 行生成“全章摘要”。长章无法在本轮完成时返回部分完成，不自动续跑，不提前发布覆盖旧索引。

### 7.5 执行与恢复：调整 `service.py`、`state.py`

受理输入增加材料范围和本轮用途。先查请求键，再校验新请求路径，避免同一请求因文件后续变化无法找回已受理轮次。请求身份比较必须包含规范化文字、会话、用途、所选路径、参考顺序、可选客户端指纹及索引目标路径；同键不同材料返回 `REQUEST_KEY_CONFLICT`。

第一次受理时由服务端读取当前指纹并存入 `turn_started.context`；客户端指纹仅用于检查作者看到的版本是否已变，不能成为实际内容依据。重试返回原快照，不能重新读取后改写既有请求身份。

旧轮次没有 context 字段时展示“未记录本轮参考”，不根据今天打开的文件补造历史。界面草稿扩展 `draft_contexts`，沿用现有版本与冲突合并流程，删除文字草稿同时删除对应引用；不改为另一套浏览器持久化。

### 7.6 提示词与回放：调整 `context.py`、`conversation_context.py`

系统材料按“写作要求 → 当前任务定位 → 最新目录和人物标签 → 当前固定设定 → 有效章节索引 → 本轮预读原文 → 执行事实”组织。每块标明来源类别、文件版本、截断与读取范围；索引与原文使用不同标题。

```text

当前打开：第三章 书房里的脚印（正文/0003 书房里的脚印.md）

## 作者指定参考
林远：已读取原文件第 1—45 行，版本 <digest>；当前文件共 80 行。

## 章节索引（派生信息，只用于定位）
第一章 暴雪来客：……

```

线索与真相现有字符预算保留，人物全文继续按需读取。跨轮仍只回放作者消息和公开回复，材料清单和读取事件不重复变成聊天内容；执行事实仍由实际结果生成。旧公开回复中的陈述可能过时，要明确要求以本轮核对和作者明确修改意图判断，不静默篡改聊天历史。

## 8. 前后端契约清单

以下均为本阶段目标。接口前缀保持 `/api/file-workspaces`，产品版本不要求重命名接口。

| 接口或事件 | 增补 | 对应使用方 |
|---|---|---|
| `GET /{wid}/files`、导入返回目录 | 元信息显示字段和诊断 | 目录、搜索定位、材料选择器 |
| `GET /{wid}/file` | 同一元信息及 `display_text`；完整 `text`/`digest` 保留 | 稿纸、文件工具共同解析 |
| `GET /{wid}/chapter-index` | 所有章节索引状态、有效摘要与证据；支持 path 筛选 | 索引面板；过期摘要不返回为可用内容 |
| 首次 `POST /{wid}/conversations` | 增加 `purpose`、`context`、`index_paths` | 首次发送和首次索引更新 |
| 后续 `POST /{wid}/conversations/{cid}/turns` | 与首次完全相同的新增字段 | 续聊和索引更新 |
| 两类轮次受理响应 | 返回固定的 `context` 快照、purpose、index_paths | 输入区受理反馈与去重重试 |
| `GET/PATCH /{wid}/conversation-ui` | `draft_contexts`，仅保留有文字的草稿 | 各会话引用草稿 |
| `turn_started` | 持久化目的、来源快照与请求身份 | 历史恢复、幂等比较 |
| `context_prepared` | 实际装入的材料、行范围、索引状态与截断信息 | 本轮材料摘要 |
| `material_read`、`context_warning` | 路径、版本、读取范围、异常 code；不含整章原文 | 模型参考状态与可展开警告 |
| `chapter_index_updated` | 已完成路径、来源版本和状态 | 索引面板刷新、逐轮结果 |

`context` 输入包含 `selected_path`、去重后保留顺序的 `reference_paths` 与可选 `observed_digests`。服务端快照包含实际来源指纹；读取事件另记录范围，两者不能混为一份可由客户端提交的“已读证明”。

`purpose` 默认为 `chat`；`update_chapter_index` 必须给 1—10 个合法章节路径，普通 chat 不接受非空 `index_paths`。所选路径和参考都属于受管文件；无效、缺失或已变化的显式输入在受理前拒绝，保留草稿，不留下空会话。

HTTP 请求形状和基础字段类型错误沿用框架的 422；下面的业务错误针对已通过形状校验的输入。首次发送和续聊共用同一个输入模型与材料验证函数，不能只给其中一个端点增加字段。

来源在受理后变化则用已受理轮次记录失败。请求、状态和事件共同使用受约束枚举；`ChapterIndexDraft` 的验证模型同时生成工具 schema，HTTP 和工具不维护两套不一致的字段定义。

| 错误码 | 条件与行为 |
|---|---|
| `CONTEXT_REFERENCE_LIMIT_INVALID` | 超过业务材料数量上限，400 |
| `CONTEXT_SOURCE_NOT_FOUND` | 明确指定文件不存在，404；给出具体路径 |
| `CONTEXT_SOURCE_STALE_CONFLICT` | 客户端观察版本、受理快照或写前依赖不再匹配，409 |
| `REFERENCE_NOT_FULLY_READ_CONFLICT` | 指定参考未读全时试图写故事文件，409；给出剩余范围 |
| `CHAPTER_INDEX_SCOPE_INVALID` | 非索引任务、越界章节或目标数量不合法，400 |
| `CHAPTER_INDEX_EVIDENCE_INVALID` | 引文、范围、结构或已读覆盖不符合要求，400 |
| `CHAPTER_INDEX_WRITE_FAILED` | 索引状态无法保存，500；原文件不受影响 |

元信息错误作为读响应中的诊断；写入新的非法元信息返回 `CHARACTER_METADATA_INVALID`。所有错误继续使用现有信封与直白文案，不能把错误混进成功摘要。

### 10.2 真实后端浏览器流程

用真实文件接口准备多章作品及有身份标签的人物：检查章名 → 阅读人物 → 指定参考 → 在受控 provider 下发送 → 切到其他文件 → 回看本轮材料 → 主动更新索引 → 外部编辑来源 → 刷新显示过期 → 再次发送确认旧摘要没有进入请求。另覆盖缺模型、停止、网络断开与服务重启，不用截图替代接口断言。

### 10.3 真实模型写作取证

至少进行一组由作者启动的索引任务和后续写作任务，记录实际提示、读取文件与范围、索引来源版本和生成结果。准备“第一次进入书房”的细节，要求写第二次进入；核对模型能定位并读取原文、呼应细节。再改变相关设定，验证旧摘要被排除，模型使用新原文或指出矛盾。

核对公开回复中是否把假设当成决定、是否把凶手标签误写成正文已披露、是否声称读过实际未读内容。真实样例只证明该样例表现，不声明所有模型均已验证或一致性必然正确。
