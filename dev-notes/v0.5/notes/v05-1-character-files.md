# V05-1 人物小传按文件组织

日期：2026-10-21。目标是使每名角色有独立文件，接入现有写作和阅读流程。作者明确要求不兼容旧版内容，直接删除项目内旧版小传。

## 实际改动

- 文件规则增加角色目录和 `character` 类别，共用路径分类与安全检查；固定设定只保留线索与真相。
- 目录、搜索、HTTP 与模型 `list_files` 增加 `characters`；写入、局部修改、改名和删除复用原文件工具与指纹约束。
- 角色只能在角色目录内改名，不能跨到正文或固定设定；角色目录拒绝符号链接和目录联接。
- Git 的受管路径覆盖角色，初始化、记录、差异与撤销共用当前文件规则。
- 模型系统材料只列角色名称与路径，提示涉及人物时读取小传；线索与真相仍按预算装入。
- 界面设定集增加可折叠角色分组，点击只读阅读、搜索定位和刷新复用现有流程。
- 后端、前端及桌面包版本与锁文件同步到 `0.5.0`；本轮没有改桌面启动逻辑。

## 接口与数据影响

`GET /files` 和正文导入返回目录新增必有的 `characters` 数组，`settings` 为两项；单文件返回的类别增加 `character`。前后端类型和空目录状态同步调整，没有新建独立角色接口或索引文件。

目录采用 `设定集/角色小传/姓名.md`。旧 `设定集/角色小传.md` 不再受管，针对旧路径保留拒绝访问测试，没有迁移、回退读取或启动时自动删除。实际删除的旧文件仅有项目内两份验证作品中的汇总小传：`data/v04-9-verify/testbook/设定集/角色小传.md`、`data/v04-10-verify/testbook/设定集/角色小传.md`。

## 实现取舍

角色目录直接扫描，不增加数据库或人工维护的名单；角色名使用前 20 行的首个一级标题，无标题时用完整文件名。别名写在同一文件，暂不进行自动去重。

改名只改变路径，语义联动由写作请求决定。模型先读小传通过系统要求表达，没有新增强制读取状态机。已有会话中的历史工具内容不会因这次拆分自动清理。

Git 撤销可能受本机换行设置影响，恢复相同文字后的实际字节指纹也可能变化；新增测试在撤销后重新读取指纹再删除，不复用旧指纹。
