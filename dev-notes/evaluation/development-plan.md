# 评测工作台开发计划

状态：P0–P3 本地首版已实现。已用真实历史档案和受控模型响应验证；尚未用本轮构建发起新的在线 T01。首版面向开发与评测人员，不作为作者写作界面的入口。

## 1. 范围和现状

工作台串起三件事：从任务库选题并核对前置条件；在隔离作品里运行；从逐项判定下钻到 Trace 和实际稿件，区分 Agent、产品流程和评测器的问题。

- **已有**：[Task Schema v1](../../eval/benchmark/task-schema.md)、[T01 r1](../../eval/benchmark/tasks/t01.json)、[T01 离线评测器](../../eval/benchmark/evaluator.md)、[T01 归档结论](../../eval/benchmark/t01-regression-log.md)和[产品运行追踪](../runtime-trace/development-plan.md)。当前离线评测器只读已有证据，只支持 T01，不启动 Agent 或 Judge。
- **P0 已实现**：[多任务库目录和运行摘要索引](../../eval/benchmark/workbench-index.md)。目录支持多库、任务修订、搜索与分页；摘要索引不打开证据附件，也不改写历史。
- **P1–P3 已实现**：[独立本机工作台](../../eval/benchmark/workbench.md)、正式 T01 的隔离 Runner、逐项人评和版本化重判。只有推理边界用受控响应验证；产品对话、工具执行、落盘取证和版本化报告均实际执行。其他在线任务仍禁用。
- **不纳入首版**：任务在线编辑、批量调度、加权总分、Judge 作为必过项裁决。任务定义仍由仓库内的版本化文件维护；真实稿件、完整 Trace 和运行证据保留在受控本地归档，不提交到 Git。

## 2. 信息架构和交互

### 2.1 任务库

先展示可筛选的任务库和可搜索的**任务列表**，再展示所选任务详情。列表为新增库、任务、筛选和翻页留出空间；当前只有一个库和 T01 时仍显示列表和详情两个层级，不用假任务填充。桌面使用列表＋详情，窄屏先选任务再进详情，并可返回之前的搜索位置。至少支持按任务 ID、标题查找；列表显示所属任务库、任务 ID、标题和修订。同一任务的历史修订从详情切换，不拆成多个同名任务。深链接以库 ID、任务 ID 和修订定位，不依赖列表行号。

任务详情按原型拆为「场景实例与作者输入」「确定性检查」「语义检查」。场景区给出隔离初态、焦点、作者原话，以及副本和步骤；检查区逐项标出检查点、必过/诊断角色、所需证据和判据。页面不复制评分规则，不把任务说明或判据拼进作者消息。选中某修订后可进入运行配置或查看该修订的历史运行。

### 2.2 运行评测

- 配置页显示已选任务与修订、在线模型连接的非敏感标识、实际模型、初态要求及拟用评测器版本。保留「核对配置 → 预检 → 开始运行」的步骤，不靠进入页面或切换任务触发模型调用。
- Runner 从任务定义建立隔离作品、会话和模块库，核对文件、焦点及所需证据的可采集性。预检未通过须显示具体原因并阻止发消息；Runner 未接入时明确禁用开跑。重跑只带入可比配置，不复用旧工作区、稿件、会话或人评。
- 执行复用产品的写作入口。按 Task 的副本和步骤执行，每步取证并评分；上一轮必过项没通过时不发下一条。需要人评时暂停；已失败、缺证、待复核和未执行按 [Task Schema](../../eval/benchmark/task-schema.md#通过条件与结果记录)分别记录。Runner 不代替作者越过产品确认点。

### 2.3 运行与复盘

**评测档案按实际执行开始时间从早到晚排列。** 有效基线可以默认打开或手动设为对比对象，但不能因此移到最前。查询先按作用域筛选，再以 `(started_at, run_id)` 升序排序和分页；使用同一时区基准比较，界面显示本地时间及时区。仅有预检记录或旧档缺开始时间时标明「未启动」或「执行时间未记录」，放到独立区，不用导入时间、结束时间或结果推断其执行顺序。补证、重判和签收只追加到同一运行，不改原开始时间，也不生成一次新的 Agent 运行。

原型使用的档案应按下表显示。默认选中「有效基线」，但它在第二行。

| 顺序 | 运行 | 业务判定 |
| --- | --- | --- |
| 1 | 首次基线：模型调用未得到输出 | `invalid`，不算 Agent 业务失败 |
| 2 | 有效基线：首次写入被拦截，同轮重写成功 | `pass`，两项自动检查通过，三项人工确认 |
| 3 | 修复后 T01 原样复跑：首写成功 | `inconclusive`，两项自动检查通过，三项新稿待人评 |
| 4 | 独立回归：无全书结构直接写正文 | 通过，标明是独立回归，不计入 T01 |

详情首屏分开显示**执行状态、业务判定、复核状态**。逐项判定按「确定性／语义」分组，展示必过/诊断、结论、理由和证据入口；无证据不展示为通过。右侧详情沿用原型四个页签：

| 页签 | 展示与操作 |
| --- | --- |
| Trace 时间线 | 「评测流程」显示实际记录的预检、执行、取证、判定和归档节点。工作台新增的人工复核与重判保存在报告版本中，不新增时间线节点；旧版归档例外，可显示已知的同轮补证重判和仍可核实的人工复核节点。「Agent 执行」展示产品记录的 Turn 事件。可展开、仅看问题，从检查或流程节点跳到具体事件。失败后重试成功时保留两条调用；历史无 Trace 时提示缺失，不补造时间或事件。 |
| 证据 | 显示作者原话、文件前后快照、模块/绑定状态、实际落盘稿件和公开回复。区分原始证据与核对版；缺失和已确认空不能混用。摘要与详情分开取，证据可定位到对应稿件版本、消息或事件。 |
| 人工复核 | 展示本轮 Rubric、指定证据、逐项结论和理由。新复核绑定运行、检查项及 `evidence_sha256`，证据变化后不能沿用；未校准的 Judge 仅作对照。历史只留下总体确认时照实展示，不补写逐项引文。 |
| 问题与回归 | 用已选基线和复跑比较同一个行为，标出 Task 修订、模型、初态和 Grader 版本差异。分开展示「修取证后，同轮重判」和「改产品后，另起 Trial 复跑」。独立回归可以关联，但不并入同题分数。 |

## 3. 数据契约与查询边界

以下是工作台的目标契约。首版只在独立回环服务中实现，不暴露给作者应用；历史缺少的版本与初态信息不补造。前端不直接扫描本地目录或读任意文件路径。

| 对象 | 身份与职责 |
| --- | --- |
| Task | `library_id` + `scenario.id` + `revision` 定位执行定义；`schema_version` 标记格式。库 ID 由目录配置提供，不写入 Task Schema v1。目录可列出尚不支持自动执行的任务，但须显示不可运行的原因。 |
| Run / Trial | `run_id` 定位一次执行，记录运行类别、任务修订（独立回归可无 Task 归属）、实际开始时间、执行状态、模型、产品与评测器版本及工作区/会话关联。记录明确的基线或复跑关系，不从位置或通过状态推断基线。 |
| Case / Step | 用 `case_id`、`step_id` 关联隔离副本、检查点及实际 `turn_id`；多轮任务的报告不能只绑定最后一个 Turn。 |
| Evidence / Report | 一次运行可保留原始和纠正后的证据及报告。逐项结果按 `case_id / step_id / check_id` 定位，含 `role`、`verdict`、理由、证据引用及判定来源；报告关联对应证据摘要和评测器版本。Task 仍按全部副本、全部必过项汇总。 |

查询层提供任务列表/修订详情、按 Task 与运行类别筛选分页的档案列表、单次运行详情，以及按引用读取证据和 Trace。Agent Trace 优先复用[现有 Turn Trace 接口](../../src/hastings/workspace/api.py#L1507)与[时间线组件](../../frontend/src/components/trace/TraceTimelineView.tsx)；若隔离作品已清理，使用归档的脱敏快照或明确提示不可用。评测流程节点来自 Runner 或可核实的归档记录，不混入产品 Trace。列表、详情和附件统一校验访问范围，证据引用不暴露凭据、本机绝对路径或其他作品数据。

## 4. 实施和验收

| 阶段 | 交付与验收 |
| --- | --- |
| P0 · 冻结目录和归档契约 | 用 T01 r1、乱序导入的四条档案和至少两条额外的测试任务验证索引。额外任务只进测试夹具，不加进正式任务库。覆盖同一开始时间、缺开始时间、独立回归和同轮重判；分页无重漏、排序不随选中项或人评时间变化。旧档没有的字段标为未记录。 |
| P1 · 只读工作台 | 实现任务库、配置预览和运行复盘。分别以一条和多条任务验证筛选、修订切换、窄屏返回；以基线复现格式门槛、同轮重试和采集漏项，并从检查项进入对应快照或 Trace。导入的修复后 T01 仍显示待复核，不被独立回归的通过覆盖。 |
| P2 · 单题在线 Runner | 先接 T01：完成隔离预检、执行和落盘取证，接现有离线评测器。验收预检失败不发送、模型失败记无效、缺证不判通过。相同配置复跑须分配新的作品、会话、模块库和 `run_id`。其他任务只有在对应初态、步骤和规则都受支持时才开放运行。 |
| P3 · 复核与可比回归 | 写入绑定证据的逐项人评，发布后读回报告与复核状态；旧报告保留。验证用新证据重判同轮不产生新 Trial、绑定旧摘要被拒绝、必过未知时不声称整轮通过。可从对比页复跑但不继承标注；用多步骤夹具验证必过未满足时不发送后续步骤。 |

先用本地夹具验证查询、排序、状态和浏览器交互，再用真实隔离 T01 验证执行链路。若采集或判据有误，先用同一历史证据重放核对；只有需要验证产品或 Agent 改动时才新开可比 Trial。

本地验收：真实 Chrome 连接回环服务，确认四份历史档案按执行顺序展示、有效基线默认打开但仍在第二条，并能从判定定位实际稿件摘要和当轮失败/重试事件。运行、复核及重判还通过浏览器自动化和受控模型响应的真实产品路由测试。产品与工作台分别构建，工作台不进入作者界面。

在线验收待办：当前配置选中订阅认证，隔离预检会拒绝，以免刷新共享凭据；选中可用的 API Key 连接后，再从工作台运行一轮 T01 并复核真实稿件。历史在线档案只证明既往运行，不替代本轮在线验收。
