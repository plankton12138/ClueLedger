# v1.0.7 验收与在线评测

状态：**待执行**。本文件定义未来实施的验收范围，未勾选的场景不能据预览效果标为通过。计划编制本身只检查文档，不运行后端全量或在线评测。

## 1. 验证分层与节奏

1. 每个模块完成后运行对应确定性测试，确认数据、接口、失败和恢复行为。
2. 每条作者流程接通后使用真实本地服务做浏览器验证；模型无关流程不调用模型。
3. P5 起验证实际讨论与写入链路，模型使用项目 `.env` 指定的在线连接。
4. P7 做一次受影响范围的完整回归与 CI 要求的检查。之后仅文档或版本号变化，不重复后端全量。
5. 在线失败保留原记录，先区分连接、接线和模型理解问题；修复后定向复验，不用自动重试消除失败证据。

本地假响应只可用于流式事件、故障和 UI 状态等确定性测试，不能计入模型语义验收；不使用本地模型完成评测。

## 2. 统一样本

使用新的隔离工作区，避免依赖旧格式或修改作者真实作品。

| 样本 | 内容 | 用途 |
|---|---|---|
| S1 雾港来信 | 五个构思、四条线索、时间不一致、一个未写节点 | 与交互预览相同的最小作者旅程 |
| S2 复杂出处 | 同章三个节点、节点跨两章、同线索同章三处、两线索重叠 | 验证多对多关联与来源 |
| S3 文本边界 | 中文、emoji、CRLF、Markdown 强调/链接/转义、重复句与重叠重复 | 验证源区间与字符坐标 |
| S4 时间边界 | 跨午夜、瞬时事件、倒叙、近似时段、只有相对先后、完全未定 | 验证时间轴不制造精确事实 |
| S5 长篇规模 | 100 章、200 节点、200 线索、600 处来源、300 条关系 | 验证窗口化、分页、关系子图与异步选择 |
| S6 新作品 | 无方案、无线索；另有仅正文但无构思的作品 | 验证合法空结果及首次标记 |

S1 的时间差异可由夹具明确登记核对依据。不能据此宣称普通摘要比较能自动识别任意“22:10 / 23:00”语义差异。

关系语义使用 S1 的扩展子样本：为船票添加“存根签名与林舟笔迹一致”的依据；船票与证词的矛盾明确包含“登船后不能在 22:00 返回旅馆”的前提。停钟与船票的预览连线不能直接当作有效的有向支撑样本。

## 3. 确定性与接口验收矩阵

每项都要记录实际测试文件和结果。表内编号与[阶段计划](development-plan.md)对应。

| 编号 | 输入与操作 | 必须观察到的结果 |
|---|---|---|
| A01 首次标记 | 无构思的已有正文中选段，手动标记真相或误导 | 一次变更创建身份、类型与精确关联；不要求先生成节点；刷新和重启仍存在 |
| A02 类型同步 | 在线索详情修改类型，再切到正文与关系图 | 各处同一类型；失败不修改颜色；回执后刷新而不是只改局部 UI |
| A03 分类语义 | 真信息用于误导、虚假证词指向真相、类型未定的观察 | 类型与事实真假、出现过程分离；未定不默认归为真相 |
| A04 多次出现 | S2 中同线索同章三处、跨章出现、同一段关联两节点 | 保留每次出处；稳定身份不重复；各节点能分别定位 |
| A05 坐标 | S3 的中文、emoji、CRLF、Markdown 源选区 | 前后端引文和码点范围一致；渲染无法安全映射时有明确处理 |
| A06 无关改稿 | 修改同章其他段落、在原引文前插入文本、修改节点标题 | 可唯一定位时当前关联保留；未受影响节点不出现无关差异 |
| A07 来源失效 | 删除引文、改动引文、插入重复句、重叠重复文本 | 不高亮错误位置；来源显示缺失或歧义；重新关联可恢复 |
| A08 过期写入 | 选段后外部改稿，或使用旧方案/账本修订提交 | 拒绝写入并保留输入；正文、结构和账本均无部分写入 |
| A09 精确时间 | S4 中跨午夜、零时长和不等长区间 | 顺序、比例和标签正确；点状事件不变成虚构时段 |
| A10 披露分组 | 倒叙、同章多节点、跨章节点与计划章节 | 发生时间与披露次序独立；详情列全出处；不存在一章一节点限制 |
| A11 未定时间 | 仅时间说明、仅先后关系或完全未定 | 节点仍可见、可选、可编辑；不猜测数字时刻 |
| A12 只读交互 | 鼠标拖动、触屏滑动、键盘选择时间轴 | 不改变顺序或持续时间；点击和键盘仍能定位；细小时间点有足够点击范围 |
| A13 关系约束 | 支撑反向、矛盾重复、同端点、关系成环 | 支撑方向保留，对称关系去重，自关联失败，普通线索关系环合法 |
| A14 空图与规模 | 无关系、孤立线索和 S5 | 无关系可用列表；完整列表分页可达；子图限制明确，剩余数量准确 |
| A15 关系生命周期 | 新建关系、改说明、解绑、删除被引用线索、撤销 | 引用完整；无隐式级联丢失；删除受阻时列出真实引用；撤销可恢复 |
| A16 关系来源 | 只有作者计划的关系、带正文证据的关系、证据过期 | 能区分计划与已出现的依据；来源失效不会继续显示为已核实事实 |
| A17 保存与提醒 | 修改已有正文节点的创作意图；另测陈旧正文补丁 | 意图可保存并返回需核对；陈旧补丁仍拒绝；UI、工具、候选入口一致 |
| A18 实际解决 | 按构思改正文、按正文改构思、明确确认保留差异 | 有真实变更/确认回执；关联重新校验；不只改标签或摘要 |
| A19 原子与恢复 | 重复请求、同键不同内容、各写入阶段中断、重启、撤销后续已编辑文件 | 原请求回执幂等；冲突拒绝；无半条线索；恢复和撤销保留不属于本次变更的内容 |
| A20 讨论边界 | 打开提醒但不点击、双击讨论、首次 review、明确要求后续写入 | 点击前零模型调用；重复点击同一讨论；首轮无写工具执行；后续用途重新判定 |
| A21 读取与刷新 | 快速切换线索/章节/作品，延迟旧请求，改类型后多视图读取 | 旧结果不覆盖新选择；版本一致；来源和提醒按回执失效 |
| A22 试读隔离 | 截止第二章的 reader_preview，包含作者真相和第四章关系 | 输入不包含未来出处、作者分类、隐藏事实或未披露关系；作者视图仍能查看这些计划 |
| A23 提醒失效 | 稍后处理、刷新、无关改稿、再修改同片段、讨论期间改稿 | 稍后处理仍是需核对；标题、偏移平移和暂缓修订不产生新指纹；相关内容变化重新提醒；过期建议不得直接应用 |
| A24 状态聚合 | 多绑定其中一处失效、无绑定、只有基准缺失、其他章未归属 | 三态按本节点事实计算；原因可定位；不会让所有未绑定节点都变为需核对 |
| A25 工作区入口 | 三种模式直达与回退、模块库进入返回、灵感、关闭讨论、窄屏 | 三入口一致；既有工具可达；选择和未发送草稿保留；无重复详情面板 |

### 3.1 可直接转成测试的具体场景

以下断言细化既有矩阵，不另行扩大版本功能。

| 场景 | 前置与操作 | 具体断言 | 对应编号 |
|---|---|---|---|
| E01 支撑方向 | A 为签名比对，B 为船票登记；作者保存 A → B，刷新 | 列表和图均显示 A 支撑 B，不自动补 B → A；箭头、说明与出处一致 | A13、A16 |
| E02 矛盾前提 | 登记船票与证词的矛盾，说明“确认同一人物且无法及时返港”；交换端点重复提交 | 保留一条对称关系；说明中的必要前提可见，不将其中任一证词标为已证明事实 | A13、A16 |
| E03 共同误导 | 证词与血迹共同指向“林舟在旅馆伤人”；另有一条误导指向“财物被盗”但未登记关系 | 前一关系显示共同的错误理解；后一线索不因同属误导而自动连线；端点均为误导不是保存关系的必要条件 | A03、A13 |
| E04 关系交互 | 点击关系线，再用键盘打开同一列表关系项；期间不点击讨论 | 同一辅助区显示相同详情，无第二个详情面板；零模型调用、零写请求；打开出处定位正确 | A16、A20、A25 |
| E05 连续时间轴 | 基准为案发当天 00:00；输入前一天 23:50、当天 00:10，另留“晚餐后”文字 | 前两者分别为 -10、10，差为 20 分钟；文字项的 event_span 为 null，仍可选中且无伪造时间条 | A09、A11 |
| E06 暂缓稳定 | 一个节点因意图变化需核对；暂缓后改标题、刷新、在引文前插入不重复的无关文字，再重启 | 始终为 attention；指纹不变、reminder_visible 为 false；重定位仍指向同一句原文 | A06、A23 |
| E07 相关变化 | 在 E06 的隔离副本中分别修改关联原句、改变构思意图、更换绑定的 clue_id（保留节点）或更新同一 finding 的内容 | 每个子例的指纹均变化，reminder_visible 为 true；不能以 finding ID 未变或已暂缓为由继续隐藏 | A23、A24 |
| E08 建议采用 | 主动讨论得到“可能矛盾”建议，先关闭；重新打开后明确采用，再读取关系 | 关闭前无正式关系；采用后才有可追溯变更与正确端点；采用前来源已变化时回读说明并重新核对 | A08、A20、O06 |

E06/E07 需要比较实际指纹，不仅检查提醒文案。关系语义由明确样本和人工核对确定，确定性测试负责验证已登记含义的方向、来源、持久化和显示，不把存储成功当作系统自动证明关系。

## 4. 浏览器流程

### B1 从正文登记

打开 S6 的已有正文 → 选择连续片段 → 标记为真相 → 查看线索详情 → 改为误导 → 回到正文 → 刷新 → 重启服务再读取。核对真实 API 结果和持久化内容，不仅检查截图。

### B2 从构思阅读

选择倒叙节点 → 观察时间条与披露章节 → 打开正文出处 → 高亮正确段落 → 返回原节点 → 选择同章另一个节点。再检查未定时间和未写节点仍可操作。

### B3 查看关系

从正文标记进入线索页 → 选择关系线 → 在共享辅助区查看端点、说明与出处 → 用列表/键盘打开同一关系 → 添加有方向说明的支撑关系 → 刷新 → 撤销。无线索、无关系和无正文出处分别验证。

### B4 处理差异

保存与正文不一致的构思 → 需核对 → 稍后处理 → 切换页面继续工作 → 回到节点 → 主动讨论 → 选择调整 → 等待提交回执 → 检查实际正文或构思变化。在线版使用 O01—O04，确定性版只验证接线和失败呈现。

### B5 布局与可访问性

- 1440×900 和 1024×768：目录按需展开，主内容与辅助区可阅读；标题、时间刻度和关系文字无重叠。
- 736px、375px、320px 宽：详情重排，表单与主操作可达，整页不产生横向溢出。
- 200% 缩放：控件不覆盖正文，必要文字可换行，键盘焦点可见。
- 真相与误导同时使用文字/形状和颜色；三状态有可访问名称。
- 键盘可以选择节点、线索、打开出处和关闭辅助区。重叠标记可打开选择列表。
- 请求失败、提交中、空结果与来源过期均有独立可见结果，不把失败显示为空列表。

S5 的关系图每次最多展示 40 个节点、80 条边；超过时使用一跳子图和分页列表。时间轴采用可见行窗口或分段加载，检查已选节点与键盘导航不会因回收 DOM 丢失。记录首屏可操作时间、响应体大小和控制台错误，不用缩小全部文字掩盖规模问题。

## 5. 在线模型验收

使用 `.env` 中的在线端点与模型，沿用 `scripts/online_acceptance_config.py` 创建隔离的临时连接。不要把凭据值写入文档、测试日志或截图。端点不可用时记为未执行及具体原因，不切换本地模型，也不以固定回复替代语义结果。

| 编号 | 作者输入与前置情况 | 必须核对的结果 |
|---|---|---|
| O01 只讨论 | 点击第三章提醒，要求说明差异，先讨论 | 模型实际读取绑定与计划，有精确依据；无正式写入和越范围工具执行 |
| O02 按构思改正文 | 在 O01 后明确“将这段正文的钟面时间改为22:10” | 正文实际修改、非目标段落不变、关联重新核验、状态回读正确 |
| O03 按正文改构思 | 独立样本明确“保留正文23:00，调整本节点构思” | 构思意图真实更新，正文不被改写；不会仅更新确认摘要 |
| O04 暂缓与恢复 | 暂缓提醒，稍后进入讨论；期间另有内容变化 | 不自动创建模型任务；恢复带入当前差异，旧决定不能直接应用 |
| O05 用途与证词 | 证词误导但包含真实信息，作者真相未定 | 不将证词当事实，不擅自补造真相，不将“回收”当成分类 |
| O06 关系建议 | 要求核对船票与证词是否可能矛盾，提供原文及能否返港的前提；另测前提不足；之后明确采用 | 先给依据、前提与不确定性，证据不足时提出待澄清点；未采用不写边，采用后实际登记正确端点；打开关系图不自动推断 |
| O07 意图重判 | 构思页开着时要求重写指定正文，随后要求只解释 | 两轮用途分别正确，既不困在 design，也不沿用上一轮写权限 |
| O08 试读与未定时间 | 截止前两章试读；未登记精确时刻的事件 | 不获得作者隐藏事实和未来关系；不为画时间轴编造精确时间 |

每个场景至少执行一个独立首轮样本。失败后的复验记录新旧两次结果与修复原因，不以最终成功覆盖原失败。判断文学解释时同时保存原始材料、模型回答和人工核对意见，不能只用另一个模型打分作为发布依据。

```powershell
uv run pytest tests/workspace/test_story_sync.py tests/workspace/test_clue_marks.py tests/workspace/test_story_joint_commit.py
```

前端验证，工作目录为 `frontend/`：

```powershell
npm test -- src/state/navigation.test.ts src/state/story.test.ts src/state/clues.test.ts src/state/taskPurpose.test.ts
npm run build
npm run test:e2e:local -- clueledger-workspace.spec.ts
```

在线连接准备，工作目录为仓库根；配置文件需使用不存在的隔离路径：

```powershell
uv run python scripts/online_acceptance_config.py create data/test-tmp/v107-online/config.yml --env-file .env
$env:HASTINGS_E2E_CONFIG = (Resolve-Path -LiteralPath 'data/test-tmp/v107-online/config.yml').Path
$env:HASTINGS_E2E_DATA_DIR = Join-Path (Get-Location).Path 'data/test-tmp/v107-online/workspaces'

```

然后在 `frontend/` 运行：

```powershell
npm run test:e2e:online -- story-simplification-online.spec.ts
```

结束后在仓库根调用同一脚本的 `cleanup`，清理本次创建的临时凭据，并恢复本次设置前的 E2E 环境变量。保留经过检查的验收记录，不重复使用旧测试工作区冒充干净首轮。

## 7. 证据与发布门槛

每次正式验收记录：代码提交、工作区样本、服务/浏览器版本、模型与在线端点类别、实际命令、耗时、调用量、原始回执、变更前后内容、截图、失败分类与未执行项。记录端点类别或已脱敏主机信息即可，不输出密钥。

发布 v1.0.7 前需要同时满足：
