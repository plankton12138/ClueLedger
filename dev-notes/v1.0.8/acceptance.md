# v1.0.8 验收计划

日期：2026-11-02。状态：确定性、前端、浏览器与在线模型验收已执行，结果见 [P5 发布记录](notes/P5-release.md)。此文件定义发布门槛，不是通过记录。

## 1. 验收样本

使用隔离的新作品：两章正文、一个未安排章节的构思、一个本章计划节点、一个跨章节点、一个仅账本线索、一条没有用途的计划线索、同章多次出现线索和一个失效引用。另备空作品、重复引文、非 BMP 字符、跨午夜时间和两条不同身份同名线索。

样本分别保存正文、作者隐藏解释和待采用建议，用来检查三者不互相污染。示例内容不得写入作者实际作品。

## 2. 确定性与浏览器矩阵

| 编号 | 场景 | 必须观察到的结果 |
|---|---|---|
| A01 | 构思 / 线索总览 | 无属性输入、保存按钮、分类切换或关系表单；内容和出处可读 |
| A02 | 正文随章查看 | 只列本章有效关联、明确计划和失效引用；未安排节点仍在全书 |
| A03 | 同对象跨布局 | 当前内容、来源和修订一致，无副本 |
| A04 | 来源去重 | 同位置多来源合并，多次出现及同名不同身份不丢失 |
| A05 | 计划 / 正文区别 | 计划不冒充出现；无关联只显示暂无已登记出处 |
| A06 | 无主方案 / 空作品 | 阅读合法为空、不建方案；首次明确创建可提交 |
| A07 | 普通讨论 | 无提醒也能讨论；点击不建会话、不发模型请求；发送后才受理 |
| A08 | 切章、换对象、刷新和重启 | 已发送引用不变，未发送文字保留，旧响应不覆盖新页面 |
| A09 | 探索与明确修改 | 探索无写入；明确指令提交允许范围并有真实回执 |
| A10 | 操作覆盖 | 创建 / 改名 / 修改 / 删除、绑定 / 解绑、用途 / 关系、提醒处理均能通过对话工具完成 |
| A11 | 采用旧建议 | 提交前识别旧版本，回读后处理，不覆盖新稿 |
| A12 | 幂等与失败恢复 | 同请求重试无重复对象，跨存储失败无半提交，重启后状态准确 |
| A13 | 修改与撤销 | 两布局、正文标记、出处及提醒一起回读；逆操作依赖受保护 |
| A14 | 正文边界 | 改构思不改正文；只在明确授权文件范围内改写 |
| A15 | 精确定位 | 唯一引文可重定位；歧义、缺失、不可读停止高亮；码点换算正确 |
| A16 | 删除依赖 | 不静默删关系、正文或其他对象；越权请求拒绝 |
| A17 | 只读图 | 时间轴 / 关系图可达且可返回，不拖动、不补造时间或关系 |
| A18 | 导航 | URL、前进后退、从出处返回、模块库返回均保留对象和阅读位置 |
| A19 | 分页和失败 | 游标过期能刷新，截断明确；服务失败不呈现空列表 |
| A20 | 屏幕与输入 | 320 / 736 / 1024 / 1440 宽度、200% 缩放、键盘可操作，无四栏并列或遮挡 |
| A21 | 试读隔离 | 实际发送的输入无作者隐藏事实、分类、未来关系及其衍生摘要 |
| A22 | 大作品 | 200 节点 / 300 关系有界读取，无逐条全书请求；记录响应体、请求数和首屏耗时 |

A22 在 P0 记录同一环境的基线，P5 比较；新增随章列表首屏必须是一次聚合请求，详情按需读取，不允许为每个节点额外请求。不要在没有测量时声称性能达标。

## 3. 在线模型验收

使用 `.env` 配置的在线模型，禁止改用本地模型；不要输出密钥。低频顺序执行，每个场景先跑一次；失败先修复，再单例复验。v1.0.7 没有执行在线讨论验收，本版必须独立取得证据。

| 编号 | 作者请求 | 检查对象 |
|---|---|---|
| O01 | 「这条铅弹线索还可以怎样安排？」 | 给出建议；正式方案、账本和正文均不改 |
| O02 | 「把身份揭示改到第五章」 | 计划真实提交，原文不变；两布局内容一致 |
| O03 | 选段后「把这里记成线索，暂不定用途」 | 创建身份和精确关联；无强制分类或补造真相 |
| O04 | 「采用刚才的建议」，之后「撤销这次调整」 | 版本明确，提交和逆操作真实完成 |
| O05 | 「按刚才构思修改第三章这一段」 | 只改授权片段，保留定位和来源更新 |
| O06 | 试读第一章，后章有隐藏解释 | 实际模型输入未泄露，建议不冒充作者确认 |

记录请求意图、读取材料、工具操作、写入前后差异、回执和浏览器结果；材料日志去除敏感配置。模型只说已完成而无提交，或只通过模拟回复，均不通过。输入含歧义时允许模型提一个必要问题，不要求无条件写入。

## 4. 验证节奏与交付

- P1—P4 只执行受影响模块的后端 / 前端定向测试及对应浏览器流程；新增测试针对身份、范围、版本、来源和真实用户行为。
- 发布阶段完成前端类型检查、构建、相关回归与在线验收；共享提交 / 受理链路确有修改时，在最终候选集中执行一次必要的后端广泛回归。
- 仅文档或版本号调整，不重复运行后端全量；本次制定计划只检查链接、内容一致性和改动范围。
- P5 核对 `pyproject.toml`、`src/hastings/__init__.py`、前端包及锁文件、`uv.lock`、健康检查和版本断言，升级为 1.0.8。
- 必需场景未通过时保留待验收状态；记录原因和剩余任务，不将版本号变更当作完成。
- 只有实际实施、验证完成后才写 `notes/` 与 `artifacts/` 的交付证据；根目录 README 和 `mynotes/` 不在本次修改范围。
