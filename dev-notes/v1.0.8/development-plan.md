# v1.0.8 详细开发计划

日期：2026-11-02。状态：P0—P5 已实施；确定性、前端、浏览器与在线模型验收完成。[产品边界](../../product-design/v1.0.8/README.md)与[接口契约](data-and-api.md)共同约束实现。

## 1. 交付目标

作者在全书总览安排故事，在正文中就近查看相关内容；两处通过同一对话调整同一对象。界面取消所有构思与线索属性表单，内部不再把字段完整度作为创作要求。

实施顺序先确保对话能承担必要操作，再统一撤除表单。最终交付不保留隐藏的高级编辑入口；不能交付只有只读页面、无法修正内容的中间状态。

## 3. 模块任务

### M1 统一阅读与随章投影

目的：双布局数据一致，不要求浏览器逐个遍历全书对象判断归属。

- 新增拟议 `workspace/story_chapter_view.py`，聚合当前方案绑定、线索账本证据和章节索引；不新增持久化表。
- 正文实际关联、本章计划项、失效引用分别返回；同一对象在不同组可以有不同来源，但客户端按对象身份合并显示。
- 用精确来源去重并保留全部出处；按章序和正文位置排序。提供分页和截断信息，不能静默遗漏。
- 当前对象详情继续复用既有读接口；全书列表不因本章过滤改变。

### M2 对话入口与上下文

目的：作者只表达调整意图，系统知道本轮对象和依据。

- 新增拟议 `state/discussionContext.ts`；统一对象、本章、选段三类焦点，服务端复核来源。
- 点击讨论只准备草稿引用；发送时冻结焦点、修订、正文摘要与请求键。重试复用同一请求。
- 扩充 `api.py → materials.py → service.py` 的输入、受理、恢复和状态保存；续聊和重启必须保持已发送引用。
- 当前会话可复用；运行中禁止用新选择替换本轮材料，等待发送或由作者明确新建会话。
- 普通讨论不强制 `review`；具体用途按本轮文字及已有授权判定。提醒核对才携带 `story_reconcile`。
- 材料优先级：显式对象 / 选段、直接出处、适用约定，再补读相关内容。截断要可追踪。

### M3 对话变更与回执

目的：所有原表单操作均有真正的对话路径。

- 逐项覆盖创建、改名、修改、删除节点 / 线索、关联 / 解除关联、用途与关系、暂缓 / 确认提醒和撤销。
- 复用 `story_tools.py`、`story_changes.py`、`story_store.py`、`story_clue_commit.py`，工具能力缺口在同一服务补齐，不另建聊天专用存储。
- 探索只给建议；明确指令可直接执行。采用已有建议时绑定具体建议和所依据的版本；旧建议先回读再处理。
- 模型只表达目标改动，由服务端读取当前完整对象并保留未修改字段，禁止用短摘要覆盖隐藏知情或线索用途。
- 跨对象改动沿用联合提交和逆操作；重试幂等；删除有引用的对象不能静默级联。
- 接入真实回执，展示改动对象和可展开差异。只在成功提交后刷新双布局；撤销保留依赖检查。

### M4 全书只读总览

目的：一眼读懂当前情节和线索，不承担数据维护。

- `WorkspaceDetail.tsx` 去掉字段状态、表单、保存、分类切换与关系编辑，抽出拟议 `ObjectReadDetail.tsx` 供两布局复用。
- 构思默认列表按讲述顺序组织；未知章节保留未安排分组。标题、情节正文、有依据的章节信息自然呈现。
- 线索详情原文与作者意图区分呈现；无值不显示空格子。保留来源失效提示。
- 时间轴、关系图按需切换，选中对象和返回位置保持；普通浏览不调用模型。
- 创建入口只进入对话，不能保留名称和用途弹窗。状态内部保持三种，不增加统计条或待办中心。

### M5 正文随章查看与导航

目的：在当前章就能找到相关内容，同时随时回到全书。

- 拟议 `components/workspace/ChapterContext.tsx` 使用聚合接口；点击正文标记、构思出处或本章相关项进入同一详情。
- 复用当前正文源坐标、Unicode 码点换算和唯一引文重定位；歧义时停止高亮。
- `WritingLayout.tsx` 统一辅助区模式，避免详情与对话同时增加列。保留正文正常编辑。
- 正文选段统一「讨论此段」；作者说「记作线索」后通过对话提交身份和绑定，不强制分类。
- URL 保留 `mode` 和对象 ID；正文允许节点 ID 和线索 ID，单次只选一种。路径和返回位置复用现有文件导航，必要补充参数在 P0 固定。
- 快速切章或换作品，旧响应不能覆盖新视图；双布局读取缓存按作品 / 方案 / 修订 / 章节隔离。

### M6 验收、清理与发布

目的：确保删除表单后没有功能缺口或无消费者接口。

- 执行[验收矩阵](acceptance.md)，真实在线验证对话闭环，不能使用预览固定回复替代。
- 删除仅为旧表单存在的前端函数、状态、样式和测试；共享写入服务保留。HTTP 端点先查全部消费者再决定去留。
- 程序完成后再统一版本到 1.0.8，更新锁文件、健康检查和必要版本断言。
- 更新当前开发入口和产品导航，记录未覆盖项。根目录 README 仅在作者另外要求时修改；`mynotes/` 只读。

## 4. 阶段与退出条件

| 阶段 | 模块 | 退出条件 |
|---|---|---|
| P0 | M1—M6 基线 | UI / HTTP / 工具消费者矩阵、操作覆盖表和验收样本确定；无已交付宣称 |
| P1 | M1、M2 | 聚合读取、发送快照、续聊恢复和章界隔离定向通过 |
| P2 | M3 | 所有必要操作可用；探索不写入，明确指令有回执，采用和撤销可核验 |
| P3 | M4 | 全书总览只读；时间轴与关系图仍可达；旧表单完整撤除 |
| P4 | M5 | 两布局同对象同结果，章节选择、出处返回和并发读取可靠 |
| P5 | M6 | 确定性、浏览器、在线验收和版本核对完成，按证据发布 |

依赖顺序为 P0 → P1 → P2 → P3 → P4 → P5。每阶段更新实际状态；计划内容不代替交付记录。

## 5. 风险与处理

全对话修改增加对模型理解的依赖：保留明确范围、真实回执和撤销，必要歧义只问一个关键问题。隐藏字段仍可能被误覆盖：规范化合并必须在服务端完成。两布局可能出现各自缓存：同一提交失效所有受影响读模型。正文修改可能使旧建议失效：提交前重新校验来源和版本。

本轮只改文档，不运行应用测试；后续按阶段定向验证，不反复运行后端全量。旧数据不迁移，测试使用新建隔离作品。
