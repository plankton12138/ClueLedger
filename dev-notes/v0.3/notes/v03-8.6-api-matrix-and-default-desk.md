## 关键决定

1. **拒启用 410 而不是 404/403**：入口曾经存在、本版不再提供——410 与「参数写错」（400）和「没有权限」（403）区分；错误码稳定，调用方按 code 分支。三要素的 `fix` 必须写清 0.3 的替代路径，拒绝本身就是迁移指引。
2. **拒绝在入口层，不删路由、不删服务**：底层 `review`/`audit`/`rewrite` 服务保留（"底层能力按用例复用"），OpenAPI 仍列出路径并返回 410——矩阵可以逐条对照，未来若要复用只需换处理器，不必恢复历史路由形状。
3. **只读与启动分离**：`GET /changes(/{cs})` 保留（历史可回看），启动类动作全部拒启。前端的旧三页同理：列表/详情只读，按钮撤掉——避免"看得见就能点"。
4. **旧写路径的证明以返回值为准**：每个旧写入口（导入/保存/恢复）都必须返回 `operation_id`，且 `GET /operations/{id}` 能回读章变化。旧单章导入此前只返回 commit_id、不进操作记录——本轮改造后与预览导入完全一致。
5. **语料隔离用静态守卫证明**：`CorpusStore`/`style_profile`/`load_all` 只允许出现在 `rag/` 与 V1 出口 `server/rest.py`；0.3 代码零引用（不靠口头承诺"没有隐藏检索"）。
6. **默认工作区切到底层体验而非入口排序**：默认视图 = 写作台，导航第一位 = 写作台；旧七页保留为兼容入口，被排除功能不再提供启动。

## 数据影响

- 无 schema 迁移、无数据删除；历史变更集、审计报告、重写记录只读保留。
- 旧入口的幂等键语义不变：保存/恢复的 `operation_id` 由既有意图指纹派生；导入的 `operation_id` 由 `chapter.import + project + chapter_id + idempotency_key` 确定性派生（重放不产生第二个操作）。

## 留白（带去向）

- V1 语料写接口（`POST /api/corpus` 等）仍可被**手工**调用（数据保留策略）；0.3 无入口、无自动消费，是否在 8.8 一并拒启待产品裁决。
- `coordinator`/`auditor` 角色仍可创建 Job（有凭据门禁），服务旧任务回看，不是 0.3 日常入口。
- 旧变更集的 impact/plan/hunk 详情不再在前端渲染（只读视图以对象清单与依据版本为限）；数据仍在，需要时经 API 回读。
- 逐章审批流的底层服务未删除；本版只保证入口不可达（8.8 收口时会再扫一遍不可达性）。
