# V03-6.1 图谱节点/边/来源/语义层统一只读投影

> 阶段开发记录；实现范围、待办与测试结果均对应记录时点。当前行为见[模块说明](../modules/README.md)，剩余缺口见[运行与验收状态](../release.md)。

关键词：图谱投影、语义层 truth/knowledge/disclosure/plan、来源 VersionedRef、证据状态、同 Commit 一致、无第二份可写事实、`GET /graphs`

## 目标与结果

V03-6.2/6.3 要交付四类图谱（人物、线索、手法、时间线），它们共用同一份图谱数据；
本任务先建这份**统一只读投影**，把「节点是什么、边从哪来、属于哪一语义层、证据
是否有效」在一个地方定义清楚，后续图谱类型只在它上面做筛选与视角，不再各存一份。

最终交付：

- 领域纯函数 `domain/story/graph.py::graph_projection`：把某 Commit 的 `StoryCatalog`
  投影为节点与边；节点覆盖正式账本种类（含叙事结构），边由条目引用字段与显式关系导出。
- 应用查询 `application/queries/graphs.py::GraphQueries`：按 Commit 回读投影，附中文
  标签/标题与证据状态；**只读端口，无写入路径**。
- HTTP `GET /api/v2/projects/{project_id}/graphs?at_commit_id=`：返回
  `{commit_id, nodes, edges}`，固定到实际读取的 Commit。

## 关键决定

1. **节点 = 正式账本对象，边 = 声明条目的引用字段或显式关系。** 图谱不是存储：
   节点带 `(kind, id, revision)` 可追回账本 Artifact；边带 `declared_by`（哪个条目
   声明的）与 `source_refs`。候选留在辅助表、不进正式快照，因此天然不入图（M12
   「候选不混入正式集合」），无需额外过滤。缺失连接只表示「未记录」，不在此推断。
2. **四语义层按种类归口**（M12 合同 `semanticLayer`）：`truth` = 故事世界中为真的
   设定与事实（人物/地点/关系/线索/真相/事件）；`knowledge` = 角色认知与证词
   （`story.knowledge`，误信/怀疑保留原语义）；`disclosure` = 读者披露；`plan` =
   尚未发生的叙事结构（`narrative.*`，含 `narrative.beat`）。作品约定
   （`story.agreement`）不是故事对象，不入图。
3. **引用字段口径复用 `canon/entries.py::LEDGER_REF_FIELDS`。** 单端引用（线索
   `points_to`、事实 `event_id`、真相 `culprit_id/accomplice_ids/true_timeline`、事件
   `place_id/participants`）导出「声明条目 → 被引对象」的边；两端引用
   （`relationship.source_id→target_id`、`knowledge.character_id→fact_id`）导出
   被引对象之间的边。不另维护一份字段清单，避免与写入校验漂移。
4. **证据状态复用 M05。** 证据状态取同一快照里的 `evidence.link`：目标对象
   `needs_check` 覆盖 `valid`，没有证据记 `not_recorded`。来源正文变化后发布器已把
   关联置为 `needs_check`（V03-2.2），本投影直接读，不另建失效逻辑（M12 硬要求）。
   边的证据状态优先取**声明条目**的核对结果，其次归因目标节点。
5. **悬空引用不入图**：边两端必须都出现在节点集合内（不变量 11 的投影侧体现），
   宁可少一条边也不画出账本里不存在的端点。
6. **命名取舍**：本任务先交付统一投影，暴露无类型的 `GET /graphs`；四类图谱的
   带类型路径（`/graphs/{characters|clues|method|timeline}`）由 V03-6.2/6.3 在它之上
   筛选实现，不在此提前固化筛选参数。

## 实现问题与未完成项

- 「无第二份可写事实」是**结构保证**而非测试保证：`GraphQueries` 只构造
  `StoryCatalog` 并调用纯函数，没有 `CommitService.commit` 调用路径；测试用
  「读图谱前后 head/条目数不变」做行为旁证。
- 留白 1：`story.place.adjacent`（相邻地点）在两处引用校验（`LEDGER_REF_FIELDS`）
  中未登记，因此暂不导出为边。要在图谱里画地点邻接，需先把它纳入引用校验口径，
  再在图谱推导中启用——不在本任务内私自定义第二份字段清单。
- 留白 2：真实工作区几乎不含 `evidence.link`（0.3 尚无产生证据的写路径），
  证据状态多为 `not_recorded`；`needs_check` 回流用直接提交测试覆盖。
- 留白 3：显式关系边（`snapshot.relations` 中 add 的边）在 0.3 账本写入里不产生，
  本任务按契约保留投影路径并用领域用例覆盖，实际数据出现依赖后续领域命令。
- 留白 4：四类图谱的带类型端点、角色视角/叙述位置筛选属 V03-6.2/6.3；布局偏好
  持久化属 V03-6.4。
