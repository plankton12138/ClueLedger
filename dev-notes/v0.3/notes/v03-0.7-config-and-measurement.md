# V03-0.7 配置与测量

> 阶段开发记录；实现范围、待办与测试结果均对应记录时点。当前行为见[模块说明](../modules/README.md)，剩余缺口见[运行与验收状态](../release.md)。

关键词：capabilities、统一配置、导入上限初值、凭据盘点、性能基线、SecretStr、环境变量回退

## 目标与结果

把「建议参数」变成「统一公布的配置」并测得服务侧基线。交付：

1. **凭据盘点**（artifact §1）：`SecretStr` + `mask_key` 已防 Key 进日志/查询/导出；未收口两点=配置文件明文（`config.yaml` 直填/env 引用）与环境变量回退（`env_fallback_config`），均移交 V03-1.3，本版不动存储。
2. **统一配置** `src/hastings/application/capabilities.py`：导入格式/上限（10 MiB 文件、20 MiB 批次、1000 章、预览 24h）、日志分页 200、图谱首屏 200 节点/500 边、防抖 500–1000ms；调用预算沿用 `execution.DEFAULT_CALL_BUDGET=12`。
3. **能力接口草案** `GET /api/v2/capabilities`（v2.py）：product/api 版本 + import 上限 + 性能目标 + 功能三态（implemented/draft/excluded）；排除项（author_model/style_observation/consistency_audit/corpus_rag）公布为 excluded——不显示为可用占位（计划 §1.4）。
4. **性能基线** `scripts/bench_v03_baseline.py` + `scripts/bench-v03-baseline.json`：100 章/30 万字/500 对象/1000 关系真实样本，走真实路径（import 命令/workflow.save/queries.catalog/get_snapshot）：保存 P95 78ms（目标 ≤1s）、章节回读 P95 77ms（目标 ≤500ms）、目录 71ms、快照 73ms——四项全达标；副本保存/完成/图谱/日志/UI 五项标 pending 到对应阶段。

## 关键决定

1. **初值是防护值不是能力承诺**：上限集中在一处经 capabilities 公布；「接口公布什么，前端就只能看到什么」——V03-2 的导入实现必须从本模块读常量，前端 V03-1 接线时同样只消费端点。
2. **功能三态而非布尔**：draft 让前端能区分「契约已冻结」与「已可用」；excluded 显式公布，避免「没有入口但也没说不支持」的灰色地带。
3. **性能测量只测已存在路径**：未建成的能力（副本保存等）标 pending 不伪造数字；脚本可复跑（`--db/--json` 参数）。
4. **凭据存储不在本任务改**：计划把改造放 V03-1.3（需要 OS 凭据存储适配端口的设计），本任务只盘点并记录升级顺序。
