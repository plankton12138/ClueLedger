# V03-0.2 冻结四类稿件身份与 revision 规则

> 阶段开发记录；实现范围、待办与测试结果均对应记录时点。当前行为见[模块说明](../modules/README.md)，剩余缺口见[运行与验收状态](../release.md)。

关键词：四类身份、ID 前缀、可辨识联合、请求指纹、并发凭据、前后端样例、往返序列化

## 目标与结果

让后续所有切片共用同一身份与引用规则（计划 §4.1、不变量 I01）。交付：

1. `src/hastings/domain/manuscript/identities.py`：四类身份 `ManuscriptKind`（formal/edit_draft/candidate/task_snapshot）+ ID 前缀表（`art/rev/cmt`、`eds/edc`、`cnd`、`tks`、`op`）+ `ManuscriptRef` 可辨识联合（每类必需锚点：commit_id/save_seq/content_hash/context_version，锚点按身份互斥）+ `reject_mixed_kinds` + `kind_of_id` + `OperationEnvelope`（计划 §6.1 统一成功信封，no_change 不伪造 commit）。
2. `src/hastings/application/idempotency.py`：业务层 `request_fingerprint`（只含「写什么」，排除 `CONCURRENCY_CREDENTIAL_FIELDS` 十类并发凭据，对齐 `CommitService._request_fingerprint` 取舍并写测试钉住）+ `operation_key_reused` 错误工厂。
3. `src/hastings/application/errors.py`：`V03_ERROR_CODES` 十项目标错误码注册表（执行指导 §3.1）。
4. 前后端共用夹具 `frontend/src/api/__fixtures__/v03-identities.json`（4 条引用 + 2 个信封 + 1 个错误信封样例），Python 侧 `tests/v2/manuscript/test_identities.py`（20 项）与 TS 侧 `frontend/src/api/identities.test.ts`（11 项）读同一文件做 wire 往返逐字段比对；`frontend/src/api/identities.ts` 为前端契约模块（camelCase 消费 + snake_case wire，纯函数可测）。

## 关键决定

1. **锚点互斥放在 wire 层硬约束**：正式稿引用携带 save_seq 直接在 `__post_init__` 拒绝（MANUSCRIPT_INVALID_OPERATION + details.field），不依赖调用方自觉——这是 I01「查询/写入拒绝混用」的可执行形式。
2. **指纹排除集显式登记为 frozenset**：新增写入口把同类凭据字段登记进 `CONCURRENCY_CREDENTIAL_FIELDS`，避免「合法重放被误判冲突」逐案复发；restore 重放场景（基础版本已前进）是该取舍的既有来源。
3. **夹具单一事实源放前端目录**：TS 导入 JSON 需要 `resolveJsonModule`（已加），Python 测试按仓库相对路径读取；两侧任一改动契约必须同时通过两侧测试，杜绝「类型文件存在但字段漂移」。
4. **错误信封沿用 `_error_body` 形状**（`{"error": {code/category/where/why/fix/details}}`），不新造信封；TS 侧 `ErrorEnvelope` 同构。
5. 与计划无偏差。既有前缀（prj/br/art/rev/cmt/rel/evt/job/run/conv/msg/turn/draft）在 `V03_ID_PREFIXES` 一并登记供盘点，未改写任何既有 ID 生成逻辑。
