# V03-2.4 手工修改副本：保存序号、暂存与一次完成

> 阶段开发记录；实现范围、待办与测试结果均对应记录时点。当前行为见[模块说明](../modules/README.md)，剩余缺口见[运行与验收状态](../release.md)。

关键词：EditSession、DraftChapter、保存序号 CAS、唯一未结束副本、完成一次发布、暂存不结束

## 目标与结果

作者随时改正文而不立刻动正式稿：修改落在独立副本，自动保存负责防丢字，
「修改完成」把本轮改动一次性发布成**一个**正式版本。交付：

1. **`domain/manuscript/edit_session.py`**：`EditSession`（作品、正式基础、状态、
   起止时间、关闭时操作）与 `DraftChapter`（章、基础、文本、指纹、保存序号、
   最后请求标识）的 wire 形式。
2. **`domain/manuscript/commands.py::save_drafts`**：完成时的领域命令，逐章复用
   `save_full_text` 的段落级 diff，整批合成一个变化集合。
3. **`CommitService.aux_mutate`**：单事务内读-改-写一条辅助记录——保存序号的
   比较与递增必须在同一事务里，否则两个并发保存都能通过检查。
4. **`application/services/edit_session_service.py`**：开始/恢复唯一副本、按章
   保存 CAS、暂存、放弃、完成（走统一发布后关闭副本）。
5. **REST**：`POST/GET /edit-sessions`、`GET /edit-sessions/current`、
   `PUT /edit-sessions/{id}/chapters/{chapter_id}`、`/suspend`、`/abandon`、`/finish`。
6. **前端**：`api/editSessions.ts` + `useEditSession`；写作台「手工修改」进入单章
   修改，800ms 防抖自动保存，显示已保存序号，提供暂存返回/完成修改/放弃。
7. **补上 2.3 的留白**：导入替换与未结束副本重叠时在确认阶段拒绝
   （`EDIT_SESSION_CONFLICT`），要求先完成或放弃本轮，不自动放弃副本
   （计划 M06 第 3 条）。

## 关键决定

1. **唯一未结束副本用「单键」表达**：辅助表 `edit_session_current/current` 存
   当前副本，键唯一即项目级唯一约束；完成/放弃后先写 `edit_session/<id>` 归档，
   再删当前指针。崩溃窗口里留下的是「已结束但未归档」的当前指针，`start()`
   发现状态非 open 时补归档再开新副本——不需要额外的锁表。
2. **CAS 放在存储事务里**（`aux_mutate`）：读序号 → 比较 → 写入在同一事务，
   这是「迟到响应不覆盖新文本」的实现基础；应用层先读后写的写法做不到。
3. **同一 `request_id` 重放不重复自增**：网络重试返回原草稿与序号；不同请求
   携带旧序号则 `EDIT_SAVE_SEQ_CONFLICT`，并带 `current_save_seq` 供前端刷新。
4. **完成 = 一次发布 + 关闭**：`save_drafts` 组合各章的纯函数，经
   `PublishManuscriptChange` 一个 `CommitRequest` 生效；成功后把副本标记 closed
   并归档。重试完成时读到 closed 副本，直接按 `closed_operation_id` 取回原操作，
   不会发布第二个版本（I03 的副本侧收口）。
5. **基础固定在首次保存**：草稿记下开始修改时的 `chapter_base`，完成时用它做
   乐观并发。副本期间正式稿被别的路径推进 → 整批 `MANUSCRIPT_BASE_CONFLICT`，
   副本与草稿原样保留，作者可以继续修改或放弃。
6. **单章限制写在交互里**：本阶段 UI 只开单章，修改期间禁用章节切换与导入，
   按钮 `title` 说明原因；底层 `save_drafts` 与完成接口已按章节集合设计，
   第二批开跨章完成不需要重建事实源。
7. **未落盘内容先持久化**：暂存与完成都先 `flush()` 等待队列清空；序号冲突时
   停在修改视图并提示，不把「暂存」变成静默丢弃。

## 实现问题与未完成项

- 坑 1：前端 `request(url)` 不带 body 时默认 GET，开始副本的 POST 被发成 GET；
  客户端测试抓到后显式传 `{}`。
- 坑 2：编辑文档时两次把装饰器与 `def` 合并到一行（删空行误操作），表现为
  整个模块语法错误；提交前跑测试是唯一可靠的发现方式。
- 留白 1：跨章完成的 UI 未开（底层已支持章节集合）；修改期间禁用章节切换，
  第二批再开放。
- 留白 2：多标签页真实并发只由「单事务 CAS + 顺序断言」覆盖，浏览器双标签
  手工走查未做；V03-5.5 会做多标签与断网重排。
- 留白 3：副本的「冻结引用」（固定 save_seq 的不可变快照）未提供独立接口，
  V03-2.5 历史回看与 V03-4 任务上下文会用到。
- 留白 4：草稿的段落来源（人工/生成混合）未记录；等 V03-3 候选采用进副本时补。
- 留白 5：放弃不清理草稿记录（归档后仍在 `edit_draft` 桶），便于事后核对；
  清理策略随备份/恢复（V03-8）一起定。
