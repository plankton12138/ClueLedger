# V03-7.5 手法图：只投影已有文字与关系

> 阶段开发记录；实现范围、待办与测试结果均对应记录时点。当前行为见[模块说明](../modules/README.md)，剩余缺口见[运行与验收状态](../release.md)。

> 交付日期：2026-10-19。计划 M12 手法结构行；执行指导 §11.4。

## 为什么做这个

手法在账本里只是一段自由文字（`MysteryTruth.method`），另有动机、掩盖方式、真实
时间线、凶手与协助者。最容易走偏的做法是「让模型把这段文字拆成步骤图」——看起来
很聪明，实际是在正式数据之外**新造一套结构**：步骤、条件、证据都变成没有账本依据
的对象，作者改一次正文，图就和事实对不上。

这一版反过来做：图里出现的每个节点、每条边都必须能追回账本已有条目；手法本身
原样回显，不解析成步骤。没写的就显示「尚未记录」，并说清去哪里补。

## 做了什么

### 领域：`domain/story/graph.py::method_projection`

- 以 `story.mystery_truth` 为起点，只沿**已有引用**走两跳：
  真相 → 凶手/协助者/真实时间线事件 → 事件的地点与参与者 → 这些事件上的
  真相事实 → 指向这些事实的线索。
- 边只取统一投影里 `semantic_layer=truth` 且两端都在子图内的；认知、披露、
  计划层的边不进入手法结构。
- 悬空引用（真实时间线指向已不存在的事件）只报缺口，不画节点。
- 输出：
  - `truths[]`：手法/动机/掩盖原文、凶手、协助者、时间线引用、`missing_fields`；
  - `gaps[]`：`METHOD_TRUTH_NOT_RECORDED`（没有真相条目）、
    `METHOD_TEXT_NOT_RECORDED`（三段文字缺哪段）、
    `METHOD_TIMELINE_UNRESOLVED`（悬空引用）、
    `METHOD_CLUES_NOT_RECORDED`（没有线索指向相关事实），每条带 where/why/fix；
  - `completeness`：只数三段文字写了几段，`note` 明说「不代表推理链成立或手法可行」。

**没有新增任何步骤/条件/证据领域对象**，也没有模型调用。

### 查询与接口

- `GraphQueries.method(project_id, at_commit_id, focus)`：固定 Commit、附展示标签
  与证据状态，与人物图/线索图同一口径。
- `GET /api/v2/projects/{id}/graphs/method`：空作品、无真相、资料不全都返回 200 +
  `gaps`，不用错误表达「还没写」。

### 前端

- `GraphViewTabs` 增加「手法结构」，时间线保留占位（V03-7.6）。
- `api/graphs.ts` 增加 `MethodGraphWire` 与 `fetchMethodGraph`；`useGraphData` 把三种
  视图归一为同一形状（`method` 字段仅手法图有值）。
- 主区 `GraphPanel` 在画布/目录上方显示手法摘要：三段文字（空的显示「尚未记录」）、
  完整度与 `note`、最多四条缺口（原因 + 补法）。侧栏概览沿用同一画布与空态文案。

## 验证

- 领域 5 项：无真相只报缺口、部分真相逐项报缺、悬空引用只报缺口、完整链条只投影
  已有关系且排除认知边、聚焦只留邻居且未知聚焦被拒。
- 接口 5 项：空作品、有正文无真相、部分真相（文字缺口 + 凶手边）、完整链条
  （无缺口、3/3、六类节点与五类边）、聚焦与 404。
- 前端 2 项：手法图请求与载荷契约、空态文案。
- 质量门：后端全量与前端 `vitest`/`npm run build` 见 `dev-notes/v0.3/README.md`。

## 已知留白（明确归属）

1. **时间线图**属 V03-7.6；本任务只做手法结构，不把时间顺序混进手法图。
2. 手法图**不解析步骤**是刻意约束：需要步骤时应该先有正式领域对象与作者确认，
   不能在投影层偷偷生成。
3. 同一批新建条目之间的引用、账本关系边（`relation_changes`）不进入手法子图——
   与 V03-7.4 的暂存边界一致。
4. 侧栏概览没有单独的「缺口摘要」块，只在主区显示；侧栏仍以画布/空态为主。
5. 完整度只是文字记录数，不评价手法可行性；这是产品口径，不是待办。
