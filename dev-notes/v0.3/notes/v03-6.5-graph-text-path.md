# V03-6.5 图谱文字等价操作、键盘与大数据布局

> 阶段开发记录；实现范围、待办与测试结果均对应记录时点。当前行为见[模块说明](../modules/README.md)，剩余缺口见[运行与验收状态](../release.md)。

关键词：文字目录、键盘等价、aria-activedescendant、布局偏好单一落盘点、半径随规模增长、大图虚拟化

## 目标与结果

V03-6.4 给了入口，但图谱仍只有一条读法：画布。验收 A22 要求「不用画布也能查看条目/来源
并继续写作」，且**键盘与目录具备相同能力**。V03-6.5 补的就是这条文字路径与大数据下的可读性，
仍然严守同一条线：图谱不是第二份可写事实（I08/I09）。

最终交付：

- 前端 `state/graphLabels.ts`（新增）：语义层、线索状态、证据状态徽章与关系概述的中文标签。
  抽成纯函数模块的原因很直接——同一对象在画布叫「真相」，在文字目录不能变成别的说法；
  原先这些标签长在 `GraphDetail.tsx` 里，文字目录会立刻复制第二份。
- 前端 `state/graphDirectory.ts`（新增）：文字目录模型（种类分组 → 条目 → 该条目的关联）、
  行键/DOM id 口径、键盘移动 `navigateRows`、空图说明 `graphEmptyText`、查看方式偏好
  `readGraphMode`/`writeGraphMode`（按 `project + view` 记本地区，缺省画布）。
- 前端 `components/desk/GraphDirectory.tsx`（新增）：`listbox` 文字目录。容器持有焦点，
  `aria-activedescendant` 指向当前行；方向键上下、Home/End 移动，回车/空格选中；鼠标点选只改选中。
- `GraphPanel.tsx`：头部加「画布 / 文字目录」切换（偏好持久化），两种方式共用同一详情区——
  查看条目、查找正文依据、加入讨论、跳转来源章因此都不再依赖画布。
- `GraphCanvas.tsx`：位置变更统一经 `handleNodesChange` → `settledPositions` 落盘（拖动结束与
  键盘方向键移动走同一条路）；超过 60 个对象只渲染视口内节点；缩放范围 0.1–2。
- `state/graphLayout.ts`：初始布局半径随节点数增长（每节点约 36px 弧长，上限 2400），
  取代原来固定 260 的上限——真实作品几十个对象不再挤成一团；新增 `settledPositions` 纯函数。

## 关键决定

1. **文字目录是同一份投影的第二种读法，不是第二份事实。** 目录由 `nodes/edges/clues` 纯函数
   派生，没有新端点、没有新存储；选中行后调用的仍是 V03-6.4 的详情区与 `/evidence-links`
   来源通道。目录里也**没有**任何写操作，事实变更照旧只能走账本编辑与确认路径。
2. **键盘与画布等价，但不等同于「把画布做成可 Tab 遍历的一堆按钮」。** 几十个节点的画布若
   逐节点 Tab，键盘用户要按几十次；列表型键盘操作（方向键移动、Home/End、回车选中）才是
   翻目录的直觉。画布本身仍保留节点聚焦与回车选中，方向键移动选中节点。
3. **键盘与鼠标共用同一份布局偏好。** React Flow 的方向键移动节点会产生位置变更而不触发
   `onNodeDragStop`；若只认拖动结束，就会出现「键盘挪了、刷新又弹回」。改法是把「落定帧」
   （`dragging !== true`）作为唯一落盘判据，拖动中间帧只更新画面。原「布局版本号触发重算」
   随之取消——落定后受控状态与偏好已经一致，不需要再补一次同步。
4. **目录顺序按中文读音（拼音），不是码位。** 作者是按读音翻目录的（「弟」在「姐」前），
   码位序对中文近似随机。同一条关系只挂在其**起点**条目下，避免目录里出现两次。
5. **大数据靠两件事：初始布局拉开 + 大图只渲染视口。** 半径随数量线性增长（弧长恒定），
   上限 2400 只防极端数据撑爆画布；超过 60 个对象交给 `onlyRenderVisibleElements`，
   配合 0.1–2 的缩放范围，让「看全」与「看清单个」都能做到。
6. **查看方式是本地区偏好，缺省仍是画布。** 与布局偏好同层、同样按 `project + view` 隔离；
   不写服务端，也不改变既有缺省行为——不打开目录的人看到的界面与 V03-6.4 一致。

## 实现问题与未完成项

- **踩坑（类型边界）**：`settledPositions` 直接接收 React Flow 的 `NodeChange` 联合类型时，
  编译器会因 add/remove 分支没有 `id` 而拒绝。改法是给最小形状加索引签名并让 `id` 可选，
  在函数里判 `typeof id` 存在后再收集；这样纯函数仍能拒绝「没有 id 的位置变更」，注释写明原因。
- **踩坑（取整余量）**：初始布局坐标取整，半径上限断言必须留 1px 余量，否则 2400 的圆周会
  报 2400.3。
- **踩坑（受控画布与本地偏好）**：取消版本号重算后，必须确认「落定帧一定在拖动结束与键盘移动时
  到达」，否则节点会在下一次重渲染时跳回旧坐标。当前由 `onNodeDragStop` + `dragging !== true`
  两条路径共同兜底，且都写同一份偏好。
- **留白 1：视角/叙述位置切换控件仍未接**（承接 V03-6.4 留白 1，后端已支持 `perspective`/
  `at_beat_id`/`at_chapter_id`/`focus`）。
- **留白 2：真实浏览器键盘走查与图谱 Playwright 旅程未补。** 本次以纯函数单测 + 构建证明；
  `listbox` + `aria-activedescendant` 的实际焦点行为、滚动到可见、导入法（IME）输入下的
  按键处理留待浏览器走查（与 V03-6.4 留白 4 同源）。
- **留白 3：手法结构与时间线视图**随 V03-7；**bundle 体积**（826.71 kB）仍无 code-split。
