# V03-1.1 三部分工作区壳（状态核心）

关键词：MainView、DeskState、applyOperationResult、阅读位置、初始焦点、数据事件与导航分离

## 目标与结果

按计划 M01 落地壳层状态核心：`frontend/src/state/desk.ts` + `desk.test.ts`（12 项）。

1. `MainView` 可辨识联合（manuscript/discussion/detail{candidate|diff|graph|history}）——主区内容一次只展开一个，`navigate` 是主区唯一变更入口。
2. `applyOperationResult`：数据事件只进 `operations` 数据区——不改主区、不改光标/滚动；**跨作品事件整体丢弃**（切作品后旧响应不写入新作品状态）。
3. 阅读位置四元组键 `project_id + chapter_id + source_kind + edit_session_id`（`readingPositionKey`）；`saveReadingPosition` 不改主区；source_kind/edit_session_id 不同即不同键（对齐 I01 身份区分）。
4. `selectInitialChapterId`：有正文恢复上次章节 → 无记录取目录第一章 → 无正文返回 null（只有未采用候选仍按构思状态）；保存的章节已删除回落第一章；按项目隔离。
5. 测试 12 项覆盖以上全部不变量；`npm run build`（tsc）通过。

## 关键决定

1. **本任务先交付状态核心，React 壳层组件接线（components/desk/ + App.tsx）随演示切片走查续做**——执行指导的关键测试就是纯函数（"applyOperationResult 等纯函数——数据事件与作者导航分离"），先把不变量钉进可测模块，UI 接线只是消费。
2. **OperationEnvelope 直接复用 V03-0.2 冻结的 identities.ts 消费形态**（camelCase），不另造操作结果类型。
3. **阅读位置含 scrollTop 字段**但讨论滚动键不共用（M01 第 3 条「禁止全局单个 scrollTop」）——讨论滚动随 V03-1.5 接着讨论接线时单独保存。
4. **跨作品事件丢弃是硬规则**：`applyOperationResult` 第一步比对 projectId，不做任何「尽力写入」。

## Agent 设计经验（四透镜）

1. 错误消息：纯函数层不产生用户可见错误；越界事件静默丢弃由上层日志负责（前端控制台可查）。
2. 硬约束：主区唯一 = 类型层面（可辨识联合）+ `navigate` 单入口；数据通道（operations）与导航通道（navigate）在类型与函数上物理分离。
3. 泄压阀：无正文（只有未采用候选）返回 null 是合法状态，壳层按构思状态渲染，不是异常。
4. 可观测性：operations 按 operationId 键控，幂等重放只保留一份——重复投递的事件不会堆叠。

1. `state/deskStore.ts`：zustand 薄包装 desk.ts 纯函数（不复制逻辑），新增
   `setProject`（换项目重置壳层，旧操作/回执不带入）、`focusMode`

   （save_idea 回执，见下）。

   **entry_id 浏览器内稳定复用**（后端由 entry_id 确定性派生作品 ID，
   同一入口 = 同一构思作品）；**request_id 按次分配**（首次提交生成、
   失败重试复用、成功清除）；草稿文本独立持久化（刷新恢复）。
3. `components/desk/DeskShell.tsx`：三部分壳——左（章节目录/想法与讨论/
   临时视图占位）、中（正文 paper-sheet + 底部唯一输入框）、右（账本概要/

   判定，区分「空目录」与「未加载」）；阅读位置滚动 300ms 防抖保存、
   打开章节恢复；detail 四类占位注明接入阶段；专注写作收起两侧。
4. `components/desk/DeskComposer.tsx`：唯一输入框——引导卡按
   `chat.serviceKind` 显示模型状态（未连接时给「打开模型设置」入口，
   M01 第 6 条）；保存成功后回执入 deskStore，作品自动登记进顶部选择器
   （已登记则保留原显示名）。
5. `App.tsx` + `Workbench.tsx`：View 联合加 `"desk"`，nav 增「写作台」，
   默认 view 仍为 overview——旧七页全保留，不提前切默认（V03-8.6）。

### 关键决定

1. **save_idea 回执不伪造 OperationEnvelope**（无 operation_id，类型对不上
   冻结 DTO），单独记 `entryReceipts` 与操作结果同区展示——不污染
   V03-0.2 冻结的数据契约。
2. **初始焦点判定自取一次 GET manuscript** 而非复用 v2 store：App 的
   refreshManuscript 异步竞态下无法区分「空目录」与「尚未加载」，一次性
   自取换取确定性；章节列表渲染仍走 v2 store（App 负责刷新）。
3. **输入框当前固定走无作品入口**（构思作品），不路由到当前选中作品——
   向已有作品发消息是 save_author_message（V03-1.5 范围），本任务不混入。

### Agent 设计经验（四透镜）

1. 错误消息：V2Error 原样透出 why+fix（request_id 冲突时后端三要素直接
   指导作者「新想法用新 request_id」），前端不改写。
2. 硬约束：幂等键规则放 api 层纯函数（可注入存储、node 可测），组件只
   消费——重试语义不依赖组件状态机。
3. 泄压阀：无正文/未连接模型/存储禁用都按合法状态渲染（构思状态卡、
   引导提示、会话内身份退化），不报错不阻塞输入。
4. 可观测性：操作结果区独立于主区——异步结果到达时作者正在读正文也
   不被打断，回执带时间与状态可回溯。
