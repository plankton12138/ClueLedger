# V03-1.3 个人 Key 与连接同源

> 阶段开发记录；实现范围、待办与测试结果均对应记录时点。当前行为见[模块说明](../modules/README.md)，剩余缺口见[运行与验收状态](../release.md)。

关键词：CredentialStore、keyring、credential_ref、明文迁移、物化、脱敏、OS 凭据存储

## 目标与结果

计划 M02 凭据三条 + 执行指导 §5.3 的核心落地。交付：

1. **端口** `application/ports/credentials.py`：`CredentialStore`（save/load/delete）。
2. **实现** `infrastructure/credentials.py`：`KeyringCredentialStore`（经 keyring 25.7 走 OS 凭据管理器，已加入依赖；库缺失/后端故障 → `CREDENTIAL_STORE_UNAVAILABLE` 三要素环境失败）+ `InMemoryCredentialStore`（测试/降级）+ `build_credential_store()` 工厂（OS 不可用降级内存——**可见故障不是静默回退**：重启后档案变不可用即安装引导触发点）。
3. **`ProviderProfile.credential_ref`**：连接元数据只存引用；`save_server_config` 按需落盘该字段。
4. **升级顺序** `migrate_plaintext_credentials(config, store, path)`：写入并验证（回读一致）→ 元数据切换（credential_ref 落盘）→ 清理旧 Key 字段（api_key 置空）；每档案独立迁移，任一步失败旧连接原样保留 + 报告带错误码；幂等（已迁移跳过）。
5. **物化** `_materialize_credentials`：运行时视图把 OS 凭据装回 `api_key`（SecretStr 只进不出）——下游 `resolved_api_key/build_provider/mask_key` 消费点零改动；`ProviderBook.__init__` 启动时迁移+物化（`book.credential_migration` 报告，boot 打印失败提示）；`update_config` 物化新配置。
6. **UI 连接** `POST /api/providers/connect`：Key 先入凭据存储再清明文（可用性判定在清空前，顺序修复过一次）；响应从物化后的 book 回读（key_hint 仍只尾 4 位）。
7. **测试** `tests/v2/server/test_credentials.py`（5 项）：存储契约；迁移（磁盘无明文 + 原始文本终检 + 幂等）；失败保持旧连接（BrokenStore 注入）；物化可用；UI 连接（响应/磁盘均无明文 + 重启后同源可用）。
8. **boot 接线** `server/__main__.py`：`build_credential_store()` → ProviderBook；迁移失败逐条打印明确提示。

## 关键决定

1. **物化而非穿透**：Key 解析只在 ProviderBook 边界发生一次（启动/更新配置时装回内存），下游 5 个消费点不改签名——「key 只进不出」防线沿用 SecretStr，OS 存储只在边界接触。
2. **迁移在 boot 时自动执行**：幂等 + 失败安全（每档案独立、失败保留旧明文可恢复），符合计划升级顺序；报告经 boot 打印与 `book.credential_migration` 可查。
3. **InMemory 降级是显式可见故障**：不伪装成「已保存」；档案在重启后不可用触发安装引导（M02 泄压阀）。
4. **与计划偏差说明**：普通流的 env 回退**未在本任务移除**——`env_fallback_config` 仍是 config.yaml 缺失时的回落（既有测试与开发模式依赖）。计划要求的是「不作为普通产品流的隐式回退」：用户连接（book.materialized profile）已全链路优先于 env（`_resolve_profile_model` book 优先）；env 回退的彻底移除与「开发模式开关」一起在 UI 接线时收口（留白 2）。

## 实现问题与未完成项

- 坑 1：`save_server_config` 白名单字段漏了 credential_ref——迁移报告成功但磁盘没写；补字段后磁盘终检通过。
- 坑 2：connect 流程先清空 api_key 再判 `available` → 恒 422；可用性判定前移。
- 坑 3：keyring 后端返回 Any → mypy no-any-return；显式注解 `str | None`。
- 留白 1：`DELETE /api/providers/{name}`（删连接）目前不清凭据存储里的 ref——残留无害但应在删除流程清理（V03-1 剩余接线）。
- 留白 2：env 回退的显式开关（开发 .env 可用、产品流不隐式借用）随模型引导 UI（V03-1.1 组件部分）收口；现状是「用户连接优先级已最高 + env 仅在无 config.yaml 时兜底」。
- 留白 3：keyring 在 Windows CI 的可用性未验证（本机 win32 已安装可导入）；打包发行（PyInstaller）时需带 keyring 后端依赖。
