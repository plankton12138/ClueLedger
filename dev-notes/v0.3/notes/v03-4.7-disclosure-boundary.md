# V03-4.7 构建笔记：前章润色的知情与披露边界

状态：**已交付**（2026-10-18）。位置解析、三个通道、保守缺省、扩大披露检测、
背景第二层与采用门槛均已完成；语义级越界检测与叙事结构入口见留白。
范围：润色前章时，回答「这个位置谁已经知道什么」，并拦住「把后文真相提前写出来」。

## 为什么这块不能靠模型判

计划同时要求两件事：「前章不泄漏后文」和「不新增独立模型一致性审计」。放在一起，
唯一自洽的做法是**把边界算成数据**，让生成前的提示词与采用前的检查用同一份结果：

- 生成前：边界作为背景的第二层（约定之后、核心之前）进入提示词，写明哪些事实
  「不得在本章让角色说出或让读者看出」；
- 采用前：拿新稿与原文比，新出现且尚未揭示的事实名就是扩大披露，需要作者授权。

两者共用同一个 `DisclosureBoundary`，所以不存在「提示里说不能写、落地时却放行」
这种两套口径的漏洞。

## 六个关键取舍

**1. 位置是输入，不是推断。**
策划分开的「叙事章」与「稿件章」没有 ID 对应关系。用章序或标题去猜这个对应，
在最需要谨慎的时候（倒叙、拆章、合并章）恰好最不可靠。所以位置由调用方显式给出：
章 ID 或节拍 ID，不给就是 `unknown`。

**2. 未知位置不是报错，是保守。**
`unknown` 时所有事实按「不要说」处理，并带一条警告。这样默认路径不会因为「没传位置」
就悄悄放开约束；同时采用门槛在位置未知时**只报不拦**——没有位置就没有裁决权。

**3. 倒叙按结构顺序，不按章号。**
边界直接用 `story_state_at_beat` 折叠，`ordered_beats` 是唯一顺序来源。测试里
「第十二章 回忆」排在「第五章 现在」之前，读者在后者已经知道前者揭示的事——
按章号比较会得出相反结论。

**4. 读者披露与角色知情是两个通道，不合并。**
`reader_known` 记解释（true/false/partial），`character_known` 记哪些角色知道。
「读者知道但角色不知道」是最常见的悬念结构，合成一个「已知」会把悬念抹平。

**5. 证据待核对优先于一切。**
某条事实只要有 `needs_check` 的证据，就降级为 `unverified`，哪怕披露记录说读者已知。
这是 I09/A16 的直接落地：旧记录不能证明已经获知，第 2 章不能据旧记录认定读者已知。

**6. 扩大披露的基线是原文，不是边界。**
「默认润色不扩大披露」的字面执行方式是：原文没有、新稿才出现的后文事实名算扩大。
作者原来就在这一章写过某个词（哪怕记录里没登记），说明它已在本章范围内。
这样避免了「历史记录不全 → 正常润色也被拦」的误伤。

## 检测能力的边界（重要）

`check_expansion` 是**字符串级**的：只在可命名的短标签（≤24 字）上做子串匹配。
长陈述句（线索、真相陈述）会被计入 `skipped_terms` 并如实返回，不假装检查过。
它的定位是「拦住『怀表早已损坏』这类被提前说破」，不是语义审计——判「这段话是否
暗示了真相」需要模型，而计划明确不为此新增模型审计。

## 留白与风险

1. **叙事结构还没有创建入口**：`narrative.chapter` / `narrative.beat` 目前只能由
   既有剧情规划链路产生，账本接口不建这些种类。所以端到端验收（真实作品里润色第 1 章）
   要等结构树与默认壳（V03-8.6）具备后再跑；本笔记的接口测试用测试替身给出位置。
2. **稿件章与叙事章没有显式绑定**：现在由调用方传 `story_chapter_id`。将来若要
   「打开第 1 章就自动知道叙事位置」，需要一条显式映射（属于 V03-8 的界面对齐）。
3. **检测只看名字**：见上节。长陈述的语义越界由生成前的边界块约束，落盘时不审。
4. **只拦改写现有章**：新建章没有「原文基线」，也就没有「扩大」可言；新章靠边界块约束。
5. **`first_reveal_at` 只给章名**：够作者定位，但没有精确到节拍或段落。

## Agent 设计经验

- **同一份约束要同时喂给生成与检查**，否则两边口径一定会分叉；这次复用了同一个
  `DisclosureBoundary`，避免「提示说不能写、发布却放行」。
- **拿不准时把「不做判断」也做成明确状态**：`unknown` 位置比猜一个位置更安全，
  而且能被观测（有警告、能显示「未定位」）。
- **字符串级检查要敢承认它的上限**：`skipped_terms` 让「没检查」可见，
  比把长陈述静默放过更像一句真话。
