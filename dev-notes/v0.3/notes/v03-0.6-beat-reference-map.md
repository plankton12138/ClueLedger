# V03-0.6 Beat 引用盘点与替换表

关键词：Beat 盘点、at_beat_id、活动路径分类、替换表、三类新表示、格式版本冻结

## 目标与结果

为 V03-3.1「Beat 活动路径退出」提供可核对基线：不猜模块名，逐文件逐条扫描并分类。产出 `dev-notes/v0.3/artifacts/v03-0-beat-reference-map.md`：

1. **引用分类**：活动路径 9 个文件（kinds/narrative models+commands+state、mystery models+rules、canon commands、views、task_drafts、agent_workflows.draft、contexts、story_proposals、changes planning/patch_guard/scope、server/v2 project_view）；历史只读 4 类（仓库存量数据、旧 Job payload beat_states、0.2 测试夹具、旧 wire 字段）；前端 0 引用（chat.ts 的 "beat" 匹配实为 heartbeat 注释）。
2. **替换表**：计划 §8.2 七行旧信息 → 目标去向，每行挂引用位置，「无法确定时」列原文保留。
3. **三类新表示草案并冻结格式版本**：`story_position.v1`（正文源位置：commit_id/chapter_id/unit_id/选区，替代 at_beat_id 的「在哪里」锚点）、`story_event.v1`（故事事件：story_time 支持 point/interval/unknown，获知事件是其 kind）、`disclosure_position.v1`（披露位置：narrative_order 叙述顺序 + knowledge_sources 获知事件 + mode 真相/证词/认知）——故事时间、获知事件、叙述顺序三者分开，不混用 chapter_index。
4. **移交 V03-3.1 执行要点**：先证明新路径无引用再删活动类型；task_drafts/agent_workflows 先改；存量转换创建新 revision 并出升级报告；兼容器只读不可创建。

## 关键决定

1. **本任务零代码改动**：纯盘点+草案。存量数据暂不删除、暂不转换（执行指导 §4.6 纪律）——转换的前置证明（新路径无引用）在 V03-3.1 才可能成立。
2. **格式版本号单独冻结**（`*.v1`，schema_version=1）：与数据库 schema 版本（v4）、产品版本（0.3）三者独立管理（计划 §8.1），后续阶段造新字段必须 bump 版本号而非改形状。
3. **`story_position` 用 TextUnit 稳定 ID + 选区**而非章节全文哈希：直接落实计划 §4.1「分段/合段/删除不能只凭章节全文哈希冒充精确来源」。
4. **`story_time.kind=unknown` 是一等公民**：未知时间保留区间/未知，不猜精确时间（M12 时间线验收）；`disclosure_position.mode` 承载 I09 的四分（真相/证词/认知/披露）。

## Agent 设计经验（四透镜）

1. 错误消息：盘点发现 views.py 的「披露未绑定到有效节拍」告警在 0.3 要有对应替身（未绑定正文位置 → needs_check），已在替换表「无法确定时」列保留语义。
2. 硬约束：活动契约扫描（Schema/工具/上下文三入口无 Beat）被写成 V03-3.1 的删除前置——先证明再删，避免「删了类型但快照还依赖」。
3. 泄压阀：三类新表示都把「未知」设计为合法值（unknown/needs_check），不把缺失信息变成异常。
4. 可观测性：每行替换表挂文件:行，升级报告可按 ID 逐项核对（计划 §8.2 要求数量与 ID）。
