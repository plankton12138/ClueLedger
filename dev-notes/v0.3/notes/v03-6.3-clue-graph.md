# V03-6.3 线索图：线索子图、计划/实现分离与叙述位置筛选

> 阶段开发记录；实现范围、待办与测试结果均对应记录时点。当前行为见[模块说明](../modules/README.md)，剩余缺口见[运行与验收状态](../release.md)。

关键词：线索图、支持（指向）、计划出现 vs 已在正文出现、合法缺口、后文线索不提前出现、M05 证据状态、`GET /graphs/clues`

## 目标与结果

V03-6.1 建立了统一只读投影；人物图（6.2）在同一投影上按视角筛选。线索图同样**不另存
一份数据**，只在同一投影上筛出「与线索相连」的子图，回答「这条线索指向什么、在哪里
出现、是否已经在正文实现、还有什么没接上」。两条硬验收：**原文变化后立即显示需核对**、
**后文线索不提前出现**。

最终交付：

- 领域纯函数 `domain/story/graph.py::clue_projection`：在 `graph_projection` 结果上筛出
  与线索相连的边，并为每条线索报出计划/实现状态与叙述位置标记。
- 复用既有投影：`domain/story/views.py` 的 `position_map`、`reader_reveals` 转为公开
  （原 `_position_map` / `_reader_reveals`），与披露时间线、公平性判定共用同一份口径。
- 应用查询 `application/queries/graphs.py::GraphQueries.clues`：按 Commit 回读，附展示
  标签、位置声明与局部邻居；**只读端口**。章→末节拍的解析抽成 `_resolve_position`，
  与人物图共用。
- HTTP `GET /api/v2/projects/{project_id}/graphs/clues`：查询参数
  `at_commit_id / at_beat_id / at_chapter_id / focus`。

## 关键决定

1. **统一投影上筛选，不重建边。** 边 ID、标签、语义层、来源、证据状态全部沿用 6.1 的
   `GraphProjection`；线索图仍不是第二份可写事实（I08/I09）。
2. **只保留与线索相连的边。** 判据是「边的任一端是线索节点」——线索自身声明的
   `points_to`（投影标签「指向」，即支持某条真相/事实），以及与线索相连的显式关系
   （如 `mentions` 连到误导解释）。**没有正式记录的连接不出现**：误导解释、反驳若没有
   账本依据就不连线，缺口如实留白，不凭模型措辞画推理链（产品 §5.6）。
3. **计划/实现分离。** 计划出现取 `Clue.disclosure_plan` 落在结构内的节拍；已在正文出现
   取 `points_to` 所指事实的**读者披露位置**（`reader_reveals`，与公平性判定同源）。
   二者不合并成一个「已实现」状态：`status` 分 `implemented`（已有正文披露）/
   `planned`（有计划无披露）/ `missing`（无任何出现记录）。
4. **「missing」是合法缺口，不判错。** 没有关联解释可以是作者刻意保留的悬念（产品
   §5.6），因此缺记录只报 `missing` + `first_position=None`，绝不合成位置或报违规。
5. **叙述位置只标不裁。** `at_beat_id`（或经 `at_chapter_id` 解析出的章内末节拍）给出截至
   位置；线索最早出现位置晚于它即标 `within_position=False`，同位置的标 `True`，无位置
   记录留 `None`。列表仍返回全部线索，由调用方按标记决定渲染——**不静默丢弃**，
   同时满足「后文线索不提前出现」。
6. **证据复用 M05。** `evidence_status` 直接读同快照的 `evidence.link`：来源正文变化后
   发布器已把关联置 `needs_check`，本视图照读，不另建失效逻辑。
7. **局部聚焦在视图边集内取邻居。** `focus` 收窄到该对象及其邻居；聚焦对象必须存在于
   投影节点集，否则按未知对象拒绝。

## 实现问题与未完成项

- **踩坑（领域设计）**：`points_to` 的目标只允许 `TRUTH_FACT` / `MYSTERY_TRUTH`
  （`canon/entries.py` 的 `LEDGER_REF_FIELDS`），且 `Clue.disclosure_plan` 已从可写字段
  退役（仍可读）。所以「计划出现」沿用既有投影的读口径，而**不**新造一套「计划」字段；
  写侧要用披露计划只能走直接提交（不在本任务补写路径）。
- **踩坑（复用边界）**：`position_map` / `reader_reveals` 原为私有，本次改为公开并把内部
  调用点一起改。判定口径只有一份——若线索图自建一份读者披露读取，就会与
  `mystery_fairness` 漂移。
- 留白 1：**误导解释与「曾被解释为」**目前没有正式账本字段/关系类型（`RedHerring` 无引用
  字段），因此独立误导解释不会自动连线；等有正式关系类型经 `catalog.relations` 记录后，
  本视图的「线索相连边」判据会自动带上它，无需改筛选逻辑。
- 留白 2：「反驳」同样依赖正式关系记录，本任务只忠实投影已有连接，不做判定。
- 留白 3：出现的**章节分组**未在本视图合成——视图只给出现的节拍位置（及其在投影里的
  节点），章节归属由前端用叙事树接口解析，避免在只读投影里凭空造「节拍→章」的结构边。
- 留白 4：前端图谱接线（右侧局部图、来源定位、布局持久化）属 V03-6.4/6.5。
