# V03-6.4 图谱交互与布局持久化：右栏小图、主区展开、来源定位、加入讨论

关键词：图谱接线、React Flow、拖动零领域写入、布局偏好本地区、来源定位、加入讨论、返回原正文位置与副本

## 目标与结果

V03-6.1–6.3 把图谱做成了**只读投影**：节点、边、语义层、证据状态、人物视角与线索计划/实现
都在后端算好，前端一直没有真实入口。V03-6.4 的职责是**接一个入口，但绝不把图谱做成第二份
可写事实**（I08/I09）。硬验收是「**拖动零领域写入；返回原正文位置与副本**」。

最终交付：

- 后端：`EvidenceService.list` 增加 `target_id` 过滤（`evidence_service.py`），
  `GET /evidence-links` 端点透传 `target_id`（`server/v2.py`）——供图谱节点「来源定位」
  按被锚定的账本对象回读它在正文中的全部依据。不新增读模型，只收窄既有查询。专项测试
  `tests/v2/history/test_history_evidence.py::test_evidence_filters_by_target_id`（命中/不命中/
  不传时行为不变）。

  `graphSelectionKey` 按 `project + view` 隔离）、确定性初始布局 `initialLayout`、

  `appendReference`。11 项单测（`graphLayout.test.ts`）。
- 前端只读客户端 `api/graphs.ts`：统一投影/人物图/线索图三者的 Wire 类型与取数，
  以及「来源定位」`fetchEvidenceByTarget`（走 `/evidence-links?target_id=`）。4 项单测。
- 组件：`GraphCanvas`（React Flow 承载；自定义节点 + 紧凑模式）、`GraphDetail`

  `DeskComposer.tsx` 消费（追加引用到唯一输入框）。

## 关键决定

1. **图谱不是第二份可写事实：拖动只写本地区。** 节点位置来自纯函数确定性初始布局 +
   浏览器 localStorage 的布局偏好；`GraphCanvas.persistPosition` 只调 `writeLayout`，
   **不发起任何请求**。正式关系与手法的变更必须走账本已有的编辑与确认路径（产品 §5.4/§5.8）。
2. **初始布局确定且不表达重要性。** `initialLayout` 把节点按 ID 排序均匀落在一个圆上，
   不引入随机或力导向收敛差异；**位置不表示故事质量或嫌疑程度**，避免「谁在中间谁重要」
   的暗示。拖过的坐标优先（`resolveLayout`），新节点补初始位置，已消失节点丢弃。
3. **布局与选中按 `project + view` 隔离。** 换作品、换视图互不污染；选中对象（上次查看的
   节点）单独记一份，「返回正文/讨论再打开图谱」能继续停在上次查看处。
4. **右栏只给摘要与小图，主区展开同一视图。** 侧栏窄栏不塞整个作品的所有节点：紧凑模式
   上限 8 个节点，边只保留两端都可见者（避免悬空线），选中对象若被截断则补进来；
   「展开查看」把同一视图放进主区 `detail.graph` 槽位（复用主区一次只展开一个的不变量）。
5. **来源定位复用既有证据通道。** 只给 `/evidence-links` 加 `target_id` 过滤，不新增读
   模型；点证据项跳转到来源章（`onNavigateChapter`），跳转不改变阅读位置四元组的记录口径。
6. **加入讨论只是把文字放进草稿。** 选中对象的可见引用（种类、标题、版本、说明）由
   `buildDiscussionReference` 构建，经 `deskStore.requestComposerInsert` 附到**唯一输入框**；
   保存前不产生任何领域写入，仍走既有想法落盘路径。
7. **画布不是唯一入口。** 节点/边同样可由文字路径选中（`GraphDetail` 的属性文本、
   线索状态、关系含义），画布只是投影——键盘/文字等价操作在 V03-6.5 补齐（A22）。

## Agent 设计经验（四透镜）

1. **错误消息三要素**：图谱取数失败不吞错（`useGraphData` 把错误交给调用方显示，
   `message(e)` 原样透传服务端信封）；来源定位失败在详情区就地显示，不静默。拖动等
   布局操作本就不该产生错误——它不接触后端。
2. **硬约束放工具层，UI 只解释世界**：「客户端只读、没有写端点」是这一层最强的硬约束
   （`api/graphs.ts` 只有 GET）；「图谱节点位置不表示重要性」写进纯函数注释与初始布局
   本身，而不是指望作者记住。库（React Flow）承载交互，领域语义留在后端投影。
3. **降级处理（区分三情形）**：**合法但空结果**——无人物/无线索时不报错，给「先去账本
   登记」的下一步指引（`GraphCanvas` 空态、`GraphDetail` 无证据时的说明）；**环境故障**——
   取数失败如实显示，不吃掉；**参数违规**——由后端在 V03-6.2/6.3 已挡住（视角/位置/聚焦），
   前端只按 code 分支。
4. **可观测性是事件契约的一部分**：详情区显式显示语义层（真相/认知/披露/计划）、证据状态
   （来源有效/需核对/未记录）、线索状态（已在正文出现/计划出现/还没有关联出现记录）、
   关系表面态与真实态（角色视角下真实态明确标注「当前视角不可见」）；右栏概览单独统计
   「N 处来源需核对」。作者能直接读到「为什么这条边这么画」，不靠猜。

## 踩坑与留白

- **踩坑（组件类型边界）**：详情徽章初版自定 `tone: "gray"`，但共用 `Pill` 只接受
  `blue/green/amber/red`——「未记录依据」改用 `blue`。复用既有组件时须先核对其类型契约，
  不为新视图另造一套视觉。
- **踩坑（受控画布与本地偏好同步）**：React Flow 的 `useNodesState` 是受控的，拖动落盘后
  若不同步重算就与偏好漂移。用 `layoutTick` 版本号在落盘后触发一次重算，保证受控节点与
  偏好一致。
- **留白 1：视角/叙述位置控件未接。** 后端已支持 `perspective` / `at_beat_id` /
  `at_chapter_id` / `focus`（V03-6.2/6.3），前端目前只按缺省口径（作者全知、全图）取数，
  视角与位置切换控件留待后续任务。
- **留白 2：手法结构与时间线视图。** 标签位已占（`GraphViewTabs`），带类型端点随 V03-7，
  0.3 不提前画「等填满的大画布」。
- **留白 3：键盘/文字等价操作与可访问性**（A22）归 V03-6.5——画布已有 `aria-label`
  与文字详情路径，但完整的键盘导航与等价操作未做。
- **留白 4：图谱旅程的浏览器 E2E** 未补（Playwright J7-J8 图谱旅程留白），本次以纯函数
  单测与构建证明前端未回归。
- **环境提示**：引入 React Flow 后主 bundle 约 822 kB（gzip 270 kB），vite 给出 chunk 体积
  警告；本任务不引入 code-split，记为构建体积留白。
