# V03-0.1 全链路 API 与调用点盘点

> 阶段开发记录；实现范围、待办与测试结果均对应记录时点。当前行为见[模块说明](../modules/README.md)，剩余缺口见[运行与验收状态](../release.md)。

关键词：API 清单、全链路盘点、前后端交叉核对、任务启动链路、缝隙分析

## 目标与结果

解决「不凭模块名推断调用链」的问题：为后续所有演进/新增/退役决策提供可核对基线。逐条读后端路由注册点（`server/rest.py`、`server/model_access.py`、`server/v2.py`、`interfaces/api/*.py`）、前端调用点（`frontend/src/api/*`、`state/*`）与任务启动链路（`JobStore.create` 与模型运行入口、恢复路径），交叉核对前后端缝隙。产出 `dev-notes/v0.3/artifacts/v03-0-api-inventory.md`：10 节、约 90 行动作清单，每行带 0.3 处置（保留/演进/适配/隔离/退役）与处置阶段。

## 关键决定

1. **处置五分类**：保留 / 演进 / 适配 / 隔离 / 退役。旧写入三条路径（`chapters/{id}/save`、`chapters/import`、`chapters/{id}/restore`）判定为「适配统一发布」而非新造接口，符合计划 §6.2「现有同能力接口优先演进或适配，不长期并存两个写入口」。
2. **缝隙结论**：前端有功能后端缺——未发现；后端多余接口——`POST /coordinate`（前端 0 调用，判退役）；语义错位——上述三条写路径绕过操作记录与证据核对。
3. **开发模式默认模拟器**：`state/chat.ts#mockEnabled` 在 `import.meta.env.DEV` 下恒真，`npm run dev` 默认走 `chatSimulator` 而非真实 API。登记为显式例外：0.3 验收必须生产构建或显式关 mock，模拟器不作交付证据（计划 §9.1 第四层）。
4. **任务启动 8 条链路**全部追迹到代码行，其中前 4 条是自动模型链（章提交→AnalysisDispatcher→manuscript.analysis Job→style 观察；worker_loop 恢复与派发），即 V03-0.3/0.4 零调用测试的覆盖点。
5. Beat 引用定位 9 个文件，移交 V03-0.6 逐文件分类。
