# V03-1.2 入口预约与无模型记录

> 阶段开发记录；实现范围、待办与测试结果均对应记录时点。当前行为见[模块说明](../modules/README.md)，剩余缺口见[运行与验收状态](../release.md)。

关键词：entry 预约、reserve_once、save_author_once、not_requested、确定性作品身份、SaveIdea

## 目标与结果

对齐计划 M02 的 `SaveIdea` 用例与 §6.2 用例矩阵两行（`POST /api/v2/entries`、`POST /conversations/{id}/author-messages`）。交付：

1. `application/services/entry_service.py`：`EntryService`——`reserve_once(entry_id, request_id)`（预约作品/讨论）、`save_author_once`（无模型端口，`not_requested`）、`save_author_message`（后续想法）。**类不持有任何模型运行端口**——保存与启动是两个用例（M02 目标骨架收编）。
2. 确定性作品身份：`create_project(name, project_id=None)` 增加可选显式 ID；entry_id → `prj_<hash(entry_id)[:24]>` 确定性派生——同 entry 的任何次重试找回同一作品，不重复创建（失败重试不重复建作品的实现手段）。
3. 预约记录落仓库辅助表（V03-0.5 的 aux 端口，bucket `entry`，key=entry_id）：`{conversation_id, messages: {request_id: {message_id, text_hash}}}`——消息级幂等 + 同键不同内容显式冲突（OPERATION_KEY_REUSED）。
4. `domain/conversation/models.py`：新增 `MESSAGE_NOT_REQUESTED`——「未发起过调用」与「失败」区分。
5. 消息 ID 由 `(conversation_id, request_id)` 确定性派生：存储崩溃窗口内重试不产生重复消息（先读后写 + 主键兜底）。
6. REST：`POST /api/v2/entries`（mode=save_idea；send 模式明确拒绝并指向 V03-1.5）、`POST /conversations/{id}/author-messages`；`ConversationService.conversation()` 公开归属校验方法（跨项目 404 信封）。
7. 测试 `tests/v2/server/test_entry_reservation.py`（5 项）：三条想法同作品/讨论、重试不重复、重启后归属正确 + 跨 entry 隔离、同键冲突、send 模式拒绝、**保存想法零模型调用**（模型运行记录器）。

## 关键决定

1. **确定性作品身份代替「先写预约再建作品」**：预约记录必须引用已存在的项目（aux 表 FK），而「建作品→写预约」之间的崩溃窗口用随机 ID 会漏作品。确定性 ID 让重试天然落到同一作品，无需孤儿回收。
2. **预约记录放 aux 表而非对话库**：aux 在仓库 DB（与作品同源），`project_id` FK 天然满足；对话库存会话与消息。两库间的崩溃窗口由确定性消息 ID + 先读后写兜住，预约记录只存映射不存真相（消息真相在对话库）。
3. **`not_requested` 是一等消息状态**：前端可区分「想法」「失败」「完成」三种作者消息；后续「接着讨论」按 message_id 引用，不重复新增（V03-1.5）。
4. **send 模式显式拒绝**（ENTRY_MODE_UNSUPPORTED）：发送必须由作者显式授权后走 grant（计划 §6.2「发送模式明确授权后才启动」）；拒绝文案指向接着讨论，不做占位假入口。
5. 预约记录更新是整记录 upsert（last-write-wins）：单作者桌面场景可接受，记录并发写冲突的说明入构建笔记。
