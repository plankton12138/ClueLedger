# V03-5.2 构建笔记：正式稿前进时的三方合并与重叠选择

> 阶段开发记录；实现范围、待办与测试结果均对应记录时点。当前行为见[模块说明](../modules/README.md)，剩余缺口见[运行与验收状态](../release.md)。

状态：**已交付**（2026-10-18）。范围：副本期间正式稿前进时，「修改完成」按
三方合并处理——干净叠加自动发布，重叠报冲突并由作者逐处选择，副本永不丢。

## 场景与退出条件

副本打开期间，另一条路径（另一页、导入、恢复）推进了正式稿。计划要求的
退出条件：**不自动丢副本；只因无关章变化不阻塞完成**。

三样东西配合达成：

- **三方合并引擎**（`domain/manuscript/merge.py`）：base（作者读到的那一版）
  / ours（副本草稿）/ theirs（当前正式稿），按段落粒度叠加。
- **finish 按当前 head 求值**：合并稿是叠在最新正式稿上的，各命令的
  `expected_chapter_base` 就是当前基础。干净 → 直接发布；求值到提交之间
  若有新保存，领域检查与提交层逐对象 CAS 仍会显式冲突。
- **重叠必须逐处选择**：409 报告带每处冲突的 base/ours/theirs 三段原文；
  作者在 finish 请求里带 `merge_choices` 逐处表态。

## 关键判断

**1. 干净合并自动发布，不问作者。**
作者改第一段、正式稿改第三段——硬拦下来等于「任何一处无关修改挡住整轮
完成」。合并是机械的段落叠加，判断是字符串比较（不做语义推断），两边都
保留。响应里的 `merged_chapters` 如实报告哪些章是合并后发布的——作者有权
知道「我完成的不只是我写的」。走过合并但没有任何可发布内容的章（作者没
真改）不在其中。

**2. 「保留我的版本」必须是显式选择，改草稿到不了这一步。**
这是实现中发现的设计缺口：冲突后作者把草稿改成自己想要的版本再完成，
**仍会冲突**——草稿与正式稿在同一处还是不同。所以计划里的「重叠具体选择」
落成 finish 的 `merge_choices` 参数（`{chapter_id, conflict: 序号, choice:
"ours"|"theirs"}`），序号即 409 报告里的冲突顺序。漏选、错号（期间又有新
保存导致冲突集变化）都会带着**重新计算的报告**再次 409——不猜作者想选哪边。
选择写进操作记录的 refs（终态持久化）：版本历史里读得出这次合并在哪处取
了哪边。

**3. 冲突区域 = 两侧改动区间的并集，两侧效果按完整区间计算。**
一侧改 [1,3)、另一侧改 [2,4) 时，报告的是 [1,4) 的三段事实——作者看到的
不是片段，而是「这片区域两人各改成了什么样」。

**4. 贴边插入不算撞车。**
在别人改写区的紧外侧插入（章首加序章、章尾加结尾），两边都成立；插进
对方改写区**内部**才冲突。这个边界由区间相交规则显式定义：实质区间严格
重叠才算同区，点区间（插入）只在**严格内部**并入。

## 行为变化（相对 5.1）

同章前进的硬冲突场景改走合并：双方各自重写全章 → `EDIT_SESSION_MERGE_
CONFLICT`（原先 `MANUSCRIPT_BASE_CONFLICT`）。两个旧用例的断言已随语义
更新——它们原本证明的「不覆盖、保副本」在新行为下依然成立，且覆盖面
更宽（能合并的不拦，拦下来的必有真重叠）。`test_first_save_binds_the_
version_the_author_read` 由此获得更强的回归形态：若 base 绑错（绑成正式
稿新版本），作者的改动会把正式稿的改动冲掉——干净合并测试里断言正式稿
的新段落原样存在，即证明 base 没绑错。

## 验证证据

- 合并引擎 `tests/v2/manuscript/test_merge.py` **17 项**：无变化、单侧变化、
  不相交叠加、同改同果、重叠报冲突、删改冲突、双方同删、贴边插入不撞、
  内部插入冲突、同点插入、部分重叠、整章重写、冲突文本可读、空输入。
- 接线 `tests/v2/edit_sessions/` **24 项**（含 5.1 的 17 项）：干净合并一次
  commit 且两边保留、重叠 409 三段事实且 head 不动、选择 ours/theirs 各自
  生效、选择进操作记录 refs、部分选择重新 409、一章两处冲突分别选择、
  作者未改的章不被重复发布（摘要修订号不动）、无关章前进不阻塞。
- 全量 `uv run pytest -q` **1743 passed**；`ruff` / `mypy` 干净。

## 留白

1. **合并预览接口未做**：冲突报告在 409 里，作者点「完成」才看到。做一个
   只读的合并预览（进完成前就能看）属于界面工作，随 V03-8.6 默认壳。
2. **语义级合并不判断**：「这两段意思是否相同」交给作者；引擎只回答文本
   是否相同。
3. **删除+紧邻插入**（一方删段、另一方在其后加段）当前按冲突处理——保守
   方向，真实使用若嫌吵再放宽。
4. **`narrative.chapter` 与稿件章的对应**仍由调用方显式给出（V03-4.7 的
   口径），本刀不涉及。
