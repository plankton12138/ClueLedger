# V03-0.4 切断旧自动模型链路

关键词：AnalysisDispatcher 隔离、确定性投影、事件流保留、旧队列分类报告、作者档案注入切断

## 目标与结果

风险表第一条（作者一次保存被夹带另一项模型功能）的根治：0.3 装配不再有自动模型调度。交付：

1. 新增 `application/workflows/event_projection.py`：`CountingProjectionSink`——确定性投影消费端，事件照常发布标记（Outbox 不积压、历史可回看），但**不创建任何 Job、不调用任何模型**；按事件类型计数、按 event_id 去重。
2. `V2Runtime` 装配切换：Outbox 订阅者由 `AnalysisDispatcher` 改为投影端；`prepare_analysis_jobs`（分析→风格观察下游派发）删除，替换为 `classify_legacy_auto_jobs`（旧自动队列分类报告：数量/类型/状态，可派发的一律 `historical_paused`，分类详情随 `job.paused` 事件入库，每 Job 只分类一次）+ `legacy_auto_report` 只读快照；worker_loop 的 `analysis_pending` 自动派发分支移除。
3. 作者档案注入切断：`ContextBuilder` 不再把作者模型偏好/样例注入任务背景（`author_preferences`/`author_examples` 恒空）；`AuthorProfileQueries` 只读路径保留（历史数据可回看），本书约定（V03-4.1）是显式替代路径。
4. 文档：`analysis_dispatch.py` / `manual_edit.py` docstring 标注 0.3 装配状态（类保留作单元历史回归）。

## 关键决定

1. **事件流本身保留**：投影端照常 `mark_published`——切断的是模型调度不是事件流（执行指导 §4.4）；重启补偿（未发布事件重投）语义不变，既有重启恢复测试改造后仍覆盖该契约。
2. **分类报告落点**：可派发旧任务的分类详情走 `job.paused` 事件负载（复用 V03-0.3 的 pause 端口）；曾尝试对每条旧任务追加 `job.legacy_classified` 事件，被 `append_event` 的代际栅栏拦下（只允许 running 任务）——栅栏是正确的硬约束，改为不绕行：终态旧任务原样保留，计数由 `legacy_auto_report` 查询。
3. **`LEGACY_AUTO_JOB_TYPES = ("manuscript.analysis", "style_observer")`**：作者显式启动的 auditor 等任务（带凭据）不在分类范围，走正常派发——分类只针对旧自动链类型。
4. **作者档案字段保留不删**：`ContextPackage.author_preferences/author_examples` 有默认值，旧 Job payload 仍可校验；tau_runner 的 preferences/examples 提示块随空列表自然消失，不改 runner。
5. 与计划无偏差；`AnalysisDispatcher` 类与 `tests/v2/manuscript` 的去重/补偿单测作为历史回归保留（执行指导 §2.3）。

## Agent 设计经验（四透镜）

1. 错误消息：分类详情带 `legacy_auto/job_type/why` 三要素式说明——回看旧任务时能回答「为什么停的、能不能继续」。
2. 硬约束：`append_event` 代际栅档阻止了「往终态任务写事件」的捷径；投影端无写端口（只有计数），物理上不可能建 Job。
3. 泄压阀：合法空结果（无旧任务→空报告）与「有旧任务→暂停+计数」分流；投影端对未知事件类型计数为 unknown 不抛错。
4. 可观测性：`event_projection.report()` 与 `legacy_auto_report()` 两个只读快照，退出证据（重启零调用、旧任务分类）可直接断言。

## 踩坑与留白

- 坑：`append_event` 的 generation 栅栏（只允许 running + 同代）对分类事件不可用——没有绕行，分类信息改走 pause 事件；这验证了「事件端口按执行期语义设防」的设计。
- 坑：`test_restart_does_not_replay_auto_style_observation` 原依赖「重启后 loop 自动建分析 Job」制造旧队列；切断后改为直接落库两条遗留任务（更贴近升级前数据形态）。
- 留白 1：投影端的计数是进程内快照（Outbox 的 mark_published 才是持久去重）；跨重启的累计计数不承诺，报告以查询为准。
- 留白 2：`style_observer` 角色代码路径（agents.py 分支、StyleContextBuilder）仍存在但 API 层已拒绝签发凭据（V03-0.3）；死代码清理随 V03-8 旧入口退役统一做，不零敲碎打。
- 留白 3：作者模型读取入口（`/author-model/*` REST）本版保留只读；退役在 V03-8.6 API 调用矩阵销号。
