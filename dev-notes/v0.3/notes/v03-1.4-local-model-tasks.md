# V03-1.4 本地模型真实阶段

> 阶段开发记录；实现范围、待办与测试结果均对应记录时点。当前行为见[模块说明](../modules/README.md)，剩余缺口见[运行与验收状态](../release.md)。

关键词：local-model-tasks、任务记录、幂等、下载完成≠测试通过、阶段即事实、重检、取消范围、pull 收敛

## 目标与结果

模型接入合同（development-plan.md §6.5）中「下载/加载/测试协调」「取消」「恢复」三行的后端与前端闭环。交付：

1. `application/services/local_model_service.py`：应用管理的本地模型任务记录。
   - `LocalModelTask`：task_id / request_id / fingerprint / action（download|test）/ model / provider / base_url / state / stage / percent / detail / error——**不含任何凭据字段**（连接快照白名单）。
   - 状态机 `queued → running → succeeded | failed | stopped`；`stage_for_frame` 把 Ollama pull 帧（pulling/downloading/verifying/writing/removing）映射为中文阶段（准备中/下载中/校验中/写入清单/清理）；`percent_for_frame` 缺任一数或 total≤0 返回 **None**——阶段无进度数时只显示阶段。
   - `LocalModelTaskService.create()`：request_id 幂等（同 id 同指纹回放原任务、同 id 不同内容 `OPERATION_KEY_REUSED`）+ 同 model+action 运行中任务复用（Ollama pull 本就串行）；`cancel()` 终态抛 `LOCAL_MODEL_TASK_CONFLICT`，运行中如实回报取消范围。
2. `server/rest.py` 四端点：`POST /api/local-model-tasks`（201 新建 / 200 重放或复用）、`GET /{id}`（404 提示「重启后记录清零」）、`POST /{id}/cancel`（KeyError→404、ViolationError→409）、`GET ?active=true`（缺参数 422）——读路径统一**重检实际状态**：服务不可达 → failed 环境归因；模型已在 tags → succeeded 升级。原 `POST /api/ollama/pull` 流式端点**删除收敛**。
3. 真实执行器装配（`_build_local_model_task_service`）：download 适配 `OllamaClient.pull`（base_url 剥 `/v1` 还原服务根）；test 动作经已保存连接 `build_provider` + `stream_response` 跑最小推理（120s 超时；`AssistantErrorEvent` → `LOCAL_MODEL_TEST_PROVIDER_ERROR` 环境归因）。
4. 前端：`api/localModels.ts`（任务客户端 + `isTerminalState` + `taskNotice` 纯函数）；`LocalModelCard.tsx` 改造——流式读帧改为 1s 轮询任务记录（sessionRef 会话号使旧轮询失效），挂载时 `?active=true` 恢复进行中任务，卸载只停轮询不取消服务端任务；percent 为 null 显示「—」；下载成功后引导「测试调用」。清理 `rest.ts`（pullOllamaModel）与 `state/ollama.ts`（流解析三函数）。

## 关键决定

1. **下载完成 ≠ 加载完成 ≠ 测试通过**落在三处：服务端成功 detail 原文写明；前端 `taskNotice` 下载成功文案重复提醒；UI 在成功后给出「测试调用」按钮而非直接宣称可用。Ollama 无独立加载 API——加载即首次推理，由 test 动作隐含覆盖。
2. **任务记录进程内存储**：对齐 JobStore 先例，重启即清零，恢复靠读路径重检兜底（`?active=true` 返回前先 tags 探测）。跨重启持久化归 V03-8 备份阶段；`interrupted` 态（服务重启时正在跑的任务）不在本任务。
3. **旧 pull 端点删除而非保留双轨**：进度流无法证明「离开后恢复下载状态」，两套进度口径会让前端回到不可恢复的旧路。API 清单（§2 表）同步收敛该行。
4. **「调用测试」仅做本地模型 test 动作**：云连接 `POST /api/providers/test` 的 connection_id/revision 演进登记留白，随 V03-2 收口。
5. **前端轮询而非订阅**：任务记录是唯一事实源，1s 间隔回读终态即停；轮询失败（服务重启清记录）显示归因并停止，不静默重试。
6. 与计划无偏差。取消语义（仅限本应用发起、Ollama 侧拉取可续传）按合同原文落 detail 文案。

## 实现问题与未完成项

- 坑 1（Agent 设计层）：create 后立即 cancel 时后台任务尚未起跑，协程的取消分支没机会落账——cancel 兜底在 `await running` 后检查「仍非终态」则直接写 stopped，取消语义单点收口；竞态不是靠调用方 sleep 规避的。
- 坑 2（测试基建）：TestClient 每请求独立事件循环会杀后台 asyncio 任务——REST 测试统一 `with client:` 长驻 portal（复用既有踩坑结论）；进度断言用 `_wait_terminal` 轮询而非固定 sleep。
- 留白 1：`POST /api/providers/test` 云连接演进（connection_id/revision + verified 更新规则）随 V03-2 收口。
- 留白 2：任务记录跨重启持久化与 `interrupted` 态归 V03-8（备份/恢复时模型任务恢复为中断）。
- 留白 3：Publisher 式后台发布循环未接 lifespan——服务装配在路由工厂内即时创建，无优雅停机；单任务规模下可接受。
