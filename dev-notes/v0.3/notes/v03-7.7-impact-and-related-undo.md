# V03-7.7 影响高亮与整体操作关联撤销

> 交付日期：2026-10-19。计划 M10 §10、M11；执行指导 §11.5。

## 为什么做这个

「这次整体调整到底改了什么」不能靠模型复述，也不能用章节数或相似度打分。作者需要
的是**版本差异**：哪一章的哪些字变了、哪条账本哪个字段变了、之后有没有人（作者自己）
又改过。撤销同理：不能把整章替换回旧文本，那样会覆盖作者后来独立写下的内容。

这一版把两件事绑在同一条事实上：

- 影响高亮只读 Commit 差异，范围来自操作记录，不接受调用方自定义；
- 撤销沿操作记录走三方逆向：当前仍等于操作后版本才直接恢复；之后不重叠的修改
  用文本合并保留；重叠或账本字段冲突逐处选择；未覆盖全部冲突时零写入。

## 做了什么

### 影响查询 `application/queries/impact.py`

`GET /api/v2/projects/{id}/operations/{operation_id}/impact`：

- **章节**：操作前/后文本的字符级差异统计（hunk 数、增删字符数），以及操作后到
  当前 head 是否又被改过；没有实际文本差异的章不列出。
- **账本**：操作前/后条目内容里实际变化的字段名、前后 revision、之后是否被独立修改。
- **高亮**：`highlights[]` 每条带 `basis: "version_diff"`；响应 `note` 明确
  「不代表修订完成、质量分数或嫌疑概率」。
- **继续创作**：本次实际改过的章、是否有后续修改、是否有未结束副本。
- **关联采用**：基于这次操作采用建议产生的独立提交（见下）。

### 因果关联 `application/services/revision_links.py`

- 采用账本候选时可带 `source_operation_id`；服务端先核对操作记录真实存在，再把
  `commit_id / request_id / item_ids / 时间` 记进 `revision_links` 辅助表。
- 这是「谁引发了谁」的记录，不复制账本内容，也不把关联提交的内容混进原操作差异。
- 影响查询与撤销预览都读同一份链接。

### 关联撤销（`undo_service` 扩展）

- 撤销预览在原有「操作前/后/当前」账本行之外，加入**关联采用**里被修改过的条目：
  当前仍等于采用后版本 → 默认恢复；之后被独立改过 → 进入冲突选择。
- 关联采用**新建**的条目不能在撤销里删除（本版没有删除账本的操作），预览里以
  `skipped_created` 报告，不阻塞原操作撤销，也不假装已恢复。
- 原有的正文 + 同 Commit 账本一起恢复、预览 token、逐项 `restore/keep` 全部复用。

### 前端

- `api/impact.ts` + `OperationFollowups`：操作后显示「本次影响」——改了几章、几条账本、
  每章增删字符数、之后是否又改过、关联采用次数，以及「只表示版本差异」的说明。

## 验证

- 接口 6 项：影响只报实际差异（章/账本/高亮依据）、后续保存后标记 `has_later_changes`、
  撤销同时恢复正文与账本、账本后来独立修改时 `keep` 保留、关联采用被报告且新建条目不删除、
  未知 `source_operation_id` 返回 404。
- 前端 1 项：影响客户端契约。
- 质量门：后端全量与前端 `vitest`/`npm run build` 见 `dev-notes/v0.3/README.md`。

## 已知留白（明确归属）

1. **关联采用目前只「报告 + 可恢复被修改条目」**：建议采用走的是新建条目，而本版
   不删除账本，所以新建的关联条目只能报告、不能随撤销删除；这与 V03-4.6「新建条目
   阻断撤销」的口径一致。
2. **影响统计是字符级增删数**，不是可视化 diff；正文差异的逐段视图仍由修改副本/
   版本历史承担。
3. **高亮不进入编辑器正文**：目前只在操作后的「本次影响」面板列出；正文内联高亮
   随整体执行界面阶段补齐。
4. 关联采用要求调用方显式传 `source_operation_id`；模型/前端自动带上它的入口随
   整体执行界面（谁发起采用）补齐。

## Agent 设计经验

- **影响必须是差异，不是评价**：一旦输出「改动比例/完整度」，界面就会把它读成质量
  分数。只给 hunk 数与增删字符数，并把 `basis` 写进每一条，读法就不会跑偏。
- **范围从记录回读**：影响范围不接客户端参数，避免「我传了什么就显示什么」；操作记录
  与实际 Commit 差异是唯一来源。
- **撤销要保护「后来」**：三方逆向的价值不在恢复旧值，而在识别「当前已经不是操作后
  的样子」；这时必须让作者选，而不是替他决定。
- **因果关联不等于合并撤销**：把关联提交单独记录下来，比把它们的内容混进原操作更
  诚实——哪些能一起恢复、哪些只能报告，响应里分得清。
