# V03-1.6 执行日志基础

> 阶段开发记录；实现范围、待办与测试结果均对应记录时点。当前行为见[模块说明](../modules/README.md)，剩余缺口见[运行与验收状态](../release.md)。

关键词：ExecutionLog、ExecutionEvent、append_once、after_sequence、execution-events、SSE、task/attempt、执行日志、模型任务生命周期

## 目标与结果

M13「作者能看见任务实际做了什么」的第一块地基：为真实普通对话调用建立公共执行日志——历史分页（`GET /api/v2/projects/{id}/execution-events`）与实时 SSE（`/execution-events/stream`）共用同一作品游标与事件 ID 空间，断线补齐 = 从上次游标重新分页。交付：

1. `domain/execution_log.py`：`ExecutionEvent`（M13 冻结字段）+ `VersionedRef`；`to_payload()` 白名单序列化（字段全集固定，summary 是摘要不是内容回放）。
2. `application/ports/execution_log.py`：`ExecutionLog` 协议（append_once / page / subscribe）+ `LogPage`（next_cursor=None 表示没有更多）。
3. `infrastructure/execution_log.py`：内存 + SQLite 双后端（表 `execution_events`，`UNIQUE(project_id, source_event_id)` 兜底，task_id/event_type 落真实列支撑筛选）。
4. `ConversationService` 可选注入 `execution_log`，在轮次生命周期四点投影事件；默认 None，既有装配与旧测试零改动。
5. `interfaces/api/execution_log.py`：历史分页（after_sequence / limit≤200 / task_id / type 筛选）+ SSE 流（游标轮询 + 心跳 + tail=0 快照，照抄对话 SSE 形状）；未知项目 404 信封。
6. 能力公布：`execution_events` draft → implemented（基础范围）。

## 关键决定

1. **task/attempt 用天然映射，不建新任务模型**：`task_id = chat-{conversation_id}`（对话任务通道），`attempt_id = turn_id`（每次轮次 = 一次尝试）。重试本就生成新 turn_id（带 retry_of 链接），「停止与重试尝试分开」的 M13 验收由身份设计天然满足，而不是靠事件层做对账。
2. **事件最小集对齐计划 §6.3 命名**：`model_task.started/completed/failed/stopped`。普通对话 runner 不公开推理过程 → 只有生命周期事件，这正是「无过程支持如实显示」的实现方式：不猜测、不伪造过程事件，事件仍真实存在。
3. **增量建表，不走 schema 迁移**（与计划偏差）：guide §3.7 给了检查点式迁移模板（migration 6 = 执行日志表），但 as-built 先例（`SqliteConversationStore`、`SqliteJobStore`）是附属表 `CREATE TABLE IF NOT EXISTS` 独立建表、不触碰 Repository schema 版本。执行日志是附属数据不是仓库事实，沿用先例；迁移模板留给 V03-8 备份/恢复统一盘点时再裁。
4. **发射失败不中断写作流**：`_log_event` 吞异常并打 stderr 三要素（where/why/fix）——日志是观测侧通道，它的故障不能反噬主链路；这与既有「落盘 IO 故障 stderr 告警」的泄压阀约定一致。
5. **幂等三保险**：source_event_id 确定性派生 `{turn_id}:{phase}`；`append_once` 按 (project, source) 去重；SQLite 再加 `UNIQUE(project_id, source_event_id)` 与 `UNIQUE(event_id)` 兜底。崩溃重放同源事件不会产生第二条。
6. **completed/stopped 只在 settle 真正收束时发射**：`settle_turn` 返回 False（已是终态）不发事件——取消后 runner 迟到返回不会在 stopped 之上再叠一条 completed。
7. 计划 `GET /execution-events` 的响应取 `{events, next_cursor}` 形状；`type` 筛选参数对齐计划表头命名（Python 侧用 `event_type` + Query alias）。

## 实现问题与未完成项

- 坑 1（typing）：Protocol 里把 `subscribe` 声明成 `async def -> AsyncIterator` 会让 mypy 期待协程返回——async generator 函数调用结果是迭代器不是协程。协议应声明为同步方法返回 `AsyncIterator[T]`，实现保持 `async def` + `yield`。
- 坑 2：`@dataclass(frozen=True, slots=True)` 实例没有 `__dict__`——带序号复制事件必须用 `dataclasses.replace`。
- 留白 1：前端日志面板（用户裁决后置）——API 与 SSE 已就绪，消费端后续接线。
- 留白 2：重启恢复 `mark_interrupted` 不发射事件（中断尝试在日志里缺一条终态）；V03-8 恢复任务统一处理。
- 留白 3：`model.process.delta` 公开过程通道未实现（无模型能力来源）；`call_id/parent_call_id` 字段已冻结但普通对话不填，待模型过程流与多调用编排时启用。
- 留白 4：Agent 任务（draft/audit 等 Job）尚未接入执行日志——本任务只覆盖普通对话通道；Job 通道的事件投影待任务卡阶段统一接。
