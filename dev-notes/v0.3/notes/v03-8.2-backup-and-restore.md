# V03-8.2 备份预览与同作品恢复

> 交付日期：2026-10-19。计划 §6.5 补充合同、§8.2；执行指导 §12.1。

## 为什么做这个，以及中途改道的原因

最初按「恢复 = 把包导入新作品」实现，测试立刻撞墙：`REPO_INTEGRITY_ERROR`
——artifact ID 归属**创建它的项目**，同库内把 ID 搬到另一个项目会被仓库不变体拒绝。
这不是缺陷，是不变量在干活（跨项目引用本就必须走关系边）。领域层那条往返测试之所以
通过，是因为它用了**另一个仓库实例**，那不是产品路径（用户只有一个库）。

于是把恢复改成产品上真正需要的形态：**把这个作品恢复到备份时的版本**。这与撤销的
区别必须讲清楚：

- 撤销按**操作记录**恢复操作前状态（谁改的、改了什么，有据可查）；
- 备份恢复按**包内容**恢复（备份那一刻的正文与账本）。

后者天然是「覆盖当前内容」，所以绝不能静默执行。

## 做了什么

### 备份预览 `GET /projects/{id}/backup`（只读）

按当前 head 构建导出包，回报清单、计数、整包指纹，以及**覆盖范围声明**：进包的
（正文章节与段落清单、账本条目、约定与结构、依赖边）与不进包的（副本与快照、覆盖
台账/任务/暂存、操作记录与候选、执行日志、凭据与模型连接）——每条排除项都写清它在
哪里、为什么不在包里。下载 zip 仍走既有 `GET /projects/{id}/export`。

### 同作品恢复 `POST /projects/{id}/restore`

- 上传导出 zip → 解包（拒绝目录穿越条目、缺 manifest）→ 校验整包哈希；
- 与当前 head **逐字比较**：相同即合法空结果（不产生版本），不同则进入差异集；
- 未确认 ⇒ 409 `EXPORT_RESTORE_CONFLICT`，列出会被改写的章（含当前章基础）与账本
  字段（`changed_fields`），`choices=["confirm_overwrite","cancel"]`；
- 确认后 ⇒ 正文命令（`save_full_text`，CAS 用当前章基础）+ 账本变化走
  `publish_commands` 进**同一个 Commit**，操作 ID 绑定整包指纹与确认状态；
- 包里有、当前没有的对象 ⇒ `EXPORT_RESTORE_NEW_OBJECT` 拒绝：恢复不新建条目、
  不做 ID 重映射。

### 导出器补强 `unzip_package`

与 `zip_package` 对称，从字节解包；拒绝非 zip、缺 manifest、`../` 与绝对路径条目。

## 验证

- 接口 8 项：预览清单与覆盖范围；无差异为合法空结果；未确认 409 且列出差异、
  确认不改写；确认后正文与账本一起恢复；恢复后再恢复仍是空结果；篡改包 400、
  坏 base64 400；目录穿越 400；包内对象缺失时报 `EXPORT_RESTORE_NEW_OBJECT`；
  备份包不含凭据类字面量（结构性保证 + 字节级断言）。
- 质量门：后端全量与静态检查见 `dev-notes/v0.3/README.md`。

## 已知留白（明确归属）

1. **恢复到新作品未提供**：需要 artifact ID 重映射表（新旧 ID 对照、引用边改写、
   幂等键绑定），0.3 不做；备份用途是同作品恢复。既有 `apply_exported_package` 仍
   面向「另一个仓库实例的空项目」，领域级往返测试继续覆盖它。
2. **恢复不做三方合并**：确认即按包内容覆盖当前内容；要「保留后来的修改」请用撤销
   （有逐处 restore/keep）。二者目的不同，不混在一个入口里。
3. **覆盖核对清单未全自动**：计划要求核对副本/操作/建议/日志，而它们不在包里（见
   覆盖范围声明），因此核对结论以「这些不在备份范围」为准，不是逐项 diff。
4. **凭据排除是结构性保证**：连接与凭据在服务器配置与 OS 凭据存储，不在仓库快照里；
   真凭据环境下的取证在 V03-8.7。

## Agent 设计经验

- **先让不变体说话，再决定产品形态**：跨项目搬运被拒绝后，最初的正确反应不是「绕过
  校验」，而是问「用户真正要的是什么」——答案通常不是我们假设的那个操作。
- **覆盖当前内容的操作必须自带确认**：备份恢复比普通保存更危险（它按旧内容盖新内容），
  所以差异必须先摊开；这一步的成本远低于一次误覆盖。
- **合法空结果也是结果**：内容一致时返回 `no_change` 而不是报错，重复恢复才不会变成
  噪音；测试专门守这条。
