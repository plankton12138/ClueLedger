# 执行日志

执行日志用于回看已经接入的任务、模型轮次与运行事件。它与对话消息流、作品版本变更事件分工独立；日志记录不代替任务状态，也不代表作品已经发布。

## 存储与读取

- 事件按作品与来源事件编号幂等写入，事件 ID 全局唯一；序号在作品内递增，不跨作品比较。
- `GET /api/v2/execution-events` 支持作品范围的游标分页，`next_cursor=None` 表示已取尽。
- `GET /api/v2/execution-events/stream` 提供实时流。`tail=0` 排空当前积压后关闭，积压跨页时继续读取；`tail>=1` 持续等待。
- 心跳是注释帧，只表明连接存活；它不代表执行进度，也不携带游标。
- 历史分页与实时流共享序号和事件身份，调用方从已收到的最后一个事件继续补齐。

停止或继续仍调用相应任务命令，读取日志不修改任务。事件输出使用允许公开的字段，凭据不进入日志。

## 当前限制

- 前端日志面板尚未接通，因此后端接口可用不能写成作者已能在写作台完整回看日志。
- 并非所有 Job 过程都已投影到执行日志；摘要任务等仍有独立事件序列。
- `mark_interrupted` 不发射执行日志事件；恢复状态通过 `GET /api/v2/recovery` 查询。
- 无限流的现有自动化证据主要在生成器层验证；缓冲式测试客户端不能证明真实浏览器的持续接收行为。

性能目标在 `application/capabilities.py`；历史压力结果属于对应测试环境，不作为当前机器的实时性能承诺。

## 代码位置

`domain/execution_log.py` 定义事件；`infrastructure/execution_log.py` 提供内存与数据库实现；`interfaces/api/execution_log.py` 提供分页、流与 `event_stream`。
