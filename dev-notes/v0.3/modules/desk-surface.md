# 写作台工作区

写作台让作者在同一工作区阅读正文、记录想法、讨论与维护故事账本。默认入口是写作台；异步消息、候选与任务结果不自动抢占作者正在阅读的主区。

## 布局与导航

- 左侧为章节、想法与讨论及临时视图，中间为正文和输入框，右侧为账本、图谱概要、证据核对与操作结果。
- 宽度 ≥1280 时显示三部分；1024–1279 时左侧折叠为抽屉；<1024 时两侧均为抽屉且互斥打开。Esc 或遮罩可关闭抽屉。
- 主区一次显示一种视图；导航由 `state/desk.ts` 的状态函数控制，数据事件不修改主区或阅读位置。
- 「整体调整」是正文头部的一个文字入口，展开为主区视图：开任务（预算）、逐章勾选范围、执行一轮、继续、停止与发布。预算「已用/上限」、覆盖与暂存计数都来自服务端；预算用完显示为可继续的等待，不是错误。
- 阅读位置按作品、章节、稿件来源和副本身份区分保存；切换作品时不带入旧作品的操作回执。
- 专注写作收起两侧，保留正文与输入框。进入写作台时自动收起兼容对话栏，作者可手动打开。

正文使用 18px 字号、32px 行高与最大 44em 行宽；输入框、讨论和账本使用 14px。图谱提供文字目录与键盘路径，来源定位失败在详情中显示。

## 输入与数据

输入框可先保存想法，草稿在浏览器保存；“接着讨论”由作者显式启动模型。Ctrl+Enter 保存，组合输入期间不提交。

正文、账本与版本来自服务端回读，浏览器保存草稿、阅读位置和布局等界面状态。正文发布走统一管线；无模型记录和副本暂存不等于发布正式正文。开发聊天默认模拟，`?chatMock=0` 使用真实 API。

## 当前限制

- 执行日志面板尚未接通后端接口。
- 整体调整执行是同步请求：执行中无法取消，也没有逐章进度；长任务的异步执行与进度未做。
- 旧变更影响、计划与逐段差异详情不再由兼容页面渲染；版本历史列表与对应 API 的能力需分别判断。
- 浏览器真实 200% 缩放与真实中文输入法仍缺专门验收证据；现有自动走查使用等价视口和合成组合事件。
