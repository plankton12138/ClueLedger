# 写作台工作区

写作台是产品的唯一主视图：作者在同一工作区阅读正文、记录想法、讨论与维护故事账本。入口即写作台，无导航栏与状态栏，顶栏只保留作品名、模型与设置。异步消息、候选与任务结果不自动抢占作者正在阅读的主区。

## 布局与导航

- 宽屏（≥1280）三部分：左栏章节目录与想法列表，中间正文与唯一输入框，右缘一排窄标记。中屏（1024–1279）左栏折叠为抽屉；小屏（<1024）主区优先，左栏走抽屉，右栏标记改为正文头部的「侧栏」入口。
- 左栏默认只展开「章节目录」，头部只有「导入正文」；「想法与讨论」默认折叠为区块头与条数，点击展开，展开状态不持久化（每次进入回到折叠）。
- 右栏默认不渲染面板，只在稿纸右缘露出窄标记条。账本、图谱、修订三枚标记常驻；后续状态与操作结果有内容才出现，空列表不占标记。点开标记沿右侧滑出抽屉，Esc 或遮罩关闭，关闭后不留痕迹。
- 稿纸默认只读。进入编辑的唯一方式是正文头部「手工修改」；进入后头部给出「修改中 · 已保存 #n」标记与暂存返回 / 完成修改 / 放弃，自动保存与序号冲突提示沿用工作副本逻辑。阅读态头部另有「历史」与「证据核对」两个文字入口，二者同样进抽屉。
- 主区一次只显示一种视图，导航由 `state/desk.ts` 的状态函数控制，数据事件不修改主区或阅读位置；阅读位置按作品、章节、稿件来源与副本身份四种键保存；切换作品时不带入旧作品的操作回执。
- 候选采用链路在写作台内闭环：讨论区渲染「待审阅候选」卡，点「打开审阅」把候选审阅展开为主区视图，采用成功后回到受影响正文，放弃或定位不到章时回原视图。
- 「整体调整」入口在右缘标记中，展开为抽屉内的面板：开任务（预算）、逐章勾选范围、执行一轮、继续、停止与发布。预算「已用/上限」、覆盖与暂存计数都来自服务端；预算用完显示为可继续的等待，不是错误。

正文使用 18px 字号、32px 行高与最大 44em 行宽；输入框、讨论和账本使用 14px。图谱提供文字目录与键盘路径，来源定位失败在详情中显示。

## 输入与数据

输入框是写作台唯一的文字入口：先保存想法，草稿在浏览器保存；「接着讨论」引用一条已保存想法显式启动模型，仅在真实服务下可用，模拟模式禁用并提示改用 `?chatMock=0`。Ctrl+Enter 保存，组合输入期间不提交。图谱的「加入讨论」把选中对象作为可见引用追加到草稿，未保存前不产生领域写入。

正文、账本与版本来自服务端回读，浏览器保存草稿、阅读位置和布局等界面状态。正文发布走统一管线；无模型记录和副本暂存不等于发布正式正文。开发聊天默认模拟，`?chatMock=0` 使用真实 API。

## 当前限制

- 执行日志面板尚未接通后端接口。
- 整体调整执行是同步请求：执行中无法取消，也没有逐章进度；长任务的异步执行与进度未做。
- 写作台没有自由对话输入框；向模型发起的轮次经「想法 → 接着讨论」触发，模拟模式下该入口不可用，因此候选链路的浏览器级验证需真实模型或服务端剧本配合。
- 旧变更影响、计划与逐段差异详情不再由兼容页面渲染；版本历史列表与对应 API 的能力需分别判断。
- 浏览器真实 200% 缩放与真实中文输入法仍缺专门验收证据；现有自动走查使用等价视口和合成组合事件。
