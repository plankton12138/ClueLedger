## 1. 交付目标

1. 每部作品有一份模型自维护的 `STRUCTURE.md`（作品根目录真实文件、Git 版本化、自由格式 Markdown）：开头铁律段 + 路线 + 章节骨架 + 模块索引。作者只读。
2. **正文台账由事实层维护**：事务层在每次入档时自动记录每章已入档修订号与状态，模型只读不可写、不进入 `STRUCTURE.md`；这是系统的「git status」，为确定性对账提供不依赖自由格式解析的事实基础。
3. 每次起草、修改请求注入装配：铁律常驻 + 结构全文常驻 + `STYLE.md` 空占位 + 当次涉及的挂载模块按需注入 + 正文台账（只读事实）+ 必发生清单（模型同回合自列，不落盘）。
4. **装配层确定性对账（第一道防线）**：目标章号来自任务元数据（系统发起，非解析自由格式），与台账比对；目标章之前存在缺章即拦截改派或报警。
5. 章节入档事务扩展为三元原子提交：正文 + 结构文件更新 + 涉及模块更新，复用 v1.1 暂存闭环，可整体撤销；写作回合预期正文未产出按任务失败归因，任何部分不入档。
6. 感知区分：记账类更新静默；计划性变化（改点位、新增线、改铁律）在对话中单独一行说明。
7. 写后自查三层（必发生核对 / 铁律自查 / 读者认知提示）随起草同回合产出，概率性、如实标注「自查」；起草前强制对账流程作为第二道保险。
8. 空作品起步：设定卡确认后，模型起草第一版结构并自主创建首批模块（走 v0.8 既有创建挂载机制），经暂存确认入档。
9. 模块机制零改动：`library/modules.py` 及其前端流程维持 v0.8 形态。

完成标准不是「文件存在」，而是 UC-S01—UC-S05（见 M5）可从空作品连续走完，且对抗用例（风格指令挤压剧情、伪造「已写」标记）下护栏实测有效。

## 3. 模块计划

### M1 结构文件层

**为什么**

逐章对话推进缺乏全书工作记忆，跨章一致性靠上下文硬扛；而 v1.0.x 的教训是结构化 schema（节点、生命周期、三层认知）复杂且不产出悬疑。`AGENTS.md` 思路给出第三条路：文件是模型自己的工作记忆，表征由模型自选。

**设计**

- 位置与形态：作品根目录真实 `STRUCTURE.md`，自由格式 Markdown；随作品复制、导出并由作品 Git 记录（复用 `files.py` / `git.py` 路径）。
- 唯一结构约定：文件开头为**铁律段**（以固定标记起始，装配器据此切分常驻注入）。铁律是写作规则不是数据字段，条数不设死，首版约三行由起步对话生成。
- 生命周期：缺失视为空；起步对话确认设定卡后，模型起草第一版结构（含铁律、路线、骨架、模块索引）+ 自主创建首批模块（伏笔账、人物等，按书自选），产出为暂存变更，作者确认入档；此后随事务更新。
- 作者只读：侧栏新增结构只读页（复用 v1.1 只读渲染与页边风格），附「在对话里继续调整」；不提供编辑框。
- 外部编辑不设对照界面：装配前按磁盘现状如实注入；模型入档时自行整理外部改动并入本次暂存。
- 字数预算：结构全文设冻结上限；超限时入档事务要求模型先提交压缩版结构（压缩本身走暂存确认），不静默截断。

**主要落点**

- 新：`workspace/structure_document.py`（定位、铁律段切分、指纹、预算检查）。
- 修改：`agent.py`（结构读写工具接入暂存模式）、`story_candidate.py`（结构暂存载体）、前端结构只读页与侧栏入口。

**退出条件**

结构文件全程由模型产出与更新，链路内无编辑框；起步可从空作品生成第一版结构与首批模块；外部改动如实注入且入档可整理；预算超限触发压缩路径。

### M2 注入装配与护栏

**为什么**

实验证明：无注入时模型逐章只能靠上下文，一致性漂移；有注入但无护栏时，风格指令会把规定事件挤出章节（2026-11-03 实验中对话驱动版核心物件零出现）。装配解决「记得住」，护栏解决「不挤掉」。

**设计**

- 装配顺序（冻结为契约）：铁律 → 结构全文 → `STYLE.md`（本版空占位）→ 当次涉及模块 → 正文台账（只读事实）→ 必发生清单。
- **正文台账**：事实层数据，非模型可写文件；装配时只读注入并写进装配回执。台账与结构文件中任何「已写」标记冲突时以台账为准（此优先级写入装配契约与提示词）。
- **确定性对账（第一道防线，纯函数）**：目标章号来自任务元数据（系统发起写作任务时已知，不从自由格式解析），与台账比对：目标章之前存在缺章 → 拦截本次装配，默认改派最早缺章，作者明确跳过才放行并记录。逻辑可离线单测（2026-11-03 试验确立：被动注入台账模型不对账 0/3，确定性检查不可下放给模型）。
- 模块按需选择：按写作目标（目标章、涉及人物/伏笔）选择注入模块，复用 `module_assembly` 既有「读相关原文」行为；目标未知时注入模块索引，由模型在会话内按需读取。全量重注入实测随章节数平方增长（第 4 章即 16.4k prompt tokens），**按需选择为必需项而非优化项**。
- 必发生清单：最小试验证明自由格式下纯函数派生不可行（脚本无法可靠解析自选格式的骨架）。改为：模型在起草同回合自列本章必发生项，进装配回执显式展示给作者一眼可否决；写后脚本做宽松关键词机检（匹配不判失败、报相对偏差），清单不落盘。自列为空时如实说明并建议补骨架或模块，不猜。
- 装配快照进请求回执：实际注入了哪些层、哪些模块、清单条目，可核对。

**主要落点**

- 修改：`assembly.py`、`materials.py`（结构层注入位）、`module_assembly.py`（选择调用位）。
- 新：`workspace/structure_assembly.py`（确定性对账、台账注入与装配快照、宽松机检）。

**退出条件**

装配契约冻结且每次请求可核对回执；确定性对账与宽松机检可离线单测；未涉及的模块不注入；预算内装配产物稳定。

### M3 事务同步与感知区分

**为什么**

结构文件如果靠模型「记得更新」必然脱节；必须把同步绑定进落盘事务。同时作者不能被模型的每次记账打扰，也不能对计划变化被蒙在鼓里。

**设计**

- 暂存变更扩展：可携带结构文件前后文本与模块更新项（沿 v0.8 模块数据结构），与正文变更同组。
- **正文台账维护（事实层）**：台账记录于事务层（每章 → 已入档修订号），三元提交成功时自动追加、整体撤销时自动回退；模型无写入口，不占对话回合。起步前为空。
- **原子性兜底**：写作回合预期正文未产出（试验复现过「只交文件更新不交正文」且自查对幻觉正文自洽）→ 整个任务按失败归因，正文、结构、模块任何部分不入档；「预期产出缺失」与「自查缺失」同列为确定性失败归因。
- 章节入档（起草采用、修改确认、建章确认）走三元原子提交：正文 + `STRUCTURE.md` + 涉及模块；复用 v1.1 联合提交与整体撤销；基础修订过期规则不变。
- 感知区分在对话回显层实现：更新项分类为**记账**（伏笔标记已埋、章节状态更新——静默，仅入档回执可见）与**计划性变化**（改回收点位、新增叙事线、改铁律、删模块——单独一行说明，附「不同意，改回来」，改回走暂存闭环）。分类由模型在暂存时标注，装配层校验标注完整性。
- 结构更新的差异回显纳入 v1.1 差异三要素：改了什么、影响哪里（哪些章的骨架/点位随之移动）、基于哪个修订。

**主要落点**

- 修改：`story_changes.py`（三元提交）、`story_candidate.py`（分类标注）、对话回显事件（`tool_feedback.py` / `chat_stream.py`）。
- 前端：回显卡支持结构/模块差异段与计划性变化行。

**退出条件**

任何入档路径（起草采用、修改确认、建章）均产生结构同步，无「只入正文」路径；撤销整体回退三层；记账静默、计划性变化必有说明；过期暂存不可覆盖。

### M4 写后自查

**为什么**

放弃字段级机检换自由格式，代价是确定性校验降级为概率性自查。实验已验证模型对写明规则的遵守度，以及「照片出现太郑重、可能提前起疑」这类读者认知提示的可执行性。

**设计**

- 起草任务同回合产出三层自查，随候选进入对话：①必发生清单逐条定位核对；②铁律逐条检查；③读者认知提示（当前误读是否立住、有无提前起疑），必须给可执行的修改建议。
- **强制对账流程（第二道保险）**：起草提示词规定，收到写作目标第一步必须核对目标章与台账，发现更早章节缺正文不得写目标章、改为补缺（2026-11-03 试验：被动注入无效 0/3，强制流程 3/3）。系统侧确定性对账仍是主防线，此流程覆盖确定性检查之外的场景。自查必须先引用对账结果，防止对幻觉正文自洽（试验中出现过自查对不存在的正文逐条「核对通过」）。
- 界面如实标注「自查」（模型自检，非系统校验），不承诺无漏报；自查失败（模型未产出自查段）按任务失败归因，不静默跳过。
- 作者采纳建议 → 修改走 v1.1 暂存闭环 → 复检（仅对改动项）通过后入档；不采纳可直接入档，⚠ 不阻断。
- 自查提示词约束放任务意图与装配层，不硬编码业务规则；铁律内容本身来自结构文件，本层只定义「逐条自查」的流程。

**主要落点**

- 修改：`chapter_writing.py`（起草任务产出自查段）、前端自查结果卡（✓/⚠ 样式与复检交互）。
- 新：`prompts/` 下自查提示词模板（版本化）。

**退出条件**

起草候选必带三层自查；⚠ 建议可执行且采纳后走暂存闭环复检；不阻断入档；自查缺失如实报错。

### M5 验收与发布

**设计**

- 确定性矩阵：结构文件生命周期（起步生成 / 事务同步 / 预算压缩 / 外部改动注入）、装配回执核对、三元原子提交与整体撤销、感知分类完整性、自查缺失报错。
- 在线评测（`.env` 在线模型，单例复测纪律）：
  - UC-S01 空作品起步：设定卡确认 → 第一版结构 + 首批模块入档，全程对话；
  - UC-S02 两章写作：结构随入档同步、记账静默、计划性变化有说明；
  - UC-S03 对抗用例：风格指令（如「对白多一点」）下必发生清单护栏保证规定事件不丢（对应实验失败场景的回归）；
  - UC-S04 计划修改：「把回收提前一章」走暂存闭环并整体撤销；
  - UC-S05 台账对账：结构文件含伪造/过期「已写」标记时，确定性对账拦截、强制对账流程改写缺章（对应 2026-11-03 最小试验的回归）。
- 发布门槛：UC-S01—UC-S05 全过 + 确定性矩阵全过；效果以结构真实性（文件与正文一致）与作者盲读为主证。
- 通过后统一版本 **1.2.0**（`pyproject.toml`、`src/hastings/__init__.py`、前端包与锁文件、健康检查、版本断言）。

**退出条件**

验收有证据；文档状态同步；未完成项如实保留。

1. 结构文件定位、铁律段切分与指纹（纯函数先行）。
2. 结构读写工具接入暂存模式（复用 v1.1 工具执行模式切换）。

6. 三元暂存变更与联合提交扩展。
7. 感知分类标注与对话回显。
8. 起草强制对账流程、自查三层与复检交互。
9. 结构只读页与入口收敛。
10. 验收与版本统一。

## 6. 风险与处理

| 风险 | 处理 |
|---|---|
| 结构文件失控膨胀（模型越写越细） | 字数预算冻结；超限入档前压缩、压缩走暂存确认；只读页可见体量 |
| 自由格式失去可校验性 | 铁律固定开头保证常驻注入；正文台账与确定性对账补足章级事实；自查概率性如实标注；UC-S03/UC-S05 对抗用例回归护栏 |
| 结构与正文脱节（模型忘更新） | 同步绑定入档事务，无「只入正文」路径；全写入路径测试防绕过 |
| 模型顺着过期的「已写」标记在假前提上继续写作 | 正文台账由事实层维护（不进 `STRUCTURE.md`）+ 装配层确定性对账为主防线；提示词强制对账为第二道；预期正文缺失按任务失败归因（2026-11-03 试验：被动注入 0/3，强制流程 3/3） |
| 静默记账掩盖计划变化 | 感知分类在装配层校验标注完整性；计划性变化必须单独一行说明 |
| 必发生清单派生为空或失真 | 自由格式下纯函数派生不可行（试验证实）；改为模型自列＋回执展示＋宽松机检；自列为空如实说明并建议补骨架/模块，不猜 |
| 结构文件与模块内容重复冲突 | 分层判据写入起步与自查提示词；自查含一致性检查；重复不阻断、模型整理 |
| 外部编辑造成解析歧义 | 按磁盘现状如实注入，不设对照界面；铁律段标记丢失时降级为全文注入并提示 |
| 结构更新打断写作回合预算 | 结构更新随入档事务落盘，不占对话回合；压缩路径独立触发 |
| 全链路依赖在线模型，评测成本上升 | 确定性测试优先；在线用例失败修复后单例复测，不短时间重复 |
