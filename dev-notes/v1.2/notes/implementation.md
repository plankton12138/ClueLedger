# v1.2 实施记录

日期：2026-11-04。

## 为什么这样改

旧写作页同时把对话、作品意图、结构页、正文编辑器和目录动作暴露给作者，作者需要判断该去哪里改、
哪些全局对象要同步。v1.2 把创作修改收敛到对话：作者只表达要求，模型负责维护结构、正文与辅助模块；
结构、章节和模块页面只承担阅读与定位。

## 已完成

- 数据格式升级为 5，删除作品意图模型、操作、接口、门槛与前端页面；格式 4 明确拒绝，不迁移。
- `STRUCTURE.md` 成为唯一全局语义提示；空作品按它是否存在进入引导或自由发挥起步。
- 正文和结构不再因缺作品意图而被接口拒绝；章节仍经过既有事务和范围保护。
- 增加只读模块目录检查与结构化模块建议。库为空或无匹配时可以建议创建人物小传、故事背景等模块；
  有匹配时建议装入精确版本。作者接受时只执行建议列出的操作，拒绝时直接继续原任务。
- 模块操作提交后以新装配自动续接原请求；续接请求使用确定性键，避免同一问题重复发起。
- 写作页删除作品意图、起步卡、正文编辑器和目录写入动作；宽屏对话常驻，窄屏在对话与只读稿纸间切换。
- 新作品空稿纸增加“一句话起步”和三条示例；点击只填写当前对话草稿，不发送、不创建会话，已有草稿不覆盖。
- 版本统一为 1.2.0，并把在线浏览器验收收敛为单条真实模型冒烟，避免短时间重复调用。

## 侧栏与模块入口

v1.2 把模块区从写作目录删除后，没有补上计划要求的次级只读入口，作者在写作页既看不到已装模块，
也无法回到模块内容；与此同时模块库页仍保留 1.0.9 的旧作品文件树，两个页面因此出现两套不同侧栏。

本轮按作者要求收敛为一种分工：

- 写作页左栏底部保留折叠的「作品模块」区，只负责装入、条目定位和阅读；模块内容仍为只读，
  内容修改只进模块库页。
- 模块库页取消左侧作品文件树，只保留模块浏览、详情与编辑；模块装卸继续通过「更多 → 作品模块管理」。
- 写作页的模块区在正在阅读某份模块时自动展开，避免当前阅读位置被折叠隐藏。
- 目录内容超过侧栏高度时在目录内部滚动，章节与模块较多时仍能到达底部。
- 目录去掉没有实际内容的「稿纸」占位入口；空作品仍由主区起步提示承接。
- 「全书结构」固定在目录滚动区上方，展开作品模块或滚动章节时仍保持可见。
- 「章节」列表可以收起，只保留栏目名；展开状态默认开启。
- 模块区顶部提示人物小传、故事背景等长期资料可以由模型判断并创建；点击「让模型补充资料」
  只把请求填进对话草稿，不直接发送，作者仍可修改后再发出。

## 章节改名

写作侧栏每章右侧增加改名入口。提交时以当前作品修订为前提，服务端只更新章节标题；正文首行仍是
旧标题时在同一提交里一并替换，作者改过的开头保持原样。保存前有未提交正文时先保存，正文存在
版本冲突时拒绝改名并提示先处理冲突。

未登记章节的正文文件与章节共用「章节」列表，不再单独设「其他正文」分组；这类文件改名时只更新
正文首行标题，文件名保持不变。已登记章节走章节提交，不允许绕过计划直接改正文文件。

## 修订学习（首批）

正文保存与候选采用在收据里登记来源，修订记录从变更记录的整文件反向补丁派生：提交后崩溃、
重试同键请求都不会重复或丢失。首次起草与纯追加续写不生成修订；模型经文件工具改稿按前后
指纹直接落一条，并保存本轮作者原话。

差异按段落对齐、段内字符高亮；能否分析每次按当前正文重算，改写段落要求唯一命中，删除要求
两侧锚点相邻，歧义片段只留在历史。Writer 工作台用「对话 / 本章修订 / 写作约定」三个状态承载
修订记录与整份约定，顶部常驻「修改正文」进入稿纸编辑。写作约定作为必装分区紧跟全书结构注入，
只在会生成正文的轮次出现；超预算报 `STYLE_CONTEXT_TOO_LARGE`，不截断。

分析结论按写作约定、全书结构、模块条目与仅当前场景分组，每条带依据；当前只有写作约定可以在
面板里确认写回，结构与模块建议仍要回到对话继续。写作约定建议由服务端合并进唯一的
「从改稿归纳」区块：已有规则不重复写入，历史遗留的同名区块合为一处，作者自己的其它章节保持原样。

章节选中时，对话输入框上方显示最近一次修订的回执，回执带入「本章修订」工作区；分析记录实际读取的
资料与执行步骤，结论下方可展开运行日志。回执按修订列表重建，不写进会话事件。

稿纸增加修订模式：章节标题旁的「修订」把正文切换为编辑器，可随时「看差异」；确认后才入稿并
生成一条作者修订，未确认的文字只留在本地草稿。编辑期间正文被别处更新时保留草稿，作者选择覆盖
或改用服务端版本。确认后标题旁出现「查看修订」。

分析判定为全书结构或模块条目的建议都会附带一段可定位的替换补丁。结构建议在核对指纹后写入
`STRUCTURE.md`；模块建议按模块合并成一次作品内版本更新，切换本作品绑定而不改模块库头版本。
定位文本不唯一、条目或结构在分析后被改过时拒绝覆盖。详细入口映射与待实施项见
[修订学习实施记录](../../revision-learning/notes.md)。

## 模块库批量删除

模块库列表增加选择框，选中后顶部显示「删除所选（N）」；确认对话框列出将被删除的模块名，并说明
已装入作品仍可读取固定版本、模块可恢复。删除逐个提交，单个失败不阻断其余项，失败原因保留在对话框里；
全部成功后清空选择并刷新列表。已删除的模块不出现在选择项中，筛选或翻页后只保留仍可见的选中项。

## 界面状态与任务终态对齐

后端日志已经写完 `assistant_finished` 与 `run_finished`、对话里也显示了完整回复，界面却仍停在
“等待模型响应”，点击暂停后一直停在“正在暂停”。原因是运行状态只由 `run_finished` 一个事件清除：
订阅被替换、连接在终态前断开时，这条事件不会到达，暂停请求改的也只是“停止请求中”这一标位，
于是界面和服务端各说一套，输入框与发送入口一直不可用。

改动把“事件流”和“实际状态”分开：

- 暂停返回时按操作状态收尾。返回 `completed`/`failed` 说明事件早已写完，直接清掉运行标记、
  结束这条订阅并按日志补齐终态卡片；返回 `paused` 立即恢复输入与「继续」，事件流再给五秒收尾，
  超时也按日志收尾，不让发送入口停在“受理中”。
- 模型回复收妥后等待整轮终态。`assistant_finished(completed)` 之后六秒仍没有整轮终态，就同时读
  操作快照与会话快照；操作已结束就按日志补齐并结束订阅，仍在执行则继续跟随，不再无限重连。
- 事件流正常关闭但没有终态时先对账再决定是否重连；重连退避用尽仍无终态时明确提示，由作者决定
  是否重新连接，不把“没收到”当成“还在跑”。
- 控制面请求增加超时，暂停、继续、插话与快照读取都不会一直挂着。
- 状态行区分“模型还在写”和“模型写完、任务在收尾”：后者显示“正在确认任务状态”，只有确实存在
  活动模型请求时才显示“等待模型响应”。
- 刷新会话列表时，已经写入 `run_finished` 的轮次不再被迟到的活动轮次标回运行中。

## 空作品的结构先行门槛

产品要求空作品收到写正文请求时，模型在同一轮先建立 `STRUCTURE.md`，再提出正文候选。此前只有
起步提示和工具描述，正文候选工具与写前检查都不核对结构，模型可以在没有结构时直接提交候选。

本轮把结构先行做成 Agent 的本轮能力状态：

- `RunContext` 增加 `structure_ready`，装配时按磁盘现状初始化；`write_structure` 成功后立即置位。
- 正文候选工具与作品内正文写入统一经过 `RunContext.before_mutation`；结构未就绪时返回可恢复的
  `STRUCTURE_NOT_READY`，提示先用 `write_structure` 建立结构。
- 候选流程会过滤直接写工具；结构未就绪时保留 `write_structure`，并允许创建/更新 `STRUCTURE.md`
  绕过「只能提交候选」的写前检查，否则门槛会让模型无法在同一轮补结构。
- 写作用途且结构缺失时，系统提示在候选说明之后追加同轮顺序要求：登记范围时同时包含
  `STRUCTURE.md` 与目标正文，先写结构再提交候选；不要求作者另开一轮确认。
- 普通正文保存、导入和候选采用仍不检查结构文件。结构先行是模型侧的顺序保证，不是 HTTP 或
  作者门槛（与开发计划 3.2 一致）。

验证：新增 6 项结构门槛测试，覆盖状态初始化、工具拦截、同轮补结构、候选流程放行与服务级
「先提正文失败 → 写结构 → 重新提交 → 核对提交」链路；后端全量 1760 项通过。

## 回合预算与批量局部修改（2026-11-04）

一次真实运行里，写第一章后逐处校订标点：18 次 `edit_file` 各占一个模型回合，加上开头的读取、
登记范围、建章失败与建稿，正好用完 24 轮，正文还剩一处半角问号。这不是死循环——每次修改都
真实生效；问题在工具设计：`edit_file` 一次只替换一处唯一原文，提示词又不建议为小改动重写整章，
模型只能一处一个回合地改。回合按模型请求计数，工具调用次数不参与。

- `edit_file` 改为 `edits` 数组：按顺序应用，任一处找不到或不唯一就整批拒绝；全部校验在写盘前
  完成，失败不准备版本基线。读取前提按整批的最小起点到最大终点核对，跨段批改要求中间内容读过。
  文件变化事件一次批改记一条（带 `edits` 条数），活动面板不再刷出十几条同样的「修改」。
- 每次工具返回带 `execution_budget.remaining_model_rounds`；剩余不超过 4 轮时附收尾提示，
  要求停止新批次、先回复作者。作者可见摘要仍取工具原本的说法，预算只进入模型可读的返回。
- `create_chapter` 只在有冻结方案上下文（`run.story` 与 `state_root`）时注册。之前普通写作
  会话里它必然报 `STORY_SCOPE_INVALID`，白耗一个回合，并把模型推向 `write_file` 直接建稿。
- 系统提示把「同一批校订放在一次调用里」写成明确要求，并说明 `execution_budget` 的含义。

验证：新增 7 项用例（批量应用、整批原子性、空批次拒绝、预算字段、收尾提示、作者摘要不受影响、
建章工具注册）；后端全量 1768 项通过（workspace 1633、其余 135）；ruff 通过；mypy 仍只有改动前
就存在的 8 处 JSONValue 收窄与 retrieval 报错。在线模型单例验收未完成：
`scripts/model_acceptance.py` 仍按旧签名调用 `TurnService.accept(index_paths=…)`，脚本需要单独
对齐，本次不作为发布证据。
