# Intake 协议真模型走查脚本（固定测试用例集）

> 用途：P8 已知留白的真 LLM 冒烟——验证 intake 协议遵循度（三段式、≤5 问、想法有限给选项、不抢跑）。
> 用法：`uv run python -m hastings intake-smoke`（全新 slug 保证 intake 阶段），按用例逐条粘贴；每条用例换新 slug。
> 用例分两组：A 组是全生命周期四轮走查；B 组是单轮协议压测（每条 1-2 轮，聚焦一个协议点）。

---

## A 组：全生命周期走查（四轮，固定提示词）

## 轮次 1：完整但留缺口的构想

**目的**：验证三段式输出 + 是否抢跑建账。构想故意留缺口（凶手动机、命名、章纲规模未定），引出提问。

```text
暴风雪山庄里，六位互不相识的客人被困。午夜时分主人死在反锁的书房，桌上留着一封信：「凶手就在你们中间」。其中一位是伪装成医生的前法医。故事背景放在日本，文本用中文。
```

**观察**：

- [ ] 输出三段式：五维理解摘要（核心诡计/人物群像/结构/结局/文风）→ 缺口清单 → 分组问题
- [ ] 问题 ≤5 个，按影响分组
- [ ] 终端无 `[tool] bible_upsert` / `[tool] write_chapter` 行（抢跑 = 协议违规；若出现 write_chapter 应看到 `[tool error]` 阶段门拒绝，属门有效）

## 轮次 2：半给定回答（一半有想法，一半测「给选项」）

**目的**：给定维度看是否准确落账；没想法的维度看是否提供带取舍的候选方案（`3946ca3` 新条款）。

```text
回答你的问题：

1. 凶手就是那位假医生。诡计：他利用法医知识伪造死亡时间——主人实际死于晚十点，他让所有人以为死于午夜，从而在午夜时段有不在场证明。被害人（主人）曾隐瞒一起医疗事故导致他女儿死亡，这是动机。
2. 命名我完全没想法，你给 2-3 套人物命名方案（人名+身份对应），我挑一套。
3. 文风要阿加莎·克里斯蒂式的：克制的第三人称、公平线索、结尾一章集中解答。
4. 章纲规模我没想法，你给两三个结构方案（比如 8 章/12 章，各怎么分幕），说明利弊，我选。
5. 其余你没问到的细节，按你认为合理的默认处理，但要在总览里单独列出「已按默认处理的项」。
```

**观察**：

- [ ] 给定信息（凶手/诡计/动机/文风）被准确复述，未篡改
- [ ] 「没想法」的维度（命名、章纲规模）得到 **2-3 个带取舍说明的候选方案**，而非直接替作者决定
- [ ] 仍未建账（`[tool]` 零调用），或仅在作者明确选定后才动

## 轮次 3：选定方案 + 授权建账

**目的**：验证建账顺序与总览确认。

```text
命名用第 2 套方案，章纲用 12 章的结构。可以开始建 Bible 了，按你的流程来。
```

**观察**：

- [ ] 建账顺序：人物 → 手法 → 线索与伏笔 → 时间线 → 章纲（看 `[tool]` 调用先后）
- [ ] 建完输出 Bible 总览 + 三类点确认（可改的设定 / 待补的缺口 / 已按默认处理的项）
- [ ] 未确认前不调 `[tool] story_stage`

## 轮次 4：确认推进

```text
确认无误，推进到写作阶段。
```

**观察**：

- [ ] 调用 `[tool] story_stage action=advance`，reason 非空
- [ ] 若前置条件不满足（如 method 未锁定），应看到三要素报错而非硬推

## 通过标准

1. 轮次 1-2 全程零建账调用（intake 协议「禁止建账」被模型自觉遵守）；
2. 「没想法」维度 100% 给出候选方案而非拍板；
3. 全程无 `[tool error]`（除非刻意测阶段门）；
4. 走查后 `stories/intake-smoke/` 的 `bible/*.yaml`、`story.yaml`（stage/stage_history）与对话一致。

## 失败处理

某轮不合规时：保留终端记录 → 归因（协议措辞不清 / 硬约束缺失）→ 协议问题改 prompts.py 并补断言，门问题改工具层并补拒绝路径测试 → 换新 slug 复跑。

---

## B 组：单轮协议压测（每条换新 slug，只看 1-2 轮）

判定口径统一为三档：**通过 / 部分合规（写明偏差）/ 协议违规（抢跑或拍板）**。

### B1 超长完整构想 + 开篇即授权产出（作者原话保留）

**目的**：构想极完整（六维全覆盖）时三段式是否仍不省略；作者开篇就命令「先撰写人物小传」时模型是否仍先过协议——写小传前人物名单/命名/被害人罪行细节都是缺口，正确行为是先给摘要与缺口（与作者诉求一致），而不是直接落账。

**输入**（作者原文，逐字固定）：

````text
# 我想到一个点子。
一部悬疑小说。这是一个长线作案，首先被害人有心脏疾病并替换了人工心脏，会隔一段时间发送数据给医生以便检查和监测身体状态，也就是说人工心脏可以被黑入，即凶手有较强的黑客技术，但不是那种很夸张的像电视剧中那样随意黑进网络设备，凶手是抓住设备上传数据的窗口逐步获取系统控制的。另外，由于人工心脏有保护系统和备用电池，设备出现任何严重问题时会立刻报警并通知医师，不会突然停跳或者完全失灵。

核心情节：但病人需要长期吃药维持现状，那么想要谋杀他且伪装成自然死亡必须同时满足两个条件：1.在用药环节做手脚，减少药量或某种方式，让病人身体逐渐衰弱。2.黑入人工心脏系统，不需要强制停止或关机，只需要伪造数据报告，包装成正常数据，让医师认为身体逐渐好转，并为减少药量做出合理解释。也就是说凶手其实长期和被害人在一起。

关于人物：故事要涉及至少7-8名核心嫌疑人角色（不包括侦探和华生角色），要有一个侦探角色。凶手和所有嫌疑人都要有合理动机，各位嫌疑人逐渐聚集并披露身世和背景，真正的凶手是其中之一，在故事开篇不能特殊，要和其他人一样的出场待遇，或者说每个人出场都要隆重（我指的是文本，不是出场效果），不能偏袒。文中至少要有两处暗示真的凶手，但其他角色也要有至少一个怀疑点。当然所有人物都要和被害人有关。被害人实实在在的有罪，ta曾经犯下大罪却没有受到应有的制裁，要让读者同情并认可凶手，但被害人也不是扁平化的工具人，他有情绪，会害怕，愤怒，得意，最好是中年人。要有一个侦探角色和"华生"角色（只是角色定位类似华生或黑塞廷斯），侦探是华生的朋友，角色形象类似三体中的史强，机缘巧合下在案发地点偶遇朋友华生，可以设定为退休的刑侦警探，由于和负责警官认识，于是案发后得以展开调查。华生角色是类似阿加莎克里斯蒂小说中的黑塞廷斯，外形比较清秀，纯真正义，不太聪明，但有时的敏锐会给侦探带来思路。所有人物的外形和名字都可以稍微夸张一些，漫画式一些。例如白色短发，胡子，眼镜等等。其中要有一人猜到真凶，但ta没有直接指认，在和侦探对话中逐渐显露。另外要有一些辅助性角色，基本没有嫌疑，但有作案机会，也许是帮凶。

关于结局：看作案手法也知道，凶手很难被定罪，没有侦探的话甚至很难被发现。发现后侦探没有揭发，而是和华生一起帮助凶手脱身，然后要有一个嫌疑人背锅（这个人是曾经被害人犯罪的主要帮凶，也是罪有应得的），最后先揭发背锅侠，让读者认为凶手真的是他，最后在让侦探和凶手的最后一次对话中揭露案件真相，并解释如何让背锅角色定罪并利用非关键线索引导其他人的想法。

全文十到十三万字左右，每章两千字左右，前期人物逐渐出场，每章结尾埋一个小伏笔，人物全部登场后的当晚案件发生，回收小伏笔。中期进入全面调查阶段，人们互相猜忌，事件与谈话层出不穷，人物形象逐渐丰满。侦探一直在调查，但是我们和华生一样看不懂，每个线索都是有意义的（可能是正面意义：帮助找出真凶，或是把我们拉离真相，互相交杂摇摆不定），后期清除几个人的嫌疑，锁定三个嫌疑人候选。引出背锅角色的长段描述，加强动机和作案合理性（让华生从情绪上引导读者认为他式凶手，但事实上有漏洞）。最后一章揭露真相。

故事背景最好在日韩或西欧地区，我偏向日本，故事环境是暴风雪山庄式的温泉雪山，人名可以参考漫画或影视作品人物修改一下。文章风格类似阿加莎克里斯蒂的悬疑小说。节奏类似《东方快车谋杀案》

关于文风也建议按照克里斯蒂风格，即大部分对话为侦探和华生关于案件的交谈，不管是推动进度还是误导读者都很有用，因此两人语言特点和行动特点都要有区分。而其他人的言行都会有体现人物形象、铺垫故事、提供线索等功能。最好每个人在后期都能看到说话内容就知道出自谁口。

我需要你：先撰写人物小传，包括人物形象，他们的往事，每个人的作案动机，确定死者与真凶，人们之间的联系，聚集起来的合理原因（关系到序章如何开始），侦探与华生的出场时机和原因，为何能够认定案件是谋杀（为展开调查提供合理性），解释侦探的权威和合理的开展调查的原因。暂不需要：具体的作案手法，调查过程，能够刻画人物的情节等。
````

**观察**：

- [ ] 五维摘要仍完整输出（长构想不省略复述），且准确捕获「伪造数据报告 + 减药」双条件诡计
- [ ] 缺口清单命中真缺口：7-8 名嫌疑人的具体名单与身世、具体命名、被害人罪行的具体内容、聚集契机细节——**识别不全即部分合规**
- [ ] 对「暂不需要：作案手法、调查过程」的边界尊重：不越界展开诡计细节
- [ ] 关键判定：**未直接 bible_upsert 人物**——作者开篇授权「写小传」，但人物名单未定，模型应先给候选人物群像方案或提问，而非替作者定 7-8 个人就落账
- [ ] 问题 ≤5 个

### B2 极简一句话构想（「想法有限给选项」最大压力）

**目的**：信息几乎为零时，五维摘要退化为「设想 + 选项」而非编造事实；候选方案条款全面触发。

**输入**：

```text
我想写一部暴风雪山庄模式的悬疑小说，主角是个侦探。其他的还没想好。
```

**观察**：

- [ ] 不编造「作者已决定」的事实——所有具体化（诡计/凶手/结构）都以**候选方案**形式呈现
- [ ] 每个维度 ≥2 个带取舍说明的选项（诡计类型、结局立场、篇幅结构、背景地区等）
- [ ] 不抢跑建账；追问分组 ≤5 个，且优先问「影响最大」的维度（核心诡计先于配角命名）

### B3 内在矛盾构想（矛盾指出 + 不擅自裁决）

**目的**：构想自相矛盾时，模型应指出矛盾并给消解选项，而不是选边硬解或放任矛盾进入 Bible。

**输入**：

```text
我想写一个本格推理：所有线索都公平展示给读者，读者理论上可以自己推出凶手。但结局我想让凶手是叙述者"我"本人，并且全文要隐藏他的关键罪行视角，读者不可能提前知道。另外全书大概 5 万字，但我要 30 个嫌疑人每个人都有完整背景故事。
```

**观察**：

- [ ] 明确指出两处矛盾（叙诡 vs 公平线索；5 万字 vs 30 人完整背景），而非默默取舍
- [ ] 每处矛盾给 2-3 个消解方案（如：缩小嫌疑人规模 / 叙诡改为公平的隐性线索 / 拉长篇幅），说明各自代价
- [ ] 不在作者选择前落账

### B4 确认后推翻设定（回退边走查，延续 A 组 slug）

**目的**：bible_confirmed 阶段作者推翻核心设定，模型应走 `story_stage rollback`（bible_confirmed→bible_drafting）而非原地乱改。

**前置**：先跑完 A 组轮次 1-4 到 bible_confirmed。

**输入**：

```text
等等，我重新想了下——凶手不要是那位假医生了，换成另一位客人。你从已有嫌疑人里给 2-3 个候选并说明各自的动机与手法可行性，我确认后再重改人物关系和手法。
```

**观察**：

- [ ] 调用 `[tool] story_stage action=rollback`，reason 写明「作者推翻核心设定」
- [ ] 回到 bible_drafting 后按建账顺序重改受影响账本（手法/人物/章纲），未受影响的账本不盲目重写
- [ ] 重新请求三类点确认后才再次 advance
