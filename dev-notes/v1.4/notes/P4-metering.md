# v1.4 P4：订阅模型代理与用量结算

更新：2026-11-06。状态：预留、代理、流式结算与额度页面已实现并通过离线测试和本地浏览器验证；真实供应商模型调用、真实用量与生产负载未验证。

## 一、交付范围

| 面 | 实现 |
|---|---|
| 计量单位 | 1 点 = 1,000,000 微点；内部只用整数微点，公式按 `(333×未命中 + 11×命中 + 1000×输出) × 倍率` 结算 |
| 预留表 | `usage_reservations` 记录用户、请求号、权益、固定额度窗口、模型、预留/结算微点、状态与到期时间 |
| 原子预留 | 单写事务内检查账号、有效权益、日额度、整期总额与每账号并发上限，再写入预留；请求号唯一 |
| 输入上限 | 代理按实际请求体做保守 token 估算，加上服务端最大输出预算；无法确定或超上限时拒绝，不静默截断 |
| 结算 | 成功按上游真实 usage 幂等结算；重复结算不重复写用量；实际用量低于预留时自然释放差额 |
| 跨窗口 | 预留固定开始时的窗口；跨窗口完成仍结算回原窗口 |
| 异常恢复 | 上游无调用失败立即释放；流式中断或缺少 usage 进入待核对，超时由恢复任务释放，不永久占用 |
| 并发与退款 | 每账号最多 2 个进行中订阅请求；退款与调用并发时，结算发现权益已退款则释放本次预留 |
| 续费窗口 | 续费沿用现有有效期的窗口锚点，不因付款重置当日额度 |
| 代理 | `POST /v1/chat/completions` 内部接口；短期 grant 按账号签发，平台模型密钥只在 relay 进程 |
| 写作接入 | `server/platform_channel.py` 向每个账号的模型配置注入只读「线簿订阅」连接；每轮把 grant 作为临时凭据，浏览器不持有 |
| 额度页面 | 订阅对话框显示用量进度、预留、每日/整期剩余与恢复时间；80% 提示，耗尽/到期给出等待恢复或切换自带连接的下一步 |

主要入口：[relay/proxy.py](../../../src/hastings/relay/proxy.py)、[relay/metering.py](../../../src/hastings/relay/metering.py)、[relay/store.py](../../../src/hastings/relay/store.py)、[platform_channel.py](../../../src/hastings/server/platform_channel.py)、[SubscriptionDialog.tsx](../../../frontend/src/components/billing/SubscriptionDialog.tsx)。

## 三、尚未完成与边界

- 没有跑完整的写作 Agent 轮次经过代理；已分别验证写作侧 grant/base_url 配置、代理上游请求与结算。真实 DeepSeek 的 usage、缓存命中与长流式响应未验证。
- 预留表的 `workspace_id` 目前为空：当前 grant 只固定账号，写作服务的作品归属由自身校验；作品级审计需要后续把 grant 扩展为账号+作品。
- 输入 token 使用字符启发式上限而非供应商 tokenizer；保守预留、真实结算，极端字符集仍可能低估，超额部分按真实用量记账。
- 未做多账号高并发压力测试；默认每账号 2 个并发请求、预留 1 小时、核对 1 小时，需按真实流量调整。
- 平台模型地址、密钥、模型倍率与输出上限需在 P5 部署配置中核定；当前默认值仅用于本地与测试。
