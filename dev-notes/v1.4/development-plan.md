# v1.4 开发计划：在线账号、作品隔离与订阅

更新：2026-11-06。状态：P0—P4 已通过离线与本地浏览器验证；P5 的生产校验、加密凭据、部署配置、日志、健康检查与备份脚本已完成，真实域名/证书、SMTP、支付宝与恢复演练待执行。P6 上线验收尚未开始。产品名称：线簿 / ClueLedger。

本版让作者通过域名访问网站，以邮箱登录后管理自己的作品、购买订阅并写作。订阅定价与点数测算见[订阅方案](subscription-plan.md)；本文约定开发顺序、服务边界、接口与验收条件。所有代码示例均为待实现的契约示例，不表示仓库已经存在相应类型或接口。

## 一、目标与当前基础

核心关系是：**账号确定作者身份，作品归属决定可访问的数据，订单决定订阅权益，实际模型请求决定用量。** 这四项共用稳定的 `user_id`，避免换浏览器后丢失权益，也避免用户之间共享作品或模型凭据。

| 范围 | 当前可见实现 | v1.4 目标 |
|---|---|---|
| 写作入口 | `server/__main__.py`、`server/file_app.py` 围绕本地目录和应用状态装配 | 登录后的用户范围服务，作品目录由服务器分配 |
| 模型配置 | `server/provider_config.py` 等管理应用级连接与凭据引用 | 连接、当前选择、凭据、测试任务均按用户隔离 |
| 支付 | `relay/app.py`、`alipay.py` 已有套餐、订单、通知、查询、退款、回跳与权益代码 | 复用正式登录账号，补齐生产配置、后台查单和端到端验证 |
| 支付身份 | `POST /v1/session` 生成随机账号与访问凭证 | 替换为可跨设备登录的邮箱账号；生产关闭匿名创建入口 |
| 计量 | `relay/store.py` 有用量表结构 | 可信用户下的模型代理、原子预留、幂等结算与恢复任务 |
| 测试 | `tests/relay/` 已有支付测试文件 | 增加身份、越权、计量、部署与浏览器证据；本次文档更新未执行这些测试 |

当前代码存在不等于生产支付已开通或验证。旧数据不迁移，使用新的测试与生产数据目录。原本地运行方式继续保留，但不把本地信任边界带入公网服务器。

## 二、模块与设计取舍

### M1 邮箱账号与登录

第一版采用邮箱＋密码登录：首次注册验证邮箱，日常登录无需每次等待邮件。需要承担密码哈希和找回流程；相较每次邮箱验证码登录，减少对邮件即时送达的依赖。

- 内部用户 ID 创建后不变。保存邮箱原始值与唯一比较值，统一注册、登录、重置、换邮箱的比较规则；不擅自删除邮箱中的点号或 `+` 后缀。
- 邮箱未验证前不创建正式会话；密码用成熟的自适应密码哈希方案保存，不自写算法、不存可逆密码。
- 验证与找回使用 6 位数字验证码，只存哈希，绑定用途、账号与 10 分钟有效期；原子单次消费，同一用途重发会替换旧码，连续错误 5 次后需重新发送。
- 登录成功建立可撤销的服务器会话，浏览器使用 `Secure / HttpOnly / SameSite=Lax` Cookie。会话寿命与订阅寿命分别管理。
- 写操作校验来源与 CSRF；退出撤销当前会话，重置密码撤销旧会话。登录和邮件接口限制发送、尝试频率，统一响应避免暴露注册状态。
- 普通用户走邮箱账号；运营后台独立授权，敏感管理操作增加二次验证。账号状态检查覆盖禁用、密码重置和后台任务执行。
- 第一版提供注册、验证、登录、退出和找回密码。换邮箱预留身份不变的契约，若实现须重新验证并通知旧邮箱，不成为首次上线的额外前置功能。

建议新增 `src/hastings/accounts/`，拆分账号存储、认证服务、邮件适配、会话依赖和接口装配；前端增加账号页面与统一登录状态。具体文件名在 P0 冻结，不把认证逻辑散落进每个路由。

### M2 作品、文件与运行任务隔离

第一版为单人作品，不引入团队、邀请和协作权限。每部作品有唯一拥有者；接口用作品 ID 标识，真实目录由服务器通过 `storage_key` 解析。

| 资源 | 必须隔离的范围 |
|---|---|
| 作品 | 列表、创建、打开、改名、删除、导入和导出 |
| 内容 | 正文、大纲、线索、构思、草稿、报告、附件、历史版本与检索索引 |
| 运行 | 会话、任务状态、暂停/继续/取消、事件流与结果下载 |
| 应用状态 | 最近作品、阅读位置、当前模型选择、私有模块库、模块修订和装配引用 |
| 模型工具 | 文件读取、搜索、修改和模块访问均使用同一受限作品服务 |

用户身份从会话获取，不从请求体中的 `owner_user_id` 获取。越权与不存在的资源统一返回 404，避免泄露存在性。网络模式禁用系统目录选择和任意绝对路径打开；上传只接收文件内容并在用户目录内落盘，压缩包条目、相对路径和符号链接也必须检查。

现有进程级注册表、连接服务、缓存与锁需要逐项清点：私有键至少包含用户与作品身份。模型任务创建时记录拥有者，执行与续接时重验授权；不能只在创建任务的 HTTP 请求上检查一次。流式事件的订阅、重连与结果查询同样校验会话和归属。

建议的服务契约示例：

```python
def require_owned_workspace(db, principal, workspace_id):
    row = db.execute(
        "SELECT id, storage_key FROM workspaces "
        "WHERE id = ? AND owner_user_id = ?",
        (workspace_id, principal.user_id),
    ).fetchone()
    if row is None:
        raise WorkspaceNotFound(
            "[WORKSPACE_NOT_FOUND] workspace.open：作品不存在或不可访问。"
            "建议：返回作品列表重新选择。"
        )
    return row
```

此查询之后仍须由受控存储层解析路径，不把 `storage_key` 直接当用户可修改的文件路径。所有 HTTP、后台任务与模型工具复用这项约束。

### M3 模型连接与凭据隔离

保留自带模型和线簿订阅两条通道。网站版的请求都由服务端执行；浏览器不直接取得平台模型密钥，也不能获取其他用户的连接配置。

- 作者自带密钥按用户加密存储，配置仅留凭据引用；服务器加密主密钥与数据库分开保管，不沿用所有用户共享的操作系统凭据条目。
- 模型连接、当前选择、模型发现、探测结果和容量配置都加用户范围。私有缓存不得跨账号命中。
- 自定义供应商地址由服务器访问，必须限制回环、内网与云元数据地址，并检查解析结果和重定向，防止借连接测试访问服务器内部资源。
- 平台订阅作为独立来源接入现有调用协议，不与现有第三方订阅授权混淆。每轮固定模型快照，并在实际调用前检查账号、作品和权益。
- 登录失效、模型配置失效与订阅到期分别显示，不能把订阅到期处理成退出网站账号。

### M4 支付、订单与订阅

采用 AI 网页应用收款；用户先登录，再创建订单。数据库中的订单用户在下单时固定，支付人代付也不改变归属。

- 复用已有支付适配与订单逻辑，金额、套餐和时长由服务端套餐表确定；客户端只传套餐代码与幂等请求 ID。
- 支付进程与写作进程复用账号和会话校验模块及同一用户 ID。只有同域名不等于共享身份，不能相信客户端传入的身份请求头。
- 现有匿名会话入口在生产禁用；删除原方案的历史订单认领流程。浏览器不再把长期购买凭据放在本地存储作为账号身份。
- 通知验签及查单均验证应用、订单、金额、收款方、交易状态；订单状态变更和权益发放在同一事务内，重复或乱序通知不重复增加天数。
- 回跳页仅展示状态，不从 URL 参数建立会话或发放权益；订单详情须验证归属。现有临时回跳令牌不得扩大为账号访问权限。
- 实现后台未决订单查询、失败重试与终态收敛；前端轮询和浏览器关闭不影响收款确认。
- 退款及退款查询由受授权运营入口执行，用户侧只能发起申请；结果确认后重算权益并阻止后续不合法调用。普通用户不能调用管理退款接口。
- 通知接口免网站登录，但验签与字段校验不豁免。生产建议配置 HTTPS 通知地址；无通知时仍须有完整主动查单链路。

下单服务契约示例：

```python
def create_order(principal, body, orders, plans):
    plan = plans.require(body.plan_code)
    return orders.create_once(
        user_id=principal.user_id,
        request_id=body.request_id,
        plan_code=plan.code,
        amount_cents=plan.price_cents,
        days=plan.days,
    )
```

请求中不接受可信的用户、金额和有效期；`create_once` 必须用数据库唯一约束保证并发幂等，不能只在应用内先查后写。

### M5 用量、额度与异常恢复

先验证权益并预留，再调用上游，最后结算。日额度、体验卡总额度与并发限制都按账号累计；多个作品和多个设备共享同一账号额度。

- 统一整数单位，建议 `1 点 = 1,000,000 微点`。金额始终为整数分；倍率及扣点使用确定的十进制规则。
- 增加请求预留表，记录用户、作品、请求 ID、权益、额度窗口、预留量和状态。数据库唯一约束阻止重复预留或结算。
- SQLite 用短写事务原子检查并更新额度；调用模型期间不持有数据库写锁。每连接开启外键约束，配置锁等待并验证并发行为。
- 预留覆盖服务端实际构造的输入及最大输出预算，不信任浏览器估算；无法确定安全上限时拒绝执行或缩减本轮预算并明示。
- 完成后以真实 usage 幂等写流水并释放差额。无上游调用的失败立即释放；缺少 usage 的流式中断标记待核对，按有限重试与到期策略恢复，不能永久占用额度。
- 预留固定在开始时的额度窗口，跨窗口完成也结算回原窗口。续费不绕过当期额度，退款与调用并发时通过同一权益状态检查收敛。
- 到期或耗尽只停止订阅模型调用，保留阅读、编辑、导出及自带模型选择。

### M6 部署、域名与运维

第一版采用单台 Linux 服务器、一个对外域名和 HTTPS。写作服务与支付服务分进程运行，通过统一入口转发；内部端口仅监听回环地址，不直接开放公网。

| 公网路径 | 目标 | 访问约束 |
|---|---|---|
| `/`、静态资源、`/api/auth/*` | 网站与账号服务 | 静态及必要认证接口公开，其余按会话限制 |
| `/api/file-workspaces/*`、模型与模块接口 | 写作服务 | 用户会话、资源归属与写入保护 |
| `/api/billing/*` | 支付服务适配层 | 共用会话；套餐可公开，订单与权益须登录 |
| `/notify/alipay`、`/return/alipay` | 支付服务 | 验签通知与只读回跳，不能绕过账号授权 |
| 原生 `/v1/*`、管理与内部模型代理 | 内部服务 | 不作通用公网转发，仅登记的映射可访问 |

- 沿用单机 SQLite 起步，不部署多个应用副本争用同一数据目录；多个进程的短事务与锁等待在 P4 专项验证。容量或可用性要求变化时另定数据库与扩容方案。
- 账号、订单与作品元数据统一数据库；正文、附件和会话文件使用持久化目录。用应用层事务与持久任务状态处理文件和数据库的非原子写入，不能直接宣称跨存储原子提交。
- 生产配置显式指定模式、正式应用、正式网关、回跳、可选通知、数据目录和密钥来源。缺项拒绝启动，不回退到仓库 `.alipay-sandbox.json`；私钥由用户在部署环境配置，不经聊天传递。
- 进程自动重启，支持健康检查、结构化日志、请求关联、支付失败与任务失败监测；日志不记录密码、验证码、会话、私钥及完整作品正文。
- 邮件使用专用发信服务和域名身份配置，验证注册、找回邮件在目标邮箱的送达情况。云厂商、地域、域名和邮件供应商尚未选定，本计划不代表采购授权。
- 开发、沙箱和生产分离。大陆部署将备案准备提前安排；按实际经营场景核对上线所需材料。
- 备份同时覆盖数据库、正文、附件、会话、私有模块与解密所需密钥；用一致性快照或暂停写入后备份，禁止只复制运行中的主数据库文件。上线前做一次独立目录恢复演练。

## 三、前后端接口对齐

下表是拟议公网契约，P0 对照现有路由冻结字段并补充类型。除回跳和通知外，认证与账单统一使用 JSON；成功示例字段不包含任何真实凭据。

| 页面动作 | 方法与路径 | 请求 → 响应要点 |
|---|---|---|
| 注册 | `POST /api/auth/register` | `{email,password}` → 通用已受理状态，不披露账号是否存在 |
| 验证邮箱 | `POST /api/auth/verify-email` | `{email,code}` → 验证结果；随后正常登录 |
| 重新发送验证 | `POST /api/auth/resend-verification` | `{email}` → 通用已受理状态，限速 |
| 登录与恢复 | `POST /api/auth/login`、`GET /api/auth/me` | 邮箱密码 → Cookie；当前账号 → 用户 ID、邮箱显示值与验证状态 |
| 退出 | `POST /api/auth/logout` | CSRF 校验 → 撤销会话并清 Cookie |
| 找回与重置 | `POST /api/auth/forgot-password`、`POST /api/auth/reset-password` | 邮箱 → 通用受理；`{email,code,new_password}` → 撤销旧会话 |
| 作品列表与新建 | `GET/POST /api/file-workspaces` | 用户内列表；创建只传名称，不传服务器路径或拥有者 |
| 作品、内容与任务 | 现有作品 ID 下的路由 | 保留已消费的业务字段；加入统一鉴权，不另建平行的作品接口体系 |
| 套餐 | `GET /api/billing/plans` | 套餐代码、名称、价格分、天数与额度 |
| 下单 | `POST /api/billing/orders` | `{plan_code,request_id}` → 订单号与受控支付宝跳转数据 |
| 订单与主动查询 | `GET /api/billing/orders/{id}`、`POST .../{id}/query` | 仅当前用户订单 → 状态与金额；主动查询限速 |
| 权益与用量 | `GET /api/billing/entitlement`、`GET /api/billing/usage` | 到期、当前窗口、已用、预留、剩余和重置时间 |
| 退款申请 | `POST /api/billing/orders/{id}/refund-request` | 原因与请求 ID → 申请状态；不直接调用管理退款动作 |

`/api/billing/*` 是新增网站适配层，统一字段并映射已有 `/v1/plans`、`/v1/orders`、`/v1/entitlement`；不能只在前端更名而漏改代理和后端。后台订单恢复、用量结算与退款执行是服务职责，不要求新增同名公开接口。

统一错误响应建议为 `{code,message,request_id}`，正文为 `[错误码] 位置：现象。建议：…`。未登录返回 401，身份有效但资源不归属返回 404，状态冲突返回 409，频率或额度限制使用明确业务错误码。全站捕获登录失效时保留草稿，不把所有失败都显示为“订阅到期”。

最小关系示例（仅展示归属与唯一性，完整字段在 P0 冻结）：

```sql
CREATE TABLE workspaces (
    id TEXT PRIMARY KEY,
    owner_user_id TEXT NOT NULL REFERENCES accounts(user_id),
    storage_key TEXT NOT NULL UNIQUE,
    name TEXT NOT NULL
);
CREATE INDEX idx_workspaces_owner ON workspaces(owner_user_id);

-- 订单下单时已经归属于账号，不预留匿名认领状态。
CREATE UNIQUE INDEX idx_order_request ON orders(user_id, request_id);
CREATE UNIQUE INDEX idx_usage_request ON usage_reservations(user_id, request_id);
```

## 四、开发阶段与完成条件

| 阶段 | 工作 | 完成条件 |
|---|---|---|
| P0 盘点与契约 | 列出路由、全局状态、文件根、凭据、任务、前端消费者；冻结账号和账单字段、新库结构及配置模式 | 每项私有资源有明确拥有者和授权入口，接口与页面消费逐项对应 |
| P1 邮箱账号 | 账号存储、邮件验证、登录/退出、找回、会话和页面 | 可验证注册并跨浏览器登录同一账号；重置撤销旧会话；限速与凭证单次消费通过 |
| P2 用户隔离 | 作品目录、应用状态、模块、模型连接、凭据、任务与事件隔离 | 两账号全链路互不可见；猜 ID、路径、任务与事件重连不能越权；模型工具同样受限 |
| P3 订单与权益 | 接正式身份，网站账单适配、幂等下单、通知、查询恢复、退款申请与执行 | 代付不改变归属；重复/乱序通知仅发一次权益；关闭页面仍可确认订单 |
| P4 模型计量 | 代理、预留、流式结算、跨窗口、异常恢复、额度页面 | 多作品并发不超额、不重扣；取消/崩溃不永久占额；订阅到期数据仍可读写 |
| P5 部署与支付联调 | 真实域名、HTTPS、邮件、生产配置、产品开通、进程与备份 | 生产不回退沙箱；正式支付权限和部署均确认；恢复演练与受影响模型单例通过 |
| P6 上线验收 | 两账号浏览器流程、真实支付及退款核验、接口和文档核对 | 有完整证据后才标记上线；材料提交或静态检查通过不等于正式收款成功 |

云资源与域名准备可提前开展；公网写作开放在 P2 通过之后。套餐最终数值与真实交易条件在 P5 前确定；本计划更新不触发采购、产品开通、生产写入或真实扣款。

## 五、验收与执行约束

| 验收组 | 必测结果 |
|---|---|
| 账号 | 伪造、过期与重复验证失败；未验证不可登录；退出/重置后旧会话不可用；邮件限速有效 |
| 隔离 | A 不能读取、修改、删除、导出 B 的作品，不能查询其任务、事件、连接、私有模块与凭据；至少验证一次模型工具越权读取被拒绝 |
| 存储 | 路径穿越、压缩包越界、符号链接与任意目录打开被拒绝；后台恢复仍保留用户范围 |
| 付款 | 未登录不下单；伪造金额无效；回跳不发权益；验签失败不入账；重复通知/查询并发不多发权益 |
| 归属 | 同一邮箱重新登录取回原作品与权益；支付宝代付归购买账号；邮箱与支付标识不能互相冒用 |
| 额度 | 月卡窗口与体验卡总额分别验证；跨作品并发、重试、跨窗口、流式中断及退款均可收敛 |
| 部署 | 正式域名 HTTPS、邮件送达、敏感配置、内部端口不可公网访问、通知/后台查单与备份恢复均有证据 |
| 体验 | 登录失效保留草稿；购买后权益刷新；到期和耗尽不阻止阅读、编辑、导出；错误遵循项目格式 |

开发时按阶段运行相关离线测试与浏览器用例，发布前再执行必要的广泛回归；只改计划或版本号不跑后端全量。需要真实模型时使用 `.env` 在线模型，不使用本地模型，不短时间大量重复；失败修复后先做单例验证。真实支付、退款和产品开通按当时明确授权及支付宝流程执行，不把沙箱通过标为生产通过。
