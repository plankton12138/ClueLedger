# 0.7 故事资料开发计划

日期：2026-10-23。状态：**待实施**。本文依据当前源码与 0.6 模块说明制定；代码示例用于说明拟定契约，尚未接线。

## 1. 目标与范围

让作者能直接回答四个问题：有哪些资料、依据哪些章节、现在是否可用、如何补充或重新整理。
把「索引」「状态」抽屉整理为独立的「故事资料」页面，并补齐每类资料的完整任务流程。
成功标准是作者能在时间线页面独立完成「选章节 → 整理 → 看结果 → 对照原文」，随后在其余资料页面使用相同操作习惯。

本轮入口与页面：

- 主页面导航：**写作、故事资料**。活动记录保留已有独立入口，本轮不重做其日志与版本功能。
- 故事资料左侧导航：**章节概览、人物、时间线、线索与伏笔、名词表**。
- 不开放「检查报告」独立页面，不显示未开放的导航或占位按钮。已有对话内检查与报告回看继续按原契约工作。
- 作品正文和设定仍由对话修改；资料页只读查看，明确启动的整理任务只发布派生资料，不获得作品文件写权限。
- 不做手工资料编辑器、关系图、自动整理、自动修稿、自动重试、跨任务队列或整书无人值守扫描。
- 不把参考图中的多事件故事时间轴照搬成承诺：本轮时间线保留现有「每章一个时间锚点」，按章节顺序展示，不自动推断故事发生的真实先后。

页面导航改变不要求用户先整理资料才能写作；来源陈旧或资料缺失也不阻断普通对话。

## 2. 已核对的现状与需要补齐的能力

现状入口：[0.6 模块说明](../v0.6/modules/context-and-materials.md)。关键代码位于 `frontend/src/components/workspace/` 与 `src/hastings/workspace/`。

| 当前行为 | 本轮调整 |
|---|---|
| `WorkspaceShell` 用局部开关打开 `ChapterIndexPanel`、`StatePanel` 抽屉 | 建立可恢复位置的主页面与资料子页面；保留写作阅读位置、会话、草稿和参考 |
| 全局「刷新」重读目录、版本与当前文件，不重新调用模型 | 移至作品操作中的「重新读取文件」；资料页按需显示局部「重新读取资料」 |
| 章节索引已有摘要、事件与证据，一次最多 10 章 | 改为章节概览，复用存储与发布校验，调整展示和任务归属 |
| `update_disclosure`、`update_state` 借用 `index_paths` 传角色小传，强制选择 1–10 份 | 新任务明确指定资料域、正文章节和可选角色；时间线、线索、名词表不要求先选人物 |
| `mode=state` 同时提供多个状态域的保存工具 | 新任务只提供目标域的发布工具，并在工具执行时再次核对域和目标 |
| 状态构建函数已有截止章参数，但作者侧 `/state` 接口未提供选择 | 资料页读接口明确截止章，返回实际采用的时点 |
| 当前状态视图省略部分原文位置、版本和失效记录 | 提供作者阅读用的完整条目、证据和有效性，避免只剩无法定位的警告文字 |
| 名词表已有查询，缺少前端页面 | 增加只读名词表、分类、冲突提示和独立整理入口 |
| 缺条目无法区分「未执行」与「执行后无发现」 | 新增带来源版本的整理覆盖记录，支持明确的空结果 |
| 资料操作调用当前会话 `send()`，复用草稿清理和选择切换逻辑 | 新增资料任务提交适配层，保留写作草稿，任务详情仍复用现有执行事件 |

现有材料读取区间、源指纹校验、活动日志与作品级单任务约束继续复用。UI 改名本身不能解决上述任务和数据缺口。

## 3. 页面结构与用户流程

### 3.1 公共结构

```text
线簿   作品选择       写作  故事资料       活动记录  字号  设置
──────────────────────────────────────────────────────────
章节概览 │ 时间线                         查看截至 [第 8 章]
人物     │ [选择章节：第 6—8 章]       [从章节整理时间线]
时间线   │ 第 6—8 章尚未整理
线索伏笔 ├───────────────────────┬────────────────────────
名词表   │ 按章节排列的资料       │ 选中条目的原文依据
         │                       │ 章节、引文、来源状态
```

左侧是页面导航；中间是主要内容；右侧是按需展开的同页详情，宽屏并列，窄屏在内容区内切换并保留返回位置。
不再用覆盖整个写作台的多层弹窗承载资料管理。选择章节可以用轻量选择器；长列表、整理结果和证据留在页面中。

顶栏显示页面导航与作品级操作；资料页内显示该类资料的操作。每个当前任务场景只有一个主要按钮。
保留暖白内容区、蓝灰界面和适量衬线标题，减少凸起渐变按钮、重复框线和常驻说明。
选中状态、来源和操作结果用布局及简短标签表达；不出现 `roster`、`recipe_version`、`index_paths` 等内部词汇。

### 3.2 两个范围必须分开

- **查看截至第 N 章**：控制页面展示的历史时点，默认采用当前阅读章；无法定位时显示全书当前末章，并明确实际选择。只用于作者浏览，不修改写作任务既有截止章。
- **本次整理哪些章节**：明确选取的正文文件集合，一次 1–10 章；默认预选当前查看范围内缺失或失效的前 10 章，并显示完整已选清单。
- 在第 8 章视图中选择未来章节时，必须先明确切换查看时点；服务端也拒绝超出本次截止章的目标。
- 章节数量按真实文件计算，不按「末章减首章」计算；章序重复或无法解析时，相关条目可阅读，但时点相关整理须先解决定位问题，不能猜测顺序。
- 选中范围不会自动跟随任务期间的导航改变。切换页面或查看时点也不修改已经受理的任务。

选择截止章影响的是正文事实，不是完整设定的保密权限。人物小传和作者计划可按需展开，清楚标为设定或计划，不混进「截至此章的正文事实」。

### 3.3 五类资料

| 页面 | 主列表及详情 | 明确的任务操作 |
|---|---|---|
| 章节概览 | 章序章名、摘要、整理状态；详情列事件、人物、地点、线索及原文依据 | 整理所选章节 |
| 人物 | 人物列表；选中后分区查看小传、身份披露、位置/生死/立场、最近依据章、作者计划 | 在身份区「核对身份披露」；在状态区「从章节整理人物状态」，每次只执行所选一类 |
| 时间线 | 每章的原文时间说法、跨度、地点；未知时间明确显示；点击查看依据 | 从章节整理时间线 |
| 线索与伏笔 | 未回收、已回收、已废弃；埋设章、计划章、回收依据；过期与计划到期分开 | 从章节整理线索 |
| 名词表 | 人物、地点、组织、物件；正名、别名、首次依据章、来源；冲突逐项显示 | 从章节整理名词 |

人物任务额外选 1–10 个人物小传；没有人物文件时说明需要先在对话中建立小传。其他三类状态任务无需角色前置条件。
人物状态未提供生死依据时展示未知，不能为了满足当前 `alive` 布尔字段而猜测存活；本轮通过不发布该人物状态并记录「信息不足」处理，不扩大既有状态模型。
时间线只有章级锚点，不增加按日历排序、同章多事件排序或自动推断持续时间。
名词表完整展示作者数据，搜索与分类在资料查询上执行，不受模型上下文中每类 24 个词的注入预算截断。
计划回收章和已废弃属于作者决策；模型不得仅凭「读完后没再出现」自行设定期限或废弃线索。

### 3.4 整理一次的完整反馈

1. 作者选择范围，按钮文字明确要整理的资料种类；操作本身就是启动授权，不增加二次确认。
2. 受理后原位置显示任务条：范围、实际模型、当前步骤、已处理目标数、停止与查看活动记录。
3. 步骤以真实事件为依据，显示「已处理 2/3 章」，不显示估算百分比或虚构模型思考过程。
4. 作者可切换资料页或返回写作；任务继续，作品级运行提示可返回来源页面。
5. 成功后重读受影响的资料。结果区列新增/更新条目、无发现的目标、未完成的目标；部分发布不能显示整批完成。
6. 失败或停止保留已经成功发布的资料；只由作者重新选择未完成范围启动下一次，不自动重试。
7. 从证据处选择「带到对话」时，仅把版本化参考加入所选写作草稿，不自动发送、不覆盖已有文字；返回资料页保留定位。

资料任务执行记录有独立归属，不被挂到当前随意选中的写作会话。为复用执行层，每次新任务创建带来源标记的专用会话；正常写作会话列表默认只列写作会话，资料任务通过本页和活动记录回看。
同一请求键只对应一次任务。创建会话、受理和返回响应必须处理响应丢失与进程中断，不能重发后多建会话或多调用模型。

## 4. 数据状态和原文依据

### 4.1 覆盖状态与资料有效性分开

| 状态维度 | 取值与含义 |
|---|---|
| 整理覆盖 | 未整理、已整理有结果、已整理无发现、信息不足/未完成 |
| 版本有效性 | 当前有效、来源已修改、来源已删除、无法读取、旧规则不再适用 |
| 执行状态 | 已受理、运行中、完成、部分完成、失败、已停止、中断 |

来源变化后保留旧结果供查看，标明旧依据，且不作为当前有效事实注入模型。
无发现记录也带目标全文指纹；正文变了之后同样失效，不能继续显示「已经核对无结果」。
「无发现」只证明模型已读完并提交了空结果，不保证作品里客观不存在该信息；语义准确性仍需在线样例判读。

覆盖的最小单位：章节概览/时间线/名词/线索为「资料域 + 正文路径」；人物身份和状态为「资料域 + 人物路径 + 正文路径」。
只整理第 6—8 章时，不宣称第 1—5 章已整理。合法空结果与读取失败、模型预算耗尽、未提交结果必须分开。

### 4.2 证据结构

每个正文事实提供来源路径、源指纹、章节、字符区间与原文引文；人物声明提供小传位置与来源类型。
已有摘要与状态记录不能只返回拼接后的说明文本。作者视图应能定位无效条目，并指出是哪一份依据变了。

```typescript
// 拟新增 api/storyMaterials.ts；展示对象与模型上下文对象分开。
type MaterialDomain =
  | "chapter_index" | "disclosure" | "roster"
  | "timeline" | "clues" | "glossary";

type SourceEvidence = {
  path: string;
  digest: string;
  chapter: number | null;
  start: number;
  end: number;
  quote: string;
  freshness: "valid" | "stale" | "source_missing" | "unavailable";
};

type Coverage = {
  domain: MaterialDomain;
  path: string;
  entityPath?: string;
  digest: string;
  outcome: "found" | "empty" | "insufficient";
  taskId: string;
  recipeVersion: number;
};
```

打开证据时再次核对当前文件指纹。相同版本才按字符区间高亮；不同版本显示保存的原引文及「来源已修改」，可另读当前原文，不用旧下标高亮新文本。
不承诺还原任意历史全文；目前可以保存证据引文，历史全文是否可回看取决于对应 Git 版本是否存在。
证据读取沿用文件网关，路径、作品归属和可读边界不由 URL 或浏览器参数绕过。

### 4.3 发布与重建

- 每个目标读完当前版本后，提交一份完整结果或明确空结果；相应资料和覆盖记录在同一个域存储更新中原子替换。
- 第一版使用既有 JSON 域存储并扩展其版本化封装，不引入第二份事实数据库。记录、覆盖和最后发布标识一起以临时文件替换落盘。
- 活动事件不是资料成功的唯一证据。落盘后崩溃而事件未写完时，任务仍标中断，重读可见已发布目标，不自动补跑。
- 整理某几章只替换其负责的条目，不清空其他章、其他角色或其他域。局部成功不回滚已经发布的其他目标。
- 线索跨章关联使用稳定条目 ID；选中回收章可以更新已有线索的回收字段，但必须保留并复核原埋设证据。选中章之外的埋设事实不得被顺带改写。
- 名词的来源去重与线索去重不能只靠当前文字覆盖：重建某章删除一条发现时，不删除其他章节仍有证据支持的同一条目。存储需保留各来源的贡献。
- 作者计划、声明与正文观察分开保存；正文整理不得清空、生成或改变作者计划。已有来源不明的计划字段保留为旧记录，不伪装成新任务推导结果。
- 旧记录可查看；没有覆盖信息时显示「整理范围未知」，不从存在一条锚点推断整章已完整核对。不得在升级时自动启动模型。

## 5. 后端与任务契约

### 5.1 新任务的明确范围

新增 `purpose=organize_materials`，不继续用 `index_paths` 承载新资料任务。
一个任务只更新一个域：`chapter_index`、`disclosure`、`roster`、`timeline`、`clues`、`glossary`。
前端五页对应六个域，人物页包含身份和人物状态两项独立操作。

```python
# 拟新增 workspace/material_tasks.py；最终使用项目既有错误格式。
class MaterialTaskScope(BaseModel):
    domain: Literal[
        "chapter_index", "disclosure", "roster", "timeline", "clues", "glossary"
    ]
    chapter_paths: list[str] = Field(min_length=1, max_length=10)
    entity_paths: list[str] = Field(default_factory=list, max_length=10)
    as_of_chapter: int = Field(ge=0)
    observed_digests: dict[str, str] = Field(default_factory=dict)

    @model_validator(mode="after")
    def check_entities(self) -> "MaterialTaskScope":
        needs_entities = self.domain in {"disclosure", "roster"}
        if needs_entities != bool(self.entity_paths):
            raise ValueError("人物资料需选择人物；其他资料不接受人物目标")
        return self
```

以上模型只负责结构。服务端受理继续完成：去重、真实路径归类、文件存在性、章序唯一性、截止章、指纹与作品归属校验；不相信客户端自行声明的章号或来源版本。
资料页发起时必须带本次选择看到的源指纹，受理冻结目标与依赖的小传版本，并沿用开始执行和发布前复核。
额外找到的支持依据允许按网关读取，但不能扩大输出目标。状态查询固定截止章，发布未来章的依据被拒绝；读取更早埋设章不代表它成为可修改目标。
所有新字段纳入同键请求一致性校验，字段不同不能返回旧任务假装成功。

模型收到的任务说明由冻结范围生成，明确列出资料种类、目标章节与人物、截止章、必须读完的文件、允许提交的结果和每个目标的完成条件。正文内容仍通过受控读取提供，不把目录或旧摘要当作读过全文。
资料整理上下文只装与该域有关的内容：时间线直接读正文；人物域补充所选小传；线索域允许读取既有线索的埋设依据；名词域带现有正名与别名用于关联。旧记录明确标为待核对资料，不能替代当前原文证据。
资料任务不回放某个写作会话的无关历史，不默认注入全书谜底和作者计划。身份核对必要时可看所选小传中的声明与计划，但发布工具仍须区分它们与正文已披露事实。

### 5.2 工具权限和完成条件

复用只读目录、搜索、原文读取与材料账本。新资料任务不包含 `write_file`、`edit_file`、`move_file`、`delete_file` 或检查报告发布工具。
旧 `mode=state` 的广泛发布工具不直接复用到新路径；每个域只装配自己的结果提交工具。

```python
# 概念示例：限制应同时存在于工具装配与提交处理器中。
def publish_target(run, scope, target, result):
    require_allowed_domain(scope.domain, result.domain)
    require_allowed_target(scope, target)
    run.materials.require_target_read(
        run.workspace, ReadRequirement.full(target.path)
    )
    check_current_source_versions(run.workspace, target, result.evidence)
    check_all_evidence_in_supplied_ranges(run.materials, result.evidence)
    # 空结果也经过同样的完整读取和版本检查。
    return publish_result_and_coverage_atomically(target, result)
```

人物域还需完整读取所选小传；跨章线索需复核埋设和回收两端的原文依据。章号、精确引文区间与本轮实际读取范围继续使用现有校验，不能因新页面而降级。
结果提交接受 `found`、`empty`、`insufficient`；空结果必须带简短说明并确认目标已完整读取。`found` 不允许零条记录，`empty` 不允许附带条目。
章节概览对有正文的章节必须提交摘要；不能用空结果绕过摘要生成。时间线允许明确记录没有时间信息，人物状态的信息不足不冒充该人物不存在。
没有调用结果提交工具的目标保持未完成，即使模型回复「已经整理完」也不能算成功。
完成度由服务端目标清单与已发布覆盖记录计算；正常结束但仍有未完成目标，任务按部分完成显示。
索引可使用已有发布逻辑适配该协议；只读工具通路、版本核对不重写两套。

### 5.3 接口与前端接线表

以下为拟新增契约，前缀均为 `/api/file-workspaces/{workspace_id}`。

| 接口 | 用途 | 前端调用位置 |
|---|---|---|
| `GET /story-materials/{domain}?as_of_chapter=N&limit=100&cursor=...&q=...` | 作者视图：条目、版本状态、证据摘要、覆盖统计、有效截止章 | 各资料页面；人物页分别请求两域 |
| `GET /story-materials/{domain}/entries/{id}?as_of_chapter=N` | 完整条目及证据；稳定 ID，不接受任意磁盘路径作为记录 ID | 同页详情与原文定位 |
| `POST /material-tasks` | 接收请求键和 scope，创建独立任务归属并调用现有 TurnService | 整理按钮 |
| `GET /material-tasks?domain=...&limit=20&cursor=...` | 恢复本域最近任务，包含仍在运行的任务 | 页面进入、刷新和返回 |
| `GET /material-tasks/{turn_id}` | 规范化目标结果、进度及未完成项，含 conversation_id | 当前任务条与结果区 |
| 既有会话事件订阅与停止接口 | 持续进度、停止；不新建第二条 SSE 协议 | 共享任务订阅层 |
| 既有受管文件读取接口 | 读取并核对当前原文 | 原文详情 |

任务创建返回 `turn_id`、`conversation_id`、`origin`、冻结范围与已选模型；HTTP 受理不等于整理完成。
资料查询的分页必须返回 `next_cursor`、总量或明确的剩余状态；统计覆盖整个筛选范围，不能用当前页条数冒充总量。排序和过滤在服务端分页前完成；游标绑定查询和资料修订，失效时提示重新读取，避免漏行和重复行。
搜索、截止章和域改变时重置分页。正文不存在、资料为空、服务不可用分别处理。
作者视图的数据适配器直接读取已有域存储，不调用给模型使用的预算裁剪函数，不把计划披露通过作者视图接回写作上下文。

旧 `/state`、`/chapter-index` 和已保存会话事件继续兼容；旧用途只服务既有调用，不用于新页面。新增字段有缺省值，旧事件无来源标记时按普通写作会话处理。
`organize_materials` 必须贯通 API 校验、受理持久化、用途分发、上下文装配、工具装配、结束结果、启动恢复、活动日志和前端事件类型；尤其不能让未知用途落到当前默认的 `write` 模式。

### 5.4 单任务、幂等和恢复

`material-tasks` 是现有轮次服务的适配入口，不是另一套执行器。写作和资料整理共享作品级执行互斥。
作品忙时返回明确冲突，页面提供「查看正在运行的任务」，不暗中排队；是否停止由作者决定。
请求键和新会话标识在服务端可恢复地绑定，同键请求先查既有受理再尝试创建。受理后响应丢失，客户端用原键核对结果，不再生成新键重发。
任务元数据与结果以既有轮次记录和域发布记录为依据；查询索引允许重建，不能成为另一个独立任务状态真相。
断线时恢复既有事件订阅；停止、切页、切作品、关闭浏览器不能触发新模型调用。服务重启沿用中断标记，不自动续跑。
跨窗口发起也服从服务端互斥；前端的 disabled 只是交互反馈，不作为并发保护。

## 6. 前端模块与页面状态

### 6.1 页面导航和状态保留

采用 hash 路由表示页面、资料类别、截止章和选中条目，适配当前静态资源托管与桌面入口；无需新增服务器页面路由。
示例：`#/workspaces/{id}/materials/timeline?chapter=8&entry=...`，写作为 `#/workspaces/{id}/writing`。
进入未登记作品时回到作品选择，不把 URL 当成本机任意路径读取指令。不存在的条目保留所属页面并显示状态，不白屏。

```typescript
type WorkspacePage =
  | { kind: "writing"; workspaceId: string }
  | {
      kind: "materials";
      workspaceId: string;
      section: "chapters" | "characters" | "timeline" | "clues" | "glossary";
      chapter: number | null;
      entryId?: string;
    };

// WorkspaceShell 仍承载作品、模型、字号与运行状态；子页面切换不重置会话 store。
// 路由解析器必须校验枚举、章号及 URI 解码失败，并支持浏览器前进/后退。
```

写作滚动位置按作品+文件恢复；资料列表选中项、筛选和滚动按作品+资料页恢复。
任务订阅放在作品级状态层，不挂在页面组件的生命周期上。离开页面仅停止无用的数据读取，不停止已经受理的任务。
正文和设定仍沿用 Paper 阅读；带到对话时复用现有参考机制，不复制原文冒充作者消息。

### 6.2 建议模块边界

| 模块 | 主要职责与示例位置 |
|---|---|
| 页面外壳 | `WorkspaceShell.tsx` 拆出 `WritingPage.tsx`；`navigation.ts` 解析主页面和资料位置 |
| 资料容器 | `components/materials/StoryMaterialsPage.tsx`：左侧导航、截止章和内容区 |
| 六域展示 | 五个页面组件；人物详情内部明确调用 disclosure/roster 两域 |
| 通用资料操作 | `ChapterRangePicker`、`MaterialTaskBar`、`EvidencePane`、`CoverageStatus`，共享交互但不强行把五页做成同一张表 |
| 作者视图接口 | `api/storyMaterials.ts`，保留明确的域返回类型，避免以任意 JSON 充当契约 |
| 页面数据状态 | `state/storyMaterials.ts`：按作品、域、截止章和查询缓存，处理迟到响应与失效 |
| 任务状态 | `state/materialTasks.ts`：提交、恢复、停止与进度；复用底层事件消费，不复用会清空草稿的 send |
| 后端作者视图 | `workspace/story_materials.py`：已有状态存储到完整作者视图、证据与覆盖的转换 |
| 后端任务范围 | `workspace/material_tasks.py`：目标校验、受理适配、域权限和结果归并 |
| 既有执行层 | `service.py`、`agent.py`、`context.py`、`state.py` 及各状态 store 按明确扩展点修改 |

```typescript
// 页面只负责提交明确范围；没有会话草稿清理、默认发送或自动重试。
async function organizeTimeline(scope: MaterialTaskScope) {
  const accepted = await materialTasks.start({
    workspaceId,
    requestKey: crypto.randomUUID(),
    scope: { ...scope, domain: "timeline" },
  });
  materialTasks.observe(accepted.conversationId, accepted.turnId);
}
```

同一次未确认受理请求保存并复用请求键，直到得到受理或明确拒绝；上例新键只在一次新的作者操作开始时生成。
数据读取应使用 AbortController 或请求代次校验。作品 A 的旧响应不能写入作品 B，也不能覆盖作者刚切换的截止章。
字号继续使用既有 80%–150% 偏好；常规正文不再大面积使用 10px 小字。150% 字号与窄窗口时，操作区换行，详情改为内容区内切换，避免全页横向滚动。
导航、范围选择、任务停止和证据定位支持键盘与焦点反馈；状态变化使用适量的无障碍播报，不连续朗读全部日志。

## 7. 分阶段实施与退出条件

阶段按依赖执行；每阶段结束记录实际改动、验证与未完成项。不把仅能渲染的页面标为完整交付。

| 阶段 | 交付内容 | 退出条件 |
|---|---|---|
| A：页面结构与阅读基础 | 主导航、故事资料容器、hash 位置恢复、公共视觉和字号适配；章节概览先接已有只读数据 | 不开放检查报告入口；切换/刷新/前进后退不丢草稿；真实数据可阅读；新增任务入口尚未接线时不展示假按钮 |
| B：时间线完整流程 | 作者视图、原文依据、明确章节范围、资料任务受理与域限制、覆盖记录、独立归属、进度和恢复 | 无人物文件也能整理时间线；页面可见结果及证据；空结果/陈旧/部分完成/停止均可区分；原正文及其他状态域不变 |
| C：章节概览与人物 | 索引任务接入通用流程；人物身份与状态两个域独立操作；小传/事实/计划分区 | 章节摘要正常生成；人物与章节范围同时有效；早期章视图不泄漏未来正文事实；原写作草稿保留 |
| D：线索与名词表 | 两页只读视图和独立任务；跨章线索证据、稳定 ID、来源贡献、重复名称与冲突 | 无人物前置依赖；局部整理不删除无关来源；不虚构计划期限；名词完整列表不受注入预算限制 |
| E：迁移、回归与交付 | 撤销旧索引/状态抽屉入口和无调用组件；迁移回归、在线验收、模块说明、运行说明与导航 | 五个资料页全部完成闭环；既有写作/参考/检查/日志/版本/字号回归通过；运行版本同步至 0.7.0 |

第一段优先完成 B 的真实闭环再展开剩余页面。A 阶段只读页面属于中间产物，不代表故事资料功能已完成。
不为追求视觉一致把模型设置、版本历史或活动日志一并重写。旧检查回看入口的回归是兼容要求，不意味着开放独立检查报告页面。

## 8. 测试与验收计划

### 8.1 后端确定性验证

用受控 provider 和真实临时作品覆盖边界，不用它替代模型语义验收：

1. 时间线/线索/名词任务接受纯章节目标，人物域必须同时有合法小传和章节；越界、重复章序、缺源和超 10 章返回结构化错误。
2. 新用途绝不进入写工具模式；错误域、未选章节、未选人物与未来章发布被处理器拒绝，域存储保持不变。
3. 全文未读完不能提交完整或空结果；精确引文、实际读取范围、章号、指纹任一不匹配均拒绝。
4. 受理后、运行中及发布前外部改源；旧依据查看；来源删除、规则版本变化；空结果的失效。
5. 域内原子更新、局部替换、多来源去重、跨章线索回收；失败不污染其他目标和其他域。
6. 同键重复/同键不同参数/受理响应丢失/并发双窗口/创建后崩溃；只有一份有效受理和一次执行。
7. 停止、断线、重启中断、预算耗尽、部分发布；无工具提交的「完成」文本不算完成。
8. 截止章下的身份披露、人物回退状态、未来回收线索还原；作者计划不进入写作状态分区。
9. 旧数据可读、旧会话可恢复、旧接口兼容；缺覆盖不自动补跑；作者列表分页与模型注入预算互不影响。

### 8.2 前端和浏览器验证

- 单元测试聚焦路由恢复、分页和迟到响应、请求键生命周期、事件归并、草稿隔离与任务结果归并。
- 浏览器检查完整导航、选择章节、任务反馈、原文定位、外部改源、返回写作、刷新后恢复、停止与部分完成。
- 草稿隔离用非空文字和已有参考测试，不能只用空会话；资料任务运行期间切会话、切页、切作品都要覆盖。
- 测试 1440×900、1024×768、窄窗口，以及 100%/150% 字号；检查阅读层级、按钮换行、键盘顺序、选中和返回位置。
- 复用并迁移既有索引 E2E；既有活动记录、文件版本、字号与对话内检查用例继续执行，不靠删除断言消除回归。

### 8.3 在线模型语义验收

使用 `config.yaml` 配置的在线模型，运行前核对实际模型名但不打印凭据；报告记录本次实际使用的模型，不把历史 `deepseek-flash` 结果当作本次证据。
准备小型作品，包含明确时间词、无时间信息、角色身份披露、前后章状态、跨章线索回收、同名/别名及无新名词章节。

| 样例 | 必须观察的结果 |
|---|---|
| 无人物小传，整理 3 章时间线 | 可独立完成，有依据的时间词保留原表达；无信息章提交空结果或明确不足 |
| 整理 2 章概览 | 摘要和事件可定位到本次完整读取的版本；不修改正文 |
| 核对人物身份与状态，分别启动 | 只发布各自域；未知状态不编造；未来披露不进入早期正文事实 |
| 只选回收章整理已有线索 | 保留早期埋设事实，复核两端证据并更新回收；无授权不生成作者计划 |
| 整理名词及没有新名词的章节 | 正名/别名依据可读，冲突不自动合并，空结果可见 |
| 任务途中停止或外部改源后重新整理 | 部分结果诚实展示，新旧依据区别明确，不暗中重试 |

在线端点故障、模型语义失败、产品接线失败分别记录；原始失败证据保留。修复后重新验证不抹掉首次失败，不以提高重试次数获得通过。
全量 Python、前端测试、构建、Ruff/mypy 和相关浏览器回归按阶段涉及范围执行；最终汇总只写本次实际结果。图像原型和静态页面截图均不构成功能验收。
