# 真实案例：悬疑长篇的写前构思与资料整理

测试对象：`c32cbaa feat(v07): 故事资料页与六域整理任务`
模型：在线端点 `api.deepseek.com`，`deepseek-flash`（`/api/model-connections` 读取，非本地模型）
作品：`data/test-tmp/real-case-20261023-e27994ea/雪山温泉案例`
方式：浏览器提交真实对话，资料任务从界面发起；每个阶段只跑一次，失败不重试、不覆盖。

## 一、阶段与开销

01-original 的 16 次文件变更 = 15 份小传 + 《真相》一次改写；《线索》是作品初始化时预建的空文件（`458dd3c`），这一轮没有写入，模型的「线索文件没有动」属实。

## 二、成立的能力

1. **证据校验拦住了错引。** 时间线第一次 `publish_material_result` 返回 `[STATE_EVIDENCE_INVALID]`（引文与区间不一致），模型重新 `read_file` 定位后第二次成功。这是本次唯一一次发布失败，机制按设计工作。
2. **计划披露与正文披露分开。** 荒井十三的小传声明 `planned: 元警视厅警部 → 第 3 章`；第一章核对结果只记「正文刻意留白」，并明确写「此时未披露其元警视厅警部身份」。
3. **人物状态不猜生死。** 三名出场人物 `alive=true`、`lag=0`，位置与立场都带原文依据；未出场人物保持未整理。
4. **名词表区分来源。** 15 条 `declared`（来自小传，`first_chapter=0`，无正文依据）与 6 条 `text`（来自第一章，带引文）分开列出。
5. **文件范围有效。** 写章回合 `changed_paths` 只有 `正文/0001 六点的白鸦馆.md`，没有改动设定文件。
6. **失效提示清楚。** 改动正文后界面显示「有结果 1 · 未整理 0 · 已失效 1」，逐条说明「依据已改过或删除，不再采用」；人物页说明「只采用仍有效的记录与声明」。
7. **重跑可恢复。** 重跑章节概览后 `stale` 归零，摘要更新为「晚八点」，与改动一致。

## 三、发现的问题

### P1 本轮暂缓项没有被执行，产物越界

原始提示词写明「暂不需要：具体的作案手法，调查过程，能够刻画人物的情节」。实际《真相》3920 字，八个分节：

| 分节 | 是否在本次委托内 |
| --- | --- |
| 一、十二年前的罪 | 在（死者与真凶的旧事） |
| 二、现案（凶手、为何必须长期同住、设备为何没救他、为何选这一夜） | 部分越界：写到 2:00—2:20 上传窗口、改报警阈值、厂家封印黑盒 |
| 三、为什么能认定是他杀 | 在 |
| 四、侦探为什么有权查 | 在 |
| 五、侦探的选择与栽赃 | 越界（调查过程与结局） |
| 六、两处指向真凶的暗示 | 越界（后续章节的叙事安排） |
| 七、每个人身上的疑点与洗清 | 越界（中后段设计） |
| 八、待定 | — |

`task_scope_set.summary` 只写「先建人物小传…并在真相文件中确定死者、真凶、旧罪、聚集理由、认定他杀依据、侦探权威」，没有登记「暂缓手法与调查」。范围校验只管文件路径，管不到内容边界。模型在最终回复里也自认「下一步按你原来的要求，应该先不动手法细节」。

### P2 线索的 `supports` 把《真相》写进台账，而该字段会进入写作上下文

9 条线索的 `supports` 全部引用真相分节，例如：

- 「对应《真相》四：荒井是元警视厅搜查一课警部…因此有现场委托与初步询问的资格」
- 「《真相》七里列为疑点人物（遗产、与曽根崎的密约），中期洗清」

`clues_section()` 会把 `supports` 拼成「｜指向：…」注入写作上下文（`src/hastings/workspace/clues.py`，预算 500 字、最多 8 条）。`_DOMAIN_RULES["clues"]` 只要求「登记读者能观察到的线索」，没有约束 `supports` 的写法。

结果是：写下一章时，模型可能拿到「谁可疑、谁中期洗清」的作者答案，与「真凶开篇不能特殊、其他角色也要有怀疑点」的要求冲突。本次没有直接读到写作上下文（没有暴露该接口），结论来自台账数据与 `clues_section` 代码。

### P3 资料任务标题固定显示「第 0 章」

`src/hastings/workspace/api.py:774`：

```python
numbers = sorted(int(path[:4]) if path[:4].isdigit() else 0 for path in scope.chapter_paths)
```

章节路径是 `正文/0001 六点的白鸦馆.md`，`path[:4]` 取到 `正文/0`，`isdigit()` 为假，落到 0。七个资料任务全部复现「整理…：第 0 章」，而 `scope` 里是 `as_of_chapter=1`、`chapter_paths=[第 1 章]`。活动记录里作者看到的标题与实际范围不一致。

### P4 失效粒度是整份文件

把「傍晚六点」改成「晚上八点」后：

- 章节概览、时间线、3 名人物、9 条线索全部 `stale`，包括引文段落没有变化的条目；
- 名词表行为不同：6 条 `text` 名词直接从列表消失，只留 6 条「原文登记已失效，暂不采用」警告，`coverage.stale=1` 但列表里看不到条目；
- 恢复需要重跑任务（章节概览 5 次请求、129 秒）。

保守设计可以理解（引文可能整体移位），但「改一个词 → 整章资料失效」在长篇里会频繁触发，且各域表现不一致。

### P5 写前资料没有存放位置（与模块灵活性直接相关）

`12-custom-docs` 要求建立《创作要求》《环境设定》《世界观》三份独立资料，结果：

- `set_task_scope` 直接拒绝：`[TASK_SCOPE_DENIED_CONFLICT] 范围只能登记作品内的确切文件路径：设定集/创作要求.md`；
- 模型没有把内容塞进《真相》，改为在对话里输出三份文本，并说明「暂时做不到」；
- 路径白名单在 `src/hastings/workspace/context.py:107` 与 `files.py` 的 `SETTING_FILES`。

同一回合还暴露另一个缺口：新会话读不到原始提示词（模型自述「你最初那条消息不在我能读到的历史里」），只能从《真相》反推创作要求，篇幅与章长标为「待确认」。**创作要求需要持久资料，不能依赖对话历史。**

另外，线索页不读 `设定集/线索.md`：`ClueStore` 只读状态目录的 `clues.json`（`clues.py:113`、`story_materials.py:481`）。作者写前设计的线索即使写进《线索》，也不会出现在「线索与伏笔」页，也不进写作上下文。

### P6 单章规模下工具开销偏重

第一章 1170 字：

- 章节概览 18 次工具调用，其中 16 次读同一份正文（为每条依据定位字符区间）；
- 线索 32 次调用（20 次读取、10 次 `search_text`）；
- 人物状态 22 次调用（18 次读取，4 个文件）。

依据要求「路径、版本、字符区间、引文」，模型反复定位，成本主要来自证据定位而不是内容理解。对「一章两千字、全书十几万字」的目标规模，这类开销会按章累加。

## 四、对两个待定方向的结论

**任务拆分。** 本次最直接的证据是 P1：一个 455 秒的回合里写出 16 个文件与 3920 字《真相》，`task_scope` 只登记了文件路径与一句 summary，没有「本轮交付什么、暂缓什么」的可核对清单。范围控制对文件有效（P5 反证：越界路径会被拒），对内容无效。第一步应先补「暂缓项 + 结束时逐项核对」，而不是先做步骤编排。

**模块灵活调整。** 不是改导航名称的问题。新增一类资料要同时改：受管路径白名单、作用域校验、目录展示、写作上下文按需读取、版本与失效记录。P5 说明当前连「新建一份自定义文档」都走不通。可行顺序是先在 `设定集/` 下放开通用资料目录（保留线索、真相为固定名），再接侧栏与写作读取，最后才做自定义整理字段。

## 五、建议的修复顺序

1. `api.py:774` 改为取文件名前四位（`path.rsplit("/", 1)[-1][:4]`），并补一条标题断言测试。
2. `task_scope` 增加「本轮暂缓项」字段，结束时按项核对并在回复里报告未完成项。
3. `_DOMAIN_RULES["clues"]` 约束 `supports`：只写读者可见的另一种解释，禁止引用《真相》分节；或在 `clues_section` 注入前剥离引用。
4. 统一失效表现：名词表保留失效条目并标注，不直接从列表消失。
5. 放开 `设定集/` 下的通用资料文件，接入导航、写作读取与版本记录；之后再评估自定义整理字段。
