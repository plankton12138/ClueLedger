# Phase 19 默认启动入口修复

日期：2026-10-16。问题来自用户实际启动 `uv run python -m hastings.server` 后，
当前前端的 V2 REST 请求全部 404、业务 WebSocket 握手被拒绝。

## 交付内容与关键决策

根因是默认服务仍把 `--v2-db` 当作 V2 启用开关，未带参数时只挂载旧接口，
却照常托管当前前端。模型未配置提示与缺少路由是两个独立问题。

- 标准启动始终装配当前 V2 工作台；`--v2-db` 只负责选择数据库。
- 默认复用现有 `data/v2.db` 或 `data/v2.sqlite`，都不存在时创建前者。
- 两种文件同时存在时明确退出，要求显式指定；不选择“看上去更新”的库，不搬移或合并数据。
- 启动日志打印实际数据库绝对路径，便于判断浏览器项目编号是否属于当前仓库。
- 保留现有 `create_app` 的可选运行时注入，旧测试/只读接口的装配契约不变。

## Agent 设计经验

1. **错误消息是模型 API**：数据库歧义说明哪里错、为什么不能猜、怎样用参数解决；
   模型配置错误不能掩盖路由装配错误。
2. **硬约束放工具层**：当前界面依赖的运行时在启动入口强制装配，不靠用户记住隐藏参数。
3. **泄压阀**：没有数据库允许新建；已有唯一库应恢复；多个库要求明确选择，三个情形分开处理。
4. **可观测性属于契约**：能访问健康检查不足以证明工作台可用；测试须通过默认启动生成的应用验证
   项目 API、WebSocket、同库重启恢复，日志也必须能定位实际数据源。
