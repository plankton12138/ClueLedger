# Phase 17 补充：V2 七页作者工作台

> 日期：2026-10-15。承接已落盘的 iOS 6 主题、客户端与应用骨架。
> 前置与迁移收口见 [phase-17-migration-cleanup.md](phase-17-migration-cleanup.md)。
> 本文记录前端重构的 as-built，不替代原迁移、性能和人工验收记录。

## 1. 为什么这样设计

旧界面以会话、文章和账本工具为入口，作者难以判断讨论、候选与正式作品之间的边界。
新界面用同一个项目身份串起「规划 → 正文 → 事实变更 → 影响 → 分支试改 → 作者审阅」，
使版本、候选与批准范围成为可见的产品信息。原型中的示意分数、预设发现与作品数据不进入运行界面。

## 2. 交付内容

1. 七页与统一外壳：项目概览、创作台、故事账本、变更影响、修订审阅、悬疑审计、作者模型。
   蓝色金属顶栏、分段导航、浅色分组面板、凸起按钮与纸面编辑器复用原型语言；桌面三栏、窄屏纵向布局。
2. 项目概览读取正文、事实、变更和任务计数；新建、编号找回与模型档案收进设置抽屉。旧工作区迁移已按[退役决策](phase-17-workspace-retirement.md)移除。
3. 创作台读取并保存 V2 正文，支持导入新章、从指定 Commit 恢复。规划/写作候选只有作者接受后才提交。
   冲突保留草稿；切章/切项目/重新读取要求处理脏稿；窗口关闭提示；异步响应按项目代次隔离。
4. 故事账本展示 Canon 与叙事计划，三层事实分开过滤，搜索结果可以定位正文或故事对象。
   常用文本字段修改进入变更集，保留完整对象内容；复杂结构继续由规划候选承载。
5. 变更影响与修订审阅保留同一个变更身份：发起、分析、计划、批准、分支执行、差异生成、逐项接受/拒绝、风险原因与合并。
   既有种子提案默认进入人工执行候选，额外修订仍限制于计划对象。空差异是合法审阅结果。
6. 审计展示真实发现、定位、证据版本与修复提交，不生成未经定义的公平性评分。
7. 作者模型展示编辑前后、分类置信度、偏好来源与作用域，支持显式声明与带原因撤销。
   新增 `interfaces/api/author_decisions.py` 两个薄出口：`POST .../author-model/preferences`、
   `POST .../preferences/{id}/revoke`，复用原领域命令和统一提交，不修改领域状态机。
8. 业务事件按 sequence 去重、携带游标重连，密集帧合并刷新；任务进度单独轮询。
   所有内容从查询接口回读，事件不充当第二份作品状态。

## 3. 关键决策与边界

- **两张修订页、一个变更身份**：分析范围与审阅正文是不同决策，分开页面便于作者理解；仍共享服务端变更集，避免两套执行状态。
- **正文缓冲高于刷新**：收到事件时，干净正文可以读取新版本；已有编辑只标记过期，不用新版本冲掉输入。
  保存期间继续输入时，回执只推进已提交基线，保留更新的草稿。
- **前端不代签授权**：批准使用展示详情的 head，合并使用作者明确选择的 hunk；版本变化由服务端拒绝并给出修正方向。
- **只做已有领域能表达的裁决**：作者可声明与撤销偏好；候选激活仍服从已有归纳规则，不用视觉开关模拟不存在的命令。
- **项目登记不是事实源**：浏览器仅记编号与名称；故事内容以服务端仓库为准。当前没有服务端项目目录查询，跨浏览器需编号找回。
- **主编是任务面板**：V2 工作者按任务无状态运行，页面不把它包装成有隐式长期记忆的聊天。
- **测试入口同步换代**：旧 j1–j8 对应被替换的 V1 壳，保留为历史材料；默认浏览器质量门切到 V2 真服务旅程，未删除旧旅程。

## 4. Agent 设计经验

### ① 错误消息是喂给模型的 API

正文冲突与作者裁决冲突原样展示原因和恢复方向，保留原输入供作者合并。错误不能只显示「操作失败」，
也不能将服务端拒绝改成前端成功提示。偏好接口在旧页面提交时返回 `REPO_HEAD_CONFLICT`，要求刷新并核对证据。

### ② 硬约束放工具层，prompt 只解释世界

作者的批准、偏好声明和撤销均经既有用例提交。页面只组织选择，不实现另一套授权或状态机。
V1 旧写路径继续由后端退役约束；新壳所有作品写入均指向 V2。

### ③ 泄压阀：违规、空结果与环境故障

空账本、零审计发现、无差异审阅均是正常结果，显示下一步而非虚构样例。
模型未配置、任务失败与版本冲突保留各自的原因和重试入口；任务完成不等同作品已接受。

### ④ 可观测性是事件契约的一部分

业务事件推进 sequence 游标，用于刷新事实；任务过程不混入业务序列。重复帧不重复刷新，重连先补齐。
页脚区分项目版本、正文基础、上次保存与脏稿；候选卡显示接受后的正式提交，避免用动画或任务状态冒充写入证据。

## 5. 验证与评审记录

- 行为测试先行：项目晚到响应、脏稿切换、保存冲突释放忙状态、保存期间继续输入、事件乱序与去重。
  先复现缺少浏览器存储防护/事件处理器，再补实现，6 项通过。
- 前端单元测试：30 文件、280 项通过；生产类型检查与构建通过。
- 真服务浏览器旅程：6 项通过，覆盖七页与 390px 窄屏、规划/写作/接受、保存冲突与恢复、
  项目切换脏稿保护、两种差异裁决、审计/导出、旧工作区预检确认迁移、偏好声明撤销。
  工作者为测试替身，不作为真模型质量走查证据。
- 后端相关回归：73 项通过（正文、作者裁决、Agent、变更、WS 与迁移）；新增作者裁决测试先以 HTTP 405 失败，
  补出口后验证同键重放、陈旧页面拒绝、撤销保留历史。
- 模型档案回归：86 项通过。新设置表单省略未更改的环境密钥来源，服务端区分「未提供」与「明确清空」，
  避免只换默认模型时丢失认证配置；本地免密状态同样保留。新增用例先复现来源丢失再修复。
- 视觉走查：逐页检查 1440×900 截图；修复 CSS 令牌原名/别名错位造成的规则消失，
  以及 `list-item` 与工具类同名造成的布局覆盖，并补真实计算样式断言。
- 未修改 `tau_agent` / `tau_ai`；未迁移或删除用户工作区，迁移旅程只使用临时测试目录。

七页截图见 [artifacts/frontend-workbench/](artifacts/frontend-workbench/)，对应真实服务与确定性工作者测试数据。

## 6. 后续边界

复杂结构的可视化编辑、服务端项目目录与更丰富的版本浏览不在本次七页主流程内。
历史恢复当前通过明确的来源 Commit 进行；设置使用服务级模型档案。发布安装包与真实模型质量验收沿用原阶段记录，不由前端替身测试代替。
