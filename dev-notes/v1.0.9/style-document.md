# v1.0.9 Aqua 视觉实施规范

日期：2026-11-02。状态：**P5 已实施；P6 最终截图与在线场景验收待执行**。本文件约束 v1.0.9 的组件与页面视觉；实现见 [P5 记录](notes/p5-aqua-and-cleanup.md)。

参考资料将经典 Mac OS X Aqua 概括为直观、明亮、有水滴感的界面，并通过顶部受光、半透明光泽、圆润控件和银灰材质建立层次。v1.0.9 采用这些结构特征，同时保留长篇写作所需的低干扰稿纸。参考：[少数派《Mac 视觉史（三）：浴“水”重生的 Mac 视觉美学》](https://sspai.com/post/60888)。

## 1. 目标与边界

目标不是复刻某一代系统截图，而是让线簿的操作层级更接近 Aqua：

- 工具区与内容区可以立即区分。
- 主操作、普通操作、选中和按下状态有明确反馈。
- 界面明亮、有材质层次，但正文不会被高光和渐变干扰。
- 连续分栏和边界承担解释作用，减少重复标签与说明。
- 相同控件在写作、灵感、模块库、设置和对话中使用同一状态规则。

不增加假的系统标题栏、红黄绿窗口按钮、装饰性玻璃球、拟物图标集合或没有功能的高光。宿主已经提供的系统外框不在网页内复制。

## 2. 三层材质

### 2.1 Chrome：应用与工具层

适用：顶栏、写作工具条、分栏标题、对话工具条、对话框按钮区。

- 使用从上到下的银白、浅灰、稍深灰三段渐变。
- 顶部保留 1 像素内高光，底部使用清楚但不发黑的边界。
- 工具条之间用边界和材质变化分层，不用重复的卡片标题。
- 可使用非常轻的拉丝或噪点纹理，但不得影响文字清晰度；若产生摩尔纹或截图噪声，直接取消纹理。

### 2.2 Control：可操作层

适用：按钮、输入框、分段控制、选中行、滚动与进度反馈。

- 普通按钮为银灰胶囊或圆角矩形；主按钮为蓝色顶部高光渐变。
- 按下状态要内陷，不能只把颜色变深。
- 输入框内部比工具区更亮，带细内阴影；聚焦时使用蓝色外环，不改变布局尺寸。
- 选中行使用浅蓝背景和较深蓝边界；只有主导航当前项可以使用高饱和蓝色。
- 禁用状态降低对比并去除强高光，同时保留文字可读性和禁用原因。

### 2.3 Content：创作内容层

适用：正文稿纸、全书构思、章节摘要、信息原句、模型候选正文。

- 正文使用温和浅纸色和深灰文字，不使用蓝色渐变背景。
- 内容区域尽量平整，只用细边界、留白和段落节奏区分。
- 模型候选与正式内容通过位置、标题和边界区分，不用强烈警示色。
- 错误、成功、差异颜色只说明语义，不承担主要布局。

## 3. 全局 token

所有材质从全局 token 获取，业务组件不得写新的 Aqua 渐变常量。建议分组如下：

| 分组 | token | 用途 |
|---|---|---|
| Chrome | `--aqua-chrome-top/mid/bottom` | 顶栏和工具条三段材质 |
| Border | `--aqua-border`、`--aqua-divider` | 控件外框与分栏边界 |
| Light | `--aqua-inner-light` | 顶部内高光 |
| Primary | `--aqua-blue-top/mid/bottom` | 主按钮和当前主导航 |
| Selection | `--aqua-selection`、`--aqua-selection-border` | 列表与信息项选中 |
| Paper | `--paper`、`--paper-ink`、`--paper-subtle` | 正文与构思内容 |
| Semantic | `--danger`、`--warning`、`--success` | 错误、待处理和完成事实 |
| Focus | `--focus-ring` | 键盘焦点；不可由阴影替代 |

颜色值先沿用现有视觉语言并统一命名，再通过真实页面截图微调。不要为了接近参考图一次性替换全部颜色。

## 4. 控件规则

### 4.1 按钮

| 状态 | 普通按钮 | 主按钮 |
|---|---|---|
| 默认 | 银灰三段渐变、顶部内高光 | 蓝色三段渐变、白字、清晰外边界 |
| 悬停 | 高光略增强，边界略清楚 | 上半部略亮，不扩大阴影 |
| 按下 | 下移 1 像素或等效内陷，内阴影 | 颜色稍深并内陷 |
| 键盘焦点 | 2—3 像素蓝色外环 | 外环仍可见，不能被蓝色按钮吞掉 |
| 禁用 | 去高光、降低对比、禁止按下动画 | 同左；说明原因可从焦点或邻近提示读取 |
| 忙碌 | 保持按钮宽度，标签说明实际动作 | 同左；不只显示无文字转圈 |

同一区域只有一个默认主操作。例如空正文区中“自己写第一段”是主按钮，“由模型起草”和“看看方向建议”是普通按钮；模型生成完成后“采用候选”可以成为候选区域的主按钮，但不能与全页主操作竞争。

### 4.2 输入与编辑器

- 标签直接说明要输入的内容，例如“这一章要改变什么？”，不再附加同义副标题。
- 模型动作紧邻输入，但不占用输入标签；无模型时保持原位置并给出禁用原因。
- 聚焦、错误和只读状态各自可辨。错误边界不能清除当前蓝色键盘焦点。
- 正文编辑器保留稿纸背景、舒适行高和足够宽的插入光标；工具按钮位于稿纸上方 chrome，不浮在正文上遮挡文字。
- 自动保存状态位于工具条一处：`正在保存`、`已保存`、`保存失败`；索引状态另行说明，避免把“正文已保存 / 索引更新中”混成一个结果。

### 4.3 分段控制与导航

- 顶部作品导航只保留“写作”和“模块库”；当前项使用 Aqua 蓝色选中。
- 全书构思与章节属于左侧目录列表，不再用顶部标签模拟页面。
- 分段控制仅用于同一内容的局部视图，例如候选“预览 / 对比”；不用于恢复构思、线索两套页面。
- 选中项不再重复显示“当前”副标签，`aria-current` 和视觉选择足够表达。

### 4.4 对话框与菜单

- 对话框顶部为轻量银灰标题区，正文为平整内容区，按钮区固定在底部。
- 危险动作不使用蓝色主按钮；保留明确危险色和二次确认。
- 菜单行高度统一，图标只在能帮助识别时使用；不为每行增加解释性小字。
- 文本生成候选不是模态对话框，避免阻断作者继续写作。

### 4.5 进度与模型运行

- 确定进度使用 Aqua 蓝色进度槽；不确定运行使用克制的移动高光。
- “模型生成中”和“信息索引更新中”是两个任务，分别显示目标和停止 / 重试动作。
- 遵循 `prefers-reduced-motion`，关闭循环高光移动；保留静态文字状态。
- 完成后状态自动收敛为普通结果，不保留长期成功横幅。

## 5. 连续稿纸页面

### 5.1 宽屏（≥ 1200）

```text
┌────────────── Aqua 顶栏 / 作品与全局操作 ──────────────┐
├──── 目录 ────┬──────── 连续稿纸 ────────┬── 页边索引 ─┤
│ 全书构思     │ 本章任务（一行，可展开） │ 对齐相关段落 │
│ 第一章       │                          │              │
│ 第二章       │ 正文编辑                 │ 或对话       │
└──────────────┴───────────────────────────┴──────────────┘
```

- 目录与辅助区使用银灰 chrome；正文使用纸色。
- 页边索引不是完整第三页，只显示与视口段落相关的简短信息；复杂内容在同一区域展开。
- 打开对话时替换页边索引，正文宽度不突然变化；关闭后恢复原选中信息与滚动位置。
- 本章任务最多占一至两行，展开修改时才占用更多空间。

### 5.2 中等宽度（760—1199）

- 目录与辅助区按需开合，一次最多保留正文加一个辅助区。
- 索引按钮显示实际待处理数量，但不显示装饰性统计。
- 辅助区覆盖或压缩正文的方式在 P0 以中文长段落验证；不得让正文窄于舒适阅读宽度。

### 5.3 窄屏（< 760）

- 默认只显示一个主要区域。
- 目录、索引详情和对话逐层进入；顶部保留明确返回动作。
- 与段落绑定的信息可以在该段落后以内联条目显示，但不在每段预留空白。
- 返回正文恢复光标、选区、滚动和未保存文字；不得重新挂载导致输入法或撤销栈丢失。

## 6. 字体、密度与图标

- 工具与界面文字使用系统无衬线字体；正文继续使用适合中文长篇阅读的衬线字体栈。
- 桌面正文起点为约 21px，窄屏不小于 18—19px；实际取值继续受现有字号设置控制。
- 正文行高约 1.8，段间距明显大于行间距；不以背景横线干扰中文标点。
- 工具按钮文字不小于 13px，点击目标至少 40×40 CSS 像素；紧凑工具可在桌面视觉上更小，但命中区域不缩小。
- 图标与文字一起出现时不重复相同含义；纯图标按钮必须有可访问名称和悬停标题。

## 7. 信息索引视觉

- `本章准备推进` 使用普通银灰或浅蓝信息项，不使用警告色。
- `已写入正文` 主要依靠准确原句与定位动作表达，不长期显示绿色“完成”标签。
- `正文新增` 使用克制的蓝紫边界，表示候选而非错误。
- `需要对齐` 使用琥珀色边界和具体差异文字；有意信息差不进入此组。
- 锚点失效使用中性错误说明并停止定位；不能用红色高亮整段正文。
- 同一信息多次出现按原句列出，避免用“出现 3 次”代替可定位内容。

## 8. 可访问性与输入可靠性

- 所有颜色组合在默认、悬停、选中、禁用和错误状态分别检查对比度。
- 键盘顺序遵循目录 → 工具 → 正文 → 辅助区，不因视觉列位置制造跳跃。
- 200% 浏览器缩放下不能出现水平页面滚动或被遮挡主操作。
- 高光、阴影和颜色不是唯一状态来源；按钮文字、`aria-pressed`、`aria-current`、状态文字共同表达。
- 中文输入法 composition 期间不自动保存或触发快捷键。
- 屏幕阅读器可读取正文保存状态、索引更新状态和模型候选状态，但状态变化不得高频打断正文输入。

## 9. 禁止项

- 不在每个内容块上使用高光渐变和厚阴影。
- 不用假的系统交通灯或假的窗口标题栏制造“像 Mac”。
- 不为 Aqua 新增第二套按钮、输入和对话框组件。
- 不把模型入口藏在悬停菜单或只用图标表达。
- 不用状态胶囊代替具体原句和差异说明。
- 不因追求复古而降低文字对比度、缩小命中区或关闭系统焦点。
- 不把作者绿色对话气泡改成与主操作相同的蓝色，避免对话身份与操作层级混淆。

## 10. 视觉验收集

每个阶段只更新受影响截图；P6 最终至少保留：

1. 空作品和全书意图，模型可用 / 不可用各一张。
2. 未构思章节前置区，人工输入、生成中、候选完成和过期状态。
3. 连续稿纸宽屏：正文、页边索引和准确定位。
4. 正文已保存 / 索引更新中，以及索引失败但正文保留。
5. 打开对话替换索引，关闭后恢复。
6. 1440、1024、760、640、390 宽度；100%、150%、200% 缩放关键组合。
7. 按钮与输入的默认、悬停、按下、焦点、禁用、忙碌和错误状态。
8. 键盘焦点、减少动态效果和高对比度检查记录。

截图只能证明布局和状态可见，不能代替模型、保存、索引和撤销的真实功能验收。
