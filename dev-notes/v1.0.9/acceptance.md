# v1.0.9 验收计划

日期：2026-11-02。状态：**发布门槛，尚未执行；按“正文为主”修订版制定**。本文件定义需要取得的证据，不是通过记录。真实实施结果只写入后续 `notes/` 和必要的 `artifacts/`。验收对象包含 P6 拆门槛改造的完成情况。

## 1. 发布判断

v1.0.9 必须同时满足四项，任何一项未完成都不能宣称交付：

1. 从空作品建立意图、直接写第一章正文到确认候选入账，可以在一个写作工作区连续完成；章节没有构思确认步骤。
2. 应用内任何正文写路径都不能绕过全书构思门槛；作品已有意图即可写任何章节。
3. 所有创作性文本输入都有人工路径和可见的模型路径，模型结果不覆盖作者输入。
4. 正文与章节信息索引基于同一最新修订更新，失败和过期结果不会冒充当前状态；确认入账是原子联合提交且可整体撤销。

Aqua 视觉、旧页面撤除、前后端接口清理和版本一致性同样是发布门槛，不能作为发布后的补做项。

## 2. 验收样本

### 2.1 主样本：《雪夜旅馆》

沿用[真实可用性用例](../../product-design/research/ideas-clues-usability-cases.md)：

- 作品起点：暴雪封山的旅馆发生命案，林砚从仍在滴水的手套开始怀疑管家，手套之后会有另一种解释。
- 第一章正文直接写：封山、林砚入住、管家给出不在场证词、章末出现湿手套。没有章节构思步骤。
- 正文计划外信息：壁炉火钳上的蓝蜡。
- 后续信息：第五章雪停记录、第八章洗手套证词、第二十四章回收。
- 语义边界：管家说自己一直在房间是角色证词；22:05 搬尸是作者真相，不能泄露给第一章读者视角。

### 2.2 边界样本

- 完全空作品、无可用模型和模型运行中断。
- 同章两处相同引文、同名不同信息线、引文缺失与歧义。
- 含 emoji 和非 BMP 汉字的原文、中文输入法合成、超长中文段落。
- 两个浏览器窗口同时修改同章、外部编辑器修改和作品尚无全书构思时的外部正文。
- 200 章、300 条故事信息线、每章多次出处的大作品。
- 作者隐藏真相、角色谎言、读者已知和模型猜测并存。
- 连续多章没有任何信息变化的空章写作。

所有样本使用隔离目录，不写入作者实际作品。旧格式不作为迁移样本；v1.0.9 直接测试新当前格式。

## 3. 第一轮真实流程

第一轮严格按 UC-P01—UC-P06 连续执行，不在每步重置作品。

| 编号 | 操作 | 必须观察到的结果 |
|---|---|---|
| P01 | 空作品中手写一句作品意图 | 建立短全书构思；未知真相保持未知；不创建批量章节；同一输入旁可见“交给模型构思” |
| P01-M | 清空新样本，不输入文字，选择“交给模型构思” | 提供多个可继续的悬疑起点候选；未采用不进入正式构思；人工输入仍可用 |
| P02 | 点击第一章（空正文） | 直接显示可编辑空白稿纸；自己写是默认状态；“由模型起草”与“看看方向建议”可见；无构思输入、无确认步骤 |
| P03 | 手写第一章正文（封山、入住、管家说谎、湿手套放结尾）并保存 | 正文可编辑并可靠保存；无门禁拦截；无需进入构思 / 线索页 |
| P03-M | 在另一空章选择“由模型起草” | 候选不自动写入；采用并保存后正文与绑定建议在同一最新修订；可撤销正式采用 |
| P04 | 手写计划外的蓝蜡细节并继续写 | 先保存正文；增量索引稍后显示候选及原句；不弹分类框、不阻断输入 |
| P04-M | 在又一空章选择“看看方向建议” | 返回方向参考文字；只可阅读与复制；不进入正式数据，不自动写正文 |
| P05 | 确认湿手套候选入账 | 同一联合提交创建信息线、信息变化与绑定；页边索引显示已写入与准确原句；回执可整体撤销 |
| P05-M | 移动已入账的湿手套原句并保存 | 绑定在保存响应中立即重定位；索引无需刷新；点击双向定位仍准确 |
| P06 | 连续保存一章无信息变化的过渡章 | 空章反馈温和出现且可忽略；页边索引只列待确认候选与需要对齐项；不出现章节确认或“开始写作”步骤 |

第一轮需要记录：总页面切换次数、必须填写的文本数量、模型调用次数、从输入到正文保存的时间、索引返回时间，以及测试者是否能回答“本章写了什么、哪些信息已经入账、哪句正文承载哪条信息、还有什么待判断”。不预设性能结论；先记录同环境数据。

## 4. 确定性与浏览器矩阵

### 4.1 数据、门槛与写入

| 编号 | 场景 | 必须结果 |
|---|---|---|
| A01 | 新当前格式 round-trip | 作品意图、章节、信息线、信息变化、知情边界和多出处不丢失 |
| A02 | 空意图 / 空信息线确认 | 服务端拒绝并只指出一个实际缺口，不生成字段清单 |
| A03 | 作品无全书构思时人工保存正文 | `BOOK_INTENT_REQUIRED`；无文件、Git 或候选副作用 |
| A04 | 作品无全书构思时 Agent 创建 / 修改正文 | 与 A03 同一错误，不能绕过策略 |
| A05 | 作品无全书构思时采用模型候选 | 保存拒绝；候选保留，未产生正文 |
| A06 | 作品已有全书构思的人工 / Agent / 模型写入 | 全部通过同一策略；章节自身无需任何构思输入；回执来源可辨 |
| A07 | 章节创建事务中途失败 | 章节登记和文件一并回滚；无法回滚时准确报告残留并阻止继续 |
| A08 | 请求重试 | 同一请求键返回同一结果，不重复建章、写文或建绑定 |
| A09 | 两窗口同时保存 | 后到者保留本地草稿并看到摘要冲突，不覆盖先到者 |
| A10 | 外部正文 | 作品有意图：内容保留、可编辑并更新锚点；作品无意图：只读打开，补一句意图后恢复写入，不自动反向生成意图 |
| A10b | 确认入账失败与撤销 | 摘要或原句不匹配时拒绝且无部分提交；入账后整体撤销恢复信息线、信息变化与绑定，不修改正文 |

### 4.2 索引与双向影响

| 编号 | 场景 | 必须结果 |
|---|---|---|
| A11 | 已有绑定原句移动 | 保存响应中立即重定位，索引无需刷新 |
| A12 | 原句删除 / 恢复 | 高亮停止并显示失效；恢复唯一原句后重定位；不猜相似位置 |
| A13 | 同章多处出现 | 每处保留可定位出处，不合并成数量 |
| A14 | 重复引文 | 无唯一依据时为 ambiguous，不绑定任意一处 |
| A15 | 非 BMP 字符 | 码点区间、选段、定位和保存一致 |
| A16 | 快速连续保存 | 只发布最新摘要的语义结果；旧任务取消或 stale |
| A17 | 模型不可用 / 分析失败 | 正文成功保存；确定性索引可用；状态说明事实，不沿用旧语义结果 |
| A18 | 正文新增 | 仅形成候选；确认前不进入正式信息线和后续章节上下文 |
| A19 | 修改信息线 | 正文只显示需要对齐的影响；无明确授权不改原文 |
| A20 | 明确同步修改 | 信息线、正文、绑定联合提交或一并失败；回执与撤销完整 |
| A21 | 删除铺垫后撤销 | 后续回收影响立即更新；撤销后正文、绑定、索引和影响一起恢复 |
| A22 | 角色谎言与作者真相 | 有意信息差不显示普通冲突；作者真相不被证词覆盖 |

### 4.3 模型入口与候选

| 编号 | 场景 | 必须结果 |
|---|---|---|
| A23 | 创作输入清单 | 作品名、灵感、模块内容、构思、标题、正文、差异和对话均有可见模型动作 |
| A24 | 控制字段清单 | 搜索、路径、连接地址、模型 ID、密钥等不显示无意义模型动作；排除原因有登记 |
| A25 | 无模型配置 | 模型动作保持可见并禁用，说明设置方式；人工输入、保存不受影响 |
| A26 | 无作者文字发起 | 服务端依据目标生成任务；不要求用空格或固定提示词绕过非空校验 |
| A27 | 生成期间继续输入 | 作者文字持续可编辑；结果旁置，不覆盖新稿 |
| A28 | 候选基础修订过期 | 只能比较、复制或重新生成；不能直接替换当前内容 |
| A29 | 停止、失败、刷新与恢复 | 人工草稿保留；活动 / 已完成候选状态准确；放弃结果不重新弹出 |
| A30 | 下一步建议 | 选择建议只填入对话框，不自动发送或执行修改 |
| A31 | 采用选段 / 插入光标 | 只改变明确范围，编辑器撤销可恢复；保存仍走普通写入契约 |
| A32 | 候选绑定 | 服务端重新核对当前原句与摘要；模型给出的错误区间不能成为正式绑定 |

### 4.4 页面、导航与编辑可靠性

| 编号 | 场景 | 必须结果 |
|---|---|---|
| A33 | 顶部导航 | 作品内无构思、线索入口；只有写作及独立全局能力 |
| A34 | 旧模式 URL | 回落到统一写作页；不恢复旧页面或旧编辑入口 |
| A35 | 全书 / 空正文章节 / 已有正文章节 | 同一主区域呈现对应状态；没有四栏并列 |
| A36 | 中文输入法、撤销、复制粘贴 | composition 不触发中途保存；浏览器撤销与选区可靠 |
| A37 | 自动保存失败 | 本地文字和撤销栈保留；错误与重试位置明确 |
| A38 | 切章、前进后退、刷新 | 未保存草稿受保护；旧响应不覆盖；光标和阅读位置按规则恢复 |
| A39 | 索引 / 对话切换 | 辅助区互相替换，关闭后恢复原信息项；未发送对话草稿不丢 |
| A40 | 全书信息线展开 | 可看到跨章变化与出处；不需要关系图、类型表或独立线索页 |
| A40b | 空章反馈 | 保存无信息变化的一章后提示温和出现、可忽略、不阻断输入；有信息变化时不出现 |

## 6. 在线模型验收

使用 `.env` 中配置的在线模型，不使用本地模型，不输出密钥。场景低频顺序执行，每项先执行一次；失败修复后只执行受影响单例，不在短时间内批量重复。

| 编号 | 作者动作 | 检查内容 |
|---|---|---|
| O01 | 空作品点击“交给模型构思” | 返回多个起点候选；不确定凶手与结局；未采用无正式写入 |
| O02 | 空正文章节点击“看看方向建议” | 依据全书构思与已完成章节给出方向参考文字；不进入正式数据，不自动写正文 |
| O03 | 空正文章节点击“由模型起草” | 候选遵循全书构思与知情边界；未采用不写正文 |
| O04 | 模型起草中作者继续手写 | 作者稿不被覆盖；模型结果显示依据的旧草稿并标记处理方式 |
| O05 | 已有正文点击“让模型续写” | 从当前选择或光标继续，只使用全书构思和允许前文 |
| O06 | 手写蓝蜡细节 | 增量分析提出正文新增及准确原句，不自动决定含义或入账 |
| O07 | 已确认信息线与正文真实矛盾 | 指出具体两边内容并给处理候选；不静默改任一方 |
| O08 | 对话框点击“给我下一步建议” | 给出可发送的具体指令；选择后只填入，不执行 |
| O09 | 第一章读者视角分析 | 实际模型输入和回复不泄露搬尸、洗手套及未来回收 |
| O10 | 过期候选尝试采用 | 服务端识别基础修订变化并拒绝直接覆盖，人工稿保留 |

每个场景保存：目标、实际材料来源和修订、模型输出、候选状态、工具 / 写入记录、正式数据前后差异、浏览器结果和调用次数。只看到模型回复“已完成”而没有真实提交，或使用固定模拟回复，均不通过。

## 7. 性能与成本观察

在同一环境记录基线与候选结果，不在没有数据时写“性能达标”。

- 打开工作台首屏不得为每条信息发独立请求；全书和章节各以一次聚合读取为主，详情按需补充。
- 200 章 / 300 信息线样本记录首屏响应体、请求数、服务端耗时、浏览器稳定时间和内存。
- 自动保存记录合并次数、写请求数和冲突行为；每次按键不得发正文或模型请求。
- 增量索引记录变化段落字符数、实际模型输入、取消任务数、有效结果数和完成时间。
- 连续编辑同章时，同一时间最多一个活动语义索引任务；过期结果发布数必须为零。
- Aqua 阴影、渐变和页边定位不得造成明显输入延迟；中文长章滚动与输入需要人工观察和浏览器性能记录。

## 8. 测试节奏

- P6 拆门槛改造只运行受影响模块的后端、前端和浏览器定向测试；P1—P5 已按章节门槛设计实施并有记录。
- 写入策略、联合提交、会话受理或上下文装配实际变化后，在最终候选执行一次必要的后端广泛回归。
- 前端最终候选执行 `npm test`、`npm run build` 和本地浏览器项目；在线项目只运行 O01—O10 所需用例。
- 在线失败修复后只单例复验；不得因一次网络失败立即批量重跑。
- 文档或版本号单独变化不重复执行后端全量。
- 本次只制定计划：检查文件链接、范围、版本状态和文档一致性，不运行产品测试。

## 9. 清理与版本门槛

P7 发布前逐项核对：

- 前端没有正文 / 构思 / 线索三入口、章节门槛页、旧页面模式或隐藏高级入口。
- `start` 端点、`CHAPTER_PLAN_*` 错误码、`chapter_plan` 辅助类型与 `ChapterPlanGate` 组件已移除，消费者矩阵无残留引用。

- HTTP、Agent 工具、上下文和恢复消费者矩阵中没有孤立前端功能或无消费者业务接口。
- `pyproject.toml`、`src/hastings/__init__.py`、前端包与锁文件、`uv.lock`、健康检查和版本断言全部为 1.0.9。
- 产品、开发和实施记录区分“计划”“已实施”“已验证”，未执行在线场景不能写成通过。
- 根目录 README 未经作者要求不修改；`mynotes/` 无改动；工作树中的既有无关变化保持原样。
