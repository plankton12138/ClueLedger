## 1. 交付目标

v1.0.9 交付的不是把两个旧页面放进一个容器，而是重新建立一条连续创作链：

1. 作者先用一句话确定全书起点；这是唯一写作门禁。
2. 创建章节即可写正文，章节没有构思输入和确认环节。
3. 作者可直接写正文，也可让模型起草、续写或看方向建议。
4. 正文保存后，章节信息索引在同一页面更新准确原句、计划外信息和真实差异。
5. 线索、伏笔和回收由正文观察：语义分析给出候选，作者确认后同一联合提交创建信息线与绑定，可整体撤销。
6. 全书构思、正文、信息索引和对话都在一个写作工作区内完成。

完成标准不是“入口减少”，而是 UC-P01—UC-P06 可以从空作品连续走完，作者只写全书构思和正文，不维护节点、线索、关系、用途或状态字段。

P0—P5 按先前“每章最小构思门槛”设计实施，实施记录见 `notes/`；本节目标状态由 P6 拆门槛改造兑现。

## 3. 模块计划

### M1 当前格式：作品、章节与故事信息线

**修订（2026-11-02，正文为主）**：M1 已按“当前格式 3”（含章节构思与确认修订）实施；P6 将其升为当前格式 4，章节退化为顺序、可选标题和正文路径。以下设计为修订后目标，旧格式数据直接放弃。

**为什么**

旧模型可以表达复杂悬疑结构，但也把复杂度暴露给页面和对话。新页面若继续围绕节点和线索计划做适配，只会隐藏表单，不会减少作者需要维持的对象。

**设计**

- 保留 `StoryVariant` 作为内部修订根，以复用 `story_store.py`、联合提交、撤销和活动回执；界面和产品文案不出现该内部名称。
- 新当前格式只保存 `book_intent`、`chapter_plans`、`information_threads`、`information_moves`、`bindings` 和必要约束。
- `ChapterPlan` 只保存顺序、可选标题和正文路径；章节创建时即分配正文文件。章节构思、信息变化 ID、内容修订和确认修订不再存在。
- `InformationThread` 提供跨章稳定身份；`InformationMove` 表达某章发生的信息变化，由确认候选入账创建，不预先规划。引入、加强、转义、否定、回收等作用由系统推断或模型建议，不要求作者选择。
- 角色证词、作者真相、读者已知和模型建议保持不同来源；界面合并对象不等于合并语义。
- 正文绑定指向 `InformationMove`，继续保存路径、摘要、Unicode 码点区间、原句和来源。
- 格式版本提升为当前格式 4；格式 3 是已实施的中间格式，其数据直接放弃，不迁移。测试和验收全部创建隔离新作品。

**主要落点**

- 修改：`src/hastings/workspace/story_models.py`、`story_store.py`、`story_changes.py`、`story_tools.py`、`chapter_write_policy.py`。
- 适配：`story_bindings.py`、`story_context.py`、`story_clue_commit.py`、`activity.py`。
- 删除或退休：仅服务旧节点、阶段、线索关系图的当前格式投影和前端类型；必须先完成 P0 消费者清单。

**退出条件**

新作品能保存最小全书构思、两章正文、一条跨章信息线（通过确认入账创建）和多个原句绑定；修订冲突、幂等提交与撤销通过定向测试；旧格式明确拒绝或按“新建作品”处理，不进入半迁移状态。

### M2 服务端写作门槛、章节创建与确认入账

**修订（2026-11-02，正文为主）**：M2 已按“已确认章节构思才可写正文”实施（`ChapterWritePolicy.require_confirmed`、章节开始事务、`CHAPTER_PLAN_*` 错误码）；P6 将门槛对象从章节改为作品，移除开始事务与相关错误码，并新增候选确认入账。以下设计为修订后目标。

**为什么**

只在前端控制写作入口无法保证规则。当前 Agent 可以直接调用文件写入，应用内编辑和未来调用方也可能绕过页面。门槛必须位于所有正文写路径共同经过的服务层。门槛的对象是作品：作品已有全书构思即可写任何章节；章节不设前置。

**设计**

- `chapter_write_policy.py` 改为校验全书构思：作品意图非空即放行，否则拒绝。策略名称与实现随改造更新，注入方式不变。
- 在 `WorkspaceFiles` 注入写入策略，`check_write_intent`、`write`、`create_chapter` 统一调用；角色小传和设置文件不受写作门槛影响。
- 章节创建即建正文文件：在领域事务中校验全书构思、分配章节顺序与唯一正文路径、创建只含章节标题的初始文件并返回回执。失败回滚，不留下章节登记或文件其中之一。“确认构思并开始写作”环节移除，`POST /story/chapters/{id}/start` 端点删除。
- 正文保存接口要求 `expected_digest` 和 `request_key`；章节构思修订前提移除，正文并发由摘要控制。直接编辑、模型候选采用和 Agent 写入复用同一服务。
- Agent 的 `write_file / edit_file` 不能凭模型文字绕过策略；作品无全书构思时返回结构化错误。
- 新增确认入账：作者确认索引候选时，服务端重新核对候选依据的正文摘要与原句，在同一联合提交中创建信息线（若候选未指向已有信息线）、信息变化与绑定，返回可整体撤销的回执。入账不修改正文。
- 外部编辑器直接创建的正文不能从文件系统层阻止。重新读取时保留文件，不删除内容；作品已有全书构思则正常更新锚点，作品尚无意图时以“先补一句全书意图”只读打开，补齐后恢复应用内写入。
- 错误显示为：`[BOOK_INTENT_REQUIRED] 正文/作品：作品尚无全书构思。建议：先写一句全书意图，或选择“交给模型构思”。` 已实施的 `CHAPTER_PLAN_REQUIRED`、`CHAPTER_PLAN_STALE`、`CHAPTER_START_PARTIAL` 在改造中移除。

**主要落点**

- 修改：`src/hastings/workspace/chapter_write_policy.py`、`files.py`、`agent.py`、`api.py`、`service.py`、`materials.py`、相关任务授权与回执。
- 新增：确认入账端点与联合提交链路（复用 `StoryChangeService` 与 `story_clue_commit.py`）。

**退出条件**

人工保存、Agent 创建、Agent 修改、模型候选采用和重试都经过同一校验；作品无全书构思全部拒绝且不产生文件，已有全书构思全部可写；章节创建、确认入账、写入冲突和失败恢复通过。

### M3 实时章节信息索引

**修订（2026-11-02，正文为主）**：M3 已实施；P6 变更为索引去掉 `prepared`（本章准备推进）状态，语义分析输入中的章节构思换成全书构思与相关信息线。以下设计为修订后目标。

**为什么**

作者不再手工维持线索对象后，系统必须把正文和已确认信息线的对应关系及时呈现。同步分为确定性部分和需要模型判断的语义部分，不能把两者都变成后台黑箱。

**设计**

- 工作台只读投影返回全书或当前章的信息项、准确出处、差异和分析状态；`InformationIndexItem.placement` 只保留 `written`、`observed_candidate`、`alignment`。
- 正文保存先同步执行确定性工作：校验或重定位已有锚点、使删除原句失效、重算受影响的跨章信息。
- 保存响应直接携带最新全书、相关上下文、正文与索引修订及确定性结果，因此无需刷新。
- 手写新段落在保存后排队做增量语义分析。服务端按作品、章节和最新正文摘要合并任务；新修订取消或废弃旧任务。
- 语义输入只包含变化段落、相邻段落、全书构思和直接相关信息线；不重复发送整本书。
- 自动结果只能产生“正文新增”和“需要对齐”候选，不能修改正式信息线、正文或作者真相；确认入账走 M2 的联合提交。
- 保存后本章索引为空时，前端给出空章反馈与“让模型看看本章”入口；不拦截写作。
- 没有模型或分析失败时正文仍保存成功，索引显示 `unavailable / failed` 及真实修订；旧分析不能继续标为最新。
- 模型生成正文的候选可在同一候选中携带绑定建议；采用时仍由服务端核对原句和当前修订。

**主要落点**

- 修改：`story_workbench_view.py`、`story_index_jobs.py`、`story_bindings.py`、`story_index.py`、`materials.py`、`service.py`、`operations.py`、前端 API 和状态缓存。
- 已完成替代：`story_chapter_view.py`、`ChapterContext.tsx`。

**退出条件**

保存后立即看到确定性变化；增量结果无需刷新出现；快速连续保存只采用最后修订；失败不回滚正文；同章多处、删除、恢复、重复原句、非 BMP 字符与跨章影响全部有测试；空章反馈出现且可忽略。

### M4 所有创作文本的模型候选

**修订（2026-11-02，正文为主）**：M4 已实施；P6 将 `AssistKind` 中的 `chapter_plan` 移除，新增 `chapter_direction`（章节方向建议，依据全书构思与已完成章节提出参考文字，不进入正式数据）。以下设计为修订后目标。

**为什么**

如果只有部分输入提供模型入口，作者仍要先理解何时应该自己组织文字、何时可以请求模型。本版把它固定为通用交互契约：创作内容可以直接写，也可以从模型候选开始。

**设计**

- P0 清点所有 `input / textarea / editor`，区分创作内容与控制信息。凡是作品名、章节名、灵感、模块内容、全书意图、正文、差异处理和对话指令，都登记人工与模型路径；搜索、路径、连接地址等控制信息排除并记录原因。
- 新增通用 `CreativeTextField` / `ModelAssistAction` 契约。模型动作名称按上下文表达，例如“交给模型构思”“由模型起草”“让模型续写”“看看方向建议”“给我下一步建议”，不使用含糊的统一“AI”按钮。
- 新增目标化辅助请求。客户端只发送目标类型、对象身份、基础修订和可选作者补充；服务端生成可审计的任务意图，并复用现有会话、材料、模型选择、流式与停止恢复链路。
- 支持 `book_intent`、`chapter_direction`、`title`、`prose_draft`、`prose_continue`、`alignment_resolution`、`idea`、`module_content` 和 `next_action`。
- 生成结果保存为有目标、有基础修订的候选。作者可采用全部、采用选段、插入光标或放弃；采用才进入正式保存和联合提交。方向建议候选只能阅读与复制，没有采用动作。
- 生成期间作者可继续输入。若输入修订改变，结果进入旁置候选并标记所依据版本，不能覆盖编辑器。
- 无模型时动作可见但禁用，显示设置入口；人工输入和保存继续可用。
- 同一目标同一时刻只保留一个活动请求；重试复用请求键，停止与重启遵循现有运行恢复。

**主要落点**

- 后端：`api.py`、`service.py`、`materials.py`、`story_candidate.py`、模型任务路由和状态存储。
- 前端：`components/ui/CreativeTextField.tsx`、`components/writing/ModelCandidate.tsx`；接入作品、灵感、模块、对话和写作相关输入。

**退出条件**

创作输入清单无漏项；无文字也能发起上下文模型辅助；作者输入不会被异步结果覆盖；过期、重试、停止、刷新恢复、无模型和采用失败都有明确行为；方向建议不进入正式数据。

### M5 单一导航与正文编辑

**修订（2026-11-02，正文为主）**：M5 已按“章节前置区 `ChapterPlanGate`”实施；P6 移除 `ChapterPlanGate`，空正文章节直接进入可编辑稿纸并提供三个起步入口。以下设计为修订后目标。

**为什么**

合并页面的核心是作者不再判断“现在去构思还是线索”。同时，当前应用只有只读稿纸；若不增加正文编辑，写作流程仍然无法形成完整的人工闭环。

**设计**

- `AppHeader` 删除构思、线索入口，只保留写作；模块库、灵感和活动记录保持原职责。
- 左侧 `WritingNavigator` 第一项为全书构思，其后为章节。路由保存 `book` 或 `chapter_id`，可选 `information_id`，不保存旧页面模式。
- 新增 `BookPlanView`、`ChapterEditor`。同一中部区域根据选择切换，不并列多张页面。
- 空正文章节直接显示可编辑稿纸，提供三个起步入口：自己写第一段（默认）、“由模型起草”、“看看方向建议”。作品尚无全书构思时正文只读并指向意图输入。
- `ChapterEditor` 提供可恢复的 Markdown 文本编辑、中文输入法、浏览器撤销、自动保存、明确保存状态和摘要冲突处理。P0 已用真实长章验证编辑内核；页面通过适配接口隔离选择。
- 保存采用乐观修订：自动保存合并连续输入；冲突时保留本地文字，提供对比和重试，不自动用服务端覆盖。
- 已有正文提供“让模型续写”；上下文为全书构思与允许前文。
- 旧 `mode=story / clues / chapter` 链接重定向到统一写作页；不保留隐藏旧入口。

**主要落点**

- 修改：`AppHeader.tsx`、`WritingLayout.tsx`、`WorkspaceToc.tsx`、`navigation.ts`、布局状态和 unsaved changes。
- 新增：`components/writing/BookPlanView.tsx`、`components/writing/ChapterEditor.tsx`、`state/writingWorkbench.ts`。
- 删除：`components/writing/ChapterPlanGate.tsx` 及其状态、样式与测试。
- 拆分或替代：`Paper.tsx` 的通用阅读渲染；退休 `StorySurface`、`ClueSurface`、`WorkspaceDetail` 作为日常入口。

**退出条件**

从空作品到第一章人工写作无需离开写作页；刷新、切章、前进后退、中文输入法、撤销和网络失败不丢文本；作品无全书构思时正文不可编辑，有意图即可直接编辑；空正文章节无构思确认步骤。

### M6 连续稿纸、页边索引与对话

**修订（2026-11-02，正文为主）**：M6 已实施；P6 移除“本章准备推进”清单（章节无构思计划项），页边索引只显示从正文观察出的信息，并新增空章反馈展示。以下设计为修订后目标。

**为什么**

用户已选择连续稿纸方向。索引如果仍是一张独立管理表，会重新制造页面切换和对象维护。它应靠近对应正文，同时在窄屏保持单一主内容。

**设计**

- 宽屏稿纸由正文列和页边注释列构成；索引项按源位置顺序对齐相近段落，点击双向定位。
- 页边索引只显示已写入、正文新增（候选）和需要对齐；同一信息的多处原句分别显示，不合并计数代替出处。
- “正文新增”和“需要对齐”只在存在时出现；不显示长期空分组和统计条。
- 保存后本章索引为空时，在稿纸下方或页边给出空章反馈与“让模型看看本章”入口；可忽略，不拦截输入。
- 1024—1199 宽度使用可开合辅助区；小于 760 宽度时，相关信息在段落后显示或逐层进入。光标、选区、滚动和未发送对话草稿必须保留。
- 打开对话时替换索引辅助区；发送时冻结当前章节、信息项或选段，页面后续选择不改变运行中的材料。
- 对话输入增加“给我下一步建议”；选择建议只填入输入区，仍由作者发送。
- 编辑中的临时文字不直接成为模型材料；自动保存成功并取得摘要后才可进入索引分析或对话快照。

**主要落点**

- 修改：`ChapterMarginIndex.tsx`、`InformationItem.tsx`、`WritingAuxiliary.tsx`、`WritingLayout.tsx`、`ConversationPanel.tsx`、讨论焦点、页面位置和响应式布局。

**退出条件**

1440、1024、760、640、390 宽度和 100% / 150% / 200% 缩放下只有一个主要写作面；索引与正文可双向定位；切换索引 / 对话不丢写作和输入状态；空章反馈出现且可忽略。

### M7 Aqua 组件系统

**为什么**

现有界面已有部分 Aqua 色彩和渐变，但材质、控件状态和页面层级分散在页面样式中。进一步接近 Aqua 应统一操作反馈和层次，不是给每张卡片增加光泽。

**设计**

- 在全局 token 中定义银灰工具区、浅色稿纸、蓝色主操作、浅蓝选择、边框、内高光、阴影和语义色。
- 统一按钮、输入、选择、分段控制、对话框、工具栏、滚动反馈和进度状态的默认、悬停、按下、焦点、禁用和忙碌状态。
- 顶部受光与内高光只用于控件和 chrome；正文、长列表和信息内容保持平整、安静。
- 连续分栏使用边界和材质变化说明层级，减少重复标题、副标签和说明文字。
- 不仿造宿主系统窗口按钮；不让装饰阻止键盘、对比度、200% 缩放和减少动态效果。
- 视觉回归覆盖完整状态，而不只截取默认首页。

**主要落点**

- 修改：`frontend/src/index.css`、`tailwind.config.ts`、`components/ui/Button.tsx`、`AppDialog.tsx`、输入和布局组件。
- 新增：必要的 token 与视觉回归页面；规则见 [style-document.md](style-document.md)。

**退出条件**

共享控件不在业务组件散写 Aqua 渐变；所有交互状态可辨认；正文阅读和输入对比度不下降；验收截图与键盘检查通过。

### M8 清理、接口对齐、验收与发布

**为什么**

v1.0.9 会替换多个旧投影和入口。若只隐藏前端，后端会保留无消费者接口；若先删服务，又可能破坏候选、上下文或撤销。清理必须依据消费者矩阵执行。

**设计**

- P0 建立页面、HTTP、Agent 工具、上下文装配、候选、恢复和测试的调用清单。
- 每完成一个新链路，登记替代关系；P5 删除确认无消费者的旧模式、组件、接口、样式和测试；P6 拆门槛改造的替代关系同样登记（`start` 端点、`CHAPTER_PLAN_*` 错误码、`ChapterPlanGate` 及相关测试）。
- 保留被提交、撤销、来源定位或材料装配继续使用的领域服务，即使旧页面已删除。
- 执行[验收计划](acceptance.md)：定向测试优先，最终候选才执行必要的广泛回归和低频在线模型场景。
- 在线模型使用 `.env`，不使用本地模型；失败修复后只复验受影响单例，避免短时间重复。
- 所有门槛通过后统一版本为 1.0.9，并更新当前文档与实际交付记录。

**退出条件**

前后端消费者矩阵无孤立 UI 或无消费者业务接口；旧导航与旧页面不可达；必需验收有证据；版本文件一致；未完成项如实保留，不以版本号代替完成。

| P5 视觉与清理 | M7、M8 | Aqua 状态完整；旧入口、旧页面和确认无消费者接口撤除；契约对齐 |

## 5. 关键接口完成顺序

2. `ChapterWritePolicy` 与章节开始事务。

1. 当前格式 4（章节退化）与 `StoryStore` 提交 / 撤销。
2. 写入策略改为全书构思校验；章节创建事务替代开始事务。

## 6. 风险与处理

| 风险 | 处理 |
|---|---|
| 空章反馈被长期忽略 | 提示可忽略是设计取舍；“完成本章”时再次列出待判断项；不强制补足 |
| 外部文件绕过规则 | 作品无全书构思时只读呈现并要求补意图；有意图时正常更新锚点，应用内写入仍受策略限制 |
| 起草上下文变薄 | 全书构思、已完成章节摘要和直接相关信息线进入上下文；提供“看看方向建议”入口 |
| 自动索引调用过多 | 保存后合并变化、按最新摘要取消旧任务、只传变化范围；不按键调用 |
| 语义索引误报 | 只成为候选；保留准确原句与置信依据；作者未确认不入账 |
| 生成结果覆盖作者输入 | 候选与编辑草稿分离；采用时核对基础修订；过期结果不能直接覆盖 |
| 新正文编辑器丢字或破坏中文输入 | P0 已用真实长章、IME、撤销和网络冲突验证；编辑内核封装在适配接口内 |
| 当前格式重构破坏提交 / 撤销 | 保留修订根和联合提交语义；先做领域测试，再接页面；不混做旧数据迁移 |
| 拆除已实施门槛引入回归 | P6 改造后重跑写入路径、联合提交、撤销和索引的定向测试；最终候选执行一次必要广泛回归 |
| Aqua 装饰降低可读性 | 光泽只放在控件与工具区；正文保持高对比；视觉与键盘、缩放同时验收 |
| 全局模型入口造成重复实现 | 用统一辅助协议和候选组件；P0 输入清单作为发布检查，不在各页面自建生成逻辑 |
