# 写作指引、空正文与连续稿纸布局调整

日期：2026-11-02。状态：**已实施并完成前端定向验证**。运行版本仍为 1.0.8；P6 在线模型与正式发布未执行。

## 1. 反馈与原因

实际页面暴露出五个问题：

1. 全书构思虽然有输入框，但没有说明作者处于哪一步、完成后去哪里。
2. 章节正文刚创建时只显示大片空稿纸，模型起草动作位于页面底部。
3. 宽屏已经常驻页边索引，工具栏仍提供“索引”按钮，会打开重复的辅助区。
4. 章节标题同时出现在编辑器工具条和 Markdown 第一行，形成重复标题。
5. 左栏的新章节标题输入过窄，并且它是一个没有模型替代路径的创作文本输入；模块与导入也长期挤占章节导航。

## 2. 实际调整

- 全书构思增加“作品起点 → 章节构思 → 开始正文”三步进度，只显示当前需要完成的下一步。
- 空作品只能先保存全书构思；完成前左栏不能新建章节，也不会出现正文入口。全书构思保存后才允许建立章节壳。
- 章节构思区显示继承的全书起点；只有章节构思被明确确认后，才开放空正文及人工 / 模型两种起稿方式。
- 章节构思页明确只需回答“故事发生什么变化”和“读者或角色知道什么”，并说明未知结局、时间和分类可以保留。
- 已确认构思后的空正文显示本章摘要、“自己写第一段”和“由模型起草”；模型候选采用后仍先成为本地草稿。
- 已有正文时把“让模型续写”放在正文上方，动作紧邻当前写作位置，不再悬在长页面底部。
- 编辑器隐藏文件中的首个 Markdown 一级标题，只编辑正文主体；保存时仍保留原始标题前缀，索引位置换算继续使用完整文件码点。
- 宽屏可容纳页边信息时不再显示重复按钮；较窄窗口仍提供“本章信息”辅助区。
- 左栏移除新章节标题输入，改为一个“新建章节”动作；章节标题继续允许未知。章节行改为两行，分别显示章号 / 标题和构思摘要。
- 模块与导入折叠为次级区域，默认让全书构思和章节保持视觉优先级。
- 稿纸从 42em 放宽到 46em，页边信息缩为 190—220px，并减少多余外边距；工具条同步减高。

## 4. 保留边界

页边信息目前仍按正文顺序列出，没有实现逐段像素对齐；原生 `textarea` 无法可靠提供每段 DOM 位置。若 P6 仍要求严格段落对齐，需要先完成编辑内核比较，不能依靠估算滚动高度。此次没有调用在线模型，也没有重复运行后端全量。

## 5. 同日追加：章节构思门槛改为两步核对

反馈：门槛页在提问之前先要求阅读「两件事」清单和全书起点引文，一次摆出四个动作（开始写作 / 只保存构思 / 交给模型构思 / 返回正文），服务端整理出的摘要只在保存后以附页形式出现。这与「减轻作者思维压力、减少人工维持对象」不一致：作者要先理解概念，再判断按哪个按钮。

调整（对照原型，覆盖第 2 节中关于构思指引清单的条目）：

- 门槛只保留一个问题「这一章要改变什么？」；删除「来自全书构思」块、「两件事」清单和输入框下的补充说明，说明并入一句副标题。
- 流程改为两步：作者写一句话点「整理构思」，服务端保存并整理；句子与已保存构思一致时显示「本章构思」核对卡片（摘要与信息变化），提供「继续调整」和「开始写作」。「开始写作」在核对阶段直接用当前修订开始，不重复提交；继续输入即回到整理状态，未改动时再次「整理构思」不会产生重复改动记录。
- 「只保存构思」按钮删除：整理即保存，作者不需要维护保存时机；「交给模型构思」保留在整理步骤，「返回正文」仅在新章改构思场景出现。
- 原型右侧的「开始条件」栏未单独成列：其中「本变化」就是作者原句、信息变化已在核对卡片列出，单独成列会重复同一内容；若 P6 验收仍需要，再作为辅助区补充。
