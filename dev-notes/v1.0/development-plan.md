## 1. 实施目标和范围

先让已有线索在写作中可看、可定位、可讨论，再支持围绕一个关键结论设计和核对多条线索。
1.0 完成共享线索身份和详情、作者计划关联、推理核对及实际写作请求；1.1 承接修订学习。
本版继续通过对话修改正文，不以新的正文手工编辑器或偏好系统为前提。

## 2. 当前代码基线

下表为 2026-10-27 阅读源码核对的事实；不是本计划已完成的开发记录。

| 位置 | 现状 | 本版处理 |
|---|---|---|
| `workspace/clues.py` | 版本 2、按章贡献；用描述文字作为 key | 稳定 ID，只使用当前新账本；保留按章替换与空结果语义 |
| `workspace/state_store.py` | 通用派生记录读取失败按空；原子替换但无完整事务 | 新账本严格读取、带锁与版本检查，不能损坏后写成空 |
| `workspace/story_materials.py` | 线索条目 ID 来自描述；字段以埋设、回收和 supports 为主 | 共用详情、提及章筛选、逐条依据过滤 |
| `workspace/material_tasks.py` | 冻结 1—10 章、只读整理、按目标发布与覆盖 | 线索贡献和覆盖同次发布；沿用其他域行为 |
| `workspace/review.py` | 只读检查、原文覆盖、疑点与冲突；历史列表最多 50 份 | 复用执行校验，线索报告持久化和目标关联独立于最近列表淘汰 |
| `workspace/api.py`、`materials.py` | 请求参考以文件路径为主，无线索引用 | 增加精确线索、计划与核对引用，首次与续聊同契约 |
| `workspace/service.py` | 资料、检查、写作共用轮次、互斥与真实请求投影 | 新引用在受理和请求前核对；沿用停止、幂等和用量 |
| `workspace/state.py` | 状态目录按路径生成的 workspace_id；改名迁移整部状态 | 账本内保存稳定 lineage；改名继续同一线索身份 |
| `workspace/files.py` | 字节指纹；文本按 UTF-8 读取并规范换行 | 坐标依据完整读取文本，指纹继续核对真实文件字节 |
| `Paper.tsx` | 只读 Markdown，无精确原文定位 | 段落位置映射、字符范围定位和过期来源处理 |
| `MaterialEntries.tsx`、`EvidencePane.tsx` | 详情和证据分区有重复标题；带到对话传 path | 共用详情；带入稳定线索和处理目的 |
| `WritingLayout.tsx`、`state/layout.ts` | 目录／正文／对话及窄屏切换 | 共用辅助区，保留对话草稿和字号布局 |
| `state/navigation.ts`、`pagePositions.ts` | 写作路由无来源锚点；资料有章界和条目位置 | 路由只放安全标识，定位信息由服务解析 |
| `ContextInput`、`ConversationUiPatch` | 文件和灵感参考；草稿上下文无精确线索 | 前后端、草稿、幂等、压缩一并扩展 |
| `frontend/playwright.config.ts` | 浏览器文件显式白名单 | 新浏览器用例同时登记 |
| 包版本 | Python／前端／桌面均为 0.9.0 | S8 才统一为 1.0.0 |

## 4. 阶段任务和完成条件

### S0：固定基线和契约

- 记录源码、版本、当前工作树、0.9 剩余发布门槛和既有失败；不把其他工作计为本版产出。
- 冻结稳定 ID、当前格式、来源坐标、章界、覆盖、请求身份、模型工具权限与接口字段。
- 固定遗书样本、相同描述的不同线索、重建空结果、未来回收、倒叙、emoji 和来源已改样本。
- 登记原型与生产差异；将新接口和前端动作逐项配对。

完成条件：数据、接口、样本各有单一出处；尚不宣称业务完成。

### S1：稳定身份和记录发布

- 建严格读取的 `clue-ledger.json`，稳定 lineage 与 clue_id，首次显式写入才创建记录。
- 只读写第 2 版账本；旧线索文件、旧覆盖行和第 1 版账本不导入，不保留旧 ID 别名。
- 带锁、ledger_revision 和 request_key 提交贡献与覆盖；只替换本章，材料不足保留旧贡献。
- 同名新线索不自动合并；已知身份重建复用，重命名不换 ID；身份冲突作为未完成目标反馈。
- 新账本纳入作品改名、移除、删除和状态备份，纯 GET 不初始化、不写文件。

完成条件：重建、空结果、写入失败与竞争不会丢当前格式其他章或生成无效身份；不恢复旧链接。

### S2：原文定位和范围

- 统一 file/module 来源，服务端签发可解析的证据标识；客户端不提交任意磁盘路径作为位置。
- 指纹采用字节指纹；区间采用完整规范化文本的 Unicode 码点左闭右开坐标。
- Markdown 源位置映射到阅读段落；过期时只展示旧引文和当前文件，不按旧区间高亮。
- 阅读文件、资料浏览截止章、任务 state_chapter 分开；定位来源不自动改变后两者。
- 首次、续聊、草稿和幂等身份准备好精确引用的结构，不以界面文字作为事实依据。

完成条件：中文、emoji、Markdown 和重复引文准确定位；跨页返回保留位置；越权位置拒绝。

### S3：已有能力的呈现（已完成）

- 共享详情接入写作右侧和资料页；默认正文依据与读者已见，作者计划关联未实现前不开放操作。
- 本章按 source_chapter／实际提及筛选，包含早章埋设、本章推进或回收的线索。
- 展示未整理、无发现、信息不足、部分完成、来源变化及明确下一步；整理复用真实资料任务。
- 去掉详情和依据重复标题；原文选中后定位，不铺满全书高亮。
- 对话与线索切换不卸载输入状态；窄屏用可返回的单区域，不挤成三列。

完成条件：无需记自然语言命令即可发现本章记录、整理并定位；所有显示来自真实接口。

### S4：作者计划与推理目标（已完成）

- 从已挂载模块选择实际条目区间，关联到线索；允许一个计划关联多条线索、一个线索参与多次推断。
- 保存推理目标、必要前提与其他解释的结构化关系；作者正文继续在模块保存。
- 「讨论设计」可提出补充证据、调整结论、保留解释的方案，明确其取舍和预期出现位置。
- Agent 修改计划沿用模块写工具；登记线索设计关系需独立 scope grant，讨论不自动保存。
- 模块升级／卸下后标记关联需核对，不按同名或最新版本偷偷重绑。

完成条件：能从零构思并显式保存一组线索安排；纯构思不产生已埋设、已披露或已回收记录。

### S5：推理核对（已完成）

- 在既有 review 用途上增加 clue_review 范围，固定目标、相关 clue_id、模块修订、1—10 章和目录摘要。
- 工具只读并发布报告；真实原文提供与证据范围沿用现有核验，未读完不得报告完成无问题。
- 检查缺失前提、未排除解释、前提尚未给读者、反证与表述性质；建议与有依据的冲突分开。
- 计划可用于定义目标，不能证明正文前提；未给定真相和有意保留不自动算错误。
- 报告与依赖持久保存，最近 50 份通用检查列表淘汰不使线索报告消失；可按报告 ID 读取。
- 列出来源变化、范围未含新章和材料不足的区别；修改不直接标为已解决。

完成条件：遗书样本给出准确、有位置的具体缺口；伪造引文、未来依据和空检查不能发布为通过。

### S6：对话、写作与 0.9 衔接（已完成）

- 「讨论设计／讨论修改」合并到当前消息草稿，保留已有正文、参考及当前问题，不自动发送。
- 首次与续聊相同引用结构，重试同键同快照；服务端读取精确版本，拒绝伪造目标或跨作品引用。
- 正文改写仍按作者请求登记路径；引用和检查不授予正文或模块写权限。
- 每次实际模型请求使用同一受理快照；0.9 压缩保留引用 ID、版本、截止章和未解决状态，不能把摘要当证据。
- 回写前章重新过滤正文观察；修正「每条线索支持所有嫌疑人」的笼统提示。
- 关闭、停止、重启和作品切换只恢复已记录状态，不重复付费启动；接真实用量与活动记录。

完成条件：完整流程可由浏览器发起并落到真实请求；改动后旧依据可见且要求复核，授权不扩大。

### S7：验证效果与恢复（自动验证与代理复核已执行）

- 执行[验收矩阵](acceptance.md)；新增浏览器文件登记进现有白名单。
- 在线使用 `.env`，比较现有方式、仅新呈现／引用、完整推理核对；同模型、同作品、相同任务预算。
- 所有尝试、人工复核和成本留证；未执行、失败和不确定不计成功，不重跑挑选好结果。
- 核对真实长内容、跨章修改、多个推理步骤共享线索及资料与对话来源变化。

完成条件：确定性和浏览器硬约束通过；在线缺口识别、误报及构思可用性经人工复核。

### S8：浏览器版运行与交付文档（自动验收已完成）

- 主包、前端、锁文件与浏览器产物在发布时统一 `1.0.0`，数据格式独立。
- 用当前格式作品副本验证正文、模块库、会话与线索的备份恢复、改名和删除；浏览器中真实整理、核对、停止与服务重启可用。
- 对外名称为线簿／ClueLedger，内部代码包名保留。
- 补实际模块说明、运行与升级说明、逐项证据、已知限制；根 README 不列为自动改动项。
- [1.1](../v1.1/README.md) 实施前以本版实际辅助区、来源定位、引用和记录能力重新核对基线。

完成条件：版本、产物、界面、后端和运行文档一致，正式验收有证据；不以旧数据迁移为发布门槛。
