# 1.0 数据、身份与恢复契约

日期：2026-10-28。状态：**当前格式记录、模块精确修订与浏览器阅读状态恢复已通过自动验收；桌面端暂不纳入范围**。本文是新增线索记录的数据单一出处。
阶段见[开发计划](development-plan.md)，请求字段见[接口与前端](api-and-frontend.md)。

## 1. 权威来源与存储取舍

| 内容 | 权威来源 |
|---|---|
| 已写正文与版本 | 当前 Markdown 与作品真实 Git |
| 作者的完整设想 | 当前作品实际挂载的模块精确修订；旧设定按原受管文件读取 |
| 线索身份、正文贡献、覆盖、计划关联、推理目标与线索检查 | 新 `workspace_state_root(state_root, workspace_id)/clue-ledger.json` |
| 通用历史检查 | 现有 `reviews.json`，继续旧格式与最近 50 份行为 |
| 模型任务过程、停止与用量 | 现有会话事件、受理记录和模型活动记录 |
| 页面列表与活动索引 | 上述来源的可重建投影，不成为另一份权威记录 |

选择单一版本化 JSON 账本，原因是本版一次更新的数据有限，且按章贡献、覆盖和引用关系需要一起发布。
不引入修订学习的记录数据库。账本包含不可随意丢弃的作者关系与稳定身份，不能再按纯派生缓存处理。
其文件必须纳入当前格式状态备份、作品改名与删除；“清理可重建资料”不清除作者关系和检查历史。

## 2. 账本结构

S1 实际记录见[实施说明](notes/S1-clue-ledger.md)：contribution 保存 contribution_id、observation_id、
clue_id、source_path、source_digest、task_id、mode，以及兼容原字段的 content 对象。
content 包含 source_chapter、埋设／回收、supports、mention_evidence 与对应原文依据；S3 接入 mode，不从标题猜测信息性质。
identity 保存独立 clue_revision、创建来源与 first_chapter；清空本章贡献时身份仍保留。coverage 按 path 索引，并含 chapter 与 recipe_version。
S3 的 mention_evidence 使用相同 path/digest/start/end/quote 结构，必须来自目标章、对应实际读取范围，
并在发布前再次核对指纹与引文。mode 只标明本章主要观察；早章引文优先采用该章原贡献的性质，
回收引文不继承另一段证词的性质，未分别登记时显示 unknown。每条引文独立验证，失效引文不计入 reader_seen。
身份没有任何可见贡献时只显示“暂无正文依据”，不据此判定已经埋设或回收。
新账本所有顶层集合必须存在，缺失字段按损坏报错。计划关联与推理目标已由 S4 扩展；
核对报告和精确引用发送仍待 S5—S6，当前集合与单章重建不删除其中记录。

S4 实际：`design_links` 与 `inferences` 已改为严格模型。计划关联保存 link_id、clue_id、来源（file 或四段模块引用）、
绑定身份、区间、引文、关系说明及创建时间／轮次／账本修订；推理目标保存 goal、intent、1—10 条 clue_ids、
必要前提、其他解释、design_link_ids 与自身修订。计划来源在写入时核对文件指纹或精确模块版本，
模块升级或卸下后视图标为 detached，不自动重绑。移除计划关联会同步移除目标中的该依据并更新目标修订；
模块原文与正文不变。创建计划身份不写贡献、覆盖或披露。

格式 `schema_version=2`，生成规则 `recipe_version=1`，与产品版本独立。拟议结构：

```json
{
  "schema_version": 2,
  "recipe_version": 1,
  "workspace_lineage": "ws_opaque",
  "ledger_revision": "rev_opaque",
  "clues": {},
  "contributions": {},
  "coverage": {},
  "design_links": {},
  "inferences": {},
  "reviews": {},
  "requests": {}
}
```

| 记录 | 必需内容 |
|---|---|
| clue | clue_id、title、创建来源、原始记录时间；标题修改不改身份 |
| contribution | clue_id、source_chapter、source_path、源指纹、观察及各自依据、更新任务 |
| observation | observation_id、所在章、plant/mention/advance/resolve、信息性质、evidence_id |
| lifecycle | 状态及有效章、依据或作者明确废弃来源；按浏览章计算，不能拿最终状态回填早章 |
| coverage | 正文章节、实际指纹、found/empty/insufficient、任务、说明与规则版本 |
| design_link | link_id、clue_id、来源完整引用、区间、原文引文、binding_id、created_revision、创建时间与轮次、关系说明 |
| inference | inference_id、inference_revision、目标结论、目标意图、相关 clue_ids、前提与其他解释、design_link_ids、创建时间与轮次、作者请求来源 |
| review | report_id、inference_id、冻结目标与意图、线索修订、章界、目录清单、模块依赖、结果、未覆盖及来源 |
| request | 操作种类、request_key、规范化负载指纹、已提交结果；不接受同键不同内容 |

正文观察的信息性质沿用 `narration/testimony/recollection/hypothesis/dream/unknown`；
旧记录没有足够信息时用 unknown，不按线索标题补出事实性质。
推理意图为 `deduce/suspect/keep_open/undecided`，分别表示此处需要得出结论、仅引起怀疑、保留解释或尚未决定。
推理节点记录可审查的前提与解释关系，不保存或要求模型私有思维过程。

同一 clue_id 可有多章贡献并参与多个 inference_id；一个推理步骤可关联多条线索。
前提和其他解释是带来源的目标或判断，不等于设定已经成立。

ledger_revision是整份账本的事务版本；clue_revision是条目相关内容版本，覆盖标题、贡献、计划和目标关系，
不随无关线索或任务进度变化。受理时还要重新核对当前源指纹和有效性，不能仅比较存储中的revision。

## 3. 当前格式和稳定身份

- 只使用 `clue-ledger.json` 当前第 2 版，不读取 `clues.json`，不导入通用覆盖文件中的旧线索行。
- 第 1 版账本直接视为没有当前记录；纯 GET 不改磁盘，首次明确发布时创建全新第 2 版账本。
- 不转换旧条目、不保留旧 ID 别名、不创建迁移备份、不恢复旧链接；旧记录需要从正文重新整理。
- 缺失账本返回只读空快照 `empty`。只有显式写操作才创建 lineage、ID 和账本文件。
- 当前格式账本损坏、字段缺失或未知更高格式明确报错，不当作空记录覆盖。
- clue_id 为作品内不可变随机标识，不由标题或章号生成；改标题不改 ID。
- workspace_lineage 首次显式保存时创建；作品改名移动整个状态目录后保持不变。

新任务重建已知线索时从受理快照复用 ID。新描述同名不自动合并；关联不明确则报告身份疑问，
保留未完成目标，作者可明确继续用某条线索或另建。纯讨论不建立空身份记录。
尚无正文但有明确作者计划时可创建线索设计身份，观察列表保持空，不伪造埋设章。

## 4. 按章贡献和发布事务

一次线索整理依然只处理作者指定的 1—10 章。受理固定目录、章号、文件指纹、账本 revision 和已知身份。
每章发布在同一账本提交贡献和该章覆盖：

| 结果 | 行为 |
|---|---|
| found | 全部条目依据通过后替换本章贡献，同时写覆盖 |
| empty | 已读完且确认无发现，移除本章旧贡献，同时写合法空覆盖 |
| insufficient | 写材料不足覆盖，保留旧贡献；旧贡献是否可用继续按其指纹判断 |
| 未发布／停止／失败 | 不写该目标完成；其他已提交章保留，任务显示部分完成或停止 |

其他章的贡献、作者关系、目标和检查历史不随单章重建删除。线索无当前有效贡献时保留身份与关系，
显示“暂无有效正文依据”；有意废弃由明确作者请求记录，不靠删除贡献表达。

新写入必须使用跨进程文件锁或同等互斥，在锁内读取、检查 ledger_revision、查重、校验再提交。
临时文件同目录写入并 flush/fsync 后原子替换；替换失败保留旧文件，清理本次临时文件。
工作区运行占用与账本锁分开：前者约束任务并发，后者保护短写事务；固定先占用、后账本锁的顺序。
初始化、计划关联、报告发布和作者操作都走同一存储服务，不允许直接整份覆盖旧快照。

## 5. 原文坐标与定位

S2 实际实现见[来源定位](notes/S2-source-locations.md)：响应以 source.kind 判别 file/module，
仅 valid 返回 start/end，其他状态保留 quote 并取消坐标。受管移动从成功文件事件解析；
外部移动不搜索相似文件。当前格式账本才提供 evidence_id；本阶段不扩展旧来源 ID 迁移。

正文来源：受管 path、真实字节 digest、规范化全文的 start/end、quote，左闭右开，`offset_unit=unicode_codepoint`。
文本使用现有 `Workspace.read().text`，不是去掉元信息或渲染后的 DOM 文本。BOM、换行规范沿用现有解码。
模块来源：library_id/module_id/revision_id/entry_id 四段引用，加实际读取内容指纹和区间。
来源位置由服务端从记录解析 evidence_id，客户端不提交任意本地路径替代标识。

定位先核对当前源、区间和引文，再返回有效位置。段落渲染维护源位置映射，Unicode 码点转 JavaScript UTF-16 索引。
Markdown 强调、链接、代码、转义和中文标点不能用渲染后字符串第一次匹配冒充位置。
复杂结构无法安全突出句内区间时，定位并突出原文所在段落，展示完整引文和“已定位至所在段落”。
人物元信息被去除时需要显示偏移映射；未实现映射的源只能打开实际原文，不能用错误区间高亮。

来源已修改时返回 stale 和保存的旧引文；允许打开当前文件，但不按旧区间高亮、不自动搜同一句重绑。
受管移动由真实移动记录更新引用映射，保留历史来源；外部重命名标为 source_missing，等待显式核对。
模块精确旧修订仍可读但已不属于当前绑定时，计划关联为 detached，不自动跟随新 head 或同名模块。

## 6. 三个时点与作者视图

1. `selected_path`：正在阅读的文件，来源跳转可以改变。
2. `browse_as_of_chapter`：作者查看资料的截止章，来源跳转不改变。
3. `ContextInput.state_chapter`：实际任务的正文披露边界，按明确目标或当前写作范围冻结。

资料 GET 只接受 `as_of_chapter`；本章筛选另给 `chapter_path`，不能用 planted_chapter 代替实际提及章。
每条观察、回收依据和检查依据分别按章界过滤。前章视图保留已出现线索，但移除后章回收引文、结果和隐藏关系摘要。
作者计划独立分区，允许未来安排但不计为读者已见。读者已见表示正文已呈现，不是读者的真实心理状态。

资料页查看未来章后回写前章，服务按写作目标重新筛选正文观察。作者真相可为规划而读取，独立标明，
不能仅凭过滤前端面板宣称模型没有未来信息；等价泄露通过在线验收核对。

## 7. 检查依赖、覆盖与失效

每次核对冻结：inference 修订与意图、clue_id 集合、相关贡献修订、目标章清单及指纹、
实际读取区间、作者计划精确修订、截止章和截止章内目录清单摘要。
目录摘要只证明目标集合，不能证明全文已读。内容提供给模型的区间仍由 MaterialLedger 核对。

| 变化 | 旧报告处理 |
|---|---|
| 目标正文／计划／推理目标版本变化 | 保留旧报告，标为来源或目标已变化，要求复查 |
| 截止章内新增、移除或重排相关目标 | 范围清单变化，不沿用旧覆盖结论 |
| 截止章之后新增章节 | 原有有界检查仍对应原范围；查看更后章时提示“检查未覆盖这些章节” |
| 当前浏览章早于报告依据章 | 不展示超出章界的结论、引文或结果摘要 |
| 修改或删除问题段落 | 标为需复查，不能直接计为已解决 |
| 作者明确保留其他解释 | 保存当前目标意图，后续核对依此判断，不把待定当冲突 |

检查的 `findings/no_findings/incomplete` 沿用旧含义；任何完成状态均需读完冻结目标与必需参考，未读完只能部分完成。
发现类型扩展为 inference_gap、alternative_open、premise_undisclosed、counter_evidence；
certainty 继续为 supported/suspected，表示依据充分程度，不是线索真实性评分。
“未排除的解释”在 keep_open 目标下是可保留安排，不能机械报错。

新线索报告仅以账本 reviews 为权威，含完整结果、版本和依赖；会话事件引用 report_id 和摘要。
现有通用报告保持原文件；仅标题或关键词命中的旧报告不能自动挂到线索。
按 report_id 的回看不依赖最近 50 条通用列表；如后续提供清理，必须显式说明被引用报告并保留可解释的缺失状态。

## 8. 对话引用、恢复与生命周期

引用最少包含 workspace_lineage、clue_id、客户端观察到的 clue_revision、browse_as_of_chapter，
以及可选 inference_id/inference_revision/report_id。标题和预览只用于显示，不由客户端提供正文事实。
服务端受理解析为不可变快照，包含实际来源、计划与检查范围；每次真实请求与该快照对应。

加入引用只保存草稿，不发模型请求；保留已有输入、参考和对话归属。草稿按作品与会话保存在现有服务端 UI 状态，
不依赖浏览器本地 origin。首次创建与续聊共享同一引用结构与请求键计算。
同一 request_key 的请求负载包含版本、范围、引用和目标；已受理重试返回原任务，不因材料后来变化重新调用模型。
尚未受理而引用过期时返回冲突，保留草稿；不得静默替换为新版本发送。

浏览、草稿、整理、核对和创作写入分别恢复；重启将未完成的付费任务标为 interrupted，不自动续跑。
任务发布前重新核对源、目录、账本 revision、停止信号和工作区生命周期 generation。
切作品后丢弃迟到 UI 响应；删除前停止任务并阻止迟到发布，改名按现有机制迁移整个状态目录。
0.9 摘要保留结构化引用身份和未解决状态；摘要、旧检查摘要和目录不计为读过原文。
