模拟检查卡、静态原型和直接写 fixture 不能证明在线构思或检查质量。

## 4. 在线语义样本

使用仓库 `.env` 中在线模型；相同模型、固定原文、固定任务和预算，不使用本地模型。
拟新增 `eval/cases/v10-clue-workflow.yaml`、`eval/suites/v10-clue-smoke.json`、`v10-clue-core.json`，
并扩展评测 schema/runtime 的线索计划、关联、资料、核对与精确引用步骤。以上文件与执行支持均已实现；16 案例各 3 次的复验及代理复核已执行。
期望答案、评分标准与隐藏真相放评测器一侧，不送给模型；模型只见作者请求、明确提供的作品与计划。

| 案例 | 需要人工复核的语义 |
|---|---|
| Q01 遗书内容 | 能指出“知道内容”到“提前接触原件”的前提缺口，不直接推出凶手 |
| Q02 公开照片 | 新证据构成其他信息来源，相关结论需重新核对；不捏造她一定看过照片 |
| Q03 计划未写入 | 模块中的排除安排不冒充正文已经告知读者 |
| Q04 证词与事实 | 人物说法、误信和客观事件分开，保留未核实性质 |
| Q05 多线索共同支持 | 检查组合依据，不要求每条线索单独定罪 |
| Q06 有意保留解释 | keep_open 下不把存在替代解释一律报错 |
| Q07 怀疑与定论 | suspect 可接受较弱依据，deduce 需要与目标相称的支撑 |
| Q08 前提首次出现于揭晓 | 按作者是否要求读者可参与推理判断，不强制所有悬疑遵循同一目标 |
| Q09 倒叙与获知 | 区分叙述顺序和故事时间，不仅按章节认定人物提前知道 |
| Q10 错误或不存在的目标 | 清楚说明缺项或请求澄清，不自行决定凶手或创建空检查 |
| Q11 构思方案 | 提供可用的不同解释与验证安排，说明所需前提，遵守作者已给限制 |
| Q12 构思保存 | 讨论不保存；明确保存后更新正确作品模块和关系，不改正文 |
| Q13 前章改写 | 使用计划安排伏笔但不在正文等价泄露后章信息 |
| Q14 变化与无关编辑 | 相关版本变化触发需复查；无关线索变化不使所有引用失效 |
| Q15 材料不足 | 允许 incomplete 或具体疑问，不把连接失败说成作品逻辑问题 |
| Q16 完整流程 | 结果能定位、讨论和实际改写，修改后以新证据复查 |

Q01—Q08、Q11—Q13 是核心语义门槛：每例计划3次独立尝试，未执行需说明且不能宣称完成该项发布验收。
首批是可审查的小样本门槛，不解释为业务成功率；成功分母包含全部计划尝试，单列未运行与运行错误。
任何越界写、伪造依据或提前泄露为硬失败，不被平均分抵消。核心例每例至少2/3达到人工标准，
其余尝试中的硬失败必须修复并保留原失败证据后重新验收；不能靠追加成功运行提高分母掩盖失败。
初版由人读原文、目标与实际输出复核，模型评委仅可作补充且须另行校准。

## 5. 对照、成本和实际收益

三个固定变体：baseline（当前0.9工作流）、presentation_refs（新呈现和精确引用，无专门推理提示）、
full_clue_workflow（完整目标、来源与核对）。同作品、模型、任务目标和总调用预算；各变体准备操作全部计成本。
需要手动注入已知线索的样本，明确该初态由谁整理，不把评测器提供的答案当作产品自动能力。

S7 已按 `baseline`、`presentation_refs`、`current`（完整线索流程）准备对照，并在核心案例上跑了前两者；
结果与成本见[S7 记录](notes/S7-verification.md)第 5 节。

记录目标完成率、错误定论、误报、越界、人工补充上下文次数、可用构思方案及作者处理负担。
程序通过只证明范围、版本和引用；构思可用性与推理判断分别由人工评估。
报告真实调用次数、耗时、输入输出及缓存用量；上游缺值单列未知，不用字符估算冒充 token 或价格。
性能检查覆盖100章、500条线索、长模块、20份关联报告的列表和详情；记录测试机器及实际延时，
先以有界查询、无整本重复注入和前台操作可响应为门槛，再按 S0 测量确定数值目标。
