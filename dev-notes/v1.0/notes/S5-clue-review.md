# S5：有原文依据的推理核对

日期：2026-10-28。状态：已实施。运行包仍为 `0.9.0`，账本格式仍为 `schema_version=2`、`recipe_version=1`。
下一阶段为 S6 讨论草稿与真实引用发送。

## 解决的问题

S4 让作者能保存推理目标，但目标是否站得住脚还没有答案。本阶段给出一条只读的核对路径：
把目标意图、线索集合、必要前提与其他解释、目标章节与当前版本一起冻结，由模型对照读者已见的
正文判断，报告写入账本而不是通用检查列表。

核对回答的不是「作者打算怎么写」，而是「读者已经读到的正文是否支撑这个推理」。作者计划、
人物小传和未写出的真相只能定义目标，不能当作正文前提；没有给定真相时，未写明的信息不算错误。

## 作者实际操作

1. 在线索详情选择一条已保存的推理目标，点「核对推理」。
2. 界面按目标线索已有的正文章节生成核对目标（最多 10 章），与查看截止章一起提交；这一轮是只读请求。
3. 报告完成后，目标下显示「上次核对：发现问题／未发现问题／未完成」；有问题的显示「查看核对报告」。
4. 报告分区显示核对范围、问题类型、确定程度、建议与依据引文；依据可定位到原文。
5. 正文改稿、推理目标或计划依据变化后，旧报告保留并标为「需复核」；重新核对产生新报告。
6. 报告不自动改稿，也不改线索、计划或目标；修改仍是另一轮写作任务。

## 状态与信息边界

| 情况 | 实际处理 |
|---|---|
| 目标或线索在读取后变化 | 受理前拒绝，返回 `CLUE_REVISION_CONFLICT`，要求重新读取 |
| 提交的线索集合与已保存目标不一致 | 拒绝；缩小范围要先编辑目标 |
| 核对目标超出截止章、不是正文或没有正文 | 拒绝；空目标返回 `CLUE_REVIEW_TARGET_REQUIRED` |
| 证据引文与区间不符 | 拒绝；引文必须等于当前文件的实际区间 |
| 证据区间本轮没有提供给模型 | 拒绝；读取记录来自实际模型输入，不采信模型自述 |
| 证据所在章超出截止章 | 拒绝，避免把未来正文当作依据 |
| 目标全文没有读完就报「没有发现问题」 | 拒绝；只能报告 `incomplete` 并写明未覆盖部分 |
| 报告如实为 incomplete | 报告照常保存可回看；这一轮标为部分完成，不冒充通过 |
| 报告发布时目标被改动 | 返回 `CLUE_SOURCE_STALE_CONFLICT`，按当前内容重新核对 |
| 正文或目标在报告之后变化 | 旧报告保留，标为 `stale` 或 `target_changed` |
| 通用检查超过 50 份被淘汰 | 线索报告在账本里，不受影响，仍可按报告 ID 读取 |
| 更早的查看章界 | 只投影当时可见的目标、问题与依据，不先下发后章结论 |

问题类型为 `inference_gap`、`alternative_open`、`premise_undisclosed`、`counter_evidence`；
`certainty` 表示依据充分程度，不是线索真实性的评分。`keep_open` 目标下未排除的解释是作者有意
保留的安排，报告要求模型不把它当作错误。

## 实际模块与接口

| 位置 | 职责 |
|---|---|
| `workspace/clue_reviews.py` | 核对要求、冻结范围、报告问题与覆盖校验、账本持久化、按当前来源计算失效 |
| `workspace/review.py` | 暴露单条证据校验与全文覆盖校验，通用检查与线索核对共用一套规则 |
| `workspace/clue_api.py` | 新增 `GET /clue-reviews/{report_id}?as_of_chapter` |
| `workspace/clue_views.py` | 详情返回核对摘要；推理目标给出已有章节作为默认核对目标 |
| `workspace/source_locations.py` | 报告依据的稳定定位标识与解析，失效时保留旧引文 |
| `workspace/api.py`、`service.py`、`state.py` | `clue_review` 请求字段、受理冻结、轮次落盘与同键重试比较 |
| `workspace/agent.py` | 只读工具集增加 `clue_analysis`；目标与范围来自冻结，模型只能提交判断与证据 |
| `frontend/src/api/clues.ts`、`state/clues.ts` | 报告类型、按报告 ID 读取与按章界缓存 |
| `components/clues/ClueReview.tsx`、`ClueDetail.tsx` | 报告展示、需复核状态、依据定位与核对入口 |
| `components/workspace/WritingLayout.tsx` | 从推理目标发起真实的只读核对轮次 |

后端路径相对 `src/hastings/`；前端组件相对 `frontend/src/`。
报告权威在账本的 `reviews` 字段，会话只记录 `review_finished` 事件与报告 ID，事件丢失可从账本恢复。
核对轮次沿用现有 `review` 用途与只读工具集，不开放线索、模块、关系或正文写工具。
