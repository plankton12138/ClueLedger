## 修复与结果

| 项目 | 实际变化 |
|---|---|
| 参考原文 | 预读结果保存实际文本，作为独立材料消息进入模型请求；路径、字节指纹和码点范围与覆盖记录一致，不受系统分区长度限制截断 |
| 写后检查 | 检查阶段接收本轮原文与工具结果，已读覆盖不再脱离检查模型实际获得的内容 |
| 阅读恢复 | 新增作品级 `GET/PATCH /reading-position`；章节、版本与滚动位置随应用状态保存，刷新和服务重启可恢复；原文改动后归零，删除后清空 |
| 生命周期 | 阅读保存与改名、删除共用互斥范围，旧登记与删除后的迟到保存被拒绝，不重建已删除状态 |
| 返回焦点 | 原文定位返回后等来源按钮实际可见再恢复焦点，修复一次渲染时序导致的焦点丢失 |

| 压缩与溢出 | 补齐真实服务压缩、后续实际请求和明确供应商溢出重试的引用身份、版本、章界与报告保留验证 |
| 核对标准 | 明确怀疑与定论的不同强度；未证实不作反证，普通叙述省略结合上下文判断；只发布最终报告，不用探针试坐标 |
| 静态检查 | 修复发布恢复测试的无用导入与超长代码行，当前检查通过 |

保存阅读位置与保存草稿都不启动模型，也不修改作品正文。新接口只接受作品内受管路径，版本不匹配返回 `READING_SOURCE_CHANGED_CONFLICT`。

## 在线语义复验

全部使用 `.env` 的在线 `deepseek-flash`，不使用本地模型。每例固定三次独立尝试，失败不追加同版本运行来提高分母。

| 运行 | 范围 | 代理复核结果 |
|---|---|---|
| [完整首轮](../../../eval/runs/v10-final-20261028/rescored.md) | 16 例 × 3 次 | 41/48 通过，7 次失败保留 |
| [明确构思来源范围](../../../eval/runs/v10-q11-explicit-scope-20261028/rescored.md) | Q11 × 3 次 | 3/3 通过 |
| [修复核对强度与反证标准](../../../eval/runs/v10-intent-fix-20261028/rescored.md) | Q01、Q04、Q07 各 3 次 | 8/9 通过，Q07 第 3 次失败保留 |

首轮发现：模型曾提交探针报告后尝试改写同轮报告；曾把“尚无人证实”当成反证；怀疑目标的要求过严。核对提示已针对这些行为明确标准，原失败没有覆盖。

Q11 原评分要求不使用后章真相，但原作者请求没有给出这项限制，模型按作者规划读取真相。原三次仍按原评分标准记失败；补齐请求中的范围约束后另建运行，三次均只读取前三章。没有降低评分标准。

按修复或明确范围后的同一案例三次记录，当前覆盖 **47/48 通过**：核心 11 例为 **32/33**，扩展 5 例为 **15/15**；每例均至少 2/3 通过，达到矩阵约定的小样本门槛。它不是业务成功率，也不是所有尝试都通过。

累计保留 60 次在线尝试，输入 242,218 token、输出 353,756 token；上游缺少价格与缓存明细，费用保持未知。复核人为 **Codex 代理**，不是作者或独立人工。逐条判断见 [首轮复核](../artifacts/s8/reviews-initial.json)、[Q11 复核](../artifacts/s8/reviews-q11-scope.json)、[核对修复复核](../artifacts/s8/reviews-intent-fix.json)。

## 运行与当前格式备份

先在前端目录构建，再从项目根目录启动服务：

```powershell
npm --prefix frontend run build
uv run python -m hastings.server
```

按启动输出的实际目录备份三部分：作品目录、应用状态目录、共享模块库目录。默认应用状态在用户主目录的 `.hastings`；共享库通常位于文档目录的 `ClueLedger/ModuleLibrary`，指定参数时以启动输出为准。模型连接与系统凭据按原配置管理，不把 Key 写进备份示例。

停止服务后复制上述目录，恢复时放回原路径并使用相同的状态和模块库启动参数。只复制作品正文不能恢复应用会话、核对报告或共享模块修订。当前只支持第 2 版账本，旧数据不导入或迁移。

在线浏览器验收可用 `uv run python -m scripts.online_acceptance_config create <隔离配置路径>` 准备 `.env` 连接；配置仅保存系统凭据引用。设置 `HASTINGS_E2E_CONFIG` 后运行 online 白名单中的 `clue-workflow-online.spec.ts`，结束后用同一脚本的 `cleanup` 清理临时凭据。本轮已完成清理。
