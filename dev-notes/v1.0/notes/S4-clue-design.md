# S4：作者计划关联与推理目标

日期：2026-10-27。状态：已实施。运行包仍为 `0.9.0`，账本格式仍为 `schema_version=2`、`recipe_version=1`。
下一阶段为 S5 推理核对；讨论草稿与真实引用发送仍留 S6。

## 解决的问题

S3 让已有正文记录可看、可定位，但作者还不能把「计划怎样安排线索」保存到作品里。
本阶段增加两条真实关系：一条线索与计划条目区间的关联，以及一个推理目标与多条线索、
必要前提和其他解释的结构。关系只描述作者安排，不复制模块正文，也不产生正文观察或披露。

作者可以从零建立一条尚无正文依据的线索身份，再关联已装模块或设定文件中的实际区间，
保存目标与解释。计划来源失效时逐条标出，不按同名或最新版自动重绑。

## 作者实际操作

1. 在资料页「线索与伏笔」选择「新建线索设计」，输入标题；只建立身份，不宣称已经埋设。
2. 打开线索详情，展开「作者计划」，选择「关联计划」。
3. 在来源选择器切换「已装模块／作品设定」，选中条目后在原文中拖选一段，填写关系说明并关联。
4. 计划条目显示来源名称、引文、关系、有效性，可定位到原文或移除关联；模块升级、卸下或来源改稿后显示待核对。
5. 在「推理目标」选择「新建推理」，填写目标、意图、关联线索、必要前提与其他解释，并可勾选本线索的计划依据。
6. 目标显示在所有关联线索的详情里，可「编辑目标」；推理内容不进入读者已见。
7. Agent 只有在作者明确要求并登记关系授权后，才能关联计划或保存目标；普通讨论不自动保存。

## 状态与信息边界

| 情况 | 实际处理 |
|---|---|
| 从零建立线索 | 只写身份；贡献、覆盖、披露与埋设章都为空 |
| 计划来自设定或小传 | 只用受管文件；正文章节里的人物流言不能当作者计划 |
| 计划来自模块 | 必须属于当前装配的精确修订与条目；保存 binding_id |
| 模块升级或卸下 | 旧关联标为 detached，保留旧引文；不自动改绑 |
| 来源文件改稿 | 标为 stale，保留旧引文；不按旧区间高亮 |
| 计划区间与原文不符 | 写入前拒绝；模块条目标为 invalid_range |
| 移除计划关联 | 删除关联；同步移除目标中的该依据并更新目标修订；模块原文与正文不变 |
| 推理目标更新 | 带 inference_revision 更新；版本不符返回冲突 |
| 重复提交 | 同一请求键同内容返回原结果；不同内容冲突 |
| 关系授权 | 独立 clue_design_grants；不授予正文、模块或其他内容写入 |
| 同一轮先改模块再关联 | 模块内容应用后本轮收尾；下一轮读取新装配后再关联，避免按旧版本建立关系 |
| 纯构思 | 不产生已埋设、已披露或已回收记录 |

`reader_seen` 仍只由有效正文引文组成。计划与目标单独分区显示，允许未来安排，
不会因为作者知道而变成读者已见。

## 实际模块与接口

| 位置 | 职责 |
|---|---|
| `workspace/clue_models.py` | 严格计划来源、计划关联、推理前提与目标模型；账本交叉引用校验 |
| `workspace/clue_designs.py` | 身份创建、来源区间核验、关联/移除、目标保存与修订 |
| `workspace/clue_store.py` | 复用文件锁、请求回执、账本版本与原子替换 |
| `workspace/clue_views.py` | 详情中的计划、目标、来源有效性与定位标识 |
| `workspace/clue_api.py`、`clue_api_models.py` | 新增 `POST /clues`、`PUT /clues/{id}/design`、`POST .../design/unlink`、`POST /clue-inferences` |
| `workspace/source_locations.py` | 计划关联的 evidence_id 与精确来源解析 |
| `workspace/task_scope.py`、`agent.py`、`context.py` | clue_design_grants、两个关系工具、讨论与保存边界 |
| `workspace/clues.py` | read_state 的线索视图增加计划与目标摘要 |
| `frontend/src/api/clues.ts`、`state/clues.ts` | 同名类型、写请求与详情刷新 |
| `components/clues/ClueDetail.tsx`、`ClueDesignPicker.tsx`、`ClueInferenceEditor.tsx`、`NewClueDialog.tsx` | 计划与目标展示、来源选择、推理编辑、从零建立 |
| `components/materials/StoryMaterialsPage.tsx` | 资料页新建线索入口 |

后端路径相对 `src/hastings/`；前端组件相对 `frontend/src/`。
新工具只在写作模式开放；检查、整理和灵感模式不返回关系写工具。
计划关联与目标保存复用账本锁和请求键，不新增第二套发布逻辑。
模块来源的定位继续复用 S2 的 `GET /source-locations/{evidence_id}`。
`read_state` 的线索域新增 `design_links` 与 `inferences` 摘要，供模型在后续轮次引用已有身份；
它们不含正文事实，也不替代 `read_record` 或 `read_file`。
