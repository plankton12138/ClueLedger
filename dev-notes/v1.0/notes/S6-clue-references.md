# S6：对话引用与写作衔接

日期：2026-10-28。状态：已实施。运行包仍为 `0.9.0`，账本格式仍为 `schema_version=2`、`recipe_version=1`。
下一阶段为 S7 验证与在线评测。

## 解决的问题

讨论线索时，作者只能用文字描述「那条线索」，模型拿不到稳定身份，也分不清正文依据、作者计划与
推理目标。本阶段把引用放进消息请求：客户端只提交线索标识、看到的版本与截止章，服务端按当前账本
重建读者已见的部分，并把计划、目标与核对结论单独分区。

引用不授予任何写入权限；它也不是原文证据。改了正文、线索或目标之后，旧引用按冲突拒绝发送，
草稿与旧引文保留，由作者重新读取后决定。

## 作者实际操作

1. 在线索详情点「带入对话」；在推理目标上点「带入目标」时，同时记下目标版本与最近报告。
2. 消息输入区显示「本轮线索」标签，可逐条移除；只加入引用、还没写文字时草稿也保留。
3. 发送普通消息时，引用随本轮材料一起提交；检查、整理、展开等明确用途不夹带草稿引用。
4. 服务端核对后，模型看到三块内容：读者已见的正文引文、作者计划、作者推理目标与旧报告结论。
5. 引用过期时返回冲突，草稿仍在；作者重新读取线索或去掉旧引用后继续发送。
6. 刷新页面、切换会话或重启后，草稿中的引用与作者看到的版本仍在。

## 状态与信息边界

| 情况 | 实际处理 |
|---|---|
| 引用属于另一个作品 | 拒绝（`CLUE_ACCESS_DENIED`），提示切回原作品 |
| 线索已删除 | 拒绝（`CLUE_NOT_FOUND`） |
| 线索版本在读取后变化 | 拒绝（`CLUE_REFERENCE_STALE_CONFLICT`），保留草稿与旧引文 |
| 推理目标版本变化或不属于该线索 | 拒绝，要求重新读取目标 |
| 引用的报告不存在或与目标不一致 | 拒绝，提示去掉报告引用或重新读取 |
| 浏览截止章晚于本轮写作边界 | 取两者较小值，不把后章内容带进这一轮 |
| 正文来源已修改 | 旧引文标注为不可用，只作历史，不进入「读者已见」 |
| 计划与真相 | 只作为作者安排显示，不当作正文前提，不产生披露 |
| 同键重试换了引用版本 | 按 `REQUEST_KEY_CONFLICT` 拒绝，不悄悄换版本 |
| 引用或检查 | 不授予正文、模块或关系写入权限；写作品仍要登记范围 |
| 上下文压缩 | 引用身份、版本、截止章、目标与报告 ID 进入压缩记录；摘要不能当证据 |
| 只有引用、没有文字 | 草稿保留；清空文字不会顺手删掉引用 |

`reader` 与 `plan` 在冻结快照里是两个字段，请求身份也包含引用版本；同键重试只认同一条款。

## 实际模块与接口

| 位置 | 职责 |
|---|---|
| `workspace/clue_context.py` | 引用的标识结构、冻结快照、读者依据/作者计划/目标/报告分区与系统提示文本 |
| `workspace/materials.py` | 受理时冻结引用；请求身份包含引用版本 |
| `workspace/context.py` | 材料区追加线索引用块 |
| `workspace/service.py` | 受理、同键比较、回答继承原引用、压缩记录保留引用 |
| `workspace/compaction.py` | 压缩记录与摘要文本保留引用身份，明确不是原文依据 |
| `workspace/api.py`、`state.py` | `clue_references` 请求字段、草稿字段、界面状态往返与空草稿保留 |
| `frontend/src/api/workspace.ts`、`state/conversations.ts` | 引用类型、草稿增删、去重、立即落盘与发送携带 |
| `components/clues/ClueDetail.tsx`、`ChapterClues.tsx` | 「带入对话」「带入目标」入口 |
| `components/workspace/ConversationPanel.tsx`、`WritingLayout.tsx` | 引用标签、移除与切换对话 |
| `components/materials/StoryMaterialsPage.tsx` | 资料页带入引用后回到写作页 |

后端路径相对 `src/hastings/`；前端组件相对 `frontend/src/`。
发送时只带标识与版本，客户端不能提交可信正文、真相或核对结论。
同一次请求的材料、引用与用途一起进入请求键；已受理的重试返回原轮次，不重复调用模型。

## 验证与限制

执行命令、结果与源码指纹见[验证清单](../artifacts/s6/manifest.json)。
后端覆盖：引用冻结、章界裁剪、跨作品与版本冲突、目标与报告不一致、草稿往返与标题显示、空草稿保留、
同键重试、真实轮次的系统提示分区、压缩记录保留引用。当前回归结果为后端 1,307 项、前端 326 项通过，
ruff、mypy 与 tsc 通过，浏览器用例 6 项通过（引用 3 项、S5 报告 3 项）。

浏览器覆盖：写作页带入引用、刷新后保留、移除；资料页带入后回到写作页；带入目标同时记录目标与报告。
