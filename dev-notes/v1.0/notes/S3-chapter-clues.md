# S3：本章线索与共享详情

日期：2026-10-27。状态：已实施。运行包仍为 `0.9.0`，账本格式仍为 `schema_version=2`、`recipe_version=1`。
下一阶段为 S4 作者计划与推理目标；旧数据仍直接放弃，没有增加迁移。

## 解决的问题

已有埋设、回收和引文记录分散在资料与对话中，作者阅读正文时不容易发现它们。
本阶段把这些记录放进写作辅助区，并让写作页与资料页使用同一个详情组件和同一份后端投影。
本章列表按实际贡献和引文关联，早章埋设、本章推进或回收的线索也会出现。

这一步提供可查看、可整理、可定位的基础。作者计划关联、必要前提、其他解释和推理核对仍由 S4—S6 实现，
不能把本阶段的“已有解释记录”当成已验证推理。

## 作者实际操作

1. 打开正文，选择“本章线索”，查看当前章及截止章下的记录。
2. 打开线索，阅读埋设、再次提及和回收引文；每段引文有自己的来源状态。
3. 点击“定位原文”，只突出所选依据。关闭后恢复原文件、阅读位置和依据按钮焦点，本章上下文与任务截止章保持。
4. 使用“整理本章／重新整理本章”启动原有资料任务；查看真实进度、停止或打开活动记录。
5. 使用“全部线索”进入资料页并保留选中身份和截止章；详情不再重复显示另一份依据面板。

对话组件在标签切换时保持挂载，未发送文字与参考继续保留。窄屏显示单一区域，Escape 返回正文，
方向键切换辅助区标签。显式打开的面板在调整窗口尺寸后保持可见。

## 状态与信息边界

| 情况 | 实际处理 |
|---|---|
| 未整理 | 提示可整理；已有跨章记录仍能查看 |
| 已整理无发现 | 显示合法空结果；替换本章贡献，保留稳定身份 |
| 信息不足 | 显示说明，保留已有贡献，避免把缺少信息当成没有线索 |
| 部分完成、停止或中断 | 复用真实任务条，显示本章未完成提示；已发布记录保留 |
| 正文已改或不可读 | 保留旧引文、逐条标明失效；不按旧区间高亮 |
| 空文件或只有 Markdown 标题 | 显示无正文；前端禁用整理，后端也拒绝受理 |
| 受理响应不确定 | 保留同一请求键，允许显式重试；4xx 明确拒绝后结束该请求身份 |

`reader_seen` 仅由截止章内、当前有效的原文引文组成，不使用作者解释或额外模型生成的摘要。
证词仍按证词显示；一份贡献的性质不自动赋给另一段回收引文，未单独登记的性质为 unknown。
原 supports 折叠显示为“已有解释记录（待核实）”。

先过滤贡献章和依据章，再选择标题、状态与解释，避免后章回收污染早章视图。
只剩身份而没有正文贡献时，显示“暂无正文依据”，不宣称已埋设；缺少可恢复的早章标题时用中性标题，
不把后来改过的标题带回早章。身份保留用于后续重新整理和作者关系，本章空结果不会删除它。

## 实际模块与接口

| 位置 | 职责 |
|---|---|
| `workspace/clue_views.py` | 共用列表、详情、逐引文有效性、章界与覆盖投影 |
| `workspace/clue_api.py` | 新增 GET `/clues`、`/clues/{clue_id}`；来源定位继续沿用 |
| `workspace/story_materials.py` | 原资料接口投影同一读模型，保留稳定条目 ID |
| `workspace/clue_models.py`、`clue_store.py` | mention_evidence、mode、first_chapter 与原子发布 |
| `workspace/material_tasks.py`、`agent.py` | 工具字段、实际读取校验与本章提及依据发布 |
| `frontend/src/api/clues.ts`、`state/clues.ts` | 同名类型、请求代次、作品隔离、分页、选择及辅助区状态 |
| `components/clues/ChapterClues.tsx`、`ClueDetail.tsx` | 本章入口、真实任务、共享详情与明确空状态 |
| `WritingLayout.tsx`、`StoryMaterialsPage.tsx` | 标签、草稿保持、窄屏、资料页共用详情 |

后端路径相对 `src/hastings/`；前端组件相对 `frontend/src/`。
新列表每页默认 20、最多 50 条，游标绑定查询、页大小、账本版本和实际来源指纹，变化返回冲突并提示重新读取。
详情最多显示 200 条观察，超出时明确提示。原集中资料列表继续沿用原入口与全量投影，搜索和分页接口已提供，
没有另建一套独立的全书页面。查看 GET 不写状态、不调用模型，也不会自动发起整理。
