# 1.0.4 验收

## 1. 确定性验收

### 后端投影

- 实际时间顺序：`event_times` 拓扑排序；未登记节点按阶段顺序、`reveal_order`、ID 追加。
- 重复关系、缺失端点不导致 500；循环关系返回诊断并回退。
- `time_status` 的 `complete / partial / unregistered` 三种状态计数正确。
- 线索聚合：计划-only、使用-only、有/无身份三种线索都能返回；标题、角色并集、使用点顺序正确。
- 知情聚合：`subject_id`、stance、source、effective event 原样返回；`subjects` 统计正确。
- 诊断：
  - 最新记录形态（20 节点长链 + 一个旁支）触发 `STORY_MAIN_CHAIN_LONG`；
  - 纯单链仍触发 `STORY_SINGLE_CHAIN`；
  - 实际时间缺失/部分覆盖触发对应诊断；
  - 只有 `plant/develop` 的线索触发 `STORY_CLUE_LIFECYCLE_INCOMPLETE`；
  - `misdirect` 但没有 `expected_interpretation` 触发 `STORY_CLUE_READING_MISSING`；
  - `explain` 但没有 `author_truth` 触发 `STORY_CLUE_TRUTH_MISSING`；
  - 单节点方案不产生时间诊断；开放结局不误报 truth 缺失。

### 接口

- `GET /api/file-workspaces/{workspace_id}/story/variants/{variant_id}/mystery` 返回 200，字段与 `api-and-frontend.md` 一致。
- 方案不存在返回 404 `STORY_VARIANT_NOT_FOUND`。
- 有方案但没有节点时返回空顺序、空线索、空诊断；没有方案时沿用 404。
- 接口只读：调用前后方案修订不变。

### 前端

- 纯函数测试：阶段过滤、节点排序回退、线索按生命周期分组、诊断筛选。
- 静态渲染：悬疑视图在加载中/空/有数据时都能输出可识别结构；不产生未捕获异常。
- 类型检查：`npm run build` 的 `tsc --noEmit` 通过。
- 现有 `storyLayout.test.ts`、`story.test.ts` 通过。

## 2. 浏览器专项

在固定夹具或真实记录上验证：

1. 打开构思页，默认看到悬疑视图；点击“结构”回到现有画布，阶段筛选、节点详情、撤销不回归。
2. 横向滚动时间轴；左侧泳道标签保持可见；节点列按实际时间顺序，未登记节点在末尾并有标记。
3. “实际发生 / 侦探与助手 / 读者”三层内容可读；没有数据的格子显示“未登记”，不显示伪造内容。
4. 点击线索 chip：下方详情切换；显示表面呈现、作者真相、想引导、知情和生命周期。
5. 点击详情里的节点：切换到结构视图并选中该节点。
6. 诊断条显示主链过长、时间覆盖不足或线索缺项；不遮挡时间轴与详情。
7. 窄屏（约 900px 以下）：时间轴仍可横向滚动，底部列表与详情上下堆叠，不出现横向溢出到整页。
8. 打开既有 1.0.3 作品不报错；缺少新字段时按“未登记”显示。
9. 生成中点击「插话」：作者消息以绿色气泡出现在旧回复之后、新生成内容之前；刷新或回放后位置不变，重复事件不重复显示。

## 3. 在线生成验收

用强模型（优先配置中的推理模型，不用本地模型）创建一个新的悬疑构思，输入使用悬疑 brief。检查：

- `event_times` 至少覆盖案发窗口的主要节点；悬疑视图的时间覆盖不是 0。
- `STORY_MAIN_CHAIN_LONG` 不出现，或出现时作者能在最终回复中说明为什么保留单线。
- 每条关键线索至少有一次 `plant` 和一次 `resolve` 或 `reinterpret`；误导线索有非空 `expected_interpretation`。
- 至少一条线索同时有两种读法：表面呈现与作者真相不同，且表面读法由真实事实支撑。
- 生成结果能被悬疑视图完整打开，不出现 500 或前端异常。

本版不做自动读者模拟器；在线生成只做一次人工检查，不把“模型是否听劝”当成确定性门槛。

## 5. 不做验收

- 不要求 1.0.3 旧作品补齐实际时间或线索生命周期。
- 不要求单线作品通过 `STORY_MAIN_CHAIN_LONG`；诊断只是提示。
- 不要求模型在自由文本输入下稳定产出；本版只保证悬疑 brief 与悬疑视图可用。
- 不验收自动推理、自动公平性检查或读者模拟器。
