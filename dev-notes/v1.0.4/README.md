# 1.0.4 开发入口：悬疑视图与构思诊断

更新：2026-10-31。运行版本：**1.0.4**。悬疑视图、只读投影、结构诊断与创建 brief 已接入；目标测试、前端全量单测、构建和浏览器专项通过，完整在线生成验收待执行。同日补充修复生成中「插话」消息不显示：前端补 `author_interjected` 事件与作者气泡。

## 本版要解决的问题

最新一条真实构思（`未命名作品4`）有 20 个节点、6 条故事线、21 条关系、17 条线索，但 20 个节点仍被一条 `next` 主链串起来；实际时间只登记了 4 条，线索主要挂在节点内部，画布只画节点和推进边。作者看到的仍然是一条纵向流程，而不是“实际时间轴 + 线索节点”。

本版不把问题归结为“卡片不好看”。单链的根源有三层：

- 数据：模型用 `next` 串联发生先后，`event_times` 覆盖不足，线索缺少完整的埋设、误导、重新解释和回收。
- 投影：现有图接口以节点/推进边为主，没有把实际时间、线索生命周期和读者认知整理成可直接阅读的结构。
- 入口：创建构思只有一个自由文本框，模型容易把它当成“写章纲”，而不是“设计谜题”。

## 本版范围

1. **悬疑视图**：在构思页增加“悬疑 / 结构”切换；悬疑视图横向展开实际时间，按“实际发生 / 侦探与助手 / 读者”三层排列，并把线索作为可点击的节点；线索详情显示表面呈现、作者真相、想引导的读者理解、角色知情和生命周期。
2. **只读投影**：后端新增悬疑投影接口，不改写现有故事状态。投影只整理已有事实，不替作者推断真相，也不在客户端拼一份“大概如此”的结构。
3. **构思诊断**：扩展现有结构诊断，指出“主链过长”“实际时间未登记或覆盖不足”“线索只有埋设没有回收”“误导线索没有写读者读法”等问题。诊断是提示，不直接阻止作者保留有意的模糊。
4. **创建契约**：把创建构思的默认提示改成悬疑 brief；在系统提示和结构工具说明中明确 `event_times`、`next`、`reframe`、线索生命周期和知情记录各自的职责。
5. **版本与文档**：版本号升到 1.0.4，补齐确定性测试、浏览器专项和本文档的验收记录。

## 本版不做

- 不重写 `StoryNode` / `StoryVariant` 为新的 `Event / Reveal / Clue / Hypothesis` 模型。
- 不增加自动“读者模拟器”或批评者模型；在线生成质量只做一次人工检查，后续版本再讨论。
- 不改正文写作、正文绑定和现有修订/撤销协议。
- 不迁移旧数据。旧作品缺少新增诊断所需字段时，按“未登记”显示，不伪造内容。
