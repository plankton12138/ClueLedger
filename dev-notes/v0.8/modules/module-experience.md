# 模块内容与侧栏体验

日期：2026-10-25。状态：已实施。产品与前端版本保持 `0.8.0`，装配格式继续为 1。

产品决定见[模块体验设计](../../../product-design/v0.8/module-experience.md)。此说明更新 H3 的表单与日常操作行为，H1–H6 的原实施记录保留为阶段历史。

## 当前行为

- 模块库采用搜索与内容卡片，不显示类型筛选、条目标签与版本计数。卡片预览来自已核验的第一份正文，最长 120 字符。
- 新建只填写名称与正文，名称可从首行生成。新内容使用兼容的 `reference` 类型和一个内容记录，不要求填写条目标题或其他字段。
- 添加成功后返回写作，侧栏立即显示挂载的模块。模块目录来自正文的小标题；已有多条目模块保留各条目的标题与稳定定位。
- 稿纸区域支持模块阅读与就地编辑；章节文件继续沿用原阅读方式。旧模块的 ID、类型、别名与附加字段在内容修改中保留。
- 作品保存仅切换当前作品的内容版本和显示名称。模块库的 head、原稿更新时间、其他作品引用保持不变。
- “另存到模块库”新增一份内容，重复提交采用同一请求键。移除与撤销保留原绑定身份和仍有效的关联。
- 已有设定文件保持原路径，侧栏折叠显示“原有资料”。缺失设定文件的占位不进入默认侧栏；显式导入入口在模块库更多菜单中。

## 接口与存储

新增 `PUT /api/file-workspaces/{workspace_id}/assembly/{binding_id}/content`，请求字段为：

| 字段 | 用途 |
|---|---|
| `module_id`、`base_revision` | 确定草稿所基于的内容，拒绝覆盖已切换的绑定 |
| `name`、`entries` | 当前作品的显示名称与完整内容，保留旧记录元数据 |
| `expected_digest` | 作品装配的并发检查 |
| `request_key` | 同次保存的重试身份 |

返回新的装配视图。保存先写入不可变内容版本，再按装配指纹替换当前绑定；库 head 不前进，版本 parent 指向草稿基础版本。绑定失败可能保留未挂载的内容版本，不能报告作品已保存。响应丢失后原请求可重放，不重复创建版本。

库的 HTTP 列表带可选 `preview`。底层 `ModuleLibrary.modules()` 默认仍只返回元信息；模型的全库搜索不因此隐含读取正文。已挂载模块继续通过精确版本参与目录、检索与原文读取。

写作轮次运行中拒绝保存装配，沿用 `ASSEMBLY_BUSY_CONFLICT`。作品切换、详情切换与后台刷新分别核对上下文，后台作品刷新不能接管已打开的模块库。

## 草稿与兼容

作品草稿按作品和绑定隔离，并记录最初的内容版本。外部版本改变后仍保留原草稿；重新读取不会把草稿自动变成可覆盖的新基线。作者可另存草稿到库，或取消草稿后重新编辑。

新建草稿和库内编辑草稿仍留在应用会话中，切页面可继续，刷新前提醒。已保存的内容可以在重载后恢复；不承诺重载恢复未保存输入。

## 模型自主维护

作者明确要求创作或修改资料时，写作 Agent 可以在同一任务内新建多份模块、更新已有模块，并通过 `prepare_module_changes` / `apply_module_changes` 一次保存并应用。它先按 `set_task_scope` 的 `module_content_grants` 登记稳定槽位或精确绑定，再读取实际版本、生成内容并提交变更集。

变更集准备只写任务进度；应用时先保存作品内内容版本，再按装配指纹一次替换本次涉及的绑定。应用成功后本轮进入收尾，不再继续写入。内容保存失败时保留生成稿，可继续保存；应用后的结果在对话里显示名称与撤销入口。撤销只恢复本次涉及的绑定，库内新增副本与其他作品不受影响。

确需作者决定的取舍用 `ask_author` 记录：问题、选项与关联路径写进作品状态目录，本轮以「等待作者回答」结束并释放运行锁；作者回答后开启新轮次，按 `reply_to_question` 核对归属与装配指纹并承接原请求。重复回答、跨会话回答与装配变化都会被拒绝，不会把旧按钮当成新的授权。

`v08-modules` 的 3 例在线语义评测已用 `deepseek-flash` 跑通并人工复核：自主新建多模块、下一轮局部更新、讨论不保存；另有 `v08_author_question` 验证提问暂停与回答后继续。运行证据见[实施方案第 9 节](../agent-module-management-plan.md#9-实施记录2026-10-25)。
