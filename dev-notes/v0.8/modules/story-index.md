# 统一章节与事件索引

状态：**已实现（0.8 E）**。运行版本 `0.8.0`。本文只写当前接线行为；阶段过程见
[E 记录](../notes/E-story-index.md)与[多来源贡献记录](../notes/E-multi-source-contributions.md)。

## 1. 一份投影，两个视图

一次整理只产出一份数据，存在作品状态目录的 `story-index.json`，一章一条投影：

```text
story-index.json
└─ chapters: {
     "正文/0001 雪夜来客.md": {
       path, digest, chapter, recipe_version, generated_at,
       summary, events: [...]
     }
   }
```

- **章节视图**（`order=chapter`）：按章序看「这一章发生了什么」，带摘要、事件与原文区间。
- **故事视图**（`order=story`）：只对**可证明的先后**排序。没有任何时间关系的事件单独列出，
  环与日期矛盾显示双方来源，不生成看似有效的全序。

两种视图不各自保存一份正文；旧版章节概览与时间锚点只读兼容，发布成功后按章切换，不做全量
自动重建。

## 2. 事件观察不是事实

每条事件带一个表达方式 `mode`：

| `mode` | 含义 |
|---|---|
| `narration` | 叙述 |
| `testimony` | 证词 |
| `flashback` | 回忆 |
| `speculation` | 推测 |
| `dream` | 梦 |
| `unknown` | 未知，也是合法取值 |

回忆既不自动等于虚假，也不自动等于真相。证据只证明原文里存在这段话，不证明人物说法为真。
「嫌疑人声称没有离开房间」应登记为证词，不能当成客观的「不在场」事实。

## 3. 引用与边界

- 人物与作者事件都使用**库／模块／修订／条目**四段引用（`RecordRef`）。不同作品里的同名人物
  不会因为名字相同被串在一起。
- `story_time` 支持绝对时间、相对时间与未知；代码不把章号当故事时间，也不对自由文本做日期运算。
- 单章摘要上限 500 字符，单条事件 300 字符，一章最多 30 条事件，防止一次提交淹掉整个视图。
- 发布要求投影指纹等于当前原文；源文件改过返回 `STORY_INDEX_SOURCE_STALE_CONFLICT`。
- 发布是整章替换：锁内重读，另一进程刚发布的章不会被抹掉；重建一章只替换这一章的贡献。
- 重建后确认没有可发布的观察时只移除这一章的投影；空操作可安全重试，不会顺手清掉别的章。

## 4. 线索、名词与时间线的多来源贡献

这些派生记录都按章记录贡献，重建一章只动这一章：

| 记录 | 按章替换 | 空批含义 | 读取侧合并 |
|---|---|---|---|
| `clues.json` | `replace_source(chapter, entries)` | 这一章确认没有线索，移除该章旧贡献 | 同一线索保留最新章的贡献；旧章贡献仍在存储里供追溯 |
| `glossary.json` | `replace_source(chapter, terms)` | 这一章确认没有新专名 | 同名同类取最新章，别名取并集，首次出现章取最早 |
| `timeline.json` | 一章一个锚点 | 这一章确认没有时间锚点，移除该章旧锚点 | 按章排列；其余章不受影响 |
| `story-index.json` | 整章投影替换 | 确认没有可发布观察时移除该章投影 | 章节视图与故事视图共用 |

- `insufficient`（材料不足、无法判断）**不清除**任何旧贡献；只有 `empty`（读完确认没有）
  才会按章移除。这避免一次没读完的整理把已有记录误删。
- 失效判定按证据指纹：源章节改过即整条不采用，并给出警告；作者计划保留。
- 人物身份、人物状态、时间线、线索与名词的作者视图继续沿用 0.7 的接口与页面，
  多来源只改变存储与合并规则。

## 5. 整理任务

- 受理时冻结范围：章节列表、章号、源文件指纹与截止章。目标超出截止章、章序重复或指纹不符时，
  在受理阶段拒绝。
- 发布时每条记录都要引用**本次实际读到的原文区间**；只给索引或摘要不算读过全文。
- 任务使用专用会话（`origin=materials`），不出现在写作会话列表；只读正文并发布派生资料，
  没有作品写权限。
- 结果分为 `found`、`empty`、`insufficient`；没提交记为部分完成，不伪装整批成功。
- 覆盖记录 `materials-coverage.json` 带来源指纹；源文件一改，覆盖与派生记录都标为失效。

## 6. 接口与页面

| 能力 | 接口 |
|---|---|
| 章节视图／故事视图 | `GET /api/file-workspaces/{id}/story-events?order=chapter｜story` |
| 作者视图（身份、状态、时间线、线索、名词） | `GET /api/file-workspaces/{id}/story-materials/{domain}` |
| 单条详情 | `GET /api/file-workspaces/{id}/story-materials/{domain}/{entry_id}` |
| 发起整理任务 | `POST /api/file-workspaces/{id}/material-tasks` |
| 任务列表与详情 | `GET /api/file-workspaces/{id}/material-tasks[/{turn_id}]` |

资料页「章节与事件」可切换两种顺序；「人物」「线索与伏笔」「名词表」继续显示覆盖与失效状态。
旧的 `#/materials/chapters`、`#/materials/timeline` 路由映射到合并后的页面，链接可用但页面只有
一份视图。

## 7. 边界

- 不自动重建索引，也不在启动时运行模型任务；重建由作者发起。
- 同一事件的多条计划线尚未叠加显示；当前只有一份统一故事索引。
- 故事视图的偏序只表达能证明的先后，不补全缺失关系，也不把未知时间排成确定顺序。
- 资料导入没有实施；作品包导出导入已取消。
