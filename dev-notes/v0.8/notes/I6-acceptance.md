# I6 专项验收与交付收口

日期：2026-10-25。状态：**已完成**。本阶段把 I0–I5 的结果按矩阵逐项登记，补上在线语义验收，
核对入口与版本，并明确没有执行的范围。

## 1. 为什么把在线验收单独放在最后

前面的阶段每步都有确定性回归，但那只能证明「接得对」，不能证明「说得对」。只读展开要求模型
给多种方向、写清代价、列出待确认问题；这些只能看真实回答。反过来，模型偶尔的措辞差异也不该
被当成产品缺陷，所以在线结果按证据逐条复核，不把自动评分当结论；这次复核由助手完成并填写
理由与事件位置，作者可随时复看推翻。

评测器这次补了两处：步骤可以声明 `purpose=expand_idea`，走与产品相同的受理与只读装配；
新增「未调用指定工具」的确定性检查，把「明确禁止搜索或保存」变成可判定的事实，而不是靠读回答猜。

## 4. 入口与版本核对

**接口**：`GET /ideas`（含 `order`）、`GET /ideas/{id}/activity`、`purpose=expand_idea` 都有前端调用方；
`POST /ideas/{id}/links` 保留但没有前端入口——它登记作者手动关联，目前只在活动记录里作为
「关联」被读取，没有界面创建。这是有意保留的契约，不是漏接。

**工具**：`read_idea`／`search_ideas`／`save_idea` 仍由模型工具表提供；只读展开只放行
`read_idea`，`build_tools` 的显式白名单在 I4 已覆盖。

**事件与按钮**：本轮没有新增事件类型；面板上的「展开讨论」「用于写作」「使用记录」及其
「继续整理／继续读取／刷新记录／打开讨论／打开正文」都有处理函数，没有保留重复入口。

**版本**：`pyproject.toml`、`hastings.__version__`、`frontend/package.json` 均为 `0.8.0`。
`desktop/package.json` 仍为 `0.7.0`，本轮没有打包桌面壳，不据此声称桌面产物已交付。
