# I3 固定版本引用与对话选段再记录

日期：2026-10-25。状态：**已完成**。本阶段接通「灵感 → 讨论」和「讨论 → 灵感」两个方向，
不改执行用途与模型能力（那是 I4）。

## 1. 这一层解决什么

引用最容易含糊的地方是「引的是哪一版」：

- 原文会继续修改，但已经带进对话的那一版不能悄悄跟着变，否则作者说不清模型看到了什么。
- 界面此前显示的是标题或内部标识，作者看到一串 `irev_…` 才知道自己引了哪条。
- 有未保存修改时「带到对话」直接禁用，作者必须先保存再点一次；这中间他可能改主意。

本阶段的处理：**引用绑定保存结果的具体修订**，界面显示**原文短预览**，只有作者明确点
「更新到最新版本」才换版本。

## 2. 实现

### 引用本身

- `DraftIdea` 从「标识 + 标题」改成「标识 + 修订 + 原文预览 + 字符数」。预览在客户端由
  正文合并空白后截前 48 字符生成，只用于显示，不写回服务端，也不当编辑原文。
- 同一条目再次加入：同修订忽略，换修订原位更新，不会叠出第二个引用（IE12）。
- 引用的加入、移除与更新都按「作品 + 会话草稿槽位」隔离，切会话互不影响。

### 显示与更新

- `components/chat/IdeaReferenceChip.tsx`：输入区的引用 chip 显示预览，点击才读取完整原文。
  对话框里给出字符数、原文、以及「这条灵感已有更新的版本」的提示；按钮只有「移除引用」
  与「更新到最新版本」，不自动替换。
- 未点开前不预取所有引用的最新版本：一次点击只读一条，避免为显示提示而反复请求。

### 保存后引用

- `state/ideas.ts` 新增 `prepareReference(ideaId)`：有脏稿先保存，保存失败就返回空，
  界面留在面板并显示错误；保存成功才用返回的 `(workspaceId, ideaId, revisionId)` 建立引用。
- 「带到对话」不再因为脏稿禁用。引用完成后收起面板并回到写作页，聊天草稿、其他参考与
  返回位置都保留。

### 对话选段记成灵感

- 消息容器带 `data-role`、`data-turn-id`、`data-turn-index`；选段只在**稳定消息**上生效，
  运行中的流式文本不给入口，避免伪造定位。
- 选中文字后出现浮动的「记成灵感」，直接把选段原文提交到作者创建接口，`origin` 带
  角色、会话、轮次序号、轮次 ID 与引文；接口新增可选 `turn_id`。
- 命令身份按「会话 + 轮次 + 角色 + 原文」冻结：网络重试复用同一请求键，作者另一次独立
  操作是新命令。
- 成功后提示「已记成灵感：<预览>」，可直接打开面板定位到新记录；失败保留提示与选区。

### 受理之后才算使用事实

- 轮次显示新增「本轮灵感 N 条」，来源是 `turn_started` 事件里冻结的 `idea_revisions`，
  并写明「只表示这一轮带上了这条灵感，不表示模型读完了全文」。
- 服务端 `IdeaReference.view()` 增加 `preview`，提示词里的标题也改用预览，
  没有标题的灵感不再以内部标识出现在模型上下文里。
- 发送失败保留输入与引用；受理成功后才清掉本轮草稿里的引用。
