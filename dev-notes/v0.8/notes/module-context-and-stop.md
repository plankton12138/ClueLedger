# 模块上下文与停止响应修复

日期：2026-10-26。状态：已实施；版本保持 `0.8.0`。

## 原因

作者这轮已经冻结并装配三个模块，运行记录也显示三个模块原文读取成功。
随后模型仍逐个人物构造旧小传路径，连续触发 `STATE_NOT_FOUND`。
问题在于模块装配之外仍保留了旧版默认指引：

- 作品目录在没有旧文件时仍列出角色小传创建提示、缺失的线索和真相路径。
- `settings_section` 为不存在的旧文件生成“尚未写入”占位，并加入 `settings` 分区。
- 系统要求写人物前先查 `read_state`，该工具的身份查询却只支持旧版角色小传。

因此，界面里出现旧“设定集”分区是真实的装配残留，不代表已装模块丢失，也不是模型已经读到旧文件全文。
该轮的默认约定与工具来源没有完成模块化对齐。

停止是另一个独立问题。原运行记录中，22:01:41.235 记下 `stop_requested`，
22:01:47.273 才记下 `run_finished`，相隔 6.038 秒。
停止只设置同步取消标记，供应商流在等响应头或下一段数据时不会检查它。

## 修改边界

新作品以已装模块为资料入口：目录不生成旧文件占位，不再要求先为模块人物查询旧身份状态。
`list_files` 也只向模型返回真实存在且未导入模块的旧文件。
`read_state` 明确说明身份记录来自旧小传；没有记录返回 `not_recorded` 与空列表，
并给出读取模块或作品原文的下一步，不把“未记录”解释成人物不存在。

旧文件兼容仍保留：实际存在且未导入模块的文件可以列出和读取，已有内容不迁移、不删除。
只有这种作品才追加旧文件兼容约定；没有一并取消历史文件接口和身份记录格式。

在应用的模型请求记录层增加可中断的异步读取：等待数据期间至多每 50ms 检查一次取消标记，
停止后取消该次模型读取并关闭流，以 `aborted` / `stopped` 收尾，保留已收到的文字。
这个间隔不是整轮停止耗时承诺；保存工具和版本记录继续正常收尾，不强行中断已开始的保存。
界面点击即显示“正在停止…”，防止重复提交，收到终态才恢复发送；请求失败恢复重试入口。

  两个静默场景均在 1 秒测试上限内结束，确认关闭流、保留片段、停止事件与模型终态各一份。
- 首批相关后端 111 项通过；前端 279 项通过，生产构建、受影响后端 Ruff / mypy 通过。
- 后端工作区与评测全量首次 953 项通过、3 项失败。三项是旧兼容提示、缺失文件占位和案例数量的断言；
  保留旧角色读取要求、调整占位与案例断言后，相关 40 项及最终上下文、兼容、停止的 47 项回归通过。
  没有在这些修正后再次运行整个全量集合。
- 浏览器停止交互专项 1 项通过：在停止请求仍未返回时即显示禁用的“正在停止…”，
  收到服务端停止终态后恢复发送入口。

没有使用作者原文或本机模型。
首次夹具构造使用了不合法的 `setting` / `plan` 条目类型，在请求模型前失败；
修正为 `place` / `plot_plan` 后，新建独立运行保留了首次有效轨迹。
