# I1 正文优先的数据与命令层

日期：2026-10-25。状态：**已完成**。本阶段只改数据与命令层和必要的界面接线，
悬浮面板、展开与使用事实不在本阶段。

## 1. 这一层解决什么

灵感记录只需要原文。此前的实现有三处把「原文」当成次要信息：

- 服务与模型工具保存前 `strip()` 正文，作者写下的首尾空白、缩进和换行被改写，
  长度也按去空白后的文本计算。
- 列表固定按更新时间排序，摘要固定截前 120 字符且没有截断标记。恢复一条旧灵感会把它
  挪到列表最前，作者按时间找记录的习惯被打断。
- 保存没有明确的命令身份：前端按「当前选中」提交，网络结果不明时重试可能换请求键，
  保存期间继续输入会把同一段文字另建成第二条灵感。

本阶段把这三件事拆开：**原文按原样保存**、**列表按创建时间**、**保存是一次冻结的命令**。

## 2. 服务端

`workspace/ideas.py`

- `_checked_content` 只用 `strip()` 判断是否全空白；正文按原文计长并保存原文。
  标题与标签仍是旧字段，继续裁剪与校验，旧修订不改写。
- `update()` 在正文与旧字段都没变化时不追加空修订，只把这次请求记在头上，重试仍幂等。
- `list()` 新增 `order=created|updated`（默认 `updated` 兼容旧客户端）。排序方式进入
  游标身份，换排序不能复用旧游标。
- 摘要新增 `created_at`、`body_chars`、`excerpt_truncated`，摘要长度由 `EXCERPT_CHARS` 统一。
- 新增 `resolve_reference(idea_id, revision_id)`：在同一条目锁内核对「条目当前未删除、
  所选修订存在且不是删除修订」，一次读盘给出本轮冻结的原文。

`workspace/materials.py`

- `freeze_context` 改用 `resolve_reference`。此前只检查所选修订的 `deleted` 标记，
  条目已删除但选择的是更早的可读修订时会被放过；现在这类新受理一律拒绝，
  已经受理的轮次仍使用原快照。

`workspace/ideas_api.py`

- `GET /ideas` 增加 `order` 参数，其余路由不变。

`workspace/agent.py`

- `save_idea` 的 schema 只公开 `body`；执行层仍接受 `title`、`tags`，供历史重放。
- 幂等键从每轮一个改成每次调用一个：`{turn_id}:idea:{tool_call_id}`，
  调用方没有提供调用 ID 时按本轮第几次保存生成稳定序号。一轮里明确要求保存多条时
  各自独立幂等，同一次调用的重试不会新增记录。

## 3. 前端

`api/ideas.ts`

- 创建只提交 `body`、`request_key` 与可选 `origin`；更新只提交 `body`、预期修订、
  预期指纹与请求键。列表类型补上长度与截断字段，`order` 显式传 `created`。

`state/ideas.ts`（重写）

- 草稿分成两类：`capture`（快速记录，只有正文）与 `editing[ideaId]`（条目修改稿）。
  每份草稿有稳定标识、编辑序号与基线修订，不再共用「新建」槽位。
- 保存是一次冻结命令：提交时确定请求键、正文快照与编辑序号。同一草稿同时只有一次保存，
  重复点击拿到同一个结果；内容变化才换新请求键，结果不明时用原键重放。
- 保存返回 `saved | unchanged | failed`。`unchanged` 由服务端返回的修订号与基线相同判定。
- 保存期间继续输入：结果绑定到已创建的条目，新增内容留在同一条灵感的修改稿里，
  不会另建重复记录；内容没变时清空快速记录草稿并保持输入焦点。
- 删除、恢复也走同一套命令身份，重试不产生多次删除或恢复修订。有未保存修改时
  删除、恢复与恢复历史都先被拦下，由作者决定保存还是放弃。

`components/ideas/`

- `IdeaCapture`：只有正文输入框，`Ctrl/⌘ + Enter` 提交，输入法选词期间不提交。
- `IdeaList`：按创建时间显示原文摘要，标出未保存、总字数与截断；正文为空的旧条目给出
  诊断而不是内部 ID。
- `IdeaEditor`：正文原位编辑，`完成` 提交、`放弃修改` 回到基线；删除脏稿时提供
  「返回编辑 / 保存后删除 / 放弃修改并删除」三种明确选择。
- `IdeaHistory`：只读预览与恢复，显示每条修订的字符数。
