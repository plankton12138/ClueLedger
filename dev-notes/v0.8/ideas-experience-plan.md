# 0.8 灵感全流程改造开发计划

日期：2026-10-25。状态：**方案已制定，I0–I6 均待实施与验收**。
产品名称为**线簿 / ClueLedger**，产品版本继续为 **0.8**，主应用与前端包保持 `0.8.0`。
本文只定义后续开发，不代表悬浮面板、模型展开或自动使用关联已经实现。

## 1. 目标与文档关系

作者想到一句话时，应能立即记录；之后能在同一入口找回、修改、删除、引用和展开，
最后按明确的写作要求用于作品。记录时只输入原文，不承担命名、分类和整理工作。

本计划承接作者确认的方向：取消灵感的标题与标签操作，以悬浮面板组织完整流程。
它取代[前端体验计划](frontend-experience-plan.md)中关于灵感独立页面、标题列表与编辑表单的后续设计要求；
该文 H1–H6 的历史实现、截图与测试结论保持原样，不回写为本专项的交付证据。
作品隔离、固定修订引用、冲突保护和当轮授权继续沿用。

配套阅读：

- [模块实现示例](ideas-experience-examples.md)：分模块的建议接口与关键处理模式，均为待实现示例。
- [C 灵感记录](notes/C-ideas.md)、[许可与草稿修复](notes/C-idea-permissions-and-drafts.md)：既有服务与历史验证。
- [0.8 实施计划](development-plan.md)、[运行说明](release.md)：版本整体交付状态，不由本计划更新。

### 1.1 本次交付范围

| 范围 | 交付要求 |
|---|---|
| 记录 | 任意作品页面呼出、正文输入、连续记录、失败重试、草稿保留 |
| 管理 | 原文列表、全文搜索、原位编辑、删除撤销、最近删除、历史恢复 |
| 引用 | 保存后引用、原文预览、引用更新、指定版本发送 |
| 展开 | 一次点击发起只读讨论、继续讨论、停止与失败恢复 |
| 再记录 | 对话选段记成新灵感，保存准确的来源定位 |
| 用于作品 | 选段带入写作要求、明确目标、复用现有范围和写入校验 |
| 回看 | 真实对话引用、经核对的写入位置、位置变更与撤销后的反馈 |
| 兼容 | 旧记录不丢失，旧链接可达，版本保持 `0.8.0` |

### 1.2 取舍与边界

- 灵感仍归属当前作品。切换作品分别保留草稿，不新增跨作品灵感库。
- 悬浮面板属于应用窗口，不实现操作系统级悬浮窗、后台常驻或系统全局快捷键。
- 不新增标题、标签、颜色分类、完成状态、提醒、自动分类或后台模型任务。
- 语音录入本次不交付；保留普通文本输入与系统现有听写方式的兼容性。
- 记录不依赖模型；只有明确点击展开或提交对话时才调用模型。
- 正文继续为只读阅读器；用于写作仍走对话任务与受控文件修改，不新建正文编辑路径。
- 草稿保证当前应用页面会话内保留。跨刷新、跨重启的持久草稿不纳入本次承诺。
- 不批量迁移或删除旧灵感字段，不提升作品存储格式版本；新增应用派生索引必须可重建。

## 3. 交互方案

### 3.1 一个内容组件，两种容器

- 顶栏“灵感”改成面板开关，显示展开状态；其他主页面继续正常导航。
- 宽桌面使用非模态面板，参考宽度 440–520px，高度受视口约束；允许操作背景内容。
- 面板不支持自由拖拽和多实例。打开时不挤压正文，不覆盖应用的全局停止操作。
- 窄窗口或字体放大导致空间不足时切换近全屏容器，提供返回和收起，正确管理背景焦点。
- “展开查看”使用更大的内容区域；复用同一列表、编辑器和状态，不复制第二套业务逻辑。
- 实际容器尺寸和字体比例决定布局。桌面矩阵为 1440、1024、760、640px × 100%、150%；390px 观察。
- 搜索、历史、最近删除在面板内部切换，不叠出一串模态窗口。
- 原有 `#/workspaces/{id}/ideas?entry=…` 链接继续有效，打开展开容器并定位记录。

焦点规则：打开记录入口时聚焦输入框；收起后回到原触发位置；从引用打开时聚焦对应记录。
打开“展开查看”不重置搜索、草稿和滚动。Esc 先关闭内部菜单，再收起当前面板；中文输入组合期间不处理 Esc 提交逻辑。
宽屏不强行锁住背景焦点；窄屏模态状态才限制焦点范围。用键盘和指针均能找到操作。

### 3.2 记录与连续输入

1. 输入框只有正文，可有“想到什么，先记下来”的占位提示；无障碍名称为“记录灵感”。
2. Enter 换行，`Ctrl/⌘ + Enter` 提交，中文输入法选词期间不提交。
3. 保存成功才清空本次未变化的输入，并保持输入焦点；列表加入新记录。
4. 等待保存时允许修改文本，同一草稿不并发提交。保存响应不能清掉之后输入的文字。
5. 若提交期间文本改变，保存结果绑定到已创建的同一条记录，新增修改保留为未保存稿；
   下一次“完成”更新该记录，不能把包含原文的整段输入另建成重复灵感。
6. 网络结果不明时保留命令快照和原请求键，先确认或重放原命令；不能用新键重建同一记录。
7. 收起、切页或切换作品不等于放弃；每份草稿有稳定标识，不能共用一个“新建”槽位。

快捷键只在应用聚焦时生效；I0 核对现有快捷键、浏览器保留键与中文输入法后，确定并记录默认组合。
快捷键冲突不影响顶栏入口，不拦截系统保留组合。

### 3.3 浏览、修改、删除与恢复

- 列表按创建时间倒序，以原文识别内容；正文为空的旧异常条目显示可理解的诊断，不显示内部 ID 充当标题。
- 短内容完整显示；较长摘要明确提供“展开”，获取完整指定版本后才能编辑。
- 点击正文进入原位编辑，“完成”提交，“放弃修改”恢复编辑基线；不因失焦自动增加修订。
- 若跳到别的条目，当前修改留在原条目草稿中；列表有简短的未保存标记。
- 历史只读预览，恢复通过新增修订完成。列表使用创建时间，不因恢复跳到最前。
- 删除已保存条目后显示“已删除 · 撤销”；最近删除可恢复同一标识。
- 有脏稿时删除，明确提供返回编辑、保存后删除或放弃修改后删除；仅此类放弃内容的操作需要选择。
- 删除、恢复同样冻结命令身份；结果不明时重复请求不得增加多次删除或恢复修订。
- 草稿冲突时保留本地输入，提供查看当前版本与复制内容；不自动合并或静默覆盖。

### 3.4 引用与展开

| 操作 | 行为 | 成功后的落点 |
|---|---|---|
| 引用到对话 | 有脏稿先保存；绑定保存结果的具体修订；加入当前会话输入区，不发送 | 当前作品写作页的对话区域，输入和其他参考保持 |
| 展开 | 有脏稿先保存；第一次用指定修订直接受理只读展开请求，首次发送即建会话 | 标准对话区域，展示流式生成和停止 |
| 继续讨论 | 打开已有讨论，不自动再发相同请求 | 原讨论会话，保留该会话草稿 |
| 更新引用 | 作者明确选择最新修订，更新原引用及其预览 | 留在当前输入区 |
| 记成灵感 | 对话选段直接创建新条目，保留来源定位 | 原对话不切走，可从成功提示打开新灵感 |
| 用于写作 | 把选段和原灵感版本带入写作要求，选择目标后提交 | 现有写作任务与结果展示 |

首次展开使用独立的普通会话，不复用正在编辑的聊天草稿。会话只有受理成功才建立关联；
双击与断线重试只回到同一个轮次。关联会话被删除时，提示不可用，并允许明确发起新讨论。
一个灵感可以有多次讨论；默认继续最近一次，完整列表放在相关记录中。

展开采用明确的请求用途 `expand_idea`，初次至少且只绑定一条灵感版本，不自动带入当前正文章节、
其他会话草稿、未选灵感或全作品材料。默认要求给出不同展开方向、影响和待确认问题。
后续讨论每次仍提交明确的用途与参考；不能只凭会话名称决定本轮权限。

作品已有运行任务时，保留选择并展示已有任务入口，遵守单任务约束，不偷偷排队或停止原任务。
模型未配置时可继续管理灵感；配置完成后保留待展开的选择，但不在关闭设置时未经操作自动发送。

### 3.5 使用事实与位置

| 显示内容 | 权威依据 |
|---|---|
| 已加入当前输入 | 当前会话草稿，仅表示准备引用 |
| 在某次对话中引用 | 已受理轮次事件中的固定灵感引用；不声称模型已读完整原文 |
| 在某次对话中展开 | 已受理且用途为 `expand_idea` 的轮次；失败、停止仍如实显示状态 |
| 已写入某章 | 作者明确把选段用于写作，实际变更已发生，目标指纹、区间与引文核对成功 |
| 该位置已变更 | 当前正文已无法核对原指纹与位置；仍保留当时的关联 |
| 该次修改已撤回 | 对应文件修改已有明确撤回事件；不能继续显示为当前有效写入 |

不从助手措辞推断写入，也不把本轮所有参考自动标为已采用。
无法确定具体使用区间时只记录对话引用或写作任务关联，不制造虚假的“已写入”。
正文修改成功而关联失败时，显示“正文已修改，使用记录待补齐”，只补关联，不能重跑正文修改。

## 4. 数据、接口与执行契约

### 4.1 正文与兼容字段

- 新客户端创建提交 `body`、`request_key`，可选 `origin`；更新提交 `body`、预期修订、预期指纹和请求键。
- 旧 `title`、`tags` 继续可读，旧客户端提交仍兼容；新界面与模型不生成、不要求、不修改这些字段。
- 更新旧记录时省略兼容字段，不能用空值覆盖历史标题和标签。旧标题与标签可在历史详情中按需查看。
- 保留正文 20,000 字符上限、空正文错误码和修订校验。当前服务与工具会去掉首尾空白，
  本次改为只用 `trim` 判断是否全空白，按原文计长并保存原文；旧修订不改写，补齐边界兼容测试。
- 原文预览是显示时生成的短文本，不保存为新标题，不调用模型，不能作为编辑原文。

### 4.2 接口增量

接口前缀继续为 `/api/file-workspaces/{workspace_id}`。

| 接口或契约 | 计划增量 | 对齐要求 |
|---|---|---|
| `GET /ideas` | 增加 `order=created\|updated`，兼容默认 `updated`；摘要增加 `created_at`、`body_chars`、`excerpt_truncated` | 新界面显式使用 `created`；排序、查询和结果版本纳入游标身份 |
| `POST /ideas`、`PATCH /ideas/{id}` | 服务端兼容默认值；前端正文优先；对话选段创建接通 `origin` | 前端草稿类型移除标题和标签，更新请求不清空旧字段 |
| 删除、恢复、历史接口 | 沿用路由，补冻结命令、完整历史读取与撤销接线 | 未确认结果保持原请求键；恢复保持条目标识 |
| `GET /ideas/{id}/activity`（新增） | 分页读取引用、讨论和已核对写入的相关记录 | 每项有固定事件身份、关联修订、会话或路径、时间和当前可用状态 |
| 现有新建会话、续聊接口 | `purpose` 增加 `expand_idea`，明确校验灵感参考与不兼容字段 | API、前端、受理去重、日志读取、重放和运行模式同步支持 |
| `context.idea_references` | 网络请求继续只传标识与修订；显示侧维护预览 | 服务端根据指定版本取原文，不相信前端传来的内容 |
| `POST /ideas/{id}/links` | 保留；连接明确的作者关联和核对后的写入 | 不把普通受理引用重复写入可变灵感文档 |
| `save_idea` 工具 | 新 schema 仅需正文，执行层保留旧参数兼容 | 幂等键细化到稳定的保存操作，不再每轮只能保存一条 |

活动读取不要求浏览器获取所有对话日志。新增 `idea_activity.py` 负责聚合：
受理事件是引用和讨论的权威来源，已核对使用关联是写入来源；派生索引放入既有作品应用状态目录，
只保存标识、事件位置和恢复游标，不复制灵感正文。索引失败不撤销受理，可从事件日志重建。
重建按批推进，接口返回明确的完整性状态与继续游标；尚未完成时不显示“没有使用记录”。
事件重放、重复读取和恢复后不重复产生相同关联。不会为此新开后台模型任务或数据库体系。

创建时间排序使用 `(created_at, idea_id)` 确定顺序。分页期间数据变更使游标失效时，
明确返回重读要求；前端保留当前编辑与选中，并从首段刷新、按 ID 去重，不接入错误页段。

### 4.3 引用、删除与并发

新增服务内引用解析方法，在同一条目锁内校验“当前条目未删除、所选修订存在且可读”。
受理时使用它冻结原文，避免分别读取当前条目和历史版本造成竞争。

- **新受理前已删除**：拒绝引用，保留聊天草稿，提供恢复或移除引用。
- **受理后才删除或修改**：本轮使用原快照；后续请求重新校验。
- **原引用有新版本**：显示可更新提示，由作者选择更新；同一条目不叠出两个重复引用。
- **保存后继续动作**：使用保存返回的 `(workspace_id, idea_id, revision_id)`，不再从全局当前选择读取。
- **切换作品、切换条目、关闭重开**：迟到响应只归入原操作所属缓存；不改变当前焦点或发送目标。
- **元信息引起指纹变化**：保留现有冲突检查，不借补写关联覆盖已有内容。普通引用使用派生索引以减少此类写竞争。

### 4.4 展开的权限与执行

`expand_idea` 不是一句提示词约定。执行模式必须在服务端限制能力，且在最终工具装配后仍有效。

- 允许读取本轮固定的灵感、生成回答；其他显式参考须在单独提出时按既有规则受理。
- 默认不提供作品写入、删除、装卸模块、发布、索引整理等工具；动态工具也不能绕过限制。
- `read_idea` 的现有授权判断复用；灵感读取函数应从目前仅 `write` 模式的注册分支中适当提取。
- 搜索其他灵感、保存新灵感分别要求当轮明确许可；不会因“继续讨论”继承历史授权。
- “用于写作”另行提交普通写作用途、明确目标与来源，经现有任务范围及原文读取校验执行。
- 用途、参考和执行约束进入请求身份；相同请求键更换用途或灵感版本必须冲突，不能重放成旧任务。
- 既有用途与历史日志保持可读；不改变普通对话、只读检查和资料整理的权限。
