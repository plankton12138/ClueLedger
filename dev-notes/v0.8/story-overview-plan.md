## 1. 交付目标

作者进入“故事总览”后，立即知道从时间线开始；挂载模块按作品内名称增加阅读视图，
人物、线索和正文事件可相互定位。没有模块、没有模型或尚未整理，都有可理解且可使用的界面。

| 场景 | 交付行为 |
|---|---|
| 只有正文 | 默认时间线；未整理的章节列章名和更新入口，不生成假事件 |
| 挂载任意模块 | 立即出现该绑定的入口和可读原文，不要求预选类型 |
| 模块包含人物 | 更新后提供人物卡与有依据的关系图；关系列表始终可用 |
| 模块包含线索 | 更新后可查看出现、推进及解释的正文来源，计划单列 |
| 一个模块混合多种内容 | 一个模块入口内切换可用视图，不要求拆模块 |
| 没有正文、只有模块 | 可以阅读和单独整理模块，不伪造章节目标 |
| 模块卸下或版本改变 | 入口与关联及时更新，不继续展示另一版本的有效图谱 |
| 修改了正文 | 受影响的结果标为需要更新；原文入口核对版本后再定位 |

本轮不增加作者填写的类型表单、关系字段、自动同名合并、跨版本人物身份推断、
风险评分或回收百分比，也不在进入页面或装卸模块时自动调用模型。

## 2. 源码核对与必要补齐

| 当前位置 | 已有能力 | 本次处理 |
|---|---|---|
| `workspace/story_index.py` | `StoryIndexStore`、按章贡献、表达方式、证据、章节顺序与故事偏序、旧结果兼容 | 继续作为正文事件来源；分页读取适配不复制另一套事件存储 |
| `workspace/story_materials.py` | 覆盖与有效性分开、原文依据、条目详情 | 复用证据和有效性判断；固定域的旧作者视图保留兼容 |
| `workspace/api.py` 的 `/story-events` | 共用章节与故事视图，并返回计划叠加 | 新总览使用有界读取接口；作者计划从主事件序列中分离，旧接口契约保留 |
| `library/bindings.py`、`workspace/module_assembly.py` | 确定版本绑定、诊断、作品独立保存、CAS 装卸 | 总览只读当前绑定，使用 `binding.label` 优先显示名称，不追全局库最新版本 |
| `workspace/story_index.py` 的 `RecordRef` | 库、模块、修订、条目四段引用 | 保留；另加模块内部派生对象引用，一个自由正文条目可以包含多个人物 |
| `workspace/material_tasks.py` | 单域、以章节为必需目标；人物域依赖人物文件路径 | 新增总览范围类型，支持模块目标，不能给旧字段塞入虚假章节或虚假文件路径 |
| `workspace/service.py` | 一作品一活动轮次、受理冻结、幂等、停止与活动事件 | 一个更新请求对应一个受控轮次，轮次内按批次处理，不新增第二套调度器 |
| `workspace/service.py::_tool_mode` | 未登记用途默认进入写作模式 | 新用途必须显式映射到只读整理能力；权限测试先于模型接线 |
| `workspace/agent.py` | `materials` 模式只读工具与受限发布工具；既有来源读取账本 | 增加总览整理分支、目标校验和发布规则；仅可发布派生结果 |
| 前端 `StoryMaterialsPage.tsx` 等 | 固定分类、多个整理入口、来源栏、截止章 | 新增总览根页面；逐步复用时间线、来源栏与任务反馈，旧分类退到兼容入口 |
| 前端 `moduleContent.ts`、`workspaceModules.ts` | 按确定版本读取、作品编辑和模块定位 | 原文阅读与跳转复用，不另存第二份可编辑模块正文 |
| `frontend/package.json` | 已包含图形展示依赖，但没有现成人物关系组件 | 优先使用现有依赖；先实现选择、定位与列表替代，不增加图库选型任务 |
| `eval/harness/` | 在线 `.env`、生产链路取证与语义复核 | 补实际总览用途的执行入口，不能用普通聊天结果替代总览任务验收 |

## 3. 数据来源与身份

### 3.1 保持三类来源清楚

- 作者内容：正文文件和装配中固定版本的模块原文。总览不维护第二份可编辑正文。
- 模块派生结果：人物、关系、线索、内容分段及其模块依据。
- 正文观察：已有事件、表达方式与正文依据；另附与模块内部对象的关联观察。

总览、关系图和线索关联均为阅读投影。派生结果写入现有作品应用状态根下的 `overview/`，
不写入全局库，不修改作品正文或装配，也不作为写作轮次的隐式新增参考。
新派生格式独立设 `schema_version` 与 `recipe_version`，不提升作者模块或装配格式版本。

### 3.2 模块内部对象引用

`RecordRef` 只能定位到整条记录，不能把同一正文中的三个人物区分开。
新增 `FacetRef`，包含 `binding_id`、完整四段记录身份及服务端生成的 `facet_id`。
`facet_id` 从确定来源、对象种类和原文锚点区间生成。引文包含对象名称时优先取名称所在区间，以区分同一句中的多个人物；其他情况取完整主依据区间。不按名称合并对象。
新增 `entity_refs`/关联贡献承载此引用，旧 `related: RecordRef[]` 继续可读，禁止把派生 ID 冒充条目 ID。

第一版只保证确定来源版本内的对象身份。模块升级、作品内保存或生成规则改变后，
重新核对关联；旧对象不能凭同名自动换到新版本。旧对象链接提供回到所属模块与来源的入口。
跨版本连续身份和跨模块实体合并不在本轮交付。

### 3.3 证据与能力

证据包含来源种类、来源版本、指纹、区间和短引文。偏移统一为 Unicode 码点的半开区间，
模块区间针对现有读取工具返回的原始记录 Markdown，正文区间针对原始文件文本；禁止先去空白再核对。
旧 HTTP 事件依据缺少显式指纹时，从已发布章投影取得指纹，不能把当前文件指纹补到旧引文上。

每个绑定始终提供 `content`；只有当前版本、当前规则且通过证据校验的结果才提供
`characters` 或 `clues`。混合模块可以同时提供两者。旧类型仅作兼容信息，不决定能力。
空结果也保存来源指纹，避免每次打开都要求重做。关系没有依据时合法返回空列表。

### 3.4 发布与失效

| 变化 | 处理 |
|---|---|
| 正文章节内容改变 | 该章事件与关联贡献需要更新，保留最后一次结果并明确标注 |
| 正文章节删除、改名或调整顺序 | 更新目录身份与截止章；删除的来源不可跳转，旧依据不可移植到同名新文件 |
| 模块版本或作品绑定变化 | 模块能力与关联按精确版本重新核对；卸下后从当前总览排除，缓存可留供撤销 |
| 库暂时不可用 | 时间线仍可读；绑定保留诊断，已有模块结果只作不可核对的旧结果 |
| 生成规则改变 | 标记相应投影需要更新，不自动重跑模型 |
| 单个任务失败或停止 | 保留已成功且仍匹配来源的贡献，失败目标不覆盖最后一份有效结果 |

原子发布单位是一个确定的模块记录或章节贡献，结果、覆盖和来源清单一起提交。
多目标更新允许部分成功；任务终止状态和目标完成度分开，不把轮次正常结束当作全部更新成功。

## 4. 页面、导航与兼容

### 4.1 默认布局

- 顶部：作品名、“查看到”、一个“更新总览”按钮；任务进行时同处显示进度与停止。
- 内容导航：固定时间线，加当前绑定的实际名称。绑定顺序沿用装配顺序。
  模块过多时保留当前入口，其余收入“更多模块”，不让导航换成多行占满首屏。
- 主区：当前时间线或模块视图。模块内部有多种能力时才出现对应的局部切换。
- 关联区：仅围绕当前选中的事件、人物或线索显示关联与原文；无模块时不留空白人物区域。
- 更多：旧版资料、详细整理范围及现有活动记录。默认不展示覆盖计数、风险仪表和多组过滤。

时间线默认按章与原文位置；故事时间沿用现有可证明的先后、未知与冲突分组。
故事顺序先在当前截止章的完整事件关系上计算，再分页；不能分别排序每一页而漏掉跨页的关系或冲突。
截止章只裁剪正文事件和已写进展；作者设定与未来计划单列，不能宣称该章读者已知。
人物图默认显示选中人物的一层关系，并提供人物卡、关系列表和相关事件；键盘可完成相同操作。

### 4.2 路由

新增规范路由 `#/workspaces/{id}/overview`，可携带截止章、顺序、绑定、视图和选中对象。
路由存稳定标识，不放任意磁盘路径。默认进入时间线；显式链接可以直接定位当前可用的模块对象。

旧 `materials/story`、`materials/chapters`、`materials/timeline` 映射到相同截止章和顺序。
旧人物、线索、名词及其条目链接保留旧只读详情；无法唯一映射时保留原入口，不按名称猜一个模块。
旧文件不自动挂载或批量迁移。“更多 → 旧版资料”始终可找回既有内容。

同一绑定只改显示名时不重置当前对象。绑定移除、对象版本失效或当前截止章排除对象时，
明确清理相应选择并提供回到时间线/模块内容的操作；切换页面不停止更新任务。

## 5. 前后端接口对齐

下表均为**已接线**接口，前缀统一为 `/api/file-workspaces/{workspace_id}`。
读取使用同一个总览服务拼装既有权威结果，不在路由中复制事件排序或证据校验。
HTTP 字段统一沿用 `snake_case`；前端原始 DTO 保持同名，展示模型的命名转换集中在一个适配层。

| 接口 | 输入与输出要点 | 前端消费者 |
|---|---|---|
| `GET /story-overview` | 截止章、独立的 `chapter_cursor`/`binding_cursor` 与页大小；轻量清单含视图代数、装配指纹、章节目录页、绑定页、能力和增量更新摘要；不返回全量正文或全图 | 根页面与模块导航 |
| `GET /story-overview/events` | 截止章、顺序、视图代数、筛选引用、游标；返回章节/事件页及未知、冲突摘要，含原始来源身份 | 时间线与相关事件 |
| `GET /story-overview/bindings/{binding_id}` | 当前精确来源、视图、分页；返回内容目录、人物卡或线索卡 | 模块主区 |
| `GET /story-overview/bindings/{binding_id}/facets/{facet_id}` | 精确来源与视图代数；返回对象、设定依据和有界相关进展 | 对象详情 |
| `GET /story-overview/relations` | 确定对象引用、截止章、视图代数与游标；返回一层节点/边，作者设定和正文关系分区 | 人物图与关系列表 |
| `POST /story-overview/updates` | `request_key`、浏览截止章、`observed_generation`；服务端计算并冻结增量范围，返回 202 受理或 200 无需更新 | 唯一更新按钮 |
| `GET /story-overview/updates/{turn_id}` | 复用活动/轮次事件，返回冻结范围摘要、目标结果、未完成项与模型事实 | 任务条、刷新恢复 |

停止继续使用现有轮次停止入口，原文继续使用现有文件读取、模块记录读取与定位入口。
旧 `/story-events`、`/story-materials` 和 `/material-tasks` 保持兼容；总览用途不能混入旧单域任务列表导致旧解析失败。

新清单每页默认 40、最大 100 个绑定/对象；关系页最多 40 个节点、80 条边，超出明确分页，
不得静默裁剪后宣称完整。事件页上限包含一章超量事件的拆页规则；冲突组跨页用稳定分组引用定位。
这些是初始实现边界，O6 根据长篇夹具记录调整，不据演示六章判断性能。

所有分段响应带 `generation` 与 `assembly_digest`。游标绑定查询、截止章和生成代数；
前端不混合两代结果，旧游标失效后重读清单。清单的指纹包含当前来源和派生版本，
清单读取复核装配、来源版本及索引状态，实际原文读取和发布再核对原文指纹；
不可为构造导航逐条拉取所有模块全文，也不能只靠浏览器主动刷新判断失效。

## 6. “更新总览”的执行契约

1. 普通读取只检查指纹、已有投影与诊断，不调用模型。
2. 作者点击更新，前端冻结提交体与请求键；结果不明时原样重放，不因刷新清单生成新命令。
3. 服务端在既有作品忙状态保护下核对 `observed_generation`，冻结当前装配、具体模块记录指纹、
   截止章内章节指纹、生成规则与模型快照。页面已过期则在受理前返回冲突。
4. 新用途 `organize_overview` 显式映射到只读整理能力；禁止落入默认写作模式。
   一个请求对应一个活动轮次，内部按“模块解析 → 正文事件 → 对象关联”的依赖顺序分批。
5. 沿用单批最多 10 章的边界；模块记录按实际读取预算分段，明确记录覆盖区间。
   单个记录不能完整处理时标记信息不足/部分覆盖，不把摘要当全文，也不靠无限增加上下文预算完成。
   每批使用独立的受控整理上下文，只传冻结引用、必要依赖和完成摘要，不累加前几批的全文与工具历史；
   主轮次的任务身份、停止信号、模型快照和活动记录保持一致。
6. 未变化且仍有效的事件投影直接复用。模块改变只触发必要的对象解析与关联重核，
   不无条件重新生成整本书摘要；依赖失败时相关关联目标保持未完成。
7. 模型只提交本轮目标的派生结果。服务端校验实际读取区间、当前指纹、允许的引用和证据后，
   原子发布该目标；最后再计算完成度。空发现是成功覆盖，信息不足与未处理不得计作完成。
8. 停止、中断和失败都保留已完成贡献；续做由作者显式再次点击触发，重新冻结剩余范围。
   旧请求键只恢复旧轮次，不继续执行新计划。重启后不自动调用模型。

没有变化时不建空会话、不请求模型。没有模型时仍可阅读，更新按钮给出现有连接入口。
只挂模块时允许零章节目标；没有任何目标时返回合法空结果，不构造虚假章节。

建议错误码：`OVERVIEW_SOURCE_CHANGED`（受理/发布的来源改变）、`OVERVIEW_CURSOR_STALE`（游标过期）、
`OVERVIEW_REF_UNAVAILABLE`（绑定或对象不可用）、`OVERVIEW_EVIDENCE_INVALID`（依据不匹配）。
界面沿用 `[错误码] 位置：现象。建议：…`；作品正在运行时沿用既有忙状态错误。

## 7. 阶段与交付门槛

| 阶段 | 工作与主要位置 | 阶段验收 |
|---|---|---|
| O0 契约与基线 | 整理两部隔离作品、混合模块、旧资料与长篇夹具；确定 `overview_models.py`、接口和用途权限测试 | 固定当前行为；用途不进入写作模式；旧引用、纯模块范围和新引用样例都有契约用例 |
| O1 可读的总览 | `story_overview.py`、`overview_api.py`；前端总览根页与动态模块导航、时间线；复用原文读取 | 零模块默认可用；未整理显示章名；挂载即能读原文；所有打开与切换场景模型调用数为 0 |
| O2 模块派生与依据 | `module_facets.py` 及派生存储；对象引用、证据、能力、空结果和失效处理 | 一条记录可产生多个人物；混合模块有多个能力；同名不串联；坏证据不落结果；原文始终可读 |
| O3 统一增量更新 | `overview_updates.py` 与现有 `service.py`、`agent.py`、任务事件；连接新读取/发布模式 | 模块可单独更新；单作品互斥、固定范围、幂等重试、停止和部分完成正确；原文与库指纹不变 |
| O4 关联阅读 | 前端人物图/卡片、线索进展、关联事件、来源定位；后端有界详情和关系读取 | 事件↔人物/线索↔原文可走通；截止章不把未来正文带入；图和列表一致；旧版来源明确 |
| O5 兼容与布局 | 旧路由、旧资料入口、刷新与导航恢复、模块版本变化和窗口适配 | 旧链接可达；卸下不留失效活动图；无模型能读；键盘、窄窗口、大字号可完成主流程 |
| O6 评测与收口 | 确定性、真实接口浏览器、在线 `.env` 语义评测、文档和发布口径 | 下节矩阵逐项有证据；失败先分类，不自动重试覆盖；未验证范围明确列出 |

阶段顺序为 O0 → O1 → O2 → O3 → O4 → O5 → O6。O1 是第一份可独立体验的交付；
O3 后才连接新语义整理，O4 不用演示数据充当真实关系图。本轮已完成接线与验证，阶段事实集中记录于 [O6 实施记录](notes/O6-story-overview.md)，逐项区分已验证范围与未覆盖场景。

## 9. 验收矩阵

### 9.1 确定性与真实接口浏览器

| 编号 | 可判定结果 |
|---|---|
| SO01 | 零模块、零模型：显示章节/既有时间线，不出现空人物和线索导航；模型请求 0 次 |
| SO02 | 纯模块、零章节：原文立即可读；明确更新后不需要虚假章节，合法空结果可保存 |
| SO03 | 一个自由条目包含 3 人物与 2 线索：身份互不混淆，局部视图正确，不要求新增作者字段 |
| SO04 | 两个模块有同名人物、两个作品绑定同一模块：不按名字或共享缓存串联 |
| SO05 | 装卸、撤销、作品内保存、库另存与库离线：严格使用当前绑定版本，原库与其他作品不变 |
| SO06 | 未来计划、证词、梦、回忆、时间未知和环：来源明确，计划不混入已发生序列，未知不强排 |
| SO07 | 截止第 4 章时，第 5 章正文关系和线索解释不进入已写进展；作者设定仍明确标来源 |
| SO08 | 改章、删章、改模块：空结果同样失效；旧引文不得贴上新指纹；过期内容不成为有效图边 |
| SO09 | 响应丢失后原键重试：仅一个任务；修改提交体重用同键被拒绝；无需更新时模型调用 0 次 |
| SO10 | 更新中切作品、切截止章或切视图：结果留在原作品/范围；迟到响应不覆盖新选择 |
| SO11 | 停止、部分失败、进程中断和刷新：已完成贡献可读，剩余项真实，重启不自动执行 |

| SO13 | 混合与通用模块、没有明确关系：原文/卡片可用，图显示合法空关系，无伪造边 |
| SO14 | 旧路由和旧资料可达，不能唯一定位时保留原详情，不按标题猜新对象 |
| SO15 | 大量模块、千章级目录、单章多事件、跨页时间冲突和分页中数据变化：有界返回，旧游标被识别，不漏页或重复 |
| SO16 | 1440/1024/760/640px × 100%/150% 字号，390px 观察：时间线、来源、停止、选择与返回可达；无横向溢出 |
| SO17 | 鼠标与键盘的关系图选择结果一致；人物卡和关系列表完整呈现图中信息 |
| SO18 | 从事件开人物、从人物开事件、从线索开原文后返回：模块、截止章、滚动位置和有效选择按约定恢复 |

### 9.2 在线语义评测

使用项目现有 `.env` 在线模型与 `eval/` 执行器，禁止本地模型。拟增加
`eval/cases/story_overview.yaml` 和 `eval/suites/story-overview.json`；执行器先补总览用途步骤，
直接调用生产更新服务，不能把“请整理人物”的普通写作对话当成新用途验收。

至少覆盖：自由混合模块识别、零关系、同名歧义、未来设定与正文区分、证词和推测、否定与假设关系、
纯模块整理、改动后的增量更新、遗漏依据时拒绝发布。判断来源准确率、遗漏与误连，
特别记录无依据关系；结构合法和字段齐全不能代替语义正确。

记录代码状态、输入指纹、模型事实、请求与提示规则版本、耗时、字符/调用规模、未完成项和人工复核。
评测目标、期望及答案不得进入模型上下文。失败分接口/网络、产品接线、来源校验与模型理解，
不以自动重跑掩盖首次失败；历史评测结果不替代本轮结论。

## 10. 本轮实施调整

- 每批一个确定目标，低于原单批 10 章上限；一个父轮次按模块、章节、关联顺序串行处理。
- 实际工具进一步收窄为 `read_overview_source` 和 `publish_overview_result`，模型不能自行指定其他路径或模块。每目标独立上下文、最多 16 个模型回合、累计提供最多 24,000 码点。
- 关联上下文超过 24,000 字符时保持未完成，不把截断数据算成全部核对；再次更新仍须作者明确发起。
- 派生 `schema_version=1`、`recipe_version=2`；规则变化使旧能力失效，不改变模块格式。
- 信息不足另存尝试记录，保留最后成功投影；无需更新的请求也保存幂等回执，不建立空会话。
- 旧 `materials/story`、`chapters`、`timeline` 映射到总览；明确的 `materials/legacy-story` 提供旧章节页，保证“旧版资料”各分类仍能互相访问。
- 章节目录独立分页且不受浏览截止章裁剪，避免选择第 1 章后无法再选择第 2 章。关系每页最多 39 条边及 40 节点，继续读取有明确入口。

本轮未执行桌面打包、真实长篇全量在线整理或跨模型稳定性对照；这些结果不能由本地矩阵和小型在线案例推断。
