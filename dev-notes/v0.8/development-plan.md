# 0.8 详细实施计划

日期：2026-10-24。状态：**实施中**（A–E 已落地，F、G 待实施）。运行包版本仍为 `0.7.0`，
完成 G 阶段验收后统一升级。
产品范围见[产品方案](../../product-design/v0.8/README.md)，实施契约见[数据](data-and-storage.md)、
[上下文](context-and-index.md)、[接口](api-and-frontend.md)与[验收](acceptance.md)。

## 1. 成功标准与范围

0.8 完成“无模型保存灵感 → 可恢复修改 → 按需带到对话 → 有范围地落实 → 查看来源和改动”，
并建立全局模块库：同类型多实例、不可变版本、作品按版本装卸。同一人物／故事线可以用于两个世界的不同作品。
正文事件仍按作品隔离；章节视图、故事时间视图和 agent 共用事件记录。详见[全局模块库与装配](library-and-assembly.md)。
索引不要求作者维护；默认不读取未选灵感，不自动运行资料整理，不增加强制候选采用。

| 范围 | 0.8 必须交付 | 不应被误解为 |
|---|---|---|
| 灵感 | 记录、收藏、编辑、删除恢复、修订恢复、关联、显式读取 | 自动理解所有灵感、自动改稿 |
| 模块 | 七种预设类型、同类型多实例、全局抽屉、装卸、变体与固定版本 | 任意类型与字段设计器；没有隐藏操作 |
| 组合与便携 | 同组合创建空正文作品、替换模块 | 自动跨世界改编正文或共享正文状态 |
| 作者资料 | 库版本内 Markdown＋受控字段、稳定完整引用、计划与作品观察分离 | 各作品各存一套可变模块副本 |
| 统一索引 | 章节摘要和事件一批发布、多来源、双视图 | 对任意自然语言时间精确排序 |
| 上下文 | L0/L1/L2、相关条目选择、预算与实际读取记录 | 已实现通用长期记忆与自动语义压缩 |
| 连贯性 | 范围检查、证据、显式检查、语义验收 | 自动证明作品结构完整或不存在矛盾 |

项目包版本、0.7 实现和当前模块说明核对。这里不把历史验证结果当本次验证。

| 现有位置 | 已有能力／缺口 | 处理 |
|---|---|---|
| `workspace/files.py` | 仅章文件、小传、固定线索和真相路径；文件指纹 | 新作品不再强制两份设定；本地网关不越根写库；旧源只读适配 |

| `workspace/material_tasks.py` | 单域任务、全文读取与发布检查 | 增加 story_index，修正计划时点限制，按来源替换贡献 |
| `workspace/story_materials.py` | 固定六域作者视图 | 模块目录、记录详情、双时间视图适配 |

| `eval/` | 现有生产链路评测、消融与人工语义复核 | 扩展 v0.8 场景，复用取证，不另造评分器 |

本次临时样例验证：两份固定设定各 3500 字符时，截取后加标题和提示为 6112 字符，
超过 6000 预算导致 settings 分区被跳过；短设定正常注入。
截至第 8 章提交计划第 22 章回收，在 `_clue_entry` 被拒绝。以上是局部函数验证，
不是在线模型或浏览器端到端结论。开发 A 阶段须转为可重复的回归测试。

## 3. 新增职责与复用边界

拟新增文件按职责拆分，实际落地可小幅合并，但不得复制现有文件网关、读取账本或范围检查。

| 模块 | 拟定后端位置 | 主要依赖 | 关键示例／契约 |
|---|---|---|---|
| 全局库与版本 | `library/modules.py`、`library/storage.py` | 应用级库定位、模块锁、原子发布、幂等 | [库与版本](library-and-assembly.md) |
| 作品装配 | `workspace/module_assembly.py` | CAS、精确版本解析、作品 Git | [绑定结构](library-and-assembly.md#3-绑定数据) |
| 预设类型 | `library/presets.py` | 七种类型、多个实例 | [ModuleSpec](data-and-storage.md#3-预设模块与条目) |
| 作者条目与目录 | `library/records.py` | 不可变模块源、完整版本引用 | [条目结构](data-and-storage.md#3-预设模块与条目) |
| 灵感修订 | `workspace/ideas.py` | 条目锁、原子文件、请求幂等 | [修订与恢复](data-and-storage.md#4-灵感的原子修订与恢复) |
| 统一章节事件 | `workspace/story_index.py` | chapter_index、证据校验、material_tasks | [事件数据](data-and-storage.md#5-共用章节索引和事件记录) |
| 有界检索 | `workspace/retrieval.py` | records、story_index、各观察域 | [查询示例](context-and-index.md#3-检索输入与来源标签) |
| 灵感和库接口 | `workspace/ideas_api.py`、`library/api.py` | 作品／库分别授权，共用发布服务 | [HTTP 契约](api-and-frontend.md) |
| 上下文适配 | 现有 context、assembly、materials、agent | 上述查询、已有读取凭据 | [装配示例](context-and-index.md#6-装配预算与排序) |

作者记录与派生记录分离，UI 与 agent 共用记录服务；不同入口只负责不同授权来源。
模型生成共享设定经库服务发布新版本，不能用作品文件工具跨根写库；正文仍用既有文件工具。
基础目录按精确模块版本复用，不额外启动语义索引任务。
代码示例是契约级示意，不要求直接复制，落地必须补上项目现有错误与并发处理。

## 4. 阶段依赖

```mermaid
flowchart LR
    A[A 基础修正] --> B[B 全局库和版本基础]
    B --> C[C 灵感本完整流程]
    B --> D[D 装配与模块抽屉]
    D --> E[E 统一事件与时间线]
    C --> F[F 渐进读取与任务装配]
    E --> F
    F --> G[G 回归、在线验收与交付]
```

每个阶段交付服务、前端和必要验证，不能只留后端接口然后宣称功能完成。
没有接线的能力不进可操作导航；未实现的预设不显示假按钮。

## 12. 风险、取舍与执行记录

| 风险 | 采取的边界 |
|---|---|
| 模块越来越多 | 固定七种类型，实例分页，普通任务仅查询已装版本，未交付预设不开放 |
| 共享修改影响其他作品 | 不可变修订、显式升级绑定，库 head 不作为运行时引用 |
| 模块被卸下仍被使用 | 目录／检索／详情／依赖同一范围，历史明确旧版本不再为当前约束 |
| 作品复制丢失全局依赖 | 仅复制目录时明确报告缺失依赖；不提供作品包导出导入 |
| 灵感被自动当设定 | 单独存储与工具边界、逐轮选中／搜索许可、对照输入快照 |
| 作者计划被重新整理覆盖 | 物理分开作者源与派生存储，发布工具只写观察 |
| 事件去重导致误合并 | 稳定作者 ID、多来源观察、歧义保留，不按同名强并 |
| 格式升级损坏作品 | 旧源只读适配、显式编辑时升级、备份和幂等、禁止启动时自动模型任务 |
| 上下文压缩失去关键约束 | 必需材料优先、任务卡、版本定位与重读；暂不新增自动语义压缩 |
| 文档先于代码夸大能力 | 每阶段分别记录接口、前端、确定性、在线与未覆盖范围 |

每个阶段记录包含：实际改动、接口影响、验证命令和结果、偏差、未完成项及证据链接。
不把本方案中的示例数据写成真实测试结果，不以页面存在代替端到端完成。
