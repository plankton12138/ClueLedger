## 1. 目标、范围与取舍

### 1.1 作者能够直接理解的四件事

1. 当前在哪个作品和页面，正在阅读或修改什么。
2. 当前区域的主要操作是什么，其他操作在哪里。
3. 操作影响灵感、全局模块、当前作品装配还是正文。
4. 内容是否保存、任务是否完成，失败后怎样继续。

视觉方向为浅色、低饱和、适合长时间阅读：保留暖白正文纸面，减弱金属高光、织物纹理与重复投影。
控件质感继续沿用已经确认的老 iOS 语言；布局组织和空间节奏参考 `prototypes/dark`，采用职责清楚的模块分区、
较大的基础字号、充分利用视口和按内容分配空间，不采用原型的深色外观、演示数据或演示功能。
导航、操作和反馈依靠布局、文字、边框及少量语义色区分。普通流程不增加重复副标题、说明段或内部编号。

### 1.2 本轮必须完成

- 修复文字对比、选中与悬停状态、窄窗口正文消失、键盘焦点和弹窗行为。
- 统一按钮、表单、列表项、页签、状态与空结果的规则。
- 按 dark 原型的布局原则重排写作、灵感、故事资料与模块库：模块按职责成组，主要内容占据可用空间，
  不靠缩小字号容纳多栏，也不为填满页面增加无业务作用的统计卡或空卡片。
- 修复模块编辑的草稿、异步读取、完整原文读取、发布与应用恢复。
- 按实际职责拆分大组件，保持前端接口与服务端能力对齐。
- 建立可重复的行为验收与视觉走查，更新当前说明和未验证范围。

### 1.3 继续沿用的业务边界

- 正文仍为只读阅读器；修改走现有对话或外部编辑，不新增正文编辑路径。
- 写作、灵感、故事资料为三个主入口；不增加独立检查报告页或空导航占位。
- 灵感只有显式选中或获得本轮检索许可才参与模型输入；带到对话不自动发送。
- 作者计划与正文观察继续分开，浏览截止章与整理任务范围继续分开。
- 模块版本不可变，作品固定精确版本；保存到库不自动改变其他作品。
- 整理、检查和写作的服务端权限、单任务约束、请求幂等与版本检查继续生效。
- 保留导入正文、导入旧资料、派生新作品、模块排序、恢复、活动记录与文件版本能力。
- 作品包导入导出继续取消；不因重排导航恢复入口、接口或隐藏按钮。
- 本轮不迁移作品数据、不改接口前缀、不新增后台模型任务、不升级到 0.9。

### 1.4 版本与桌面壳

`pyproject.toml`、`frontend/package.json` 及其现有锁文件中的主应用声明保持 `0.8.0`。
不为前端修复递增补丁号，不修改作品存储版本。独立桌面壳的 `desktop/package.json` 当前仍为
`0.7.0`，属于既有差异；本轮不据此宣称全仓版本一致。若实际执行桌面重新打包，在交付任务中
单列对齐到 `0.8.0` 与对外名称检查，不能以修改计划为由提前改包或声称已验证桌面产物。

## 3. 确定的界面规则

### 3.1 应用结构

| 区域 | 安排 | 操作边界 |
|---|---|---|
| 顶栏左侧 | 作品切换与作品菜单 | 打开、新建、重新读取、失效登记清理放入菜单 |
| 顶栏中部 | 写作、灵感、故事资料 | 主导航固定；使用链接与当前页面标记 |
| 顶栏右侧 | 模块库、设置 | 设置收纳模型连接和显示偏好；没有作品仍可管理应用级内容 |
| 写作页工具区 | 目录开关、对话开关、阅读显示、活动记录 | 只显示当前页面有效的控件；文件版本在活动记录内保持直接可达 |
| 模块库 | 应用级完整管理视图 | 浏览与编辑分开；以作品上下文横幅说明当前装入对象；返回保留原页面位置 |
| 作品内模块入口 | 跳转到模块库并携带当前作品上下文 | 只查找、预览、选版本、装入；完整编辑在模块库内完成，不复制第二套选择面板 |

设置菜单中的“模型连接”继续使用现有应用级能力，不因导航重排要求先打开作品。
模块库没有作品时允许浏览、发布、变体、删除与恢复；装入、卸下、派生等作品操作需要已登记作品。
不建立第四个作品主页面，也不新增第二套模块选择面板：作品内入口只负责带着当前作品上下文打开同一个模块库页面。

应用级页面采用模块化布局：顶栏只承载作品、主导航和应用工具；每页由一个有明确职责的主模块与按需出现的辅助模块组成。
模块之间用稳定间距和细边界分组，列表、正文、证据与操作在各自模块内组织；宽屏利用剩余空间增加内容与留白，
不拉长正文行宽，也不增加装饰性卡片。窄窗口按任务优先级收起辅助模块，而不是把全部模块同比压缩。

对应到当前产品：写作页以正文为主模块，目录与对话按空间出现；灵感以列表和编辑正文为主，历史按需展开；
故事资料以资料列表和正文依据为主，筛选与整理工具独立成组；模块库以浏览列表和模块详情为主，版本与应用操作
随选中对象出现；活动记录以事件流为主，概览在宽屏作为辅助模块。这里借鉴的是空间关系，不复制原型的页面数量或演示模块。

### 3.2 视觉与控件

| 项目 | 规则 | 验收重点 |
|---|---|---|
| 版面 | 参考 dark 原型的模块化分区：主任务模块优先，辅助模块按需出现；模块内部成组，不把说明、操作和结果堆成一条 | 宽屏充分利用视口，内容充实但不拥挤；不出现无业务作用的统计卡或空卡片 |
| 色彩 | 页面、表面、正文纸面、文字、边框、选中、焦点、状态均使用语义变量；材质与控件质感沿用浅色老 iOS 方向 | 选中与悬停必须成对定义文字和背景；不把 dark 原型的深色配色带入成品 |
| 操作 | `primary`、`secondary`、`quiet`、`danger` 四类；导航与页签独立 | 同一区域通常只有一个突出主操作；颜色不承担唯一含义 |
| 字号 | 界面正文基准 14px，正文阅读约 16–18px，辅助信息通常不低于 12px | 延续已有 80%–150% 显示偏好，放大时容器允许增高；不用缩小字号换空间 |
| 尺寸 | 普通控件最小高度 36px；紧凑工具 32px；如确认触控目标，再单独要求至少 40px | 桌面指针操作为本轮基线，避免固定高度裁字；390px 与触控能力不作为默认阻断门槛 |
| 列表 | 选中、悬停、焦点、禁用各有明确样式 | 标题与摘要继承当前行色调，禁止固定灰字覆盖选中态 |
| 表单 | 可见标签、同一字段间距、就近错误；占位符不替代标签 | 键盘焦点与错误文本都能被识别 |
| 状态 | 加载、空结果、失败、过期、部分完成分别表达 | 加载未结束时不显示“没有内容”；无发现属于合法结果 |
| 图标 | 仅用于稳定含义，主操作保留文字 | 图标按钮有名称，不能只依靠悬停提示完成操作 |
| 细节信息 | 修订标识、内部工具名、结构化原文放详情或高级区 | 普通操作优先显示作者可理解的名称与时间 |

普通文字与其背景的对比目标至少 4.5:1；大字至少 3:1；识别控件所必需的边界、状态与焦点目标至少 3:1。
依据 [W3C 文字对比说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)与
[非文字对比说明](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)；大字采用标准定义，
16–18px 阅读文字仍按普通文字检查。这是本轮验收目标，不把当前主题测试中的“颜色不同”当作对比验证。
有意义的状态还需要文字或形状标记。必要渐变逐段检查最弱区域，不依靠文字阴影补足对比。

### 3.3 按可用空间适配

布局模式由实际容器宽度与字体比例决定，宽度只作为起始参考。旧拖拽宽度仍可读取，实际显示时
钳制到当前空间；自动适配不反写用户的桌面偏好。这里的空间分配参考 dark 原型：主任务模块优先，
辅助模块随可用空间出现或收起，模块可滚动但不用缩小字号硬塞进固定宽度。

| 模式 | 典型范围 | 写作页 | 灵感、资料与模块库 |
|---|---|---|---|
| 宽屏 | 约 1280px 及以上且预算足够 | 目录＋正文＋对话；正文至少约 560px | 列表／正文／证据按内容空间展开 |
| 紧凑桌面 | 约 900–1279px | 默认正文＋对话；目录按需抽屉，正文至少约 420px | 列表＋详情；证据可作为侧面板 |
| 窄窗口 | 空间不足以容纳上述组合 | 正文／对话切换，目录抽屉；任一时刻核心区域占满可用宽度 | 列表与详情原位切换，返回保留筛选、滚动和选中项 |

`640px` 是桌面窄窗口的阻断验收边界。`390px` 只做观察记录，除非另行确认移动端产品目标，
否则不把完整操作、触控尺寸或移动布局作为本轮发布门槛。

不以 `overflow-x-hidden` 隐藏布局失败。正文、代码、差异和表格中的局部横向滚动可以保留；
页面整体不能裁掉发送、保存、停止、返回等关键操作。任务开始后不强行把正在阅读的正文切走；
窄窗口提供带状态的对话入口，任务和草稿不依赖面板是否挂载。

## 5. 前后端接口对齐清单

本轮以复用服务能力为默认；前端路由与服务接口分别管理。新增接口只有在既有契约无法满足
明确的作者行为时才立项，同时给出后端实现、客户端类型、错误与端到端验收。

| 作者行为 | 当前可复用能力 | 必须补齐或核对 |
|---|---|---|
| 应用级库管理 | `/api/module-library/*` | 去掉全局读写对 `workspaceId` 的前端依赖，保留库身份校验 |
| 长记录编辑 | 记录 GET 已支持 `start/end`，返回 digest／length／truncated／next_cursor | 客户端传分页参数、完整读取、连续性与码点长度检查；接口无需扩展 |
| 表单字段 | presets 返回 kind／label／source_kinds／organize_domain | 在既有 presets 响应中补充 allowed_fields，补服务端响应与客户端类型测试；标量列表沿用现有服务支持，未知字段、嵌套对象及含非标量的列表按现有校验拒绝，不另造前端字段表 |
| 发布模块 | revisions POST，base_revision／expected_head／request_key | 原文完整且未修改禁用；冲突保留草稿；不自动覆盖 head |
| 发布并应用 | module-updates POST，published／binding_updated／module／error | 两阶段反馈；结果不确定复用请求键；已发布后的重试只更新装配 |
| 装卸／排序／升级 | assembly GET／PUT，bindings／links／expected_digest | 保留绑定 ID、标签、links；目标冲突不覆盖；运行中忙冲突照常展示 |
| 灵感编辑与历史 | ideas、revisions、精确修订 GET、restore | 列表与历史分页、预览、完整错误；带到对话固定保存版本 |
| 对话参考 | ContextInput 支持 reference_paths、idea_references；模块读取使用既有工具 | 文件与灵感仍分别传递；没有 record 输入字段，不增加未接通的模块条目草稿选择 |
| 整理与核对 | story-materials、story-events、material-tasks | 浏览时点、任务范围、覆盖与失效不混合；不加隐藏模型调用 |
| 写作与活动 | 既有草稿、会话、SSE、activity、reviews、Git | 提交差异响应补充受管文件 paths；两个撤销入口共用确认，不创建第二条任务或绕过原动作 |
| 正文／旧资料导入与派生 | 既有上传、library-imports、derive | 区分名称和入口；作品包仍无对应入口 |

每完成一个页面，按原功能清单检查能力保留，再移除旧控件；不长期维护两套界面或两套权威状态。

### 7.1 验证方法与命令

1. 对请求乱序、草稿归属、完整读取、幂等命令、部分成功恢复、允许字段往返与路由写有意义的状态／接口测试。
2. 对真实导航、焦点、输入法、窗口空间、保留输入和关键操作可达写浏览器行为断言。
3. 截图覆盖写作、灵感、资料、模块预览／编辑、设置与活动的关键状态；人工记录布局、字号、模块边界与可读性结论。
4. 不给每个样式类或低影响外观改动写镜像单元测试，不把存了截图等同于视觉通过。

在 `frontend/` 执行：

```powershell
npm test -- --no-file-parallelism
npm run build
npx playwright test --project=workspace --output=../data/test-tmp/frontend-experience-results
```

新增 `frontend-experience.spec.ts` 必须加入 workspace 项目的 `testMatch`；快速定位可执行
`npx playwright test --project=workspace frontend-experience.spec.ts --output=../data/test-tmp/frontend-experience-results`。
状态测试串行运行并核对文件与用例总数。
只有前端和文档变化时不扩散到全量后端评测；如果实际修改服务端预设、发布或装配，则运行对应服务测试。

涉及模型执行的UI13–UI15另用 `.env` 在线端点做相关冒烟，不使用本地模型；机制夹具和在线结果分别记录。
没有改动任务、参考或SSE契约时，不因换样式重跑全部语义矩阵。需要重跑的场景写明实际模型和文件证据，
没有运行的项保持“未执行”，不得借用旧在线结果作本次通过结论。
示例：[E9](frontend-experience-examples.md#e9)。
