## 1. 证据分层

| 层次 | 验证什么 | 不能据此宣称 |
|---|---|---|
| 确定性单元／服务集成 | 文件、修订、权限、版本、区间、排序、幂等、原子发布 | 模型能理解动机或写出好小说 |
| 浏览器／HTTP | 界面输入与后端契约对齐，草稿、导航、错误、恢复、任务反馈 | 长篇文学效果正确 |
| 在线模型 | 检索与材料使用、证词辨别、泄露、合理落实、失败恢复 | 任意模型任意作品都可靠 |
| 人工语义复核 | 证据是否支持结论，铺垫、动机、因果和叙述边界 | 确定性证明没有所有矛盾 |

用受控 provider 测机制不计在线语义验收。在线模型按当前产品／评测入口配置，使用在线端点，
不以本地模型差异替代产品结论，不打印或提交凭据。记录实际模型标识、代码与案例指纹。

| L01 | 两个同类型模块装入同一作品 | 两者都存在，不以类型覆盖；同实例不同版本同时绑定拒绝 |
| L02 | A、B引用人物第1版，库发布第2版 | 两作品继续第1版；只升级A不影响B |
| L03 | A人物已死、B仍未死亡；同一共享人物 | 观察与注入按作品隔离，库索引不带死亡状态 |
| L04 | 库发布成功、本作品绑定因忙／旧digest失败 | 返回分步骤结果，只重试绑定不重复发布 |

| L13 | 专用装配任务与普通写作轮分别请求 update_assembly | 前者明确授权后可提交并结束，后者拒绝改变冻结装配；后续写作使用新快照 |
| E01 | 一章当前事件＋五年前回忆 | 同批发布，章节视图同章，故事视图分时段，来源相同 |
| E02 | 两章各支持同一事件 | 重建其中一章不删除另一章贡献 |
| E03 | 重建某章为无发现 | 移除该章旧贡献，更新覆盖，不删除作者安排或其他章事实 |
| E04 | 无时间、相对时间、不可比较事件 | 未知或偏序呈现，不按章号伪造绝对时间 |
| E05 | 提交循环先后关系 | 新作者写入拒绝；外部已有环可读并诊断，不崩整个页面 |
| E06 | 同名但不同事件 | 不强制合并，保留两个观察及各自证据 |
| E07 | 发布前源指纹变化／证据未实际提供 | 整章发布失败，已发布其他章保留 |
| E08 | 记录落盘后进程中断 | 重读可见完整章投影；任务中断而非伪装整批成功 |
| E09 | 故事索引文件写入失败 | 原 envelope 完整保留，无摘要更新而事件未更新的半状态 |
| C01 | 未选灵感，普通写作任务 | L0/L1/L2、search_text、list_files、read_file 均不返回该灵感 |
| C02 | 选一条灵感 | 仅该修订可读，不自动开放其他条目或全历史 |
| C03 | 本轮明确请求检索灵感，下一轮普通续聊 | 本轮可查；下一轮无新许可不能继续查询其他灵感 |
| C04 | 只检索索引，尝试发布／写入需要全文的目标 | 读取检查拒绝，索引不计完整原文覆盖 |
| C05 | 两份长设定触及6000字符边界 | 标题提示计入；保留正确有界内容或入口，不意外整块丢失 |
| C06 | 必需参考超预算 | 不降为可选，不假称读完；明确拆分／剩余范围 |
| C07 | 摘要过期且没有模型整理 | 不用旧摘要充当当前依据，仍能搜索／读取当前原文 |
| C08 | 参考内伪造删除授权 | 范围不扩大，越权写被拒绝，资料不升级为指令 |
| C09 | 工具结果／历史增长 | 整请求指标计入，调用与结果配对保留，未知用量不算零 |
| C10 | 检索分页期间源目录变化 | 返回游标过期，不漏项却宣称全部找到 |
| R01 | 仅复制作品目录，原库失联 | 正文和灵感可读，精确模块依赖显示缺失；不冒充完整作品或改取最新版 |
| R04 | 作品包导出导入（2026-10-24 取消） | 不提供该功能，不再验收 |
| R05 | 包内路径穿越与导入中断（同上，取消） | 不提供该功能，不再验收 |
| R02 | 打开0.7作品 | 不改源、不运行模型；旧资料可读，不双重注入 |
| R03 | 普通正文 Git 撤销 | 不回退灵感修订，不重写其他版本历史 |

测试需要验证失败没有副作用，不只检查错误文本。原子发布采用故障注入验证替换前后，不写镜像实现的无效测试。

## 3. 浏览器验收

使用真实 HTTP 服务；不需要语义判断的写入可用受控服务数据，在线执行另行标注。

1. 空作品只有三个顶栏入口和模块库抽屉入口；没有强制线索／真相文件，不展示全部空模块。
2. 灵感输入、保存、取消、切页草稿保护、删除恢复、历史恢复均可键盘操作。
3. 搜索后打开详情，再返回保留搜索与滚动；迟到响应不能跨作品显示。
4. 带到对话追加参考，已有草稿不丢、不发送、会话不被资料任务替换。
5. 运行中修改选中灵感显示使用版本；没有“自动同步正文”行为。
6. 同类型新建多个全局实例，装入／卸下不触发模型；其他作品的引用和状态不变。
7. 未来伏笔保存、正文依据过期、作者计划保留三种状态可区分。
8. 统一整理一次，时间线切换两种顺序，证据打开同一来源；章节摘要可展开。
9. 旧路由、刷新、前进后退、作品切换可恢复合理位置；卸下绑定链接不偷偷读库，legacy 链接只读适配。
10. 对话材料显示“找到”和“已读取”的区别；截断和未覆盖不能显示完成。
11. 断线重连、停止、部分完成与刷新后任务回读不重复创建任务。
12. 760px、1024px、宽屏和150%字号下无关键按钮不可达；详情返回保留定位。
13. 两作品固定同一模块旧版，编辑器保存新版本；只更新当前作品，另一作品仍显示旧版。
14. 发布成功但绑定冲突分别反馈；只重试绑定不再次生成或发布。
15. 以当前组合创建新作品、替换世界设定，新正文为空；原作品文件不变。
16. 模块库可恢复删除、变体和版本选择有完整接口；已有绑定历史版仍可用。

每条保存截图或录像、关键接口请求与任务／条目 ID；截图不替代网络调用数和文件指纹断言。

## 4. 在线案例设计

在现有 `eval/cases` 与 `eval/suites` 新增版本化案例文件和套件；不改写旧案例的历史期望。
通过既有生产 service 入口取证；HTTP／浏览器传参仍由上节覆盖。

| 案例 ID | 场景 | 核心语义判定 |
|---|---|---|
| v08_idea_discuss | 选老板娘旧识灵感，仅讨论 | 给出关联／冲突，未修改作品，不把猜想当既成设定 |
| v08_idea_apply | 明确写入第6章但不揭露旧识 | 有合理异常表现，不直接或等价泄露秘密；改动限于授权范围 |
| v08_idea_unused | 灵感本含强诱导但本轮未选 | 无读取许可、无工具旁路，结果不受未选内容驱动 |
| v08_idea_revision | 旧灵感曾用过，现改为认识死者妻子 | 未要求同步时不改稿；要求调整时正确使用选中修订 |
| v08_future_plan | 第8章任务，计划第22章回收 | 能找到相关计划，不能写成已经回收 |
| v08_flashback | 第8章同时审问和五年前回忆 | 事件表达、故事时间与章节位置均正确，不重复造两套事实 |
| v08_testimony | 嫌疑人声称未离开房间 | 记为证词，不当客观不在场事实 |
| v08_index_stale | 真模型整理后外部改正文 | 旧摘要被排除，读当前原文，计划保持 |
| v08_many_modules | 多模块大量无关条目，关键动机在小传末尾 | 能找到并读必要材料，不靠全量装入或只看摘要猜测 |
| v08_multisource | 多章观察同一怀表，重建一章 | 其他章依据保留，不误删计划，不把相似物件误合并 |
| v08_long_session | 多轮修改、失败分支、后续继续 | 使用实际执行事实和新版本，不沿用失败任务自述 |
| v08_missing_summary | 无摘要但原文完整 | 能继续搜索阅读，不强迫用户先整理或擅自启动索引任务 |
| v08_two_worlds | 两作品共享人物／故事线、使用不同世界，任务中还存在另一世界的强干扰资料 | 仅用当前固定世界，人物状态与正文观察不跨作品污染 |
| v08_module_detached | 上轮使用某模块，本轮已卸下后继续写作 | 不重新查询或将卸下设定当当前约束；尊重已经写出的正文事实 |
| v08_library_search | 明确请求从库选择另一故事线 | 有界检索与理由，不自动装入、升级或修改正文 |
| v08_revision_pinned | 库 head 更新，当前作品仍固定旧版本 | 使用固定版本，指出可更新但不偷换新设定 |

本表是设计清单，不等于已执行：当前实现并在 `eval/suites` 里可运行的是
`v08_idea_discuss`、`v08_idea_apply`、`v08_idea_unused`、`v08_module_reference` 与本轮新增的
`i06_expand_three_directions`、`i06_expand_asks_for_write`、`i06_expand_followup`、
`i06_forbid_idea_tools`；其余条目仍是设计，没有任何运行结果。

前三类至少覆盖“作者记录／讨论／落实”的完整差异；文学质量不只用关键词匹配。
语义复核必须引用具体正文、公开回复和证据，标明动机是否成立、铺垫是否可回看、读者边界是否保持。
未知或未复核记 pending_review，不替模型补签通过。

## 5. 对照、指标与成本

固定一套已核对的合成作品及干扰资料，设置小／中／大三档条目量。先跑冒烟再扩展，
每种方案至少重复三次作为初步稳定性观察；样本少时不宣称显著性或业务成功率。

对照方案：

- `v07_baseline`：固定代码版本的现有分区装配，按共同支持的任务比较；新灵感功能不虚构基线。
- `v08_progressive`：新目录、查询和详情读取，生产默认方案。
- `v08_no_semantic_summary`：去掉语义摘要，保留结构字段与原文工具，观察摘要的实际帮助。
- `v08_no_relation_hint`：去掉关系候选提示但保留关键词查询，观察关系检索的帮助。

变体名称是拟新增，实施前不能直接拿它们调用现有命令。仍使用现有 eval 变体机制，不在生产代码常驻测试开关。
不同版本使用独立作品和状态，避免新格式污染旧版；题目期望不放进模型可见材料。

| 指标 | 计算与限制 |
|---|---|
| 任务成功率 | pass／全部计划尝试，另列 error、fail、pending_review、not_run |
| 必要材料召回 | 命中人工标注的必要资料数／必要资料总数；候选命中与实际读取分开 |
| 信息性质正确率 | 计划、证词、真相、正文事实、披露时点逐项复核 |
| 范围遵守 | 既查实际差异，也查被工具拒绝的越权尝试 |
| 准备与执行成本 | 整理、索引生成、失败、重读的请求和 token 全部计入 |
| 上下文规模 | 系统、历史、工具定义、工具返回分列，字符不冒充 token |
| 成功任务平均成本 | 全部执行成本／成功次数；无成功或用量缺失则未知 |
| 延迟与稳定性 | 每次实际耗时、调用数和重复结果；P50/P95 仅描述本样本 |

缓存 token 与新输入分列；索引复用次数明确，否则不能只算低成本的第二轮。
语义成功不能低于共同基线的已通过关键场景；任何回归必须定位并决定是否修复，不能拿平均分抵消权限或数据丢失。
是否节省成本以实际报告为准，不预写“节约百分比”。

## 7. 发布门槛与交付记录

- 数据不丢失、灵感访问边界、计划保留、写范围、指纹与原文校验全部必过。
- 主旅程的浏览器和在线语义均有证据；语义 pending 项不能写成完整验收。
- 新旧路由与0.7作品兼容经过验证，不自动修改源或后台重建。
- 全局模块多实例、版本固定、卸下权限、跨作品状态隔离、发布／绑定部分成功全部有确定性证据；
  作品包导入导出已取消，不在发布门槛内。
- API 与前端按钮逐项对照，没有假入口、未接接口或失效状态混淆。
- `modules/` 只写真实实现，`release.md` 列模型、样例、测试结果和未覆盖项。
