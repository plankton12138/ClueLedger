# Hastings 前端

当前默认入口为 **0.4 工作区**：作品是一个 Markdown 目录，界面只读文件、发起对话、查看 Git 改动与历史。产品目标见[产品设计](../product-design/README.md)，界面契约见[写作台界面](../dev-notes/v0.4/modules/desk.md)。

0.3 的写作台组件与状态仍在源码中（`components/desk/`、`state/v2*.ts`），默认页面已不引用，待 V04-5 清理；其说明在[0.3 模块文档](../dev-notes/v0.3/modules/desk-surface.md)。

## 运行

仓库根目录启动后端（默认打开最近使用的作品目录）：

```powershell
uv run python -m hastings.server
```

在本目录运行：

```powershell
npm install
npm run dev
npm run build
```

开发服务器将 `/api` 转发到本地 8000 端口。生产文件位于 `frontend/dist`，由后端托管。

## 当前可用流程

- **打开与新建**：顶栏「打开 / 新建」按本机路径操作，附最近打开列表；新建建立 `正文/`、`设定集/`、三份空设定与 Git 基线。
- **阅读**：左栏列正文各章与三份设定；中区是只读 Markdown 稿纸（不执行内嵌 HTML）。界面没有写正文的入口，修改走对话或外部编辑器。
- **搜索**：左栏逐行搜索正文与设定，结果含路径、行号与摘录。
- **对话**：右栏发送一轮请求；工具调用、回复与结果显示在同一个过程里。停止保留已写入文件；「撤销这次修改」「补记到历史」在结果卡上。
- **改动与历史**：抽屉显示未记录的改动、工作区差异、提交历史与某次提交的差异；可补记、可撤销最新一次提交。
- **外部编辑**：切回窗口或点「刷新」重新扫描目录；应用内没有文件监听。

## 模型设置

- **入口**：顶栏「模型设置」是应用级入口，没有打开作品也能用；对话栏顶部有当前「连接 / 模型」选择器与「管理」按钮。
- **新增连接的顺序**：选择供应商（可搜索）→ 填写名称与 API Key（地址与接口类型在高级设置里）→ 获取或手填模型、选默认模型、保存。编辑已有连接直接进入后两步。
- **状态分开显示**：连接已保存、Key 已配置、响应测试、工具测试是四件事；测试结果随地址、协议、Key 或模型变化回到「未测试」。
- **切换**：保存连接不自动切换；「设为当前」与对话栏选择器都以服务端返回为准，只影响下一轮。
- **Key 的边界**：只存在于表单与一次请求里，保存后清空；不进入全局状态，也不写浏览器存储。脱敏值不回填到密码框。
- **未配置时**：输入区上方提示「连接模型后开始对话」并给「去设置」入口；已输入的草稿保留，后端仍然会拒绝没有模型的轮次。

字段、接口与失败行为见[模型连接](../dev-notes/v0.4/modules/model-connections.md)。

## 验证

```powershell
npm test
npm run build
node e2e/walkthrough-v04-workspace.mjs
```

浏览器走查需先按脚本头部说明启动后端；脚本自己通过真实接口准备作品，不调用模型。模型连接的真实链路见[验证材料](../dev-notes/v0.4/artifacts/v04-9-verification.md)，尚未在浏览器里逐屏走查。

本机沙箱下并行运行 vitest 会偶发系统临时目录 `ssr\*` 的 EPERM，症状是只跑完部分文件但退出码仍为 0。用 `npx vitest run --no-file-parallelism` 串行执行可稳定得到完整结果（5 个文件、36 项），这与测试本身无关。
