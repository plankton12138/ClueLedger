# Hastings 工作台

> 当前实现基于 0.2（原 V2），正在开发下一版本 0.3，包版本为 `0.3.0`。
> 0.3 产品方案与版本约定见[产品设计入口](../product-design/README.md)；以下描述当前已实现的工作台。

以作者的项目为中心：概览 → 创作台 → 故事账本 → 变更影响 → 修订审阅，辅以悬疑审计与作者模型。
视觉语言参考 [老 iOS 原型](../prototypes/ios6/README.md)。当前七页使用蓝色金属栏、浅色分组面板、纸面正文与凸起按钮。
原型仅提供设计语言参考，不代表成品功能、最终布局或交付状态；后续功能与交互以[当前产品设计](../product-design/README.md)为准。

## 运行

在仓库根启动服务：

```powershell
uv run python -m hastings.server
```

在本目录运行 `npm run dev`。开发服务器代理 `/api` 与 `/ws` 到本地 8000 端口；
后端默认启用当前工作台：复用已有 `data/v2.db` 或 `data/v2.sqlite`，都不存在时创建
`data/v2.db`。启动日志会打印实际数据库路径；需要打开其他仓库时传 `--v2-db <路径>`。
两种默认文件同时存在时必须显式指定，避免打开错误的作品库。
`npm run build` 生成生产文件。新建项目与编号找回在右上角「设置」。顶栏模型按钮可直接打开模型选择，也可从设置进入模型接入。
选择厂商 / Coding Plan 后粘贴对应 Key，地址自动填写；保存连接后选模型并点击「使用此模型」。
Ollama 保留检测、下载与安装引导，LM Studio 自动使用本地默认地址。需要其他服务时选择「自定义」。
当前选择保存在服务端，刷新与重启后保留，后续任务使用新选择；正在执行的任务继续原模型。
本阶段订阅通过套餐 Key 接入，没有网页登录授权；套餐工具资格以厂商说明为准。
作者偏好接口、正文写入、变更和 Agent 任务均走 `/api/v2`，模型档案走服务级接口；不再发现或迁移旧工作区。

模型接入的设计、来源与验证边界见 [Phase 18](../dev-notes/v2/phase-18-model-access.md)。

## 对话侧栏（Phase 19）

七页共用右侧常驻对话栏：普通发送固定为聊天（流式回复、停止、逐会话草稿），
讨论中的构想经「准备为任务」或输入框创作操作生成可检查的任务建议（TaskDraft），
**建议不自动开工**；明确「开始」后才进入规划/起草/检查工作流，候选回到对话
经作者接受才成为正式内容。输入框 Enter 发送、Shift+Enter 换行、输入法组合
期不发送；正文选中文本可「引用到对话」（未保存摘录明确标注）。

任务建议的「调整」可选择本章节拍或检查范围；空项目可以直接规划，新章无需先导入正文。
候选的「打开审阅」在主区显示对应任务完整内容；预览保留正文草稿，有未保存稿时禁止接受。
定向修订通过「打开变更流程」继续影响分析、批准与差异审阅。默认聊天重试保留原模型来源。

- 契约与状态：`src/api/chat.ts`（模拟器与真实 API 同接口）、`src/state/chat.ts`
- 组件：`src/components/chat/*`；走查清单 `e2e/v2-chat.spec.ts`
- 设计取舍：[Phase 19](../dev-notes/v2/phase-19-chat-workbench.md)
- 审查修复与证据：[Phase 19 review fixes](../dev-notes/v2/phase-19-review-fixes.md)

## 页面与状态

| 入口 | 职责 |
|---|---|
| `src/pages/OverviewPage.tsx` | 项目选择、真实计数、待处理工作、导出 |
| `src/pages/StudioPage.tsx` | 正文读写、冲突与草稿保护、章节导入、历史恢复 |
| `src/components/AgentTasks.tsx` | 规划、写作、审计、咨询、候选接受、任务重试与过程 |
| `src/pages/LedgerPage.tsx` | 故事资产、叙事计划、真相/认知/披露三层查看 |
| `src/pages/ChangesPage.tsx` | 影响与审阅两页，共用变更身份、批准范围与差异选择 |
| `src/pages/AuditPage.tsx` | 规则发现、证据与修复提交；无虚构的质量分数 |
| `src/pages/AuthorModelPage.tsx` | 偏好、编辑证据、显式声明、带原因撤销 |
| `src/state/v2.ts` | 项目隔离、正文缓冲、版本基础与命令回读 |
| `src/state/v2socket.ts` | 业务事件游标补齐、去重、合并刷新与重连 |

项目编号与名称登记在当前浏览器，内容始终来自服务端；换浏览器可用项目编号找回。浏览器不再载入旧工作区迁移登记。
切页不清空正文缓冲；切章、切项目、重新读取前必须明确处理未保存稿。保存冲突保留草稿与旧基础，禁止自动覆盖。

故事变更的常用文本字段使用表单修改；复杂结构仍通过规划候选进入故事。
作者模型候选按已有领域规则归纳与生效，界面不伪造「一键激活候选」状态；作者可以显式声明偏好或撤销现有偏好。
任务不是长期聊天：主编面板展示持久任务和候选，业务事件与任务过程分开。

## 验证

```powershell
npm test
npm run build
npm run test:e2e
```

浏览器测试启动隔离的真实 API + SQLite 服务，模型使用确定性工作者，不访问真实 Provider。
`e2e/v2-chat-real.spec.ts` 通过真实 HTTP/SSE 测试聊天与创作闭环，不使用 `chatMock`；
它和调用真实模型的 `eval/v2/chat_driver.py` 属于不同层次的证据。
默认运行 `e2e/v2-*.spec.ts`，覆盖七页、迁移入口退役、规划到正文、保存冲突、项目切换、版本恢复、
批准与分支修订、接受/拒绝差异、审计、导出及作者裁决。截图输出在 `test-results/`。
`j1`–`j8` 保留为旧 V1/早期变更中心界面的历史旅程，不适用于替换后的七页壳；不作为当前 UI 质量门。

设计与交付记录见 `../dev-notes/v2/phase-17-frontend-workbench.md`。
