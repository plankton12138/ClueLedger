## 运行

仓库根目录启动后端（默认打开最近使用的作品目录）：

```powershell
uv run python -m hastings.server
```

在本目录运行：

```powershell
npm install
npm run dev
npm run build
```

开发服务器将 `/api` 转发到本地 8000 端口。生产文件位于 `frontend/dist`，由后端托管。

## 当前可用流程

- **目录与对话开关**：写作工具区的两个按钮始终保留在固定位置，按下表示显示，再次点击隐藏；关闭对话不自动展开目录。窄窗口目录在工具区下方展开，仍可直接点同一个按钮关闭；对话关闭后回到正文，不插入或替换按钮。
- **打开与新建**：顶栏「作品 → 打开 / 新建」经系统文件夹窗口选择位置，附最近打开列表；新建建立 `正文/`、`设定集/角色小传/` 与 Git 基线，不强制创建线索与真相文件；旧作品已有文件照常读取。
- **阅读**：左栏列正文各章，设定集提供可折叠的角色小传分组和线索、真相入口；中区是只读 Markdown 稿纸（不执行内嵌 HTML）。界面没有写正文的入口，修改走对话或外部编辑器。
- **搜索**：左栏逐行搜索正文与设定，结果含路径、行号与摘录。
- **对话**：右栏发送一轮请求；回复流式出现，思考与工具过程默认折叠，状态行说明当前阶段。停止保留已写入文件；「撤销这次修改」「补记到历史」在结果卡上。
- **阅读回复**：公开回复按 Markdown 显示；每条回复可复制原文、展开到宽视图阅读；向上翻阅时出现「回到最新」。
- **字号**：设置和活动记录面板提供同一字号选择器，支持 80%–150% 和恢复默认；正文、对话、日志及详情同步变化，设置保存在本机。见[显示偏好](../dev-notes/v0.6/modules/appearance.md)。
- **章名与人物**：章节显示「第X章 章名」，人物名后带身份标签（侦探、助手、凶手、嫌疑人、受害者）；显示名与标签都来自服务端，前端不自行拼规则。
- **活动记录**：事件流可按会话、任务、类型、结果、时间与关键词筛选，实时查看模型请求和操作过程，展开详情并导出；文件版本页保留差异、补记与最新提交撤销。输入快照、详情保留与查询边界见[活动记录模块](../dev-notes/v0.6/modules/activity-log.md)。
- **故事资料**：顶栏「故事资料」进入独立页面；左侧四页，顶部「查看截至」只影响浏览，整理按钮按所选章节与人物发起一次任务。章节与事件页可在章节顺序与故事顺序之间切换：故事顺序只排可证明的先后，未知与冲突单独列出；旧「章节概览」「时间线」链接分别落到这两种顺序。任务条显示范围、模型与已处理目标数，可停止并跳到活动记录；条目右侧显示原文依据、失效说明与「打开原文」「带到对话」。见[0.8 E 记录](../dev-notes/v0.8/notes/E-story-index.md)。
- **外部编辑**：切回窗口或点「重新读取文件」重新扫描目录；资料页另有「重新读取资料」。应用内没有文件监听。

## 模型设置

- **入口**：顶栏「设置 → 模型设置」是应用级入口，没有打开作品也能用；对话栏顶部有当前「连接 / 模型」选择器与「管理」按钮。
- **新增连接的顺序**：选择供应商（可搜索）→ 填写名称与 API Key（地址与接口类型在高级设置里）→ 获取或手填模型、选默认模型、保存。编辑已有连接直接进入后两步。
- **状态分开显示**：连接已保存、Key 已配置、响应测试、工具测试是四件事；测试结果随地址、协议、Key 或模型变化回到「未测试」。
- **切换**：保存连接不自动切换；「设为当前」与对话栏选择器都以服务端返回为准，只影响下一轮。
- **Key 的边界**：只存在于表单与一次请求里，保存后清空；不进入全局状态，也不写浏览器存储。脱敏值不回填到密码框。
- **未配置时**：输入区上方提示「连接模型后开始对话」并给「去设置」入口；已输入的草稿保留，后端仍然会拒绝没有模型的轮次。

## 会话与草稿

- **新建不落盘**：「新对话」只切到临时输入状态，首次发送才建会话；输入了没发就切走，内容作为「新对话草稿」留在入口。
- **草稿分会话**：切换会话先保存当前草稿再读另一份；只有受理确认才清除「仍然等于提交文本」的那一版，受理期间新输入的字保留。
- **切换不停止任务**：任务属于原会话，切回后按快照恢复事件、运行状态与停止按钮；另一个会话在跑时发送按钮不可用并说明是哪个会话。
- **结果按轮次归属**：每轮结果卡挂在它自己的位置后面，不再是「最后一个结果」。
- **刷新恢复**：回到上次查看的正式会话并恢复运行状态；不自动发送草稿，不自动重跑中断的轮次。

字段、接口与失败行为见[模型连接](../dev-notes/v0.4/modules/model-connections.md)。

## 验证

```powershell
npm test -- --no-file-parallelism
npm run build
npm run test:e2e          # workspace（不调模型）+ online（在线模型）
npm run test:e2e:local    # 只跑不调模型的确定性部分
npm run test:e2e:online   # 只跑在线模型流程
```

端到端测试会构建前端、启动真实后端并经接口准备作品。`workspace` 项目不调用模型；
`online` 项目真的调用在线模型，检查参考发送与草稿切换、范围展示、写后报告与过期回看、
索引生成与外部改源后的重读。除文件、版本和事件外，也核对页面可见的材料、范围、报告
与结果卡；未完成报告不算通过。失败保存错误、事件和页面文字，不重试；没有明确端点或
工具错误时先标为待判读，再区分脚本或夹具、产品接线、模型理解问题。
`e2e/chat-rendering.spec.ts` 是受控 SSE 夹具：
渲染真实对话组件，并在测试构建里统计 Markdown 解析与轮次渲染次数，用来守住「折叠不解析、
合批只重绘变化的一轮」。涉及模型的走查与语义验收一律接在线模型端点，不用本地模型
（见[开发约定](../AGENTS.md)）。当前验证结果见[0.8 前端验证](../dev-notes/v0.8/artifacts/frontend-experience/verification.md)；模型连接的历史真实链路见[验证材料](../dev-notes/v0.4/artifacts/v04-9-verification.md)，不算本次重新验证。

本机并行运行 vitest 曾出现系统临时目录 `ssr\*` 的 EPERM，症状是只跑完部分文件但退出码仍为 0。验证使用 `--no-file-parallelism` 串行执行，并核对完整结果。
