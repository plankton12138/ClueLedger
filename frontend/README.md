# Hastings 前端

当前默认入口为 **0.5 工作区**：作品是一个 Markdown 目录，界面只读文件、发起对话、查看 Git 改动与历史。人物小传一人一文件。产品目标见[产品设计](../product-design/README.md)，当前目录与文件契约见[文件工作区与角色小传](../dev-notes/v0.5/modules/file-workspace.md)，其余布局见[写作台界面](../dev-notes/v0.4/modules/desk.md)。

当前页面只接文件工作区接口，旧版内容界面已移除。对话的流式接收、折叠过程与阅读操作见[对话展示与流式回复](../dev-notes/v0.5/modules/chat-display.md)。

## 运行

仓库根目录启动后端（默认打开最近使用的作品目录）：

```powershell
uv run python -m hastings.server
```

在本目录运行：

```powershell
npm install
npm run dev
npm run build
```

开发服务器将 `/api` 转发到本地 8000 端口。生产文件位于 `frontend/dist`，由后端托管。

## 当前可用流程

- **打开与新建**：顶栏「打开 / 新建」经系统文件夹窗口选择位置，附最近打开列表；新建建立 `正文/`、`设定集/角色小传/`、线索与真相两份空设定及 Git 基线。
- **阅读**：左栏列正文各章，设定集提供可折叠的角色小传分组和线索、真相入口；中区是只读 Markdown 稿纸（不执行内嵌 HTML）。界面没有写正文的入口，修改走对话或外部编辑器。
- **搜索**：左栏逐行搜索正文与设定，结果含路径、行号与摘录。
- **对话**：右栏发送一轮请求；回复流式出现，思考与工具过程默认折叠，状态行说明当前阶段。停止保留已写入文件；「撤销这次修改」「补记到历史」在结果卡上。
- **阅读回复**：公开回复按 Markdown 显示；每条回复可复制原文、展开到宽视图阅读；向上翻阅时出现「回到最新」。
- **改动与历史**：抽屉显示未记录的改动、工作区差异、提交历史与某次提交的差异；可补记、可撤销最新一次提交。
- **外部编辑**：切回窗口或点「刷新」重新扫描目录；应用内没有文件监听。

## 模型设置

- **入口**：顶栏「模型设置」是应用级入口，没有打开作品也能用；对话栏顶部有当前「连接 / 模型」选择器与「管理」按钮。
- **新增连接的顺序**：选择供应商（可搜索）→ 填写名称与 API Key（地址与接口类型在高级设置里）→ 获取或手填模型、选默认模型、保存。编辑已有连接直接进入后两步。
- **状态分开显示**：连接已保存、Key 已配置、响应测试、工具测试是四件事；测试结果随地址、协议、Key 或模型变化回到「未测试」。
- **切换**：保存连接不自动切换；「设为当前」与对话栏选择器都以服务端返回为准，只影响下一轮。
- **Key 的边界**：只存在于表单与一次请求里，保存后清空；不进入全局状态，也不写浏览器存储。脱敏值不回填到密码框。
- **未配置时**：输入区上方提示「连接模型后开始对话」并给「去设置」入口；已输入的草稿保留，后端仍然会拒绝没有模型的轮次。

## 会话与草稿

- **新建不落盘**：「新对话」只切到临时输入状态，首次发送才建会话；输入了没发就切走，内容作为「新对话草稿」留在入口。
- **草稿分会话**：切换会话先保存当前草稿再读另一份；只有受理确认才清除「仍然等于提交文本」的那一版，受理期间新输入的字保留。
- **切换不停止任务**：任务属于原会话，切回后按快照恢复事件、运行状态与停止按钮；另一个会话在跑时发送按钮不可用并说明是哪个会话。
- **结果按轮次归属**：每轮结果卡挂在它自己的位置后面，不再是「最后一个结果」。
- **刷新恢复**：回到上次查看的正式会话并恢复运行状态；不自动发送草稿，不自动重跑中断的轮次。

字段、接口与失败行为见[模型连接](../dev-notes/v0.4/modules/model-connections.md)。

## 代码位置

| 位置 | 职责 |
|---|---|
| `src/App.tsx` | 挂载工作区壳层 |
| `src/components/workspace/` | 顶栏、章节目录、只读稿纸、对话栏（会话选择与改名、逐轮装配）、改动与历史抽屉、目录对话框 |
| `src/components/chat/` | 回复展示：Markdown、思考折叠、工具摘要、复制与展开、逐轮视图、滚动跟随 |
| `src/state/chatMessages.ts` | 事件归并为轮次与内容块；实时与回放共用 |
| `src/components/models/` | 模型设置对话框、供应商选择、连接表单、日常模型选择器 |
| `src/state/workspace.ts` | 目录、文件、Git 与抽屉的状态与动作 |
| `src/state/conversations.ts` | 会话列表、每个会话的事件与运行状态、草稿与界面版本 |
| `src/state/models.ts` | 脱敏连接、当前选择、配置版本与对话框状态 |
| `src/api/workspace.ts` | `/api/file-workspaces` 客户端（含会话、草稿与 SSE 解析） |
| `src/api/models.ts` | `/api/model-*` 客户端（含 `If-Match` 与错误码） |

## 验证

```powershell
npm test -- --no-file-parallelism
npm run build
npm run test:e2e
```

端到端测试会构建前端、启动真实后端并经接口准备作品，不调用模型。当前验证结果见[0.5 运行说明](../dev-notes/v0.5/release.md)；模型连接的历史真实链路见[验证材料](../dev-notes/v0.4/artifacts/v04-9-verification.md)，不算本次重新验证。

本机并行运行 vitest 曾出现系统临时目录 `ssr\*` 的 EPERM，症状是只跑完部分文件但退出码仍为 0。验证使用 `--no-file-parallelism` 串行执行，并核对完整结果。
